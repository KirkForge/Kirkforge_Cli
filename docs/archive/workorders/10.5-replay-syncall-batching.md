# Workorder 10.5 — replay.rs sync_all Batching

## Status: Done (sync_all batched every sync_interval turns; Drop flushes final batch; with_sync_interval + 2 tests added)

## Problem
`src/session/replay.rs:81-88` `TraceRecorder::record` calls
`self.file.sync_all()` (an `fsync`) on every single turn:

```rust
pub fn record(&mut self, mut record: TurnRecord) -> anyhow::Result<()> {
    self.turn += 1;
    record.turn = self.turn;
    let line = serde_json::to_string(&record)?;
    writeln!(self.file, "{line}").with_context(|| "write trace record")?;
    self.file.sync_all().with_context(|| "sync trace file")?;  // <-- per-turn fsync
    Ok(())
}
```

For a long session (100+ turns), this is 100+ `fsync` calls, each
blocking the executor's turn loop. On a slow disk (HDD, networked FS,
CI runner) the latency is ~5-50 ms per `fsync` — 100 turns × 50 ms =
5 seconds of cumulative blocking. The `sync_all` is there for
crash-safety (so a killed session's trace is recoverable up to the last
turn), but per-turn is the wrong granularity. A burst recorder that
`sync_all`s every N turns or on a timer is the standard pattern.

Pass 13 finding #6 noted this. The `ponytail:` annotation at the top of
`replay.rs` (lines 7-8: "NDJSON turn traces parallel the conversation
log. The upgrade path is interactive TUI replay with diff
highlighting.") names the *TUI* upgrade path, not this perf fix — this
WO is independent of the TUI work (which shipped in WO 9.4).

## Root cause
The `sync_all` was added for crash-safety without considering the
per-turn cost. The recorder was built for correctness first (each
turn must survive a crash) and the perf cost was not measured. There
is no batching, no timer, no "sync every N turns" logic.

## Files to touch
- `src/session/replay.rs:60-118` — `TraceRecorder` struct + `record`
  method. Add a `turns_since_sync: u32` counter and a `sync_interval:
  u32` config field (default 10, or a `Duration` for a timer-based
  approach). In `record`, increment the counter; only call `sync_all`
  when `turns_since_sync >= sync_interval` (or the timer elapsed). At
  recorder `Drop`, always `sync_all` (so a dropped recorder flushes the
  final partial batch).

## Approach
Two options; pick A (simpler, deterministic):

**Option A — batch every N turns.**
```rust
pub struct TraceRecorder {
    file: std::fs::File,
    turn: u32,
    turns_since_sync: u32,
    sync_interval: u32,  // default 10
}

impl TraceRecorder {
    pub fn open(path: &Path) -> anyhow::Result<Self> {
        // ... existing open ...
        Ok(Self { file, turn: 0, turns_since_sync: 0, sync_interval: 10 })
    }

    pub fn record(&mut self, mut record: TurnRecord) -> anyhow::Result<()> {
        self.turn += 1;
        record.turn = self.turn;
        let line = serde_json::to_string(&record)?;
        writeln!(self.file, "{line}").with_context(|| "write trace record")?;
        self.turns_since_sync += 1;
        if self.turns_since_sync >= self.sync_interval {
            self.file.sync_all().with_context(|| "sync trace file")?;
            self.turns_since_sync = 0;
        }
        Ok(())
    }
}

impl Drop for TraceRecorder {
    fn drop(&mut self) {
        // Flush the final partial batch on drop so a dropped recorder
        // does not lose the last < sync_interval turns.
        let _ = self.file.sync_all();
    }
}
```

Add a `pub fn with_sync_interval(path, sync_interval)` constructor for
tests that want to force a sync every turn (set `sync_interval = 1` to
get the old behavior).

**Option B — timer-based (more complex, better for long turns).**
Spawn a background thread that `sync_all`s every `Duration::from_secs(5)`.
This is better when turns are slow (a 30-second turn shouldn't wait 30
seconds for a sync), but it adds a thread and a shutdown path. Prefer A
unless turns are demonstrably slow.

## Notes
- The crash-safety guarantee weakens slightly: with `sync_interval =
  10`, a crash can lose up to the last 9 turns (the un-sync'd batch).
  This is acceptable for a trace recorder (the conversation log is the
  source of truth; the trace is a debugging aid). If a future use case
  needs per-turn crash-safety, set `sync_interval = 1` (the old
  behavior).
- Do NOT remove the `sync_all` entirely — the trace file must still be
  recoverable after a crash. The fix is batching, not removal.
- This is a P3 perf WO. It does not block the release or the
  cache-stem wiring. It can be batched with 10.3/10.4/10.6 in a single
  "doc + perf hygiene" commit if desired.
