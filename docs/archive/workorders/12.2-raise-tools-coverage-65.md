# Workorder 12.2 — Raise `src/tools` Coverage Threshold 50% → 65%

## Status: Done (intermediate threshold landed)

## Problem
The `src/tools` coverage threshold in `.github/workflows/ci.yml:344`
is 50.0%. Current actual coverage (CI run `30275314517`): 60.8%. 10.8%
headroom — the threshold is far below actual, so the gate provides
almost no regression protection. The target is 75% (WO 12.8/12.9);
this WO is the intermediate step to 65%, still leaving ~5% headroom
above the current 60.8%.

## Root cause
`src/tools/` (1323 lines) contains the tool implementations: `bash`,
`read_file`, `write_file`, `edit_file`, `grep`, `glob`, `web_fetch`,
`web_search`, `task`, `todo`, `computer_use`, `lsp_query`, `workflow`,
`lsp_query`, and the plugin tool wrapper. The tools are mostly
async + I/O-heavy (subprocess spawn, file read/write, HTTP fetch), so
unit-test coverage is uneven: the pure logic (arg parsing, schema
validation, path-guard checks) is ~90% covered; the I/O paths (actual
subprocess, actual HTTP) are ~30-50% covered because tests mock the
I/O. The 50% threshold was set low because the I/O paths were hard to
test; 12.2 raises it to reflect the current reality (60.8%) + push
toward 75%.

## Files to touch
- `.github/workflows/ci.yml:344` — change `'src/tools': 50.0` to
  `'src/tools': 65.0`.
- `src/tools/` — add tests to raise coverage from 60.8% to ≥65%.
  Run `cargo tarpaulin` locally + parse the XML to find the
  lowest-covered tool files. Likely targets:
  - `src/tools/web_fetch.rs` — the SSRF guard + the HTML→text regex
    path may have uncovered branches.
  - `src/tools/web_search.rs` — the "not configured" degrade path
    + the Brave API response parsing.
  - `src/tools/computer_use.rs` — the `BrowserSession` open/close/step
    paths (WO 3.8/9.x) may have uncovered branches.
  - `src/tools/task.rs` — the background-task spawn + `task_output`
    retrieval path.
  - `src/tools/lsp_query.rs` — the LSP pool query path (the pool is
    mocked in tests; the error-recovery branches may be uncovered).

## Approach
1. **Measure.** Run `cargo tarpaulin --out Xml --locked --lib --timeout
   120` locally; parse the XML for `src/tools/` per-file coverage.
2. **Add tests.** For each low-coverage tool file, add tests for the
   uncovered branches. Use `wiremock` (already a dev-dep) for HTTP
   tools; use the existing `FakeTab` pattern for `computer_use`; use
   mock LSP servers for `lsp_query`.
3. **Re-measure.** Iterate until `src/tools/` is ≥65%.
4. **Raise the threshold.** Change `.github/workflows/ci.yml:344` from
   `50.0` to `65.0`. Commit the threshold change in the same commit as
   the tests.
5. **Verify CI.** Push + watch the coverage job.
