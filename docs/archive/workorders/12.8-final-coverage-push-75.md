# Workorder 12.8 — Final Coverage Push to 75% on All Three Target Directories

## Status: Done (`3fb20b9`; 144 new tests; src/session 68.6%, src/tools 76.5%, src/adapters 84.1%)

## Problem
After WO 12.1-12.3 raised the thresholds to 68/65/70, the coverage is
still ~5-10% below the 75% target on each directory:
- `src/session/`: ~68% (target 75% — gap ~7%)
- `src/tools/`: ~65% (target 75% — gap ~10%)
- `src/adapters/`: ~70% (target 75% — gap ~5%)

This WO is the final push: add the remaining tests to close the gap to
≥75% on all three, so WO 12.9 can raise the thresholds to 75%.

The 12th-pass review named "coverage gate" as shipped (at 62/50/61).
The 12-series is the work that turns the gate from a regression-guard
into a quality target: 75% is the "A− production" bar for test
coverage.

## Root cause
The remaining uncovered lines are the hard cases: async I/O paths
that require mock servers, error branches that require specific
failure conditions, and integration paths that require live services.
The 12.1-12.3 work closed the easy gaps (pure functions, arg parsing,
config); 12.8 closes the hard gaps (mock HTTP, mock LSP, mock
subprocess, error recovery).

## Approach
1. **Run `kirkforge doctor gaps`** (WO 12.7) to get the prioritized
   list of uncovered files + ranges.
2. **Add tests for each gap.** Use the mock patterns already in the
   codebase: `wiremock` for HTTP, `FakeTab` for computer_use, mock LSP
   server for `lsp_query`, `EnvGuard` for env-var tests.
3. **Re-measure after each batch.** Run `cargo tarpaulin --out Xml
   --locked --lib --timeout 120` locally; parse the XML; verify the
   coverage moved. Iterate until all three directories are ≥75%.
4. **Do NOT raise the threshold yet.** WO 12.9 raises the threshold
   after this WO confirms ≥75% on all three. This WO only adds tests;
   the threshold stays at 68/65/70 until 12.9.
