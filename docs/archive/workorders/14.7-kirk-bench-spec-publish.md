# Workorder 14.7 — Publish KIRK-BENCH Spec + Signature Token Budget Challenge

## Status: Done

## Problem
The `123.md` helper file defines a 40-task benchmark spec ("KIRK-BENCH.md")
 across 8 categories (Repository Understanding, Refactoring, Bug Fixes,
 New Features, Verification, Context Intelligence, Real Engineering,
 Cost) plus 10 "hero" benchmarks and one signature benchmark — the
 **Token Budget Challenge**: complete the same task under progressively
 tighter context budgets (128k → 64k → 32k → 16k → 8k), recording
 success rate, token consumption, verification success, retrieval/
 compression passes, and cost.

The Pass-14 REVIEW's honest summary table (lines 53-63) gives
 KirkForge an "A" on Bench/Measurement — the only product of the four
 with a published bench (30 tasks, multi-model leaderboard, PR-delta CI
 gate). But the bench harness currently has **30 ad-hoc tasks** in
 `benches/tasks/`; the `123.md` spec is not adopted, the categories are
 not formalized, and the signature Token Budget Challenge — the one
 benchmark that would showcase the repo's tree-sitter index + Stratum
 + budget management (the architectural advantages the REVIEW names vs
 Claude Code / Vix / opencode) — does not exist.

The `123.md` author's closing line: "If you package all of this into a
 KIRK-BENCH.md with automated execution and publish results over time,
 you'll have something more compelling than 'we support more providers.'"

## Root cause
The bench harness was built incrementally (WO 6.1 → 9.9) by adding
 tasks that exercised specific features (plugin tools, multi-file
 patterns, PR review). It never adopted a *spec* — there's no
 `KIRK-BENCH.md` defining the category taxonomy, the universal scoring
 format, or the signature challenge. The 30 tasks exist; they're just
 not organized against the spec, and the differentiator benchmark was
 never built.

## Files to touch
- `KIRK-BENCH.md` (new, repo root) — the spec document. Adapt the
  `123.md` content into the repo's voice: 8 categories, 40 tasks, the
  universal scoring block (Benchmark / Success / Compilation / Tests /
  Lint / Verification / Retries / Elapsed / Input Tokens / Output
  Tokens / Compression Ratio / Budget Violations / Provider / Cost),
  the 10 hero benchmarks, and the Token Budget Challenge as the
  signature. This is the *spec*; the *implementation* of each task is
  a follow-up (see 14.7 Notes).
- `benches/tasks/` — map the existing 30 tasks to the spec categories
  in a table in `KIRK-BENCH.md` (which existing task covers which
  spec task). Several spec tasks already have rough counterparts
  (e.g. spec #6 "Rename Public API" ↔ existing `rename_function.toml`;
  spec #11-16 "Bug Fixes" ↔ `fix_borrow_error.toml`,
  `fix_clippy_warning.toml`, `fix_failing_test.toml`;
  spec #34 "PR Review" ↔ `pr_review.toml`). The table makes the gap
  analysis explicit: which of the 40 spec tasks are covered, which
  are not, which are partial.
- `benches/tasks/token_budget_challenge.toml` (new) — the signature
  benchmark task definition. This is the one new task to *implement*
  in this WO (the rest of the 40-task spec is documented but not all
  built here — see Approach). The task: given a medium-sized repo
  (use the existing `setup_files` pattern), implement a small feature
  under a `KIRKFORGE_BUDGET_CEILING` env override that the bench
  harness passes at 128k, 64k, 32k, 16k, 8k across 5 runs. The verify
  spec checks the feature is implemented (command_exits_zero on
  `cargo test`). The harness records the 6 metrics (`123.md` lines
  282-288) per run.
- `crates/kirkforge-bench/` — the `BenchTask` struct + runner:
  - Add an optional `budget_ceiling: Option<usize>` field (default
    None). When set, the runner exports
    `KIRKFORGE_BUDGET_CEILING=<n>` to the agent's env so the Plugin3
    budget guard (`src/session/budget.rs`) enforces it. This wires
    the signature benchmark to the existing budget infrastructure
    (ADR-0005 / WO 7.5 / WO 8.6) without new budget code.
  - Add a `BudgetChallengeReport` struct recording the 6 metrics per
    ceiling level. The report writer emits a markdown table
    (ceiling × success × tokens × compression-passes × cost).
- `docs/TECHNICAL.md` Benchmarks section — document the spec adoption
  + the Token Budget Challenge as the signature. Doc-sync per
  AGENTS.md §9 (the bench system is architecture).
- `README.md` — one line in "Why KirkForge" pointing to KIRK-BENCH.md
  (the REVIEW §10 says README is a landing page; one line is fine).

## Approach
1. **Spec first.** Write `KIRK-BENCH.md` from `123.md`, adapting voice
   and mapping existing tasks. The 8 categories + universal scoring +
   10 hero benchmarks + signature challenge. This is the durable
   artifact; the task implementations come after.
2. **Token Budget Challenge task.** One new `.toml` exercising the
   budget guard at 5 ceiling levels. The setup is a small Rust crate
   (reuse the `setup_files` pattern from `add_cli_flag.toml`); the
   prompt asks for a small feature (add a `--verbose` flag, matching
   the existing `add_cli_flag` task so the difficulty is known); the
   verify is `cargo test` + `cargo clippy`. The runner loops 5× with
   descending ceilings.
3. **Budget env wiring.** `BenchTask::budget_ceiling` → runner sets
   `KIRKFORGE_BUDGET_CEILING`. The budget guard already reads env
   overrides (grep `KIRKFORGE_BUDGET` in `src/session/budget.rs` +
   `config/mod.rs` — confirm the env hook exists; if not, add it as a
   one-line `env::var` read in `init_from_config`, mirroring the
   `minify_above_bytes` env pattern from WO 9.7).
4. **Report.** The `BudgetChallengeReport` markdown table is the
   scoreboard. The REVIEW's "A" on bench is currently based on the
   30-task leaderboard; the signature challenge table is the public
   differentiator the `123.md` author asks for.
5. **Don't build all 40 tasks.** The spec documents 40; this WO
   builds the signature one + maps the existing 30. The remaining
   ~10 spec tasks (e.g. #1 Find Dead Code, #5 Cross-Repository Search,
   #27 Large Repository Navigation) are future WOs — list them in
   `KIRK-BENCH.md` as "planned tasks" with a note on which feature
   each exercises (dead-code finder → context index; cross-repo →
   workspace support). Honest deferral per AGENTS.md §5.

## Gate
```
cargo fmt --check && cargo clippy --all-targets -- -D warnings &&
cargo test --locked --workspace --no-fail-fast &&
cargo run -- bench verify-only --tasks benches/tasks/token_budget_challenge.toml
# (verify-only should SKIP with "requires model" — the task needs the
# model to implement the feature; the verify spec checks post-model
# content. Confirm it skips cleanly, then a live `bench run` is the
# real test, gated on Ollama per AGENTS.md §4.)
```

## Notes
- The `123.md` author's "Universal Scoring" block (lines 216-258) is
  the contract every bench task should emit. The current bench
  reports (JSON + markdown) emit some of these fields; the
  Token Budget Challenge report should emit all of them. Check
  `kirkforge-bench` report writers for the existing field set and
  extend, don't rewrite.
- The signature challenge is the *showcase* — the `123.md` author
  explicitly says "This directly showcases your investments in
  Tree-sitter indexing, Stratum, and budget management." The
  report table is the public artifact; make it clean.
- Do NOT gate the 30 existing tasks on the new spec. They keep their
  current verify specs. The spec is the *organization*, not a
  rewrite mandate.
- The `requires_model: bool` field (WO 9.9) already exists — the
  token_budget_challenge task sets it `true` so `verify-only` skips
  and `bench run` runs it.
- If the `KIRKFORGE_BUDGET_CEILING` env hook doesn't exist yet, adding
  it is a 3-line change in `init_from_config` mirroring
  `KIRKFORGE_MINIFY_ABOVE_BYTES` (WO 9.7). Check first; don't
  duplicate.
