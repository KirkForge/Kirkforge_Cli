# WO 17.0 — Series 17: vix-Parity Gap Inventory

## Status: Done

## Purpose
Series 17 closes gaps where `vix-main` (Go, the reference agent) is ahead of
`kf-code` (Rust). This inventory is the single source for the series: every
gap found by a seven-way parallel comparison (token efficiency, daemon arch,
auth/providers, whiteboard/workflow/jobs, testing, update/telemetry/packaging,
TUI UX), graded and mapped to a workorder or explicitly deferred to Series 18.

Nothing is silently dropped. Gaps not assigned a 17.x workorder are listed
under "Deferred to Series 18" with a one-line reason.

## Method
Seven read-only comparison agents each took one dimension, read the actual code
in both repos, and reported verified `GAP:` findings with file:line evidence.
This doc distills ~60 raw gaps into 9 shippable workorders (17.1–17.9) plus a
deferred bucket. Evidence line numbers are from HEAD at audit time; re-verify
before each workorder starts.

### Priority rationale
- **17.1 (P0)**: The plain Anthropic adapter sends no auth header and reads no
  `ANTHROPIC_API_KEY`. It is non-functional against `api.anthropic.com` today —
  a defect, not a parity nicety. Ships first, unblocks the rest of auth.
- **17.2 / 17.3 (High)**: vix's daemon owns a per-instance control channel
  with broadcast fanout, auth, version gate, and exclusive session ownership.
  KirkForge's daemon is an unauthenticated, blind-`remove_file` metadata cache.
  17.2 is the foundation; 17.3 bundles the security/correctness fixes that
  hang off it.
- **17.4 / 17.5 (High)**: vix's headline feature — 20–50% fewer tokens. 17.4 is
  the AST minifier + surgical edit (position map); 17.5 is the cache-stem reuse
  that makes cross-phase prompts hit Anthropic's prompt cache.
- **17.8 (High)**: vix has a real binary-driving e2e harness with a mock
  provider and tmux TUI driver. KirkForge tests the executor in-process only;
  no test spawns `kf-code` or drives the TUI. This unblocks confident delivery
  of every other workorder in the series.
- **17.6 / 17.7 / 17.9 (Medium)**: Real parity wins (programmable workflows,
  self-evolving jobs, TUI basics) but not blocking. 17.7 depends on 17.6;
  17.9's threads-overview depends on 17.2's instance channel.

## Verification against HEAD

Each sub-workorder was re-verified against the current codebase. Findings below
supersede the original gap descriptions where implementation has landed.

### 17.1 — Anthropic auth + per-provider env resolution ✅ Shipped

**Original gap:** The Anthropic adapter sent no `x-api-key` header and read no
`ANTHROPIC_API_KEY` env var, making it non-functional against `api.anthropic.com`.

**Current state:** Fully resolved.
- `src/adapters/auth.rs` implements `resolve_api_key(provider, config_key)` with
  the correct resolution order: config field → `<PROVIDER>_API_KEY` env →
  keychain (stubbed `None`, Series 18). Tests for all five providers pass.
- `src/adapters/anthropic.rs:86-96` calls `resolve_api_key("anthropic",
  self.api_key.as_deref())` and sets `x-api-key` on the request. Missing key
  returns a clear error before any HTTP request.
- `src/session/config/env_overrides.rs:304` reads `ANTHROPIC_API_KEY` (plus
  `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `GEMINI_API_KEY`, `KIMI_API_KEY`).
- `src/shared/config/model.rs:58-70` has per-provider config fields
  (`anthropic_api_key`, `openai_api_key`, `deepseek_api_key`, `gemini_api_key`,
  `kimi_api_key`).

**Remaining (Series 18):** OS keychain storage, `kf-code auth login/logout`,
PKCE/device-code OAuth, new adapter integrations (OpenAI Codex, OpenRouter,
Bedrock full credential chain).

### 17.2 — Daemon instance control channel + event broadcast ✅ Shipped

**Original gap:** KirkForge's daemon was strictly request/response with no
persistent connection, no instance registry, no push path.

**Current state:** Fully resolved.
- `src/daemon/mod.rs:210-223` defines `InstanceEvent` (`ThreadsChanged`,
  `JobsChanged`, `Quit`).
- `src/daemon/mod.rs:272-276` adds `instances: Arc<Mutex<Vec<UnboundedSender<InstanceEvent>>>>`
  to `DaemonState`.
- `src/daemon/mod.rs:298-301` implements `broadcast()` with `try_send` + dead-sender pruning.
- `src/daemon/mod.rs:184-190` defines `Request::InstanceRegister` with optional
  `version` and `auth_token` fields.
- `src/daemon/server.rs:341-402` implements `handle_instance_register`: sends
  handshake ack, creates an `UnboundedChannel`, registers the sender, and runs
  a single-writer loop that serialises `InstanceEvent`s as NDJSON frames.
- `src/daemon/server.rs:307` broadcasts `ThreadsChanged` on `Touch`.
- `src/daemon/server.rs:314` broadcasts `Quit` on `Shutdown`.

### 17.3 — Daemon hardening: socket guard, auth, version, ownership, quit ✅ Shipped

**Original gap:** Blind socket steal, no auth, no version gate, no session
ownership, no coordinated quit.

**Current state:** Fully resolved.
- **Socket guard** (`src/daemon/server.rs:42-61`): Before `remove_file`, the
  daemon attempts `UnixStream::connect`; if it succeeds, it bails with
  "daemon already running". Only removes the stale socket on connection failure.
- **Auth** (`src/daemon/mod.rs:282-323`): `DaemonState::expected_token` loaded
  from `KF_CODE_DAEMON_TOKEN_FILE`. `check_auth()` uses `subtle::ConstantTimeEq`.
  Every request type carries an `auth_token` field; `None` = legacy (no auth
  required when no token configured).
- **Version gate**: `InstanceRegister` carries an optional `version` field.
- **Session ownership** (`src/daemon/mod.rs:165-171`): `Request::Claim` returns
  `Response::Busy` if the session is already claimed; `open_sessions: HashSet`
  tracks claims; released on connection close.
- **Coordinated quit**: `Request::QuitAll` and `InstanceEvent::Quit` broadcast
  to all instances.

### 17.4 — AST minification + surgical edit position map + revalidation ⏳ Open

**Original gap:** KirkForge's minifier (`src/shared/minify/lang.rs`) is a
lossy char-scan comment-stripper + blank-line collapse with no position map.
`src/shared/minify/expand.rs` expands the whole `<minified>` envelope,
clobbering surrounding formatting. No revalidation, no idempotency guarantee.

**Current state:** Still a char-scan minifier. `lang.rs:5-19` dispatches by
extension to `minify_rust_inner`, `minify_python`, `minify_js_like`, etc. —
all character-scanning, no AST. `expand.rs` has `extract_minified_envelope` and
`expand_minified` that do whole-envelope expansion via external formatters
(rustfmt/black/prettier/gofmt) or a heuristic fallback. No position map, no
`surgical_edit`, no `revalidate`.

**Note:** `tree-sitter` + grammars (`tree-sitter-rust`, `tree-sitter-typescript`,
`tree-sitter-python`, `tree-sitter-go`) already exist in
`crates/kf-context-index/Cargo.toml:13-17` for symbol extraction. 17.4 would
add them to the main `Cargo.toml` for the minifier.

### 17.5 — Stem-agents: shared cached context + top-N files + cache breakpoints 🟡 Partial

**Original gap:** `CacheStemTracker` only measured; nothing enforced a shared
stem, injected top-N files, or set cache breakpoints correctly.

**Current state (partial):**
- `src/session/prompt/cache_stem.rs:38-50` now has `shared_context_stem()` that
  builds a `Vec<Message>` from system text + tool names + top-N file bodies.
  This is the enforcement path, not just measurement.
- `src/session/prompt/cache_stem.rs:23` defines `DEFAULT_TOP_N_FILES = 10`.
- **Still missing:** Anthropic `cache_control` breakpoints on the system+tools
  block and the last user message's last content block (the two key breakpoints
  vix sets). The current `cache_marker_indices` in `src/adapters/mod.rs` marks
  only the last 2 prefix messages and skips the trailing user message.
- **Still missing:** LLM summarizer behind a config flag (microcompaction is
  still heuristic-only in `src/session/prompt/microcompaction.rs`).

### 17.6 — Workflow engine parity ⏳ Open

**Original gap:** `kf-workflow` has only `agent` steps with `depends_on` and
`${var}` flat string interpolation. No `bash`/`tool` step kinds, no `fan_out`/
`fan_in`, no `if`, no `on_error`, no `budget`, no `fork_from`, no `$()`.

**Current state:** Still open. `src/tools/workflow.rs:129-137` `interpolate_vars`
does flat `${name}` substitution only. `TaskSpawnerStepRunner::run_batch`
(`workflow.rs:187-199`) is explicitly serial ("we do not fan out here"). The
`Step` struct in `kf-workflow` still has only `prompt`+`persona`+`depends_on`.

### 17.7 — Jobs↔workflow integration + alert persistence + per-job policy ⏳ Open

**Original gap:** `JobKind` has only `Bash` and a stub `Skill`; no `Workflow`
variant. No timezone in `Cron`. No per-job timeout/skip_if_empty/auto_write.
No persisted alert on failure. `Skill` stub says "not implemented".

**Current state:** Still open. `src/jobs/schedule.rs:53-61` still has
`JobKind::Bash { command }` and `JobKind::Skill { name, args }`. `Skill` at
`src/jobs/runner.rs:44-48` still returns "Skill scheduled jobs are not yet
implemented". `ScheduleSpec` has `Cron`, `Once`, `Restart` — no `tz` field.
No `timeout`, `skip_if_empty`, `auto_write`, `auto_dirs`, or `SpecFile` on
`ScheduledJob`. No persisted alert on failure (only ephemeral TUI notification).

### 17.8 — E2E test harness ⏳ Open

**Original gap:** No binary-driving harness, no mock provider server, no PTY
driver, no regression catalog.

**Current state:** Still open. `tests/` contains only `smoke_test.rs`,
`integration_test.rs` (Ollama live), and `mock_ollama.rs`. No `tests/e2e/`
directory. No mock provider that serves Anthropic/OpenAI-compat dialects. No
PTY/tmux driver. No regression catalog. In-process executor tests in
`src/session/executor/tests/` exercise `MockAdapter` but never spawn `kf-code`.

### 17.9 — TUI parity ⏳ Open

**Original gap:** No top tab bar, no threads overview, read-only tabs,
line-completion-only (no popups), no welcome screen.

**Current state:** Still open.
- `src/tui/widgets/tabs.rs` contains `render_models`, `render_plugins`,
  `render_jobs`, `render_settings` — all render read-only `Paragraph` dumps with
  "Use /command" hints. No `tab_bar_line` function exists.
- `src/tui/connection.rs` is an Ollama probe, not a daemon event stream.
- `src/tui/keys/mod.rs` `try_completion` does readline-style Tab completion.
- `src/tui/widgets/input.rs:87-95` renders one-line dim suggestions.
- No `SlashMenu`, no `FileCompleter`, no welcome screen widget.

## Deferred to Series 18 (with reason)

- **OS keychain storage + `kf-code auth login/logout` CLI + PKCE/device-code
  OAuth (Anthropic, OpenAI Codex, OpenRouter)** — each OAuth adapter is a large,
  provider-specific surface (PKCE, loopback callback server, RFC 8628 polling,
  token refresh). 17.1 unblocks the broken adapter with env keys; the full
  login/OAuth expansion is its own series.
- **OpenAI Codex adapter, OpenRouter adapter, Bedrock full credential chain
  (`aws-config`), data-driven provider catalog, `AuthProvider` registry** —
  new adapters / provider plumbing. Series 18 once 17.1's auth surface lands.
- **Whiteboard mode (Mermaid→positioned canvas, ASCII render, link injection,
  voice walkthrough)** — voice walkthrough is vendor-coupled (ElevenLabs);
  the rest is lower user-visible leverage than the 17.9 TUI basics. Series 18.
- **Self-update (`kf-code update`), in-app upgrade + re-exec, panic/crash
  reporting hook, remote analytics (device ID + opt-out), headless stream-json
  final-result + per-event `ts`, headless SIGINT handling, Homebrew formula,
  Dockerfile, cosign install verification** — release/ops polish, bundled as a
  Series 18 "ship & operate" set.
- **TUI: command palette (Ctrl+P), attachment panel, multi-question
  QuestionPanel, central theming system** — second-tier TUI features behind the
  17.9 set. Series 18.
- **Token efficiency: per-language annotators (Go semicolons, Python indent),
  formatter-gated write-back** — refinements on top of 17.4's AST minifier;
  fold in during 17.4 implementation if cheap, else Series 18.

## Notes
- The comparison was code-level, not marketing-level. "Watchers" in vix's
  README did not correspond to a real filesystem-watcher trigger type in
  `internal/daemon/jobs/spec.go` (only `cron` + `at`), so no gap was filed for
  it — both codebases lack a true fs-event trigger.
- vix is Go + Bubble Tea; kf-code is Rust + ratatui. Workorders specify Rust
  idioms (tokio, `subtle::ConstantTimeEq`, tree-sitter crate, `keyring` crate,
  `portable-pty`/tmux) — do not port Go patterns literally.
- Re-verify every file:line against HEAD before starting a workorder; the
  audit was a single snapshot and the repo moves fast.
- **17.1, 17.2, and 17.3 are shipped.** The auth resolver, Anthropic `x-api-key`
  header, daemon instance channel, broadcast, socket guard, constant-time auth,
  session ownership (`Claim`), `QuitAll`, and version handshake are all in HEAD.
  Workorders 17.1–17.3 remain as design docs but no longer require
  implementation.
- **17.5 is partially shipped.** The `shared_context_stem()` function and top-N
  files injection exist, but Anthropic cache breakpoints on the system+tools
  block and trailing user message, plus the LLM summarizer, are still open.
- **tree-sitter already exists** in `crates/kf-context-index` for symbol
  extraction. 17.4 should add it to the main `Cargo.toml` and reuse those
  grammars rather than vendoring fresh copies.
