# Workorder 17.9 — TUI Parity: Top Tab Bar, Threads Overview, Interactive Tabs, Slash/File Popups, Welcome

## Status: Done

## Problem
vix's TUI (`internal/ui/`) has several UX surfaces KirkForge lacks or does
worse, all verified in component code:

1. **No top tab bar.** `src/tui/widgets/tabs.rs:38` `tab_bar_line` is dead
   code; `src/tui/widgets/status.rs:16-33` renders only the *active* tab label
   in the bottom bar. The user never sees the full F1–F5 set at once. vix
   draws a full top tab bar (`tabs.go:renderTabBar:1378-1467`).
2. **No threads overview.** KirkForge's only thread-ish UI is
   `src/tui/components/session_picker.rs` (saved sessions for `/resume`).
   vix has a Threads tab with User/Vix-initiated groups, unread dots,
   "Waiting for input" badges, busy spinners (`tabs.go:renderThreadsView:136-393`).
3. **Read-only tabs.** `src/tui/widgets/tabs.rs:42-396`
   `render_models`/`render_plugins`/`render_jobs`/`render_settings` are
   read-only `Paragraph` dumps ending in "Use /reload", "Use /plugins toggle"
   hints — every change needs a slash command. vix's tabs are interactive
   (toggle rows, sliders, type-to-filter, space-to-enable) (`tabs.go:649-681,838-964,1100-1376`).
4. **Line completion, not popups.** `src/tui/keys/mod.rs:848-927`
   (`try_completion`) + `src/tui/widgets/input.rs:87-95` (`render_suggestions`)
   do readline-style Tab completion — one match replaces the buffer, multiple
   print a dim one-line join. vix has a filterable `SlashMenu` popup
   (`slashmenu.go:73-327`) and a `FileCompleter` directory-browser popup for
   @-mentions (`filecompleter.go:53-291`).
5. **No welcome/recent-dirs screen.** KirkForge goes straight into chat; cwd
   is only visible via the session log path. vix shows a welcome screen with
   banner, version, cwd, a navigable Recent dirs list, and a Ctrl+O dir
   picker (`welcome.go:renderWelcomeInline:44-151`).

## Root cause
The TUI grew bottom-bar status + readline completion as the cheap option; the
richer overlay/tab surfaces were never built. The `rendering/table.rs`
`ListState` infrastructure already exists for interactive lists — it's unused
on the tabs.

## Approach
1. **Top tab bar first.** It's a render change with the dead `tab_bar_line`
   already half-written; resurrect it. Biggest "where am I" win for the least
   code.
2. **Interactive tabs via existing `ListState`.** Don't invent a widget
   framework — `src/tui/rendering/table.rs` already has `ListState`. Wire ↑/↓
   to it and Enter/Space to the underlying `/command`. The slash commands stay
   as the keyboard shortcut; the tabs gain pointer-free selection.
3. **Slash menu + file completer as popups, not readline.** Both render as a
   bordered box above the input (mirror `render_search_bar`); both are
   `Option<…>` on `AppState` so they're absent when not active. Reuse the
   existing command table / `read_dir` data — only the *rendering* changes.
4. **Threads tab needs 17.2.** It consumes `ThreadsChanged` events; without
   the instance channel it's a static list. Land the tab bar + interactive
   tabs + popups + welcome independently; the threads tab is the one item that
   depends on 17.2.
5. **Welcome is a render gate, not a mode.** Show it only when
   `messages.is_empty() && input.is_empty()`; any keystroke into the input
   dismisses it. No new app state machine.

## Done condition
- A persistent top tab bar shows all F1–F5 (and F6 Threads if added) with the
  active tab highlighted; the bottom status bar no longer carries the tab label.
- The Models/Plugins/Jobs/Settings tabs are interactive: ↑/↓ selects, Enter/Space
  toggles or invokes the underlying action — no "Use /command" hint lines.
- A slash-command popup filters the command table, navigates with ↑/↓, and
  inserts on Enter (replacing the dim one-line suggestion list).
- An @-mention file-completer popup browses directories with descend/parent.
- A welcome screen (banner + cwd + Recent dirs) shows on a fresh session and
  dismisses on first input; Ctrl+O opens a directory picker.
- The Threads tab (if landed) lists active forks/sessions with status, fed by
  17.2's events.
- Depends on: 17.2 (for the Threads tab's live events). Everything else in
  this WO is independent.
