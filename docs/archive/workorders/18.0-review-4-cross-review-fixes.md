# Workorder 18.0 — Review-4 Fix Verification, Cross-Review Findings, and Remaining Gaps

## Status: Planned

## Problem

Review-4 identified 22 findings (2 Critical, 10 High, 22 Medium, 11 Low). Post-review
commits fixed 21 of them and partially fixed 3. Two independent external reviews (GPT
and Claude Sonnet) then reviewed the same codebase and independently found a critical
bug that review-4's C1 fix *missed*: the runtime gate for budget tool/hook registration
uses `"kf-plugin-sdk3"` instead of `"kf-budget"`, making the entire budget subsystem
silently dead on default builds. The external reviews also flagged a design gap
(startup-only toggle, no live re-registration for compiled-in tools) and a test gap
(no integration test asserts budget tools are present after boot).

This workorder consolidates all remaining open findings, all partial fixes that need
completion, and all new findings from the cross-review.

## New findings from cross-review (GPT + Sonnet)

### 🔴 Critical — budget subsystem silently dead on default builds

**18.0.1 Runtime gate uses wrong plugin name for budget tools/hooks**

Both external reviews independently found this. Review-4's C1 fix changed
`folded_feature_enabled()` in `loader.rs` from `"kf-plugin-sdk3"` to `"kf-budget"`,
but **four separate runtime gates** still use the wrong name:

```
src/main/run_session.rs:543-544
    .any(|n| n == "kf-plugin-sdk3")
    && !cfg.tools.disabled_plugins.contains("kf-plugin-sdk3")

src/session/executor/mod.rs:237-238   (hook registration)
    .any(|n| n == "kf-plugin-sdk3")
    && !cfg.tools.disabled_plugins.contains("kf-plugin-sdk3")

src/session/executor/mod.rs:636-637   (hot-reload re-registration)
    .any(|n| n == "kf-plugin-sdk3")
    && !cfg.tools.disabled_plugins.contains("kf-plugin-sdk3")
```

The canonical name per `FOLDED_PLUGINS` and `default_plugin_sources()` is `"kf-budget"`.
Nothing in the codebase ever inserts `"kf-plugin-sdk3"` into `enabled_plugins`, so
these gates evaluate to `false` unconditionally. The result: **the entire budget
subsystem (tools + hooks) never registers on any default build**.

The string `"kf-plugin-sdk3"` is a merge artifact from the kirkforge → kf-code rename
sprint — it conflates `"kf-plugin-sdk"` (the Node SDK rename) and `"plugin3"` (budget's
old name). It also has a stale code comment at `executor/mod.rs:230` claiming this is
"the correct name for the folded budget plugin."

Impact: any user relying on budget tracking, token limits, or session-start hooks from
the budget plugin gets nothing. `/plugins toggle kf-budget` and `/plugins list` show
`kf-budget` — the name a user would actually interact with — but the gate is keyed to a
nonexistent string.

Fix: replace all four `"kf-plugin-sdk3"` with `"kf-budget"`.

Verified against `FOLDED_PLUGINS` table at `loader.rs:41-44`:
```rust
const FOLDED_PLUGINS: &[(&str, &str)] = &[
    ("stratum", "stratum"),
    ("kf-budget", "budget"),   // <-- the real name
    ("kf-draw", "draw"),
    ("kf-video", "video"),
];
```

And `default_plugin_sources()` in `shared/config/tools.rs` seeds `enabled_plugins`
with `"kf-budget"`.

### ⚠️ Design — startup-time toggle, not live

**18.0.2 Compiled-in plugin toggle requires restart**

The WO 15.7 runtime gate (`enabled_plugins` / `disabled_plugins` check) is
startup-time only. `toggle_plugin()` in the TUI (`src/tui/commands/plugins/mod.rs:555`)
writes config and calls `reload_plugins()`, which reloads the **external** plugin
registry but does **not** re-run the compiled-in toolset registration that happened
once at process start in `run_session()` and `Executor::new()`.

This is a reasonable design (most CLI tools require restart for this class of
setting) — but it should be documented in the `/plugins toggle` output. Currently
the toggle message is:

```
🔌 Plugin 'kf-budget' is now disabled.
```

It should say something like:

```
🔌 Plugin 'kf-budget' is now disabled (takes effect on next launch for compiled-in tools).
```

### 🔴 Test gap — no integration test for budget registration

**18.0.3 No test asserts budget tools/hooks are present after default boot**

The 2879-passing test gate did not catch 18.0.1 because no test boots with default
config and asserts that budget tools appear in the registered toolset, or that
budget hooks fire on session start / post-tool. This is a systemic gap: the folded
plugin path has tests for the loader and the plugin system, but no end-to-end test
for the full registration chain.

Fix: add an integration test that constructs a `CompositeToolset` with default
config (`enabled_plugins` containing `"kf-budget"` with the `budget` feature
enabled) and asserts that budget tools are present.

### 🟡 Stale reference in budget.rs comment

**18.0.4 `budget.rs` module doc references `plugins/kf-plugin-sdk3/tools/`**
