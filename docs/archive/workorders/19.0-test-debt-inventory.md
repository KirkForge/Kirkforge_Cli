# Workorder 19.0 — Test Debt Inventory: Monoliths, Shallow Tests, and Dead Infrastructure

## Status: Planned

## Problem

The codebase has ~3,735 `#[test]` + 806 `#[tokio::test]` attributes across 2,043 in `src/` and
1,688 in `crates/`. The numbers look healthy. The depth is not. Review-4's critical bug
(`kf-plugin-sdk3` runtime gate) shipped through 2,879 passing tests because no test
boots with default config and asserts the budget tools are present. The testdoctor
scans 3 of 20+ source directories. Nine separate subsystems have only shallow unit
tests with zero integration coverage. The largest test file is 5,183 lines.

This is the single workorder that defines the whole problem. Subsequent WOs (19.1–19.9)
address specific pieces. Read this first, then pick a WO.

### Tests with no assertions (~90)

The worst clusters:

- **kf-compress-cli/tests/integration.rs**: 33 tests that check exit codes or output
  but never assert on the output content. They're "does not panic" tests in disguise.
- **kf-plugin-sdk/src/lib.rs**: 13 validation tests that call `.validate()` and expect
  `Err` but the test bodies just call `assert!(manifest.validate().is_err())` — these
  are fine (they DO assert), the explorer counted them as no-assertion because the
  assertion is on the same line as the test function.

Actually-weak tests (no meaningful assertion about behavior):
- ~40 tests in `session/` and `tui/` that are `_does_not_panic` or `_is_noop` — they
  prove nothing about correct behavior, only absence of crashes.
- ~20 tests in `kf-compress-cli` that check subprocess exit codes but not output content.

### Testdoctor shortcomings

1. **Scans 3 of 20+ directories.** `DEFAULT_DIRS = ["src/session", "src/tools", "src/adapters"]`.
   Misses `src/tui` (388 tests), `src/daemon` (3), `src/jobs` (18), `src/main` (19),
   `src/shared` (143), and all 16 crates (1,688 tests).
2. **No CLI flag to add directories.** Can't say `doctor diagnose --dirs src/tui,crates/kf-draw`.
3. **Only counts `pub fn/struct/enum/trait` at line start.** Misses `pub const`, `pub type`,
   methods in `impl` blocks, `pub mod` re-exports.
4. **No cross-reference with coverage data.** `diagnose` is purely static (line counting).
   The `gaps` command reads Cobertura XML but they don't talk to each other.
5. **Test density is a crude metric.** Counts `#[test]` per line, not per public API surface.
6. **`suggest-detailed` resolves source paths by guessing.** Falls back to v1 text suggestions
   when the binary name doesn't match the filesystem path.
7. **`gaps` drift guard may break.** The `default_thresholds_match_ci_yml` test looks for a
   `targets = {` line format that doesn't exist in the CI YAML.

### Flaky test markers

7 locations explicitly mention flakiness or race conditions. Two tests are `#[ignore]`d
for timing sensitivity. The `init.rs:611` comment acknowledges CI flakiness.

### Duplicate test helpers

6 helper functions are duplicated across 2–3 files: `make_state`, `make_ctx`,
`test_state_with_log`, `make_config`, `test_session_start_hook_returns_allow`,
`test_state`. A shared test-support module would eliminate the duplication.

### Ignored tests

17 total: 6 need Ollama, 2 need Docker, 2 need Chrome, 3 spawn subprocesses,
1 is timing-sensitive, 2 need real CPU/rlimits, 1 needs display server.

## Prioritized fix sequence

The WOs below are ordered by impact. Each addresses one focused thing.

- **19.1** — Testdoctor: full workspace coverage + cross-reference with `gaps`
- **19.2** — Test doctor `diagnose` depth: public API surface, not just line counting
- **19.3** — Test monolith surgery: split the 3 worst offenders
- **19.4** — Kill no-assertion tests: upgrade or delete
- **19.5** — Integration test gaps: daemon RPC, jobs lifecycle, plugin registration
- **19.6** — E2E TUI scenarios: use the existing TmuxDriver harness
- **19.7** — Shared test support module: de-duplicate helpers
- **19.8** — Testdoctor `suggest` upgrade: crate-aware path resolution
- **19.9** — Flaky test stabilization: address the 7 acknowledged flakes
