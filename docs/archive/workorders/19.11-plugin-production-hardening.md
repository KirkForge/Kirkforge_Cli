# Workorder 19.11 — Plugin Plumbing: Production Hardening

## Status: In Progress

## Problem

WO 19.10 audit passed (zero medium/critical findings) but identified 5 honest
gaps that prevent the plugin modules from being peak production level:

1. **Silent file I/O in video session integration** — `src/session/video.rs`
   swallows `create_dir_all` errors on artifact-creation paths (not cleanup).
   A missing project directory silently proceeds, then fails downstream in
   ffmpeg with a confusing error instead of surfacing the real cause.

2. **`eprintln` vs `tracing` in `kf-budget-core`** — the crate uses
   `eprintln!` for error reporting because it has no `tracing` dependency.
   In production with log aggregation, these are unstructured stderr noise
   that bypass the session-scoped tracing pipeline.

3. **`eval_condition` fail-open semantics** — a typo in a workflow condition
   silently skips the step instead of surfacing as a workflow error. The
   `tracing::warn` added in WO 19.10 helps but the step still silently
   vanishes from the workflow plan.

4. **4 stub host modules in `kf-budget-hosts`** — `claude_code.rs`,
   `cursor.rs`, `aider.rs`, `kf_code_host.rs` each contain only a
   `stub_present` test. Per ADR-0013 this is intentional: the real payload
   handling lives in `kf-budget-cli::hooks` which consumes canonical types
   directly. The stubs are honest placeholders that keep the crate layout
   honest and will grow when a second host needs support. **No code change
   needed** — this is an ADR-pinned design decision.

5. **No integration test for folded plugin lifecycle** — no test boots a
   session with default config, runs a turn, and verifies hooks fire with
   correct payloads. The 18.0.1 bug proved this gap is real.

## Fix

### 19.11.1 — Surface video file I/O errors

Replace `let _ = std::fs::create_dir_all(parent)` with proper error
propagation in `src/session/video.rs` at 5 sites (lines 196, 206, 323,
330, 516). Return a `ToolOutcome::Error` with a clear message when the
project directory cannot be created.

### 19.11.2 — Add `tracing` to `kf-budget-core`

Add `tracing.workspace = true` to `crates/kf-budget-core/Cargo.toml`.
Replace all `eprintln!("kf-budget: ...")` calls with `tracing::warn!`
or `tracing::error` as appropriate. Keep the crate's zero-new-dep
constraint — `tracing` is already a workspace dependency used everywhere
else.

### 19.11.3 — eval_condition: return `Result<bool>`

Change `eval_condition` from `async fn eval_condition(condition: &str) -> bool`
to `async fn eval_condition(condition: &str) -> Result<bool>`. Callers
already have error-handling context; this lets a shell-exec failure
bubble up as a workflow error rather than silently skipping a step.

### 19.11.4 — Stub host modules: no change (ADR-0013 design)

The 4 stub modules are honest placeholders per ADR-0013. The canonical
payload types are fully implemented and consumed by `kf-budget-cli::hooks`.
The stubs exist to prevent a future contributor from adding host-specific
code in the wrong place. Marked as "accepted" in WO 19.10.

### 19.11.5 — Plugin lifecycle integration test

Add a test in `src/session/plugin_tools/tests.rs` that:
1. Creates a `CompositeToolset` with default config (budget + stratum + draw)
2. Asserts budget tools (`budget_status`, `budget_set`) are present
3. Asserts stratum tools (`stratum_run`, `stratum_apply`) are present
4. Asserts `folded_feature_enabled("kf-budget")` returns true
5. Asserts `folded_feature_enabled("nonexistent")` returns false
