# Workorder 20.0.3 — Over-Engineering Removal: Collapse Unnecessary Abstractions

## Problem

Several abstractions add complexity without adding value: traits with one impl,
config structs for constants, 3-layer chains that should be 2.

## Targets

### E1. `TaskSpawner` trait — one impl, dyn dispatch for zero gain (HIGH)

`src/session/executor/mod.rs` — `TaskSpawner` trait has exactly one
implementation (`TokioTaskSpawner`). The trait exists solely to allow test
injection, but the test impl does the same thing as the production impl
(`tokio::spawn`). No test currently uses a different `TaskSpawner`.

**Fix:** Replace `dyn TaskSpawner` with a concrete `TokioTaskSpawner` struct.
If test injection is needed later, add it then. Delete the trait.

### E2. `RouterConfig` — mirrors 2 fields from `ModelConfig` (MEDIUM)

`src/session/router.rs` — `RouterConfig` holds `primary_model` and
`fallback_model`, which already live in `ModelConfig`. It's constructed in
one place and passed to `Router::new()`.

**Fix:** Remove `RouterConfig`. `Router::new()` takes the two fields directly.

### E3. `SummarizerConfig` — defaults never used (MEDIUM)

`src/session/prompt/summarizer.rs` — `SummarizerConfig` has defaults for
`max_tokens`, `model_override`, etc. The sole call site overrides all of them.

**Fix:** Remove `SummarizerConfig`. Pass the 2-3 relevant fields as params to
`summarize()`.

### E4. `CorrectionLoop → VerifierHandler → VerifierSlots` — 3-layer chain (MEDIUM)

`src/session/verifier/` — `CorrectionLoop` delegates to `VerifierHandler`
which delegates to `VerifierSlots`. The handler is a thin pass-through.

**Fix:** Merge `VerifierHandler` into `CorrectionLoop`. Two layers instead of
three.

### E5. `DockerConfig` / `SandboxConfig` — const values disguised as config (MEDIUM)

`src/session/sandbox.rs` — `DockerConfig.image`, `memory`, `cpus` never vary
at runtime. Same for `SandboxConfig.cpu_limit_secs`, `memory_limit_mb`,
`filesize_limit_mb`. These are constants dressed as fields.

**Fix:** Replace with `const` values. If runtime config is needed later, add it
then.

### E6. Dead enum variants and misleading names (LOW)

- `TruncationStrategy` has 2 dead variants never constructed — remove them
- `ToolCallStyle::None` never used — remove
- `ModelConfig.seed` always `None` — remove field
- `ModelConfig.summarize_enabled` redundant with `compaction_use_llm` — remove one
- `ToolRegistry` wraps a `Vec` — consider exposing the Vec directly or giving it meaningful methods
- `ToolContextBuilder` — misleading name for what's a simple struct constructor
- `build_recovery_message` — factory for one shape, inline it
- `adapter_kind_for` — one-liner delegation, inline it
- `default_verifier_bus` — one-liner constructor, inline it

### E7. BusVerifier / VerifierBus duplicate subsystem (evaluate, do NOT delete yet)

`src/session/verifier/bus.rs` — `BusVerifier`/`VerifierBus`/`VerifyContext`/
`Severity`/`VerdictEntry`/`VerifierSource` is a parallel system to the existing
`Verifier` trait. Only plugin verifiers use it. It starts empty and adds
complexity without clear value over the `Verifier` trait path.

**Action:** Evaluate whether plugin verifiers can use the existing `Verifier`
trait. If yes, plan a migration WO. If no, document why both exist in a comment
at the top of `bus.rs`. Do NOT delete without evaluation — this is
architectural, not mechanical.

## Verification

- Each removal compiles and passes all gates
- `cargo clippy --all-targets` clean
- No test changes needed (tests should be using concrete types or the remaining
  abstraction)
