# Workorder 20.0.4 — Error Handling Consistency

## Problem

Mixed error patterns across the codebase: `anyhow` in some places, typed
errors in others, raw `.unwrap()` on API responses, and `KirkForgeError`
classifying errors by string matching.

## Targets

### R1. `KirkForgeError` string-based classification (MEDIUM)

`src/main/error.rs:70-91` — Error classification uses `msg.contains("denied")`,
`msg.contains("rate")`, etc. Rephrased error messages silently fall into
`General`. The TODO at line 67 says "replace with further downcast_ref checks."

**Fix:** Add typed error variants for each category. Replace string matching
with `downcast_ref::<SpecificError>()`. This is incremental — add one typed
error at a time, don't rewrite everything at once.

### R2. `.unwrap()` on streaming API responses (HIGH)

`src/adapters/openai_compat/mod.rs:646,773`,
`src/adapters/ollama_ndjson.rs:992,1005`,
`src/adapters/anthropic.rs:246,764,768,770,772,777,782`

Malformed API responses will panic the process. Streaming paths should be
resilient, not crash.

**Fix:** Replace each `.unwrap()` with `.ok_or_else()` returning a
`ToolError::Internal` or `.context()` with a descriptive message. This is
safety-critical — a bad API response should produce an error in the stream, not
crash the process.

### R3. Poisoned `RwLock` panics (MEDIUM)

`src/tui/commands/jobs.rs:524`, `src/daemon/server.rs:483,520`,
`src/tui/commands/plugins/mod.rs:828,953`

`.unwrap()` on `RwLock::write()` panics on poison. The project already has
`read_shared_config()`/`write_shared_config()` in `shared/mod.rs`.

**Fix:** Replace all 5 sites with the poison-safe helpers.

### R4. `thiserror` dependency unused (LOW)

`Cargo.toml:51` — `thiserror = "1"` is a dependency but zero source files use
it. All error types use manual `Display`/`Error` impls.

**Fix:** Either adopt `thiserror` for `KirkForgeError`, `McpError`, `ShellError`,
`ToolError` (incremental — one type per PR), or remove the dependency.

### R5. `McpError` missing `std::error::Error` impl (LOW)

`src/session/mcp_client/error.rs:7-40` — Has manual `Display` impl but no
`Error` impl. Gets converted to `ToolError` at boundary.

**Fix:** Add `impl std::error::Error for McpError {}` or use `thiserror`.

### R6. Hybrid error pattern in tools (MEDIUM)

`src/tools/edit_file.rs:386`, `src/tools/write_file.rs:165`,
`src/tools/workflow.rs` — Internal helpers return `anyhow::Result`, then wrap
into `ToolOutcome::Failure(ToolError::...)` at boundary. Same file mixes
`anyhow::anyhow!()` and `ToolError::InvalidArgs { ... }`.

**Fix:** Internal helpers should return `Result<T, ToolError>` directly.
Remove the `anyhow` → `ToolError` wrapping layer.
