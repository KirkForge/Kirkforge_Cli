# Workorder 20.0.6 — Module Merges & Dead Code Cleanup

## Problem

Several modules are over-split (thin wrappers that should fold into their
parent) and several items are marked `#[allow(dead_code)]` that are genuinely
dead or should be `#[cfg(test)]`.

## Targets

### M1. Merge `adapters/cache.rs` + `adapters/caching.rs` (MEDIUM)

`cache.rs` defines `ResponseCache`. `caching.rs` wraps it with a thin
`ModelAdapter` layer (~128 lines). All external code imports from
`caching.rs`. Two files for one concept.

**Fix:** Merge `cache.rs` into `caching.rs`. Result: ~1100 lines, one module.

### M2. Merge `tools/bash_cancel.rs` + `tools/bash_status.rs` into `bash.rs` (MEDIUM)

Both are 95-111 lines of identical boilerplate (imports, Tool trait impl, arg
parsing). Both import `bash_jobs::global_registry`. Always registered together
in `tools/mod.rs`.

**Fix:** Move both into `bash.rs`. Result: ~1413 lines, one module for all bash
tool variants.

### M3. Merge `shared/backoff.rs` into `shared/mod.rs` (LOW)

41 lines, one exported function (`retry_backoff`), 2 callers. Already
re-exported from parent.

**Fix:** Inline into `shared/mod.rs`. Delete the file.
