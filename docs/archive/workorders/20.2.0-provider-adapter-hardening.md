# Workorder 20.2.0 — Provider & Adapter Hardening

## Source

Cross-review §4.2 + P0-2 + P0-3.

## Problem

Two of six advertised providers (Bedrock, Vertex) are unwirable. Cache
breakpoints explode past Anthropic's limit. Key features (tool_choice,
extended thinking, native Gemini) are missing. Keychain auth is stubbed.

## Targets

### P1. Bedrock + Vertex config plumbing (CRITICAL)

- `adapter_for_with_provider` (`src/adapters/mod.rs:442-457`) hardcodes
  Bedrock region `"us-east-1"` and Vertex `project_id = ""`,
  `region = "us-central1"`, `service_account = None`
- Config fields `aws_region`, `aws_profile`, `gcp_project_id`, `gcp_region`,
  `gcp_service_account_path` are parsed, documented, unit-tested — and never
  plumbed through
- Vertex URL emits `projects//locations/us-central1/...` — malformed
- 5 call sites need updating: `run_session.rs:234`, `adapter_swap.rs:75,119`,
  `bench.rs:179`, `task.rs:307`
- **Fix:** Add provider config params to `adapter_for_with_provider`. Update
  all 5 call sites. Add smoke test: construct Bedrock/Vertex adapter with
  non-empty config, verify URL is well-formed.

### P2. Cap Anthropic cache breakpoints at 4 (CRITICAL)

- `src/adapters/anthropic.rs:201-231` marks every prefix message with
  `cache_control`, plus last system block, last tool, tail
- 20-message conversation ≈ 21 breakpoints. Anthropic hard limit is 4
- Short-conversation tests pass (3-4 messages); bug only fires in production
- **Fix:** Count breakpoints before sending. Prioritize system + tools + last 2
  user messages. Strip `cache_control` from low-priority messages.

### P3. Keychain auth is stubbed to `None` (HIGH)

- `src/adapters/auth.rs:31-35` — keychain path returns `None`
- `keyring` crate is a dependency but never wired
- **Fix:** Implement `keyring::Entry` integration or remove the stub and
  document that keychain auth is not available.

### P4. `tool_choice` forcing (MEDIUM)

- Only `"auto"` is ever set for `tool_choice`
- Claude Code, opencode, Codex CLI can force a specific tool
- **Fix:** Add `tool_choice: Option<ToolChoice>` to the adapter trait request
  struct. Wire through Anthropic (`tool_choice: {type: "tool", name: X}`) and
  OpenAI (`tool_choice: {type: "function", function: {name: X}}`).

### P5. JSON-schema structured outputs (MEDIUM)

- Only `{type: "json_object"}` mode supported
- No JSON-schema output validation
- **Fix:** Add `response_format: Option<ResponseFormat>` to the request
  builder. Implement `JsonSchema` variant for Anthropic and OpenAI.

### P6. Extended thinking request (MEDIUM)

- `supports_thinking` flag exists but `build_anthropic_body` never emits
  `thinking:{...}`
- Code parses thinking blocks from responses but never requests them
- **Fix:** When `supports_thinking && config.extended_thinking`, emit
  `thinking: {type: "enabled", budget_tokens: N}` in the Anthropic request.

### P7. `Anthropic max_tokens` hardcoded to 8192 (LOW)

- `src/adapters/anthropic.rs` — max_tokens is a constant
- Should be configurable per model
- **Fix:** Make `max_tokens` configurable via Config or model info.

### P8. Native Gemini provider (LOW)

- Currently only via Ollama proxy (`oellama.rs:109,193,204`)
- "Six providers" marketing collapses Gemini/DeepSeek/GLM/Kimi into one
  Ollama-shaped adapter
- **Fix:** Add first-party Gemini adapter or document that Gemini requires
  Ollama proxy.

### P9. AWS profile/SSO/instance-metadata auth (LOW)

- `bedrock_signing.rs:8-14` — only static env-var creds
- No AWS profile, SSO, or instance-metadata support
- **Fix:** Use `aws-config` crate for credential resolution chain, or document
  the limitation.

## Verification

- Bedrock adapter constructed with non-empty config produces well-formed URL
- Vertex adapter constructed with non-empty config produces well-formed URL
- Anthropic cache breakpoints never exceed 4 in any conversation length
- `tool_choice: {type: "tool", name: X}` forces tool use in Anthropic + OpenAI
- Extended thinking requested when config enables it
- `cargo test --workspace` green
