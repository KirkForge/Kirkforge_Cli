# Workorder 20.5.0 — Tool Surface Improvements

## Source

Cross-review §4.3.

## Problem

Several tool gaps cause daily friction for users. `grep` is literal-only,
`bash` can't handle interactive commands, `edit_file` lacks replace_all,
`web_fetch` loses structure, and MCP is tools-only.

## Targets

### T1. Add regex support to `grep` (HIGH)

- `grep.rs:186` — `line.contains(pattern)`, literal substring only
- Cannot do `fn\s+\w+`, case-insensitive, or scoped search
- Daily friction for a coding agent
- **Fix:** Use the `regex` crate (already a transitive dep) when pattern
  contains regex metacharacters. Add `--regex` flag to tool definition.
  Preserve literal mode as default for simple patterns.

### T2. Add PTY + streaming to `bash` (HIGH)

- `bash_runner/mod.rs:397-479` — no PTY, no stdin, no streaming
- `npm login`, `gh auth login`, `python -i`, password prompts all hang
- **Fix:** Add `portable-pty` or equivalent as optional dep. Gate behind
  `--interactive` flag. Preserve current non-interactive mode as default.
  Stream stdout/stderr in real-time.

### T3. Add `replace_all` / multi-edit to `edit_file` (MEDIUM)

- Refactors touching N identical call sites require N tool calls
- Claude Code supports `replace_all` in its edit tool
- **Fix:** Add `replace_all: bool` to `edit_file` args. When true, replace
  all occurrences of the old string in the file. Preserve unique-match
  enforcement as default.

### T4. HTML→markdown is regex tag-stripping (MEDIUM)

- `web_fetch.rs:370-395` — loses headings, lists, tables, code fences
- Returns plain text, not markdown
- **Fix:** Use `html2text` crate (or add as dep) for structured HTML→markdown
  conversion. At minimum, preserve headings, code blocks, and tables.

### T5. MCP resources/prompts/sampling (MEDIUM)

- MCP only supports `tools/list` + `tools/call`
- `resources/*`, `prompts/*`, `sampling/createMessage`, `roots/list` all
  not implemented
- Comment at `mcp_client/mod.rs:95` falsely claims "reading resources"
- **Fix:** Implement `resources/list` + `resources/read` (most impactful).
  Add startup warning when a server advertises unsupported capabilities.
  Defer `prompts/*` and `sampling/*` to later WO.

### T6. Tool schema validation (LOW)

- Tool argument schemas are hand-written JSON
- No validation that `args` matches `def().parameters` before `run()`
- **Fix:** Add JSON-schema validation at dispatch time. Reject malformed
  args with a clear error message.

### T7. `computer_use` ~80-line duplication (LOW)

- `computer_use.rs` has `run_on_tab`/`run_on_session_sync` duplication
- Covered in WO 20.0.2 as a duplication target
- **Fix:** Extract shared `with_browser_session` helper.

### T8. No Anthropic computer-use beta (LOW)

- Local `computer_use` tool is headless-Chrome DevTools, not the Anthropic
  `computer_*` beta
- **Fix:** Document clearly that this is local-only. If Anthropic computer-use
  beta is needed, add a separate adapter.

## Verification

- `grep --regex "fn\\s+\\w+" src/main.rs` returns regex-matched results
- `bash --interactive` supports PTY commands (e.g., `python -i`)
- `edit_file --replace_all "old" "new"` replaces all occurrences
- `web_fetch` preserves headings and code blocks in markdown output
- MCP server advertising `resources` gets a warning, not a crash
- Malformed tool args produce a clear validation error
