# Workorder 21.9 — Engineering-Discipline Debt

## Status: Done

## Problem

The honesty culture is the project's standout asset (best-in-class ADR drift
tests, PONYTAIL-DEBT ledger, real eval harness) — but several discipline items
are still open and one of them is **gating all of CI**: the latent
`tui::approval_keys` test deadlock that forced every workflow to be renamed
`.disabled`. The rest is ADR/doc drift that the honesty tests do not catch
(because `adr_xref_drift` checks cross-reference consistency, not path-literal
existence), a coverage floor still under target, thin fuzzing, a stale WO
Status, and the remaining dead-code + overclaim tail. This workorder closes
them with explicit done/fail signals.

### 21.9-R4 — Fix `tui::approval_keys` deadlock + un-quarantine CI (HIGH · est S · dep: —)

**Reality check (`a870571`):** "🔴 CI test-step deadlock (root cause of the

`:125,:130`) with a "TODO: fix the source, then REMOVE this filter" note
(`:116`).

**Scope:** `src/tui/approval_keys.rs:205-207` (insert `drop(cfg);` between the
write and the read), `.github/workflows/ci.yml:99-130` (remove the
quarantine filter so the four tests run again).

**Success (done):**
- The deadlock is fixed at the source — `drop(cfg);` (or an equivalent
  guard-release) is inserted so the write lock is released before the read —
  and the four tests
  (`test_always_approves_dedups_repeated_calls`,
  `test_always_approves_edit_file_uses_path_key`,
  `test_always_approves_saves_permission_rule`,
  `test_always_approves_does_not_overwrite_existing_deny`) pass WITHOUT the

  the closing commit's CI run is green on the full suite.

**Failure (regression / not-done):**

  FAIL (the one-line fix is the deliverable; the quarantine is the disclosed

- Tests "pass" only because they were deleted or `#[ignore]`'d = FAIL (AGENTS.md
