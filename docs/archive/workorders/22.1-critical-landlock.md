# Workorder 22.1 — Critical: Fix Non-Functional Landlock Sandbox

## Status: Planned

## Problem

The landlock sandbox implementation (`src/session/bash_runner/landlock.rs`, untracked) has three independent ABI bugs that cause `landlock_add_rule` to return `EINVAL` on every kernel. The code bails before `landlock_restrict_self` — zero confinement is applied. The tests are vacuous (dropped `TempDir` makes assertions pass regardless). state.md marks this "DONE."

This is a ship-blocking security bug. The "verification-first" moat claims sandbox confinement on Linux; the reality is zero confinement.

## Reality-check

`landlock.rs:31-36` struct `landlock_path_beneath_attr` has:
- Extra `rule_type: u64` field (belongs in syscall arg, not struct)
- Wrong field order (kernel: `allowed_access, parent_fd`; code: `rule_type, parent_fd, allowed_access`)
- Not `#[repr(C, packed)]` (24 bytes vs kernel 12 bytes)

`landlock.rs:79-85` syscall args swapped: `(&attr, size_of)` where `(RULE_PATH_BENEATH as i32, &attr)` should be.

`landlock.rs:39-40` access flags: `ACCESS_FS_READ` includes WRITE_FILE (1<<1); `ACCESS_FS_WRITE` excludes it.

Tests (`landlock.rs:191-226`) use `tempfile::tempdir()` whose `TempDir` drops before assertion — `!outside.exists()` passes because parent dir was deleted.

`state.md:48` claims "DONE — landlock wired... 3 tests passing" and "+ network egress block" — both false (no CLONE_NEWNET by default, landlock doesn't apply).

## Scope

1. `src/session/bash_runner/landlock.rs` — full rewrite of struct, syscall, flags, allow-list, tests

3. `src/session/bash_jobs.rs` — background path wiring
4. `src/session/executor/sandbox.rs` — doc update (remove false "landlock confinement" claim until tests pass)
5. `state.md` — fix 21.7-R1 status
6. `docs/workorders/21.7-sandbox-trust.md` — update R1 status

## Success criteria

1. `landlock_path_beneath_attr` is `#[repr(C, packed)] struct { allowed_access: u64, parent_fd: i32 }` (12 bytes)
2. `landlock_add_rule` called as `syscall(ADD_RULE, ruleset_fd, RULE_PATH_BENEATH as i32, &attr as *const _, 0u32)`
3. `ACCESS_FS_READ` excludes WRITE_FILE (1<<1); `ACCESS_FS_WRITE` includes it. All bit assignments match `linux/landlock.h`.
4. `add_path` failure for workspace dir → fatal (log error, close fd, do NOT call `restrict_self`, abort bash launch per WO 21.7-R5)
5. `add_path` failure for system/home dirs → skip (log warning, continue)
6. `restrict_self` failure → fatal (abort bash launch)
7. `/dev`, `/proc` added to `SYSTEM_READ_DIRS` (read-only for `/proc`; read-write for `/dev/null`, `/dev/zero`, `/dev/tty`, `/dev/urandom` — grant `ACCESS_FS_ALL` for `/dev` or use per-file fds)
8. Home dir granted `ACCESS_FS_ALL` (not just READ) — `cargo`, `rustup`, `npm` need to write `~/.cargo/`, `~/.local/`, `~/.config/`
9. XDG dirs (`XDG_CACHE_HOME`, `XDG_DATA_HOME`, `XDG_CONFIG_HOME`) granted `ACCESS_FS_ALL`
10. No heap allocation in pre_exec closure — env vars resolved in parent process, passed as owned `PathBuf`
11. Both foreground (`mod.rs`) and background (`bash_jobs.rs`) paths wired
12. Test `landlock_blocks_write_outside_workspace` uses a kept-alive `TempDir`, writes to `$outside/file.txt`, asserts the write was blocked (file not created or `EACCES`/`EPERM`)
13. Test `landlock_allows_read_everywhere` reads `/dev/null`, `/etc/hostname`, `/tmp` — asserts success
14. Test `landlock_allows_write_in_workspace` writes inside workspace tempdir — asserts success
15. `state.md` 21.7-R1 row updated: if tests pass on real kernel, mark "Done"; if not, mark "Partial" with specific failure
16. `sandbox.rs` doc comment: replace "Landlock (Linux 5.13+) provides OS-level filesystem confinement" with honest description until landlock actually passes tests on CI

## Failure criteria

- Any landlock test fails on a Linux 5.13+ kernel.
- Any write outside the workspace succeeds when landlock is active.
- `apply_landlock` silently no-ops (bails without `restrict_self` on a supported kernel).
- Pre_exec allocates heap memory (env vars).
- Background path not wired.
