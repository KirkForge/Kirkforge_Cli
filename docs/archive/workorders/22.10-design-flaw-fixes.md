# Workorder 22.10 — Design Flaw Fixes

## Status: Planned

## Problem

Five data-flow lies and architectural flaws: verifier skip producing no
CorrectionResult, offload store being process-global, TruncationStrategy
unused variant, CompactionTransform trait with one impl, and
format_verdict_report being dead code.

## Source

Review Part 4 §4.6 (architecture smells) and §4.7 (data-flow lies). WO 22.0
overview §22.10.

## Targets

### 22.10-R1 — Verifier skip → inject `CorrectionResult` (MEDIUM · est M · dep: —)

**Reality check:** When a verifier returns `Verdict::Skipped`, the correction
loop at `src/session/verifier/correction.rs:47` breaks immediately:
`Verdict::Clean | Verdict::Skipped(_) => break`. This means `Skipped` verdicts
produce no `CorrectionResult` — the model has no visibility that verification
was skipped for a file (e.g. non-Rust file, no git repo).

**What was done (subagent):** `catch_unwind` was added for verifier panics
in `handler.rs:76-87` and `bus.rs:167`, which converts panics to
`Verdict::Skipped("verifier panicked: ...")`. But `Skipped` verdicts still
don't produce a `CorrectionResult`.

**Remaining:**
- Inject a `CorrectionResult { verifier, success: true, message: "verification
  skipped: <reason>", fix: None }` for `Skipped` verdicts so the model can
  see that verification was intentionally skipped.
- The `correction.rs` match arm should produce a `CorrectionResult` for
  `Skipped`, not just break.

**Scope:** `src/session/verifier/correction.rs`, `src/session/verifier/handler.rs`.

**Success criteria:**
- When a verifier returns `Verdict::Skipped(reason)`, a `CorrectionResult`
  with `success: true`, `message: "verification skipped: <reason>"`, and
  `fix: None` is injected into the correction loop output.
- The model can see skipped verification in the turn output.
- Test: a `Verdict::Skipped` produces a `CorrectionResult` with
  `success: true`.

**Failure criteria:** `Verdict::Skipped` produces no `CorrectionResult`.
Model has no visibility into skipped verification.

**Estimate:** M

**Defer note:** DEFER-2210-R1 — the model doesn't need to see every skipped
verification; only error verdicts are actionable. Adding a `CorrectionResult`
for skips would add noise. Revisit if model confusion about skipped files
becomes a real issue. Tracked in PONYTAIL-DEBT.md.

### 22.10-R5 — `format_verdict_report` cleanup (LOW · est S · dep: —)

`format_verdict_report` is marked `pub(crate)` with `#[allow(dead_code)]` and

path.

  acceptable per the honesty culture.

**Scope:** `src/session/verifier/bus.rs`.

**Success criteria:**
- Either `format_verdict_report` is deleted (with a note that it can be
  re-added from the ADR), or the `ponytail:` comment documenting it as dead

**Failure criteria:** Dead code without documentation. Clippy warning.

**Estimate:** S (already documented with ponytail: comment)

**Defer note:** DEFER-2210-R5 — the `ponytail:` comment already documents the
ceiling. Deletion is a cleanup, not a bug. Tracked in PONYTAIL-DEBT.md.
