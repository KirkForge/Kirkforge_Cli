# Workorder 22.2 — Critical: Fix Folded Plugins Default-OFF

## Status: Planned

## Problem

The WO 21.11 yeet removed `stratum` and `kf-budget` from `default_plugin_sources()` (config/tools.rs:52-57). `default_enabled_plugins()` derives from it → `["kf-plugin"]` only. The compiled-in registration gates on `enabled_plugins.iter().any(|n| n == "kf-budget")` (executor/mod.rs:242, run_session.rs:531,551). With default config, stratum and budget tools never register — no budget enforcement, no stratum compression out-of-the-box.

This defeats the entire WO 21.11 "fold into Rust, default-on" goal. The tools are compiled in but invisible to the user.

## Reality-check

`src/shared/config/tools.rs:52-57`:
```rust
fn default_plugin_sources() -> HashMap<String, PathBuf> {
    let mut sources = HashMap::new();
    let base = PathBuf::from(env!("CARGO_MANIFEST_DIR"));
    sources.insert("kf-plugin".into(), base.join("plugins/kf-plugin"));
    sources
}
```

`default_enabled_plugins()` at :59-63 derives `["kf-plugin"]`. The `enabled_plugins` field is what the executor checks for compiled-in tool registration. Result: `cargo test session::plugin_tools::tests::budget_tools_present_in_default_toolset` **fails** ("default config must include kf-budget in enabled_plugins, got: [\"kf-plugin\"]").

## Scope

1. `src/shared/config/tools.rs` — fix `default_enabled_plugins()` to include folded plugin names when features are enabled
2. `src/session/executor/mod.rs` — verify the registration gate uses `enabled_plugins` correctly
3. `src/main/run_session.rs` — same
4. Test file for `budget_tools_present_in_default_toolset` and `stratum_tools_present_in_default_toolset`

## Success criteria

1. With default config (no user config file), `enabled_plugins` includes `["kf-budget", "kf-plugin", "stratum"]` (or the exact names the registration gates check — verify against executor/mod.rs and run_session.rs).
2. The `enabled_plugins` list respects Cargo features: when `feature = "stratum"` is on (it's default-on), `"stratum"` appears; when `feature = "budget"` is on (it's default-on), `"kf-budget"` appears.
3. `cargo test -p kf-code session::plugin_tools::tests::budget_tools_present_in_default_toolset` passes.
4. `cargo test -p kf-code session::plugin_tools::tests::stratum_tools_present_in_default_toolset` passes (or equivalent).
5. A user config that explicitly sets `enabled_plugins = ["kf-plugin"]` still works (budget/stratum excluded by user choice).
6. A user config that sets `disabled_plugins = ["stratum"]` still works (stratum excluded).

## Failure criteria

- Default config does not include stratum and kf-budget in `enabled_plugins`.
- User config regression (explicit `enabled_plugins` or `disabled_plugins` breaks).
- Any `plugin_tools::tests` test fails.
