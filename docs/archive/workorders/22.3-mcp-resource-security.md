# Workorder 22.3 — MCP Resource URI Validation + Init Handshake

## Status: Planned

## Problem

MCP resource tools accept arbitrary URIs from model output without validation
or sanitisation, and the MCP init handshake does not advertise `resources` or
`prompts` capabilities — servers that gate features on client capability
advertisements will not offer them to kf-code.

## Source

Review Part 2, §2.5 (MCP resource security). WO 22.0 overview §22.3.

## Targets

### 22.3-R1 — Validate MCP resource URIs (HIGH · est S · dep: —)

**Reality check:** `src/session/mcp_resource_tools.rs:98-106` — the `read`
action takes the URI string directly from `args.get("uri")` and passes it to
`manager.read_resource(uri)` with no validation. A model can inject arbitrary
scheme strings (`file:///etc/passwd`, `ssh://...`, etc.). There is no
`validate_mcp_uri` function or allowlist check anywhere in the codebase.

**What was done (subagent):** A `validate_mcp_uri` function was added that
rejects URIs with dangerous schemes (`file:`, `ssh:`, `ftp:`, etc.) and only
allows known-safe MCP schemes (`resource://`, custom server-specific schemes).
The `read` action now calls `validate_mcp_uri` before forwarding to the
manager.

**Remaining:**
- `validate_mcp_uri` needs a test: assert `file:///etc/passwd` is rejected,
  assert `resource://my-server/doc` is accepted, assert empty/missing URI
  returns clear error.
- The `list` action should also reject non-MCP URI filters (if a `server`
  filter is provided, validate it doesn't contain path traversal).
- ADR documenting the URI allowlist decision.

**Scope:** `src/session/mcp_resource_tools.rs`, new test module within,
`docs/adr/` for the allowlist ADR.

**Success criteria:**
- `validate_mcp_uri` rejects `file:`, `ssh:`, `ftp:`, `data:`, and other
  dangerous schemes; allows `resource://`, server-specific custom schemes, and
  bare paths that match `[a-zA-Z0-9_-]`.
- `mcp_resource` tool `read` action calls `validate_mcp_uri` before
  `manager.read_resource`; returns `ToolError::InvalidArgs` on rejection.
- `mcp_resource` tool `list` action validates `server` filter (if present)
  against known MCP server names from config.
- Tests: `file:///etc/passwd` rejected, `resource://my-server/doc` accepted,
  empty URI returns clear error.
- ADR written for URI allowlist decision.
- `cargo test -p kf-code mcp_resource` green.

**Failure criteria:** Any dangerous URI scheme reaches `read_resource`.
Missing validation test. No ADR.

**Estimate:** S

**Defer note:** none.

### 22.3-R2 — Advertise `resources` + `prompts` capabilities in MCP init handshake (MEDIUM · est S · dep: —)

**Reality check:** `src/session/mcp_client/mod.rs:302-314` — the `initialize`
request sends `"capabilities": {}` (empty object). Servers that gate resource
or prompt listing on the client advertising `resources`/`prompts` capabilities
will not return them. The HTTP transport at
`src/session/mcp_client/http.rs:137-152` also sends `"capabilities": {}`.

**What was done (subagent):** The `capabilities` field in both stdio and HTTP
init requests was updated from `{}` to `{"resources": {}, "prompts": {}`.
The `warn_unsupported_capabilities` function (mod.rs:65) already existed and
logs a warning when the server advertises capabilities kf-code doesn't support.

**Remaining:**
- Test that the init request JSON includes `"resources": {}` and `"prompts": {}`.
- Verify that servers responding with `resources`/`prompts` capability lists
  are correctly handled (the `warn_unsupported_capabilities` path already
  covers this, but no test asserts it).

**Scope:** `src/session/mcp_client/mod.rs`, `src/session/mcp_client/http.rs`,
test modules within.

**Success criteria:**
- Both stdio (`mod.rs`) and HTTP (`http.rs`) init requests advertise
  `"capabilities": {"resources": {}, "prompts": {}}`.
- Test asserts the init JSON includes both capability keys.
- Existing MCP integration continues to work (no regression in
  `mcp_tools`/`mcp_resource_tools` tests).

**Failure criteria:** Empty `capabilities: {}` still sent on either transport.
Missing capability advertisement test. Regression in MCP tool listing.

**Estimate:** S

**Defer note:** none.
