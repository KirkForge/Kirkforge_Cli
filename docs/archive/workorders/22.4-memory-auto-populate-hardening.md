# Workorder 22.4 — Memory Auto-Populate Hardening

## Status: Planned

## Problem

Memory auto-population is noisy (extracts low-signal facts every turn) and
silent (no user visibility in TUI, no config flag to disable it). Slug
collisions can silently overwrite earlier facts.

## Source

Review Part 3 §3.3 (memory extraction). WO 22.0 overview §22.4.

## Targets

### 22.4-R1 — Cap facts per turn and add dedup (HIGH · est S · dep: —)

**Reality check:** `src/session/memory/extract.rs` — before the subagent
fix, `extract_facts` had no cap on facts per turn, and slug collisions
between different facts would silently overwrite earlier facts in the memory
store.

**What was done (subagent):**
- Added `MAX_FACTS_PER_TURN = 3` (`extract.rs:9`) with `facts.truncate(MAX_FACTS_PER_TURN)` at line 224.
- Added `EXTRACT_EVERY_N_TURNS = 3` rate-limit in `turn.rs:86-89` — extraction only runs every 3rd turn, or immediately when `is_preference_like()` detects preference/correction keywords.
- Added `make_slug` with FNV-1a hash suffix (`extract.rs:112-125`) — slugs now include a 4-hex-digit hash to disambiguate facts with similar prefixes.
- Added `tracing::info!(count, facts = ?names, "auto-remembered facts")` at `turn.rs:120`.
- Added tests: `slug_includes_hash_suffix`, `different_facts_different_slugs`, `max_facts_per_turn_caps_output`, `is_preference_like_*`.

**Remaining:**
- The hash suffix prevents slug collision between different facts in the same
  turn, but the memory store's `upsert` still overwrites on name collision
  across turns. Consider a name-clash guard (e.g. append turn number or
  timestamp if the same slug already exists with different content).

**Scope:** `src/session/memory/extract.rs`, `src/session/memory/mod.rs`,
`src/session/executor/turn.rs`.

**Success criteria:**
- `MAX_FACTS_PER_TURN` caps extraction to 3 facts per turn.
- `EXTRACT_EVERY_N_TURNS` rate-limits to every 3rd turn (with preference/correction bypass).
- Slug hash suffix prevents collision between same-prefix facts.
- `tracing::info` logs extracted fact names.
- All existing + new memory extraction tests pass.

**Failure criteria:** Unlimited facts per turn. Slug collision across turns
silent. No rate limiting. No tracing.

**Estimate:** S (most work done)

**Defer note:** Cross-turn slug collision guard — DEFER-224-R1d; current hash
suffix prevents same-turn collisions. Cross-turn collision is unlikely
(`upsert` with identical content is idempotent; different content on same slug
is a real but rare edge case). Tracked in PONYTAIL-DEBT.md.

### 22.4-R2 — User visibility in TUI (MEDIUM · est M · dep: —)

**Reality check:** Auto-populated facts appear in the memory store
(`~/.kirkforge/memory/<session>/`) but are invisible in the TUI. The `/memory`
command lists facts but doesn't distinguish auto-populated from user-pinned
facts. No visual indicator shows "3 facts auto-remembered" after a turn.

**What was done (subagent):** `tracing::info!` was added in `turn.rs:120` —
server-side logs now show auto-remembered facts. No TUI surface was changed.

**Remaining:**
- Add a `[memory]` indicator in the TUI status bar or turn output showing
  auto-remembered fact count (e.g. `📝 3 facts remembered`).
- Distinguish auto-populated vs user-pinned facts in `/memory list` output
  (add a `source` column: `auto` vs `user`).
- Consider a config option to show/hide auto-populated facts.

**Scope:** `src/tui/`, `src/tui/commands/memory.rs`, `src/session/memory/mod.rs`.

**Success criteria:**
- TUI shows a brief indicator when facts are auto-remembered (status bar or
  turn footer).
- `/memory list` shows fact source (`auto` or `user`).
- No regression in existing memory commands.

**Failure criteria:** No TUI visibility. `/memory list` doesn't show source.
Regression in existing commands.

**Estimate:** M

**Defer note:** DEFER-224-R2 — TUI indicator is UX polish, not a ship-blocker.
Server-side `tracing::info` already provides observability. Tracked in
PONYTAIL-DEBT.md.

### 22.4-R3 — Config flag default-off (MEDIUM · est S · dep: —)

**Reality check:** Memory auto-extraction runs unconditionally on every Nth
turn. There is no `memory.auto_populate` config flag to disable it. Users
who don't want automatic fact extraction have no way to turn it off.

**What was done (subagent):** No config flag was added.

**Remaining:**
- Add `memory_auto_populate: bool` to `DisplayConfig` (or `ToolConfig`) with
  default `true` (preserves current behavior).
- Gate the extraction in `turn.rs` on this config flag.
- Document the flag in TECHNICAL.md and the config schema.

**Scope:** `src/shared/config/display.rs`, `src/session/executor/turn.rs`,
`src/session/config/mod.rs`, `docs/TECHNICAL.md`.

**Success criteria:**
- `memory_auto_populate` config key exists, defaults to `true`.
- Setting it to `false` disables auto-extraction (no `extract_facts` call).
- Documented in TECHNICAL.md config section.

**Failure criteria:** No config flag. Flag exists but doesn't gate extraction.
Not documented.

**Estimate:** S

**Defer note:** none.

### 22.4-R4 — Slug collision fix across turns (LOW · est S · dep: 22.4-R1)

**Reality check:** `MemoryStore::upsert` in `src/session/memory/mod.rs:284`
overwrites existing facts on name match. If two different facts across
different turns produce the same slug (even with the hash suffix, collisions
are possible though unlikely), the later fact silently replaces the earlier
one.

**What was done (subagent):** The hash suffix (`make_slug`) makes same-turn
collisions extremely unlikely. Cross-turn collision is not addressed.

**Remaining:**
- Option A: append turn number to slug (e.g. `user-pref-tabs-{hash}-t7`).
- Option B: on `upsert`, if content differs, append a disambiguator instead of
  overwriting.
- Option C: accept the rare collision as idempotent (same content = no harm;
  different content = rare overwrite documented as `ponytail:` known ceiling).

**Scope:** `src/session/memory/extract.rs`, `src/session/memory/mod.rs`.

**Success criteria:**
- Either a disambiguation strategy is implemented, or a `ponytail:` comment
  documents the known ceiling with upgrade path.

**Failure criteria:** No documentation of the collision ceiling.

**Estimate:** S

**Defer note:** DEFER-224-R4 — the hash suffix makes collision extremely
unlikely. A `ponytail:` comment documenting the ceiling is sufficient for now.
Full disambiguation tracked in PONYTAIL-DEBT.md.
