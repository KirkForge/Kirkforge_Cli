# Workorder 23.3 — Add Mouse Click/Drag Support to TUI

## Problem

The TUI handles only `MouseEventKind::ScrollUp` and `ScrollDown` (`tui/mod.rs:835-848`). All other mouse events — click, drag, release — fall through the `_ => {}` arm. The user cannot click to place the cursor, select text, or drag to scroll. Every comparator (Claude Code, opencode, Cursor) supports mouse interaction in their TUI/GUI.

## Source

Review #21 (Phase 2). `src/tui/mod.rs:835-848` — `handle_mouse` only handles `ScrollUp`/`ScrollDown`. Review §4.6: "mouse scroll-only (no click/drag)."

## Scope

1. `src/tui/mod.rs` — expand `handle_mouse` to handle `Down`/`Up`/`Drag`/`DragMoved`
2. `src/tui/app.rs` — add click state fields to `AppState`
3. `src/tui/keys/` — key handlers may need mouse-click integration for approval buttons
4. `src/tui/widgets/` — widgets need hit-testing for click targets

## Targets

### 23.3-R1 — Mouse click to focus/place cursor (est M)

**Reality check:** `handle_mouse` at `mod.rs:835-848` dispatches only scroll events. Adding `MouseDown`/`MouseUp` requires:
1. Hit-testing which panel (chat vs sidebar) was clicked
2. Converting the y-coordinate to a message index and line offset
3. Placing the cursor at the clicked position (or selecting the nearest message)

**Plan:**
- Add `MouseDown` handler in `handle_mouse` that:
  - Determines which panel was clicked (chat area vs sidebar vs input)
  - In the chat area: scrolls to the clicked message, deselects any approval highlight
  - In the approval dialog: clicks on the diff area scroll to the clicked line
- Add `MouseUp` handler to finalize click (no-op for now — drag will use it later)
- Add mouse state fields to `AppState`: `mouse_down_at: Option<(u16, u16)>`

**Success criteria:**
- Clicking in the chat area scrolls to the clicked position
- Clicking in the sidebar selects the clicked tab row
- Clicking in the input box focuses it (if it wasn't focused)
- Scroll behavior is unchanged
- All existing tests pass

**Failure criteria:** Click events are swallowed. Scroll behavior regresses. Key handling changes.

**Estimate:** M

### 23.3-R2 — Mouse drag to scroll/select (est M)

**Reality check:** Mouse drag (click + move) is the standard way to select text in a terminal. crossterm emits `MouseDrag`/`MouseDragMoved` events.

**Plan:**
- Add `MouseDrag`/`MouseDragMoved` handlers in `handle_mouse`
- On drag in chat area: scroll the view by the delta (drag up = scroll up, drag down = scroll down)
- On drag in sidebar: no-op (or extend selection if sidebar has multi-select in the future)
- Track drag state in `AppState`: `drag_origin: Option<(u16, u16)>`, `is_dragging: bool`

**Success criteria:**
- Dragging in the chat area scrolls smoothly
- Dragging in the sidebar is a no-op (doesn't crash)
- Release after drag resets drag state
- All existing tests pass

**Failure criteria:** Drag causes flicker, incorrect scroll, or crash.

**Estimate:** M

**Defer note:** R2 can be deferred independently — click-to-focus is more valuable than drag-to-scroll for a coding agent TUI.
