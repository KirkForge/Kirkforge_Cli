# Workorder 24.2 — Make Cosign Signing Blocking on Release

## Problem

The release workflow (`.github/workflows/release.yml:229-239`) installs cosign and signs `SHA256SUMS.txt` with `cosign sign-blob --yes`, but a signing failure does not block the release. The `--yes` flag auto-confirms; if cosign itself fails (keyless flow error, network issue, sigstore outage), the step will error — but there is no explicit guard ensuring the signature and certificate are present and valid before uploading.

The review (#32) requires: if cosign signing fails, the release must not proceed. Currently, the signing step is best-effort — a transient sigstore outage could produce unsigned releases.

## Root cause

`release.yml:236-239` runs `cosign sign-blob` but does not verify the output artifacts (`SHA256SUMS.txt.sig`, `SHA256SUMS.txt.pem`) exist and are non-empty before the release upload step. If cosign fails silently or the output is empty, the release proceeds unsigned.

## Scope

1. `.github/workflows/release.yml` — add verification after the sign step
2. `scripts/ci_local.sh` — document the release-signing posture (no local equivalent)

## Plan

### 24.2-R1 — Add post-sign verification step to release workflow

- After the `cosign sign-blob` step, add a verification step:
  ```yaml
  - name: Verify cosign signature
    run: |
      test -s dist/SHA256SUMS.txt.sig || { echo "ERROR: cosign signature missing or empty"; exit 1; }
      test -s dist/SHA256SUMS.txt.pem || { echo "ERROR: cosign certificate missing or empty"; exit 1; }
      cosign verify-blob \
        --certificate dist/SHA256SUMS.txt.pem \
        --signature dist/SHA256SUMS.txt.sig \
        dist/SHA256SUMS.txt
  ```
- This makes the release workflow fail if either: (a) cosign didn't produce a signature/certificate, or (b) the signature doesn't verify against the blob.
- The `--yes` flag on `sign-blob` is fine — it skips the interactive confirmation prompt in CI. The verification step is what blocks.

**Success criteria:**
- Release workflow fails if `cosign sign-blob` errors.
- Release workflow fails if `SHA256SUMS.txt.sig` or `.pem` are missing/empty.
- Release workflow fails if `cosign verify-blob` rejects the signature.
- `scripts/ci_local.sh` documents the posture (cosign is release-only, no local equivalent).

**Failure criteria:** Unsigned or unverified release artifacts are uploaded to GitHub.
