# Workorder 24.6 — Raise `src/session` Coverage Above 75%

## Problem

The review (#36) identifies `src/session` as the least-tested core path. The executor loop (turn dispatch, tool results, verifier feedback, budget slicing, undo/redo) is the heart of the agent, and it has poor unit test coverage relative to its complexity. The review scorecard gives the agent loop 7.0/10 with "primitive single-turn subagents" and "doom-loop is hint-only" — but even the core path is undertested.

`src/session` contains the executor, turn loop, verifier bus, budget slicing, prompt building, compaction, memory, and configuration — roughly 60% of the critical path. Coverage below 75% means edge cases in the executor loop, budget slicing, compaction, and verifier feedback are likely untested.

## Root cause

The session module grew organically. Tests were added for individual tools and adapters, but the executor loop integration path (turn dispatch → tool call → verifier → correction → undo) is primarily tested via the bench harness, which requires a live model. Unit tests for the executor loop are thin.

## Scope

1. `src/session/executor/` — executor, turn, loop, helpers, outcome, correction
2. `src/session/verifier/` — handler, bus, correction
3. `src/session/budget.rs` — budget slicing, token accounting
4. `src/session/prompt/` — compaction, microcompaction, summarizer
5. `src/session/config/` — config parsing, env overrides
6. `src/session/access/` — path guard, sandbox
7. `src/session/memory/` — extraction, storage
8. `src/session/stratum.rs` — compression pipeline

## Plan

### 24.6-R1 — Baseline coverage measurement

- Run `cargo tarpaulin` (or `cargo llvm-cov`) on `src/session` to get current coverage numbers.
- Identify which modules are below 75% and which are above.
- Prioritize: executor loop > budget slicing > compaction > verifier > config > memory > stratum.

**Success criteria:** Coverage report for `src/session` exists. Modules below 75% identified.

**Failure criteria:** Cannot measure coverage (toolchain issue).

**Estimate:** S

**Defer note:** none.

### 24.6-R2 — Executor loop unit tests

- Add tests for:
  1. Turn dispatch with multiple tools in one response (parallel + sequential phases).
  2. Verifier correction loop (mock verifier returns `Dirty`, confirm correction is injected).
  3. Budget slicing: `apply_budget_slice` reduces content and marks `truncated: true`.
  4. Undo stack: snapshot → apply edit → undo → confirm file restored.
  5. Doom-loop hint injection: loop count exceeds threshold, confirm `Role::User` hint injected.
  6. Cancellation: `AtomicBool` set → confirm in-flight tools are aborted.
- Use mock adapters (the existing test infrastructure in `executor/tests/`).

**Success criteria:** Each of the 6 scenarios has at least one passing test. `src/session/executor` coverage increases by ≥5 percentage points.

**Failure criteria:** Coverage doesn't increase. Tests don't cover the executor loop path.

**Estimate:** L

**Defer note:** This is the core value of this workorder. Start here.

### 24.6-R3 — Budget slicing tests

- Add tests for:
  1. `HeadTailSlicer` with short content (no slicing needed).
  2. `HeadTailSlicer` with long content (head + tail preserved, middle truncated).
  3. Budget enforcement: turn exceeds token limit, confirm slicing is triggered.
  4. Budget accounting: token counts match between prompt builder and budget state.

**Success criteria:** 4 new tests. `src/session/budget.rs` coverage ≥ 80%.

**Failure criteria:** Coverage below 75%.

**Estimate:** M

**Defer note:** none.

### 24.6-R4 — Compaction and microcompaction tests

- Add tests for:
  1. `compact_to_budget` with messages under budget → no compaction.
  2. `compact_to_budget` with messages over budget → compaction reduces to budget.
  3. `heuristic_summary` extracts tool names and paths.
  4. `maybe_microcompact` with short messages → no microcompaction.
  5. `maybe_microcompact` with long messages → microcompaction reduces.

**Success criteria:** 5 new tests. `src/session/prompt/` coverage ≥ 75%.

**Failure criteria:** Coverage below 70%.

**Estimate:** M

**Defer note:** none.

### 24.6-R5 — Verifier bus tests

- Add tests for:
  1. Verifier returns `Verdict::Clean` → no correction.
  2. Verifier returns `Verdict::Dirty` → correction injected.
  3. Verifier returns `Verdict::Skipped` → skip message injected (WO 22.11-R2).
  4. Verifier panics → `catch_unwind` returns `Verdict::Skipped` (WO 22.11-R1).

**Success criteria:** 4 new tests. `src/session/verifier/` coverage ≥ 75%.

**Failure criteria:** Coverage below 70%.

**Estimate:** M

**Defer note:** Depends on WO 22.11-R1/R2 (catch_unwind + skip injection).
