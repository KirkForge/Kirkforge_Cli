# Workorder 25.10 — Stale Binary/Path/Config References + ADR Path-Literal Enforcement

## Status: Done (R4 deferred)

## Priority: P0 — install + user-config correctness

## Problem

Three deleted binaries (`plugin3`, `stratum`, `kf-code-video`) and one
deleted daemon (`kfd`) are still referenced in user-facing config and ADR
prose. The install script will fail on the ghost binaries (covered by
WO 25.5); `config.toml.example` will enable non-existent plugins on
uncomment; 12 ADRs had stale `crates/plugin3-*` paths (prose being fixed by
a parallel doc agent, but the **enforcement gap** remains — the
`adr_xref_drift` test only checks cross-refs, not path-literal existence).

## Source

- `config.toml.example:344-348` — references plugin names `kf-code-plugin3`,
  `stratum`, `kf-code-plugin` and paths `plugins/stratum`, `plugins/kf-code-plugin3`.
  Real plugin is `plugins/kf-plugin`.
- 12 ADRs had stale `crates/plugin3-*` path references (parallel doc agent
  fixing prose).
- `tests/adr_xref_drift.rs:258` — `ponytail:` note acknowledges the
  path-literal gap.
- `scripts/install.sh:92` — covered by WO 25.5 (do not double-edit).

## Requirements

### R1 — Fix `config.toml.example`

**Lines 344-348.** Plugin block references deleted plugin names and paths.

- Remove `kf-code-plugin3` / `stratum` / `kf-code-plugin` entries.
- Correct remaining paths to `plugins/kf-plugin` (the real plugin dir).
- Verify: uncommenting the plugins block produces a config that loads
  without "plugin not found" errors.

### R2 — ADR path-literal enforcement test

- Extend `tests/adr_xref_drift.rs` to grep ADR prose for `crates/X` and
  `src/X` path literals, and assert each match resolves to a directory
  that exists in the worktree.
- Either replace the `ponytail:` note at `:258` with the real check, or
  upgrade it to a `ceiling:` note documenting the precise gap if markdown
  parsing proves too lossy (e.g., path appears inside a code-fenced
  example that shouldn't be probed).

### R3 — Audit remaining scripts and workflows

- Grep `scripts/*.sh` (those NOT already covered by 25.5) and
  `.github/workflows/*.yml` for any remaining
  `plugin3`/`stratum`/`kf-code-video`/`kfd` references.
- List every finding; fix or document each.

### R4 — CI enforcement gate

- Add a CI grep gate that fails any PR introducing a reference to a
  deleted binary/path in an active script or workflow.
- Reuse the gate added by 25.5 if compatible; otherwise add a sibling check.

## Success criteria

- `config.toml.example` references only existing plugin paths; uncommenting
  the plugins block loads cleanly.
- `cargo test -p kf-budget-core --test adr_xref_drift` enforces path-literal
  existence.
- CI grep gate fails on any new stale binary/path reference.
- Zero references to deleted binaries in active scripts or workflows.

## Failure criteria

- R2 test passes by allow-listing known-stale paths instead of probing
  the filesystem.
- Config example fixed but breaks a working plugin entry.
- Double-editing `install.sh` creates a merge conflict with WO 25.5.

M (~4-5h).

## Defer note

None — but **coordinate with WO 25.5** (which is P0 and should land first;
25.5 owns `install.sh`, `build-all.sh`, `ci-local.sh`, `release.yml`).
