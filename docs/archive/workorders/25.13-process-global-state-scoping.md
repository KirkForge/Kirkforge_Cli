# Workorder 25.13 — Process-Global State Scoping

## Status: Done

## Priority: P2 — multi-session correctness

## Problem

Offload stores were correctly scoped per-session (`SessionStores`,
`src/session/mod.rs:44-51`, 1000-entry cap) — that fix landed. But
`SESSION_MODE` (`src/session/stratum.rs:86`) and `SLICED_LISTENERS`
(`src/session/budget.rs:105`) remain process-global `OnceLock`. In a
multi-session process (daemon mode, multi-fork), listeners pushed per
session-build accumulate with no eviction → unbounded growth, and
session-mode is shared across sessions that may legitimately want
different modes.

## Source

- `src/session/mod.rs:44-51` — `SessionStores` (per-session, capped).
- `src/session/stratum.rs:86` — `SESSION_MODE: OnceLock<...>` (global).
- `src/session/budget.rs:105` — `SLICED_LISTENERS: OnceLock<...>` (global).

## Requirements

### R1 — Bound or scope `SLICED_LISTENERS`

- Audit: confirm whether listeners are pushed per session-build (leak)
  or replaced (safe). Grep all push sites.
- If leak: either scope the listener set into `SessionStores` (per-session
  lifecycle), or add bounded eviction (LRU or last-N cap matching the
  1000-entry pattern of `SessionStores`).
- If safe (replacement semantics): document why and add a test pinning
  the invariant.

### R2 — Document or scope `SESSION_MODE`

- If multi-session processes need different modes per session: scope it
  into `SessionStores` (per-session).
- If a single process-wide mode is intentional (env-driven config):
  document the decision in an ADR + leave a `ceiling:` note at the
  `OnceLock` site explaining why per-session mode is out of scope.

### R3 — Multi-session unit test

- Build N sessions in one process; assert listener growth is bounded
  (cap or steady-state) and that session teardown releases listeners.

## Success criteria

- `SLICED_LISTENERS` growth is bounded (cap or eviction) or scoped
  per-session.
- `SESSION_MODE` is either scoped per-session or documented as
  intentionally global with an ADR + `ceiling:` note.
- Multi-session test asserts no unbounded listener accumulation.
- `cargo test --workspace` green.

## Failure criteria

- R1 caps listener growth but breaks existing single-session behavior.
- R2 scopes `SESSION_MODE` per-session without verifying that env-var
  config still works (regression for the common case).
- R3 test passes by special-casing the test runtime (single-session
  only) — must exercise multi-session.
