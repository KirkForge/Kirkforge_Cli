# Workorder 25.18 — Deferred Capability Carry-Forward (21.5-R2/R3, 21.5-R9, 22.4-R2/R3, 22.9-R4)

## Status: Planned

## Priority: P2/P3 — backlog tracking; each R-item separable

## Problem

Five deferred capability items from state.md remain open. Each was
deferred for a concrete reason (recorded in state.md); this WO tracks
them as a backlog so they don't rot. Each R-item can ship independently
— split into separate PRs or even separate WOs if scope demands.

## Source

state.md "Deferred items" section. Each R-item cites its deferral origin.

## Requirements

### R1 (21.5-R2/R3) — Stream partial bash output to TUI

- Add `TurnEvent::BashPartialOutput` variant.
- Forward PTY output through `event_tx` as partial-output events.
- Render a streaming indicator in the TUI tool-result card.
- PTY itself remains deferred (WO 21.5); this is the streaming UX for
  the existing PTY path. Non-PTY path unchanged.

### R2 (21.5-R9) — Anthropic computer_use beta

- Opt-in beta path routed to the Anthropic model, gated behind a
  feature flag (e.g., `computer_use`).
- Coordinate-vision model integration.
- Gate must default OFF — computer_use is a meaningful capability and
  cost surface; users opt in explicitly.

### R3 (22.4-R2/R3) — TUI memory visibility widget

- Add a memory indicator to the TUI status bar (shows memory entry
  count + last-updated turn).
- Add a config flag (`memory.show_in_status` or similar) to toggle
  memory display.

### R4 (22.9-R4) — Bedrock/Vertex test hardening

- Mock provider adapters for CI so Bedrock/Vertex integration tests
  don't need live credentials.
- Reuse the mock-provider scaffolding from WO 17.8 if compatible;
  otherwise add a sibling mock layer.

## Success criteria

- Each R-item either ships (with success criteria of its own) or is
  re-deferred with explicit AGENTS.md §11 disclosure (what / why /
  remaining / tracking location).
- R1: bash output visibly streams in the TUI during long-running
  commands (manual smoke).
- R2: computer_use beta path works end-to-end behind a feature flag
  that defaults OFF (or is re-deferred with reason).
- R3: memory widget renders in the status bar; config flag toggles it.
- R4: Bedrock/Vertex integration tests run in CI against mocks, no
  live credentials required.

## Failure criteria

- Any R-item silently stubbed to mark the WO "done" (AGENTS.md §11
  silent-deferral violation).
- R2 ships computer_use without the feature flag — security/cost
  surface ungated.
- R4 mocks are too loose (accept any request) — mocks must enforce
  contract conformance or they're theater.

## Estimate

L+ (each R-item is S-M; total ~1-2 weeks if all shipped).

## Defer note

Each R-item may be independently deferred — split into separate WOs if
the scope is too large for one PR. Track per-item deferrals in state.md
"pending" + this WO's Status line. **No silent deferral**: an R-item
shipped smaller than specified MUST carry an explicit deferral entry
naming the remaining work.
