# Workorder 25.4 — Coverage Baseline Tooling

## Status: Done (R3 deferred)

## Problem

The repo has no coverage tooling in CI. WO 24.6 (session coverage 75%) is deferred because `cargo llvm-cov` isn't wired into CI and there's no baseline to gate against. WO 12.8 raised coverage to 75%+ on three target directories, but there's no CI enforcement beyond the `kf-budget-core` `adr_xref_drift` test. Coverage can regress silently.

## Root cause

`cargo llvm-cov` is not installed in CI. No GitHub Action runs it. No baseline report exists. Without a baseline, there's nothing to gate against.

## Scope

1. GitHub Actions workflow — coverage job
2. Per-crate baseline report
3. Coverage regression gate
4. Documentation

**Note:** This WO picks up the tooling only, not the 75% target. WO 24.6 (session coverage 75%) remains deferred. The coverage baseline established here enables future WO 24.6 work.

## Plan

### 25.4-R1 — Add `cargo llvm-cov` to CI (HIGH · est M · dep: —)

**Reality check:** `cargo llvm-cov` requires LLVM tools (`llvm-cov`, `llvm-profdata`) which are available on GitHub Actions runners via `cargo-llvm-cov`'s installer action. The repo already uses GitHub Actions (see `.github/workflows/`).

**What to do:**
- Add a new GitHub Actions job (`coverage`) to the CI workflow:
  ```yaml
  coverage:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - name: Install cargo-llvm-cov
        run: cargo install cargo-llvm-cov
      - name: Generate coverage report
        run: cargo llvm-cov --workspace --lcov --output-path lcov.info
      - name: Upload coverage artifact
        uses: actions/upload-artifact@v4
        with:
          name: coverage-report
          path: lcov.info
  ```
- Run `cargo llvm-cov --workspace` (not per-crate — start with the full workspace).
- The job should run on every push to `dev` and on PRs against `dev`.

**Scope:** `.github/workflows/` (existing CI workflow).

**Success criteria:**
- Coverage job runs on `dev` pushes and PRs.
- `lcov.info` artifact uploaded.
- Job completes successfully (no missing LLVM tools).

**Failure criteria:** Job fails due to missing `llvm-cov`. Artifact not uploaded.

**Estimate:** M

**Defer note:** none.

### 25.4-R3 — Gate: reject coverage regression below baseline (MEDIUM · est M · dep: R1, R2)

**Reality check:** A baseline without a gate is just a number. The gate must fail the build if any crate drops below its baseline. This is the mechanism that prevents silent coverage regressions.

**What to do:**
- Add a step to the CI coverage job that compares per-crate coverage against the baseline:
  ```yaml
  - name: Check coverage regression
    run: |
      cargo llvm-cov --workspace --json --output-path cov.json
      # Compare each crate's coverage against baseline
      # Fail if any crate is below baseline - 1% (tolerance for noise)
  ```
- Implement a small script (`scripts/check-cov-regression.sh`) that parses the `cargo llvm-cov --json` output and compares against the baseline table.
- Allow a 1% tolerance for noise (CI runners may have slight variations).
- The gate should output which crates regressed and by how much.

**Scope:** `.github/workflows/` (CI workflow), `scripts/check-cov-regression.sh` (new).

**Success criteria:**
- CI job fails if any crate drops below baseline - 1%.
- Regression message identifies which crate and by how much.
- False-positive tolerance ≤ 1% (no flake from measurement noise).

**Failure criteria:** Gate doesn't fail on real regression. Gate flakes on no-change runs.

**Estimate:** M

**DEFERRED:** Needs a real baseline from the first successful CI coverage run before the gate can be meaningful. Remaining: implement `scripts/check-cov-regression.sh`, add regression-check step to CI, validate tolerance. Tracked in WO 25.4-R3.
