# Workorder 25.7 — Benchmark Source of Truth + KIRK-BENCH.md

## Status: Done

## Priority: P1 — documentation credibility

## Problem

Two issues:

1. **Broken README link:** `README.md` line 42 links to `[KIRK-BENCH](KIRK-BENCH.md)` but that file doesn't exist at the repo root. `docs/bench/` contains only `leaderboard.md`. The README creates an immediate "doesn't match reality" signal for evaluators.

2. **Manually maintained task count:** README says "31 coding tasks" but `benches/tasks/` contains 30 `.toml` files. Manually maintaining counts drifts — the source of truth should be automated.

## Source

External audit finding. `ls benches/tasks/*.toml | wc -l` = 30. `ls docs/` shows no `KIRK-BENCH.md`.

## Requirements

### R1: Fix the README link

`README.md` line 42: `[KIRK-BENCH](KIRK-BENCH.md)` → link to actual benchmark documentation. Options:
- `[Benchmarks](docs/bench/leaderboard.md)` if leaderboard covers it
- `[Benchmarks](docs/TECHNICAL.md#benchmarks)` if there's a benchmarks section in TECHNICAL.md
- Create a minimal `docs/bench/README.md` that explains the benchmark system and links to leaderboard

### R2: Generate task count from source

Stop manually saying "31 tasks" in README. Options:
- `ls benches/tasks/*.toml | wc -l` in a build script or CI step
- A `bench list` subcommand in `kf-bench` that counts and reports
- At minimum: update README to say "30 coding tasks" (accurate) and add a comment: `<!-- regenerate: ls benches/tasks/*.toml | wc -l -->`

### R3: Benchmark manifest validation (optional, deferred if >30min)

Add a CI step that verifies the bench task directory matches a manifest. If a task file is added/removed, the manifest count updates automatically. This prevents README drift in the future.

## Success criteria

- README links to an existing file for benchmark documentation.
- Task count in README matches actual file count.
- No broken links from README root.

## Failure criteria

- Link fixed but points to wrong content.
- Count fixed to 30 but a 31st task is added tomorrow — back to drift. (Mitigated by R2's generate-from-source approach.)
