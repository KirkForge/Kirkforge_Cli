# Workorder 26.10 — Provider Hardening and Polish

## Status: Planned

## Priority: P3

## Problem

Provider layer has four gaps: Bedrock/Vertex tests require live credentials
(running them in CI is infeasible), Plugin3 env var backward compat is
missing (existing workflows break on upgrade), Landlock default-on decision
is unresolved, and memory retrieval uses naive TF-IDF with no dedup.

## Source

state.md — 25.18-R4 / 22.9-R4 (mock providers), Plugin3 env compat
(handoff), Landlock decision (22.1 carry-forward), memory retrieval
(21.6-R2/R3).

## Requirements

### R1 (25.18-R4 / 22.9-R4) — Bedrock/Vertex test hardening

- Create mock provider adapters that satisfy the Bedrock/Vertex interfaces
  without live credentials.
- Reuse mock-provider scaffolding from WO 17.8 if compatible; otherwise
  add a sibling mock layer.
- Replace all Bedrock/Vertex integration tests with mock-backed tests in CI.
- Gate: `cargo test` passes with zero live-provider credentials in CI env.
- Constraint: mocks must enforce contract conformance — they must reject
  malformed requests, not accept anything.

### R2 — Plugin3 env var backward compat shim

- Existing workflows reference `PLUGIN3_*` env vars (e.g., `PLUGIN3_API_KEY`).
- Add a compat layer that maps `PLUGIN3_*` → `KF_BUDGET_*` (or the current
  canonical env var prefix) with a one-time deprecation warning on stderr.
- Gate: a workflow using old env vars continues to work AND emits a warning
  directing users to the new var name.
- No silent fallback — users must see the warning.

### R3 — Landlock default-on decision + execution

- WO 22.1 established Landlock as the sandbox mechanism but left the
  default-on decision deferred.
- Decide: Landlock defaults ON (preferred for security) or OFF (preferred
  for compatibility with non-Linux kernels).
- If ON: add kernel version check (Landlock requires 5.13+); graceful
  fallback to seccomp-only on older kernels.
- If OFF: add a clear opt-in path (`--sandbox landlock` or config flag).
- ADR documenting the decision.
- Gate: CI runs with the chosen default; tests pass on the CI kernel.

### R4 — Memory semantic retrieval + dedup

- Current memory retrieval uses TF-IDF with no dedup — similar memories
  accumulate and waste context window space.
- Add semantic dedup: before inserting a new memory, check if an existing
  memory has cosine similarity above a threshold (e.g., 0.85) and skip
  the insert or merge.
- Upgrade retrieval from TF-IDF to at least a normalized embedding cosine
  similarity (using the project's existing embedding infrastructure if
  available, or a lightweight alternative).
- Gate: after 10 similar memories are added, only 1-2 unique entries are
  retained in the memory store.

## Success criteria

- R1: Bedrock/Vertex tests run in CI against mocks; zero live credentials.
- R2: old `PLUGIN3_*` env vars still work with a deprecation warning.
- R3: Landlock decision documented in ADR; implementation matches the
  decision.
- R4: memory dedup prevents near-duplicate entries; retrieval returns
  semantically ranked results.

## Failure criteria

- R1 mocks accept any request (too loose — they're theater).
- R2 compat shim silently maps without warning (users never migrate).
- R3 Landlock default-on crashes on pre-5.13 kernels without fallback.
- R4 dedup threshold too aggressive (merging genuinely distinct memories)
  or too permissive (no dedup happens).

## Estimate

M (each R-item is S-M; total ~1 week).

## Defer note

Each R-item is independently deferrable. R3 (Landlock) may be blocked on
kernel compatibility testing across CI runners — defer with explicit
kernel-version constraint if blocked. R4 (memory) is lower priority and
may be re-scoped based on the embedding infrastructure available at
implementation time.
