# Workorder 26.2 — P0 Crash Fixes (F2 + F3)

## Status: Planned

## Priority: P0 — user-facing panics on valid input

## Problem

Two findings from the handoff audit cause runtime panics on valid/expected input:

1. **F2 — `cell.as_object_mut().unwrap()` panics on non-object JSON cell**: `src/tools/notebook_edit.rs:151` calls `.unwrap()` on a JSON Value that may be an array cell (not an object). When a notebook contains non-object cells (e.g., raw-text cells), the unwrap panics.

2. **F3 — byte-slice at multi-byte char boundary**: `src/tools/web_fetch.rs:185` slices `&output[..4000]` which can split a multi-byte UTF-8 character, producing invalid UTF-8 and a panic on subsequent string conversion.

## Source

- Handoff audit (WO 26 bug-fix series).
- F2: `src/tools/notebook_edit.rs:151`.
- F3: `src/tools/web_fetch.rs:185`.

## Requirements

### R1 — Fix F2: replace `unwrap()` with `ok_or_else`

- At `src/tools/notebook_edit.rs:151`, replace `.as_object_mut().unwrap()` with `.as_object_mut().ok_or_else(|| anyhow::anyhow!("notebook cell is not a JSON object"))`.
- Propagate the error up the call stack (the function already returns `Result`).
- Verify the error message is user-actionable (tells them which cell/type caused the failure).

### R2 — Fix F3: use `floor_char_boundary`

- At `src/tools/web_fetch.rs:185`, replace `&output[..4000]` with `&output[..output.floor_char_boundary(4000)]`.
- `floor_char_boundary` is a nightly-only method on `str`. If the toolchain is stable, use `output.floor_char_boundary(4000)` — if not available, use the manual approach: `output.char_indices().take_while(|(i, _)| *i < 4000).last().map(|(i, _)| i).unwrap_or(0)` to find the last valid boundary.
- ponytail: `floor_char_boundary` on stable Rust 1.82+ via `str::floor_char_boundary`. If toolchain is pre-1.82, add a one-liner helper; upgrade path: remove helper when MSRV hits 1.82.

## Success criteria

- Notebook edit tool returns a typed error instead of panicking on non-object cells (F2).
- Web fetch tool truncates at a valid char boundary, never panics on multi-byte split (F3).
- `cargo test -p kf-code -- notebook_edit web_fetch` passes.
- `cargo clippy --all-targets -- -D warnings` clean.

## Failure criteria

- F2 still panics on non-object cells.
- F3 still panics on multi-byte boundary.
- Error messages are not actionable.
- New dependency added for char-boundary logic.
