# Workorder 26.9 — Test Optimization and Hardening

## Status: Planned

## Priority: P3

## Problem

Test suite has known performance bottlenecks (slow individual tests),
no coverage regression gate, and testdoctor lacks parallel scanning and
result caching. These are quality-of-life issues that compound over time.

## Source

state.md — 25.2-R2, 25.2-R4, 25.3-R3, 25.3-R4, 25.4-R3, 25.7-R3,
25.8-R4/25.10-R4.

## Requirements

### R1 (25.2-R2) — Top-10 slowest individual test fix

- Profile the test suite: `cargo test -- --format json` or `cargo test
  -- --nocapture 2>&1 | grep 'test .* ok'` to identify the 10 slowest
  tests.
- For each: determine if the slowness is unnecessary setup, I/O, sleep,
  or genuine complexity.
- Fix or skip (with `#[ignore]` + documented reason) the top 10.
- Gate: total test time reduced by ≥20% from baseline, or each slow test
  has a documented reason for its runtime.

### R2 (25.2-R4) — Split slow integration tests behind feature flag

- Identify tests that require external services (Ollama, network, etc.)
  and gate them behind a cargo feature flag (e.g., `integration`).
- Default `cargo test` runs only unit/fast tests.
- `cargo test --features integration` runs the full suite.
- Gate: `cargo test` (no features) completes in ≤60s on a cold cache.

### R3 (25.3-R3) — testdoctor parallel directory scanning

- `kf-testdoctor diagnose --root .` currently scans directories
  sequentially.
- Use `rayon` or `tokio::spawn` (whichever the crate already depends on)
  to parallelize directory scanning.
- Gate: wall-clock time reduced proportionally to core count on a
  multi-core machine.

### R4 (25.3-R4) — testdoctor result caching

- Cache testdoctor results keyed by file content hash + testdoctor version.
- Skip re-analysis of unchanged files on subsequent runs.
- Cache file location: `target/testdoctor-cache.json` (gitignored).
- Gate: second run on unchanged codebase is ≥50% faster than first run.

### R5 (25.4-R3) — Coverage regression gate

- Add a CI step that compares coverage against a baseline (stored in
  `docs/bench/coverage-baseline.json` or similar).
- Fail CI if coverage drops by more than 0.5% from baseline.
- Baseline updated only via explicit PR (not auto-updated).
- Gate: `scripts/ci-local.sh` includes the coverage check.

### R6 (25.7-R3) — Benchmark manifest validation

- CI step that verifies `benches/tasks/*.toml` file count matches a
  manifest entry in `docs/bench/`.
- Prevents the README/leaderboard task count from drifting again.
- Gate: adding/removing a task file without updating the manifest fails CI.

### R7 (25.8-R4 / 25.10-R4) — Dead-id gate extension to src/

- Extend the dead-ID detection gate (currently covers `docs/`) to also
  scan `src/` for references to deleted/renamed symbols.
- Gate: `scripts/ci-local.sh` includes the dead-id check for src/.

## Success criteria

- R1: top-10 slowest tests fixed or documented.
- R2: `cargo test` (no features) completes in ≤60s.
- R3: testdoctor parallel scan shows measurable speedup.
- R4: cached testdoctor run is ≥50% faster than uncached.
- R5: coverage regression gate runs in CI.
- R6: benchmark manifest auto-validated in CI.
- R7: dead-id gate covers src/.

## Failure criteria

- R2 gates real tests behind `--features integration` but forgets to add
  the feature to `Cargo.toml`.
- R5 baseline auto-updates on every run (defeats the purpose).
- R7 produces false positives on legitimate dynamic symbol references.

## Estimate

M (each R-item is S-M; total ~1 week).

## Defer note

Each R-item is independently shippable. R5 and R6 are CI-only changes and
can land in a single PR. R3 and R4 (testdoctor) are tightly coupled and
should ship together.
