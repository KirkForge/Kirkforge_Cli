# Workorder 28.1 — Break the tools↔session Circular Dependency (H7)

## Status: Done (R1 as relocation per ADR-073; 3 non-cyclic residuals disclosed)

Production `use crate::session::` in `src/tools/`: **26 → 3** (total 34 → 8).
Cut: the toolset cycle (`tools/mod → session::toolset → tools::Tool`) and all 24
`tools → session::access` edges. Relocations: `access`→`shared::access`,
`check_bash_command_str`→`shared::bash_safety`, `UndoKind`→`shared::undo`,
toolset→`tools::toolset`, `InProcessTaskSpawner`→`session::task_spawner` (the
`TaskSpawner` port stays in `tools::task`). R1 used relocation rather than a
`Guard` trait — lower risk (compiler-verified path moves vs. 14 constructor
rewrites) and better layering; trait deferred (YAGNI, single impl). See ADR-073.

The 3 residuals are genuine session-layer concerns that need their own port
traits (out of scope here): `bash::bash_runner` shell-I/O, `bash::bash_jobs`
registry, `remember::memory` (WO 29.6). None imports `tools`, so none is cyclic.

## Problem

`src/tools/` reaches UP into `src/session/` for guards, undo, bash-safety, the
executor, and the toolset. This is a circular module dependency — `tools` depends
on the very `session` layer that owns the loop which calls `tools`. It blocks
ever extracting `tools` to its own crate (the dependency arrow points the wrong
way) and concentrates the blast radius: `gitnexus impact PathGuard` reports the
struct at `src/session/access/mod.rs:34` as **HIGH risk, 76 upstream impacted,
28 direct callers**.

The import census (verified 2026-08-12 at `5296f41`):

| Session import | Tool files | Sites |
|----------------|-----------|-------|
| `session::access::{PathGuard, DenyList, GuardVerdict}` | bash, edit_file, write_file, read_file, glob, grep, lsp_query, notebook_edit, read_image, computer_use, web_fetch, bash_minify, workflow, registry | 16 |
| `session::undo::UndoKind` | edit_file, write_file, notebook_edit | 3 |
| `session::executor::{Executor, ApprovalRequest, ApprovalResponse}` | task.rs:3 | 1 |
| `session::bash_runner::check_bash_command_str` (+`pty`) | bash.rs:3, workflow.rs:17 | 2 |
| `session::toolset::{CompositeToolset, Toolset, VecToolset}` | mod.rs:88, workflow.rs:18, task.rs:4 | 3 |

The worst inversion is `tools/task.rs:3` — a **tool** constructing the nested
**`Executor`** that drives the loop which calls the tool. That is the load-bearing
seam to cut.

## Scope

### R1 — Define a `tool::Guard` port trait + relocate `GuardVerdict`
- New `src/tools/guard.rs`:
  ```rust
  pub enum GuardVerdict { Allowed(PathBuf), Denied(String) }   // moved from access/mod.rs:21
  pub trait Guard: Send + Sync {
      fn check_read(&self, path: &Path) -> GuardVerdict;
      fn check_write(&self, path: &Path) -> GuardVerdict;
  }
  ```
- `session::access::PathGuard` implements `tools::Guard` (the multi-layer checks
  stay where they are). `access/mod.rs` re-exports `GuardVerdict` for backward
  compat (`pub use crate::tools::guard::GuardVerdict;`).
- The 11 tool files swap `use crate::session::access::{GuardVerdict, PathGuard}`
  → `use crate::tools::guard::{Guard, GuardVerdict}` and take `&dyn Guard` (or a
  generic `G: Guard`) where they currently take `&PathGuard`.

### R2 — Move pure safety/undo types into `shared/`
- `session/bash_runner/safety.rs:293-464` `check_bash_command_str` (+ the
  evasion helpers it calls) → `src/shared/bash_safety.rs`. No session state.
- `session/undo.rs:105` `UndoKind` enum → `src/shared/undo.rs` (or fold into an
  existing shared module). `session::undo` re-exports for its own callers.
- Update importers: `tools/bash.rs:3`, `tools/workflow.rs:17`,
  `tools/edit_file.rs:2`, `tools/write_file.rs:2`, `tools/notebook_edit.rs:2`
  → `use crate::shared::...`.

### R3 — Move `toolset` types to `tools/`
- `CompositeToolset`, `Toolset`, `VecToolset` live in `src/session/toolset.rs`
  but are the tools' own composition primitives. Move the **type definitions +
  trait** to `src/tools/toolset.rs`; `session::toolset` becomes the place that
  *assembles* a default toolset (imports from `tools`), not the type owner.
- Updates: `tools/mod.rs:88`, `tools/workflow.rs:18`, `tools/task.rs:4`.

### R4 — `SubagentSpawner` port for `task.rs`
- New trait in `src/tools/task.rs`:
  ```rust
  pub trait SubagentSpawner: Send + Sync {
      async fn spawn_subagent(&self, req: SubagentRequest)
          -> anyhow::Result<SubagentResult>;
  }
  ```
- `task.rs:3` drops `use crate::session::executor::Executor`; the `Executor`
  implements `SubagentSpawner` (impl in `session/executor/`). `task.rs` calls the
  trait — this is the single remaining seam and it is *intentional* (the seam is
  where the loop plugs into the tool).

## Success criteria

1. `grep "use crate::session::" src/tools/` returns **≤2 hits** (the
   `SubagentSpawner` registration site + at most one documented residual), down
   from 24.
2. `gitnexus check --cycles` no longer reports a path through
   `src/tools/... -> src/session/access/...`.
3. `cargo check --workspace --all-targets` + `cargo clippy --all-targets -- -D
   warnings` + `cargo fmt --check` PASS.
4. All existing tool tests, access tests, and executor dispatch tests pass
   unchanged (behavior-preserving move + trait indirection).
5. ADR documenting the `tool::Guard` + `SubagentSpawner` ports (the seams that
   unblock a future `kf-tools` crate).

## Failure criteria (anti-patterns to avoid)

- Introducing the `Guard` trait but leaving `PathGuard` named concretely in tool
  signatures (the count drops but the coupling doesn't — a regression per AGENTS.md §5).
- Moving `check_bash_command_str` and silently changing a blocklist verdict to
  sneak a previously-failing test green (AGENTS.md §6).
- Breaking the 30+ `safety.rs` evasion tests or the `plugin_tools` sandbox tests.
- "Splitting" by adding re-exports that keep every old path working — the
  success metric is the grep count, not "it still compiles the old way".
