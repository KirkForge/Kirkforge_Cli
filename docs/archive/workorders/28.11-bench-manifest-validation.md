### The REAL residual gap (what this WO actually does)

- **(a)** The count check covers README only; `docs/TECHNICAL.md`'s benchmark
  table (lines ~770-790) lists task rows individually and is not cross-checked
  against the directory. A task file can land without a TECHNICAL.md row (or vice
  versa) and nothing fires.
- **(b)** The toml **parse** validation (ci.yml:44-60) does not validate
  **schema** — a toml missing a required field (`name`, `prompt`, `expected`,
  etc.) parses clean but is a broken task. No `kf-bench` dry-run or schema check
  exists in CI.
- **(c)** The `EXPECTED_BENCHES` count is recomputed from scratch every run
  (good), but there is no recorded "expected set" manifest, so a rename
  (`foo.toml` → `foo_v2.toml`) keeps the count constant and silently passes.

## Success criteria

1. README count check (already works) stays green.
2. TECHNICAL.md row count matches the directory (R1) — verified by deliberately
   adding a stray row and seeing CI fail.
3. A toml missing a required key fails CI (R2).
4. A silent rename fails CI until the manifest is updated (R3).

## Failure criteria

- Hardcoding "30" instead of computing from source (re-introduces the manual drift).
- Schema check so strict it rejects legitimate task variants (false positives).
- Manifest approach that blocks legitimate new-task addition without a clear
  update path.
