# Workorder 28.5 — Landlock on Background Bash Jobs (27.5 follow-up)

## Status: Done (R1+R2; R3 test deferred — requires landlock-capable kernel)

## Problem

WO 27.5-R1 applied rlimits (`RLIMIT_CPU`/`AS`/`FSIZE`) + `unshare(CLONE_NEWNET)`
to background bash jobs, but **DEFERRED filesystem landlock confinement**. The
deferral is documented in-place at `src/session/bash_jobs.rs:180-190`:

```rust
// ponytail: rlimits only — filesystem landlock is NOT applied to
// background jobs yet. resolve_paths() lives in the private
// bash_runner::landlock module; re-exporting it requires editing
// bash_runner/mod.rs (owned by WO 27.1). Passing None gives us
// CPU/AS/FSIZE caps + CLONE_NEWNET … enough to kill a fork bomb …
// without the FS confinement.
// ceiling: a background job can still read/write anywhere the user
// can until landlock is plumbed through … upgrade path: re-export
// resolve_paths from bash_runner (WO 27.1 follow-up) and pass
// Some(paths) here.
setup_rlimits(&mut proc, cfg, None);   // bash_jobs.rs:190
```

Net effect today: a `bash` call with `background: true` is CPU/memory/fork-bounded
and network-isolated, but **a background job can still read `~/.aws/credentials`
or write anywhere the `kf-code` user can**. This is the remaining half of the H5
fix — the foreground path is fully confined (WO 27.1), the background path is not.

## Source

- WO 27.5-R1 remaining work (the deferral note above).
- The H5 review finding (background jobs skip resource limits) — rlimits half
  landed; FS-confinement half deferred.

### gitnexus evidence + reality-check (verified at `5296f41`)

- `src/session/bash_runner/mod.rs:13` — `mod landlock;` is **private** (no
  `pub(crate)`). That is the *only* reason `bash_jobs.rs` (a sibling module under
  `session/`) cannot name `bash_runner::landlock::resolve_paths`.
- `landlock.rs:143` — `pub(crate) fn resolve_paths(workspace: &Path, extra:
  &[PathBuf]) -> Option<LandlockPaths>` is **already `pub(crate)`**.
- `landlock.rs:130` — `pub(crate) struct LandlockPaths` is **already `pub(crate)`**.
- `bash_runner/mod.rs:127-130` — the real Linux `setup_rlimits` already takes
  `landlock_paths: Option<landlock::LandlockPaths>` (owned) and **uses it** at
  `:178-179` (`if let Some(paths) = &landlock_paths { match
  landlock::apply_landlock(paths) { … } }`).
- The foreground path already does the right thing — `run_shell_with_token`
  (`bash_runner/mod.rs:476`) computes `let lp = landlock::resolve_paths(workdir,
  landlock_extra_paths);` (`:496`) and passes `setup_rlimits(&mut proc, cfg, lp)`
  (`:502`). The background path just needs to mirror it.
- `BashJobRegistry::spawn` (`bash_jobs.rs:102`) already receives
  `workdir: Option<&str>` (`:105`) and `sandbox: Option<&SandboxConfig>` (`:110`).
  The only missing input is `landlock_extra_paths`.

So the fix is genuinely small: **re-export** the two already-`pub(crate)` items
through the module boundary, plumb one `&[PathBuf]` param into `spawn`, and
change `None` → the resolved paths.

## Scope

### R1 — Re-export `resolve_paths` + `LandlockPaths` from `bash_runner`
- `src/session/bash_runner/mod.rs` — add, next to `mod landlock;` (`:13`):
  ```rust
  pub(crate) use landlock::{resolve_paths, LandlockPaths};
  ```
  (Equivalently: `pub(crate) mod landlock;` — but the `use` re-export is narrower
  and keeps the module's other internals private.)

### R2 — Plumb `landlock_extra_paths` into the background spawn
- `BashJobRegistry::spawn` (`bash_jobs.rs:102`) — add a parameter
  `landlock_extra_paths: &[PathBuf]` (mirroring `run_shell_with_token`'s signature
  at `bash_runner/mod.rs:482`).
- Update the call site of `spawn` (in `src/session/executor/turn.rs`
  `dispatch_tool_call_batch`'s spawn phase, which already calls
  `read_shared_config()` per gitnexus `context` output) to pass
  `cfg.security.landlock_extra_paths`.
- At `bash_jobs.rs:190`, replace the `None`:
  ```rust
  let workspace = workdir
      .map(|w| std::path::PathBuf::from(shellexpand::tilde(w).as_ref()))
      .or_else(|| sandbox.as_ref().and_then(|c| c.sandbox_dir.clone()))
      .unwrap_or_else(|| std::env::current_dir().unwrap_or_default());
  let lp = crate::session::bash_runner::resolve_paths(&workspace, landlock_extra_paths);
  setup_rlimits(&mut proc, cfg, lp);
  ```
  (Reuse the canonicalization already done at `bash_jobs.rs:197-200` to avoid
  resolving twice.)

### R3 — Delete the deferral note + test
- Remove the `ponytail:` block at `bash_jobs.rs:180-190` (it is now resolved —
  keeping a stale "deferred" ceiling comment is a regression per AGENTS.md §5).
- Add a test (Linux-gated, `#[cfg(target_os = "linux")]`, `#[ignore]`-free) that
  a background job cannot escape FS confinement: spawn a background
  `cat ~/.aws/credentials` (or write to `/etc/`) against a sentinel file outside
  the allow-list and assert it fails with `EACCES` / nonzero exit, while a write
  inside the workspace `workdir` succeeds. Gate on `landlock_usable()` (skip on
  kernels <5.13) like the existing tests in `landlock.rs:317+`.

## Success criteria

1. `setup_rlimits(&mut proc, cfg, None)` at `bash_jobs.rs:190` is gone — the
   background path passes resolved `LandlockPaths`.
2. On a Linux ≥5.13 kernel, a background bash job that reads a path outside the
   allow-list (e.g. `~/.aws/credentials`) fails with `EACCES`; a read/write
   inside `workdir` succeeds. (Verifiable by the R3 test.)
3. The foreground behavior is unchanged (WO 27.1 still passes).
4. `cargo check --workspace --all-targets` + `cargo clippy --all-targets -- -D
   warnings` + `cargo fmt --check` PASS (Linux + the non-Linux stubs at
   `bash_runner/mod.rs:199`/`:236` still compile).
5. The `ponytail:` deferral note is removed; `state.md` closes the 27.5-R1
   remaining-work item.

## Failure criteria (anti-patterns to avoid)

- Re-exporting the *whole* `landlock` module as `pub` (over-exposure — keep it
  `pub(crate)`; only `resolve_paths` + `LandlockPaths` cross the boundary).
- Making the allow-list so tight that legitimate background jobs (`cargo
  build`, `npm install`) fail — the R3 test must include a positive case (write
  inside `workdir` succeeds).
- Forgetting the non-Linux stub signature (`bash_runner/mod.rs:199`/`:236` take
  `_landlock_paths: Option<&()>`) — the `spawn` plumbing must compile on
  macOS/Windows too (the landlock resolution becomes a no-op there).
- Leaving the stale `ponytail:` "deferred" comment in place after the fix lands.
