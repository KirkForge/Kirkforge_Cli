## Reality-check (verified 2026-08-12)

- The loopback harness already exists: `server.rs:537` `client_server_round_trip`
  builds a real daemon on a tempdir socket, waits for bind, connects via
  `connect_at`, and round-trips ping/touch/list/resolve/claim. Reuse this shape.
- Constants to pin: `CONNECT_TIMEOUT = 5s` (`client.rs:23`), `READ_TIMEOUT = 30s`
  (`client.rs:27`). Both have `ponytail:` comments documenting the tuning knob.
- The `call()` method (`client.rs:98-122`) wraps `read_line_limited` in
  `tokio::time::timeout(READ_TIMEOUT, ...)` — the line-length limiting + timeout
  compose and need a joint test.
- Auth: every request ships `read_auth_token()`; the server must reject a missing
  / wrong token. `ping_with_version` (`:64-95`) bails on version mismatch.
- Windows: `windows_imp` (line 490+) is a no-op stub that degrades to file-based
  session discovery. Needs a compile-checked smoke test (cfg-gated).

## Scope

Each R-item is one `#[tokio::test]` in a new `#[cfg(test)] mod tests` block at the
bottom of `src/daemon/client.rs` (or alongside, matching the `server.rs:489`
placement). All use the `run_daemon_at` + tempdir + `test_data_dir_lock` pattern
from `server.rs:537`. Each test must pin **behavior**, not lines.

### R1 — Connect timeout (`CONNECT_TIMEOUT`)
- File: `src/daemon/client.rs` (new `mod tests`).
- Test: `connect_at_times_out_against_nonexistent_socket` — point `connect_at` at
  a path inside a tempdir whose parent does not exist / is not writable, assert
  the `Err` lands within ~`CONNECT_TIMEOUT + slack` and names the timeout.
- Done-condition: dropping the 5s timeout breaks the test.

### R2 — Read timeout (`READ_TIMEOUT`)
- Test: `call_times_out_when_daemon_never_responds` — start a daemon that binds
  the socket but never writes a response (a stub `UnixListener` that accepts and
  parks). Assert `call()` returns the `READ_TIMEOUT` error within ~30s+slack.
  Use `tokio::time::pause` if the constant is injectable; otherwise accept the
  real wait but mark the test with a generous harness timeout.

### R3 — Auth-token handshake
- Test: `request_with_wrong_auth_token_is_rejected` — start the real daemon with
  one auth token, connect with a client holding a different token, assert the
  server returns `Response::Error` (or closes) for touch/list. Pin the
  `read_auth_token()` contract on every request method.

### R4 — Line-length limiting
- Test: `oversized_response_line_is_rejected` — daemon writes a line longer than
  `read_line_limited`'s cap; assert `call()` returns an error (not a panic, not a
  truncation). Pins the DoS guard on the daemon wire format.

### R5 — Version-gate mismatch
- Test: `connect_at_bails_on_version_mismatch` — handshake where the daemon
  reports a `version` != `CARGO_PKG_VERSION`; assert `connect_at` returns the
  "version mismatch: client {}, daemon {}" error from `ping_with_version` (`:78`).
  Drive by having the daemon echo a synthetic version in its `Response::Ok` data.

### R6 — Windows stub fallback (cfg-gated)
- Test: `windows_imp_stubs_degrade_gracefully` — under `#[cfg(not(unix))]` (or a
  dedicated `#[cfg(windows)]` test), assert `try_touch` / `try_list_recent`
  return `Ok(None)` rather than panicking, so the TUI falls back to file-based
  discovery. On unix this is a compile-only check that the stub module exists.
