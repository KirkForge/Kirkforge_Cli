# Workorder 29.9 — Delete npm/kf-plugin/ + Remove TS CI Jobs + Dependencies

## Status: Done (WO 29.8 skipped, 29.1–29.7 shipped)

## What shipped

- Deleted `npm/kf-plugin/` (entire TS tree, ~3.2 MB / ~16k LOC) and the now-dead
  `plugins/kf-plugin/` shell-plugin tree (its `tools/*.sh` scripts `exec node`
  against the deleted TS CLI — keeping them would be dead code).
- Removed the `Lint Node SDK (eslint)` CI step (`.github/workflows/ci.yml`),
  the Optional Node SDK pass (`scripts/ci-local.sh`), the Node build path
  (`scripts/build-all.sh`), and the `plugins/kf-plugin` dir check
  (`scripts/check-artifact-consistency.sh`).
- Removed `kf-plugin` from `default_plugin_sources()` (compiled-in path needs
  no filesystem source) and added it to `default_enabled_plugins()` behind the
  `kf-plugin-tools` feature flag.
- Updated `wrapper.rs::npm_bin_dirs()` — dropped the source-layout walk; only
  the data-dir layout remains (for user-installed Node-based plugin SDKs).
- Updated `native.rs` deferred messages — no Node SDK fallback to point at;
  the verify tools are stubs pending a real model client in the orchestrator
  crate (WO 29.7 shipped `PanickingClient`).
- Deleted dead tests: the three `bundled_*` tests (referenced the deleted
  `plugins/` tree), `bundled_node_sdk_tool_executes_via_host` (referenced
  `npm/kf-plugin/`), and `npm_bin_dirs_includes_source_layout_from_target_binary`.
- Fixed a pre-existing bug: `folded_plugin_identification` test asserted
  `kf-plugin` was NOT folded, but the loader listed it as folded since WO 29.1.
- Updated docs: TECHNICAL.md (plugin table, feature flags, non-Rust linting),
  config.toml.example, Cargo.toml feature comment, run_session.rs/loader.rs
  doc-comments, 28.4 workorder (superseded).

## Verification

- `grep -rn "npm/kf-plugin" src/ crates/ scripts/ .github/` → 0 hits.
- `cargo check --workspace --all-targets`, `cargo clippy --all-targets -- -D warnings`,
  `cargo fmt --check` all green.

## Problem
Once all TS packages are ported to Rust (or confirmed dead), the entire `npm/kf-plugin/` directory is dead weight: node_modules, package-lock.json, tsconfig, eslint config, the CI quality job that runs `npm run lint + npm run build`. This WO is the cleanup that makes the migration permanent.

## Source
- WO 29.0 overview: Phase 5 cleanup.
- Inventory: `core-sandbox` is dead (zero consumers); `HttpAuditSink`/`SyslogAuditSink`/`WormAuditSink` are dead; the `decompose.ts` legacy file is dead; several orchestrator exports are dead.

## Scope

### R1 — Delete npm/kf-plugin/
- `rm -rf npm/kf-plugin/` (the entire directory — all packages, apps, tests, configs).
- Remove from workspace (if it's a Cargo workspace member — check; it's npm, not Cargo).
- Remove `npm/` directory if nothing else lives there.

### R2 — Remove TS CI jobs
- `.github/workflows/ci.yml`: remove the `quality` job's Node SDK lint/build step (`npm run lint`, `npm run build` in the `quality` job).
- `scripts/ci-local.sh`: remove the "Optional Node SDK pass" section (lines ~44-51).
- Remove any `package.json`/`package-lock.json` at the repo root if they only served the npm workspace.

### R3 — Remove TS dev-dependencies
- Remove `eslint`, `typescript`, `@types/*`, `jose`, `better-sqlite3`, `zod`, `@opentelemetry/api` — all TS-only deps.
- Check: do any Rust dev-deps reference the TS workspace? (e.g., test fixtures that shell out to Node.) If so, remove those fixtures.

### R4 — Update docs
- `docs/TECHNICAL.md`: remove the Node SDK section; document the Rust-native plugin tools.
- `README.md`: remove any `npm install` references.
- `config.toml.example`: remove any TS-related config.
- `AGENTS.md`: remove references to `npm/kf-plugin` or `eslint`.
- `docs/workorders/28.4-ts-plugin-cycles.md`: mark "Superseded by WO 29 (TS code deleted)."

### R5 — Verify no Rust code references the deleted TS paths
- `grep -rn "npm/kf-plugin" src/ crates/ scripts/` → zero hits.
- `grep -rn "node_modules" src/ crates/ scripts/` → zero hits (except comments).
- The `plugins/kf-plugin/tools/common.sh` `find_cli` function: delete or replace with a no-op (if the tools are folded in 29.1, the shell scripts are already gone).

## Success criteria
1. `npm/` directory does not exist.
2. CI runs without any Node/npm job.
3. No Rust code references the deleted TS paths.
4. Binary size drops (no node_modules in the source tree — though node_modules was never in the release binary, the source tree is cleaner).

## Failure criteria
- Deleting before all ports (29.1-29.8) are verified.
- Breaking the bundled plugin for users who installed an older version with the Node SDK.
