# WO 33.12 — Kill Wall-Clock Sleeps in Tests (Phase 1)

## Status: Done (`b010aa4` + `ac8df2b`)

## Problem
Tests use `thread::sleep`, `tokio::time::sleep`, `Duration::from_secs`,
`Duration::from_millis` to wait for async operations instead of
synchronizing on events. Examples found in the audit:

- `kf-context-index/tests/edge_cases.rs` — 1s sleep for mtime
- `tests/e2e/harness/ui.rs` — 500ms after TUI startup
- `wait_stable()` — 2s stability with 500ms polling
- `wait_for_contains()` — 500ms polling
- `session/bash_jobs.rs` — 500ms/300ms/6s sleeps
- `session/hooks.rs` — 2s + multiple 50/100ms sleeps
- `session/bash_runner` — 2s sleep
- `tools/bash.rs` — 500ms + 1s sleeps
- `src/adapters/caching.rs` — 5-60ms sleeps
- `session/executor/tests/turn.rs` — 50ms sleep

## Approach
For each sleep:
1. Identify what the test is actually waiting for.
2. Replace with a deterministic primitive:
   - Channel/barrier for "operation completed"
   - `tokio::time::pause()` + `advance()` for timer behavior
   - Notify/oneshot for "event arrived"
   - Poll with short interval (10ms) + total timeout (1s) as fallback
3. Keep genuine timeout tests (testing the timeout itself) as-is.

Run per-package to avoid the hanging full workspace run:
```
cargo nextest run -p kf-code --lib <module> -j4
```

## Files
- All test files containing sleeps (see list above)

## Gate
- `cargo nextest run -p kf-code --lib <module>` passes per module
- No new `thread::sleep` or `Duration::from_secs` in test code
  (except genuine timeout tests)

## Done
Zero wall-clock sleeps in tests except genuine timeout tests.
