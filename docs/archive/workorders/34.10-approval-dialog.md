# WO 34.10 — Approval dialog: action-first, human risk wording

## Status: Done

## Problem

The approval dialog shows tool name + path + risk heuristic. The user
has to understand tool names and risk levels to make a decision. The
action (what will happen) is not the headline.

## Approach

1. Restructure the approval dialog:
   - **Headline**: the action, not the tool name. For file edits:
     `⚠ Change  src/tui/app.rs` with `+18 lines  -4 lines`. For bash:
     `⚠ Run command` with the command text.
   - **Context**: where it will execute (working directory), what it
     modifies.
   - **Risk**: standardized to `SAFE` / `REVIEW` / `DANGEROUS` with a
     one-line explanation:
     - SAFE: "Reads files only"
     - REVIEW: "Modifies project files"
     - DANGEROUS: "Can delete or overwrite data"
   - **Diff preview** (for file edits): keep the existing diff viewer.
   - **Buttons**: `[Y] Approve  [N] Reject  [A] Always` (keep existing
     keybindings).
2. The existing approval infrastructure (`src/tui/approval_keys.rs`,
   `src/tui/components/`) handles the dialog. This is a presentation
   change, not a structural one.
3. Standardize risk wording: replace the current `destructive — could
   delete data` style with the `SAFE` / `REVIEW` / `DANGEROUS` +
   one-liner format.
