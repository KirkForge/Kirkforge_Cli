# WO 34.3 — Simplify status bar

## Status: Done

## Problem

`src/tui/widgets/status.rs` squeezes 12+ indicators into one line:
model, connection, cost (turn + cumulative), tokens (sent + received),
skill count, tool-call count, round/max, carryover, memory widget,
plugin count, sandbox warning, tool-collapse toggle. The code has a
drop-loop (line 187+) that removes spans when the terminal is too narrow
and tests like `status_bar_drops_plugin_count_below_70_cols` — solving
the wrong problem by making the bar responsive via deletion.

## Root cause

Every metric that exists in the app was added to the status bar. No
curation. The bar became a dashboard instead of a status indicator.

## Approach

1. Reduce the status bar to 4 essential items:
   - Model name (e.g. `Claude Sonnet 4`)
   - Context pressure (e.g. `82% context` with color: green <50%,
     yellow 50-80%, red >80%)
   - Cost (e.g. `$0.04`)
   - State (e.g. `Ready`, `Generating…`, `Cancelled`)
2. Format: `● Claude Sonnet 4 · 82% context · $0.04 · Ready`
3. When context pressure is low (<50%), show token count instead:
   `● Claude Sonnet 4 · 8.2k tokens · $0.04 · Ready`
4. Move everything else to `/status` (already exists as a slash command)
   or the command palette details view.
5. Keep the sandbox warning (`⚠️ UNSANDBOXED`) — it's safety-critical and
   should stay visible. Append it after the 4 items when active.
6. Remove the drop-loop and the narrow-width deletion tests. The 4-item
   bar fits in ~50 chars; if it doesn't fit, truncate the model name.

## Files to touch

- `src/tui/widgets/status.rs` — rewrite `render_status`
- `src/tui/widgets/status.rs` tests — remove drop-loop tests, add 4-item
  layout tests
- `src/tui/app.rs` — remove status-bar-related UI state if any becomes

## Gate

- `cargo clippy -p kf-code --lib --tests -- -D warnings`
- `cargo fmt --check`
- `cargo nextest run -p kf-code --lib tui::widgets::status`
- Status bar shows exactly: model · context/tokens · cost · state (+sandbox warning if active)
- No drop-loop; bar fits in 50 chars

## Done condition

Status bar is 4 items + optional sandbox warning. No responsive
deletion. Everything else is in /status.
