# WO 36.2 — Bash-job owner tracking + cancel-by-owner

## Status: Done

Resolved the WO 35.3 background-jobs deferral: cancelling a subagent now
kills exactly the background bash jobs it spawned. Cancel semantics were
also hardened while here (root-cause fix required by the gate test): the
watcher parks on the child mutex inside `wait().await` for the job's whole
lifetime, so a lock-based cancel serialized behind the process's natural
exit and never fired for a long-running job — `cancel()` now flips the
status to `Cancelled` *before* the kill (the watcher preserves it) and, when
the mutex is contended, kills the process group by pid.

## Problem

WO 35.3 disclosure: when a subagent is cancelled, background bash jobs
it spawned keep running. `BashJobRegistry`
(`src/session/bash_jobs.rs:57`, process-global `OnceLock`) has no
notion of which task/session spawned a job; the child handle is
stored globally (`bash_jobs.rs:228-233`) so `kill_on_drop` never fires
when the subagent's future ends. The jobs remain manually cancellable
(`bash_cancel`, `/jobs`) but nothing ties them to the dead subagent —
a cancelled agent's `find / | slow-thing` keeps burning CPU forever.

## Root cause

`BashJobRegistry::spawn` takes no owner identifier; `ToolContext`
carries no task id, so the spawn site cannot attribute the job.

## Approach

1. Add an owner tag to job registration: `owner: Option<String>`
   (subagent task id, or a session marker for the main agent).
2. Thread it: `ToolContextBuilder` → `ToolContext` gains an optional
   `task_owner: Option<String>`; `task_spawner.rs` sets it to the
   subagent's task id when constructing the subagent's tools; the
   main session leaves it `None` (or a sentinel).
3. `TaskManager::cancel` (and `ParallelOrchestrator::cancel_all`)
   gains the final step: after the cooperative exit, cancel
   background jobs whose owner matches — registry gets
   `cancel_by_owner(owner) -> usize`.
4. Main-agent jobs (owner None/sentinel) are NEVER touched by
   subagent cancellation — that invariant gets a test.
5. Keep it small: no per-job ACLs, no priority, just the owner string.
