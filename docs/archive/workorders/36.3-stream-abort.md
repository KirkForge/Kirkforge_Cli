# WO 36.3 — Abort model streams mid-request on cancel

## Status: Done

Implemented in `fix(wo36.3)`: `stream_iteration` (turn.rs) races each
next-event await against the executor's live root cancel token
(`tokio::select!`, biased toward cancel). On cancel the flag is set (routing
into the loop's existing cancelled path: flush partial assistant message,
placeholder tool results, `Finished(Error)`) and the stream receiver is
dropped, aborting the in-flight request. No attached root token keeps the
WO 15.7 semantics unchanged. Test:
`cancel_token_aborts_stalled_model_stream` (stalled adapter = one token
then `pending()`; cancel is event-driven, no sleep-races). The WO 35.3
deferral entry for mid-request abort is resolved.

## Problem

WO 35.3 disclosure: cancelling a subagent (or a turn) does not abort
an in-flight model HTTP request. The executor's cooperative cancel
checks (`turn.rs:363,973,1019`) run BETWEEN stream events; if the
provider is slow/stalled, the request sits until the next token or
the adapter timeout. A stuck 120s+ provider stream keeps the turn
alive after the user cancelled.

## Root cause

The adapter stream future (`adapter.stream(...)` inside the turn
loop) is awaited inline without selecting against cancellation. The
cancel token exists (`ToolContext`, executor `set_cancel_token` from
WO 35.3) but is not racing the stream.

## Approach

1. In the stream-iteration site (`src/session/executor/turn.rs`,
   `stream_iteration` or the loop awaiting adapter events), wrap the
   next-event await in `tokio::select!` against the live cancel
   token: on cancellation, drop the stream future (dropping a reqwest
   response future aborts the request — same semantics the WO 35.2/3
   work relies on) and return the cooperative-cancelled outcome the
   loop already knows how to handle.
2. Respect the existing snapshot-token semantics where they apply
   (WO 15.7): if the root token is absent, behavior is unchanged.
3. Test: mock adapter that emits one token then never completes
   (pending future / wiremock with a stalled response); set the
   cancel flag mid-stream; assert the turn returns Cancelled within a
   bounded window (~2s), not at the adapter timeout. There may be an
   existing slow-stream mock pattern in `src/session/executor/tests/`
   — reuse it.
4. Do not add per-chunk overhead: the select races only the
   next-event await, no polling loops.
