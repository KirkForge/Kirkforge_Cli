# WO 38.11 — TUI state hygiene

## Status: Done

## Problem (TUI audit; executor-zombie overlap with 38.5)

1. **P1 — executor death = silent zombie UI** (loop_.rs:538-547 +
   keys/mod.rs:1630-1641): after the first turn error, every Enter
   silently discards input. (Exit-on-error fix lands in 38.5; this WO
   adds the input-failure UX: system entry "backend exited — /exit to
   quit" + input restore.)
2. **P1 — chat render cache serves stale lines** after
   CompactionReport/prune_display_messages/fork-swap mutate the
   message list without `clear_entries()` (events.rs:362, 529-560;
   fork.rs:153-180) → post-/compact shows pre-compaction chat.
3. **P1 — `thinking_buffer` unbounded across session** (app.rs:298,
   events.rs:174-176; only /clear and /resume clear it) + re-wrapped
   per frame — tens of MB + O(total) per frame on long
   reasoning-model sessions.
4. **P1 — streaming PTY tool card grows unbounded**
   (events.rs:424-437) — `watch`-style commands balloon the card and
   every frame renders the full string.
5. **P1 — chat scroll offset truncated to u16** (chat/mod.rs:354):
   >65,535 wrapped lines → view wraps to top while the indicator
   claims otherwise.
6. **P1 — doom banner vs approval dialog z-order/key-routing
   conflict** (mod.rs:994-999 vs 1203-1242): banner drawn on top but
   keys go to the approval handler; Esc denies the approval instead
   of dismissing the banner.
7. **P2 set**: TurnEvent::Error leaves stale `streaming`/`continuation`
   flags; approval dialog re-reads + re-diffs the file every frame at
   8Hz (memoize on (identity, mtime)); textwrap width-0 degenerate
   wrap on tiny panes; doom banner renders hardcoded selection index;
   `short_ts` byte-slicing (covered in 38.1 if landed there); mouse
   click on wrapped lines mis-maps; help overlay over approval; paste
   cap; O(content) per-frame re-wrap of long streams.

## Approach

Per finding: clear_entries in the three mutation paths (or a
generation counter in the cache key); thinking_buffer cleared on
TurnComplete (retain last N KB ring if the panel needs history); PTY
card keeps tail 64KB + byte-count marker; scroll clamp with a
`ponytail:` u16 ceiling note; doom-banner keys routed above approval
when unacknowledged; P2s individually small.

## Gate

Standard TUI suite + tests: compact → cache cleared (render after
compact shows compacted content), thinking buffer bounded across 100
turns, PTY card capped, doom+approval key routing both ways.

## Done condition

No stale-render path after list mutation; no unbounded per-session
buffer in the UI layer; no stuck-overlay key traps.
