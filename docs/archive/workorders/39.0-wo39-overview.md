# WO 39.0 — Series overview: prove the thesis, borrow the ecosystem

## Status: In Progress

Two strategic tracks from the audit wave (bench readiness + Claude
compat explorations). WO 38 makes the machine stable; this series
makes the machine *matter*: run the benchmark that proves the token
thesis, and defuse the ecosystem-moat claim by consuming the Claude
plugin ecosystem directly.

unimplemented `output_contains` variant — fails all 30). The
cross-tool script is broken four ways; 5/30 tasks are free-wins;
no external-agent harness exists. `verified_success/total_tokens`
is computable for kf-code alone once loading is fixed.

## Track B — Claude ecosystem compat (exploration verdict: YES, ~500-900 LOC for 80%)

kf-code already scans `.claude/skills` by default, matches Claude's
hook exit-2 deny convention, speaks full MCP, and has the Claude
hooks JSON schema pinned in-repo (ADR-0009). OpenCode's "runs
everything" reputation rests on exactly the layers kf-code already
has plus discovery glue.

| WO | Title |
|----|-------|
| 39.2 | Compat phase 1: skill trigger derivation (~10 LOC — every existing Claude skill becomes invocable), `.claude/commands` loader, `.mcp.json` discovery + approval gate |
| 39.3 | Compat phase 2: `.claude/agents` dynamic personas + tool-name alias table + prompt-alias suffix |
| 39.4 | Compat phase 3 (deferrable): hook stdin-JSON contract + generic pre/post-tool events per ADR-0009 |

Disclosed non-goals: marketplace/distribution (git-clone import
instead), model-invoked skills (phase-2 candidate), MultiEdit
multi-hunk semantics (aliases to sequential edits).
