# WO 40.1 — CI workflow architecture reset

## Status: Done

> Audit on 2026-08-20 found the WO 33.x + ADR-074 work had already landed
> items 2-7 in this worktree's starting state (dev `4969d6e4`):
> `fmt`→`static` rename, artificial `needs:` removal, PR/merge/nightly
> split, path-aware conditional skip via `changed-packages.sh`, redundant
> `cargo check` removal, and incident-history comment cleanup. Concurrency
> blocks already present on ci-pr/ci-merge/ci-nightly. The one remaining
> gap was `release.yml` (no concurrency block); this WO added it with
> `cancel-in-progress: false` (a re-tag must not kill an in-flight
> release). ci-nightly keeps `cancel-in-progress: false` and ci-pr/ci-merge
> keep per-PR isolation (`github.event.pull_request.number || github.ref`)
> per ADR-074.

## Problem (GPT doc §CI-workflow-analysis, items 78-80, P0)

1. No concurrency cancellation — 3 rapid pushes = 3 full CI runs
   (items 78-80, 🔴 Huge).
2. Artificial `needs:` dependencies — e2e/coverage depend on quality,
   creating a false critical path (item 4).
3. PR validation runs the same weight as post-merge — no PR fast path
   (item 3, the whole workflow shape).
4. Ollama + coverage in normal PR validation (items 7-8).
5. `fmt` job does 4 unrelated things (item 12).
6. Historical workaround comments accumulate (item 11).
7. No path-aware execution — a README edit triggers full Rust tests
   (item 85, 🔴).

## Approach

1. Add `concurrency: { group: ci-${{ github.workflow }}-${{ github.ref }},
   cancel-in-progress: true }` to ALL workflows.
2. Remove artificial `needs:` — e2e/coverage/windows are siblings of
   quality, not children.
3. Split: PR = static + fast-tests + clippy (only); post-merge = full
   + windows + e2e; nightly = ollama + coverage + slow.
4. Rename `fmt` → `static` (conflict markers + TOML + artifact
   consistency + rustfmt).
5. Add path-aware `paths:` filters: `docs/**`, `*.md`,
   `.github/**` → skip Rust test jobs (static only).
6. Remove redundant `cargo check` (clippy IS the compile gate).
7. Clean historical workaround comments — keep only current
   architecture rationale.

## Gate

Workflows parse (YAML valid); a docs-only push triggers NO Rust
test jobs; a code push triggers PR-gate only (not full); concurrency
cancellation visible in the workflow YAML.

## Done condition

PR CI runs 3 jobs (static + fast-tests + clippy), not 6+; a superseded
push is cancelled; a README edit skips Rust entirely.
