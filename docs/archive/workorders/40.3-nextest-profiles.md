# WO 40.3 — Nextest profiles + timeout policy

## Status: Done

## Problem (GPT doc items 61-62, 8-10, P1)

1. No nextest profiles — every CI job uses inline `--config` flags
   duplicated across YAML (item 10).
2. No per-tier timeout policy — fast tests get the same 60s timeout
   as integration tests (item 61).
3. No slow-test budget — a test can become 10x slower without anyone
   noticing (item 62).
4. `--no-fail-fast` everywhere including PR — PR should fail fast
   (item 9).

## Approach

1. Create `.config/nextest.toml` with profiles:
   - `ci-fast`: timeout 30s, fail-fast, skip `#[ignore]`
   - `ci-full`: timeout 60s, no-fail-fast, skip `#[ignore]`
   - `integration`: timeout 120s, no-fail-fast
   - `e2e`: timeout 300s, no `#[ignore]` skip (run them)
   - `nightly`: timeout 600s, include slow/external
2. Each profile overrides the default with per-test-group timeouts
   where nextest supports them.
3. CI workflows reference profiles by name:
   `cargo nextest run --profile ci-fast` — no inline `--config`.
4. PR uses `ci-fast` (fail-fast); merge uses `ci-full`; nightly uses
   `nightly`.
5. Add a slow-test report step: `cargo nextest run --profile ci-full
   --message-format json` → extract top-20 slowest → post as a CI
   summary (or a warning if any test > 10s).

## Files to touch

- `.config/nextest.toml` (new)
- `.github/workflows/ci-pr.yml` (use `--profile ci-fast`)
- `.github/workflows/ci-merge.yml` (use `--profile ci-full`)
- `.github/workflows/ci-nightly.yml` (use `--profile nightly`)
- `scripts/test-fast.sh` (use `--profile ci-fast`)
- `scripts/test-full.sh` (use `--profile ci-full`)
- `scripts/ci-local.sh` (use the profiles)

## Gate

`cargo nextest run --profile ci-fast` works locally; profiles parse;
CI YAML references them by name (no inline `--config`); slow-test
report visible in CI output.

## Done condition

Test policy lives in `.config/nextest.toml`, not in YAML; PR fails
fast; slow tests are visible; adding a 30s test to the fast profile
triggers a profile-assignment question.
