# Workorder 40.5 — Global State Isolation (env/cwd/serial)

## Status: Done

## Priority: P2 — parallel-test correctness

## Problem

Tests mutated process-global state (CWD, env vars, OnceLock registries)
without RAII guards or shared serialization, causing parallel-test flakes.
The CWD guard pattern existed privately in `src/tools/workflow.rs`; env
mutation was partially guarded by `EnvGuard` in `test_util.rs` but several
tests still used raw `set_current_dir`/`set_var`. Data-dir tests mutated
`KF_CODE_DATA_DIR` (process-global env) under a shared mutex, serializing
needlessly when a thread-local override would allow parallel isolation.

## Changes

### 1. CwdGuard (hoisted to test_util.rs)
- Hoisted the private `CWD_GUARD`/`cwd_lock()` from `src/tools/workflow.rs`
  into `src/shared/test_util.rs` as a public `CwdGuard` (RAII, restore-on-
  panic, shared serializing `tokio::sync::Mutex`).
- Converted `src/tools/workflow.rs` (2 tests), `src/tools/glob.rs` (1 test),
  `src/tui/commands/workflow.rs` (3 tests) to use `CwdGuard`.

### 2. EnvGuard audit
- Converted `src/session/bash_runner/mod.rs` `run_shell_child_env_scrubs_secret_vars`
  from raw `set_var`/`remove_var` to `EnvGuard`.
- Verified `src/adapters/auth.rs` (9 tests), `src/session/verifier/security.rs`
  (PATH mutation tests), `src/session/config/mod.rs` (env override tests) —
  all already use `EnvGuard` with appropriate serialization locks.

### 3. Data dir injection
- Added `DataDirGuard` (thread-local override) in `src/session/mod.rs`:
  `data_dir()` checks the thread-local override first, before `KF_CODE_DATA_DIR`.
- Converted `src/session/session_index.rs` (15 tests) and 4 `session/mod.rs`
  tests from `EnvGuard`+`test_data_dir_lock` to `DataDirGuard` — no env
  mutation, no lock, parallel-safe by thread isolation.
- `data_dir_respects_env_override` test keeps `EnvGuard` (it tests the env-
  var path specifically).

### 4. #[serial] for OnceLock registries
- Added `serial_test` dev-dep (zero binary-size impact — dev-dep only).
- `#[serial]` on 5 tests that mutate `SESSION_MODE` (OnceLock registry):
  `session_mode::session_mode_round_trip`, `stratum::session_mode_round_trip`,
  `stratum::default_budget_sliced_listener_returns_some`,
  `budget::test_apply_budget_slice_auto_escalates_lite_to_full_on_approaching`,
  `budget::test_pre_compact_hook_runs_stratum_compression`.
- Each has a comment explaining why injection is impossible (production code
  reads `SESSION_MODE` via `current_session_mode()` across module boundaries).

## Gate

- Grep for unguarded `set_var`/`remove_var`/`set_current_dir` in test code:
  zero results (remaining hits are production code or comments).
- `cargo nextest run -p kf-code --lib --no-fail-fast` green (run 2x).
- `cargo clippy -p kf-code --lib --tests -- -D warnings` clean.

## Failure criteria

- Removing `#[serial]` from a `SESSION_MODE` test (race returns).
- Using `CwdGuard` for a test that doesn't mutate CWD (wrong tool).
- Using `DataDirGuard` for a test that tests the env-var path (bypasses it).

## Defer note

The following `test_data_dir_lock` callers were NOT converted to
`DataDirGuard` (out of scope — not named in this WO): `src/daemon/` (6
tests), `src/tui/commands/plugins/` (1 test), `src/session/plugin_ops.rs`
(1 test), `src/session/plugin_tools/tests.rs` (1 test), `src/session/undo.rs`
(1 test). These still mutate `KF_CODE_DATA_DIR` env under the shared lock.
Converting them is tracked as remaining work for a future WO.
