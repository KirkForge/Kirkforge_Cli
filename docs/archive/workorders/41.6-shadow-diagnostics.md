# WO 41.6 — Shadowed-rule diagnostics in /permissions list

## Status: Done

## Problem

First-match-wins means `#1 bash:* → allow` shadows `#2 bash:command=rm -rf ** → deny` — the deny is unreachable. Documented and tested, but the user gets no warning. A production agent should surface this.

## Approach

In `/permissions list` output, for each rule, check if any earlier rule matches the same (tool, key) with a broader or equal pattern. If so, emit `⚠ Rule #N is shadowed by rule #M`. Pure function, testable. Small.

## Gate

Standard clippy (Linux + Windows cross-compile), fmt, nextest. Test: shadowed rule detected, non-shadowed rule no warning.
