# WO 41.8 — Audit logging of which permission rule caused a decision

## Status: Done

## Problem

`evaluate()` returns an action but doesn't record WHICH rule matched. For a security-sensitive system, logging "rule #3 (bash:command=rm -rf ** → deny) matched command `rm -rf /tmp`" is the missing piece.

## Approach

1. `evaluate()` returns `(PermissionAction, Option<usize>)` — the index of the matching rule (or None for default). Minimal signature change; update callers.
2. The executor's pre_run path logs the matched rule (tool name, pattern, action, rule index) to tracing at debug level.
3. The audit log entry includes the rule that caused the decision, not just the tool name.
4. Test: evaluate returns the correct rule index; the first-match-wins test checks the index.

## Gate

Standard clippy (Linux + Windows cross-compile), fmt, nextest. Test: rule index returned and logged.
