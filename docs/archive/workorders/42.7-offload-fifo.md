# WO 42.7 — Offload store: fix false FIFO + add byte cap

## Status: Done

## Problem
`InMemoryOffloadStore` in `crates/kf-compress-core/src/store.rs` had only
`max_entries` — no byte cap. Eviction took `guard.keys().take(excess)`, and
`HashMap` iteration order is random, not FIFO despite the `ponytail:` comment
at line 61 claiming "evict FIFO if throughput matters." The comment was
aspirational; the code was random-order.

## Fix
- Replaced the bare `HashMap<String, String>` with an insertion-ordered
  `StoreData { map, order: VecDeque<String>, total_bytes: u64 }` behind one
  `RwLock`. `order` tracks insertion sequence (front = oldest); `map` keeps
  O(1) lookup; `total_bytes` is a running byte counter.
- `evict_if_over_cap` now pops from the front of `order` (true FIFO) until
  under BOTH `max_entries` and `max_bytes`.
- Added `new_with_byte_cap(max_entries, max_bytes)` constructor.
- The `ponytail:` comment is now accurate — FIFO is implemented.
- No new dependency (`indexmap` is not a workspace dep; stdlib `VecDeque` +
  `HashMap` suffice).

## Tests added
- `evict_if_over_cap_is_fifo` — insert A,B,C cap=2 → A evicted, B+C remain.
- `byte_cap_evicts_oldest_first` — byte cap evicts oldest first.
- `byte_cap_evicts_multiple_until_under_cap` — evicts down to 1 when needed.
- `both_caps_enforced_together` — entry cap and byte cap both bind.
- `duplicate_put_does_not_grow_order` — duplicate key does not double-count.

## Scope
- `crates/kf-compress-core/src/store.rs` only (plus this workorder + README
  index row + CHANGELOG).
- `crates/kf-budget-core/src/store.rs` has a parallel `InMemoryOffloadStore`;
  it is a separate type and was NOT touched.
