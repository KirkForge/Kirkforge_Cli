  reqwest re-enables the rest. Profile :335-340 (z/lto/cgu-1/strip/abort)

## Root cause

Deps added per-WO with default features and no size gate at add time;
`computer_use` is documented default-OFF (:288) but its heavy impl was never
actually compile-gated.

## Approach

1. `aws-sigv4` "1.2" → "1.3" (:217) — drops http 0.2 + http-body 0.4. ~100-200 KB.
2. `arboard = { version = "3", default-features = false }` (:199) — drops
   image+png+flate2. ~0.5-1 MB. Verify Wayland copy path still works.
3. base64 → "0.23" (root :193 + crates/kf-orchestrator/Cargo.toml) — unifies
   with tiktoken. ~10-20 KB.
4. rustyline 14 → 15/16 (:150) — dedupes unicode-width. Small; check API.
5. Replace handlebars with ~30-line `{{var}}`/`{{#each}}`/`{{#if}}` renderer +
   a construct-freeze test on system.hbs — drops pest stack. ~300-500 KB.
   Skip if templates outgrow the subset.
6. headless_chrome `optional = true` + `computer_use = ["dep:headless_chrome"]`,
   cfg-gate chrome_launcher.rs + real impls (PlaceholderTab stays ungated).
   ~1-2 MB, biggest win. DEFER-disclosure required: default builds lose local
   Chrome execution until the feature is on; align messaging with 43.5.

Per item:
1. aws-sigv4 → 1.3: **REFRESHED, DEDUP NOT ACHIEVABLE**. Root Cargo.toml
   says `1.3`; lock pinned to the highest MSRV-≤1.88 set (sigv4 1.3.8,
   smithy-http 0.63.3, runtime-api 1.11.3, types 1.4.3, async 1.2.11,
   credential-types 1.2.11 — newer set needs rustc 1.91–1.94, toolchain is
   1.88). The http 0.2 + http-body 0.4 dedup hoped for here is upstream-
   blocked: `sign-http` (the `http_request` module Bedrock signing uses)
   itself depends on http 0.2 for canonical-request internals (E0433
   evidence when http1 is off), and aws-smithy-http's default features
   keep http-body 0.4 alive via aws-smithy-types' byte-stream-poll-next.
   Feature list is now `["sign-http", "http1"]` (http1 required for the
   module's http 1.x types). Original premise ("1.3.8 requires http ^1.3.1")
   read the dependency addition, not the sign-http feature structure.
2. arboard `default-features = false`: **DONE**. image-data chain dropped
   (image/png/tiff/fax/zune-jpeg/weezl/fdeflate/bytemuck/byteorder-lite/
   zune-core/moxcms/pxfm/num-modular/num-order gone from the lock). Sole
   call site is `set_text` (text-only). **UNVERIFIED: Wayland clipboard
   path needs a manual check** — in a Wayland session run the TUI, select
   output, press Ctrl+Shift+C, then `wl-paste` / paste into an editor and
   confirm the text arrives. (X11/other backends compile; arboard without
   image-data still builds wayland-data-control via its `wayland-data-control`
   feature, which remains in defaults.)
3. base64 → 0.23: **DONE for direct deps** (root + kf-orchestrator now
   0.23, unified with tiktoken). base64 0.22.1 REMAINS as a transitive dep
   of hyper-util (via reqwest) and jsonwebtoken (kf-rbac) — not removable
   without patching transitive crates; the "single copy" goal is blocked
   there. Size delta ≈ 0 (both copies still compile).
4. rustyline 14 → 16: **DONE**. `line_mode.rs` API surface
   (DefaultEditor/Config::builder/ColorMode/ReadlineError) unchanged;
   unicode-width deduped to a single 0.2 copy.
5. handlebars → mini renderer: **DONE + CORRECTED**. The salvaged renderer
   lacked Handlebars' stand-alone-tag line stripping (would have emitted
   extra blank lines around comments and {{#if}}/{{#each}} blocks). Ground
   truth was captured from a real handlebars 6 render; the renderer now
   matches it byte-for-byte, locked by two golden tests
   (`test_render_matches_handlebars_reference{,_no_thinking}`). Both call
   sites (build/build_stem) route through the same `render_template`.
   Bonus bug fix: the old template's `{{! ... {{#if x}} ... }}` comment
   leaked ` block is rendered only for models }}` into every system prompt
   (handlebars ends `{{!` at the first `}}`); template comments rewritten
   as `{{!-- --}}`. Construct-freeze test present and fails on unsupported
   syntax ({{else}}, {{#unless}}, {{> partial}}, {{{unescaped}}}, …).
   Ceiling: no HTML-escaping of values (fine for identifier-like data);
   nested-block stand-alone interaction approximate; user template
   overrides using old-style `{{! }}` comments with nested `}}` may leak
   text (ponytail comment in prompt/mod.rs).
6. headless_chrome optional + real `computer_use = ["dep:headless_chrome"]`
   feature: **DONE**. chrome_launcher.rs module-gated, real impls + the two
   Chrome-requiring tests cfg-gated, PlaceholderTab fallback ungated
   (run_session warns when config enables computer_use but the Cargo
   feature is off). Verified compiles both with and without the feature.
   TECHNICAL.md feature-flag section updated in the same push.
   **DEFERRED (by design, disclosed): default builds lose local Chrome
   execution** until rebuilt with `--features computer_use`; the hosted
   (Anthropic-side) computer_use wire format is unaffected. Align
   release/messaging with WO 43.5 when shipping.
