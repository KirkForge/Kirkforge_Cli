# WO 43.29 — Prompt-compaction out-of-bounds panic (minify_old_messages)

## Status: Done

## Problem

Fresh segment audit (round 4). `build_messages_with_compaction` passes the
PRE-microcompact full `messages` slice AND the POST-microcompact `adjusted`
(which may be strictly shorter) to `minify_old_messages(&messages, &mut
adjusted)`. Inside (`src/session/prompt/mod.rs:827,853`), it iterates `i`
over the longer `messages` and, for any non-tool message whose minified text
saves >20 chars, executes `adjusted[i].content = minified`. When
microcompaction has already collapsed the middle messages into a single
summary, `adjusted.len()` ≈ 7 (anchor + summary + tail) while `messages.len()`
can be arbitrarily larger, so `i >= adjusted.len()` indexes out of bounds →
**panic**. This branch is reachable exactly when the compacted form still
exceeds the budget (`result.tokens_after > budget`, `mod.rs:625`), which the
over-budget continuation at `mod.rs:628-631` routes into.

The call is at `mod.rs:633`; the OOB write is `mod.rs:853` (line 854 resets
`adjusted[i].token_count`).

## Root cause

`minify_old_messages` writes into the shorter `adjusted` vector using indices
derived from the longer `messages` vector, without an `i < adjusted.len()`
guard. The two vectors diverge in length precisely on the over-budget path.

## Approach

Guard the write with `if i < adjusted.len()`. (Passing `&adjusted` instead of
`&messages` is not sufficient — the iteration still needs the pre-minify
`messages` for content, so the guard is the correct, minimal fix.) Add a
pinning test that forces microcompaction + over-budget and asserts no panic.

## Gate

`scripts/test-fast.sh`, `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check`. New OOB-guard test green.

## Done

The over-budget continuation path cannot panic on index-out-of-bounds.
