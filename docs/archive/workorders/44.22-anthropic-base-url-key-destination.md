# WO 44.22 — First-party Anthropic sends `x-api-key` to the Ollama default host

## Status: Done

## Problem

The first-party Anthropic adapter has no provider-correct base URL. Every
production construction passes `cfg.model.ollama_host` as the Anthropic
API base (src/adapters/mod.rs:558-563 in `adapter_for_with_provider` — the
only non-test call site of `AnthropicAdapter::new`; the same value flows
through `AdapterSwap` at src/session/executor/mod.rs:250-252, the task
spawner at executor/mod.rs:512-524, and `sampling_adapter` at
adapters/mod.rs:596-626). `ollama_host` defaults to
`http://localhost:11434` (src/shared/config/model.rs:179) and only
`--host` overrides it (src/main/run_session.rs:76-78).

Consequences with `kf-code run -m claude-sonnet-4`, `ANTHROPIC_API_KEY`
set, and stock config:

1. The request goes to `http://localhost:11434/v1/messages`
   (anthropic/mod.rs:155) — Ollama does not speak the Messages API, so
   first-party Anthropic is broken out of the box.
2. **Credential hygiene**: the `x-api-key` header carrying the real
   Anthropic key (anthropic/mod.rs:180) is transmitted to whatever
   process owns port 11434 on localhost — and in cleartext whenever
   `ollama_host` is an `http://` remote. config.toml.example:102-105
   documents `anthropic_api_key` "for direct Anthropic access" but never
   tells the user they must also repoint `ollama_host`; WO 17.1 (Done)
   fixed the auth header but left the base-URL wiring on the shared
   Ollama knob.

Sibling wiring bug, same area: the OpenAI-compat adapter builds
`{api_base}/v1/chat/completions` after only trimming trailing slashes
(openai_compat/mod.rs:424, 545). A user who sets
`ollama_host = "http://localhost:11434/v1"` — the canonical OpenAI-compat
base in Ollama's own docs — gets `/v1/v1/chat/completions` → 404.

## Root cause

`ollama_host` predates the cloud adapters and became the single shared
base-URL knob for every adapter kind; no per-provider base was ever
introduced when Anthropic auth landed (WO 17.1), and the OpenAI-compat
path-doubling was never re-checked against how users actually configure
Ollama's compat endpoint.

Long-term shape (not this WO — tracked here so the next adapter wiring
doesn't re-introduce the shared-knob): `ModelConfig` should carry
per-provider bases (`ollama_host`, `anthropic_api_base`,
`openai_api_base`, `vertex_endpoint`) rather than one historical
`ollama_host` becoming a universal adapter endpoint. This WO adds the
first of those (`anthropic_api_base`); the openai_compat `/v1` de-dup is
a localized fix, not the full refactor.

## Approach

1. Add `anthropic_api_base` to `[model]` (String, default
   `"https://api.anthropic.com"`), threaded exactly like
   `anthropic_api_key`: `adapter_for_with_provider` Anthropic branch,
   `sampling_adapter`, `AdapterSwap` construction. `ollama_host` stops
   being consulted for `AdapterKind::Anthropic`.
2. openai_compat: after the trailing-slash trim, strip one trailing
   `/v1` suffix (`strip_suffix("/v1")`) before appending
   `/v1/chat/completions`, so both `:11434` and `:11434/v1` bases work.
3. config.toml.example: document `anthropic_api_base` and the accepted
   `ollama_host` forms for the compat endpoint.
4. Tests: `adapter_for_with_provider` with default config builds an
   Anthropic adapter whose endpoint is `https://api.anthropic.com/v1/messages`;
   base-URL builder test for the `/v1` de-dup (both suffix forms).

## Done

1. Added `anthropic_api_base` to `[model]` config (String, default
   `"https://api.anthropic.com"`), threaded through `adapter_for_with_provider`
   (new last param), `adapter_for` wrapper, `sampling_adapter`, `AdapterSwap`
   (`maybe_swap` + `force_swap`), `run_session`, `bench`, `persona`,
   `task_spawner`, and all test call sites (10 files, 16 call sites).
   `ollama_host` is no longer consulted for `AdapterKind::Anthropic`.

   (`trim_end_matches("/v1")`) before appending `/v1/chat/completions`, so
   both `:11434` and `:11434/v1` bases work.
3. config.toml.example: documented `anthropic_api_base` and the accepted
   `ollama_host` forms (both `:11434` and `:11434/v1`).
4. Tests: `adapter_for_with_provider_anthropic_uses_dedicated_api_base`
   (default config builds Anthropic adapter with correct base, not
   ollama_host), `adapter_for_with_provider_anthropic_custom_base` (custom
   proxy base), `default_api_base_produces_correct_messages_endpoint`
   (endpoint = https://api.anthropic.com/v1/messages), openai_compat
   `/v1` de-dup tests (both suffix forms + non-v1 path preserved).
5. docs/TECHNICAL.md: updated provider section with per-provider base URLs
   paragraph (doc-sync rule §9).
