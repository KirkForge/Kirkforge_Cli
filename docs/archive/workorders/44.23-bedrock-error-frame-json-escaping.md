# WO 44.23 — Bedrock error frames interpolate transport errors into JSON unescaped

## Status: Done

## Problem

When the Bedrock event-stream transport yields an `Err` chunk, the
envelope wrapper injects a synthetic Anthropic error frame by string
interpolation (src/adapters/anthropic_bedrock.rs:192-196):

```rust
let payload = format!("data: {{\"type\":\"error\",\"error\":{{\"message\":\"{e}\"}}}}\n\n");
```

`{e}` is the raw `Display` of the transport error, dropped into a JSON
string context with no escaping. Two failure modes:

1. **Error laundering.** reqwest/hyper error text containing `"`, `\`, or
   newlines produces an invalid JSON frame; the shared Anthropic parser
   then emits `StreamEvent::Error("JSON parse: ...")` (sse.rs:211-221)
   instead of the real transport cause. Operators debugging a mid-stream
   Bedrock drop see a parse error, not "connection reset".
2. **Frame smuggling (hardening).** The parser locates frames by scanning
   for the `data: ` substring anywhere in the buffer — not line-anchored
   (sse.rs:58) — so multi-line error text, or text containing
   `data: {...}\n\n` sequences, becomes additional parsed frames. Today
   the error text originates from reqwest `Display` (URL + OS/hyper
   phrasing), so exploitation requires a hostile network path — but the
   wrapper should not be structurally capable of injecting parser frames
   from error text at all.

Note: the unconditional `[DONE]` injection at anthropic_bedrock.rs:199 is
WO 43.22 item 1 (in flight) — this WO is the OTHER injection site in the
same wrapper and should land with or after 43.22 to avoid conflicting
edits.

## Root cause

The envelope wrapper predates WO 38.5's framing rules and hand-rolls JSON
via `format!` instead of `serde_json::json!`; the transport-error branch
was never exercised with error text that isn't JSON-clean.

## Approach

1. Build the frame with `serde_json::json!({"type":"error","error":{"message": e.to_string()}})`
   and `format!("data: {payload}\n\n")` — one-line change, escaping for
   free. Apply the same construction to the envelope-overrun message at
   anthropic_bedrock.rs:167-172 for consistency (it is currently static
   text, but keep the two sites uniform).
2. Test: drive `parse_bedrock_event_stream` with a stream that yields
   `Err("conn \"reset\"\nby peer")` — assert exactly one
   `StreamEvent::Error` whose payload contains the original text
   verbatim, and that no `JSON parse:` error and no extra events are
   emitted.

## Done

Both error-frame injection sites in `parse_bedrock_event_stream`
(`src/adapters/anthropic_bedrock.rs`) now build the JSON payload via
`serde_json::json!` instead of `format!` string interpolation:

1. **Err-chunk branch** (transport error): the raw `Display` of the
   transport error is passed through `serde_json::json!({"type":"error",
   "error":{"message": e.to_string()}})`, which escapes quotes, backslashes,
   and newlines. The frame can no longer be broken JSON or smuggle extra
   `data:` lines through the parser.

2. **Envelope-overrun branch** (8 MiB cap): same construction for
   consistency, even though the message is currently static text.

New test `parse_bedrock_event_stream_escapes_transport_error_text` feeds
`Err("conn \"reset\"\nby peer")` and asserts exactly one
`StreamEvent::Error` whose payload contains the original text verbatim
(quotes + newline preserved), no `JSON parse:` error, and no extra events.
