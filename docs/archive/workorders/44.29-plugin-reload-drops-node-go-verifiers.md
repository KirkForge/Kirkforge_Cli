# WO 44.29 — `/plugins` reload silently drops the Node/Go/Generic verifiers

## Status: Done

## Problem
`Executor::init_default_verifiers` (`src/session/executor/mod.rs:587-941`) registers 14
built-in verifiers into the `VerifierSlots`: security, lint, build, git, rustfmt, test,
python_test, python_lint, python_typecheck (WO 31.1) **plus** node_test (:800-818),
node_lint (:820-838), go_test (:840-858), go_vet (:860-878), generic_test (:880-898)
(WO 32.20, commit `598841da`).

But `rebuild_plugin_verifiers` — invoked from `reload_plugins` on every `/plugins` reload
(`src/session/executor/loop_.rs:271-282` → `mod.rs:984-1068` → `mod.rs:947-978`) — prunes
with a stale allowlist:

```rust
// src/session/executor/mod.rs:948-958
const BUILTIN_VERIFIERS: &[&str] = &[
    "security", "lint", "build", "git", "rustfmt", "test",
    "python_test", "python_lint", "python_typecheck",
];
...
s.retain(|v| BUILTIN_VERIFIERS.contains(&v.name()));   // :970
```

The five WO 32.20 verifiers are not in the list, so the first live plugin reload in a
Node/Go/generic workspace permanently removes them from the correction loop for the rest of
the session — file edits in a JS/TS/Go project stop being verified (no node_test failures
surfaced, no auto-fixes), with no log line announcing the loss. The Python entries prove the
list was supposed to track `init_default_verifiers` (WO 31.1 updated it; WO 32.20 did not).

## Root cause
`BUILTIN_VERIFIERS` is a hand-maintained duplicate of the built-in registration set in the
same file. WO 32.20 added five registrations to `init_default_verifiers` but never extended
the retain list, so reload treats the new built-ins as stale plugin verifiers and drops them.

## Approach
1. Add `"node_test"`, `"node_lint"`, `"go_test"`, `"go_vet"`, `"generic_test"` to
   `BUILTIN_VERIFIERS` in `rebuild_plugin_verifiers` (`src/session/executor/mod.rs:948-958`).
2. Add a guard test (in `src/session/executor/tests/`) that registers the full default set
   on a fresh executor, runs `rebuild_plugin_verifiers` with an empty registry, and asserts
   every built-in name survived — so the next added verifier fails the test instead of
   silently regressing (the drift class this bug demonstrates).
3. One-line CHANGELOG entry.
