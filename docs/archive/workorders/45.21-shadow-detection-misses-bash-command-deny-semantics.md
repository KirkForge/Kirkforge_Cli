# WO 45.21 — detect_shadowed_rules misses bash-command deny semantics (*→** promotion + prefix match)

## Status: Done

## Problem

`detect_shadowed_rules` (src/shared/permission.rs:411-422) and its
subsumption helper `rule_subsumes` (permission.rs:426-444) silently miss
shadowings for `bash:command` deny rules — the most common rule type users
write. The diagnostic compares patterns with raw
`glob_match(earlier.pattern, later.pattern)` (permission.rs:443), but the
runtime matcher `deny_command_matches` (permission.rs:266-295) applies two
bash-command-specific transformations that the subsumption check does NOT
model:

1. **`*`→`**` promotion (permission.rs:267, 329-350):** a deny pattern
   `rm -rf *` is promoted to `rm -rf **` at match time, so it crosses `/`.
   The subsumption check uses the raw pattern `rm -rf *` whose lone `*`
   does NOT cross `/` (glob_match_recurse, permission.rs:154-156).

2. **Prefix matching (permission.rs:288-289):** a deny pattern ending in
   `/`, ` `, or `\t` matches any clause that *starts with* it
   (`n.starts_with(&pattern_lower)`). The subsumption check uses anchored
   `glob_match` (permission.rs:130-131) which requires the pattern to
   match the *entire* later-pattern string.

### Concrete misses (both verified by tracing the code)

**Miss A — promotion:** rules `[#0 bash:command=rm -rf * → Deny,
#1 bash:command=rm -rf /home → Allow]`. Runtime: rule #0 promotes to
`rm -rf **`, `glob_match("rm -rf **","rm -rf /home")`=TRUE → Deny wins.
Rule #1 is shadowed. `detect_shadowed_rules` calls
`glob_match("rm -rf *","rm -rf /home")` → lone `*` stops at `/` → FALSE.
No warning emitted.

**Miss B — prefix:** rules `[#0 bash:command=rm -rf / → Deny,
#1 bash:command=rm -rf /home → Allow]`. Runtime: `deny_command_matches`
prefix branch fires (`normalized.ends_with('/')` &&
`n.starts_with("rm -rf /")`) → Deny wins. Rule #1 is shadowed.
`detect_shadowed_rules` calls `glob_match("rm -rf /","rm -rf /home")` →
anchored match fails (pattern exhausted, value longer) → FALSE.
No warning emitted.

## Root cause

`rule_subsumes` (permission.rs:426-444) was written against the generic
`glob_match` semantics and never updated when WO 38.1 added
bash-command-specific matching (`deny_command_matches` with
`normalize_command_pattern` promotion + prefix matching) and WO 44.21
added clause normalization. The subsumption check knows nothing about
the bash deny path's two extra matching surfaces.

The doc comment at permission.rs:398-406 acknowledges general
incompleteness ("subset relations not expressible as M matches N's
pattern string") but under-states the gap: these misses ARE
expressible — the check just uses the wrong (raw) pattern instead of
the normalized/promoted one and ignores the prefix branch entirely.

## Are the claims over-credited?

The external reviewer's claim that `detect_shadowed_rules` is
"sound-but-incomplete" is correct on soundness (no false positives —
verified: `rule_subsumes` only returns true when `glob_match` proves
M's pattern covers N's pattern string, which is a genuine superset
relation under generic glob semantics) but over-credits completeness
for bash command rules. The incompleteness is not the benign "rare
subset relation" the doc comment describes — it hits the most common
deny-rule shapes (`rm -rf *`, `rm -rf /`) that users actually write,
because those are exactly the patterns that trigger promotion and
prefix matching.

**Severity: LOW.** This is a diagnostic, not a security boundary. The
permission engine itself (`evaluate`, permission.rs:194-238) is
correct — first-match-wins still applies at runtime, so a shadowed
deny/allow is still shadowed in the verdict. The gap only means the
user doesn't get a `⚠ Rule #N is shadowed by rule #M` warning for
bash-command deny rules. No security impact; UX-only.

## Approach

In `rule_subsumes` (permission.rs:426-444), when both rules are
`bash:command` rules AND `earlier.action == Deny`, model the two
bash-deny-specific surfaces before falling back to the generic
`glob_match`:

1. **Promotion:** compare `normalize_command_pattern(earlier.pattern)`
   (promoted) against `normalize_command_pattern(later.pattern)` — or
   against `later.pattern` if `later.action` is not Deny (allow/ask
   patterns are NOT promoted at runtime). Reuses the existing
   `normalize_command_pattern` helper (permission.rs:329-350).

2. **Prefix:** if `normalize_command_pattern(earlier.pattern)` ends with
   `/`, ` `, or `\t`, AND `normalize_command_pattern(later.pattern)`
   (or the runtime-normalized later value) starts with it, return true.

Keep the generic `glob_match` path for non-bash and non-deny rules
unchanged. The soundness property (no false positives) must be
preserved — only add checks that prove a true superset relation under
the actual runtime semantics.

Tests: the two concrete misses above (Miss A promotion, Miss B prefix)
must now report `vec![(1, 0)]`. Existing shadow tests
(`shadow_broader_pattern_shadows_specific`, `shadow_identical_pattern_`,
etc., permission.rs:1526-1659) must stay green. Add a test for
allow-earlier / deny-later (no promotion on the allow side — must NOT
report a false positive).

## Done

Extended `rule_subsumes` (src/shared/permission.rs) to model the two
bash-command-deny surfaces that `deny_command_matches` applies at runtime,
closing both concrete misses (A promotion, B prefix) without weakening
soundness (no new false positives — both surfaces are sufficient conditions
for true subsumption).

**Change:** when `earlier.tool == "bash" && earlier.key == "command" &&
earlier.action == Deny`, before the generic `glob_match` fallback, run two
extra checks:

1. **Promotion surface** — compare `normalize_command_pattern(earlier.pattern)`
   (promoted `*`→`**`) against `normalize_command_pattern(later.pattern)` if
   later is also Deny (deny patterns are promoted at runtime), else against
   the raw `later.pattern` (allow/ask patterns are NOT promoted). If the
   promoted earlier glob matches later's pattern string → subsumption holds
   (glob transitivity: M matches N's pattern ⇒ M matches every value N matches).

2. **Prefix surface** — if `normalize_command_pattern(earlier.pattern)` ends
   with `/`, ` `, or `\t` (the runtime prefix-branch trigger), and later's
   pattern (lowercased) starts with the earlier pattern (lowercased) →
   subsumption holds (every value later matches starts with that boundary
   prefix → earlier's prefix branch fires at runtime).

The generic `glob_match(earlier.pattern, later.pattern)` path is kept as the
final fallback for non-bash, non-deny, and patterns where neither surface
fires. It's strictly narrower than the promotion surface (raw `*` vs promoted
`**`), so it can't add a false positive the promotion surface missed; it
preserves the existing behaviour for non-promoted patterns byte-for-byte.

**Soundness preserved:** both new surfaces are sufficient conditions for
"every value later matches, earlier also matches" — the soundness property
(no false positives) is unchanged. The earlier `allow rm -rf *` does NOT
shadow `rm -rf /home` (deny) because the promotion surface is gated on
`earlier.action == Deny` (allow/ask are not promoted at runtime), and the
generic fallback also fails (lone `*` stops at `/`).

**Tests added (4):**
- `shadow_deny_star_promotion_shadows_allow` — Miss A: `rm -rf *`(Deny) shadows `rm -rf /home`(Allow) → `vec![(1, 0)]`
- `shadow_deny_prefix_shadows_allow` — Miss B: `rm -rf /`(Deny) shadows `rm -rf /home`(Allow) → `vec![(1, 0)]`
- `shadow_deny_double_star_shadows_star` — `rm -rf **`(Deny) shadows `rm -rf *`(Deny) → `vec![(1, 0)]`
- `shadow_allow_earlier_no_promotion_no_false_positive` — soundness guard: `rm -rf *`(Allow) does NOT shadow `rm -rf /home`(Deny) → empty
