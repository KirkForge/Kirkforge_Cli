# Workorder 46.0 — Event Bus No-Drop Under Load Invariant

## Status: Done

## Problem

The reviewer's "9 invariant categories" claim listed an **event** invariant
(config/permission/sandbox/budget/run/event/workspace/verifier). The event
category has *partial* coverage today — `src/shared/event_bus.rs` has 6 tests
covering dedup within the idempotency window, inflight counter, graceful
shutdown drain, unsub removal, and buffer stats. What is **genuinely missing**
is the invariant that matters most for a streaming agent UI: under sustained
load (emit rate exceeds handler drain rate, buffer near capacity), the bus
must either deliver every event to every registered handler or fail loudly —
it must not silently drop events that were emitted *outside* the idempotency
window. The current `emit` returns `Err` when the buffer is full (line ~210),
but no test pins this; a future refactor could switch to silent drop-on-full
and no existing test would catch the regression.

## Root cause

`EventBus` is a port of the TypeScript event bus (`shared/event_bus.rs:1-15`).
The TS original relied on backpressure behavior the port approximates with a
bounded buffer + `Err` on full. The tests pin the *happy path* and the
*idempotency* path but not the *saturation* path. The invariant — "an emitted
event outside the idempotency window is either delivered to all handlers or the
caller gets `Err`" — is the load-bearing property for the TUI's
`buffer_and_reports_stats` (line 387) and the executor's turn-event stream. It
is not currently asserted anywhere.

Existing coverage (verify before writing tests):
- `src/shared/event_bus.rs:338` `emits_events_to_registered_handlers` — 1 event, 1 handler.
- `:362` `deduplicates_events_within_idempotency_window` — dedup, not drop.
- `:405` `unsub_callable_removes_handler` — registration, not delivery.
- `:443` `graceful_shutdown_drains_inflight` — drain on shutdown, not under load.

None of these emit faster than the handler drains.

## Approach

Add **2 proptest-style / stress tests** to the existing `mod tests` in
`src/shared/event_bus.rs` (not a new file — keep it with the unit it pins):

1. `emit_faster_than_drain_never_silently_drops`: register a handler that
   sleeps 5ms per event. Emit N=1000 events (unique identity hashes, so
   outside the idempotency window) on a buffer sized to hold ~64. Assert every
   emit *either* returned `Ok` and was eventually received, *or* returned
   `Err` (buffer full). Count must satisfy `received + rejected == emitted`.
   No silent drop.

2. `proptest! emit_returns_err_or_eventually_delivered`: for arbitrary emit
   counts (1..=500) and arbitrary handler delays (0..=10ms), the invariant
   holds. This is the property version of (1). `proptest = "1.6"` is already
   a root `[dev-dependencies]` entry (`Cargo.toml:268`), so no new dep.
   Follow the WO 41.7 pattern: proptest! blocks live in a dedicated `mod
   proptest_suites` to dodge the `cargo clippy --all-targets` "cannot test
   inner items" false-positive (see `src/shared/permission.rs:1661`).

Keep it lazy: 2 tests, not a suite. Both ship — `proptest` is already a dev-dep.
