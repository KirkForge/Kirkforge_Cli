# Workorder 7.2 — Unit Tests for Fold-In Wrapper Modules

## Status: Done

## Problem

The four fold-in wrapper modules (`src/session/budget.rs`,
`src/session/stratum.rs`, `src/session/draw.rs`, `src/session/video.rs`) have
zero `#[test]` functions. The `Tool::run()` implementations and hook handlers
that parse args and call into the core crates have no direct coverage. The
coverage gate was lowered from 62% to 61% to accommodate this — it should be
raised back up once tests are added.

## Root cause

The fold-ins were implemented as MVPs (WO 6.6-6.9) and tests were deferred to
keep scope tight. The underlying crates (`plugin3-core`, `kirkstratum-core`,
`kirkforge-draw-core`, `kirkforge-video`) have their own tests, but the wrapper
layer is untested.

## Files to touch

- `src/session/budget.rs` — add `#[cfg(test)] mod tests` with:
  - `test_budget_status_returns_state` — call `BudgetStatus::run`, assert output contains "Budget status"
  - `test_budget_set_updates_ceiling` — call `BudgetSet::run` with a new ceiling, verify via `BudgetStatus`
  - `test_post_tool_bash_hook_records_usage` — call `PostToolBashHook::handle` with a HookContext containing tool_result, verify budget.used increased
  - `test_pre_compact_hook_resets_when_over` — push budget over ceiling, call PreCompactHook, verify used reset to 0
  - `test_session_start_hook_logs_state` — call SessionStartHook, verify it returns Allow
- `src/session/stratum.rs` — add `#[cfg(test)] mod tests` with:
  - `test_stratum_run_tool` — call StratumRun::run with valid args, assert output
  - `test_stratum_rules_tool` — call StratumRules::run, assert output contains rules
  - `test_session_start_hook_returns_allow` — call StratumSessionStartHook::handle, assert Allow
  - `test_pre_tool_bash_hook_validates_config` — call StratumPreToolBashHook::handle, assert Allow
- `src/session/draw.rs` — add `#[cfg(test)] mod tests` with:
  - `test_draw_render_loads_and_renders` — create a temp .td.json, call DrawRenderTool::run, assert output contains rendered text
  - `test_post_turn_hook_finds_td_json` — create temp .td.json files, call DrawPostTurnHook::handle, assert Allow + tracing
  - `test_post_turn_hook_no_files` — call with no .td.json files, assert Allow
- `src/session/video.rs` — add `#[cfg(test)] mod tests` with:
  - `test_video_demos_tool` — call VideoDemos::run, assert output
  - `test_video_pipeline_tool` — call VideoPipeline::run with valid args (may need a fixture project)
  - Keep video tests minimal — the crate's own tests cover the heavy logic

## Approach

1. Each test module uses `#[cfg(test)]` and only runs when the corresponding
   feature is enabled (the modules themselves are `#[cfg(feature = "...")]`).
2. Use `tempfile::tempdir()` for filesystem tests.
3. Tests should exercise the `Tool::run()` path (args parsing + core call) and
   the `InProcessHook::handle()` path.
4. After adding tests, check if the coverage threshold can be raised back to 62%.

## Gate

```
cargo fmt --check && cargo check --workspace --all-targets --all-features &&
cargo clippy --all-targets --all-features -- -D warnings &&
cargo test --locked --workspace --no-fail-fast --all-features
```

## Done condition

- Each fold-in module has at least 3 unit tests.
- `Tool::run()` and `InProcessHook::handle()` paths are directly tested.
- Coverage threshold can be raised from 61% back to 62% (or higher).
- Full gate green with --all-features.
