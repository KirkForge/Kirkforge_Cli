# Workorder 7.4 — Remove Legacy Plugin3 Spec-Drift Tests

## Status: Done

## Problem

`crates/plugin3-core/tests/build_spec_drift.rs` contains 33 `#[ignore]` tests
that assert the original standalone Plugin3 repo's build spec (toolchain
1.85.0, exactly 3 workspace members, etc.). These tests do not apply to the
CLI workspace and are dead weight. They're honestly labeled with `#[ignore =
"original Plugin3 build spec, not CLI workspace"]` but they clutter the test
output and represent untracked tech debt.

## Root cause

The tests were copied verbatim from the standalone Plugin3 repo during the P0
restoration and marked `#[ignore]` as an honest adaptation. No plan was made
to either update them or remove them.

## Files to touch

- `crates/plugin3-core/tests/build_spec_drift.rs` — either:
  - **Option A (recommended):** Delete the file entirely. The adapted
    replacements (`size_budget.rs`, `readme_drift.rs`) already exist and run
    normally. The 33 ignored tests serve no purpose in the CLI workspace.
  - **Option B:** Update the tests to assert the CLI workspace's build spec
    instead of the standalone repo's. This is more work for less value.
- `crates/plugin3-core/Cargo.toml` — no change needed (test discovery is
  automatic).
- `crates/plugin3-core/README.md` — update the test count if it references the
  ignored tests.
- `crates/plugin3-core/tests/adr_xref_drift.rs` — no change needed (it doesn't
  count ignored tests).

## Approach

1. Delete `build_spec_drift.rs`.
2. Run `cargo test -p plugin3-core` and confirm all remaining tests pass.
3. Update README test count if needed.
4. Run the `readme_drift` test to confirm the count is still within tolerance.

## Gate

```
cargo fmt --check && cargo test -p plugin3-core &&
cargo test -p plugin3-core --test readme_drift --test adr_xref_drift
```

## Done condition

- `build_spec_drift.rs` is deleted.
- No `#[ignore]` count increase in the workspace.
- All remaining plugin3-core tests pass.
