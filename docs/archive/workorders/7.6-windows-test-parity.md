# Workorder 7.6 — Windows Test Parity

## Status: Done

## Problem

The Windows CI job (`ci.yml:129`) has `continue-on-error: true` on the test
step, meaning Windows test failures are silently non-blocking. ADR-025
exists but no tracked follow-up timeline. The build step IS blocking, but
test parity is explicitly "work in progress."

## Root cause

Windows-specific issues (process group kill, daemon, SIGHUP, symlink
behavior) cause test failures that were never fixed. The
`continue-on-error` was added as a stopgap.

## Files to touch

- `src/session/process_group.rs` — verify `kill_process_group` works on
  Windows or has a correct fallback.
- `src/session/daemon/` — verify daemon tests are properly `#[cfg(unix)]`-gated.
- `src/session/hooks.rs` — verify hook tests don't assume Unix-specific
  behavior.
- `tests/` — verify integration tests are properly gated.
- `.github/workflows/ci.yml` — remove `continue-on-error: true` from the
  Windows test step once tests pass.

## Approach

1. Run the Windows test suite in CI and collect all failures.
2. For each failure, determine if it's a real Windows bug or a test that
   needs `#[cfg(unix)]` gating.
3. Fix real bugs; gate Unix-only tests.
4. Once all Windows tests pass, remove `continue-on-error: true`.
5. Update ADR-025 to reflect completion.

## Gate

CI validation — push and confirm the Windows job passes without
`continue-on-error`.

## Done condition

- Windows tests pass in CI without `continue-on-error`.
- ADR-025 updated to reflect test parity achieved.
- All Unix-only tests are properly `#[cfg(unix)]`-gated.

## Residual close (WO 43.12, 2026-08-23)

The three residual gaps left open after this WO's "Done" are closed by
[WO 43.12](43.12-windows-test-parity-finish.md):

1. **Doctests now run on Windows** — `ci-merge.yml` windows job has a
   dedicated `cargo test --locked --doc --workspace --no-fail-fast` step
   (mirror of the Linux full-tests doctest step).
2. **No PR-tier Windows job (by design)** — ADR-074 tier choice; late
   feedback is the accepted tradeoff for PR speed. No change.
3. **cfg(unix) audit completed** — 205 `cfg(unix)` occurrences audited;
   90 `#[cfg(unix)]`-gated test functions categorized. 8 platform-agnostic
   tests ungated (pure std::fs / std::io::Cursor logic, no Unix API, no
   subprocess, no module-level `cfg(all(test, unix))` gate). The remaining
   82 stay Unix-only: they use `std::os::unix::` (symlink, PermissionsExt),
   `#!/bin/bash`/`#!/bin/sh` scripts + chmod 0755, `setrlimit`/SIGXCPU,
   `kill()` syscall, `UnixStream`/`AsRawFd`, process groups, or live in
   `#[cfg(all(test, unix))]` modules (kf-plugin-host tool/hook/verifier/
   toolset, worktree.rs tests); or they invoke real subprocesses via
   `run_shell`/`BashJobRegistry::spawn` (depend on Git-for-Windows bash);
   or they have existing Windows variants (separator-specific assertions).
