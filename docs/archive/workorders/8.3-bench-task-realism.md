# Workorder 8.3 — Bench Task Realism: Real-Repo Tasks with Tool Access

## Status: Done (partial — 3 items deferred, see Notes)

## Notes

- `use_workflow_run.toml` was **skipped**: there is no `Tool` impl for
  `kirkforge-workflow` in this repo. The workflow crate ships a library
  and a TUI slash command, but the in-process `Tool` wrapper was never
  created. That work belongs in a follow-up WO about workflow tool
  wrappers, not in WO 8.3 (which is scoped to bench task realism).
- `build_bench_toolset` was **not** extended with plugin tools. The
  WO's gate command (`kirkforge bench verify-only`) runs only the
  verify spec — it does not invoke the model or the toolset. So
  whether the bench toolset contains plugin tools is irrelevant to
  `verify-only` passing. Extending the toolset is real-model-run
  scope and would be scope creep here.
- 11 pre-existing bench tasks (added in WO 7.8) still FAIL
  `verify-only` because their `file_contains` verify specs look for
  post-model substrings that the setup file does not contain. This
  is a pre-existing flaw in those tasks, not a regression from WO
  8.3. The 5 conversions + 4 new plugin tasks in this WO all pass
  `verify-only`. Total: 13/24 pass.

## Problem
WO 6.1 fixed the empty-toolset issue but 5 of the 20 bench tasks target the "real repo" (no setup files). These tasks depend on the repo's current state and break when the repo changes. WO 7.8 added 10 self-contained tasks, but the original 5 real-repo tasks remain fragile. Additionally, all tasks use a sandboxed toolset that may not include plugin tools (stratum, budget, draw) — so no bench task tests plugin tool usage.

## Root cause
The real-repo tasks were the original 5 from the MVP and were never converted to self-contained format.
