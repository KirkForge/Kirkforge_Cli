# Workorder 8.9 — Context Index: TypeScript and Python Edge Cases

## Status: Done

## Problem
The tree-sitter context index supports Rust, TypeScript, Python, and Go, but the symbol extraction has known gaps:
- **TypeScript**: `export const foo = () => {}` arrow functions are not extracted as symbols (only `function foo()` is)
- **TypeScript**: interface merging (declaration with same name in different files) creates duplicate symbols
- **Python**: decorator-wrapped functions (`@app.route("/api")\ndef handler():`) are extracted with the decorator name, not the function name
- **Python**: `if __name__ == "__main__":` blocks create spurious module-level symbols
- **Go**: method receivers (`func (s *Server) Start()`) are extracted as `Start` but the receiver type is lost

## Root cause
The tree-sitter queries for each language were written for the common case and don't handle all syntax patterns.

## Files to touch
- `crates/kirkforge-context-index/src/lib.rs` — improve the `extract_symbols` function per language:
  - TypeScript: handle arrow function assignments, handle interface merging (deduplicate by name + file)
  - Python: strip decorators from function names, skip `if __name__` blocks
  - Go: include receiver type in the symbol name (e.g., `Server.Start` instead of just `Start`)
- `crates/kirkforge-context-index/tests/` — add test fixtures for each edge case:
  - `fixtures/ts_arrow.ts` — arrow function exports
  - `fixtures/ts_interface_merge.ts` — interface merging
  - `fixtures/py_decorator.py` — decorator-wrapped functions
  - `fixtures/py_dunder.py` — `if __name__` block
  - `fixtures/go_method.go` — method with receiver

## Approach
1. Write test fixtures that exercise each edge case
2. Run the current extractor on each fixture and identify what's wrong
3. Fix the tree-sitter query or post-processing logic for each language
4. Add regression tests that assert the correct symbols are extracted
