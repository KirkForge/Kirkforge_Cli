# Workorder 9.0 — Fix 11 Broken Bench Task Verify Specs

## Status: Done

## P0 Windows CI fix: commit 6482dea (before this WO). `Path::is_absolute()` treats `/foo` as relative on Windows; fixed by also rejecting `as_str.starts_with('/')`. 3 validate tests now pass.

## Problem
WO 8.3 converted 5 real-repo tasks to self-contained format and added 4 new
plugin-tool tasks, bringing the total to 24. But 11 of the pre-existing tasks
(added in WO 7.8) still FAIL `bench verify-only` because their `file_contains`
verify specs look for post-model substrings that the setup file does not
contain. WO 8.3 deferred this as "pre-existing flaw, not WO 8.3 scope." That
deferral is now the single biggest bench-harness gap — 11/24 tasks broken
means the bench pass rate is unmeasurable for nearly half the suite.

## Root cause
The `file_contains` verify specs were written to check for content the model
is expected to *produce* (e.g., `contains = "///"` for `add_doc_comment`), but
`verify-only` runs the setup file through the verify spec without invoking the
model. So the verify checks the *pre-edit* file, which obviously doesn't
contain the post-edit content. The `test_passes` and `command_exits_zero`
verify types work because they run a command that depends on the model's
edits having landed — but `file_contains` has no model to make the edit.

## Files to touch
- `benches/tasks/add_doc_comment.toml` — verify spec looks for `///` in a file
  that starts without doc comments
- `benches/tasks/add_test_module.toml` — same pattern
- `benches/tasks/extract_trait.toml` — same pattern
- `benches/tasks/use_budget_check.toml` — verify spec checks for post-model
  budget output text
- `benches/tasks/use_draw_render.toml` — same pattern
- `benches/tasks/use_lsp_query.toml` — same pattern
- `benches/tasks/use_stratum_compress.toml` — same pattern
- `benches/tasks/add_adr.toml` — already converted in WO 8.3 but verify may
  still be broken; check
- Audit the remaining 3 tasks (`add_enum_variant`, `add_struct_field`,
  `fix_failing_test`) — these use `test_passes` which should work, verify they
  actually pass `verify-only`

## Approach
1. Run `kirkforge bench verify-only --tasks benches/tasks/` and list every
   failing task
2. For each `file_contains` failure: the verify spec should check the
   *setup* file content, not the post-model content. Either:
   - Change the verify type to `test_passes` / `command_exits_zero` (if the
     task's setup includes a test that validates the model's edit), OR
   - Change the `contains` field to match something in the setup file that
     the model's edit must *preserve* (not produce), OR
   - Add a `post_setup` script that the verify runs against (if the bench
     harness supports it — check `kirkforge-bench/src/lib.rs`)
3. For plugin-tool tasks (`use_budget_check`, `use_draw_render`,
   `use_lsp_query`, `use_stratum_compress`): the verify spec should check
   that the model *called* the plugin tool, not that the plugin produced
   specific output. If the bench harness doesn't record tool-call traces,
   this may need a new verify type or a different approach.
4. Re-run `bench verify-only` until all 24 tasks pass
