# Workorder 9.1 — Workflow Tool Wrapper for Bench and Agent Use

## Status: Done

Shipped in commit 9ce537f (Wave 2 of the 9-series). `WorkflowTool` lives
in `src/tools/workflow.rs` (main crate, not the workflow crate, to avoid
a dependency cycle), implements the `Tool` trait as `workflow_run`,
accepts `{template, vars}`, and delegates to `WorkflowEngine::run`.
Registered unconditionally in `all_tools()`. 7 unit tests with an
`EchoSpawner` mock. The deferred `benches/tasks/use_workflow_run.toml`
bench task was added and passes `verify-only`.

## Problem
The `kirkforge-workflow` crate ships a library and a `/workflow` TUI slash
command, but there is no in-process `Tool` impl for it. WO 8.3 deferred the
`use_workflow_run` bench task because "no `Tool` impl exists for
`kirkforge-workflow`." This means:
1. The bench harness cannot test workflow execution as a tool call.
2. The model (in agent mode) cannot invoke workflows via tool calls — only
   via the TUI slash command, which the agent loop doesn't use.

## Root cause
The workflow crate was built as a library + TUI command, not as a tool. The
`Tool` trait (`src/shared/mod.rs`) requires `name()`, `schema()`,
`run()`. The workflow crate's `WorkflowEngine::run()` exists but is not
wrapped in a `Tool` impl.

## Approach
1. Read the `Tool` trait definition in `src/shared/mod.rs` and an existing
   simple tool (e.g., `src/tools/todo.rs`) for the impl pattern
2. Implement `WorkflowTool` in the workflow crate — it holds an
  `Arc<WorkflowEngine>` and delegates `run()` to `engine.run(template, vars)`
3. Register in `all_tools()` — check if the workflow crate is always
  compiled in or feature-gated
4. Add the `use_workflow_run` bench task (the one WO 8.3 deferred)
5. Test: the bench task passes `verify-only`; a unit test confirms the tool
   returns step summaries
