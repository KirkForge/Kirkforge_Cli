# Workorder 9.3 — Version Reconciliation and v0.3.6 Release

## Status: Done

`Cargo.toml` bumped `0.3.0` → `0.3.6` via `scripts/bump-version.sh`
(commit 2c46425). The script also refreshed `Cargo.lock`, split the
`CHANGELOG.md` `[Unreleased]` section into a new empty `[Unreleased]`
plus a versioned `[0.3.6] - 2026-07-27` section, committed, and created
annotated tag `v0.3.6`. Pushing the tag triggers `release.yml` which
gates on `main` CI green, then builds 6 platform binaries + SHA256SUMS
+ cosign signature.

Chose `0.3.6` (patch-level) over `0.4.0` (minor) to match the
`state.md` baseline claim and avoid implying a breaking change — the
8-series and 9-series added capabilities but no public API breaks. The
repo convention is patch-level for WO series.

## Problem
`state.md` declares the baseline as "v0.3.6 (2026-07-25)" but `Cargo.toml` is
still at `version = "0.3.0"`. No `v0.3.1`–`v0.3.6` tags exist. `gh release view
v0.3.6` → "release not found." The 8-series workorders shipped substantial
features (multi-model leaderboard, embedding quality, ADR unification,
stratum-budget coordination, error hints, manifest validation, context-index
edge cases) but none of it is in a released artifact. The last release tag is
`v0.3.0`.

## Root cause
The workers who shipped WO 8.0–8.9 updated `state.md` with a "v0.3.6" label
but never bumped `Cargo.toml`, never cut a tag, and never triggered the
release workflow. This is the same merge-discipline failure the review series
has flagged since the third pass: code ships, tracking doesn't.
