## Root cause
The test at `crates/plugin3-core/src/cost.rs:512` does:

```rust
{
    let _g_seed = EnvGuard::set("PLUGIN3_CONFIG_DIR", "/tmp/cfg-seed");
    assert_eq!(std::env::var("PLUGIN3_CONFIG_DIR").as_deref(),
               Ok("/tmp/cfg-seed"));
}  // <-- EnvGuard::Drop runs here: calls remove_var, then releases the
   //     ReentrantMutex (see test_support.rs:138-152)
assert!(
    std::env::var("PLUGIN3_CONFIG_DIR").is_err(),  // <-- reads AFTER lock release
    ...
);
```

`EnvGuard::Drop` (`crates/plugin3-core/src/test_support.rs:138-152`) calls
`remove_var(key)` while holding the `ReentrantMutex`, then releases the
lock. The assertion at `cost.rs:525-529` reads `PLUGIN3_CONFIG_DIR`
**after the lock is released**. Another test thread in the same `cargo
test --workspace` process (e.g. `emit_writes_one_jsonl_line_to_target_path`
at `cost.rs:257`, which sets `PLUGIN3_CONFIG_DIR` to a `tempfile::tempdir()`
path via its own `EnvGuard`) acquires the lock, calls `set_var`, and the
assertion reads *that* value — exactly the `Some("C:\\Users\\RUNNER~1\\AppData\\Local\\Temp\\.tmpMNwRir")`
the panic message reports.

On Linux the window between lock-release and `std::env::var` is
sub-microsecond so the race almost never loses. On Windows the env-block
sync (`SetEnvironmentVariableW` + CRT env-block copy) is slower, widening
the window enough that the race loses regularly under `cargo test
--workspace` parallelism.

The `paths.rs:306` mirror test `env_guard_restores_prior_value_some_branch`
has the same shape and races on Windows for the same reason (it passed in
this CI run by luck — both branches are racy).

## Approach
Two options; pick A (smaller, more honest about what the test is really
checking):

**Option A — assert on the captured `prior`, not on the env var post-drop.**
The `EnvGuard` already captures `prior: Option<String>` at `set` time
(`test_support.rs:126`). Add a `pub fn prior(&self) -> Option<&str>` accessor.
The test then becomes:

```rust
let g_seed = EnvGuard::set("PLUGIN3_CONFIG_DIR", "/tmp/cfg-seed");
assert_eq!(g_seed.prior(), None, "seed guard must have prior=None");
assert_eq!(std::env::var("PLUGIN3_CONFIG_DIR").as_deref(),
           Ok("/tmp/cfg-seed"));
drop(g_seed);  // Drop calls remove_var under the lock
// The contract is: prior was None, so Drop called remove_var.
// We cannot re-read the env var here without racing another test.
// Instead we assert the captured prior — that's what Drop used.
```

This is the smaller change and is honest: the test pins the `EnvGuard`
contract (prior=None ⇒ Drop removes), not the env-var state post-drop
(which is inherently racy when other tests can mutate the same var).

**Option B — hold the lock across the assertion.**
Wrap the whole seed round-trip in an outer `EnvGuard::set` on a *different*
key (or expose `ENV_TEST_MUTEX.lock()` directly) so no other test can
mutate `PLUGIN3_CONFIG_DIR` between Drop and the assertion. This is more
invasive and adds a public lock-exposure to `test_support.rs` — prefer A.
