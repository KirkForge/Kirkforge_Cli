# Workorder 10.4 — Clean Up Leftover wo/* Worktree Branches

## Status: Done (8 local + 8 remote wo/8.* branches deleted; 7 stale worktrees removed)

## Problem
`git branch | grep wo/` shows 8 leftover worktree branches from the
8-series, all merged to `main`:

```
wo/8.0-coverage-2047781
wo/8.2-tui-parity-2121971
wo/8.3-bench-realism-2341416
wo/8.6-stratum-budget
wo/8.6-stratum-budget-rebased
wo/8.7-error-hints-2403154
wo/8.8-manifest-validate-2499265
wo/8.9-ctx-edge-cases-2602474
```

These branches are stale: their work shipped to `main` and `dev`
(WO 8.0-8.9 are all marked Done in the README). Leaving them clutters
`git branch -v` output (the 9-series review noted "9 `wo/*` worktree
branches present (leftover from the 8-series, not deleted)") and makes
it harder to spot genuinely-open work branches. AGENTS.md "Worktree
discipline" implies branches are deleted after merge (the 7-series
branches were deleted; the 8-series were not).

## Root cause
The 8-series workers created `wo/<N.N>-<slug>-<rand>` branches off
`origin/dev`, pushed, merged to `main`, but did not delete the worktree
branches after merge. The 9-series workers were more disciplined (no
`wo/9.*` branches exist), suggesting the discipline was learned but
the 8-series branches were never cleaned up.

## Files to touch
None (git operation only). Optionally:
- `state.md` — one-liner noting the branch cleanup
- `lessons.md` — fold "delete wo/* branches after merge" into the
  worktree-discipline lesson (it's already implied in AGENTS.md §Task
  Management 6, but a reminder in `lessons.md` helps the next worker)

## Approach
1. **Verify each branch is merged to `main`:**
   ```
   for b in wo/8.0-coverage-2047781 wo/8.2-tui-parity-2121971 \
            wo/8.3-bench-realism-2341416 wo/8.6-stratum-budget \
            wo/8.6-stratum-budget-rebased wo/8.7-error-hints-2403154 \
            wo/8.8-manifest-validate-2499265 wo/8.9-ctx-edge-cases-2602474; do
     echo "=== $b ==="
     git log --oneline main..$b 2>&1 | head -3
     # if empty, $b is fully merged into main
   done
   ```
   Every branch should show empty `main..$b` (fully merged). If any
   branch shows unmerged commits, **STOP** — that branch has unmerged
   work; do not delete it; note it in `lessons.md` and escalate.
2. **Verify no live worktrees point at these branches:**
   `git worktree list` should show only the main/dev worktree (no
   `wo/*` worktree paths). If a worktree exists, remove it with
   `git worktree remove <path>` before deleting the branch.
3. **Delete each merged branch:**
   ```
   git branch -d wo/8.0-coverage-2047781
   git branch -d wo/8.2-tui-parity-2121971
   # ... etc for all 8 branches
   ```
   Use `-d` (lowercase), not `-D`. `-d` refuses to delete if the branch
   is not fully merged to its upstream — a safety net. If `-d` refuses,
   investigate; do not `-D` without understanding why.
4. **Verify the remote has no `wo/8.*` branches either:**
   ```
   git fetch --prune
   git branch -r | grep wo/8
   ```
   If remote `wo/8.*` branches exist, delete them:
   `git push origin --delete wo/8.0-coverage-2047781` (etc). Skip the
   `-rebased` variant's remote if it was force-pushed (check first).
5. **Verify cleanup:**
   `git branch | grep wo/` should show no `wo/8.*` branches. The 9-series
   left no `wo/9.*` branches, so the output should be empty.

## Gate
```
git branch | grep wo/   # should be empty (or contain only active WO branches)
git worktree list       # should show only the main/dev worktree
git fetch --prune && git branch -r | grep wo/8   # should be empty
```

## Done condition
- All 8 `wo/8.*` local branches deleted (verified by empty
  `git branch | grep wo/`)
- No `wo/8.*` remote branches remain (verified by empty
  `git branch -r | grep wo/8` after `git fetch --prune`)
- No worktrees point at deleted branches (verified by
  `git worktree list` showing only the main/dev worktree)
- `state.md` one-liner: "WO 10.4: cleaned up 8 stale wo/8.* branches"
- Depends on: nothing (pure git hygiene)

## Notes
- Use `git branch -d` (lowercase) — it refuses to delete unmerged
  branches. Do NOT use `-D` (uppercase) unless you have verified the
  branch is merged AND the `-d` is refusing for a known reason (e.g.
  the upstream tracking is wrong).
- The `wo/8.6-stratum-budget-rebased` branch is `[ahead 2, behind 1]`
  per `git branch -v` — investigate before deleting. If the 2
  ahead-commits are already on `main` (rebased onto a different base),
  `-d` will refuse; verify with `git log main..wo/8.6-stratum-budget-rebased`
  and, if the commits are duplicates of merged work, delete with `-D`
  and note why in `lessons.md`.
- This is a P3 hygiene WO. It can be batched with 10.3/10.5/10.6 in a
  single "doc + branch hygiene" commit, or done as a standalone
  git-only operation with no commit (just branch deletion).
