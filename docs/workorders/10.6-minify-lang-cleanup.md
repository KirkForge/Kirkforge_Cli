# Workorder 10.6 — minify/lang.rs Style Cleanup + Dead-Code Removal

## Status: Done (allow(dead_code) removed from lang.rs + mod.rs; minify_rust dead wrapper deleted; comment style fixed; clippy --all-targets clean)

## Problem
`src/shared/minify/lang.rs:1-3` has two style issues and a stale
allowance (Pass 13 finding #7):

```rust
// Per-language minification engine — pure, stateless string transforms.
//! Extracted from the VFS cache + public API in `mod.rs`.
#![allow(dead_code)] // minify_rust wrapper and Phase-10 symbols not yet wired up.
```

1. **Mixed comment style.** Line 1 uses `//` (plain comment), line 2
   uses `//!` (inner doc comment). The file-level doc comment should be
   one `//!` block, not a mix.
2. **Stale `#![allow(dead_code)]`.** The string says "minify_rust
   wrapper and Phase-10 symbols not yet wired up" — but
   `minify_content_by_ext` (line 8) calls `minify_rust_inner` directly,
   and `minify_rust` (line 143) is a thin wrapper
   (`fn minify_rust(s) { minify_rust_inner(s, false) }`) that is never
   called. The "Phase-10 symbols not yet wired up" comment suggests
   future work, but WO 9.7 shipped the read-path wiring (the WO 9.7
   commit message says "15 new tests" and "tree-sitter is NOT added to
   the read path; the lexical minifier already handles the WO contract
   across Rust/TS/Python/Go"). The minify module is fully wired; the
   `allow(dead_code)` is hiding a genuinely-dead wrapper, not a planned
   future symbol.
3. **`src/shared/minify/mod.rs:2`** has the same stale
   `#![allow(dead_code)]` with the comment "Partial prompt-compression
   implementation; unused symbols are wired up in Phase 10." — same
   staleness; the "Phase 10" work this WO does is cleanup, not new
   symbols.

Pass 13 finding #7 noted: "a contributor reading the file will see the
`allow(dead_code)` and wonder what's not wired." This WO answers: nothing
is not wired; the allowance is hiding dead code.

## Root cause
The minify module was built with a "Phase 10" plan that included a
`minify_rust` wrapper and possibly other symbols (per the allow string).
WO 9.7 shipped the read-path wiring using `minify_rust_inner` directly
and did not need the wrapper. The `#![allow(dead_code)]` was left in
place "for the future symbols," but the future symbols never became
necessary — `minify_content_by_ext` is the public API, and it dispatches
to the `_inner` functions. The allowance is now hiding a genuinely-dead
`minify_rust` function (and possibly other dead helpers — audit with
`cargo clippy --lib` after removing the allowance).

## Files to touch
- `src/shared/minify/lang.rs:1-3` — fix the comment style (use a single
  `//!` doc block) and remove the `#![allow(dead_code)]`. After removal,
  run `cargo clippy --lib` to find any newly-reported dead code; either
  wire it or delete it.
- `src/shared/minify/lang.rs:143-145` — `minify_rust` is dead (never
  called; `minify_content_by_ext` calls `minify_rust_inner` directly).
  Delete it, OR if there's a reason to keep the `preserve_tests=false`
  shorthand (e.g. a test uses it), make `minify_content_by_ext` call
  `minify_rust` for the `"rs"` arm and delete `minify_rust_inner` (or
  inline the `preserve_tests` parameter into `minify_rust` and drop the
  `_inner` suffix). Prefer deletion — the wrapper adds no value.
- `src/shared/minify/mod.rs:2` — remove the stale
  `#![allow(dead_code)]` and the "Phase 10" comment. Audit for
  newly-reported dead code and wire/delete.
- Any other dead symbols surfaced by removing the allowance.

## Approach
1. **Remove the two `#![allow(dead_code)]` lines** (lang.rs:3, mod.rs:2).
2. **Run `cargo clippy --all-targets -- -D warnings`** and capture every
   new `dead_code` warning. Each warning is a symbol the allowance was
   hiding.
3. **For each warning, decide: wire or delete.**
   - If the symbol is called from a test or a real path, wire it (the
     allowance was wrong; the symbol is not dead).
   - If the symbol is never called, delete it (the allowance was hiding
     genuine dead code).
   - For `minify_rust` specifically: delete it (it's a thin wrapper
     around `minify_rust_inner(.., false)` that is never called; the
     `minify_content_by_ext` "rs" arm calls `minify_rust_inner`
     directly). If a test uses `minify_rust`, change the test to call
     `minify_rust_inner(.., false)` directly, or add a `pub(crate)`
     shorthand if multiple tests need it.
4. **Fix the comment style.** Replace the mixed `//` + `//!` block at
   the top of `lang.rs` with a single `//!` doc block:
   ```rust
   //! Per-language minification engine — pure, stateless string transforms.
   //! Extracted from the VFS cache + public API in `mod.rs`.
   ```
5. **Run the full gate** to confirm no warnings and all tests pass.

## Gate
```
cargo fmt --check && cargo clippy --all-targets -- -D warnings &&
cargo test --locked --workspace --no-fail-fast --all-features
cargo test -p kirkforge --lib shared::minify
```

The `cargo clippy --all-targets -- -D warnings` step is the key gate —
it must be clean after removing the allowance. If it reports new
warnings, this WO is not done; either wire or delete each flagged
symbol.

- `minify_rust` dead wrapper deleted (or wired if a caller exists)
- `lang.rs:1-3` comment style fixed (single `//!` block, no mixed `//` +

- All existing minify tests pass (the 15 from WO 9.7 + any earlier)

- Depends on: nothing

## Notes
- This is a P3 cleanup WO. It does not block the release or the
  cache-stem wiring. It can be batched with 10.3/10.4/10.5 in a single
  "doc + perf + cleanup hygiene" commit.
- If removing the `allow(dead_code)` surfaces a large number of dead
  symbols (more than ~5), STOP and escalate — the allowance may have
  been hiding a bigger refactoring gap. A large dead-code surface
  suggests the "Phase 10" plan was more substantial than this WO
  assumes, and the dead symbols may represent intended-but-unwired
  functionality that should be a separate WO.
- Do NOT add new `#![allow(dead_code)]` to silence warnings. The point
  of this WO is to surface and resolve the dead code, not to relocate
  the allowance.
