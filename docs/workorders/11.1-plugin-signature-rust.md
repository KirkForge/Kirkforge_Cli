# Workorder 11.1 — Plugin Signature Verification in Rust (No minisign Shell-Out)

## Status: Planned

## Problem
Plugin signature verification (`crates/kirkforge-plugin-host/src/lib.rs:299`)
shells out to the `minisign` binary:

```rust
fn verify_plugin_signature(plugin_root, key_path) -> Result<(), String> {
    // ...
    return Err("minisign binary not found in PATH; install minisign to
    verify plugin signatures".into());
}
```

`find_minisign_binary()` (lib.rs:410-425) walks `PATH` looking for a
`minisign` executable; if not found, verification fails with a hard
error. This means:

1. **Plugin signatures only work if `minisign` is installed.** A user
   who enables `verify_signatures = true` in the config but doesn't
   have `minisign` in `PATH` gets a hard error for every plugin load —
   even plugins without a `.kirkforge.sig` file (the verify path
   requires the binary before it checks whether the sig file exists).
2. **Subprocess overhead + env-curation.** The current path spawns a
   `minisign` subprocess with `Command::new(minisign_bin)` — an
   external process for what is a pure cryptographic verification (Ed25519
   signature check over the manifest bytes).
3. **Windows friction.** `minisign` is not commonly installed on
   Windows; the `.exe` suffix handling at lib.rs:418-421 is a band-aid.
   A Rust impl works everywhere `kirkforge` runs.

The `TrustPolicy::with_verify_signatures` API exists
(lib.rs:74-82), is tested (lib.rs:913), and is documented in ADR-050.
The gap is purely the verification backend: it shells out instead of
verifying in-process.

## Root cause
The plugin host was built to shell out to `minisign` because (a) it was
the fastest path to a working verify, and (b) at the time there was no
mature pure-Rust minisign-verify crate. Both are no longer true: the
`minisign-verify` crate (or `ed25519-dalek` + minisign header parsing)
is mature and adds a small dep (ed25519 is ~50KB in a size-optimized
binary). The shell-out was a v1; the v2 is in-process.

## Files to touch
- `Cargo.toml` (root) — add `minisign-verify` (or `ed25519-dalek` if a
  minisign-specific crate isn't maintained) behind the existing
  `plugin` feature or unconditionally. Check crate sizes; the
  size-optimized release profile (`opt-level = "z"` + `lto = true`)
  should keep the dep small.
- `crates/kirkforge-plugin-host/Cargo.toml` — add the dep here (the
  host owns signature verification).
- `crates/kirkforge-plugin-host/src/lib.rs` — replace
  `find_minisign_binary` + the subprocess spawn in
  `verify_plugin_signature` with an in-process verify: read the
  `.kirkforge.sig` file, parse the minisign header, verify the
  Ed25519 signature over the `kirkforge.toml` bytes using the
  configured public key. Keep the same error semantics (missing sig
  file, malformed sig, key mismatch, signature mismatch).
- `crates/kirkforge-plugin-host/src/lib.rs:410-425` — delete
  `find_minisign_binary` (no longer needed).
- Tests — update the existing signature-verify tests (lib.rs:913+) to
  use the in-process path. Add a test that verification succeeds with a
  real minisign-generated sig (generate one in the test fixture using
  the `minisign` crate or a pre-generated keypair in `tests/fixtures/`).
- `docs/adr/` — new ADR (057 or next free number) documenting the
  in-process verification decision and the dep choice.

## Approach
1. **Survey the Rust minisign crate landscape.** Candidates:
   - `minisign-verify` — pure verify, no signing. Smallest dep. Check
     maintenance status and crate size.
   - `ed25519-dalek` + hand-rolled minisign header parsing — more work
     but the most minimal dep (dalek is already audited and widely used).
   - `minisign` (full crate, by the Rust port author) — supports both
     sign and verify; larger than needed if we only verify.
   Pick the smallest maintained crate that does verify-only. Document
   the choice in the ADR.
2. **Replace `verify_plugin_signature`.** The new function:
   - Reads `.kirkforge.sig` (if missing → error with a clear message).
   - Parses the minisign signature header (the `untrusted comment:` +
     `trusted comment:` + base64 signature lines).
   - Reads `kirkforge.toml` bytes.
   - Verifies the Ed25519 signature over the manifest bytes using the
     configured public key (from `signature_key_path` or a config-provided
     key string).
   - Returns `Ok(())` on success, `Err(message)` on any failure.
3. **Delete the shell-out path.** `find_minisign_binary` and the
   `Command::new(minisign_bin)` spawn go away. The `minisign` binary is
   no longer required.
4. **Tests.** The existing test at lib.rs:913 uses
   `with_verify_signatures(true, Some(key_path))` — update it to use
   a real keypair + sig generated in the test fixture. Add tests for:
   missing sig file, malformed sig, wrong key, valid sig.
5. **Update ADR-050** (the plugin consolidation ADR) to note the
   signature verification backend changed from shell-out to in-process.
   Write a new ADR for the dep choice.

## Gate
```
cargo fmt --check && cargo clippy --all-targets -- -D warnings &&
cargo test --locked --workspace --no-fail-fast --all-features
cargo test -p kirkforge-plugin-host --lib signature
cargo bloat --release --crates -- | grep -E "ed25519|minisign"   # check size impact
```

Check the binary size impact: the size-optimized release profile
should keep the new dep under ~100KB. If it's larger, document the
trade-off in the ADR (the dep earns its place because signature
verification is a security feature).

## Done condition
- `verify_plugin_signature` is in-process (no `Command::new`, no
  `find_minisign_binary`)
- `minisign` binary is no longer required to be in `PATH` (a user with
  `verify_signatures = true` but no `minisign` installed gets the same
  behavior as a user with it installed — both verify in-process)
- Tests cover: valid sig, missing sig file, malformed sig, wrong key
- Binary size impact documented in the ADR (and acceptable — under
  ~100KB in the size-optimized profile)
- ADR-057 (or next free) written; ADR-050 updated to note the backend
  change
- `docs/TECHNICAL.md` plugin section updated
- Depends on: nothing (the signature-verify API exists)

## Notes
- The `ponytail:` / `ceiling:` annotations in
  `crates/kirkforge-plugin-host/src/lib.rs` must be preserved.
- Do NOT remove the `verify_signatures` / `signature_key_path` config
  fields or the `TrustPolicy::with_verify_signatures` API — those are
  the public contract; only the backend changes.
- If the chosen Rust crate requires a C dependency (rare for ed25519),
  reject it — the project avoids C deps for the size-optimized binary.
  Prefer a pure-Rust crate.
- The `.kirkforge.sig` file format and the `kirkforge.toml` signing
  contract are unchanged — only the verification backend changes.
