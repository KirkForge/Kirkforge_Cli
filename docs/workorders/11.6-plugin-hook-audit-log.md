# Workorder 11.6 — Plugin Hook Fail-Open Audit Log

## Status: Planned

## Problem
Plugin hooks (`src/session/hooks.rs`) follow a fail-open convention
(documented at `crates/kirkforge-plugin-host/src/hook.rs:7-12`):
exit 0 → allow, exit 2 → deny, any other non-zero / timeout / crash →
allow with a warning. The warning is `tracing::warn!(...)`
(`src/session/hooks.rs:212-225`) — it goes to the tracing log, not
the audit log.

The audit log (`src/session/executor/mod.rs:57` `audit_log: Arc<AuditLog>`)
records tool calls, approvals, and turn events to an NDJSON file at
`cfg.security.audit_log_path` (default `/tmp/kf-audit.ndjson`). It's
the tamper-evident record of what the agent did. But hook denials and
hook failures (timeouts, crashes) are not in it. A hook that denies
a tool call (exit 2) is logged to `tracing::warn!` and lost; a hook
that crashes (non-zero exit) is fail-opened (the tool runs anyway)
and the warning is lost.

This is a security-observability gap: a malicious or buggy hook that
denies legitimate tool calls (or fails open on dangerous ones) is
not in the audit trail. The 12th-pass review noted "audit log" as a
shipped feature — true for tool calls, not for hooks.

## Root cause
The hook system (`src/session/hooks.rs`) was built before the audit
log was wired into the executor. `run_hook_script` (hooks.rs:496)
returns `HookDecision::Allow` / `Deny` / `Err`; the caller
(`spawn_hook_script`, hooks.rs:199) logs denials and errors via
`tracing::warn!` because the audit log (`AuditLog`) lives on the
`Executor`, not on the `HookRunner`. The hook runner doesn't have a
handle to the audit log.

## Files to touch
- `src/session/hooks.rs` — `HookRunner` (or `spawn_hook_script`)
  gains an optional `audit_log: Option<Arc<AuditLog>>` field. When
  present, hook denials and failures are appended to the audit log
  as `AuditEntry::Hook { event, plugin, verdict, reason }` (or a new
  `AuditEntry` variant). When absent (e.g. in tests), the existing
  `tracing::warn!` path is preserved.
- `src/session/audit.rs` (or wherever `AuditLog` / `AuditEntry` is
  defined) — add a `Hook` variant (or a `HookDenial` / `HookFailure`
  variant) to the `AuditEntry` enum. The entry includes: the event
  name, the plugin name (if it's a plugin hook), the verdict
  (Allow/Deny), and the reason (for Deny) or error (for failure).
- `src/session/executor/mod.rs` — pass the `audit_log` handle to the
  `HookRunner` when constructing it on the executor.
- `src/session/executor/turn.rs` — when a pre-tool hook denies a tool
  call, the audit entry is appended BEFORE the tool is blocked (so
  the audit trail shows the denial + the non-execution). When a hook
  fails open, the audit entry is appended with `verdict = Allow (fail-
  open)` + the error, so the audit trail shows the tool ran because
  the hook failed.
- Tests — extend the hook tests to assert the audit log contains the
  expected `Hook` entries. Use a temp audit log path + read it back.

## Approach
1. **Add the `AuditEntry::Hook` variant.** Fields: `event: String`,
  `plugin: Option<String>` (None for built-in hooks), `verdict:
  HookVerdict`, `reason: Option<String>` (for Deny), `error:
  Option<String>` (for failure). Serialize as NDJSON.
2. **Pass the audit log to the hook runner.** `HookRunner::new`
  accepts `Option<Arc<AuditLog>>`; `spawn_hook_script` and the
  async hook path use it when present.
3. **Log denials and failures.** In `spawn_hook_script` (hooks.rs:199)
  and the async hook path (hooks.rs:317, 374, 383), after the
  `tracing::warn!`, append an `AuditEntry::Hook` to the audit log.
  The audit entry is the tamper-evident record; the `tracing::warn!`
  is the live-operator signal. Both are kept.
4. **Pre-tool hook denial.** When a pre-tool hook returns `Deny`, the
  executor blocks the tool call AND appends the audit entry. The
  audit trail shows: hook denied → tool not run. This is the
  security-relevant case: a hook prevented an action.
5. **Fail-open.** When a hook crashes / times out / returns non-zero
  (not 0 or 2), the fail-open path runs the tool. The audit entry
  records `verdict = Allow (fail-open)` + the error, so the audit
  trail shows: hook failed → tool ran anyway. This is the
  safety-relevant case: a hook that should have denied was bypassed.
6. **Test.** A test that runs a pre-tool hook that denies, asserts
  the tool was not called AND the audit log contains a `Hook` entry
  with `verdict = Deny`. A test that runs a hook that crashes, asserts
  the tool was called (fail-open) AND the audit log contains a `Hook`
  entry with `verdict = Allow (fail-open)` + the error.

## Gate
```
cargo fmt --check && cargo clippy --all-targets -- -D warnings &&
cargo test --locked --workspace --no-fail-fast --all-features
cargo test -p kirkforge --lib session::hooks
cargo test -p kirkforge --lib session::audit   # or wherever AuditLog is tested
```

## Done condition
- `AuditEntry::Hook` variant exists (or `HookDenial` / `HookFailure`)
- Hook denials (exit 2) are appended to the audit log with the event,
  plugin (if any), verdict, and reason
- Hook failures (non-zero / timeout / crash) are appended to the
  audit log with `verdict = Allow (fail-open)` + the error
- Pre-tool hook denials: the audit trail shows the denial + the tool
  not run
- Fail-open: the audit trail shows the hook failure + the tool ran
- Tests assert the audit entries for both cases
- ADR-061 (or next free) documenting the hook audit decision
- `docs/TECHNICAL.md` audit-log section documents hook entries
- Depends on: nothing (the audit log + hook system exist)

## Notes
- The `tracing::warn!` path is kept (live operator signal); the audit
  log is the persistent record. Both are written.
- Do NOT change the fail-open convention (exit 0 → allow, exit 2 →
  deny, other → allow-with-warning). This WO only adds audit logging;
  the semantics are ADR-009-documented and must not change.
- The audit log is append-only NDJSON with sequential hashes (per
  ADR-0010). The `Hook` entry follows the same format.
- The `ponytail:` annotations in `src/session/hooks.rs` (the fail-open
  convention comment) must be preserved.
