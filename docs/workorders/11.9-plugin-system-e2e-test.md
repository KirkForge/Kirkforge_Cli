# Workorder 11.9 — Plugin System End-to-End Integration Test Suite

## Status: Done (commit pending)

## Problem
The plugin system has unit tests for each component (manifest
validation, trust-tier filtering, env curation, sandbox policy,
hook verdict, verifier-bus registration) but no single end-to-end
test that exercises the full plugin lifecycle: load a plugin with
all 4 capability kinds (skill + tool + hook + verifier), exercise
each through the executor, and verify the trust/sandbox/env-
curation/audit contracts hold.

The 12th-pass review named the plugin system "consolidated" (ADR-050)
and the verifier-bus "complete" (ADR-028, WO 9.6) — but the
integration confidence is spread across many small tests. A
regression that breaks the *composition* (e.g. a plugin whose hook
runs before its verifier, or whose tool runs at the wrong trust
tier) would not be caught by the unit tests.

This is the "agent capability B+" → "measured grade" gap the
12th-pass named for the bench harness, applied to the plugin
system: the unit tests prove each piece works; the integration test
proves the pieces compose.

## Root cause
The plugin system was built incrementally (manifest v1 → trust
tiers → folded plugins → verifier bus → signature verification →
resource limits). Each WO added unit tests for its piece. No WO
added a full-lifecycle integration test because each WO's scope was
its piece, not the composition.

## Files to touch
- `src/session/plugin_tools/tests.rs` (or a new
  `src/session/plugin_tools/integration_tests.rs`) — add a
  `#[ignore]` (or `#[test]`) end-to-end test that:
  1. Creates a temp plugin directory with a mock plugin manifest
     declaring all 4 capability kinds: a skill (`/mock`), a tool
     (`mock_tool`), a hook (`pre-tool`), and a verifier (`mock`).
  2. Loads the plugin via `load_plugin_registry` with a
     `TrustPolicy::up_to(TrustTier::Shell)`.
  3. Asserts the skill is registered in the skill registry.
  4. Asserts the tool is registered in the tool registry and callable
     (invoke it with mock args, assert the result).
  5. Asserts the hook fires on the `pre-tool` event (invoke the hook
     runner, assert the verdict).
  6. Asserts the verifier is registered on the `VerifierBus` and
     produces a verdict (run `bus.verify(ctx)`, assert the verdict).
  7. Asserts the env curation: the plugin tool subprocess receives
     only the `curated_env` allowlist (not the test process's full
     env). The mock tool script echoes `env` and the test asserts no
     unexpected vars are present.
  8. Asserts the sandbox policy: the mock tool script's capability
     requires `Shell` trust; with `TrustPolicy::up_to(ReadOnly)`,
     the tool is filtered out (not registered).
  9. Asserts the audit log (if WO 11.6 lands): the hook's verdict is
     in the audit log.
- `tests/plugin_integration.rs` (new, at the repo root) — if the
  test needs the full executor (not just the plugin loader), it
  lives here as a separate integration test binary.

## Approach
1. **Mock plugin.** A temp dir with:
   - `kirkforge.toml` — manifest with all 4 capabilities.
   - `tools/mock_tool.sh` — a script that echoes its args + `env`
     (so the test can assert env curation).
   - `hooks/pre-tool.sh` — a script that exits 0 (allow) or 2
     (deny) based on an arg (so the test can assert both verdicts).
   - The verifier is a `Capability::Verifier` declared in the
     manifest; the test mocks its behavior via the
     `PluginVerifier` path (or uses the TS-orchestrator bridge from
     WO 10.8 if available).
2. **Load + assert.** Load via `load_plugin_registry`; assert each
   capability kind is registered in the right place (skill registry,
   tool registry, hook runner, verifier bus).
3. **Exercise + assert.** Invoke the tool, fire the hook, run the
   verifier; assert each produces the expected output/verdict.
4. **Env curation.** The tool script writes `env` to a file; the
   test reads the file and asserts only the `BASELINE_ENV_VARS`
   allowlist is present (no `HOME` secrets, no test-process env).
5. **Trust filtering.** Re-load with `TrustPolicy::up_to(ReadOnly)`;
   assert the tool and hook are filtered out (only the skill and
   verifier remain, since they're `ReadOnly`).
6. **Audit.** If WO 11.6 lands, assert the hook verdict is in the
   audit log.
7. **Mark `#[ignore]` if slow.** The test spawns subprocesses (tool
   + hook scripts); mark `#[ignore]` with a `requires bash` note if
   it's slow or platform-specific.

## Gate
```
cargo fmt --check && cargo clippy --all-targets -- -D warnings &&
cargo test --locked --workspace --no-fail-fast --all-features
cargo test -p kirkforge --lib session::plugin_tools -- --ignored   # the integration test
```

## Done condition
- A single end-to-end test loads a mock plugin with all 4 capability
  kinds, exercises each, and asserts:
  - skill registered + callable
  - tool registered + callable + env-curation (only allowlist vars)
  - hook fires + verdict is correct (Allow and Deny cases)
  - verifier registered + produces a verdict on `bus.verify`
  - trust filtering: at `ReadOnly` max, tool + hook filtered out
  - (if WO 11.6 lands) hook verdict in audit log
- The test is marked `#[ignore]` if it's slow or platform-specific,
  with a note explaining why
- ADR-064 (or next free) documenting the integration-test contract
  (what it covers, what it doesn't, the mock plugin layout)
- `docs/TECHNICAL.md` plugin section references the integration test
- Depends on: WO 11.6 (hook audit) for the audit-log assertion;
  otherwise the audit assertion is skipped with a note

## Notes
- The mock plugin scripts must be executable (`chmod +x` in the
  test setup). On Windows, shell scripts don't run — mark the test
  `#[cfg(unix)]` if it uses bash scripts, or use a cross-platform
  mock (e.g. a Python or Node script that the test asserts is
  invoked). The simplest path is `#[cfg(unix)]` + `#[ignore]`.
- The test does NOT replace the unit tests — it composes them. Each
  unit test still exists; the integration test proves they compose.
- This is a P2 WO — confidence, not correctness. The plugin system
  works; this test makes regressions visible.
- The `ponytail:` / `ceiling:` annotations in the plugin code must be
  preserved; the integration test is additive.
