# Workorder 12.0 — Fix Final CI Gate (Tarpaulin Flake on `test_build_fork_tree_orphan_fork_is_a_root`)

## Status: Planned

## Problem
The `coverage` CI job is the last non-green job on `main`/`dev`. It
fails intermittently on `session::session_index::tests::test_build_fork_tree_orphan_fork_is_a_root`
under `cargo tarpaulin --lib`. The panic:

```
thread 'session::session_index::tests::test_build_fork_tree_orphan_fork_is_a_root'
  panicked at src/session/session_index.rs:923:38:
build tree: commit session index from /tmp/.tmpXXX/sessions/.index.tmp
  to /tmp/.tmpXXX/sessions/.index.ndjson
Caused by: No such file or directory (os error 2)
```

The test passes in isolation (`cargo test -p kirkforge --lib
session::session_index::tests::test_build_fork_tree_orphan_fork_is_a_root
-- --exact` → ok) and on the regular `quality` job (which uses
`cargo nextest`/`cargo test`, not tarpaulin). It only fails under
tarpaulin's instrumentation, which adds overhead that widens temp-file
races. `state.md` documents this as a pre-existing flake; three re-runs
on `dev` failed, a fresh full re-run cleared it. This is the last
blocking issue for a fully-green CI.

## Root cause
`test_build_fork_tree_orphan_fork_is_a_root`
(`src/session/session_index.rs:898-932`) creates a `tempfile::tempdir()`,
sets `KIRKFORGE_DATA_DIR` to point at it, writes a fork json, then calls
`build_fork_tree()`. `build_fork_tree()` → `list_sessions()` →
`SessionIndex::load_or_refresh()` → `refresh()` → `save()`
(`src/session/session_index.rs:178-204`). `save()` does:

1. `create_dir_all(parent)` — creates `<tmpdir>/sessions/` (already
   exists; no-op).
2. Opens `<tmpdir>/sessions/.index.tmp` for writing.
3. Writes entries + `sync_all()`.
4. `rename(.index.tmp, .index.ndjson)`.

The panic is at step 4's `with_context` — the rename fails with "No
such file or directory." Under tarpaulin, the tempdir's parent
(`/tmp/.tmpXXX`) can be cleaned up between steps 1 and 4 (tarpaulin's
subprocess instrumentation, or `/tmp` GC under load). The `tempdir`
guard holds a reference to the path, but if the OS removes the path
out from under it, the rename target doesn't exist.

The deeper issue: `save()` writes to `self.path.with_extension("tmp")`
which is `<tmpdir>/sessions/.index.tmp`. If the `sessions/` dir was
created by the test but the tmpdir itself was removed, the `sessions/`
dir is gone too, and the rename fails. The `create_dir_all(parent)` at
step 1 succeeds (the dir exists at that moment), but by step 4 the dir
is gone.

## Files to touch
- `src/session/session_index.rs:178-204` — `save()`: make it resilient
  to the parent dir disappearing mid-write. Options (pick one):
  - **A — re-create the parent dir before the rename:** call
    `create_dir_all(parent)` again right before `rename`. If the dir
    was cleaned up, this re-creates it; if it still exists, it's a
    no-op. This is the smallest fix.
  - **B — write to a tempfile in the same dir, not a `.tmp` extension:**
    use `tempfile::NamedTempFile::new_in(parent)` which creates a
    random-name temp file in the parent dir, write to it, then
    `persist(path)` (atomic rename). The `tempfile` crate handles the
    cleanup; `persist` is atomic. This is the more robust fix but adds
    a `tempfile` dep to the main crate (check if it's already a dep —
    it's a dev-dep for tests; making it a runtime dep needs an ADR).
  - **C — make the test hold the tempdir alive longer:** the test
    already holds `dir = tempfile::tempdir()` for the whole function;
    the issue is not the test's tempdir but the OS cleaning `/tmp` under
    tarpaulin load. This is not fixable in the test alone.
  - **Recommend A** (smallest, no new deps, addresses the root cause:
    the parent dir can disappear between `create_dir_all` and `rename`).
- `src/session/session_index.rs:898-932` — the test: add a comment
  explaining the tarpaulin race and why the `save()` fix addresses it.
  No test-logic change (the test is correct; the production code was
  fragile).

## Approach
1. **Add `create_dir_all(parent)` before the rename in `save()`.** The
   `save()` method already does `create_dir_all(parent)` at the top
   (line 180-183), but the rename at line 198-203 can fail if the dir
   was removed between the top and the rename. Add a second
   `create_dir_all(parent)` call right before the rename — it's a
   no-op if the dir exists, and re-creates it if it was cleaned up.
2. **Alternatively, wrap the rename in a retry.** If the rename fails
   with `NotFound`, re-create the parent dir and retry once. This
   handles the case where the `.index.tmp` file itself was removed (not
   just the parent dir). Prefer the simpler `create_dir_all` approach
   unless the retry is needed.
3. **Test.** Add a unit test that simulates the race: create a
   `SessionIndex` whose `path` points at a temp dir, write entries,
   `save()`, then delete the parent dir, `save()` again — assert it
   succeeds (re-creating the dir). This is hard to test directly
   because the race is timing-dependent; the test just verifies
   `save()` re-creates the dir if it's gone.
4. **Verify the flake is gone.** Run the coverage job locally:
   `cargo tarpaulin --out Xml --locked --lib --timeout 120` (or the
   CI rerun). The test should pass consistently. If it still flakes,
   escalate to option B (NamedTempFile).
