# Workorder 12.1 — Raise `src/session` Coverage Threshold 62% → 68%

## Status: Done (intermediate threshold landed)

## Problem
The `src/session` coverage threshold in `.github/workflows/ci.yml:344`
is 62.0%. Current actual coverage (CI run `30275314517`): 63.1%. Only
1.1% headroom — a single new uncovered file drops CI below the gate.
The target is 75% (WO 12.8/12.9); this WO is the intermediate step to
68%, leaving 5% headroom for the next iteration.

The 12th-pass review named "coverage gate" as a shipped feature (it is,
at 62/50/61). The gate prevents regression but doesn't push
improvement. Raising the threshold forces the team to write the tests
that close the coverage gap, which is the point of the 12-series.

## Root cause
`src/session/` is the largest directory in the binary (9781 lines). It
contains the executor, the turn loop, the adapter dispatch, the
verifier bus, the MCP client, the hooks, the prompt builder, the
session index, the replay recorder, the worktree, the budget, the
stratum, the draw, the video. Many of these modules have unit tests,
but the coverage is uneven: pure functions (prompt assembly, config
parsing, env curation) are ~90% covered; async I/O paths (MCP client
HTTP transport, the executor's turn loop, the session daemon) are
~30-50% covered because the tests use mocks that skip the real I/O.

## Approach
1. **Measure.** Run `cargo tarpaulin --out Xml --locked --lib --timeout
   120` locally (or use the CI cobertura artifact). Parse the XML to
   find the per-file coverage in `src/session/`. Sort by coverage %
   ascending; the lowest 5-10 files are the targets.
2. **Add tests.** For each low-coverage file, add unit tests for the
   uncovered branches. Focus on error paths (the happy paths are
   usually covered; the `Err` branches are not). Use the existing test
   patterns in the file (mocks, temp dirs, `tokio::test`).
3. **Re-measure.** After each batch of tests, re-run tarpaulin to verify
   the coverage moved. Iterate until `src/session/` is ≥68%.
4. **Raise the threshold.** Change `.github/workflows/ci.yml:344` from
   `62.0` to `68.0`. Commit the threshold change in the same commit as
   the tests (so the gate is green at the new threshold).
5. **Verify CI.** Push + watch the coverage job. It must pass at the
   new 68% threshold.
