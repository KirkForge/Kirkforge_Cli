# Workorder 12.4 — Fold `kirkforge-testdoctor` into the Workspace + Integrate into `kirkforge doctor` CLI

## Status: Planned

## Problem
`crates/kirkforge-testdoctor/` (920 lines across 5 files) is a
standalone prototype, explicitly excluded from the workspace build
(`Cargo.toml:16` `exclude = ["crates/kirkforge-testdoctor"]`,
AGENTS.md §0: "Don't add it back without an ADR"). It builds standalone
(`cd crates/kirkforge-testdoctor && cargo build` works) but:

1. **Not in the workspace.** It doesn't benefit from `cargo test
   --workspace`, `cargo clippy --all-targets`, or the CI gate. Its 12
   unit tests (in `classify.rs`, `partition.rs`, `suggest.rs`) run only
   when a developer remembers to `cd` into it.
2. **Not integrated into the main CLI.** The main `kirkforge` binary
   has no `doctor` subcommand. A user wanting to profile the test
   suite must `cd crates/kirkforge-testdoctor && cargo run -- profile`,
   which is not discoverable.
3. **ADR-0029 documented it as a prototype** "not a workspace member
   yet — prototype only." The 12-series is the time to promote it: the
   12.1-12.3 coverage work needs the testdoctor's profiling + gap
   analysis to find the uncovered files.

## Root cause
The testdoctor was built as a standalone prototype (ADR-0029) to
avoid affecting the main binary's size (the testdoctor pulls in `clap`
+ `serde` + `anyhow` which are already deps, so the size impact is
zero, but the prototype was conservative). ADR-0029 explicitly deferred
the workspace inclusion: "The `kirkforge-testdoctor` crate is built
standalone and is not listed as a workspace member." The deferral was
reasonable when the testdoctor was a prototype; it's now a working tool
that the 12-series needs.

## Files to touch
- `Cargo.toml` (root) — remove `exclude = ["crates/kirkforge-testdoctor"]`
  from the workspace definition. Add `kirkforge-testdoctor` to the
  workspace members (it's under `crates/*` which is already a member
  glob, so removing the exclude is sufficient). If the testdoctor
  needs to be an optional dep of the main binary, add it behind a
  feature flag.
- `crates/kirkforge-testdoctor/Cargo.toml` — align with the workspace
  deps (use `workspace = true` for `clap`, `serde`, `serde_json`,
  `anyhow` per the WO 8.x workspace-deps-consolidation pattern).
- `crates/kirkforge-testdoctor/src/lib.rs` (new) — extract the core
  logic (profile, classify, partition, suggest) into a library so the
  main `kirkforge` binary can call it. Currently the crate is a binary
  only (`[[bin]] name = "kirkforge-testdoctor"`); add a `[lib]` target.
- `src/cli.rs` — add a `Doctor` subcommand (or `Test { subcommand:
  TestSubcommand }` to namespace it). Variants: `Profile`, `Classify`,
  `Partition`, `Suggest`, `Gaps` (the new coverage-gap analysis from
  WO 12.7).
- `src/main/mod.rs` — `handle_doctor(cmd)` dispatches to the
  testdoctor library functions. The output is human-readable text
  (the testdoctor already produces this).
- `docs/adr/0029-test-partitioning.md` — update the Status: "the
  testdoctor is now a workspace member + integrated into the
  `kirkforge doctor` CLI (WO 12.4)."
- `AGENTS.md` — remove the "Don't add it back without an ADR" note
  (the ADR is being updated by this WO).
- `docs/TECHNICAL.md` — document the `kirkforge doctor` subcommand.

## Approach
1. **Extract a library.** `crates/kirkforge-testdoctor/src/lib.rs`
   re-exports the core functions from `profile`, `classify`,
   `partition`, `suggest`. The existing `main.rs` becomes a thin
   wrapper that calls the library (kept for standalone use, but now
   the main `kirkforge` binary can call the library too).
2. **Remove the exclude.** `Cargo.toml` root: remove
   `exclude = ["crates/kirkforge-testdoctor"]`. The `members =
   ["crates/*"]` glob now includes it.
3. **Align deps.** `crates/kirkforge-testdoctor/Cargo.toml`: use
   `clap = { workspace = true }`, `serde = { workspace = true }`, etc.
   (the WO 8.x pattern).
4. **Add `kirkforge doctor` subcommand.** In `src/cli.rs`:
   ```rust
   #[derive(Subcommand, Debug)]
   pub enum DoctorCommand {
       Profile,
       Classify,
       Partition,
       Suggest,
       Gaps,
   }
   ```
   Add `Doctor(DoctorCommand)` to the top-level `Command` enum. In
   `src/main/mod.rs`, `handle_doctor` dispatches to the testdoctor
   library.
5. **Test.** The testdoctor's 12 existing unit tests now run under
   `cargo test --workspace`. Add integration tests for the
   `kirkforge doctor` CLI subcommand.
6. **Update ADR-0029.** Status: the testdoctor is now a workspace
   member; the prototype is promoted.

## Gate
```
cargo fmt --check && cargo clippy --all-targets -- -D warnings &&
cargo test --locked --workspace --no-fail-fast --all-features
cargo test -p kirkforge-testdoctor   # the testdoctor's own tests
cargo test -p kirkforge --bin kirkforge -- doctor::   # CLI integration
```

## Notes
- The testdoctor pulls in `clap`, `serde`, `serde_json`, `anyhow` —
  all already workspace deps. The size impact on the main binary is
  zero if the testdoctor is a separate bin; if it's a lib dep of the
  main bin, the size impact is the testdoctor's code (~920 lines, small).
  Prefer keeping it as a separate bin that the main `kirkforge` binary
  calls via the library — the main binary gets the lib, not the bin.
- The `ponytail:` annotations in the testdoctor code must be preserved.
- The `readme_drift` test: the testdoctor has 12 tests under `crates/`
  that are already counted (they were counted even when excluded,
  because the test counts `crates/` recursively — verify this). If the
  count changes, bump the README.
- This WO is the prerequisite for 12.5-12.7 (the advanced testdoctor
  features need the testdoctor to be a workspace member to run under
  the CI gate).
