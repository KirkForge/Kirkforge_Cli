# Workorder 12.5 — Advanced Testdoctor: Per-Test Timings + Flaky-Test Detection

## Status: Planned

## Problem
The current `kirkforge-testdoctor` profiles at the *binary* granularity
(`profile.rs`: captures the `test result: ok. N passed; ... finished
in X.XXs` line per binary). It cannot tell you which *individual test*
is slow — only which binary is slow. A binary with 1000 tests finishing
in 43s is classified "fast" even if one of those tests takes 30s and
the other 999 take 13s.

ADR-0029 documented this limitation: "On stable Rust 1.88 the nightly-
only `--format json` test output is not available, so the doctor parses
the standard text output. This gives per-binary timings (not per-test)
on stable; per-test timings require nightly or a custom test harness."
The 12-series is the time to close this gap: the 12.1-12.3 coverage
work needs per-test timings to find the slow tests that block the
coverage job.

Additionally, there is no flaky-test detection. The tarpaulin flake
(WO 12.0) was found manually by re-running the coverage job 3×. The
testdoctor should be able to run a test N times and report which tests
fail intermittently.

## Root cause
The testdoctor was built to parse the stable text output (which has
per-binary `test result:` lines but not per-test timings). Per-test
timings require either (a) nightly Rust's `--format json` (which
includes per-test durations), or (b) a custom test harness that wraps
each test in a timer. The testdoctor deferred both as "future work"
(ADR-0029).

## Files to touch
- `crates/kirkforge-testdoctor/src/profile.rs` — add a
  `profile_per_test(profile_path)` function that runs `cargo test
  --workspace --no-fail-fast -- --format json` (if nightly is available)
  OR falls back to running each test binary separately with `cargo test
  -p <pkg> -- <test_filter>` and timing each invocation. The nightly
  JSON path is preferred; the fallback is slower but works on stable.
- `crates/kirkforge-testdoctor/src/profile.rs` — add a
  `TestProfile { name: String, binary: String, duration_ms: u64,
  passed: bool, ignored: bool }` struct for per-test timings.
- `crates/kirkforge-testdoctor/src/classify.rs` — extend `classify` to
  use per-test timings when available: a test with `duration_ms >
  SLOW_TEST_MS` (default 2000) is `slow` even if its binary is `fast`.
- `crates/kirkforge-testdoctor/src/flaky.rs` (new) — a `detect_flaky`
  function that runs a test N times (default 10) and reports the
  pass/fail rate. A test that passes 8/10 is flaky (80% pass rate);
  a test that passes 10/10 is stable. Use `cargo test -- <test_filter>
  --exact` N times, parse the result, report the rate.
- `src/cli.rs` — add `Doctor` subcommand variants:
  - `Doctor::ProfilePerTest` — per-test timings.
  - `Doctor::Flaky { runs: u32, filter: Option<String> }` — flaky-test
    detection.
- `crates/kirkforge-testdoctor/src/suggest.rs` — extend the suggestions
  to use per-test timings: a test with `duration_ms > 5000` gets a
  stronger suggestion ("move behind `#[ignore]` + run in a dedicated
  job") than a test with `duration_ms > 1000` ("consider mocking").

## Approach
1. **Per-test timings via nightly JSON.** If `rustup toolchain list`
   includes nightly, run `cargo +nightly test --workspace --no-fail-
   fast -- --format json -Z unstable-options` and parse the JSON
   (each `event: "test"` line has a `duration` field). If nightly is
   not available, fall back to the per-binary path (the current
   behavior).
2. **Flaky-test detection.** `detect_flaky(test_filter, runs)` runs
   `cargo test -- <filter> --exact` `runs` times, counts pass/fail,
   reports the rate. A test with <100% pass rate is flaky; the report
   shows the failure messages from the failing runs.
3. **Classify with per-test data.** When per-test timings are
   available, classify each test (not just each binary) as
   fast/medium/slow. A binary's classification is the slowest test's
   classification.
4. **Suggest with per-test data.** The suggestions can now name the
   specific slow test ("`test_build_fork_tree_orphan_fork_is_a_root`
   takes 2.3s; suggest `#[ignore]` + dedicated job") instead of just the
   binary.
5. **Tests.** Unit tests for the JSON parser + the flaky detector (mock
   the `cargo test` output).

## Gate
```
cargo fmt --check && cargo clippy --all-targets -- -D warnings &&
cargo test --locked --workspace --no-fail-fast --all-features
cargo test -p kirkforge-testdoctor
```

## Done condition
- `kirkforge doctor profile-per-test` produces per-test timings (using
  nightly JSON if available, per-binary fallback otherwise)
- `kirkforge doctor flaky --runs 10 --filter <test>` runs a test 10×
  and reports the pass/fail rate + failure messages
- `classify` uses per-test timings when available
- `suggest` names specific slow tests, not just slow binaries
- Unit tests for the JSON parser + the flaky detector
- ADR-0029 updated: per-test timings + flaky detection shipped
- `docs/TECHNICAL.md` documents the new doctor subcommands
- Depends on: WO 12.4 (testdoctor is a workspace member)

## Notes
- The nightly JSON path requires `rustup toolchain install nightly`.
  Do NOT make nightly a hard dep — the fallback (per-binary timings)
  must work on stable. Document the nightly path as "preferred, not
  required."
- The flaky detector is slow (10 runs × test time). Default `runs = 10`
  but allow `--runs 3` for a quick check. Document the time cost.
- Do NOT run the flaky detector in CI (it's too slow). It's a
  developer tool, run manually when investigating a flake.
- The `ponytail:` annotations in the testdoctor code must be preserved.
