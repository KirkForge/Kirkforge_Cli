# Workorder 12.7 — Testdoctor: Coverage-Gap Report (Uncovered Files + Suggested Test Targets)

## Status: Planned

## Problem
The 12.1-12.3 coverage work requires finding which files/lines are
uncovered. Currently, a developer must run `cargo tarpaulin --out Xml`,
parse the XML manually (or use the CI `Enforce coverage gate` Python
script), and eyeball the per-file coverage. There is no command that
says "here are the 10 least-covered files in `src/session/`, with the
specific uncovered line ranges, and a suggested test target for each."

The `kirkforge-testdoctor` has a `profile` command (per-binary timings)
and a `classify` command (fast/medium/slow), but no `gaps` command
(coverage gaps). The 12.1-12.3 work needs this to find the uncovered
files efficiently. This WO adds it.

## Root cause
The testdoctor was built for *time* profiling (which tests are slow),
not *coverage* profiling (which lines are uncovered). Coverage data
comes from tarpaulin's XML output, which the testdoctor doesn't parse.
The CI `Enforce coverage gate` Python script
(`.github/workflows/ci.yml:336-365`) parses the XML for the three
target directories + thresholds, but it's a CI-only script, not a
developer tool. This WO brings the coverage analysis into the
testdoctor.

## Files to touch
- `crates/kirkforge-testdoctor/src/gaps.rs` (new) — a `CoverageGaps`
  struct + `analyze_gaps(cobertura_xml_path) -> CoverageGaps` function
  that parses tarpaulin's Cobertura XML and produces:
  - `per_file: Vec<FileCoverage { path, lines_total, lines_covered,
    rate, uncovered_ranges: Vec<(u32, u32)> }>` sorted by rate
    ascending (lowest-covered first).
  - `per_dir: Vec<DirCoverage { dir, lines_total, lines_covered, rate,
    threshold, headroom }>` for the three target directories
    (`src/session`, `src/tools`, `src/adapters`) with the current
    thresholds (from `ci.yml`).
  - `suggestions: Vec<Suggestion { file, uncovered_range, suggested_test
    }>` — for each file with <50% coverage, a suggested test target
    ("add a test for `src/session/foo.rs:42-58` — the `bar()` error
    branch is uncovered").
- `crates/kirkforge-testdoctor/src/gaps.rs` — the suggestion engine:
  parse each uncovered range, look at the surrounding code (read the
  file, find the function/trait/impl the range is in), suggest a test
  target. Use the source-analysis patterns from WO 12.6 (subprocess,
  sleep, network, env-var).
- `src/cli.rs` — add `Doctor::Gaps { xml: PathBuf, dir:
  Option<String> }` — run the gap analysis on a Cobertura XML file,
  optionally filtered to a directory.
- Tests — a fixture Cobertura XML + assertions on the gap report.

## Approach
1. **Parse the Cobertura XML.** The format is standard
   (`<package><classes><class><lines><line hits="0"/></lines></class>`)
   — the same format the CI `Enforce coverage gate` script parses.
   Reuse that parsing logic (it's Python; port to Rust or use a Rust
   XML parser like `quick-xml` — check if it's already a dep).
2. **Per-file coverage.** For each `<class filename="src/session/foo.rs">`,
   count `lines/line` elements with `hits > 0` (covered) vs `hits = 0`
   (uncovered). Compute `rate = covered / total * 100`. Sort ascending.
3. **Uncovered ranges.** Group consecutive uncovered lines into ranges
   (`(42, 58)` means lines 42-58 are uncovered). This helps the
   developer see "the error branch from line 42 to 58 is uncovered"
   rather than 17 individual lines.
4. **Per-directory summary.** For `src/session`, `src/tools`,
   `src/adapters`: sum the per-file coverage, compare to the threshold
   (read from `ci.yml` or hardcoded defaults), compute headroom.
5. **Suggestions.** For each file with <50% coverage, read the file,
   find the function the uncovered range is in, suggest a test target.
   "src/session/mcp_client/http.rs:380-420 — the `post_request` error
   branch (non-2xx response) is uncovered. Suggested test: mock a
   server returning 500, assert `post_request` returns
   `McpError::JsonRpc`."
6. **Output.** Human-readable table:
   ```
   Coverage gaps (src/session/ — 63.1%, threshold 62%, headroom 1.1%):
     Lowest-covered files:
       src/session/mcp_client/http.rs        45.2%  (380-420, 512-540)
       src/session/executor/turn.rs          52.8%  (1067-1163)
       src/session/verifier/bus.rs           58.1%  (240-280)
     Suggested test targets:
       http.rs:380-420 → test post_request error branch (mock 500)
       turn.rs:1067-1163 → test deferred-file-calls recording path
       bus.rs:240-280 → test NDJSON parse-error → Warn verdict
   ```

## Gate
```
cargo fmt --check && cargo clippy --all-targets -- -D warnings &&
cargo test --locked --workspace --no-fail-fast --all-features
cargo test -p kirkforge-testdoctor -- gaps
```

## Done condition
- `kirkforge doctor gaps --xml <cobertura.xml>` produces a per-file
  coverage report sorted by rate ascending, with uncovered line ranges
  + suggested test targets
- The per-directory summary shows the three target dirs + their
  thresholds + headroom
- The suggestion engine names the function the uncovered range is in +
  a specific test target
- Unit tests with a fixture Cobertura XML
- ADR-0029 updated: coverage-gap analysis shipped
- `docs/TECHNICAL.md` documents the `kirkforge doctor gaps` command
- Depends on: WO 12.4 (testdoctor is a workspace member); WO 12.6
  (source-analysis patterns for suggestions) is helpful but not
  required (suggestions can be generic without 12.6)

## Notes
- The Cobertura XML parsing can use `quick-xml` (check if it's a dep)
  or `serde-xml-rs`. Prefer the lightest XML parser; the testdoctor is
  a dev-tool, but the dep should be small.
- The `Enforce coverage gate` Python script in `ci.yml:336-365` is the
  reference implementation — port its logic to Rust. Do NOT remove the
  Python script (it's the CI gate; the testdoctor is the developer
  tool).
- This WO is the tool that makes 12.1-12.3 + 12.8 efficient. Without
  it, finding the uncovered files is manual XML parsing. With it,
  `kirkforge doctor gaps` tells you exactly where to add tests.
- The `ponytail:` annotations in the testdoctor code must be preserved.
