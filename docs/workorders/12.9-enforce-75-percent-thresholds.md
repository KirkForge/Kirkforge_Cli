# Workorder 12.9 — Enforce 75% Coverage Thresholds in CI

## Status: Planned

## Problem
After WO 12.8 raised the actual coverage to ≥75% on all three target
directories, the CI thresholds (`.github/workflows/ci.yml:344`) are
still at 68/65/70 (the 12.1-12.3 intermediate values). The gate
provides 7/10/5% headroom — a regression that drops coverage by 8%
on `src/session/` would still pass the gate. This WO raises the
thresholds to 75% on all three, leaving zero headroom at first (any
regression fails CI) and enforcing the 12.8 achievement.

The 12th-pass review's "coverage gate" finding: shipped at 62/50/61.
The 12-series raised it to 68/65/70 (12.1-12.3) and then to 75/75/75
(12.8 + this WO). This is the final step: the gate matches the
target.

## Root cause
The threshold is a Python dict in `ci.yml:344`:
```python
targets = {'src/session': 68.0, 'src/tools': 65.0, 'src/adapters': 70.0}
```
Raising it is a one-line change, but only after WO 12.8 confirms the
actual coverage is ≥75% on all three. If the threshold is raised
before the coverage is there, CI goes red.

## Files to touch
- `.github/workflows/ci.yml:344` — change the targets dict to
  `{'src/session': 75.0, 'src/tools': 75.0, 'src/adapters': 75.0}`.
- `state.md` — note the final threshold raise + the 12-series
  coverage achievement.
- `docs/TECHNICAL.md` — update the coverage-gate section to reflect
  the 75% target.
- `docs/adr/` — new ADR (065 or next free) documenting the 75%
  coverage-gate decision: why 75% (the A− production bar), what's
  excluded (integration tests, which are in `tests/` not `src/`), and
  the headroom policy (0% headroom at first; allow 2% headroom after
  one regression to avoid flaky CI).

## Approach
1. **Verify coverage.** Run `cargo tarpaulin --out Xml --locked --lib
   --timeout 120` locally; parse the XML; confirm all three
   directories are ≥75%. If any is below 75%, STOP — go back to WO
   12.8 and add more tests. Do NOT raise the threshold below the
   actual coverage.
2. **Raise the threshold.** Change `ci.yml:344` to 75/75/75.
3. **Verify CI.** Push + watch the coverage job. It must pass at the
   new 75% threshold.
4. **Headroom policy.** At first, 0% headroom (75% threshold = 75%
   actual). After one CI failure due to a coverage regression,
   consider relaxing to 73% (2% headroom) to avoid flaky CI — but only
   if the regression is a single uncovered line, not a pattern.
   Document the policy in the ADR.
5. **Celebrate.** The 12-series is the work that takes the coverage
   gate from a regression-guard-at-62% to a quality-target-at-75%.
   `state.md` records the achievement.

## Gate
```
cargo fmt --check && cargo clippy --all-targets -- -D warnings &&
cargo test --locked --workspace --no-fail-fast --all-features
cargo tarpaulin --out Xml --locked --lib --timeout 120
# Parse XML; confirm all three >=75%.
# Push + watch CI:
gh run watch <coverage-run-id>
gh run view <id> --json jobs | jq '.jobs[] | select(.name=="coverage") | .conclusion'
# Must be "success".
```

## Notes
- Do NOT raise the threshold above the actual coverage. If
  `src/session/` is 75.2% and you set the threshold to 76%, CI goes
  red. Set the threshold to 75% (the floor) and let the actual float
  above.
- The 0% headroom at first is intentional: it catches regressions
  immediately. If it's too strict (a single uncovered line fails CI),
  relax to 73% (2% headroom) — but document the relaxation in the ADR
  + `state.md` so it's a conscious decision, not a silent drift.
- This is the final WO of the 12-series. After it, the CI gate is at
  75%, the testdoctor is a workspace member with per-test timings +
  flaky detection + coverage gaps + smart suggest, and the coverage
  flake is fixed. The 12-series is the "test infrastructure + coverage"
  series.
- The `ponytail:` annotations in `ci.yml` (if any) must be preserved.
- The `readme_drift` test is unaffected (this WO touches only `ci.yml`
  + docs, no test additions).
