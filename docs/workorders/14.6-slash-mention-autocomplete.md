# Workorder 14.6 — Slash-Command + `@`-Mention Autocomplete

## Status: In Progress (worktree)

## Problem
The Pass-14 REVIEW (§2 + §6) names two discoverability gaps:
1. "No slash-command autocomplete: Typing `/he` doesn't suggest
   `/help`. The user must know the full command or scan `/help`
   output." (§2, rough edges)
2. "`@`-mention syntax (`@path:A-B:raw`) is documented in `/help` but
   has no inline hints. A user who types `@` sees no autocomplete or
   syntax reminder." (§6, hidden depth)

The REVIEW's fix (item 5): "Tab-complete `/he` → `/help` and `@` →
file path suggestions. 50-100 lines but high UX payoff." This is the
largest single UX win in the REVIEW's priority list — it turns the
24-command flat list and the 4-form `@` syntax from "read the manual"
into "type and see suggestions."

## Root cause
The input widget (`src/tui/components/input.rs` or wherever the line
editor lives — grep first) processes keystrokes char-by-char but
never inspects the buffer content to offer completions. The `COMMANDS`
table (WO 14.2 adds groups; the triggers are already there) and the
filesystem are the two completion sources; neither is wired to Tab.

## Files to touch
- `src/tui/components/input.rs` (or the actual input editor — grep
  `InputComponent` / `LineEdit` to find it) — on Tab keypress:
  - If the buffer starts with `/` and the cursor is after the `/`,
    complete against `COMMANDS` triggers. If one match, insert it.
    If multiple, show a one-line suggestion list above the input
    (reuse the existing "status row" pattern from `@`-mentions if
    one exists). If zero, beep / no-op.
  - If the buffer starts with `@` and the cursor is after the `@`,
    complete against filesystem paths relative to CWD. Reuse the
    `glob` tool's matching or a simple `fs::read_dir` of the current
    prefix's parent. The `@path:A-B:raw` suffix syntax should NOT
    be autocompleted (it's a modifier, not a path) — only the path
    portion up to the first `:`.
- `src/tui/keys/slash_commands.rs` — expose a
  `pub(crate) fn complete_command(prefix: &str) -> Vec<&'static str>`
  returning the triggers that start with `prefix`. The `COMMANDS`
  table is the source. This is a pure function the input widget calls.
- `src/tui/mod.rs` — wire the Tab key in the main event loop to call
  the completion. If a suggestion popup is needed, add a small
  `completion_suggestions: Vec<String>` field to `AppState` and
  render it as a one-line overlay above the input (or below, wherever
  ratatui makes it cheap — the search results UI may already have a
  popup pattern to mimic).
- Tests:
  - `complete_command("he")` returns `["/help"]` (or `["/help",
    "/h", "/?"]` — decide whether to return all aliases or just the
    primary; the REVIEW says "Tab-complete `/he` → `/help`" so the
    primary is the target).
  - `complete_command("p")` returns `["/plan", "/plugins", ...]`.
  - `complete_command("zzz")` returns `[]`.
  - `@` path completion test is harder (filesystem-dependent); use a
    temp dir as CWD and assert `@tmp` completes to `@tmpfile.txt` or
    similar. Mark `#[ignore]` if it's flaky on Windows path separators.

## Approach
1. **Slash completion first.** It's pure (no I/O — `COMMANDS` is
   const). The `complete_command` function is 5 lines. The input
   widget wiring is the bulk: on Tab, if buffer starts with `/`,
   call `complete_command`, if exactly one match replace the buffer,
   if many show suggestions.
2. **Path completion second.** More I/O. On Tab, if buffer starts
   with `@`, take the text after `@` up to the cursor, treat it as a
   path prefix, list entries in its parent dir that start with the
   prefix's last component. Reuse `glob` crate matching if it's
   already a dep (it is — the `glob` tool uses it). Single match:
   complete. Many: show suggestions. The `:A-B:raw` suffix is left
   alone.
3. **Suggestion UI.** Keep it minimal — a one-line overlay. If the
   existing search results or `@`-mention status row has a pattern,
   mimic it. Do NOT build a full popup widget — that's a bigger
   feature. The REVIEW asks for "Tab-complete"; a one-line
   suggestion list is enough to satisfy "the surface invites
   exploration."
4. **Don't break existing Tab behavior.** If Tab currently does
   something (indent? focus change?), grep for the existing handler
   and preserve it when the buffer doesn't start with `/` or `@`.
5. **Test the pure layer.** `complete_command` is pure and
   deterministic — pin it. The path completion is I/O-heavy; test
   with a temp dir and accept that it may need `#[cfg(unix)]` if path
   separators cause issues (but the `glob` crate handles this, so
   prefer cross-platform).

## Done condition
- Typing `/he` + Tab completes to `/help` (single match)
- Typing `/p` + Tab shows a suggestion list (`/plan`, `/plugins`,
  `/permissions` if 14.5 landed, etc.); Tab cycles or selecting
  completes
- Typing `@src/` + Tab shows files under `src/`; selecting one
  inserts `@src/<file>`
- The `:A-B:raw` suffix is not mangled by path completion
- `complete_command` is pure + tested (3 cases: 1 match, N matches,
  0 matches)
- `docs/TECHNICAL.md` TUI section: note that slash + `@` completion
  shipped (doc-sync per §9 — new user-visible interaction)
- ADR not needed (input widget behavior, not architecture)
- Depends on: WO 14.2 (for `complete_command` to return group-aware
  suggestions — optional; can complete without groups) and WO 14.5
  (so `/permissions` appears in completions) — soft deps; can land
  independently

## Notes
- The REVIEW's 50-100 line estimate is optimistic once the
  suggestion UI + path I/O + tests are counted. Budget 200-300 lines.
  This is still the highest-UX-payoff WO in the series.
- Do NOT add fuzzy matching. Prefix match is the contract; fuzzy is a
  bigger feature with different ergonomics. Prefix is what readline
  users expect.
- The `@`-mention status row (the REVIEW mentions a status row per
  mention exists) is a separate display; this WO adds the *input*
  completion, not the status row. Don't conflate.
- If the input widget is a single-file component, the bulk of the
  code lands there; if it's spread across `tui/mod.rs`, consolidate
  carefully. Grep `fn handle_key` / `KeyEvent` in `src/tui/` first.
- Preserve `ponytail:` / `ceiling:` annotations (grep `input.rs` /
  the editor file before editing).
