# Workorder 17.3 — Daemon Hardening: Socket Guard, Auth, Version, Ownership, Quit

## Status: Done

## Problem
KirkForge's daemon has five correctness/security gaps vix does not:

1. **Blind socket steal.** `src/daemon/server.rs:43-47` unconditionally
   `remove_file`s the socket before `bind`. A second `kf-code daemon`
   silently steals the socket from a running one, orphaning its in-flight
   state. vix dials the existing socket and refuses to hijack a live daemon
   (`server.go:516-541` `daemonAlreadyListening`).
2. **No auth.** `server.rs:270-307` has zero auth on any op — any local
   process can `Shutdown` or read the session list. vix gates every frame
   with a constant-time shared secret (`server.go:369-374`, `subtle.ConstantTimeCompare`).
3. **No version gate.** An older TUI can talk to a newer daemon and get
   mismatched behavior silently. vix enforces an exact client/daemon version
   match on `thread.start` (`server.go:740-750`).
4. **No session ownership.** Two TUIs can resume the same `*.conv.ndjson` and
   append concurrently. vix refuses `attach` to a thread already held
   (`server.go:843-865`, `thread_busy`).
5. **jobd accept loop not shutdown-wired.** `src/jobs/daemon.rs:80-95` spawns
   the accept loop with no `tokio::select!` on shutdown; the scheduler stops
   on `Shutdown` (`daemon.rs:194-207`) but `listener.accept()` is orphaned
   until process exit. The session daemon already does this right at
   `server.rs:121-147` — copy that shape.

Plus coordinated quit (rides 17.2's channel).

## Root cause
The daemon was built as a trusted-single-user local cache and never grew the
multi-process safety vix designed in from the start. Each gap is one focused
fix in `server.rs` / `mod.rs` / `jobs/daemon.rs`.

## Files to touch
- `src/daemon/server.rs` — socket liveness guard: before `UnixListener::bind`,
  attempt `UnixStream::connect(path)`; if it succeeds, bail with "daemon already
  running — stop it first". Only `remove_file` if connect fails with
  connection-refused / stale.
- `src/daemon/mod.rs` — add `auth_token: Option<String>` to `Request` (or a
  handshake field) and a `DaemonState::expected_token: Option<String>` loaded
  from a file path env var (`KF_CODE_DAEMON_TOKEN_FILE`). Empty/unset token =
  legacy-off (no auth, current behavior) so this is opt-in and non-breaking.
  `handle_request` does `subtle::ConstantTimeEq` when a token is configured.
- `src/daemon/server.rs` `Ping`/`InstanceRegister` — include `version` in the
  handshake; `DaemonClient::connect` (`src/daemon/client.rs`) compares it to
  `env!("CARGO_PKG_VERSION")` and bails on mismatch with a restart hint.
- `src/daemon/mod.rs` / `server.rs` — `open_sessions: HashSet<SessionId>` on
  `DaemonState`; add `Request::Claim { id }` returning `Response::Busy` if
  already claimed, `Ok` otherwise; cleared on connection close. `Touch`
  consults it; the TUI warns before opening a claimed session.
- `src/jobs/daemon.rs:80-95` — wrap the accept loop in
  `tokio::select! { _ = shutdown.notified() => break, accept = listener.accept() => … }`
  mirroring `src/daemon/server.rs:121-147`.
- Coordinated quit: add `Request::QuitAll` (or a daemon-side
  `DaemonState::broadcast(InstanceEvent::Quit)` + a 500ms flush); the TUI
  reader task (from 17.2) treats `Quit` as an exit request. Needed before any
  in-app self-update (Series 18).
- Tests: each guard gets a unit test — second-bind is refused, wrong-token is
  rejected with constant-time (assert same timing within tolerance is not
  required; assert rejection), version mismatch bails, `Claim` on a claimed
  id returns `Busy`, jobd accept loop exits on shutdown within a deadline.

## Approach
1. **Socket guard first.** It's a pure footgun fix with no dependencies and
   prevents data loss today. Land it even before 17.2's channel.
2. **Auth is opt-in.** No token configured → current behavior (the daemon is
   single-user local). Token configured → every op checks it. This avoids
   breaking existing setups while letting security-conscious users enable it.
   Constant-time via the `subtle` crate (add to `Cargo.toml`).
3. **Version gate on the handshake, not every op.** Compare once at
   `InstanceRegister`/`Ping`; reject the connection, not individual ops. Keeps
   the hot path clean.
4. **Ownership is advisory in the TUI.** `Claim` returns `Busy`; the TUI shows
   "session open in another window — open read-only or take over?". Do not
   hard-block — the user may have closed the other window uncleanly. The
   `open_sessions` set clears on connection drop, so a dead window releases
   its claim.
5. **jobd accept loop.** One `select!` edit; copy the working pattern from the
   session daemon verbatim.

## Done condition
- A second `kf-code daemon` refuses to start while the first is live
  (dial-then-refuse), instead of stealing the socket.
- With a token file set, an unauthenticated `Shutdown`/`List` is rejected;
  without one, behavior is unchanged (opt-in, non-breaking).
- A TUI built from a different `kf-code` version than the daemon fails the
  handshake with a clear "restart both halves" message.
- `Claim` on an already-claimed session returns `Busy`; the TUI surfaces it;
  closing the owning window releases the claim.
- `jobd` `Shutdown` unblocks the accept loop within a deadline (no orphaned
  task until process exit).
- `QuitAll` (or `Quit` broadcast) makes every attached TUI exit cleanly.
- Depends on: 17.2 (the instance channel carries `Quit` and the version
  handshake rides `InstanceRegister`).

## Notes
- Keep each fix small and independent so they can land in any order after 17.2.
  The socket guard can even land before 17.2 — it has no dependency.
- Do not implement full Bedrock/IMDS/SSO credential chains here (that's auth
  *provider* work, Series 18). This WO is daemon-process security only.
- Constant-time compare is for token equality only; do not roll a generic
  crypto layer. `subtle::ConstantTimeEq` on the token bytes is the whole story.
