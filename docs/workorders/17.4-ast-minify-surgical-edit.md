# Workorder 17.4 — AST Minification + Surgical Edit Position Map + Revalidation

## Status: Done

## Problem
vix's headline feature is "20–50% fewer tokens" via a Tree-sitter virtual
filesystem: it minifies code by collecting AST leaf tokens
(`internal/daemon/treesitter.go:minifyWithTreeSitterMapped`), keeps a
byte-position map, edits the *minified* text, then `VfsEdit` splices the edit
back into *only the matched source region* — surrounding formatting/comments
on disk are untouched (`vfs.go:274-336`). It re-parses the minified output and
rejects it if new ERROR nodes appeared (`revalidateMinified`, `treesitter.go:240-274`),
and guarantees minification is idempotent (`TestMinifyIdempotency`) so
second-pass edits match.

KirkForge's minifier (`src/shared/minify/lang.rs:5-19`,
`minify_content_by_ext`) is a lossy char-scan comment-stripper + blank-line
collapse. It has no position map, so `src/tools/edit_file.rs:137-161` and
`src/shared/minify/expand.rs` expand the *whole* `<minified>` envelope (reformatting the entire file) and do string replacement in expanded space —
clobbering surrounding formatting and forcing whole-file round-trips. There is
no revalidation and no idempotency guarantee, so a char-scan edge case (e.g.
`//` inside an unmatched string) silently emits broken code.

## Root cause
The minifier was built as a display compression, not a lossless transform with
a round-trip. Without a minified→source byte map, edits can't be surgical;
without revalidation, invalid minified output reaches the model and disk.

## Files to touch
- `Cargo.toml` — add `tree-sitter` + the per-language grammars you ship (start
  with the languages vix covers that kf-code users hit: Rust, Go, Python, TS/JS,
  Bash; vix ships 18, but YAGNI — ship the 5 that matter and add the rest on
  demand). Reuse grammars already vendored if any exist.
- `src/shared/minify/lang.rs` — replace `minify_content_by_ext`'s char-scan
  with a tree-sitter token-leaf collector that emits minimal spacing and
  returns a `Minified { text: String, map: Vec<Span> }` where each `Span` maps a
  minified-text byte range to its source byte range. Keep the old char-scan as
  a fallback for languages without a grammar (gated, not the default path).
- `src/shared/minify/mod.rs` — add `revalidate(src_lang, minified) -> Result<()>`
  that re-parses the minified text with the grammar and rejects if new
  ERROR/MISSING nodes appeared. Add an `idempotent` check: re-minifying the
  minified output is byte-identical.
- `src/shared/minify/expand.rs` — add `surgical_edit(minified, old, new) ->
  Result<String>` that matches `old` in minified space, projects the match to
  source bytes via the map, and splices `new` into only that source region.
  Falls back to the existing whole-file expand only when no map exists (legacy
  path / no grammar).
- `src/tools/edit_file.rs` — when the edit targets a minified block, call
  `surgical_edit` instead of expand-then-replace. The on-disk file keeps its
  formatting outside the matched region.
- Tests: `src/shared/minify/` — idempotency suite (minify twice == once per
  language), revalidation rejects a deliberately-broken minification,
  `surgical_edit` edits only the matched region and leaves surrounding bytes
  identical, round-trip (minify → edit → source) is byte-exact for a corpus of
  fixtures.

## Approach
1. **Position map is the keystone.** Build `minify_with_map(lang, src) ->
   Minified` first; the map is what makes everything else surgical. Each
   minified token records `(min_start, min_end, src_start, src_end)`.
2. **Surgical edit.** `surgical_edit` finds `old` in `minified.text`, maps the
   match's minified byte range to source bytes, reads the source file, splices
   `new` into that source range, writes back. Surrounding source is untouched.
   This is vix's `VfsEdit` (`vfs.go:274-336`).
3. **Revalidation is a hard gate.** After minification, `revalidate` re-parses;
   on failure, fall back to sending the *unminified* file rather than shipping
   broken code to the model. Never let invalid minified text reach the model
   or disk.
4. **Idempotency is a test, not runtime.** The suite asserts minify is a
   fixed point; if it isn't, the map would drift on second-pass edits. Fix the
   annotators (per-language statement separators — vix's `preserveSemicolons`)
   until idempotency holds.
5. **Per-language annotators (deferred unless cheap).** Go needs semicolon
   insertion between adjacent statements; Python needs indentation preserved.
   Start with Rust + Go + Python; TS/JS and Bash can follow. If an annotator
   is more than a day, defer to Series 18 and ship the languages that work.
6. **Formatter-gated write-back (deferred).** vix runs `gofmt`/`rustfmt` after
   `VfsWrite`. kf-code already formats on edit via its tools; do not add
   formatter detection here — Series 18 if the surgical edit produces
   non-canonical output in practice.

## Done condition
- Minification is AST-based for the shipped languages; char-scan is fallback
  only for languages without a grammar.
- A `Minified` carries a byte map; `surgical_edit` edits only the matched
  source region, leaving surrounding formatting/comments byte-identical.
- `revalidate` rejects broken minified output; on rejection the unminified
  file is sent instead (never broken code to the model).
- The idempotency suite passes for every shipped language.
- Token cost: a before/after measurement on a fixture corpus (reuse
  `KIRK-BENCH.md` or `benches/`) shows a measurable reduction vs the char-scan
  minifier, with zero round-trip corruption.
- Depends on: nothing. Pairs with 17.5 (the cache stem benefits from stable
  minified content).

## Notes

  formatter-gating are refinements (deferred to Series 18 if scope creeps).
