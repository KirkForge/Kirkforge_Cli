# Workorder 17.5 — Stem-Agents: Shared Cached Context + Top-N Files + Cache Breakpoints

## Status: Done

## Problem
vix maximizes Anthropic prompt-cache reuse across workflow phases by (a)
appending the thread's shared `contextSystemBlocks()` (CLAUDE.md/AGENTS.md +
skills metadata) to *every* workflow step's sub-agent system prompt so the stem
is byte-identical across phases (`internal/daemon/workflow_state.go:184-193`,
the "stem agents" feature), (b) injecting the top-10 frequently-accessed file
bodies into the cached system stem from SQLite access stats
(`internal/daemon/thread.go:frequentlyAccessedFilesText:1248-1278`), and (c)
placing a top-level `cache_control` on the system+tools block and an
ephemeral breakpoint on the last user message's last content block so the
growing conversation tail is cached for the next turn
(`internal/daemon/llm/anthropic.go:126`, `llm/bedrock.go:603-625`).

KirkForge does none of this well:
- `src/session/prompt/cache_stem.rs` (`CacheStemTracker`) only *hashes and
  reports* stem stability as a metric — it does not *enforce* a shared stem.
- `src/session/router.rs` / `stratum.rs` do not inject a shared context block
  into sub-agent system prompts, so cross-phase cache reuse is not enforced.
- There is no per-session top-N file injection (`src/session/carryover.rs` is
  cross-session only; `src/session/access/mod.rs` tracks reads for the
  read-gate but exposes no top-files query).
- `src/adapters/anthropic.rs:184-196` and `src/adapters/mod.rs:600-611`
  (`cache_marker_indices`) mark only the last 2 prefix messages' last content
  blocks and explicitly *skip* the trailing user message — so the tools block
  is not separately cached and no breakpoint is placed on the conversation tail.
- `src/session/prompt/microcompaction.rs:1-20` is a heuristic, non-LLM
  summarizer that drops user/assistant prose — lower compaction quality than
  vix's structured LLM compaction (`thread.go:compactionSystemPrompt:2098-2118`).

## Root cause
The cache infrastructure exists but is observational, not prescriptive. The
tracker measures; nothing guarantees the stem is identical across callers,
places breakpoints for maximum cache hits, or feeds the cache hot file
contents.

## Files to touch
- `src/session/prompt/cache_stem.rs` — flip from metric-only to enforcement:
  expose `shared_context_stem(state) -> Vec<ContentBlock>` (project
  instructions + tool catalog) that every sub-agent / workflow step system
  prompt prepends. Keep the tracker as a cheap assertion that the stem hash is
  constant across phases; fail loud in dev if it drifts.
- `src/session/router.rs` (and `src/session/stratum.rs`, workflow step
  spawning) — prepend the shared stem to sub-agent system prompts so phases
  share the Anthropic cache prefix.
- `src/session/access/mod.rs` — add a per-session access-count query
  `top_files(n) -> Vec<PathBuf>` (the read-gate already counts reads; expose
  it). `src/session/prompt/mod.rs` injects those files' *minified* bodies
  (via 17.4's minifier) into the cached stem as a stable block.
- `src/adapters/anthropic.rs` + `src/adapters/mod.rs` — add a top-level
  `cache_control: ephemeral` on the system+tools block (one breakpoint up
  front) and an ephemeral breakpoint on the last user message's last content
  block (the tail cache vix sets at `bedrock.go:603-625`). Revisit
  `cache_marker_indices` — the current last-2-prefix scheme is fine *in
  addition*, but the top-level and tail breakpoints are the ones vix relies
  on for cross-turn cache hits.
- `src/session/prompt/microcompaction.rs` — wire the LLM summarizer
  (`src/session/prompt/summarizer.rs`) behind a config flag
  (`compaction.use_llm = true|false`) so the heuristic summary is the default
  but a structured LLM compaction (goals/decisions/files/tool-outputs/TODOs,
  mirroring vix's order) is available when the heuristic would drop >N% of
  content. Keep the heuristic as the cheap path.
- Tests: `cache_stem` — assert the stem hash is identical across two
  sub-agent spawns in a workflow; assert top-N files appear in the stem and
  are stable across turns; adapter test asserting the system+tools block and
  the last user block both carry `cache_control` on the wire.

## Approach
1. **Enforce, don't just measure.** The single highest-leverage change: one
   shared stem prepended everywhere. Once the stem is byte-identical across
   phases, Anthropic's prompt cache hits on every phase. The existing tracker
   becomes a cheap invariant check.
2. **Top-N files feed the cache.** The files the model re-reads every turn are
   the cache's hottest content. Inject their minified bodies into the stem
   (17.4's minifier keeps them small) so the model stops re-reading and the
   block is cached. The access counts already exist in the read-gate.
3. **Two breakpoints, not one.** Top-level (system+tools) caches the static
   prefix across the whole session; tail (last user message) caches the
   growing conversation for the next turn. vix sets both; kf-code sets neither
   correctly. Keep the existing last-2-prefix markers — they help — but add
   these two.
4. **LLM compaction is opt-in.** The heuristic is cheap and good enough most
   of the time. The LLM compaction is heavier; gate it behind a flag and a
   "heuristic dropped >N%" trigger, not on by default.
5. **Measure.** Before/after: cache-read vs cache-creation token counts on a
   multi-turn + multi-phase fixture. The win shows up as cache-read tokens
   dominating.

## Gate
```
cargo fmt --check && cargo clippy --all-targets -- -D warnings &&
cargo test --locked --workspace --no-fail-fast &&
cargo test -p kf-code --lib session::prompt::cache_stem session::prompt::microcompaction
```

## Done condition
- A workflow with N phases produces N sub-agent system prompts whose stem
  (project instructions + tool catalog) is byte-identical — verified by the
  tracker asserting the hash is constant.
- The top-N frequently-accessed files are injected into the cached stem and
  are stable across turns (no re-read needed).
- The Anthropic request carries a `cache_control` breakpoint on the
  system+tools block and on the last user message's last content block.
- LLM compaction is available behind `compaction.use_llm` and triggered when
  the heuristic drops >N% of content; heuristic remains the default.
- A before/after measurement shows cache-read tokens increase (cache hits) on
  a multi-turn + multi-phase fixture without raising total tokens.
- Depends on: nothing strictly; pairs with 17.4 (minified top-N files are
  smaller, so the stem stays under cache size limits).

## Notes
- The stem must be byte-identical, not just "similar" — Anthropic's cache is
  prefix-exact. Any per-phase variation (e.g. a phase index in the prompt)
  breaks the cache. Put phase-specific content *after* the shared stem.
- Do not build a generic "context system" framework here. One shared stem
  function, one top-N query, two breakpoints. YAGNI until a second cache
  strategy is needed.
- The `CacheStemTracker` metric-only path is the kind of observational
  scaffolding the ponytail audit flags — repurpose it to enforcement rather
  than adding a parallel enforcement layer alongside it.
- Coordinate with 17.6 (workflow steps are the main multi-phase beneficiary
  of the shared stem) and 17.4 (minified file bodies keep the stem small).
