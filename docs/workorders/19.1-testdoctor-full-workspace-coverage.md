# Workorder 19.1 — Testdoctor: Full Workspace Coverage + Gaps Cross-Reference

## Status: Planned

## Problem

`kf-testdoctor diagnose` only scans 3 directories (`src/session`, `src/tools`,
`src/adapters`), missing 1,731 tests across `src/tui`, `src/daemon`, `src/jobs`,
`src/main`, `src/shared`, and all 16 crates. It also doesn't cross-reference with
`tarpaulin` coverage data — you can't ask "which uncovered files also have low test
density?"

M17 (already fixed in WO 18) added `crates/` to `DEFAULT_DIRS`, but the scan is still
incomplete and shallow.

## Root cause

1. `DEFAULT_DIRS` was hardcoded to match the CI coverage gate's 3 directories.
   WO 18's fix added `crates/` but didn't add `src/tui`, `src/daemon`, `src/jobs`,
   `src/main`, `src/shared`.
2. `diagnose` counts lines and `#[test]` attrs but never reads Cobertura XML.
   The `gaps` command reads it but they're separate subcommands with no shared output.
3. No `--dirs` CLI flag to customize scan scope.

## Fix

### 1. Add all source directories to `DEFAULT_DIRS`

```rust
const DEFAULT_DIRS: &[&str] = &[
    "src/session", "src/tools", "src/adapters",
    "src/tui", "src/daemon", "src/jobs", "src/main", "src/shared",
    "crates",
];
```

### 2. Add `--dirs` CLI flag to `diagnose`

Allow `kf-testdoctor diagnose --dirs src/tui,crates/kf-draw` to customize scope.
Default remains `DEFAULT_DIRS`.

### 3. Cross-reference `diagnose` with `gaps`

Add a `diagnose --with-coverage <cobertura.xml>` flag that:
1. Reads tarpaulin output (same XML format `gaps` already parses)
2. Joins coverage percentages with test density by file
3. Reports files that are both low-coverage AND low-test-density (highest ROI targets)

This makes `diagnose` and `gaps` work together instead of as isolated subcommands.

## Verification

- `cargo test -p kf-testdoctor`
- `kf-testdoctor diagnose` output now lists all directories with test counts
- `kf-testdoctor diagnose --dirs src/tui` works
- `kf-testdoctor diagnose --with-coverage cobertura.xml` shows cross-referenced output

## Ponytail note

`--with-coverage` is the only non-trivial piece. The directory list and `--dirs` flag
are one-liners. Do those first, ship, then add coverage cross-ref.
