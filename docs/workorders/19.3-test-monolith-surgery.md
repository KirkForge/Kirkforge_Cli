# Workorder 19.3 — Test Monolith Surgery: Split the 3 Worst Offenders

## Status: Planned

## Problem

Three test files dominate the codebase at a combined 9,000+ lines:

| File | Lines | Top function | Lines |
|---|---|---|---|
| `kf-budget-cli/src/tests_adr_0015.rs` | 5,183 | `report_last_after_combined_filters_at_subprocess` | 224 |
| `kf-draw-core/src/state/tests.rs` | 3,031 | (state machine combinatorics) | — |
| `session/executor/tests/approval.rs` | 1,832 | (approval flow with MockAdapter) | — |

`tests_adr_0015.rs` alone has 16 functions over 100 lines. The file is named after an
ADR but has grown far beyond it. Finding anything in it requires scrolling through
5,000 lines.

## Fix

### 1. Split `tests_adr_0015.rs` by feature area

The file contains tests for budget report, budget status, config validation, and
hook wire-shapes. Split into:

- `tests/report.rs` — all `report_*` tests
- `tests/config.rs` — all `config_*` tests
- `tests/hooks.rs` — all `hook_*` tests (already partially in `tests_main.rs`)
- `tests/budget_compact.rs` — all `budget_compact_*` tests

Each new file < 1,500 lines. The ADR reference stays in a header comment.

### 2. Split `kf-draw-core/src/state/tests.rs` by state

The file tests state machine transitions. Split into:

- `state/tests/initial.rs` — initial state transitions
- `state/tests/active.rs` — active state transitions
- `state/tests/error.rs` — error state transitions

### 3. Split `session/executor/tests/approval.rs` by scenario

Split into:

- `tests/approval_auto.rs` — auto-approve scenarios
- `tests/approval_deny.rs` — deny and reject scenarios
- `tests/approval_timeout.rs` — timeout scenarios

### 4. Add `#[cfg(test)] mod tests` re-exports if needed

If the parent module imports via `mod tests;`, add a re-export module that
`pub use`s the split modules. This preserves the public API.

## Verification

- `cargo test -p kf-draw-core` — all tests still pass
- `cargo test -p kf-code --lib` — all tests still pass
- No file > 1,500 lines
