# Workorder 19.4 — Kill No-Assertion Tests: Upgrade or Delete

## Status: Planned

## Problem

~40 tests across the codebase have no meaningful assertions. They prove "does not
panic" or "is a noop" — they'd pass even if the code returned garbage. The worst
clusters:

- `session/executor/tests/turn.rs`: `post_turn_guard_constructs_and_drops`,
  `set_recovered_messages_stores_count`, `set_session_id_updates_field`,
  `set_plan_mode_toggles`, `set_system_override_does_not_panic` — all are
  struct setter tests that don't assert the value is stored correctly.
- `session/process_group.rs`: `reap_child_*` and `setup_process_group_*` — test
  that the function doesn't panic, but don't verify the process group is set.
- `session/hooks.rs`: `test_run_noop_for_missing_hook`, `test_run_hook_timeout_does_not_panic`,
  `test_run_hook_blocks_dangerous_content` — name suggests assertions but some
  only verify no panic.
- Various `_does_not_panic` and `_is_noop` tests across 8+ files.

## Fix

### Principle

A test should assert something about the **output** or **state** of the system,
not just that it doesn't crash. "Does not panic" is not a test — it's a debug
assert in production code.

### 1. Upgrade struct setter tests

Tests like `set_session_id_updates_field` should assert the field is actually
updated:

```rust
// Before (no assertion):
fn set_session_id_updates_field() {
    let mut ctx = TurnContext::new(...);
    ctx.set_session_id("test");
}

// After:
fn set_session_id_updates_field() {
    let mut ctx = TurnContext::new(...);
    ctx.set_session_id("test");
    assert_eq!(ctx.session_id(), "test");
}
```

### 2. Upgrade process group tests

`setup_process_group_does_not_panic` should verify the process group is set
via `getpgid()` on the child PID.

### 3. Upgrade hook tests

`test_run_hook_blocks_dangerous_content` should assert the hook returns `Deny`,
not just that it doesn't panic.

### 4. Delete truly useless tests

If a `_does_not_panic` test can't be upgraded to assert meaningful behavior
(because the function genuinely has no observable output and no side effects),
delete it. A test that passes on every implementation is not a test.

### 5. `kf-compress-cli/tests/integration.rs`

33 tests that check subprocess exit codes but not output content. At minimum,
add assertions on stderr/stdout for the success cases. For the error cases,
assert the exit code AND the error message substring.

## Verification

- `grep -r '#\[test\]' src/ crates/ | wc -l` count should stay the same or decrease
  by no more than 10 (deletions of truly useless tests)
- Every remaining test has at least one `assert!`, `assert_eq!`, `assert_ne!`,
  `should_panic`, or `?` operator
- `cargo test --workspace` passes
