# Workorder 19.5 — Integration Test Gaps: Daemon RPC, Jobs Lifecycle, Plugin Registration

## Status: Planned

## Problem

Review-4's critical bug (18.0.1: budget runtime gate using wrong plugin name) shipped
through 2,879 passing tests because no test boots with default config and asserts
budget tools are present. Three subsystems have zero integration tests:

- **daemon** — 3 unit tests, 1 e2e test that only pings the socket. No test for
  session management, job submission, or auth token enforcement.
- **jobs** — 21 unit tests. No integration test for the full job lifecycle
  (submit → schedule → run → status).
- **plugins** — 23 unit tests. No test for plugin tool invocation through the
  executor, and no test for folded-plugin registration with default config.

This WO addresses the three most critical integration gaps that would have caught
review-4 bugs.

## Fix

### 1. Plugin registration integration test (would have caught 18.0.1)

Add a test in `src/session/plugin_tools/tests.rs` or a new integration test that:

1. Constructs a `CompositeToolset` with default config (`enabled_plugins` contains
   `"kf-budget"`, `"stratum"`, `"kf-draw"`)
2. With the `budget` feature enabled, asserts that `budget_status` and `budget_set`
   tools appear in the toolset
3. With the `stratum` feature enabled, asserts that stratum hooks are registered
4. Asserts that `folded_feature_enabled("kf-budget")` returns `true`
5. Asserts that `folded_feature_enabled("nonexistent-plugin")` returns `false`

This is the test that would have caught the `kf-plugin-sdk3` vs `"kf-budget"` bug.

### 2. Daemon RPC integration test

Add a test in `src/daemon/` or a new `tests/integration_daemon.rs` that:

1. Starts a `DaemonServer` on a temp socket
2. Sends `Ping` and verifies `Pong`
3. Sends `Shutdown` without auth token and verifies rejection (catches H5 regression)
4. Sends `Shutdown` with auth token and verifies success
5. Starts a `JobDaemon` on a temp socket
6. Submits a bash job and verifies status transitions

### 3. Jobs lifecycle integration test

Add a test in `src/jobs/` that:

1. Creates a `ScheduledJob` with a timeout
2. Runs it via `run_bash_job`
3. Verifies the timeout is enforced (catches H6 regression — timeout was `None`)
4. Verifies the job exits with the correct exit code
5. Verifies that jobs with invalid `SpecFile.path` are rejected
