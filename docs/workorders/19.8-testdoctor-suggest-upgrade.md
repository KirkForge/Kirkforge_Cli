# Workorder 19.8 — Testdoctor `suggest` Upgrade: Crate-Aware Path Resolution

## Status: Planned

## Problem

`suggest-detailed` resolves source paths by guessing: it tries `tests/{binary}.rs`,
`src/{binary}.rs`, `crates/{binary}/src/lib.rs`. If the binary name doesn't match the
filesystem path (e.g., `kf-code` maps to `src/main/` not `src/kf-code/`), it falls
back to v1 text suggestions, losing the source-pattern analysis.

The 16 crates under `crates/` each have different binary names and directory structures.
The `suggest` module doesn't know about them.

## Fix

### 1. Build a binary-to-path map from `Cargo.toml`

Read the workspace `Cargo.toml` and each crate's `Cargo.toml` to build a mapping
from binary name → source directory. This is deterministic and doesn't require guessing.

```rust
fn build_binary_map(root: &Path) -> HashMap<String, PathBuf> {
    // Parse workspace members from root Cargo.toml
    // For each member, parse [[bin]] and [[test]] targets
    // Map binary name → source root
}
```

### 2. Use the map in `suggest-detailed`

When `suggest-detailed` identifies a slow binary, look up its source directory
from the map instead of guessing paths.

### 3. Add crate-level patterns

The v2 source-pattern scanner currently only checks `src/session`, `src/tools`,
`src/adapters`. With the path map, it can scan the actual crate source directories
and find patterns in `crates/kf-*/src/`.

## Verification

- `kf-testdoctor suggest-detailed` correctly resolves `kf-code` → `src/`
  and `kf-budget-cli` → `crates/kf-budget-cli/src/`
- `kf-testdoctor suggest-detailed` finds source patterns in crate code
  (e.g., `std::process::Command` in `kf-compress-cli`)
