# Workorder 19.9 — Flaky Test Stabilization

## Status: Planned

## Problem

7 locations in the codebase explicitly acknowledge flakiness or race conditions:

1. `session/executor/tests/loop_.rs:225` — "test used 1000ms sleeps with a 3.5s threshold, which was flaky under"
2. `session/plugin_tools/tests.rs:1183` — `#[ignore = "timing-sensitive file-system watcher test"]`
3. `session/router.rs:305` — "Debug the race condition and refactor the executor" (production code)
4. `tui/connection.rs:49` — "probe uses a short timeout so a flaky/unreachable host does not block"
5. `kf-budget-core/src/test_support.rs:17` — "overrides and produce flaky failures"
6. `kf-budget-core/src/orchestrator.rs:374` — "Timing would be flaky on shared CI"
7. `kf-budget-cli/src/commands/init.rs:611` — "surfaces in CI as a flaky pass/fail"
8. `tests/integration_test.rs:17` — "previous 60 s ceiling caused flaky failures"

Additionally, 17 tests are `#[ignore]`d for requiring external services (Ollama, Docker,
Chrome, display server, subprocess spawning, real CPU).

## Fix

### Principle

Flaky tests fall into 3 categories:
1. **Timing-dependent**: fix with `#[tokio::test(start_paused = true)]` or deterministic waits
2. **Environment-dependent**: fix with mock servers or `#[ignore]` with dedicated CI job
3. **Race conditions**: fix the race, don't work around it with sleeps

### 1. Timing-dependent tests

- `loop_.rs:225`: Replace 1000ms sleep with `tokio::time::advance(1000)` inside
  `#[tokio::test(start_paused = true)]`. The testdoctor `apply` command already knows
  how to add `start_paused`.
- `plugin_tools/tests.rs:1183`: Replace filesystem watcher timing with
  `tokio::time::advance` and a bounded channel. The watcher should emit events to
  a channel that can be awaited.
- `kf-budget-core/orchestrator.rs:374`: Use `tokio::time::pause()` in the test
  and advance time deterministically.

### 2. Environment-dependent tests

Already `#[ignore]`d. Create a dedicated CI job matrix:
- `ci.yml` job: `integration-test` (runs with Ollama)
- `ci.yml` job: `docker-test` (runs bash tests with Docker)
- `ci.yml` job: `e2e-test` (runs e2e harness)

This is CI config work, not code changes.

### 3. Race conditions

- `session/router.rs:305`: The comment says "debug the race condition and refactor."
  This is a production code race, not a test race. If it affects tests, fix the race
  in production code.

### 4. `integration_test.rs:17` timeout ceiling

The 60s timeout was raised. If it's still flaky, increase to 90s or use
`tokio::time::timeout` with a generous margin.
