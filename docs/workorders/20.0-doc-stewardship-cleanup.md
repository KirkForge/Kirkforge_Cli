# Workorder 20.0 — Documentation Stewardship: Cleanup + Ongoing Discipline

## Problem

175 .md files, many stale from initial import. No ongoing rule prevents
re-accumulation. The AGENTS.md doc-sync rule (§9) only covers TECHNICAL.md
and ADR counts — it doesn't say where new docs live or when to archive old
ones.

This workorder does two things:
1. One-time cleanup (A1–A5)
2. Add a permanent doc-placement rule to AGENTS.md (A6)

## One-time cleanup

### A1. Archive superseded ideas

```
docs/ideas/ → docs/archive/ideas/
```

Replace `docs/ideas/` with a README pointing to archive and noting new ideas
go straight to ADRs.

### A2. Move review post-mortems out of root

```
review-1.md → docs/reviews/review-1.md
review-2.md → docs/reviews/review-2.md
review-3.md → docs/reviews/review-3.md
review-4.md → docs/reviews/review-4.md
```

### A3. Write `docs/README.md` index

One file explaining the doc tree so newcomers know where things go.

### A4. Audit ADRs for staleness

Read-only: scan the 59 Jul-19 ADRs for ones where code has diverged from
spec. Add `Status: Superseded` header where applicable. Update the ADR
index table in `docs/adr/README.md` to match.

### A5. Audit runbooks

The 3 runbooks (trust-tier rejection, docker timeout, quota exceeded) are from

## Ongoing discipline

### A6. Add doc-placement rule to AGENTS.md

Extend §9 with:

> **Doc-placement rule**: New docs go in the right directory on first write.
> Don't drop .md files in the repo root (exceptions: README, CHANGELOG,
> CLAUDE.md, AGENTS.md, state.md). When a workorder is completed, any
> post-mortem or review file goes in `docs/reviews/`. When an idea becomes
> an ADR, the idea file gets moved to `docs/archive/ideas/`. The
> `docs/README.md` index is the source of truth for where things go.

This is the part that outlives this workorder — the rule, not the cleanup.
