# Workorder 20.0.5 — Deferred Work & Security Gaps

## Problem

Audit found 2 HIGH-severity security gaps and several MEDIUM stubs that are
land mines in production.

## Targets

### S1. SSRF guard not wired — `host_resolves_to_internal_ip()` (HIGH)

`src/tools/web_fetch.rs:226` — Complete SSRF defense function exists but is
`#[allow(dead_code)]` and never called from the fetch path. The comment says
"this guard catches rebinding attacks" but the guard isn't active.

This is either dead code or a **security gap**. If the function is correct, it
should be called. If it's not correct, it should be deleted so nobody thinks
SSRF protection exists.

**Fix:** Wire `host_resolves_to_internal_ip()` into the `web_fetch` request
path, or delete it and document that SSRF protection is not implemented.

### S2. Keychain auth stubbed to `None` (HIGH)

`src/adapters/auth.rs:31-35` — The keyring auth path returns `None`, silently
skipping OS keychain credentials. The TODO says "Series 18 keyring
integration" but no integration exists.

**Fix:** Either implement `keyring::Entry` integration (the dependency exists
but isn't wired), or remove the stub branch and document that keychain auth is
not yet available. The current state (silently returning None) is the worst of
both worlds — code exists, users expect it to work, it doesn't.

### S3. `ConnectionState::Connecting` — dead variant (MEDIUM)

`src/tui/app.rs:23` — `#[allow(dead_code)]` on a variant reserved for async
connection state machine that was never implemented. 6 match arms handle it
but it's never constructed.

**Fix:** Remove the `#[allow(dead_code)]` and either implement the connecting
state (it has UI handling already) or remove the variant and simplify the
match arms.

### S4. MCP `disconnect()` — lifecycle API never called (MEDIUM)

`src/session/mcp_client/mod.rs:506,699` and `http.rs:382` — `disconnect()`
methods are `#[allow(dead_code)]`. Production relies on `Drop`, which kills
tasks without graceful shutdown. The task handles (`reader_task`, `poster_task`,
`shutdown_tx`) stored for cleanup are never used.

**Fix:** Call `disconnect()` before dropping MCP clients. Remove the
`#[allow(dead_code)]` annotations. If graceful shutdown isn't feasible now, add
a `// ponytail:` comment explaining why and remove the allow.

### S5. Daemon client `touch()` — silent no-op (MEDIUM)

`src/daemon/client.rs:483` — `touch()` returns `Ok(())` without doing anything.
The caller has no way to know the operation was discarded.

**Fix:** Either implement touch (update the file timestamp via the daemon) or
return an explicit error `Err(anyhow!("touch not implemented"))` so callers
know it's not available.

### S6. Config access — 7 different patterns (MEDIUM-HIGH)

Found in: `tui/commands/jobs.rs:524`, `session/bench.rs:157,164`,
`tui/approval_keys.rs:205,280`, `session/executor/approval.rs:113`,
`tui/commands/plugins/mod.rs:828,953`

Patterns include `.read().unwrap()`, `.read().unwrap().clone()`, direct field
access, `.write().unwrap()`, `if let Ok(mut cfg)`,
`unwrap_or_else(|e| e.into_inner())`.

**Fix:** Standardize on `read_shared_config()`/`write_shared_config()` from
`shared/mod.rs`. These are poison-safe and consistent.

### S7. `Config::clone()` into new `Arc<RwLock<>>` in `task.rs` (MEDIUM)

`src/tools/task.rs:391` — `Arc::new(RwLock::new(self.config.clone()))` copies
the entire Config struct per subagent instead of cloning the Arc reference.

**Fix:** Change to `self.config.clone()` to clone the Arc reference.
