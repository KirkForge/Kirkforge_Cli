# Workorder 20.1.0 — Agent Loop & Subagent Improvements

## Source

Cross-review §4.1 + internal audit findings.

## Problem

The agent loop is the core value path and the least-tested part of the codebase
(68.6% coverage, ADR-065). Several gaps reduce it from production-grade to
prototype-grade.

## Targets

### A1. Multi-turn subagent dialog (HIGH)

- `task` tool runs exactly one `run_turn_collecting` (`task.rs:419-422`)
- No multi-turn subagent dialog — the subagent gets one shot
- Claude Code, Codex CLI, opencode all support multi-turn subagents
- **Fix:** Add `max_turns` parameter to `task` tool. Subagent loops until
  `FinishReason::Stop` or `max_turns` reached. Stream partial results back to
  the parent.

### A2. Background task concurrency limit (HIGH)

- 20 `task(background=true)` = 20 concurrent executors, no semaphore
- Can exhaust API rate limits, token budgets, and system resources
- **Fix:** Add a `Semaphore` with configurable `max_concurrent_background`
  default (e.g., 4). Acquire permit before spawning; release on completion.

### A3. Doom-loop remediation (MEDIUM)

- `loop_.rs:99-111` detects doom loops (banner + metric) but doesn't act
- Burns tokens indefinitely in unattended runs
- **Fix:** After N consecutive tool-call-only turns with no user interaction,
  inject a system hint suggesting plan mode. After M turns, force `/compact`
  or pause with a warning. Configurable thresholds.

### A4. `FinishReason::Length` continuation (MEDIUM)

- `turn.rs:308-317` silently ends the turn on max-tokens
- Zero feedback to model or user
- **Fix:** When `FinishReason::Length`, inject a continuation message
  ("Your previous response was truncated. Continue from where you left off.")
  and re-prompt. At minimum, display a warning to the user.

### A5. `RetryTracker` dead code (LOW)

- `error_recovery.rs:380-417` — instantiated at `turn.rs:277` but `can_retry()`
  never called
- **Fix:** Remove `RetryTracker` or wire it up for actual retry logic.

### A6. Non-file tool durations always 0 (LOW)

- `turn.rs:991` records tool duration but non-file tools always show 0
- Can't profile slow tools
- **Fix:** Record wall-clock duration for all tool calls, not just file tools.

### A7. `tokio::time::timeout` over `ready` future is a no-op (LOW)

- `turn.rs:906-912` wraps a `ready` future with a timeout — it resolves
  immediately, making the timeout meaningless
- **Fix:** Remove the timeout or move it to the actual async operation.

### A8. `RouteMethod::Cached` never produced (LOW)

- `router.rs:83` — `Cached` variant exists but is never constructed
- **Fix:** Remove the variant or implement cache-based routing.

## Verification

- `task --max-turns 3` completes a 3-turn subagent dialog
- 20+ background tasks don't exhaust API rate limits
- Doom-loop detection triggers remediation after configured threshold
- `FinishReason::Length` produces a visible warning + continuation
- `cargo test --workspace` green
