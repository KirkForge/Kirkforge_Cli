# Workorder 20.10.0 — MCP Resources, Prompts & Sampling

## Source

Cross-review §4.3 (tools & MCP) + WO 20.0.10 (strategic direction).

## Problem

MCP currently only supports `tools/list` + `tools/call`. The protocol defines
resources, prompts, sampling, and roots — none of which are implemented. The
comment at `mcp_client/mod.rs:95` falsely claims "reading resources."

## Targets

### M1. Implement `resources/list` + `resources/read` (HIGH)

- Most MCP servers expose resources (files, data, configs) alongside tools
- Without this, servers like `mcp-server-filesystem` lose half their value
- **Fix:** Add `list_resources` and `read_resource` methods to `McpClient`.
  Wire into the session's tool resolution so the model can access resources.
  Add startup warning when a server advertises resources but we don't support
  them.

### M2. Implement `prompts/list` + `prompts/get` (MEDIUM)

- MCP prompts are reusable prompt templates provided by servers
- Useful for common workflows (code review, test generation, etc.)
- **Fix:** Add `list_prompts` and `get_prompt` methods. Display available
  prompts in the `/mcp` command output. Allow `/mcp-prompt <server> <name>`
  to inject a prompt into the conversation.

### M3. Implement `sampling/createMessage` (LOW)

- Allows MCP servers to request LLM completions from the host
- Useful for servers that need to reason about data
- **Fix:** Add `create_message` handler. Gate behind config flag
  `mcp_sampling_enabled`. Requires careful security consideration — servers
  should not be able to make unlimited LLM calls.

### M4. Fix MCP comment overclaim (LOW)

- `mcp_client/mod.rs:95-96` claims "reading resources" — not implemented
- **Fix:** Correct the comment to accurately reflect current capabilities.

### M5. Shell hooks cannot see `tool_result` content (MEDIUM)

- `hooks.rs:46-63` — hooks fire after the tool returns but cannot access
  the tool result content
- Plugin scripts admit this: `plugins/kf-budget/hooks/post-tool-bash.sh:19`
  emits a no-op JSON
- READMEs fictionally describe hook behavior that doesn't happen
- **Fix:** Pass `tool_result` content to hook environment variables. This is
  the minimum needed for post-tool hooks to be useful.

### M6. Post-turn hooks fire async after commit (LOW)

- `turn.rs:39-59` — hooks fire after the turn commits
- Observational only, can't affect the turn
- **Fix:** Document clearly that post-turn hooks are for logging/auditing, not
  for modifying behavior. If synchronous hooks are needed, implement a
  pre-turn hook that can veto.

### M7. Signature verification is OFF by default (LOW)

- Real minisign Ed25519 crypto exists (`kf-plugin-host/src/lib.rs:544-576`)
  but verification is off by default
- Zero signed plugins ship
- **Fix:** Document that signature verification is available but opt-in. Add
  `--verify-plugins` flag. Consider enabling by default after a bootstrap period.

## Verification

- MCP server advertising `resources` can list and read resources through
  KirkForge
- `/mcp` command shows available prompts
- `mcp_client/mod.rs` comment accurately reflects capabilities
- Post-tool hooks receive `tool_result` content in environment variables
- `cargo test --workspace` green
