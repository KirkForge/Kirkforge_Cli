# Workorder 20.3.0 — Sandbox & Security Hardening

## Source

Cross-review §4.5 + internal audit SSRF finding (WO 20.0.5 S1).

## Problem

Default non-Docker bash has no OS-level sandbox. Codex CLI ships seatbelt/landlock
by default. KirkForge is materially behind on sandbox hardening.

## Targets

### X1. Default sandbox is rlimits-only (HIGH)

- `src/session/executor/sandbox.rs` (41 lines) — `SandboxEnforcer` is
  `PathGuard` + `DenyList` + `ReadGate`. No OS isolation.
- `SandboxEnforcer` name overclaims — it's filesystem access control, not a
  sandbox
- Codex CLI ships seatbelt (macOS) / landlock (Linux) by default
- **Fix:** Add seccomp-bpf (Linux) or landlock as a `--harden` default.
  ADR-054 explicitly defers this for the static-binary story — document the
  trade-off and set a timeline.

### X2. No network egress control on default bash (HIGH)

- A model can `curl evil.com` freely in non-Docker mode
- Only Docker mode (`--network none`) blocks it
- **Fix:** Add `--no-network` flag that uses `unshare(CLONE_NEWNET)` on Linux
  or network-scope `sandbox-exec` on macOS. Default in `--harden` mode.

### X3. Missing sandbox config is a warning, not a refusal (MEDIUM)

- `warn_if_unsandboxed` (`access/mod.rs:542-556`) warns but doesn't refuse
- In production, a missing sandbox config should be a hard error or at least
  a prompt refusal
- **Fix:** In `--harden` mode, refuse to run without sandbox config. In
  default mode, keep the warning.

### X4. `host_resolves_to_internal_ip()` not wired (HIGH)

- `src/tools/web_fetch.rs:226` — complete SSRF defense function exists but is
  `#[allow(dead_code)]` and never called from the fetch path
- The comment says "this guard catches rebinding attacks" but the guard isn't
  active
- This is either dead code or a security gap
- **Fix:** Wire into the `web_fetch` request path, or delete and document that
  SSRF protection relies on resolve-and-pin-DNS only.

### X5. Diff-review-before-apply (MEDIUM)

- Claude Code shows a diff and asks y/n for every edit
- KirkForge relies on plan mode or post-hoc `/undo`
- **Fix:** Add `--confirm-edits` flag that shows a diff and requires approval
  before each `edit_file` or `write_file` application. Not default — but
  available for safety-critical workflows.

### X6. Token counting is `bytes/4` everywhere (LOW)

- Not a real tokenizer — ±30% drift on multi-byte content
- ADR-0005 calls this "heuristic, conservative"
- **Fix:** Integrate `tiktoken-rs` for Anthropic/OpenAI models, or call the
  Ollama token-count endpoint for Ollama models. Fall back to `bytes/4` only
  when no tokenizer is available.

## Verification

- `--harden` mode refuses to run without sandbox
- `--no-network` blocks `curl` in non-Docker mode
- `host_resolves_to_internal_ip()` is called in the production `web_fetch` path
- `--confirm-edits` shows diff and requires approval
- Token counting within 5% of actual token count for English text
