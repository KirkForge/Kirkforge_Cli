# Workorder 20.8.0 — CI & Release Hardening

## Source

Cross-review §4.9.

## Problem

CI is advisory on security advisories. Cosign signing is best-effort. Session
coverage is below the 75% target. No fuzzing exists for parsers that handle
untrusted input.

## Targets

### C1. Make `cargo audit` blocking on critical/RCE (HIGH)

- `.github/workflows/ci.yml:398` — `continue-on-error: true`
- A real RCE advisory would not fail CI
- This is the single worst CI smell
- **Fix:** Remove `continue-on-error`. Add `--deny warnings` or at minimum
  `--deny unmaintained` for critical severity. Keep advisory for low/info.

### C2. Make cosign signing blocking on release (MEDIUM)

- `.github/workflows/release.yml:223` — `continue-on-error`
- Releases can ship unsigned
- **Fix:** Remove `continue-on-error`. If cosign fails, the release fails.
  If cosign infrastructure is down, halt the release.

### C3. Raise `src/session` coverage above 75% (MEDIUM)

- Currently 68.6% (ADR-065 acknowledges the gap)
- The executor loop is the core value path and the least-tested part
- **Fix:** Target 75% coverage for `src/session/`. Focus on `executor/turn.rs`
  and `executor/loop_.rs`. Use `kf-testdoctor` to identify gaps.

### C4. Add fuzzing for parsers (MEDIUM)

- 4,752 tests but zero `cargo fuzz` targets
- NDJSON parser, SSE parser, minifier, and tool-arg parser all handle untrusted
  input
- **Fix:** Add fuzz targets for:
  - `adapters/ollama_ndjson.rs` (NDJSON parser)
  - `adapters/anthropic.rs` (SSE parser)
  - `shared/minify/` (minifier)
  - `tools/edit_file.rs` (diff/patch parser)
  - `session/plugin_tools/wrapper.rs` (JSON arg parser)
- Use `cargo fuzz` with `libfuzzer`. Start with 1M iterations per target.

### C5. Audit 47 `tracing::debug!` calls (LOW)

- AGENTS.md §5 says "no debug spam in committed code"
- 47 `tracing::debug!` calls in `src/` exceeds this rule
- **Fix:** Audit each. Convert to `tracing::trace!` for hot-path diagnostics,
  or remove entirely if the information is redundant with other telemetry.

### C6. TUI/daemon coverage gating (LOW)

- No coverage gating for TUI or daemon code
- Defensible given testing difficulty, but should be documented
- **Fix:** Add ADR documenting the coverage exclusion and the manual test plan
  for TUI/daemon paths.

## Verification

- `cargo audit` fails CI on critical advisories
- Cosign signing fails the release workflow on signing failure
- `src/session` coverage ≥ 75%
- At least 3 fuzz targets exist and run in CI
- `tracing::debug!` count in `src/` is under 20
