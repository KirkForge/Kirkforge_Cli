# Workorder 20.9.0 — Scope & Architecture: Cut, Collapse, Document

## Source

Cross-review §3 (scope creep) + §3.5 (over-decomposition) + review #3
(ownership boundaries).

## Problem

~43% of satellite-crate LOC is draw+video (34K LOC) with zero external users.
Over-decomposition (core/hosts/cli × 2) adds build complexity without value.
The workspace needs focus and clear ownership boundaries.

## Targets

### S1. Remove `kf-video` from default workspace (HIGH)

- 11,213 LOC, zero external users, broken default path (P0-1 env-var bug)
- No `brand.json` anywhere — even the author never used brand theming
- Already feature-gated (`video` feature, off by default)
- **Fix:** Remove from default workspace members in root `Cargo.toml`. Keep the
  crate in the repo for now, but it doesn't build by default. Fix P0-1 first
  so the shell fallback works if the feature is enabled.

### S2. Make `kf-draw` default-OFF (HIGH)

- 22,939 LOC (`kf-draw` + `kf-draw-core`), zero external users
- `.td.json` format has no external consumers
- Currently default-ON, pulling `unicode-segmentation` + `unicode-width` into
  every build
- **Fix:** Make `draw` a non-default feature. Remove from default workspace
  members. Document in TECHNICAL.md that it's incubating. Evaluate for spin-off
  after 2 months.

### S3. Collapse `kf-compress-hosts` into `kf-compress-core` (MEDIUM)

- 151 LOC — one function in a separate crate with its own build.rs, Cargo.toml,
  docs/, tests/
- The function filters a markdown file by `<!-- stratum:mode -->` directives
- **Fix:** Inline `filter_by_mode` into `kf-compress-core`. Delete the crate.
  Update workspace Cargo.toml and all imports.

### S4. Collapse `kf-budget-hosts` stubs (MEDIUM)

- 843 LOC, but Cursor/Aider/KfCode modules are "stub modules that document the
  intended shape when a future contributor adds a second host"
- Only Claude Code host is wired
- **Fix:** Remove stub modules. Keep only the wired host. Document multi-host
  intent in ADR if not already there.

### S5. Delete or fold standalone CLIs (LOW)

- `kf-budget-cli` (14K LOC) and `kf-compress-cli` (1.9K LOC) exist as second
  CLI binaries
- The core binary already folds the libraries in
- No evidence of external users
- **Fix:** Remove the `[[bin]]` entries. Keep the library crates. The core
  binary is the only entry point.

### S6. Reconcile `TECHNICAL.md` Stratum claims (MEDIUM)

- `TECHNICAL.md:383-389` claims "content-type-specific transforms with offload
  storage and query-based relevance filtering"
- Reality: `CompressionPipeline::new()` is empty in production
- **Fix:** Downgrade claims to "minify + head/tail truncation with bloat
  offload." Register real transforms or remove the pipeline (see WO 20.4.0
  R5).

### S7. Add crate ownership documentation (MEDIUM)

- Review #3 requested: for every crate, document Owner, Purpose, Public API,
  Dependencies, Consumers
- **Fix:** Add a `CRATE_MAP.md` to the repo root (or a section in
  `docs/TECHNICAL.md`) with a table:

  | Crate | Owner | Purpose | Public API | Deps | Consumers |
  |-------|-------|---------|------------|------|-----------|

  Populate from existing `Cargo.toml` metadata + manual review.

### S8. `SandboxEnforcer` naming overclaim (LOW)

- `src/session/executor/sandbox.rs:7` — name implies enforcement but it's
  `PathGuard` + `DenyList` + `ReadGate` (rlimits, no OS isolation)
- **Fix:** Rename to `PathGuardEnforcer` or add a `// ponytail:` comment.
  Covered in WO 20.0.9 S9.

## Verification

- `kf-draw` feature is off by default

- `TECHNICAL.md` Stratum claims match reality
- `CRATE_MAP.md` or equivalent exists with ownership for every crate
