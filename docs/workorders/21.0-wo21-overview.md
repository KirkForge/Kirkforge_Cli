reality-checked @ `a870571` on 2026-08-07) closed Phase 0 (~95% done: 8/9 Part-2
silent breakages fixed, `kf-compress-hosts` cut, bench de-rigged). What it left

The WO 20 series is **done** but exposed a process failure: items shipped
without explicit done/fail criteria, and deferral was used to hide incomplete
work (the owner is explicit that this is the thing to fix). WO 21 is the
close-out series: **every still-open review item becomes an item with explicit
success AND failure criteria, and no deferral is silent.**

## The global rule — explicit done/fail + defer-disclosure (the point of WO 21)

**Every item in every 21.* sub-workorder carries, verbatim:**

1. **ID** (`21.X-Rn`) + title.
2. **Reality check** — current state quoted from the review with `file:line`.
3. **Scope** — files that will be touched.
4. **Success criteria (done)** — concrete, testable, gate-referenced.
5. **Failure criteria (regression / not-done)** — what counts as not done or a
   regression. This is mandatory; an item without a failure condition is
   treated as not-specified.
6. **Estimate** (S/M/L) + dependency on another `21.X-Rn`.
7. **Defer note** — `none`, or `DEFER-21X-Rn — <reason>; tracked in
   PONYTAIL-DEBT.md`. **No silent deferral.** A deferral that is not disclosed
   inline with a reason + tracking ID is itself a failure condition.

This operationalizes AGENTS.md §6 / rule #8 ("Honesty over claim") and rule #9
("Doc-sync discipline") into a per-item contract. **Promulgation note:** this
defer-disclosure rule is intended to be folded into AGENTS.md §9 by the owner
as a tracked follow-up (a doc edit, not code) — it is stated here first so the
WO 21 series is self-enforcing regardless.

## Cross-cutting failure conditions (apply to the whole series)

- Any item whose reality-check citation is found stale (line moved, code
  changed) at implementation time MUST be re-verified against current HEAD and
  the `file:line` updated before the item is closed — per AGENTS.md #8.
- Any item closed "Done" without a pasted gate run + head SHA is a regression
  (AGENTS.md #4).
- Closing an item that required a TECHNICAL.md / ADR / state.md update without
  updating those in the same commit is a regression (AGENTS.md #9).

## Verification (whole series)

- Every still-open review item (PARTIAL / STILL TRUE / NEW findings) is
  represented by exactly one `21.X-Rn` item — no orphans, no duplicates (see
  the coverage check at the bottom of each sub-workorder).
- `docs/workorders/README.md` lists all 21.* files.
- Series is "Done" only when every item's success criteria are met AND its
  failure criteria are demonstrably not-triggered, evidenced by gate output on
  the closing commit.
