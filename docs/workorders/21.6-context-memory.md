# Workorder 21.6 — Context, Retrieval & Memory Gaps

## Status: Done

## Problem

The context subsystem has real tree-sitter indexing, real LSP, and (now-wired)
`Symbol.doc` TF-IDF signal. But four still-open gaps limit its
differentiation: LSP and the index aren't federated (call-graph resolution is
name-based and conflates same-named methods), memory never auto-populates (the
store stays empty unless hand-edited), token estimation is `chars/4` (no real
tokenizer), and the index rebuilds on every git commit with no incremental
path. The `compaction_use_llm` flag is a misnomer (heuristic, not LLM).

## Source

Review reality-check §4.4 + scorecard "Context/retrieval/compression 6.0" row.
FIXED items (Symbol.doc wired, P0-4 offload retrieval) excluded. Stratum
pipeline emptiness is 21.3; `compaction_use_llm` rename folds here.

## Targets

### 21.6-R1 — Federate LSP with the context index (HIGH · est L · dep: —)

**Reality check (`a870571`):** "LSP not federated with index — name-based
call-graph resolution (`lib.rs:860`) conflates same-named methods across
types; never asks a running rust-analyzer for ground truth."

**Scope:** `crates/kf-context-index/src/lib.rs:860` (call-graph resolution),
LSP pool integration (reuse the existing production-grade LSP client).

**Success (done):**
- Call-graph / definition resolution consults a running language server for
  ground truth (at least rust-analyzer for Rust) instead of pure name-matching;
  same-named methods across types are disambiguated.
- A test asserts a query resolves the correct method among same-named
  candidates (the conflation case the review names).

**Failure (regression / not-done):**
- Still name-based only = FAIL.
- LSP consulted but falls back to name-matching silently when LSP is slow/down
  without a `// ponytail:` note = FAIL (silent degradation).

**Defer:** DEFER-216-R1 — federation may be staged per-language (Rust first);
languages without a running LSP gracefully degrade to the index. Disclose the
staging with tracking IDs; do not claim federation for languages not wired.

### 21.6-R2 — Memory auto-populate (`remember` tool) (MEDIUM · est M · dep: —)

**Reality check (`a870571`):** "Memory never auto-populates — no tool/hook
writes facts; store stays empty unless hand-edited. The entire subsystem can
silently no-op."

**Scope:** new `remember` tool, system-prompt instruction, memory store write
path.

**Success (done):**
- A `remember` tool (or post-turn hook) writes facts to the persistent memory
  store; the system prompt instructs the model to use it after significant
  turns.
- A test asserts the store gains a fact after a qualifying turn (not empty
  unless hand-edited).

**Failure (not-done / regression):**
- Store still empty unless hand-edited = FAIL.
- Tool writes garbage / every turn (noise) with no relevance gate = FAIL.

**Defer:** none.

### 21.6-R3 — Real tokenizer for budget math (HIGH · est M · dep: —)

**Reality check (`a870571`):** "Token estimation is `chars/4` everywhere — no
real tokenizer (documented)." ADR-0005 calls it "heuristic, conservative";
±30% drift on multi-byte content. Feeds both context budget math (§4.4) and
sandbox/verification budget math (§4.5).

**Scope:** token-estimation call sites (budget cascade, prompt builder, cost
tracking), a tokenizer backend (`tiktoken-rs` and/or an ollama token-count
endpoint).

**Success (done):**
- A real tokenizer backs token estimates (per-model where possible; a sensible
  default fallback otherwise); the `chars/4` heuristic is replaced or demoted
  to a last-resort fallback with a `// ponytail:` note.
- A test asserts the estimate for a multi-byte sample is within a documented
  tolerance of the real count (not ±30%).

**Failure (regression / not-done):**
- Still `chars/4` in the budget cascade = FAIL.
- Tokenizer added but slow enough to dominate turn latency without memoization
  = FAIL.

**Defer:** DEFER-216-R3 — if the chosen backend adds unacceptable binary size
(release profile), a per-model server-side token-count (ollama/provider
endpoint) fallback is acceptable, disclosed with a tracking ID. Pure
`chars/4` retention is FAIL.

### 21.6-R4 — Incremental index rebuild (mtime path) (MEDIUM · est M · dep: —)

**Reality check (`a870571`):** "Index rebuilds on every git commit (HEAD-keyed
invalidation) — no incremental/mtime path. Slow on large repos."

**Scope:** `crates/kf-context-index` cache/invalidation path (use the existing
`CachedIndex` struct pattern per AGENTS.md §7; mtime + path-keyed
invalidation).

**Success (done):**
- The index rebuilds incrementally (only changed files since last build) keyed
  on mtime/path, not a full rebuild per commit.
- A test/benchmark asserts a no-op re-index (no changed files) is cheap, and a
  single-file change re-indexes only that file's symbols.

**Failure (not-done / regression):**
- Still full rebuild per commit = FAIL.
- Incremental path produces a stale/inconsistent index (missing new symbols) =
  FAIL.

**Defer:** none.

### 21.6-R5 — Rename `compaction_use_llm` (LOW · est S · dep: —)

**Reality check (`a870571`):** "`compaction_use_llm` is a misnomer — flag flows
to `deterministic_compaction_summary` (`microcompaction.rs:228`) which is
**heuristic keyword extraction** (`\"i'll \"`, `\"let me \"`, `\"plan:\"`),
no LLM call. STILL TRUE (moved to `config/session.rs:33-36`, self-documented)."

**Scope:** `config/session.rs:33-36`, `src/session/prompt/microcompaction.rs:228`,
all call sites, config docs.

**Success (done):**
- Flag renamed to `compaction_use_heuristic` (or equivalent) across config +
  call sites; the `config/session.rs:33-36` self-documenting comment updated.
- A spec-drift / config-key test pins the new name so it cannot silently
  revert.

**Failure (regression / not-done):**
- Still named `compaction_use_llm` = FAIL.
- Renamed but a config-file key changes without migration/back-compat = FAIL.

**Defer:** none.
