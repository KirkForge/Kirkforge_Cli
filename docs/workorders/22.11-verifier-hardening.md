# Workorder 22.11 — Verifier Hardening

## Status: Planned

## Problem

Verifiers can panic and crash the session; `Verdict::Skipped` is silent
(no CorrectionResult); `GitOperationEvent` is defined but never emitted
(dup of 22.5-R3).

## Source

Review Part 4 §4.7 (data-flow lies). WO 22.0 overview §22.11.

## Targets

### 22.11-R1 — Wrap verifier.verify() in catch_unwind (HIGH · est S · dep: —)

**Reality check:** Before the subagent fix, a panic in any verifier
(`rustfmt`, `build`, `security`, `lint`, `git`) would crash the entire
session. There was no panic boundary between verifier execution and the
correction loop.

**What was done (subagent):**
- `src/session/verifier/handler.rs:76-87` — The async path now wraps
  `verifier.verify(event)` in `AssertUnwindSafe(...).catch_unwind().await`.
  If the verifier panics, it returns `Verdict::Skipped("verifier panicked:
  <message>")` instead of crashing the session.
- `src/session/verifier/bus.rs:29,167` — The sync `BusVerifier` path also
  uses `catch_unwind(AssertUnwindSafe(|| verifier.verify(ctx)))`.

**Remaining:**
- Add a test: mock a verifier that panics, assert the handler returns
  `Verdict::Skipped` with a message containing "verifier panicked".
- Verify that the panic message is logged at `tracing::warn!` level.

**Scope:** `src/session/verifier/handler.rs`, `src/session/verifier/bus.rs`.

**Success criteria:**
- A panicking verifier returns `Verdict::Skipped("verifier panicked: ...")`
  instead of crashing the session.
- Panic message is logged via `tracing::warn!`.
- Test: mock verifier panic → assert `Verdict::Skipped` result.
- `cargo test -p kf-code verifier` green.

**Failure criteria:** Verifier panic crashes the session. No panic boundary.
No test.

**Estimate:** S (catch_unwind done; needs test)

**Defer note:** none.
