# Workorder 22.14 — JSON-Schema Structured Output

## Status: Planned

## Problem

There is no `response_format: { type: "json_object", schema: ... }` support in
any adapter. The current `json_mode: bool` flag only toggles unstructured JSON
mode — Ollama gets `"format": "json"`, OpenAI-compat gets
`response_format: { type: "json_object" }`, and Anthropic gets nothing (its
`json_mode` branch is an empty comment). None of these paths accept a JSON
schema to constrain the model's output shape.

This is a competitive gap vs Claude Code, Codex CLI, and opencode, all of
which can request structured JSON responses that conform to a schema. The
`ToolChoice::Specific` variant exists and is wired (WO 22.9-R1 closed that),
but structured output — constraining the *response format*, not the *tool
choice* — is orthogonal and missing.

## Source

WO 22.9-R2 (deferred), WO 20.0.8-G4, review Part 2 §2.3.

## Root cause

No `response_format` parameter with schema support exists in the adapter
layer. The `ModelAdapter` trait has `set_json_mode(bool)` — a binary flag
that cannot carry a schema. The `build_anthropic_body` and
`build_openai_compat_body` functions accept `json_mode: bool` but have no
schema parameter. Anthropic's `json_mode` branch (`anthropic.rs:326-331`) is
an empty block with a comment saying "callers are expected to use a system
prompt that asks for JSON."

## Plan

### R1 — Shared types and trait extension (est M · dep: —)

Add the `ResponseFormat` type and extend `ModelAdapter` + body builders to
carry structured output configuration.

**Files to touch:**

- `src/shared/mod.rs:199-205` — Add `ResponseFormat` enum alongside
  `ToolChoice`:

  ```rust
  #[derive(Debug, Clone, PartialEq, Serialize, Deserialize, Default)]
  #[serde(rename_all = "lowercase")]
  pub enum ResponseFormat {
      #[default]
      Text,
      JsonObject,
      JsonSchema {
          name: String,
          schema: serde_json::Value,
      },
  }
  ```

- `src/shared/config/model.rs:92` — Change `json_mode: bool` to a
  `response_format: ResponseFormat` field (default `Text`). Add `json_mode`
  as a deprecated accessor that returns `true` for `JsonObject` or
  `JsonSchema` variants (so existing config `json_mode = true` maps to
  `ResponseFormat::JsonObject` via a `#[serde(deserialize_with)]` adapter
  or manual `Deserialize` impl that reads the old bool form).

- `src/adapters/mod.rs:322-360` — Extend `ModelAdapter` trait:
  - Change `set_json_mode(&mut self, bool)` to
    `set_response_format(&mut self, ResponseFormat)`. Default impl becomes a
    no-op (same as before, preserving backward compat for adapters that
    don't override).
  - Keep `set_json_mode` as a deprecated adapter method that calls
    `set_response_format(ResponseFormat::JsonObject)` for one release cycle,
    then remove.

- `src/adapters/mod.rs:528-637` — `build_ollama_chat_body`: add
  `response_format: Option<&ResponseFormat>` parameter (replacing `json_mode:
  bool`). When `JsonSchema`, emit `"format": {"type": "object", "properties":
  ...}` (Ollama's native schema-constrained mode). When `JsonObject`, emit
  `"format": "json"` (current behavior). When `Text`, omit.

- `src/adapters/mod.rs:651-797` — `build_openai_compat_body`: add
  `response_format: Option<&ResponseFormat>` parameter (replacing `json_mode:
  bool`). When `JsonSchema`, emit
  `response_format: { type: "json_schema", json_schema: { name, schema } }`.
  When `JsonObject`, emit current `response_format: { type: "json_object" }`.
  When `Text`, omit.

- `src/adapters/anthropic.rs:151-340` — `build_anthropic_body`: add
  `response_format: Option<&ResponseFormat>` parameter. When `JsonSchema`,
  implement the Anthropic tool-use trick: inject a synthetic tool named
  `respond_with_schema` whose `input_schema` is the requested schema, and set
  `tool_choice: { type: "tool", name: "respond_with_schema" }`. When
  `JsonObject`, inject a system-prefill instruction (current empty-block
  behavior becomes a real instruction). When `Text`, no action.

- `src/adapters/oellama.rs` — `OellamaAdapter`: update `stream()` to pass
  `response_format` through to `build_ollama_chat_body`.

- `src/adapters/anthropic_bedrock.rs` — `AnthropicBedrockAdapter`: add
  `response_format` field, implement `set_response_format`, pass to
  `build_anthropic_body`.

- `src/adapters/anthropic_vertex.rs` — `AnthropicVertexAdapter`: same as
  Bedrock.

- `src/adapters/openai_compat/mod.rs` — `OpenAiCompatAdapter`: add
  `response_format` field, implement `set_response_format`, pass to
  `build_openai_compat_body`.

- `src/adapters/caching.rs` — `CachingAdapter`: add `response_format` field,
  implement `set_response_format`, propagate to inner adapter, include in
  cache key (replace `json_mode: bool` in `CacheKey`).

- `src/session/executor/mod.rs:191` — Change `adapter.set_json_mode(...)` to
  `adapter.set_response_format(cfg.model.response_format.clone())`.

- `src/session/executor/mod.rs:418` — Same for hot-reload path.

- `src/session/config/mod.rs:347-348` — Update TOML deserialization for the
  new `response_format` field. Accept both old `json_mode = true` (maps to
  `ResponseFormat::JsonObject`) and new `response_format = { type =
  "json_schema", name = "...", schema = {...} }`.

- `src/session/config/env_overrides.rs:136` — Update `KF_CODE_JSON_MODE` env
  var to map to `ResponseFormat::JsonObject`, or add a separate
  `KF_CODE_RESPONSE_FORMAT` env var.

- **Tests** in `src/adapters/mod.rs`, `src/adapters/anthropic.rs`,
  `src/adapters/m5_tests.rs`, `src/adapters/caching.rs` — Update all tests
  that pass `json_mode: bool` to use `ResponseFormat` variants. Add new
  tests:
  - `build_openai_compat_body` with `JsonSchema` emits
    `response_format.json_schema`.
  - `build_anthropic_body` with `JsonSchema` emits synthetic tool + forced
    tool_choice.
  - `build_ollama_chat_body` with `JsonSchema` emits structured `format`
    object.
  - Backward compat: `json_mode = true` in TOML maps to `JsonObject`.

**Success criteria:**
- `ModelAdapter::set_response_format(ResponseFormat)` exists and is wired.
- `ResponseFormat` enum has `Text`, `JsonObject`, `JsonSchema` variants.
- Old `json_mode = true` config still works (maps to `JsonObject`).
- All three body builders emit provider-correct structured output fields.
- `cargo test --workspace` green.

**Failure criteria:** Structured output requests are silently ignored. Old
`json_mode` config breaks. Anthropic `JsonSchema` doesn't force tool use.

**Estimate:** M

### R2 — Executor and config integration (est M · dep: R1)

Wire the new `ResponseFormat` through the executor so that per-request
structured output can be requested, not just global config.

**Files to touch:**

- `src/session/executor/mod.rs` — Add `request_response_format:
  Option<ResponseFormat>` field to the executor's turn state. When set, it
  overrides the config's `response_format` for that turn (e.g. a structured
  extraction step can request `JsonSchema` even when config is `Text`).

- `src/shared/config/model.rs` — Add `response_format` to TOML config schema
  so users can set:
  ```toml
  [model]
  response_format = { type = "json_schema", name = "extraction", schema = { type = "object", properties = { ... } } }
  ```

- `src/session/config/mod.rs` — Wire TOML `response_format` parsing. Support
  string shorthand `"json_object"` and full object form.

- `src/session/config/env_overrides.rs` — Add `KF_CODE_RESPONSE_FORMAT` env
  var (JSON string, parsed into `ResponseFormat`).

- **Tests:**
  - Config TOML round-trips `ResponseFormat::JsonObject` and
    `ResponseFormat::JsonSchema`.
  - Per-request override takes precedence over config default.
  - `cargo test --workspace` green.

**Success criteria:**
- Config can specify `response_format` in TOML.
- Executor passes `ResponseFormat` to adapter on each turn.
- Per-request override works (future: agent loop can request schema per turn).

**Failure criteria:** Config parsing fails. Executor ignores the new field.

**Estimate:** M

### R3 — ADR and documentation (est S · dep: R1)

Document the structured output decision, provider support matrix, and
fallback behavior.

**Files to touch:**

- `docs/adr/071-structured-output.md` — ADR documenting:
  - Decision: `ResponseFormat` enum with `Text`/`JsonObject`/`JsonSchema`.
  - Provider support: OpenAI has native `json_schema`; Anthropic uses
    tool-use trick; Ollama has `format: {type: "object", properties}`.
  - Fallback: providers that don't support `JsonSchema` silently degrade to
    `JsonObject` (or `Text` with a system-prompt instruction for providers
    that don't support any JSON mode).
  - Backward compat: `json_mode = true` maps to `ResponseFormat::JsonObject`.

- `docs/adr/README.md` — Add ADR-071 to the index table.

- `docs/TECHNICAL.md` — Add `ResponseFormat` to the adapter feature table
  (if one exists) or the model capabilities section.

**Success criteria:**
- ADR-071 exists with provider matrix and fallback spec.
- `adr_xref_drift` test passes (status + README index match).
- TECHNICAL.md reflects the new capability.

**Failure criteria:** Missing ADR. ADR drift test fails.

**Estimate:** S
