### 22.7-R2 — Collapse `ToolChoice::Specific` + `set_tool_choice` (HIGH · est S · dep: —)

**Reality check:** `src/shared/mod.rs:201` — `ToolChoice` enum has `Auto` and
`Specific(String)` variants. `set_tool_choice` on adapters sets the tool
choice parameter. After the subagent review, this was examined but the current
codebase still uses `ToolChoice::Specific` in adapters
(`adapters/anthropic.rs:317-320`, `adapters/mod.rs:777-780`,
`adapters/openai_compat/mod.rs:431`).

**What was done (subagent):** `ToolChoice::Specific` was examined. The enum
is actively used by the Bedrock, Vertex, and OpenAI-compatible adapters to
force specific tool calls. It is NOT dead code — it's wired into adapter
routing.

**Remaining:**
- `ToolChoice::Specific` is actually used. Do NOT delete it. This item is
  CLOSED as "not over-engineering" — the variant serves a real purpose.
- `set_tool_choice` is a trait method with a default no-op impl. This is fine
  for adapters that don't support tool choice forcing.

**Scope:** No changes needed.

**Success criteria:**
- `ToolChoice::Specific` remains in production code.
- No dead `set_tool_choice` code.

**Failure criteria:** Deleting `ToolChoice::Specific` would break adapter
routing for forced tool calls.

**Estimate:** S (item closed — not over-engineering)

**Defer note:** none. Item was reviewed and determined to be correctly
engineered, not over-engineering.

### 22.7-R5 — Delete `CompactionTransform` trait (MEDIUM · est S · dep: —)

  from the public API.

  references `CompactionTransform`.

**Scope:** `crates/kf-budget-core/src/compaction.rs`,
`crates/kf-budget-core/src/lib.rs`,
`crates/kf-budget-core/tests/output_split_spec_drift.rs`.

**Success criteria:**

- `output_split_spec_drift` test updated.

**Estimate:** S
