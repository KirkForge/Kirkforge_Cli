# Workorder 23.2 — Decompose AppState (~63 Fields) into Sub-Structs

## Status: Planned

## Problem

`AppState` in `src/tui/app.rs:214-540` has ~63 fields spanning 7+ concerns: conversation, input, connection, rendering, cost, search, approval, budget, doom-loop, tab, session, plugin, and UI state. Every key handler and event dispatcher takes `&mut AppState` — the struct is effectively a god object. Adding new state requires touching every construction site and every test that builds an `AppState`.

The review calls this out explicitly (§4.6: "AppState ~63 fields") and recommends extraction into sub-structs.

## Source

Review #20 (Phase 2). `src/tui/app.rs:214-540` — 63 fields, single struct.

## Scope

1. `src/tui/app.rs` — extract sub-structs, update `AppState` to contain them, update all construction sites
2. `src/tui/events.rs` — update `dispatch_turn_event` and `drain_*` functions
3. `src/tui/mod.rs` — update `handle_mouse`, key dispatch, render calls
4. `src/tui/keys/` — update key handlers that access `AppState` fields
5. `src/tui/widgets/` — update widget renderers
6. `src/tui/commands/` — update slash commands
7. `src/main/run_session.rs` — update `AppState` construction

**Success criteria:**
