# Workorder 23.5 — Add `remember` Tool + System-Prompt Instruction for Memory Auto-Populate

## Problem

Memory auto-population (`src/session/memory/extract.rs`) is a heuristic keyword extractor that runs every N turns. It has no explicit interface for the model to store facts deliberately. The model cannot say "remember that the user prefers X" — it relies on the heuristic detecting it, which is fragile and noisy (review §4.4: "memory is still heuristic keyword matching, no dedup").

A `remember` tool gives the model an explicit, reliable way to store facts, and a system-prompt instruction tells the model when and how to use it. This makes memory a first-class feature instead of an implicit side effect.

## Source

Review #25 (Phase 3). `src/session/memory/extract.rs:1-393` — heuristic extraction with `MAX_FACTS_PER_TURN=3`. `src/session/memory/mod.rs` — `MemoryStore` with `upsert`/`query`. Review §4.4: "memory is still heuristic keyword matching, no dedup."

## Scope

1. `src/tools/` — new `remember.rs` tool
2. `src/tools/mod.rs` — register `remember` in the toolset
3. `src/session/memory/mod.rs` — expose `store`/`store_fact` for the tool to call
4. `src/session/prompt/mod.rs` — add system-prompt instruction for memory
5. `src/shared/config/` — add `memory_auto_populate` config flag (carried from WO 22.4-R3, not yet shipped)
6. `docs/TECHNICAL.md` — document the `remember` tool

## Targets

### 23.5-R1 — Add `remember` tool (est M)

**Reality check:** `MemoryStore` in `src/session/memory/mod.rs` already has `upsert` and `query`. The tool just needs to call `store.upsert(fact)` and return a confirmation.

**Plan:**
- Create `src/tools/remember.rs` with a `Remember` tool struct
- Schema: `{ "fact": string, "category?": string }`
- The tool calls `MemoryStore::upsert` with the fact, auto-generating a slug from the fact content
- Returns `ToolOutcome::Success` with confirmation: "Remembered: <fact>"
- Register in `src/tools/mod.rs` in the default toolset
- The tool is always available (not gated by config) — explicit memory is different from auto-populate

**Success criteria:**
- `remember` tool appears in the model's tool list
- Calling `remember({ "fact": "User prefers tabs over spaces" })` stores the fact in `MemoryStore`
- Subsequent `retrieve_hybrid` returns the stored fact
- Duplicate facts are idempotent (same slug = upsert, not duplicate entries)
- Tool returns clear confirmation message

**Failure criteria:** Tool not in tool list. Fact not stored. Duplicate facts created.

**Estimate:** M

### 23.5-R2 — Add system-prompt instruction for memory (est S)

**Reality check:** The system prompt at `src/session/prompt/mod.rs:408` includes context from `retrieve_hybrid`. It does not include instructions for when/how to use memory.

**Plan:**
- Add a memory instruction block to the system prompt (after the tool list, before the context):
  ```
  You have a `remember` tool to store important facts about the user's preferences, project conventions, and recurring patterns. Use it when the user explicitly states a preference or when you observe a pattern worth remembering. Stored facts are available in future sessions.
  ```
- The instruction is short (3-4 lines) and model-agnostic
- Auto-populate extraction continues independently (gated by `memory_auto_populate` config when that ships from WO 22.4-R3)

**Success criteria:**
- System prompt includes memory instruction
- Instruction does not change the model's behavior for non-memory tasks
- Instruction is visible in `/system` command output (or equivalent debug view)

**Failure criteria:** Instruction causes model to over-remember (storing chaff). Instruction is too long (>50 tokens added).

**Estimate:** S

### 23.5-R3 — Add `memory_auto_populate` config flag (est S, carried from WO 22.4-R3)

**Reality check:** WO 22.4-R3 specified a `memory_auto_populate: bool` config flag defaulting to `true`. This was listed as "remaining" but never shipped.

**Plan:**
- Add `memory_auto_populate: bool` to `DisplayConfig` (or `ToolConfig`) defaulting to `true`
- Gate `extract_facts` in `turn.rs` on this flag
- Document in `docs/TECHNICAL.md`

**Success criteria:**
- `memory_auto_populate = false` disables auto-extraction (no `extract_facts` call)
- `memory_auto_populate = true` (default) preserves current behavior
- Documented in TECHNICAL.md

**Failure criteria:** Flag exists but doesn't gate extraction. Not documented.

**Estimate:** S

**SHIPPED:** R3 committed — `memory_auto_populate: bool` on DisplayConfig, gates extract_facts in turn.rs, env override KF_CODE_MEMORY_AUTO_POPULATE.
