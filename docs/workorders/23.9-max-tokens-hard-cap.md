# Workorder 23.9 — Max-Tokens Continuation Hard Cap

## Problem

When `FinishReason::Length` is returned (model hit max tokens), the executor at `src/session/executor/turn.rs:351-373` injects a continuation message and loops. This is correct for genuine continuations, but there's no hard cap on how many continuation rounds can occur. A model that consistently hits `max_tokens` will loop indefinitely, burning tokens and cost.

The review notes: "`FinishReason::Length` handled but no hard cap — turn emits truncation warning + continuation prompt, but no hard token cap" (§4.1).

## Source

Review #30 (Phase 3). `src/session/executor/turn.rs:351-373` — continuation loop with no hard cap. `src/session/executor/turn.rs:489` — `FinishReason::Length` also used for tool-call loop limit. Review §4.1: "max-tokens continuation exists but has no hard cap."

## Scope

1. `src/session/executor/turn.rs` — add continuation counter and hard cap
2. `src/shared/config/` — add `max_continuation_rounds` config field
3. `src/session/executor/types.rs` — add `TurnEvent::ContinuationLimitReached`
4. `docs/TECHNICAL.md` — document the hard cap

## Targets

### 23.9-R1 — Add hard cap on `FinishReason::Length` continuation rounds (est S)

**Reality check:** `turn.rs:351-373` handles `FinishReason::Length` by appending a continuation message and `continue`-ing the loop. The outer loop at `turn.rs:326` iterates `0..max_iterations` where `max_iterations = max_tool_calls_per_turn`. Each continuation round consumes one iteration of this loop, so there IS an implicit cap: `max_tool_calls_per_turn` (default varies but typically 20-50). However, this is an accidental cap, not an intentional one — it was designed for tool calls, not token continuations.

**Plan:**
- Add a `continuation_count: usize` counter in `run_turn_inner`, initialized to 0
- On `FinishReason::Length`, increment `continuation_count`
- If `continuation_count >= max_continuation_rounds` (default: 5), break the loop with a clear message instead of continuing
- Emit `TurnEvent::Error("Max continuation rounds reached (5). The response was truncated and could not be completed within the allowed rounds.")`
- The counter resets for each new user turn (it's local to `run_turn_inner`)

**Success criteria:**
- After 5 (default) consecutive `FinishReason::Length` responses, the turn ends with a clear error message
- `max_continuation_rounds = 0` disables continuation entirely (treat `Length` as `Stop`)
- `max_continuation_rounds = 100` effectively removes the cap (matches current behavior)
- Default 5 allows genuine multi-part responses while capping pathological loops
- Existing continuation behavior for 1-4 rounds is unchanged

**Failure criteria:** Cap fires on non-Length iterations (tool calls). Cap fires too early (< 5). Error message not surfaced to user.

**Estimate:** S

### 23.9-R2 — Make `max_continuation_rounds` configurable (est S)

**Reality check:** The implicit cap (`max_tool_calls_per_turn`) is already configurable. The new explicit cap should also be configurable.

**Plan:**
- Add `max_continuation_rounds: usize` to `Config` under `[executor]` section, default `5`
- Clamp to `0..=50` (0 = disable continuation, 50 = effectively unlimited)
- Add `KF_CODE_MAX_CONTINUATION_ROUNDS` env override
- Thread the value through to `run_turn_inner`

**Success criteria:**
- `max_continuation_rounds = 5` (default) — no behavioral change
- `max_continuation_rounds = 0` — `FinishReason::Length` treated as `Stop`
- `max_continuation_rounds = 1` — exactly one continuation allowed
- Env override works

**Failure criteria:** Default behavior changes. Config value ignored.

**Estimate:** S

### 23.9-R3 — Surface continuation count in TUI status (est S, deferrable)

**Reality check:** The TUI status bar shows token counts and cost but not continuation state. When a response is being continued (3rd or 4th continuation round), the user has no visibility.

**Plan:**
- Add `TurnEvent::ContinuationRound { round, max }` event emitted when a continuation starts
- TUI shows `⟳ 3/5` in the status bar during continuation rounds
- Reset the indicator when the turn completes normally

**Success criteria:**
- Status bar shows continuation round count during `FinishReason::Length` loops
- Indicator resets when turn completes

**Failure criteria:** Indicator persists after turn ends. Status bar layout broken.

**Estimate:** S

**Defer note:** R3 is UX polish — the hard cap (R1+R2) is the correctness fix. The status indicator can be deferred.
