# Workorder 24.0 — WO 24 Series Overview: Trust & Hardening

## Status: Planned

## Problem

The review (Part 6 §Phase 4) identifies 8 trust-and-hardening items that close the gap between "works in dev" and "safe in production." The core agent loop is solid; the verifier moat is real; the remaining issues are: audit isn't blocking, release signing isn't enforced, sandbox config isn't mandatory in production, token math still has `/4` heuristics outside budget state, there's no diff-review-before-apply, session coverage is below 75%, fuzz harnesses don't cover SSE/minifier, and ~23 `tracing::debug!` calls violate AGENTS.md §5.

## Source

Code review roadmap — Part 6, Phase 4 (#31–#38). Review re-verified @ 2026-08-08.

## Ordering / dependencies

1. **24.1 + 24.2** are CI/release hardening — independent, can start immediately.
2. **24.3** (sandbox refusal) depends on 22.1 (landlock) being confirmed working — refuse unsandboxed only makes sense if landlock actually confines.
3. **24.4** (tokenizer) is self-contained; the `/4` sites are in compaction, microcompaction, prompt, memory, carryover, events, and budget.
4. **24.5** (diff-review) is the largest item; can start in parallel.
5. **24.6** (coverage) is ongoing; start with executor loop tests.
6. **24.7** (fuzzing) is self-contained.
7. **24.8** (debug audit) is quick and self-contained.
