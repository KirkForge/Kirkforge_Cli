# Workorder 24.1 — Make `cargo audit` Blocking on Critical/RCE Advisories

## Status: Planned

## Problem

The CI workflow runs `cargo audit --deny warnings --deny unmaintained --deny unsound` (`.github/workflows/ci.yml:245`), but this blocks on *any* advisory severity including low-information ones. There is no distinction between a low-severity advisory and a critical RCE. The review (#31) asks for blocking on critical/RCE at minimum, with lower severities as non-blocking warnings.

Currently the audit step is all-or-nothing: `--deny warnings` treats every advisory as fatal, which can block CI on noisy or low-impact findings that have no real exploit path. The correct posture is: block on critical and high-severity (especially RCE), warn on the rest.

## Root cause

`ci.yml:245` uses `--deny warnings` which denies *all* advisory severities equally. There is no severity-based gate. A low-severity advisory in a dev-only dependency can block the entire pipeline.

## Scope

1. `.github/workflows/ci.yml` — split the audit step into critical/RCE blocking + advisory warning
2. `scripts/ci_local.sh` — mirror the same split
3. `AGENTS.md` §4 — update gate command to reflect the new audit posture

## Plan

### 24.1-R1 — Split `cargo audit` into blocking (critical/RCE) + warning (everything else)

- Replace `cargo audit --deny warnings --deny unmaintained --deny unsound` with two steps:
  1. `cargo audit --deny critical --deny unsound` (blocks on critical/high/RCE + unsound)
  2. `cargo audit` (runs after; non-blocking — outputs warnings for informational advisories)
- Alternatively, use `cargo audit --deny warnings --deny unmaintained --deny unsound` with an advisory ignore-list for known low-severity items, but that requires ongoing maintenance.
- **Preferred approach:** Use `cargo audit` with `--deny critical --deny unsound` (the `critical` category covers RCE and high-severity). The `warnings` and `unmaintained` categories become non-blocking.
- Add a comment explaining the posture.
- Mirror the same logic in `scripts/ci_local.sh`.

**Success criteria:**
- CI fails on critical/RCE/unsound advisories.
- CI succeeds with warnings-only advisories (low, medium, informational).
- `scripts/ci_local.sh` reproduces the same gate.
- `AGENTS.md` §4 gate section updated.

**Failure criteria:** CI still blocks on low-severity advisories. CI doesn't block on critical/RCE.
