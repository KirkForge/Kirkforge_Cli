# Workorder 24.4 — Complete BPE Tokenizer Coverage (Eliminate `/4` Heuristics)

## Problem

The review (#34) identifies that `kf_budget_core::estimate_tokens` uses real BPE (tiktoken cl100k_base, `budget.rs:184-200`), but multiple call sites still use `len()/4` or `estimate_tokens_heuristic` instead of the real BPE path. The `count_tokens` function in `prompt/mod.rs:20-27` has a `not(budget)` feature gate that falls back to `s.len() / 4`. The TUI events module has its own `estimate_messages_tokens` that hardcodes `len()/4` (`events.rs:319-325`). The compaction and microcompaction modules have local `estimate_tokens` that route through `count_tokens` but with their own heuristic paths.

The budget state uses BPE consistently, but ~8 files still have `/4` fallbacks:
- `src/session/prompt/mod.rs:26` — `not(budget)` fallback: `s.len() / 4`
- `src/tui/events.rs:319-325` — `estimate_messages_tokens` with `len() / 4`
- `src/session/prompt/compaction.rs:156,662,689` — local `estimate_tokens` (routes through `count_tokens`, but has `/4` in test assertions)
- `src/session/prompt/microcompaction.rs:620` — local estimate
- `src/session/budget.rs:756` — routes through `count_tokens`
- `src/session/carryover.rs:101` — routes through `count_tokens`
- `src/session/memory/mod.rs:208-209` — routes through `count_tokens`
- `src/session/prompt/mod.rs:279,299,300` — tool-call token estimation

The `estimate_tokens_heuristic` function (`budget.rs:206-214`) is still `pub` and available for callers that want the cheap path.

## Root cause

`prompt/mod.rs:24-27` has a `#[cfg(not(feature = "budget"))]` fallback that returns `s.len() / 4`. The `budget` feature is enabled by default in the binary, so this path is dead in release builds — but it exists and could be activated in feature-flag combinations. The TUI events module deliberately uses its own `len()/4` estimator (documented as a ponytail), which means TUI token estimates diverge from the canonical BPE path.

## Scope

1. `src/session/prompt/mod.rs` — remove `not(budget)` fallback; always use BPE
2. `src/tui/events.rs` — replace `estimate_messages_tokens` with BPE-based estimation
3. `crates/kf-budget-core/src/budget.rs` — consider making `estimate_tokens_heuristic` `pub(crate)` or deprecating it
4. `src/session/prompt/compaction.rs` — update test assertions that assert `/4` behavior
5. `src/session/prompt/microcompaction.rs` — verify routing through BPE
6. `src/session/budget.rs:756` — verify routing
7. `src/session/carryover.rs:101` — verify routing
8. `src/session/memory/mod.rs:208-209` — verify routing
9. `src/session/prompt/mod.rs:279,299,300` — tool-call token estimation

## Plan

### 24.4-R1 — Remove `not(budget)` fallback from `count_tokens`

- Delete the `#[cfg(not(feature = "budget"))]` arm in `prompt/mod.rs:24-27`.
- Make `count_tokens` always call `kf_budget_core::estimate_tokens`.
- If the `budget` feature is disabled, this is a compile error — which is correct, because the binary always enables it.
- Update any test assertions that depend on `/4` heuristic behavior.

**Success criteria:**
- `count_tokens` has exactly one implementation: BPE via `kf_budget_core::estimate_tokens`.
- No `s.len() / 4` in production token estimation paths.
- All tests pass.

**Failure criteria:** Any production path still uses `len()/4` for token estimation.

**Estimate:** S

**Defer note:** none.

### 24.4-R2 — Replace TUI `estimate_messages_tokens` with BPE

- `tui/events.rs:296-329` has its own `estimate_messages_tokens` that uses `len()/4` for content and `json.len()/4` for tool calls.
- Replace with a call to `kf_budget_core::estimate_tokens` for content, and real BPE for tool-call JSON.
- The ponytail comment (`bytes/4 is not a tokenizer`) goes away.
- The function signature stays the same (takes `&[Message]`, returns `usize`).

**Success criteria:**
- TUI token estimates match budget-state estimates to within ±2 tokens.
- No `len()/4` in TUI token estimation.
- `cargo test -p kf-code tui::events` green.

**Failure criteria:** TUI still uses `len()/4`.

**Estimate:** M

**Defer note:** none.

### 24.4-R3 — Deprecate `estimate_tokens_heuristic`

- Make `estimate_tokens_heuristic` in `budget.rs:206-214` `#[deprecated]` with a message pointing to `estimate_tokens`.
- Add `#[allow(deprecated)]` on any call sites that still use it (compaction test assertions).
- Goal: no new call sites should use the heuristic.

**Success criteria:** `estimate_tokens_heuristic` is deprecated; all new code uses `estimate_tokens`.

**Failure criteria:** Heuristic is still `pub` without deprecation warning.

**Estimate:** S

**Defer note:** Low priority. The heuristic is still useful for call sites that explicitly want cheap estimation without BPE overhead. Deprecation signals intent; removal can happen later.
