# Workorder 24.7 — Add Fuzzing for NDJSON/SSE/Minifier Parsers

## Problem

The review (#37) identifies that the existing fuzz harnesses (`fuzz/fuzz_targets/`) cover `minify_rust`, `minify_revalidate`, `ndjson_parse`, `config_parser`, and `deny_list` — but do not cover SSE framing (used by OpenAI-compat, Anthropic, Bedrock, and Ollama adapters) or the minifier's edge-case paths (JS/CSS minifier, expand/revalidate paths).

SSE framing (`adapters/openai_compat/`) and the minifier (`shared/minify/`) parse untrusted external input (network streams, file content). A bug in the SSE parser could cause a panic or infinite loop on malformed input from a malicious or buggy LLM provider. A bug in the minifier could corrupt code or panic on edge-case syntax.

The NDJSON harness (`ndjson_parse.rs`) tests `parse_ndjson_lines` with `OllamaNdjsonConfig::GLM`, but not with other configs or with the Anthropic Bedrock event-stream parser (`parse_bedrock_event_stream`).

## Root cause

`fuzz/Cargo.toml` lists 5 fuzz targets. None cover SSE framing, Bedrock event-stream parsing, or JS/CSS minification. The minifier has ~12 language backends (`shared/minify/`), but only `minify_rust` and `minify_revalidate` are fuzzed.

## Scope

1. `fuzz/fuzz_targets/` — add new fuzz targets
2. `fuzz/Cargo.toml` — register new targets
3. `src/adapters/openai_compat/` — SSE parser (source of input for fuzzing)
4. `src/adapters/anthropic_bedrock.rs` — Bedrock event-stream parser
5. `src/shared/minify/` — JS/CSS minifier backends

## Plan

### 24.7-R1 — Add SSE framing fuzz target

- Create `fuzz/fuzz_targets/sse_parse.rs` that fuzzes the SSE frame parser from `openai_compat`.
- The harness should feed arbitrary byte sequences into the SSE parser and confirm it doesn't panic or loop.
- Target: the `parse_sse_line` / event-stream framing functions that split `\n\n`-delimited SSE frames.
- Register in `fuzz/Cargo.toml`.

**Success criteria:**
- New fuzz target `sse_parse` exists and compiles.
- `cargo fuzz build --release --target sse_parse` succeeds.
- Manual fuzz run (`cargo fuzz run sse_parse`) completes 1000 iterations without panic.

**Failure criteria:** Fuzz target doesn't compile. SSE parser panics on valid fuzz input.

**Estimate:** M

**Defer note:** none.

### 24.7-R2 — Add Bedrock event-stream fuzz target

- Create `fuzz/fuzz_targets/bedrock_event_stream.rs` that fuzzes `parse_bedrock_event_stream`.
- The Bedrock event-stream format is AWS's binary framing (headers + payload). Feed arbitrary byte sequences.
- This is more complex than SSE because the parser handles binary framing with CRC checks.
- Register in `fuzz/Cargo.toml`.

**Success criteria:**
- New fuzz target `bedrock_event_stream` exists and compiles.
- Fuzz run completes 1000 iterations without panic.

**Failure criteria:** Fuzz target doesn't compile. Parser panics on valid fuzz input.

**Estimate:** M

**Defer note:** Can be deferred if R1 is sufficient for the SSE/NDJSON path. Bedrock is used less than OpenAI-compat.

### 24.7-R3 — Add JS/CSS minifier fuzz targets

- Create `fuzz/fuzz_targets/minify_js.rs` that fuzzes `minify_content` with `Language::JavaScript`.
- Create `fuzz/fuzz_targets/minify_css.rs` that fuzzes `minify_content` with `Language::Css`.
- The minifier uses tree-sitter grammars; fuzzing confirms it doesn't panic on malformed JS/CSS input.
- Register both in `fuzz/Cargo.toml`.

**Success criteria:**
- New fuzz targets `minify_js` and `minify_css` exist and compile.
- Fuzz run completes 1000 iterations each without panic.

**Failure criteria:** Minifier panics on valid fuzz input.

**Estimate:** S

**Defer note:** none.

### 24.7-R4 — Add NDJSON config variant fuzz target

- Extend or create a fuzz target that tests `parse_ndjson_lines` with all available `OllamaNdjsonConfig` variants (not just `GLM`).
- If there's only one config, add a variant that tests the Anthropic/Bedrock NDJSON path if applicable.

**Success criteria:** Fuzz target covers all NDJSON config variants.

**Failure criteria:** Only GLM config is tested.

**Estimate:** S

**Defer note:** none.

## Verification

- `cargo fuzz build --release` compiles all fuzz targets (including new ones).
- `cargo fuzz list` shows all targets including new ones.
- Manual: `cargo fuzz run <target> -- -max_total_time=60` for each new target, no panics.
- `cargo clippy --all-targets -- -D warnings` green (fuzz targets are not in the main workspace, so this is a separate check).
