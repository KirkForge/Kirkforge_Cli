# Workorder 25.0 — WO 25 Series Overview: Test Infrastructure Optimization

## Status: Planned

## Problem

The test suite has grown to ~3000+ tests in `kf-code` alone, plus tests across 5 workspace crates (`kf-budget-core`, `kf-testdoctor`, etc.). `cargo test --workspace` takes 10+ minutes locally and frequently times out in CI. Known pre-existing test failures (see `state.md` "Known pre-existing test failures") add noise. The AGENTS.md §4 gate requires the full test suite before every commit — this blocks development velocity and makes agents reluctant to run the gate.

CI is also affected: the `test` job is the longest single step in the pipeline. The lack of a fast feedback loop means regressions are caught late, and the long cycle time discourages incremental verification.

## Source

Developer frustration (10+ min test wall). CI job timing data. `state.md` known pre-existing test failures section. `kf-testdoctor` crate (WO 12.4) exists as a diagnostic tool but has not been optimized for speed.

## The global rule (carried from WO 22)

Every item carries: ID, reality-check, scope, success criteria, failure criteria, estimate, defer note. No silent deferral. See WO 21.0 for the full rule text.

## Ordering / dependencies

1. **25.1** (fast gate) is independent and should ship first — it provides immediate relief by giving agents and developers a fast feedback loop. No speed optimizations needed to benefit; even a slow suite filtered to unit-only will be faster than running everything.
2. **25.2** (test speed) depends on nothing but benefits from 25.1 being in place so the fast gate stays fast as tests are added.
3. **25.3** (testdoctor) is independent of 25.1 and 25.2. It optimizes the diagnostic tool, not the tests themselves.
4. **25.4** (coverage) depends on 25.1 (the coverage job is CI-only, like `test-full.sh`) and on `cargo llvm-cov` being available. WO 24.6 (session coverage 75%) is deferred — this WO picks up only the tooling, not the 75% target.

## Success criteria (whole series)

- `scripts/test-fast.sh` completes in under 30 seconds on a warm cache.
- `cargo test --workspace` completes in under 3 minutes on a warm cache.
- CI full gate (test + lint + fmt + check) completes in under 5 minutes.
- No new `#[ignore]` without a `ponytail:` or `// ignore:` label explaining why.
- `cargo llvm-cov` runs in CI and produces a per-crate baseline report.
- Coverage regression gate rejects PRs below baseline.

## Failure criteria (whole series)

- `test-fast.sh` takes longer than 60 seconds (the fast gate must be fast).
- Full workspace test time increases from current baseline.
- Broken tests are deleted rather than `#[ignore]`-labeled.
- Coverage regression gate is trivially bypassed (e.g., 0% baseline).
