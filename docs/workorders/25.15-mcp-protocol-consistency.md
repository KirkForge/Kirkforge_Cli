# Workorder 25.15 — MCP Protocol Consistency: `roots` Capability + `sampling/createMessage`

## Status: Done (R2+R3 deferred)

DEFERRED: R2 (sampling/createMessage with approval gate) and R3 (headless policy + ADR) are too large for a quick fix. R2 requires TUI prompt integration, adapter plumbing, and audit-log wiring (~1-1.5 days). R3 requires a new ADR + config flag. Tracked as deferred item 21.5-R4 in state.md.

## Priority: P1 — protocol correctness + security surface

## Problem

Two MCP-spec gaps. (1) The client handles incoming `roots/list` requests
but does NOT advertise the `roots` capability in the init handshake —
servers cannot know the client supports roots, so they never call
`roots/list` against this client. (2) `sampling/createMessage` (server
requests model completion) is unimplemented — a real security surface
(server-initiated model calls) that requires an approval gate. Carries
forward deferred item 21.5-R4.

## Source

- Roots: `src/session/mcp_client/mod.rs:561-572` (handles `roots/list`),
  `:308` (init handshake sends only `{resources:{}, prompts:{}}`), tested
  at `:1560-1579`.
- Sampling: not implemented; deferred in state.md "21.5-R4".

## Requirements

### R1 — Advertise `roots` capability in init handshake

- `src/session/mcp_client/mod.rs:308` — add `"roots": {}` to the
  capabilities blob sent in the init handshake.
- Verify the existing roots test at `:1560-1579` still passes.
- Servers will now know they can call `roots/list` against this client.

### R2 — Implement `sampling/createMessage` with approval gate

- Implement the handler. The handler MUST:
  - Display the server's requested prompt + model hint + max-tokens to
    the user.
  - Block until the user approves/denies (TUI prompt).
  - On deny: return MCP `error` to the server.
  - On approve: execute the completion via the configured adapter,
    return the result to the server.
  - Log every sampling request + disposition to the audit trail
    (cf. WO 11.6 hook audit log).

### R3 — Headless mode policy + ADR

- Headless mode (no TUI): auto-deny sampling by default.
- Add a config flag (`mcp.allow_sampling_unattended` or similar) to
  enable sampling in headless mode for explicitly-trusted servers.
- Document the approval gate + headless policy in an ADR.

## Success criteria

- Init handshake advertises `roots`; a server calling `roots/list` gets
  a real response (existing roots handler test green).
- `sampling/createMessage` from a server triggers a user prompt;
  approval executes the completion, denial returns MCP error.
- Headless auto-deny is the default; opt-in flag documented.
- ADR documents the approval gate + headless policy.
- Audit log records every sampling request (server, prompt, disposition).
- `cargo test --workspace` green.

## Failure criteria

- R1 advertises `roots` but the existing roots handler is broken
  (regression — server calls `roots/list` and gets an error).
- R2 ships sampling without the approval gate — silent security hole,
  AGENTS.md §11 deferral-disclosure violation.
- R3 headless policy allows sampling without explicit user opt-in.
- R2 audit log entry is optional or skipped on the deny path.

## Estimate

M-L (R1 ~1h; R2 ~1-1.5 days; R3 ~2h + ADR).

## Defer note

None for R1/R2/R3. PTY-driven streaming for sampling responses (showing
partial model output as it generates) is deferred — out of scope; the
approval gate + synchronous completion is the security-relevant core.
