# Workorder 25.17 — Persona Adapter Bedrock/Vertex Plumbing + Landlock Default-On Decision

## Status: Planned

## Priority: P1 — config correctness for two distinct user populations

## Problem

Two config-correctness gaps that each produce silent failures for a
specific user population. (NF-3) A Bedrock/Vertex-configured user
invoking a persona silently routes through Anthropic-direct and fails
with an auth error — `adapter_for` hardcodes `anthropic_provider="anthropic"`
and passes `None` for all Bedrock/Vertex params. The previous review's
"persona adapter_for also fixed" claim is FALSE. (Landlock) The landlock
feature is feature-gated and NOT in default features; state.md previously
overclaimed "default landlock". Either make it default-on for Linux
(codex-cli ships landlock by default) or document the opt-in requirement
explicitly — "TBD" is not an acceptable state.

## Source

- Persona: `src/tui/commands/persona.rs:216` — calls
  `adapter_for(model_name, ollama_host, None, timeout)`.
- `src/adapters/mod.rs:389-409` — `adapter_for` hardcodes
  `anthropic_provider="anthropic"`, passes `None` for Bedrock/Vertex.
- Landlock: `Cargo.toml:233` — `landlock` not in `default-features`.

## Requirements

### R1 — Persona adapter Bedrock/Vertex plumbing

- **Preferred:** plumb config through `adapter_for`. Either change the
  signature to accept a `&ModelConfig` (or `&Config`) ref, or extend it
  with the Bedrock/Vertex params currently hardcoded to `None`:
  `bedrock_region`, `vertex_project`, `vertex_location`, etc.
- Update ALL `adapter_for` call sites (cf. AGENTS.md §7 "When adding
  fields to Config" rule — same discipline applies here).
- Update the persona path at `persona.rs:216` to pass the real config.
- Add a test: a Bedrock-configured user invoking a persona routes
  through the Bedrock adapter, not Anthropic-direct.
- **Fallback (if plumbing is too invasive for one PR):** document
  explicitly in `docs/TECHNICAL.md` + persona command help that
  personas are Anthropic-direct only, with a `ponytail:` note at the
  `adapter_for` call site and a deferral entry in state.md naming the
  remaining work. No silent limitation.

### R2 — Landlock default-on decision (pick one, execute)

**Option A — default-on for Linux:**
- Add `landlock` to `default-features` for `target_os = "linux"` (use
  target-specific dependency section in `Cargo.toml`).
- Fix `pre_exec` heap allocation (landlock forbids heap allocation in
  the pre_exec closure — current code may allocate).
- Add `/dev` and `/proc` to the default allow-list.
- Resolve the home read-only break: `cargo build` needs write access
  to `$HOME/.cargo` — either carve out the cargo dir, or document a
  dev-mode escape hatch (`--i-accept-unsandboxed` exists; ensure it
  disables landlock cleanly).
- Integrate PathGuardTower.
- Update state.md to reflect "default landlock on Linux" truthfully.

**Option B — opt-in (document honestly):**
- Leave landlock feature-gated, NOT in default features.
- Correct state.md to remove the "default landlock" overclaim.
- Add docs explaining the `--features landlock` install path.
- Add a `ponytail:` note on the feature gate documenting the opt-in
  decision and the reason (the home read-only break is unresolved).

## Success criteria

- R1: Bedrock/Vertex-configured persona invocations route through the
  correct provider (verified by test), OR docs explicitly state the
  Anthropic-direct limit with a `ponytail:` note + state.md deferral.
- R2: Landlock is either default-on for Linux with `cargo build`
  still working (verified in CI on a Linux runner with read-only home
  simulation), OR documented as opt-in with state.md corrected.
- `cargo test --workspace` green. `cargo build --features landlock`
  green on Linux.

## Failure criteria

- R1 plumbing changes `adapter_for` signature and breaks existing call
  sites silently (AGENTS.md §7 violation).
- R2 default-on breaks `cargo build` for users with read-only home
  directories (the original blocker, re-shipped).
- R2 keeps landlock opt-in BUT state.md still overclaims default-on
  (AGENTS.md §11 silent-deferral violation).
- R1 fallback path (opt-out docs) shipped without the state.md
  deferral entry.

if opt-in).
