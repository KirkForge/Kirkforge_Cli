# Workorder 25.19 — AGENTS.md Multistep Workflow Upgrade

## Status: Planned

## Priority: P1 — process discipline (gpt-5.6 request)

## Problem

The current AGENTS.md workflow is a flat checklist (plan → check → implement → commit → close). In practice, the most effective sessions follow a phased pattern with explicit gates between comprehension, impact analysis, verification, planning, implementation, review, and synthesis — but this pattern is not codified. Agents skip comprehension and jump to edits; they don't run impact analysis before modifying shared symbols; they don't verify assumptions before acting on them; they don't dispatch review subagents after non-trivial changes. The result is the migration-boundary drift documented in the 2026-08-09 review: changes land in code but not in scripts, docs, or configs because no phase checks for cross-layer consistency.

This WO codifies the phased workflow into AGENTS.md so every agent session follows it by default.

## Source

- gpt-5.6 explicit request: "upgrade the workflow to be even more multistep in agents.md."
- The 2026-08-09 review's structural finding: every operational bug (stale scripts, persona misroute, dead code) is cross-layer identity drift that a phased comprehension + verification + review workflow would catch.
- The session that produced WO 25.9-25.18: five subagents ran phased (3 verify → 2 act) and caught ~30 issues the flat workflow missed.
- AGENTS.md §1-§4 and Task Management rules 1-11 (current flat workflow).
- GitNexus integration already in AGENTS.md (impact before edits, detect_changes before commits) — this WO makes those mandatory phases, not suggestions.

## Requirements

### R1 — Add a "Phased workflow" section to AGENTS.md

Insert a new section (between current §1 Plan mode and §2 Subagent strategy, or as a new §1 that supersedes the flat checklist) that defines **six mandatory phases** with gates between them. Every agent session MUST pass through these phases in order. The phases:

**Phase 0 — Comprehension (no edits allowed)**
- Read every file the task touches. Trace the full flow end-to-end.
- Grep for callers, patterns, and cross-layer references (scripts, configs, docs that reference the symbols being changed).
- State the root cause in workplan.md, not the symptom.
- Gate: workplan.md lists every file to touch with full paths + the root cause. No edits until this exists.

**Phase 1 — Impact analysis (mandatory for non-trivial changes)**
- Run `gitnexus impact({target, direction: "upstream"})` on every symbol to be edited.
- Report blast radius (direct callers, affected processes, risk level) to the user.
- If HIGH or CRITICAL risk: warn the user before proceeding. Do not edit until acknowledged.
- Gate: impact results pasted/summarized. No edits on HIGH/CRITICAL symbols without explicit go-ahead.

**Phase 2 — Verification (mandatory when assumptions are uncertain)**
- For multi-file changes or claims about code behavior: dispatch parallel verification subagents to confirm assumptions against actual source (read the file:line, don't trust stale reviews or memory).
- For cross-layer changes (renames, deletions, API changes): grep ALL layers (src/, scripts/, .github/, docs/, *.toml, configs) for references to the changed symbol.
- Gate: assumptions verified or explicitly marked "unverified — proceeding at risk."

**Phase 3 — Planning**
- Create/update workorders for any uncovered work (AGENTS.md #11: no silent deferral).
- Write workplan.md: files to touch, root cause, gate command, done-condition.
- For each edit: state what file, what change, why.
- Gate: workplan.md is complete and checked.

**Phase 4 — Implementation**
- Per-file edits with per-edit compile/lint check (AGENTS.md task management #3).
- Commit after every task, not at the end (task management #5).
- Worktree discipline (task management #6).
- Scope discipline: touch only named files; note scope creep in lessons.md (task management #7).
- Gate: each edit compiles. Each task is a gated commit.

**Phase 5 — Review + synthesis**
- For non-trivial changes: dispatch a review subagent to verify changes match intent and check for cross-layer drift.
- Run `gitnexus detect_changes()` to verify blast radius matches expectations.
- Update state.md (what changed, what's pending), lessons.md (what learned), CHANGELOG.md (one-liner).
- Verify `git status` clean. Verify gates green. Paste gate output + head SHA.
- Gate: clean tree, green gates, docs updated, deferred work disclosed.

### R2 — Make the GitNexus mandates explicit

The current AGENTS.md GitNexus block says "MUST run impact before editing" and "MUST run detect_changes before committing" — but these are in a comment block at the bottom and agents skip them. Move these into the phased workflow (Phase 1 and Phase 5 respectively) so they're structurally mandatory, not aspirational.

### R3 — Add a cross-layer consistency check to Phase 2

The root cause of every operational bug in the 2026-08-09 review is cross-layer identity drift: code renamed a symbol but scripts/docs/configs still reference the old name. Add an explicit step to Phase 2:

> **Cross-layer grep:** before any rename, deletion, or API change, grep ALL of these layers for references to the symbol:
> - `src/**/*.rs` (source)
> - `scripts/**/*.sh` (shell scripts)
> - `.github/**/*.yml` (CI/release workflows)
> - `docs/**/*.md` (documentation + ADRs)
> - `*.toml` (Cargo.toml, config.toml.example)
> - `crates/**/README.md` (crate docs)
>
> Every reference found must be either updated in the same commit or explicitly deferred with AGENTS.md #11 disclosure.

### R4 — Add a "when to use subagents" decision tree to §2

Replace the current vague §2 ("For complex multi-step tasks, break them into subtasks") with a decision tree:

- **Can I do this in <5 minutes?** → Do it yourself. (Current rule, preserved.)
- **Is this a read-only verification task?** → Dispatch `explore` subagent(s) in parallel.
- **Is this a multi-file write task with independent files?** → Dispatch `general` subagents in parallel, one per file group.
- **Is this uncertain (I'm not sure what the code does)?** → Dispatch verification subagents FIRST, then implement. Never edit on unverified assumptions.
- **Is this HIGH/CRITICAL risk (from Phase 1)?** → Dispatch a review subagent AFTER implementation (Phase 5).

### R5 — Add a "session archetype" quick-reference

Codify the session pattern that produced the best results (the WO 25.9-25.18 session):

```
Comprehension (Phase 0)
    ↓
Impact (Phase 1) ← run gitnexus impact on target symbols
    ↓
Verify (Phase 2) ← dispatch N parallel explore subagents
    ↓                     (read-only, structured output)
Plan (Phase 3) ← create workorders for uncovered work
    ↓
Execute (Phase 4) ← dispatch M parallel general subagents
    ↓                     (write, gated per task)
Review (Phase 5) ← detect_changes + review subagent
    ↓
Synthesize (Phase 5) ← state.md + lessons.md + CHANGELOG
```

This is the "even more multistep" workflow: 6 phases, explicit gates, subagent dispatch at verification and execution phases, cross-layer consistency check baked in.

### R6 — Preserve existing rules

The current AGENTS.md rules (§5 elegance, §6 autonomous bug fixing, §7 codebase patterns, task management #1-#11) are NOT replaced — they're preserved and the phased workflow is layered on top as the structural skeleton. The rules are the "what"; the phases are the "when."

## Success criteria

- AGENTS.md contains a "Phased workflow" section with 6 named phases and explicit gates.
- Every phase has a gate condition that must be met before proceeding.
- Cross-layer consistency grep is an explicit step in Phase 2.
- GitNexus `impact` and `detect_changes` are structurally mandatory in Phase 1 and Phase 5 (not just in a comment block).
- The subagent decision tree in §2 is concrete (not "for complex tasks, break into subtasks").
- The existing §5-§7 + task management rules are preserved unchanged.
- An agent reading the new AGENTS.md knows exactly which phase it's in and what gate it must pass.
- `cargo test -p kf-budget-core --test adr_xref_drift` still passes (AGENTS.md ADR-path references unchanged).

## Failure criteria

- The phased workflow is added but the existing flat checklist is also left in place (two conflicting workflows = agents pick the easier one).
- Phases are described but gates are not enforceable (no clear pass/fail condition).
- Cross-layer grep is mentioned but not scoped to specific file patterns (vague = skipped).
- GitNexus mandates stay in the comment block at the bottom instead of being promoted into the phases.
- The subagent decision tree is still vague ("for complex tasks...").
- Any existing AGENTS.md rule or codebase-pattern note is deleted or weakened.
- AGENTS.md grows beyond ~2× its current length (the workflow should be dense, not bloated — ponytail).

## Estimate

S (~2-3h). This is a single-file edit to AGENTS.md with structural reorganization. No code changes.

## Defer note

None. This is a documentation/process change, not a code change. If the phased workflow proves too heavy for trivial tasks (e.g., "fix this typo"), add a fast-path exemption: "For changes under 5 lines touching a single file, Phase 0 (comprehension) + Phase 4 (implement) + Phase 5 (synthesize) suffice; skip Phase 1-3." But start strict — loosen later if needed.
