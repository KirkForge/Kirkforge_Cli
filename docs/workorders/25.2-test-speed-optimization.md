# Workorder 25.2 — Test Speed Optimization

## Status: Planned

## Problem

The test suite takes 10+ minutes. Even with a fast gate (WO 25.1), the full suite is slow. Known pre-existing test failures (documented in `state.md`) waste CI time. Individual slow tests (likely I/O-bound, sleep-based, or single-threaded tokio) drag the whole suite down.

## Root cause

1. Broken tests run and fail every invocation, wasting time.
2. No measurement of per-test timing — slow tests are invisible.
3. Some `tokio::test` annotations may use the single-threaded runtime, serialized.
4. Integration tests (requiring external services) are mixed with unit tests.

## Scope

1. Known-broken tests — `#[ignore]` labels
2. Top-10 slowest individual tests — fix or split
3. `tokio::test` runtime configuration — multi-threaded
4. Integration test separation

## Plan

### 25.2-R1 — Audit and `#[ignore]` known-broken tests (HIGH · est S · dep: —)

**Reality check:** `state.md` lists specific known pre-existing test failures:
- `compaction_use_llm_alias_backward_compat`
- `bundled_node_sdk_tool_executes_via_host`
- `adapters::m5_tests::openai_cache_mode_marks_last_two_prefix_messages`
- `session::plugin_tools::*` (7 tests)
- `tools::bash::*` (2 tests)
- `kf-budget-core::tests::adr_0004_marker_block_pins_literal_prefix_and_suffix`

These tests fail on every run. They consume CI time and produce noise in test output.

**What to do:**
- Add `#[ignore]` to each known-broken test with a label comment:
  ```rust
  #[ignore] // ignore: broken — see state.md "Known pre-existing test failures"
  ```
- Do NOT delete the tests. They document expected behavior that needs fixing.
- Grep for any additional failing tests not listed in `state.md` — run the suite once and capture the failures. Add any new failures to the `#[ignore]` list and to `state.md`.
- Update `state.md` to note that these tests are `#[ignore]`-labeled, not deleted.

**Scope:** Test files containing the known-broken tests. `state.md`.

**Success criteria:**
- All known-broken tests have `#[ignore]` + label comment.
- `cargo test --workspace` (without `--ignored`) shows zero failures from these tests.
- `state.md` updated to reflect `#[ignore]` status.

**Failure criteria:** Any known-broken test still runs and fails. Test deleted instead of labeled.

**Estimate:** S

**Defer note:** none.

### 25.2-R2 — Identify and fix the top 10 slowest individual tests (HIGH · est M · dep: R1)

**Reality check:** Without per-test timing data, the slowest tests are unknown. `kf-testdoctor` (WO 12.5) added per-test timings — use it, or use `cargo test -- --format json` + `jq` to identify the top 10.

**What to do:**
- Run `cargo test --workspace -- --format json 2>&1 | jq` (or use `kf-testdoctor`) to get per-test timing.
- Rank tests by wall-clock time, top 10.
- For each slow test, determine why it's slow (sleep, I/O, single-threaded tokio, large fixture setup, redundant compilation).
- Fix or mitigate:
  - Replace `std::thread::sleep` with `tokio::time::advance` in async tests.
  - Replace real I/O with in-memory mocks where possible.
  - Reduce fixture sizes.
  - If the test is genuinely slow (e.g., integration test requiring startup), move it behind a feature flag or into a separate `tests/` directory that the fast gate skips.

**Scope:** Test files for the top 10 slowest tests.

**Success criteria:**
- Top 10 slowest tests identified with timing data.
- At least 7 of the 10 reduced by 50% or more, or moved to slow gate.
- Full suite time reduced by at least 20%.

**Failure criteria:** No measurement taken. No tests improved.

**Estimate:** M

**Defer note:** Fixing genuinely complex slow tests may require refactoring test infrastructure. If a test can't be fixed without a major rewrite, label it `#[ignore] // ignore: slow — needs rewrite (WO 25.x)` and move on.

### 25.2-R3 — Ensure `tokio::test` uses multi-threaded runtime (MEDIUM · est S · dep: —)

**Reality check:** `#[tokio::test]` defaults to the multi-threaded runtime. But some tests may use `#[tokio::test(flavor = "current_thread")]` or `#[tokio::test(flavor = "single_thread")]` for isolation. Single-threaded tokio serializes async operations and can be slower for I/O-bound tests.

**What to do:**
- Grep for `flavor = "current_thread"` and `flavor = "single_thread"` in test code.
- Audit each: is the single-threaded constraint necessary? (It is if the test depends on task ordering or `tokio::task::block_in_place` panics — see AGENTS.md §7.)
- For tests that don't need single-threaded, remove the flavor constraint to allow multi-threaded execution.
- For tests that genuinely need single-threaded (e.g., testing task-local state), add a comment explaining why.

**Scope:** All test files with `tokio::test` annotations.

**Success criteria:**
- Grep finds all `flavor = "current_thread"` usages.
- Unnecessary single-threaded constraints removed.
- Necessary ones documented with a comment.

**Failure criteria:** Single-threaded constraints removed where they're needed (test becomes flaky).

**Estimate:** S

**Defer note:** none.

### 25.2-R4 — Split slow integration tests behind a feature flag (MEDIUM · est M · dep: R2)

**Reality check:** Integration tests requiring external services (Ollama, Node.js, Docker) are mixed with unit tests. They fail without the service running and add minutes to the suite.

**What to do:**
- Identify integration tests that require external services (grep for test names matching integration patterns, check `scripts/run-integration-tests.sh` for the list).
- If they're in `tests/` directories (integration test convention), they're already somewhat separate.
- If they're inline (`#[test]` in source files), move them to a dedicated `tests/` integration file or gate them behind a `#[cfg(feature = "integration-tests")]`.
- The fast gate (`test-fast.sh`) should skip integration tests entirely. The full gate (`test-full.sh`) should run them.

**Scope:** Integration test files. `Cargo.toml` (if feature flag needed).

**Success criteria:**
- Integration tests are separable from unit tests.
- Fast gate does not run integration tests.
- Full gate runs integration tests.
- No integration test is deleted.

**Failure criteria:** Integration tests deleted. Fast gate still runs integration tests.

**Estimate:** M

**Defer note:** Feature-flag gating is optional if `tests/` directory separation is sufficient for the fast gate to skip them.

## Verification

- `cargo test --workspace -- --format json` timing shows top 10 improved or gated.
- `scripts/test-fast.sh` completes in under 60 seconds.
- `scripts/test-full.sh` still runs all tests (including integration).
- `cargo clippy --all-targets -- -D warnings` green.
- No known-broken test runs without `--ignored`.
