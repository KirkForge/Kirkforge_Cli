# Workorder 25.6 — Eliminate Quarantined Deadlock Tests

## Status: Planned

## Priority: P1 — known deadlock code path

## Problem

Four tests in `src/tui/approval_keys.rs` (lines 385, 431, 467, 496) are quarantined in CI via nextest timeout strategy. The root cause was a `RwLock` deadlock: write guard acquired, then read guard attempted on same lock without dropping the write guard first. The fix (`drop(cfg)` between write and read) was already applied in commit `222e28e fix(21.9)`.

**The tests should now pass.** The CI quarantine comment block (`.github/workflows/ci.yml` lines 95-114) documents the fix and says "fix the source, then REMOVE this filter" — but the cleanup was never done.

## Source

External audit finding. CI quarantine comment block explicitly names the fix. Commit history confirms `222e28e` applied the `drop(cfg)` fix.

## Requirements

### R1: Verify the four tests pass

Run the four tests individually:
```
cargo test -p kf-code -- test_always_approves_saves_permission_rule
cargo test -p kf-code -- test_always_approves_edit_file_uses_path_key
cargo test -p kf-code -- test_always_approves_dedups_repeated_calls
cargo test -p kf-code -- test_always_approves_does_not_overwrite_existing_deny
```

All four should pass. If any deadlock, the `drop(cfg)` fix was incomplete — escalate.

### R2: Remove quarantine comment block from CI

Remove the quarantine comment block from `.github/workflows/ci.yml` lines 95-114. The comment documents the root cause and says to remove after fixing — the fix is done.

### R3: Verify no regression in CI

After removing the quarantine block, the CI `quality` or `test` job should still pass all four tests within the normal timeout.

## Success criteria

- All four `test_always_approves_*` tests pass without `#[ignore]` or timeout overrides.
- CI quarantine comment block removed from `ci.yml`.
- CI passes on the commit that removes the quarantine.

## Failure criteria

- Any of the four tests still deadlock after the `drop(cfg)` fix — means the fix is incomplete.
- Quarantine removed but tests still fail for a different reason (new bug introduced).
