# Workorder 26.4 — P1 Correctness Fixes (F4–F10)

## Status: Planned

## Priority: P1 — silent data corruption and logic bugs on edge cases

## Problem

Seven findings from the handoff audit are correctness bugs — they don't panic, but they produce wrong results on edge cases:

| ID | File:line | Bug | Impact |
|----|-----------|-----|--------|
| F4 | session_index.rs:461 | Prune overflow — arithmetic can overflow on large counts | Silent data corruption / panic in release |
| F5 | bash_jobs.rs:182 | Cancel race — child removed from map before reaped | Zombie processes, double-kill |
| F6 | runner.rs:111 | Sub-second timeout truncation — `as_secs()` drops remainder | Timeouts silently shorter than configured |
| F7 | store.rs:158 | Run-id collision — same-id overwrites previous run | Lost session data |
| F8 | daemon.rs | Lock held across `.await` — potential deadlock | Deadlock under load |
| F9 | prompt/mod.rs:767 | Compaction inversion — floor division at 0 → div-by-zero | Panic on empty context |
| F10 | prompt/mod.rs:649 | Dedup key missing tool_name/tool_call_id | False dedup, dropped tool calls |

## Source

- Handoff audit (WO 26 bug-fix series).
- Specific file locations listed above.

## Requirements

### R1 — F4: Fix prune overflow with saturating arithmetic

- At `session_index.rs:461`, replace unchecked arithmetic with `saturating_sub` / `saturating_add`.
- Ensure the prune count never exceeds `usize::MAX` or wraps.
- Add a test with a count near `usize::MAX` (or mock the arithmetic path).

### R2 — F5: Fix cancel race — keep child in map until reaped

- At `bash_jobs.rs:182`, defer removing the child from the jobs map until after the child process has been reaped (waitpid/WIN32 equivalent).
- If the current code removes-on-cancel: move the map removal into the reap path.
- Verify: cancel a running job, then list jobs — the cancelled job should appear in a "completed/cancelled" state, not vanish mid-reap.

### R3 — F6: Fix sub-second timeout truncation

- At `runner.rs:111`, replace `.as_secs()` with `.as_millis()` (or use a `Duration` directly).
- Ensure timeouts under 1 second are honored (e.g., 500ms timeout should not become 0s).
- ponytail: if the downstream API only accepts seconds, use `max(1, duration.as_secs())` — but prefer millis if the API supports it.

### R4 — F7: Fix run-id collision

- At `store.rs:158`, add uniqueness to run-id generation: append a counter, random suffix, or timestamp.
- Verify: two rapid session starts never produce the same run-id.
- ponytail: `format!("{timestamp}-{random_u64:016x}")` is sufficient. UUID adds a dep; skip it.

### R5 — F8: Fix lock held across await

- In `daemon.rs`, scope the lock so it's dropped before any `.await` point.
- Pattern: `{ let guard = lock.lock().await; /* sync work */ } // guard dropped` then `.await`.
- Verify: no `MutexGuard` or `RwLockGuard` is held across an `.await` after the fix.

### R6 — F9: Fix compaction division by zero

- At `prompt/mod.rs:767`, guard against division by zero when the compaction target is 0.
- Use `checked_div` or `max(1, target)` — whichever matches the intent (skip compaction at 0 vs. compact to minimum).

### R7 — F10: Fix dedup key missing tool fields

- At `prompt/mod.rs:649`, include `tool_name` and `tool_call_id` in the dedup key.
- Verify: two different tool calls to the same tool with different call IDs are not falsely deduplicated.

## Success criteria

- Each fix addresses the specific edge case without regressing the happy path.
- `cargo test --workspace` green.
- `cargo clippy --all-targets -- -D warnings` clean.
- No new dependencies added.

## Failure criteria

- Fix introduces a worse bug (e.g., F8 fix causes data race).
- Fix adds unnecessary abstraction or dependency.
- F5 fix causes jobs to leak (never removed from map).
- Any fix skips verification (no test for the edge case).

None — all seven are one-line or few-line fixes. No feature work deferred.
