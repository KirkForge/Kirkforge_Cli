# Workorder 26.5 — P1 Infra Hardening (F11–F16)

## Status: Planned

## Priority: P1 — resource leaks and silent failures in infrastructure

## Problem

Six findings from the handoff audit are infrastructure hardening issues — unbounded growth, missing timeouts, stale state, and correctness bugs in support code:

| ID | Component | Bug | Impact |
|----|-----------|-----|--------|
| F11 | Broadcast channels | Unbounded queues — no capacity on broadcast/try_send | Unbounded memory growth under load |
| F12 | Daemon client | No connect/read timeouts | Hangs forever if daemon is slow/dead |
| F13 | Worktree resume | Stale worktree blocks resume | User stuck, no recovery path |
| F14 | Schedule | `@once` case bug — `replacen` lowercases the tag | `@Once` becomes `@once`, breaks user intent |
| F15 | Fork | Relative path used — breaks if cwd changes | Wrong directory after fork |
| F16 | Undo | Orphan `.snap` files not cleaned up | Disk leak, stale undo state |

## Source

- Handoff audit (WO 26 bug-fix series).
- Specific components listed above (exact line numbers to be confirmed in Phase A).

## Requirements

### R1 — F11: Add capacity to broadcast channels

- Audit all `tokio::sync::broadcast::channel()` calls — add a bounded capacity (e.g., 1024 or matching the existing pattern if one exists).
- Replace `tx.send()` with `tx.try_send()` where appropriate, or handle the full-channel error.
- ponytail: 1024 is arbitrary but bounded. Tune when throughput measurement shows it's wrong.

### R2 — F12: Add connect and read timeouts to daemon client

- Audit daemon client connection setup — add `connect_timeout` and `read_timeout` to the HTTP/IPC client.
- Use a reasonable default (e.g., 5s connect, 30s read). Make configurable if the client already has a config struct.
- Verify: daemon dies or hangs → client errors out within the timeout, doesn't hang forever.

### R3 — F13: Clean up stale worktree on resume error

- In the worktree resume path, if resuming fails, clean up the stale worktree (git worktree remove or equivalent).
- Log the cleanup action (tracing::warn, not debug).
- Verify: simulate a stale worktree → resume error → worktree is cleaned, next attempt succeeds.

### R4 — F14: Preserve case in schedule `@once` replacen

- Find the `replacen` call that lowercases schedule tags. Use case-preserving replacement.
- If the tag comparison is case-insensitive by design, keep the comparison insensitive but preserve the original case in output.
- Verify: `@Once`, `@once`, `@ONCE` all work without mangling case.

### R5 — F15: Use canonical path for fork

- In the fork path, resolve the working directory to a canonical/absolute path before forking.
- `std::fs::canonicalize()` before the fork call. Handle the error (nonexistent cwd) with a clear error message.
- Verify: fork with relative cwd → child process has the correct absolute cwd.

### R6 — F16: Clean up orphan `.snap` files

- On undo completion (or session start), scan for `.snap` files that have no corresponding active session and delete them.
- Add a cleanup pass in session teardown or daemon startup.
- ponytail: simple glob + delete. Add age-based expiry (e.g., >24h) if snap files are legitimately in-flight. Upgrade path: reference-count if snap files need transactional semantics.

## Success criteria

- F11: broadcast channels have bounded capacity; full-channel case is handled.
- F12: daemon client has connect+read timeouts; hangs are bounded.
- F13: stale worktree is cleaned on resume failure.
- F14: `@once` tag case is preserved.
- F15: fork uses canonical path.
- F16: orphan `.snap` files are cleaned up.
- `cargo test --workspace` green.
- `cargo clippy --all-targets -- -D warnings` clean.

## Failure criteria

- F11: bounded channel causes silent message drops without error handling.
- F12: timeout too aggressive — daemon interactions fail under normal load.
- F13: cleanup deletes a valid worktree (false positive).
- F15: `canonicalize` panic on nonexistent path.
- F16: cleanup deletes in-flight snap files.
- Any fix adds a new dependency.

## Estimate

M (~4-6h). Six independent fixes across different subsystems.

## Defer note

None — all six are bounded fixes. F16's age-based expiry is ponytail-noted; full reference-counting is deferred until snap files need transactional semantics.
