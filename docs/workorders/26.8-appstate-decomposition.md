# Workorder 26.8 — AppState Decomposition

## Status: Planned

## Priority: P2

## Problem

`AppState` has ~68 fields in a single flat struct. This makes it hard to
reason about ownership, increases the blast radius of every mutation, and
makes tests harder to construct. The goal is to decompose into ≤12
sub-struct fields grouped by concern.

## Source

state.md — 25.12-R1. Original analysis in WO 23.2.

## Requirements

### R1: Group fields by concern

Identify natural clusters and extract sub-structs:
- `ConversationState` (messages, turn count, model, temperature, etc.)
- `BudgetState` (token counts, budget limits, cost tracking)
- `SessionState` (session ID, timestamps, dirty flags)
- `ProviderState` (provider config, adapter handles)
- `ToolState` (registered tools, approvals, pending)
- `MemoryState` (memory entries, retrieval config)
- Remaining fields grouped into ≤6 additional sub-structs as needed.

Target: AppState contains ≤12 fields, each a sub-struct or a small
primitive that doesn't fit a group.

Gate: `grep -rn 'app_state\.' src/` — every access site must still
compile after decomposition.

### R2: Add accessors/Deref shims

For each sub-struct, add accessor methods on AppState so that call sites
don't need to change from `app_state.model` to `app_state.conversation.model`
in a single pass. Deref impls or explicit `fn model(&self) -> &str` shims
are acceptable; prefer explicit accessors over Deref (Deref is implicit
magic).

Gate: zero regressions in existing tests — accessors are additive,
not breaking.

### R3: Preserve TUI public API

The TUI rendering code consumes AppState. After decomposition, the TUI
must render identically with no visual changes. This may mean the TUI
accesses sub-structs directly (preferred) or goes through accessors
(acceptable).

Gate: `cargo test -p kf-code` passes unchanged.

## Pre-existing work

R2 from WO 25.12 (cached_tokens fork-reset bug) was completed in that WO
and is NOT part of this workorder. It is listed here for tracking only.

## Success criteria

- AppState has ≤12 top-level fields.
- All existing tests pass without modification (accessor shims absorb the
  change).
- TUI renders identically to pre-decomposition.

## Failure criteria

- Decomposition breaks the TUI or session persistence format without a
  migration path.
- Accessors introduced but not used — dead code.
- Fields grouped incorrectly (e.g., budget fields split across two
  sub-structs without clear rationale).

## Estimate

M+ (large refactor, ~1 week including test verification).

## Defer note

None — this is a single coherent refactor. If scope proves too large,
split R1 (grouping) and R2+R3 (accessors/TUI) into separate PRs.
