# Workorder 27.3 — Architecture Debt: tools↔session Cycle + God-Objects (H7/H8)

## Status: Planned

## Problem

Two structural debts the deep review flagged:
1. **H7 — Circular module dependency `tools ↔ session`.** Nearly every tool imports `session::access::{PathGuard, DenyList, GuardVerdict}` for path-guard enforcement; `tools/task.rs:2-4` imports `ConversationLog`, `ApprovalRequest`, `Executor`; `tools/workflow.rs` imports `session::bash_runner::check_bash_command_str`. `tools/mod.rs:88` even imports `session::toolset::CompositeToolset`. The `Tool` trait lives in `tools/` but tools reach UP into session for guards + undo + bash-safety. This blocks ever extracting `tools` to a crate + confuses the call graph (`task.rs` constructs a nested `Executor` — a tool building the loop that calls the tool).
2. **H8 — God-objects on the hot path.** `src/adapters/anthropic.rs` (2317 LOC: adapter struct + SSE parser + content-block state machine + tool-use accumulator + usage parser, all inline). `src/session/executor/turn.rs` (2087 LOC: `dispatch_tool_call_batch` ~360 LOC at `:1239-1599`; `stream_iteration` ~390 LOC at `:1600+`; `pre_run_verdict` ~276 LOC). These are the files edited for every provider-API drift + every loop-behavior fix; concentration = regression risk. The `openai_compat/` split (already `mod.rs` + `tool_call.rs`) is the pattern not applied to anthropic.

## Scope

### R1 — Break the tools↔session cycle (introduce a `tool::Sandbox` port trait)
- New trait in `src/tools/sandbox.rs` (or `src/tools/guard.rs`):
  ```rust
  pub trait Sandbox: Send + Sync {
      fn check_read(&self, path: &Path) -> GuardVerdict;
      fn check_write(&self, path: &Path) -> GuardVerdict;
      fn check_bash(&self, cmd: &str) -> Option<String>; // borrow check_bash_command_str
  }
  ```
- Move `PathGuard`, `DenyList`, `GuardVerdict` type definitions into `src/tools/` (or a new `src/shared/guard.rs`); `session::access::*` becomes the IMPLEMENTATION of the trait, not the type source.
- `src/tools/task.rs` — define a `SubagentSpawner` port trait that the executor implements; `task.rs` calls the trait, not the concrete `Executor`. This removes the `use crate::session::executor::Executor` import.
- Move `bash_runner::check_bash_command_str` + `undo::UndoKind` into `shared/` (no session state).
- After: `grep "use crate::session::" src/tools/` returns ~0 hits (only `task.rs`'s spawner port, which is the seam).

### R2 — Split `anthropic.rs` into directory form
Mirror `openai_compat/`:
```
src/adapters/anthropic/
├── mod.rs              # AnthropicAdapter struct + ModelAdapter impl + stream()
├── sse.rs              # parse_anthropic_stream + SSE framing (was :382-480)
├── content_blocks.rs   # content-block state machine + tool-use accumulator (was :584-701)
└── usage.rs            # usage parser (was :721)
```
Pure move + re-exports. No behavior change. The 370 adapter tests must pass unchanged.

### R3 — Extract `dispatch_tool_call_batch` phases
- `src/session/executor/dispatch.rs` already exists — promote the prepare/spawn/collect phases of `dispatch_tool_call_batch` (`turn.rs:1239-1599`) into named functions in `dispatch.rs`: `prepare_batch(...)`, `spawn_batch(...)`, `collect_batch(...)`.
- `turn.rs::dispatch_tool_call_batch` becomes a 3-line orchestrator calling the three phases.
- Same for `stream_iteration` if it doesn't compress cleanly — at minimum extract the memory-context-build + config-snapshot preamble into a helper.

## Success criteria

1. `grep "use crate::session::" src/tools/` returns ≤2 hits (the spawner port + maybe one residual), down from ~15.
2. `src/adapters/anthropic/` is a directory; `anthropic.rs` is gone; all 370 adapter tests pass.
3. `dispatch_tool_call_batch` in `turn.rs` is ≤30 lines (delegates to `dispatch.rs`).
4. `cargo check --workspace --all-targets` + `cargo clippy --workspace --all-targets -- -D warnings` PASS.
5. ADR documenting the `Sandbox` port + the `SubagentSpawner` seam.

## Failure criteria

- Breaking any of the 370 adapter tests or the dispatch/turn/approval executor tests.
- "Splitting" by moving code but leaving a re-export that keeps the god-object accessible (the file count goes up but the surface doesn't shrink).
- Introducing a new trait with a single implementation that's never going to have a second (AGENTS.md §5 forbids unrequested abstractions — the `Sandbox` trait is justified because `PathGuard` already has the `tool::Guard` shape AND it unblocks the crate extraction).

## Estimate

L (2 weeks). R1 is the riskiest (touches 11 tool files + the executor); R2/R3 are mechanical splits. Do R2/R3 first (low risk, immediate readability win), then R1.

## Defer note

If R1 (the cycle break) proves too invasive in one pass, ship R2+R3 first and defer R1 to 27.3-R1-later with an explicit note in `state.md`. The god-object splits are independent of the cycle break.
