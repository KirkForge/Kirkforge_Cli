# Workorder 28.10 — Slow Integration / e2e Test Feature-Flag Split

## Status: Planned

## Priority: P2 — carry-forward of WO 25.2-R4. The e2e suite is fragile + slow.

## Problem

The e2e integration test crate (`[[test]] name = "e2e"` at `Cargo.toml:228-231`,
root `tests/e2e/main.rs`) is compiled + run by every `cargo nextest run --workspace`
invocation — including the `windows` CI job (`ci.yml:150`) where it is fragile, and
the push-path quality job (`ci.yml:100`). The 7 binary-spawn scenarios were the CI
red blocker WO 27.2 had to `#[ignore]`-gate; even with them ignored, the crate's
compile time + the remaining scenarios (config_isolation, daemon_ping) add weight
to every workspace run. The fast local gate (`scripts/test-fast.sh`) already skips
integration tests, but `--workspace` on CI does not.

## Reality-check (verified 2026-08-12)

- `Cargo.toml:228`:
  ```
  [[test]]
  name = "e2e"
  path = "tests/e2e/main.rs"
  ```
  No `required-features` → built on every `--workspace` / `--all-targets`.
- ci.yml `windows` job runs `cargo nextest run --locked --workspace --no-fail-fast`
  (`:150`) — picks up e2e unconditionally.
- ci.yml `quality` job (`:92`) splits PR vs push: PR runs `--lib`, push runs
  `--workspace` — so e2e runs on every push to dev, not on PRs. The windows job
  runs `--workspace` in both paths.
- `scripts/test-fast.sh` is already lib-only; `scripts/test-full.sh` runs everything.
- The e2e crate is a custom-harness integration test (`harness = false` is NOT set
  on the `[[test]] e2e` block — it uses the default libtest harness via main.rs).

## Scope

### R1 — Gate the e2e crate behind a Cargo feature
- File: `Cargo.toml`.
- Add to `[features]`:
  ```
  e2e-tests = []
  ```
- Add `required-features = ["e2e-tests"]` to the `[[test]] name = "e2e"` block:
  ```
  [[test]]
  name = "e2e"
  path = "tests/e2e/main.rs"
  required-features = ["e2e-tests"]
  ```
- Effect: `cargo nextest run --workspace` no longer builds/runs e2e unless
  `--features e2e-tests` is passed. `cargo check --workspace --all-targets` (the
  lint gate) must ALSO pass `--features e2e-tests` or the e2e crate stops compiling
  in CI entirely — wire that in R3.
- Alternative (directory separation): move `tests/e2e/` out of the default
  `tests/` discovery by keeping it as a named `[[test]]` (already is) — the
  feature gate is the cleaner knob. Prefer the feature.

### R2 — Tag the e2e test attrs (belt + suspenders)
- Files: `tests/e2e/scenarios/*.rs`.
- Optional: if any inline integration tests live in `src/` (grep
  `#[ignore = "WO 27.2"` to find the e2e-adjacent ones), gate them behind
  `#[cfg(feature = "e2e-tests")]`. The `tests/e2e/` crate itself is already
  isolated by R1 — only touch inline tests if they exist.

### R3 — Dedicated CI job for e2e
- File: `.github/workflows/ci.yml`.
- New job `e2e` (or extend the existing windows/quality push path):
  ```yaml
  e2e:
    runs-on: ubuntu-latest   # or windows-latest if the binary-spawn coverage matters there
    needs: quality
    timeout-minutes: 20
    steps:
      - uses: actions/checkout@v4
      - name: Install Rust toolchain
        uses: dtolnay/rust-toolchain@master
        with: { toolchain: ${{ env.RUST_TOOLCHAIN }} }
      - uses: Swatinem/rust-cache@v2
      - name: Run e2e suite
        run: cargo nextest run --locked --test e2e --features e2e-tests --no-fail-fast
  ```
- Remove e2e from the `windows` job's `--workspace` run (it will no longer be
  picked up once R1 lands, but make the intent explicit in the job name/comment).
- Ensure `cargo check --workspace --all-targets --features e2e-tests` runs in at
  least one job so the e2e crate does not rot (compile coverage).

### R4 — Update gates + docs
- `scripts/ci-local.sh`: add an `e2e` mode (or fold into `full`) that passes
  `--features e2e-tests` for local reproduction.
- `scripts/test-full.sh`: decide whether "full" includes e2e (recommend YES, with
  the feature flag).
- `docs/TECHNICAL.md`: if the test-tier section mentions the e2e crate, note the
  feature gate (doc-sync discipline, AGENTS.md task-mgmt #9).

## Success criteria

1. `cargo nextest run --workspace` (no features) does NOT build or run the e2e crate.
2. `cargo nextest run --test e2e --features e2e-tests` runs the full e2e suite.
3. The `windows` CI job stops running e2e (no more 30s-per-scenario weight).
4. A dedicated CI job runs e2e with the feature on every push to dev.
5. `cargo check --workspace --all-targets --features e2e-tests` stays green (crate
   does not silently stop compiling).

## Failure criteria

- e2e crate silently stops compiling because no CI job passes the feature.
- e2e tests deleted to "fix" the gate (AGENTS.md §6).
- Feature added but `--all-targets` lint gate not updated → red CI on the next push.
- `|| true` / `#[ignore]` used to keep a fragile e2e test green (AGENTS.md §4/§6).

## Estimate

S-M (~half-day). R1 is one Cargo.toml block; R3 is one CI job; the rest is wiring.

## Defer note

None. The feature-gate approach is reversible (drop the `required-features` line
and the crate is unconditional again). If the dedicated e2e CI job proves flaky
on its chosen runner, land R1+R2 first and defer R3 to a follow-up with explicit
disclosure (what: the dedicated job; why: runner-flake; remaining: pick a stable
runner; tracked here + state.md pending).
