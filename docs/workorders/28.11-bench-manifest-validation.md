# Workorder 28.11 — Benchmark Manifest Validation (close the residual drift gap)

## Status: Planned (small — much already shipped; verify + close the residual gap)

## Priority: P3 — carry-forward of WO 25.7-R3. Closes the manual-count gap.

## Problem

`benches/tasks/*.toml` count is documented in `README.md` ("30 coding tasks") and
referenced in `docs/TECHNICAL.md`, but the validation story is **partially**
manual and partially automated — and the two halves are not obviously aligned.
The task prompt frames this as "not auto-generated from source"; reality (per
AGENTS.md §7 stale-cleanup warning — *grep before you plan*) is that **most of
the gate already exists**, and this WO closes the residual gap rather than
building from scratch.

## Reality-check (verified 2026-08-12) — the gate is mostly ALREADY shipped

1. **`scripts/check-artifact-consistency.sh` check #3** computes
   `EXPECTED_BENCHES=$(ls benches/tasks/*.toml | wc -l)` and greps README for
   `"$EXPECTED_BENCHES coding tasks"` — FAILS the script on mismatch, and the
   script ends with `if [ "$FAIL" -gt 0 ]; then exit 1; fi` (verified at the
   script tail). So count-drift vs README **already fails CI**.
2. **`ci.yml:61`** runs `bash scripts/check-artifact-consistency.sh` in the `fmt`
   job — so the check is live in CI.
3. **`ci.yml:44-60`** runs a Python step that `tomllib.loads()` every
   `benches/tasks/*.toml` and fails the job on any parse error
   (`::error file=...::Invalid TOML`).
4. README currently says "30 coding tasks" and `ls benches/tasks/*.toml | wc -l`
   = 30 — they match TODAY.

### The REAL residual gap (what this WO actually does)

- **(a)** The count check covers README only; `docs/TECHNICAL.md`'s benchmark
  table (lines ~770-790) lists task rows individually and is not cross-checked
  against the directory. A task file can land without a TECHNICAL.md row (or vice
  versa) and nothing fires.
- **(b)** The toml **parse** validation (ci.yml:44-60) does not validate
  **schema** — a toml missing a required field (`name`, `prompt`, `expected`,
  etc.) parses clean but is a broken task. No `kf-bench` dry-run or schema check
  exists in CI.
- **(c)** The `EXPECTED_BENCHES` count is recomputed from scratch every run
  (good), but there is no recorded "expected set" manifest, so a rename
  (`foo.toml` → `foo_v2.toml`) keeps the count constant and silently passes.

## Scope

### R1 — Extend check-artifact-consistency.sh to TECHNICAL.md row count
- File: `scripts/check-artifact-consistency.sh`.
- Add a check #9: count `.toml`-row entries in the `docs/TECHNICAL.md` benchmark
  table (the `| <slug>.toml | ... |` rows) and compare to
  `ls benches/tasks/*.toml | wc -l`. Fail on mismatch with both numbers.
- Done: adding a toml without a TECHNICAL.md row (or the reverse) fails CI.

### R2 — Schema validation for each bench task toml
- File: new tiny validator (reuse `kf-bench` if it has a `--validate` /
  `--dry-run` mode — grep first; otherwise a short Python step alongside the
  existing ci.yml:44-60 parse check that asserts required keys present).
- Required keys: enumerate from an existing well-formed task (e.g.
  `benches/tasks/<one>.toml`) — likely `name`, `prompt`, and an expected/eval
  field. Pin the set in the validator with a `ponytail:` comment naming the
  source task if it is a heuristic ceiling.
- Done: a toml missing a required key fails CI even when it parses.

### R3 — Name-set manifest (catch silent renames)
- File: `scripts/check-artifact-consistency.sh` (extend) or a sibling script.
- Record the expected set of `benches/tasks/*.toml` basenames in a checked-in
  manifest (`benches/tasks/MANIFEST.txt` or inline in the script). Compare the
  live `ls` to the manifest; require an explicit manifest edit on add/rename.
- Done: a rename that preserves count but changes the set fails CI until the
  manifest is updated.

## Success criteria

1. README count check (already works) stays green.
2. TECHNICAL.md row count matches the directory (R1) — verified by deliberately
   adding a stray row and seeing CI fail.
3. A toml missing a required key fails CI (R2).
4. A silent rename fails CI until the manifest is updated (R3).

## Failure criteria

- Hardcoding "30" instead of computing from source (re-introduces the manual drift).
- Schema check so strict it rejects legitimate task variants (false positives).
- Manifest approach that blocks legitimate new-task addition without a clear
  update path.
