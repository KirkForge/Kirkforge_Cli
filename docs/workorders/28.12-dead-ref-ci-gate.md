# Workorder 28.12 — Dead Crate/Binary Reference CI Enforcement (extend to `src/` + `crates/`)

## Status: Planned

## Priority: P2 — carry-forward of WO 25.8-R4 / WO 25.10-R4.

## Problem

`scripts/check-artifact-consistency.sh` already greps **scripts/, .github/, install.sh,
docs/RELEASE.md** for retired identifiers (`plugin3`, `kfd`, `kf-code-video`,
`kf-code-draw`, `kf-code-plugin`) and fails CI on hit (ci.yml:61). But it does NOT
grep **active source** (`src/`, `crates/`). A `use plugin3::...` or a `mod kfd` can
land in source and nothing fires until the build breaks — and a *comment-only*
reference (`// removed plugin3 in WO 12`) would slip past even a build gate. The
retired-name firewall stops at the `src/` boundary.

gitnexus evidence — no indexed symbol; pure CI/scripting tooling. Blast radius is
CI-only (the gate runs read-only greps).

## Reality-check (verified 2026-08-12)

- Existing check #5 greps `scripts/ .github/workflows/*.yml` for
  `plugin3|kf-code-video|kf-code-plugin` (excluding `#` comment lines + this
  script itself) and fails on hit. Pattern is the model.
- Existing check #2 greps `scripts/install.sh` for
  `plugin3|stratum|kf-code-video|\bkfd\b` — note the `\b` word-boundary on `kfd`
  (avoids matching `kfdata`, etc.). Reuse that boundary discipline.
- `src/` and `crates/` are NOT covered. The historical migration (Plugin3 →
  kf-budget-core, kfd → daemon mode, kf-code-video/draw → yeeted WO 21.1) is
  documented in ADRs + workorders, so any LIVE source hit is a true positive.
- Risk of false positives: source comments legitimately say `// plugin3 legacy`
  or `// was kfd`. These are HISTORICAL prose, not live identifiers — the gate
  must allowlist them or restrict to identifier positions (not comment text).

## Scope

### R1 — Add a source-tree dead-identifier check
- File: `scripts/check-artifact-consistency.sh` (new check #9, modeled on #5).
- Grep `src/ crates/` for retired identifiers AS **live code**, not historical prose:
  ```bash
  # Live identifier heuristics (NOT inside // or /* */ comments, NOT in string
  # literals that are historical prose). Word-boundary on short names.
  ```
- Identifier-position patterns (true positives):
  - `use plugin3::` / `use kf_code_video::` / `use kfd::` (mod/use paths)
  - `mod plugin3` / `mod kfd` / `mod kf_code_video` (module decls)
  - `extern crate plugin3` (legacy)
  - `plugin3::` (path-qualified call — outside string literals)
  - Cargo dep refs: `plugin3 =` / `kf-code-video =` in any `Cargo.toml` under
    `src/`/`crates/` (there are none normally, but `crates/*/Cargo.toml` is in scope)
- Reject the naive `grep -rn plugin3 src/ crates/` (catches every `// plugin3`
  comment — false positives). Use the identifier-position regex OR allowlist (R2).

### R2 — Allowlist for legitimate historical references
- File: a checked-in allowlist (`scripts/dead-ref-allowlist.txt` or inline in the
  check) listing `file:line` pairs (or `file:regex`) that are historical and OK.
- Seed the allowlist by running R1's grep once, classifying every hit:
  - **HISTORICAL (allowlist):** `// plugin3 was renamed in WO 12`,
    `//! legacy kfd binary`, ADR-style prose in doc-comments.
  - **ACTIVE (fail):** any `use`/`mod`/`extern crate`/path-qualified call.
- The allowlist must be explicit (no wildcard `*` exemptions) so a new active ref
  cannot hide behind a broad rule.

### R3 — Wire into CI (already wired via check-artifact-consistency.sh)
- `ci.yml:61` already runs `bash scripts/check-artifact-consistency.sh` in the
  `fmt` job — R1's new check rides along automatically. No new CI job needed.
- Add to `scripts/ci-local.sh` (it already calls check-artifact-consistency.sh in
  its `full` mode — verify and note if the call is missing from `quick`).

### R4 — Identifier set review
- Confirm the retired-identifier set against state.md + WO 21.1 (the yeet) +
  WO 12 (the Plugin3 migration):
  - `plugin3` (crate name)
  - `kfd` (daemon binary — `\bkfd\b` boundary)
  - `kf-code-video` / `kf_code_video` (Cargo name + Rust ident)
  - `kf-code-draw` / `kf_code_draw`
  - `kf-code-plugin` (already in check #5)
  - `stratum` — CAREFUL: `stratum` is STILL a live Cargo feature
    (`Cargo.toml:233` `stratum = ["dep:kf-compress-core"]`) and a live concept.
    Do NOT add `stratum` to the dead-identifier set. (Existing check #2 greps it
    in install.sh only because install.sh must not install it as a binary —
    different semantics. Leave source-side `stratum` alone.)

## Success criteria

1. A deliberate `use plugin3::foo;` added to `src/` fails CI.
2. A deliberate `mod kfd;` added to `crates/` fails CI.
3. The existing historical prose comments (`// plugin3 legacy`) do NOT fail CI
   (allowlist works).
4. `stratum` references in source do not fail (it is a live feature).
5. The allowlist is explicit (no wildcard exemptions).

## Failure criteria

- A naive whole-word grep that floods CI with historical-comment false positives.
- `stratum` added to the dead set (breaks the live feature — AGENTS.md §7).
- Allowlist with wildcard `*` that lets new active refs through silently.
- `|| true` / `|| echo non-fatal` to suppress a real hit (AGENTS.md §4/§6).

## Estimate

S-M (~half-day). R1 is one bash block; R2 (classification + allowlist seed) is
the bulk of the work — run the grep, triage every hit, record the historical set.

## Defer note

None. If the identifier-position regex (R1) proves too brittle (too many false
positives or negatives), fall back to the allowlist-only approach: grep broadly,
allowlist every current hit explicitly, fail on any NEW unallowlisted hit. That is
less precise but closes the firewall. Disclose the fallback choice in the Status
line if taken (what: regex approach; why: false-positive flood; remaining: refine
regex / accept allowlist-only; tracked here).
