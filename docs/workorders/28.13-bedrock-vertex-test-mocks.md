# Workorder 28.13 — Bedrock/Vertex Wiremock-Backed CI Contract Tests

## Status: Planned

## Priority: P2

## Problem

The Bedrock and Vertex adapters (`src/adapters/anthropic_bedrock.rs`,
`anthropic_vertex.rs`, `bedrock_signing.rs`, `vertex_auth.rs`) have rich
**offline** unit tests — URL string assertions, SigV4 host-derivation checks,
AWS event-stream frame parsing against static byte fixtures. What they LACK is
any **wiremock-backed end-to-end contract test**: nothing spins up a mock
HTTP server, drives the adapter + executor through a full turn, and asserts
the wire bytes match the provider contract.

The OpenAI-compat / Ollama path has exactly this —
`src/session/executor/tests/wiremock_integration.rs`
(`adapter_stream_drains_against_wiremock`,
`executor_turn_drains_against_wiremock`). Bedrock/Vertex have no equivalent.
Net effect: request-building drift on the AWS/GCP paths (SigV4 canonical
form, event-stream framing, Vertex token injection) goes undetected until a
live-credential run, and CI has ZERO coverage of half the provider matrix —
"CI green" gives false confidence for the paths operators actually use in
production.

## Scope

### R1 — Bedrock wiremock contract test

- New test (sibling of `wiremock_integration.rs` or a section within it):
  spin a `wiremock::MockServer`, drive `adapter_for_with_provider(...,
  AnthropicBedrock, ...)` through `run_turn_collecting`.
- Mock enforces contract conformance, not just shape:
  - Authorization header IS SigV4-well-formed (`AWS4-HMAC-SHA256` + signed
    body). Mock rejects unsigned/malformed requests with 403.
  - Model id appears in the path
    (`/model/{model_id}/invoke-with-response-stream`).
  - Response is a real `application/vnd.amazon.eventstream` frame sequence
    (reuse the static fixtures from the offline parse tests).
- Gate: test PASSES in CI with zero AWS credentials in the env; mock rejects
  a deliberately-mangled signature.

### R2 — Vertex wiremock contract test

- Spin a `MockServer` that (a) accepts the GCP service-account token exchange
  (fake SA JSON → fake bearer) and (b) serves an Anthropic-style SSE stream.
- Mock enforces: bearer token from the SA exchange, project + region in the
  path, Anthropic SSE framing.
- Gate: test PASSES with zero GCP credentials; mock rejects a request with a
  stale/missing bearer.

### R3 — Shared mock harness (only if R1+R2 duplicate setup)

- If R1 + R2 share significant scaffolding, extract a `MockProvider` helper
  per the WO 17.8 design. Otherwise leave inline — do not invent an
  abstraction for two call sites (AGENTS.md §5).

## Success criteria

1. Bedrock + Vertex executor-drain tests pass in CI with zero live
   credentials.
2. The mocks REJECT malformed requests (contract conformance), not just
   accept any well-formed HTTP.
3. `cargo test --workspace` no longer depends on a live-cred run to exercise
   the AWS event-stream + SigV4 + GCP token paths.

## Failure criteria

- Mocks accept any request (theater — explicitly forbidden by WO 26.10-R1).
- Tests require credentials (defeats the point).
- SigV4 signing + event-stream parsing not actually exercised (mock too
  loose to catch a real drift).
