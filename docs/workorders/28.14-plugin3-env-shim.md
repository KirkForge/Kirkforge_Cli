# Workorder 28.14 — PLUGIN3_* → KF_BUDGET_* Env-Var Backward-Compat Shim

## Status: Planned

## Priority: P2

## Problem

`kf-budget-core` renamed its directory env vars `PLUGIN3_*_DIR` →
`KF_BUDGET_*_DIR` for namespace consistency. The canonical read sites are
`crates/kf-budget-core/src/paths.rs:25-29`:

```rust
config_dir: std::env::var("KF_BUDGET_CONFIG_DIR")...
data_dir:   std::env::var("KF_BUDGET_DATA_DIR")...
runtime_dir:std::env::var("KF_BUDGET_RUNTIME_DIR")...
```

Existing operator workflows, CI envs, and docs still reference the old
`PLUGIN3_*` names (ADR-0015:87/169, ADR-0016:206/221-300, the WO 10.0
repro). On upgrade, any workflow exporting only `PLUGIN3_CONFIG_DIR`
**silently breaks** — the var is unread, the default dir is used, and budget
state appears to reset with no diagnostic. There is no backward-compat shim
and no migration note.

## Source

- `state.md` "Deferred items" item 16 (WO 26.10-R2, not started).
- WO 26.10-R2.

## Reality-check (verified against code at `5296f41`)

- `grep "PLUGIN3_" src/ crates/ scripts/` → **zero** source hits. The rename
  is complete on the read side.
- `PLUGIN3_` survives only in docs (ADR-0015, ADR-0016, CHANGELOG:529) and
  WO docs — i.e. the lineage is documented but the runtime alias is gone.
- No shim reads `PLUGIN3_*` anywhere; the break is silent.

## Scope

### R1 — Backward-compat shim with one-shot deprecation warning

- In `crates/kf-budget-core/src/paths.rs` `Paths::resolve` (around :24-29):
  when `KF_BUDGET_*_DIR` is unset AND `PLUGIN3_*_DIR` is set, use the
  `PLUGIN3_*` value AND emit a **one-time** `eprintln!` deprecation warning
  naming the new variable.
- One-time means ONE warning per process per var (use a `std::sync::Once`
  or an `AtomicBool`), not one per call. Clean installs (neither var set)
  stay completely quiet.
- No warning when both are set — `KF_BUDGET_*` wins silently (the new name
  is canonical); optionally warn on conflict, but prefer silence to avoid
  noise.

### R2 — Doc lineage

- ADR-0015 + ADR-0016: mark `PLUGIN3_*` as **deprecated aliases** of
  `KF_BUDGET_*` (do NOT strip the old names — they document the lineage and
  operators reading old runbooks need to find them).

### R3 — CHANGELOG migration note

- Under the next release's "Deprecated" or "Breaking" section: name the
  rename, the shim window (one release), and the exact var mapping.

## Success criteria

1. A workflow exporting only `PLUGIN3_CONFIG_DIR` still resolves the config
   dir correctly AND emits exactly one deprecation warning to stderr.
2. A clean install (neither var exported) emits zero warnings.
3. `cargo test -p kf-budget-core` green; the `EnvGuard` concurrency tests
   (cost.rs:523+, paths.rs:85+) do not pick up `PLUGIN3_*` bleed-through.

## Failure criteria

- Silent fallback (no warning — users never learn to migrate; WO 26.10-R2
  explicitly forbids this).
- Warning spams every invocation (must be one-shot per var per process).
- Breaks the existing `KF_BUDGET_*_DIR` test suite (the `EnvGuard` tests are
  mutex-sensitive — the shim must not introduce a new env-read race).

## Estimate

S (half-day). R1 is ~20 lines + a one-shot guard; R2/R3 are doc edits.

## Defer note

None. The shim is scoped to a one-release window — after that it is removed
and the rename becomes a hard break. Do NOT silently extend the window.
