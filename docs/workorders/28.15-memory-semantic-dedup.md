# Workorder 28.15 — Memory Store: Near-Duplicate Dedup + Retrieval Ranking

## Status: Planned

## Priority: P3

## Problem

`MemoryStore` (`src/session/memory/mod.rs:48`) accumulates semantically
near-duplicate facts with no dedup. `upsert` (`:105`) overwrites ONLY on
exact name-slug match — the `ponytail:` comment at `:104` flags this
("collisions extremely unlikely but not impossible"). So `"user prefers
rust"` and `"Kirk likes Rust"` both persist as separate files. With
`max_facts = 200` and alphabetical eviction (`:125-128`), near-duplicate
noise crowds out unique signal in the prompt-injection block.

Retrieval is purely lexical: `search` (`:148`) scores by substring match;
`score_for_context` (`:201`) is TF-IDF-style keyword matching. No semantic
ranking — a fact using different vocabulary for the same concept scores
zero against a relevant context.

## Scope

### R1 — Near-duplicate gate on insert

- In `upsert`, before writing: tokenize the new fact's `description` + `body`
  and compute a lexical-similarity score against every existing fact's
  `description` + `body`. Use a normalized token-overlap measure (Jaccard
  or TF-cosine on lowercased whitespace tokens — no new dep).
- If max similarity ≥ threshold (start 0.85), either skip the insert or
  merge (append body into the existing fact, keep the higher-rank name).
  Default: merge (memories are expensive to extract; don't silently drop).
- `ponytail:` comment naming the ceiling: lexical similarity misses
  synonym-only paraphrases; upgrade path = real embeddings if dedup
  underperforms in practice.

### R2 — Retrieval ranking tightening

- `score_for_context` already does TF-IDF over name + description + body.
  Verify it normalizes by vector magnitude (cosine, not raw dot product) and
  tighten if not. No new dependency, no model calls.

### R3 — Dedup test

- New test in `memory/mod.rs` tests: after 10 near-duplicate inserts (same
  fact reworded), ≤2 entries retained; after 10 genuinely-distinct inserts,
  10 retained. Asserts the threshold is neither aggressive nor a no-op.

## Success criteria

1. After a burst of near-duplicate inserts, only 1-2 unique entries survive.
2. `score_for_context` ranks semantically-close facts above pure
   lexical-gloss matches (verified by a before/after test fixture).
3. No new dependency added; no model/HTTP call introduced on the insert or
   retrieval path.

## Failure criteria

- Threshold too aggressive (merges genuinely distinct memories — data loss).
- Threshold too lax (no dedup happens — no-op shipped as "done").
- Adds an embedding-model dependency or a network call per insert
  (out-of-scope cost/latency regression).

## Estimate

None. Deferred since WO 21.6 — lexical dedup is the right first rung; if it
