# Workorder 28.16 — Anthropic Hosted computer_use Beta (Coordinate-Vision)

## Status: Planned

## Priority: P3

## Problem

Anthropic's hosted **computer_use** beta — the coordinate-vision model that
takes a screenshot and emits coordinate actions (click at x,y, type, scroll)
— has no adapter path in `kf-code`. `build_anthropic_body`
(`src/adapters/anthropic/mod.rs:162`) serializes tools only as
`{name, description, input_schema}` (`:314`, `:338`); there is no `computer`
tool type, no `anthropic-beta: computer-use-2025-01-24` header in
`AnthropicAdapter::stream`, and `parse_anthropic_stream` has no
`computer_tool_result` content-block handling.

The **local** headless-Chrome CDP `computer_use` tool
(`src/tools/computer_use.rs`, gated by `config.security.computer_use.enabled`,
default false) is a DIFFERENT capability — it drives the browser locally via
CDP, not via Anthropic's hosted vision model. It does not satisfy this WO.

This has been re-deferred three times (WO 25.18-R2 → WO 26.7-R4 → now) with
full disclosure each time. The disclosure in `state.md` item 3 is the
canonical record.

## Scope

### R1 — Cargo feature flag, default OFF

- New `computer_use` feature in root `Cargo.toml` (default OFF — this is a
  meaningful capability + cost surface; users opt in explicitly).
- Gate every downstream R-item behind `#[cfg(feature = "computer_use")]`.
- Test: assert zero `anthropic-beta` / `computer` tool-type bytes are emitted
  when the feature is OFF (compile-time + a runtime wire assertion).

### R2 — Adapter wire format

- `build_anthropic_body` (feature-gated branch): emit
  `{"type":"computer","name":"computer","display_width_px":W,
  "display_height_px":H}` instead of `input_schema` for the computer tool.
- `AnthropicAdapter::stream`: add the `anthropic-beta:
  computer-use-2025-01-24` header when the feature is on + the model is
  computer-use-capable.

### R3 — Stream parser

- `parse_anthropic_stream`: handle the `computer_tool_result` content-block
  type. Route screenshot + coordinate-action events through a new
  `TurnEvent` variant (or reuse the existing tool-call event shape).

### R4 — Coordinate-vision execution loop

- Screenshot capture: reuse `src/tools/computer_use.rs`'s CDP capture path
  (do NOT duplicate the headless-Chrome plumbing).
- Loop: screenshot → model turn → coordinate-action execution → screenshot
  until the model emits a terminal action.
- Distinguish from the local CDP tool via a config flag
  `computer_use.hosted` (default false). The local tool stays; this adds a
  hosted path alongside it.

### R5 — ADR + docs

- ADR documenting the capability, the cost surface (vision-model tokens per
  screenshot), the opt-in posture, and the relationship to the local CDP
  tool.
- `docs/TECHNICAL.md` feature-flag table updated.

## Success criteria

1. With the feature OFF: zero computer_use wire bytes; all 370 existing
   anthropic adapter tests pass unchanged.
2. With the feature ON + `computer_use.hosted = true`: a model turn drives
   the hosted coordinate-vision loop end-to-end against a real Anthropic
   computer_use model (manual smoke; the live-model test stays out of CI).
3. ADR + TECHNICAL.md updated in the same commit.

## Failure criteria

- Ships default-ON (cost/surface ungated — WO 26.7-R4 explicitly forbids).
- Breaks the existing anthropic adapter tests when the feature is OFF.
- Confuses the local CDP `computer_use` tool with the hosted path (they
  share screenshot plumbing but are distinct capabilities).

## Estimate

L (~1-2 weeks). R3 (stream parser extension) + R4 (vision loop) are the
long poles.

## Defer note

This is the re-deferred-with-disclosure item. **R1-R3 must ship** (adapter
wire format + stream parser, still default-OFF); R4 (the vision execution
loop) may defer to `28.16-R4-later` IF the loop proves too large for one PR
— disclose explicitly in `state.md` + this WO's Status line. Do NOT silently
stub R4 and mark the WO done (AGENTS.md §11).
