# Workorder 28.17 — Bash Evasion Tripwire Posture (H3 Remaining)

## Status: Planned

## Priority: P2

## Problem

`contains_shell_expansion_evasion` (`src/session/bash_runner/safety.rs:166`)
catches `$()`, backticks, `$IFS`, `${IFS}`, `$'` (tests at `:544-572`,
`:981`). It deliberately does NOT catch:

- **Encoded payloads**: `eval $(echo cm0gLXJmIC8K | base64 -d)` — the
  ceiling comment at `safety.rs:159-165` names this explicitly.
- **Variable-assignment indirection**: `x=/; rm -rf $x` — substring
  blocklists cannot resolve runtime variable state.

This is **fundamental**, not a gap: no substring/regex blocklist can catch
encoding evasion. WO 27.1 shipped landlock as the real filesystem boundary
(`apply_landlock` at `landlock.rs:177`, wired into the `setup_rlimits`
pre-exec at `bash_runner/mod.rs:179`), which makes the deny-list a
**tripwire**, not the boundary. The remaining work is NOT "catch more
evasion in the blocklist" (that is theater — AGENTS.md §5 forbids it). It is:

1. **Document the tripwire posture** so operators do not mistake the
   deny-list for a boundary. (Closes WO 27.5-R3, which did not fully ship.)
2. **Optionally offer a `bash.require_allowlist` mode** for high-security
   deployments where landlock-alone is insufficient — an allowlist is the
   only blocklist-shape that isn't theater.

## Scope

### R1 — Document the tripwire posture (MUST ship)

- `docs/TECHNICAL.md` security section + `README.md` operator section: an
  explicit "deny-list is a tripwire; landlock + `--no-network` is the
  boundary" subsection. Recommend `--harden --no-network` for unattended /
  headless runs.
- State honestly: the deny-list narrows the obvious-payload surface; a
  determined payload evades via encoding; landlock confines the blast
  radius to the allow-listed paths; `unshare(CLONE_NEWNET)` blocks network
  exfiltration.
- This is the honest close of the H3 "remaining" item as a DOCUMENTED
  ceiling, not a code gap.

### R2 — Optional `bash.require_allowlist` mode (defer-able)

- New config field `bash.require_allowlist: bool` (default false). When true,
  bash commands must match an operator-defined allowlist (`bash.allowlist =
  ["git", "cargo", "npm", "ls", ...]`) or be denied with a clear error.
- For high-security deployments where landlock-alone is insufficient (e.g.
  the allow-listed paths include sensitive material).
- This is an ALLOWLIST, not a deny-list extension — the deny-list stays as
  tripwire. `ponytail:` comment: allowlist is the only blocklist-shape that
  isn't theater.
- If the allowlist semantics need operator input (glob vs prefix vs regex,
  compound-command handling), defer R2 to `28.17-R2-later` with explicit
  disclosure and ship R1 alone.

## Success criteria

1. Operator docs name landlock + `--no-network` as the boundary and call the
   deny-list a tripwire (R1).
2. (R2, if shipped:) `bash.require_allowlist = true` rejects a
   non-allowlisted command with a clear error; allowlisted commands run.
3. No new regex/evasion detection added to `safety.rs` (that would be
   theater).

## Failure criteria

- Adds more regex / encoded-payload detection to the deny-list (theater;
  AGENTS.md §5 + this WO's Problem section both forbid it).
- Documents the deny-list AS a boundary (misleads operators about the
  security model).
- R2 ships an abstraction with one user (the default-off allowlist is
  operator-opt-in, so it clears the one-impl rule).
