for every loop-behavior fix and every provider-API drift. Three methods are far
past readable size and concentrate regression risk:

| Method | Lines | LOC |

followed by spawn and collect phases). The extraction is mechanical.

- `pre_run_verdict` (`turn.rs:583`) returns a `PreRunVerdict` enum consumed by

## Scope

### R1 — Promote `dispatch_tool_call_batch` phases into `dispatch.rs`
- Move the prepare/spawn/collect bodies out of the inline `turn.rs:1241-1601`
  method into named free functions (or `impl Executor` fns) in `dispatch.rs`:
  ```rust
  // in dispatch.rs
 (super::Executor).async fn prepare_batch(...) -> (Vec<PreparedCall>, Vec<SkippedCall>);
 (super::Executor).async fn spawn_batch(...) -> Vec<ToolCallResult>;
 (super::Executor).async fn collect_batch(...) -> anyhow::Result<usize>;
  ```
- `turn.rs::dispatch_tool_call_batch` becomes a ~20-line orchestrator:
  ```rust
  let (prepared, skipped) = self.prepare_batch(...).await?;
  let results = self.spawn_batch(prepared, ...).await?;
  self.collect_batch(results, skipped, ...).await
  ```
- Preserve the `// Phase N` comments at the new function boundaries.

### R2 — Extract `pre_run_verdict` alongside dispatch
- Move `pre_run_verdict` (`turn.rs:583-859`) + its `PreRunVerdict` enum into
  `dispatch.rs` (or a new `executor/pre_run.rs` if `dispatch.rs` would exceed
  ~400 lines after R1). It is the per-call gate consumed only by `prepare_batch`.

### R3 — Extract `stream_iteration`'s preamble
- Pull the memory-context-build + config-snapshot prologue of
  `stream_iteration` (`turn.rs:1602-~1680`) into a helper
  `build_stream_preamble(&self) -> StreamPreamble` (in `turn.rs` or a new
  `executor/stream.rs`). The SSE-driver loop stays in `stream_iteration` — only
  the setup boilerplate moves.
- Leave the stream loop itself alone (it is tightly coupled to the adapter
  parser + `TurnEvent` emission; moving it is high-risk for no readability win).

## Success criteria

1. `dispatch_tool_call_batch` in `turn.rs` is **≤30 lines** (delegates to
   `prepare_batch` / `spawn_batch` / `collect_batch` in `dispatch.rs`).
2. `turn.rs` net LOC drops by the size of the moved phases (target: ≤1500, from
   2087).
3. All executor tests pass unchanged — `tests/turn.rs`, `tests/approval/*`,
   `tests/wiremock_integration.rs`, the doom-loop tests.
4. `cargo check --workspace --all-targets` + `cargo clippy --all-targets -- -D
   warnings` + `cargo fmt --check` PASS.
5. `run_turn_inner`'s call to `dispatch_tool_call_batch` is unchanged (the
   public signature is preserved; only the body is redistributed).

## Failure criteria (anti-patterns to avoid)

- "Extracting" by moving the body but leaving a re-export / `pub use` that keeps
  the 360-line method reachable — the file count rises, the surface doesn't
  shrink (AGENTS.md §5).
- Changing the ordering or semantics of the prepare/spawn/collect phases (this
  is a pure refactor; any behavior diff is a regression).
- Splitting into so many tiny helpers that call-graph readability drops (one
  method per phase, not one per statement).
- Pulling the SSE stream loop out of `stream_iteration` — it is intentionally
  left in place (high-risk, low-reward).
