## Status: Done (R1+R2+R3+R4-local). R4-ci.yml step deferred — see Defer note.

## Priority: P1 — carry-forward of WO 27.2-R4 / WO 25.4-R3. Unblocks WO 28.9.

## Problem

The CI `coverage` job generates + uploads `lcov.info` but **never enforces a
threshold** — coverage can regress silently. The local gate uses `cargo-tarpaulin`
(`scripts/ci-local.sh:87`) with `DEFAULT_THRESHOLDS` baked into kf-testdoctor
(`crates/kf-testdoctor/src/gaps.rs:55`: `src/session=68.5, src/tools=76.0,
src/adapters=75.0`), but that is local-only and the two sides have already
drifted: the kf-testdoctor drift-guard `default_thresholds_match_ci_yml`
(`gaps.rs:415-471`) is itself `#[ignore]`'d because the matching `targets = { ... }`
dict was removed from `.github/workflows/ci.yml`. And `docs/coverage-baseline.md`
is all `TBD` placeholders — there is no per-crate floor recorded.

gitnexus evidence — `DaemonClient` / coverage flows confirm the gate touches no
indexed symbol (it is pure tooling around the build), so blast radius is CI-only.

## Scope

### R1 — Write `scripts/check-cov-regression.sh`
- New script. Runs `cargo llvm-cov --workspace --lcov --output-path lcov.info`,
  then parses per-crate line coverage and compares against
  `docs/coverage-baseline.md` with **-1% tolerance** (CI runner noise).
- Source of per-crate numbers: `cargo llvm-cov --workspace --json` (machine-parseable)
  OR parse the lcov `SF:`/`DA:` records aggregated by crate prefix.
- On regression: print `REGRESSION: crate X baseline Y% now Z% (-W%)` and `exit 1`.
- On the no-baseline (`TBD`) case: print `BASELINE-MISSING: crate X` and treat as
  non-fatal for the first run (so R2 can capture numbers), fatal thereafter.

### R2 — Fill `docs/coverage-baseline.md` from one CI run
- Download the `coverage-report` artifact from one green CI run, run the script's
  parser, replace all six `TBD` rows with real numbers + the date.
- Commit the baseline as the **floor**. Subsequent PRs must not drop below it.

### R3 — Un-ignore the kf-testdoctor self-guard
- `crates/kf-testdoctor/src/gaps.rs:415-471`: remove the `#[ignore]` at `:416` AND
  restore the `targets = { ... }` dict in ci.yml that it parses (or update the
  test to parse the new baseline file instead of a ci.yml dict — whichever is the
  smaller, more honest pin). The `ponytail:` comment at `:417` documents the
  upgrade path; update it when the guard goes live.
- This is a `ponytail:`-adjacent pin — editing it without restoring the matched
  spec side is a regression (AGENTS.md §5).

### R4 — Wire into CI + ci-local.sh
- ci.yml `coverage` job: add a step after the upload:
  ```
  - name: Check coverage regression
    run: bash scripts/check-cov-regression.sh
  ```
- `scripts/ci-local.sh full`: add the same script after the tarpaulin step (or
  replace tarpaulin with llvm-cov for consistency — the local + CI gates should
  use the SAME tool or the numbers will not match).

## Success criteria

1. `scripts/check-cov-regression.sh` exists, runs in both `ci-local.sh full` and
   the ci.yml `coverage` job.
2. The gate **fires** on a real coverage drop (verified by temporarily removing
   one test, seeing the gate fail, then restoring it).
3. The gate **passes** on an unchanged tree (no flake at -1% tolerance).
4. `docs/coverage-baseline.md` has real numbers + date for all six crates.
5. `default_thresholds_match_ci_yml` runs un-ignored and green.

## Failure criteria

- Gate does not fire on a real drop (false negative).
- Gate flakes on no-change runs (tolerance too tight, or local-vs-CI tool mismatch).
- Baseline left as `TBD` after the first qualifying CI run.
- Self-guard un-ignored but the spec side not restored (drift in the other direction).
- `|| true` added to make the gate "pass" (AGENTS.md §4/§6).
