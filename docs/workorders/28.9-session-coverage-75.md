# Workorder 28.9 — `src/session` Coverage >75% (executor loop + budget + compaction + verifier bus)

## Status: Done (5 tests, R2.5/R2.6 disclosed — see Commit)

## Priority: P2 — carry-forward of WO 24.6 / WO 25.16. Depends on WO 28.7.

## Problem

`src/session` — the executor loop, budget slicing, compaction, verifier bus — is
the deepest, most safety-relevant module in the binary, and its line coverage is
~68.6% (per `docs/coverage-baseline.md` prose + the `DEFAULT_THRESHOLDS` entry
`src/session = 68.5` at `crates/kf-testdoctor/src/gaps.rs:55`). The WO 28.7 gate
will **enforce** that floor; this WO fills the actual gaps so the floor can be
raised to 75. Without these tests, regressions in doom-loop accounting, the
max-continuation cap, plan-mode token resets, and cost-budget trips land silently.

gitnexus evidence — `gitnexus query "session executor loop untested" -r Kirkforge_Cli`
returns process flows `proc_27..proc_118` all anchored on `run_line_mode` /
`CorrectionLoop::new` (`src/session/verifier/correction.rs:16`), confirming the
executor loop + correction loop are the densest untested region.

## Success criteria

1. `src/session` line coverage ≥75% per `cargo llvm-cov` (line + region).
2. Every R2-R5 test passes AND fails if its pinned behavior is removed/weakened.
3. The WO 28.7 baseline is bumped from 68.5 → 75.0 for `src/session` in the SAME
   commit that lands the last test (so the gate never lags the reality).
4. Baseline numbers recorded in `docs/coverage-baseline.md`.

## Failure criteria

- Tests added to game the metric (trivial asserts exercising lines, not behavior
  — AGENTS.md §6).
- Coverage gate lowered to make the number pass.
- Baseline measured only on happy paths (error branches uncovered).
- Tests `#[ignore]`-marked to keep the suite green (AGENTS.md §4).
- `tokio::task::block_in_place` used in a single-threaded test runtime (AGENTS.md §7).
