# Workorder 29.1 — Fold Bundled Plugin into Compiled-In Rust Tools

## Status: Planned

## Problem
`plugins/kf-plugin/` ships 7 POSIX shell scripts (`tools/*.sh`) that each `source common.sh && exec node $CLI_JS <cmd>`. Every tool invocation hops: Rust → shell script → Node CLI → external linter. The Node hop adds ~200ms startup + a Node runtime dependency. The 6 tool commands (`verify`, `verify-workspace`, `audit-verify`, `doctor`, `health`, `tools`) are deterministic wrappers that translate env-var JSON → CLI flags → `exec node`. All business logic lives in `npm/kf-plugin/apps/cli/src/commands/*.ts`.

## Source
- Rust plugin inventory (subagent, 2026-08-12): bundled plugin file inventory + each script's behavior.
- ADR-050: "the `kf-plugin` self-plugin (Node SDK) is not folded; its tools depend on the Node ecosystem" — the linters stay external, but the WRAPPER LOGIC can be Rust.
- The stratum/kf-budget fold-in pattern (WO 21.11): `FOLDED_PLUGINS` + `folded_feature_enabled` + compiled-in registration.

## Reality-check
- `plugins/kf-plugin/kf-code.toml` declares 6 tools + 1 skill.
- Each `tools/*.sh` script: `find_cli` (resolve the Node CLI JS path) → parse `KIRKFORGE_TOOL_ARGS_JSON` → translate to CLI flags → `exec node $CLI <cmd>`.
- The actual tool logic: `npm/kf-plugin/apps/cli/src/commands/*.ts` — verify.ts, verify-workspace.ts, audit-verify.ts, doctor.ts, health.ts, tools.ts.
- The `common.sh` helpers (`find_cli`, `node_json_arg`, `node_json_file_arg`) are shell→Node bridges that a Rust impl doesn't need.

## Scope

### R1 — Implement the 6 tool commands as Rust functions
Create `src/tools/plugin_sdk/` (or `src/session/plugin_tools/native/`):
- `verify` — runs verification on a task (shells out to external linters as needed). Port the TS `commands/verify.ts` logic.
- `verify_workspace` — runs verification on a workspace (multiple files). Port `commands/verify-workspace.ts`.
- `audit_verify` — verifies the JSONL audit chain integrity (hash chain). Port `commands/audit-verify.ts`. This needs the hash-chain impl from core-events (WO 29.4).
- `doctor` — probes for external tools (ESLint, tsc, Ruff, Pyright, Bandit). Port `commands/doctor.ts` (which uses `execFile`).
- `health` — health check (no args, returns status). Port `commands/health.ts`.
- `tools_list` — lists native lint engines. Port `commands/tools.ts`.

Each function: read args from the tool-call `serde_json::Value` (not env vars), do work, return `ToolOutcome::Success(content)`.

### R2 — Register as compiled-in tools behind a cargo feature
- `Cargo.toml`: add `kf-plugin-tools = []` feature (default ON, like stratum/budget).
- `src/session/plugin_tools/loader.rs`: add `("kf-plugin", "kf-plugin-tools")` to `FOLDED_PLUGINS`. When the feature is on, `folded_feature_enabled("kf-plugin")` returns true → the shell-plugin dir is skipped → the 6 tools register directly.
- `src/tools/mod.rs` or `src/main/run_session.rs`: register the 6 tools when the feature is on (mirror how stratum/budget tools register).
- Update `default_enabled_plugins` in `src/shared/config/tools.rs` if needed.

### R3 — Delete the shell scripts (when the feature is default-on)
- Remove `plugins/kf-plugin/tools/*.sh` + `common.sh`.
- Keep `plugins/kf-plugin/kf-code.toml` (the manifest + skill prompt) OR fold the skill into the Rust registration.
- The `plugins/kf-plugin/` dir may be emptied except for README + kf-code.toml (for non-folded fallback), or fully removed if the feature is always on.

## Success criteria
1. `kf-code run` with the `kf-plugin-tools` feature ON: the 6 tools are available as native Rust calls (no Node subprocess, no shell hop).
2. Each tool returns the same result shape as the TS version (verify returns the same verification output; doctor probes the same tools).
3. `folded_feature_enabled("kf-plugin")` returns true when the feature is on → the shell-plugin dir is skipped.
4. The `/kf-code` skill prompt is preserved (either via the manifest or inline in the Rust registration).
5. `cargo test --lib -p kf-code` passes; no new deps added (the tools shell out to external linters via `tokio::process::Command`, which is already a dep).

## Failure criteria
- Adding a Node or npm dependency (the whole point is to eliminate it).
- Breaking the plugin manifest contract (plugins loaded from `~/.local/share/kf-code/plugins/` must still work via the shell wrapper when the feature is OFF).
- Porting the external linters themselves (ESLint/Ruff stay external — ADR-050).

## Estimate
M (3-5 days). The TS commands are straightforward wrappers; the doctor probe is the most complex (walks up 6 parent dirs to find bundled binaries).

## Defer note
None. This is Phase 1; it ships independently.
