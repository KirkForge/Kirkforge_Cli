# Workorder 29.3 — Port Pure Modules (Classifier + Routing + Correction + Truth-Model + Path-Safety)

## Status: Planned

## Problem
~1700 LOC of TS pure functions (no model calls, no fs, no event bus) that form the foundation of the orchestrator. These are ready for direct Rust translation — they're pure math/regex/logic.

## Source
- Inventory: "Pure modules ready for direct port" — `routing-engine.ts` (268), `classifier-nlp.ts` (379), `classifier.ts` (151), `correction-loop.ts` (137), `truth-model.ts` (142), `task-profile.ts` (234), `cost.ts` (45), `path-safety.ts` (386).

## Scope

### R1 — routing-engine.ts → kf_routing (or extend src/session/memory/)
Port: `tokenize`, `vectorize` (FNV-1a), `cosine`, `detectFamily`, `buildEmpiricalRecommendation`, `fingerprintTask`. These are pure math; port verbatim. The Rust `src/session/memory/mod.rs:tokenize` exists but uses a different algorithm (alphanumeric split) — keep both, don't merge.

### R2 — classifier.ts + classifier-nlp.ts → Rust classifier
Port: `classifyTask` (regex scoring), `classifyHybrid` (regex + NLP fallback), `classifyNlp` (TF-IDF + cosine archetype matching), `ARCHETYPES`, `STOP_WORDS`, `MODE_SCORING`, `NLP_FALLBACK_THRESHOLD`. Pure; no model calls.

### R3 — correction-loop.ts + truth-model.ts → Rust correction decision
Port: `decideCorrection(packet, count, max, tokens, ...)` (the pure decision function — what correction action to take), `computeFinalVerdict` (the single-precedence truth table), `SourceOfTruth` enum. These are the decision logic; the IMPURE parts (running the correction, model calls) are WO 29.7.

### R4 — task-profile.ts + cost.ts → Rust lookups
Port: `detectTaskProfile` (regex family classifier), `PROFILES`, `extensionForLanguage`, `profileForLanguage`, `PROVIDER_COST_RATES`, `estimateSimpleCost`. Pure lookup tables.

### R5 — path-safety.ts → Rust path safety
Port: `sha256Of`, `isInsideCwd`, `safeRelativePath`, `isBinaryLikeContent`, `hasHiddenSegment`, `segmentsHaveEscapingSymlink`, `finalFileIsSymlink`, `disallowedArtifact`, `writeArtifacts` (atomic fs writes). Mostly pure + atomic writes. Check overlap with existing `src/session/access/mod.rs` PathGuard — don't duplicate.

## Success criteria
1. All pure functions ported to Rust with identical behavior (port the TS tests as Rust tests).
2. No model calls, no fs (except path-safety's atomic writes), no event bus.
3. The Rust modules are usable as a foundation for WO 29.7 (orchestrator port).

## Estimate
M (3-5 days). ~1700 LOC of pure functions; the port is mechanical.
