# Workorder 29.4 — Port EventBus + AuditLogger (core-events)

## Status: Planned

## Problem
`@kirkforge/core-events` provides an in-process `EventBus` (pub/sub with idempotency + bounded buffer) + a tamper-evident `AuditLogger` (hash-chained sinks: file/http/memory/syslog/WORM). Consumed by ~20 orchestrator files + the CLI. Rust has `src/shared/audit.rs` (file-only, no hash chain, no bus).

## Source
- Inventory: core-events full function/type/dependency map. LIVE exports: EventBus, AuditLogger, createAuditSink, FileAuditSink, chainHashOf, initialHash. DEAD: SyslogAuditSink, WormAuditSink, HttpAuditSink (tested but no production wiring).

## Scope

### R1 — EventBus → tokio broadcast or mpsc wrapper
Port `EventBus` (emit/on/drainBuffer/shutdown) as a Rust struct backed by `tokio::sync::broadcast` or a custom bounded mpsc. The idempotency cache (EventBusOptions) needs a `HashMap<EventId, Instant>` + TTL eviction. Port the TS tests.

### R2 — AuditLogger + hash chain → Rust audit module
Port `initialHash` (SHA-256 or HMAC-SHA256), `chainHashOf` (prevHash + canonicalJson(event) + HMAC), `AuditEvent` struct (id, sequence, timestamp, action, outcome, actorId, tenantId, reason, chainHash, ...). Extend `src/shared/audit.rs` with the hash chain (currently file-only append). Port the `AuditAction` enum (29 string literals — much richer than Rust's `AuditEntry` enum).

### R3 — FileAuditSink → Rust file sink with rotation
Port `FileAuditSink` (buffered appendFileSync + size-based rotation: 50MB / 10 files). Rust `AuditLog` currently does file append without rotation — add it.

### R4 — SKIP the dead sinks
Do NOT port `HttpAuditSink`, `SyslogAuditSink`, `WormAuditSink` — zero production consumers (per inventory). If needed later, they're follow-up WOs.

## Success criteria
1. EventBus + AuditLogger + hash chain work in Rust with identical behavior (port the 36 TS tests).
2. The `kf audit-verify` CLI command works against the Rust audit log.
3. FileAuditSink rotation works (test: write >50MB, verify rotation).

## Estimate
M (3-5 days). The hash chain + canonical JSON are the trickiest parts.

## Defer note
None for R1-R3. R4 (dead sinks) explicitly skipped — not a deferral, a decision.
