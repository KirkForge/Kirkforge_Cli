# Workorder 29.5 — Port RBAC + JWT Verification (core-rbac)

## Status: Planned

## Problem
`@kirkforge/core-rbac` provides role-based access control (4 roles × 16 permissions), OIDC JWT signature verification via `jose` + JWKS, and timing-safe API-key auth. Consumed by 11 TS files (orchestrator health-server + plugin auth middleware). Rust has no RBAC/JWT/JWKS.

## Source
- Inventory: core-rbac full function/type/dependency map. External dep: `jose@^6.2.3` (the ONLY external npm dep across the 3 security packages).

## Scope

### R1 — Port the role/permission/actor model
Port `Role` (admin/operator/developer/viewer), `Permission` (16 literals), `Actor` (id, role, tenantId, authMethod, verifiedAt), `hasPermission`, `authorize`, `authorizeTenant`, `resolveRole`, `GroupRoleMapping`. Pure map-lookup logic.

### R2 — Port timing-safe API-key auth
Port `actorFromApiKey` using Rust's `subtle::ConstantTimeEq` (already a workspace dep). Mirror the timing-safe padding logic.

### R3 — Port JWT/JWKS verification
Port `verifyJwt` (OIDC discovery + remote/local JWKS + signature verification + scope check + clock skew). Rust candidates: `jsonwebtoken` crate (RS/ES/PS/EdDSA). Port `validateJwtClaims`, `actorFromJwt`, `OidcConfig`, `JwtClaims`, `clearJwksCache`, `ALLOWED_ALGORITHMS`.

### R4 — Port the TS tests (58 tests)
Port the 46 RBAC tests + 12 JWT tests as Rust tests.

## Success criteria
1. RBAC role/permission/actor model works in Rust.
2. JWT verification via `jsonwebtoken` crate produces the same results as the TS `jose` version.
3. Timing-safe API-key comparison is constant-time (test with `subtle`).
4. All 58 ported tests pass.

## Failure criteria
- Using a non-constant-time comparison for API keys (security bug).
- Dropping any of the 10 allowed JWT algorithms.

## Estimate
M (3-5 days). The JWT/JWKS part needs the most care (choose the right crate + verify algorithm coverage).

## Defer note
None. Foundation for WO 29.8 (health-server).
