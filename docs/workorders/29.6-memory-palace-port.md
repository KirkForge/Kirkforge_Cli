# Workorder 29.6 — Port Memory-Palace (Routing Store + Adapters)

## Status: Planned

## Problem
`@kirkforge/memory-palace` (1859 LOC, 8 src files) provides a routing-oriented memory system: tokenization, vectorization, cosine similarity, empirical recommendations, SQLite/file/in-memory adapters. Rust `src/session/memory/` has a DIFFERENT memory system (markdown+frontmatter facts for prompt injection) — do NOT merge by name.

## Source
- Inventory: memory-palace full function/type/dependency map. Depends on `better-sqlite3` (optional, falls back to FileAdapter). The routing-engine functions (tokenize/vectorize/cosine) are pure — ported in WO 29.3.
- The Rust `rusqlite` crate is the natural SQLite replacement (or `sqlx` if async is needed).

## Scope

### R1 — MemoryStore facade
Port `MemoryStore` class: `create`, `evictExpired`, `evictOverflow`, `writeTaskObservation`, `writeDecomposition`, `recallDecomposition`, `recall`, `writeEmissionRecords`, `writeRunRecord`, `writeRunAndEmissions`, `queryRuns`, `queryEmissions`, `queryEmissionsForRun`.

### R2 — FileAdapter
Port `FileAdapter` (JSON-file with lock + atomic rename + `.corrupt` backup). Straightforward Rust port using `std::fs` + `tempfile`.

### R3 — SqliteAdapter (optional)
Port `SqliteAdapter` using `rusqlite` (schema, prepared statements, migrations, backup/restore). The `better-sqlite3` → `rusqlite` mapping is mostly mechanical (synchronous API both sides). Port `SCHEMA_VERSION`, the schema DDL, the prepared statements.

### R4 — EncryptedAdapter (optional, NOT in barrel)
Port `EncryptedAdapter` (AES-256-GCM decorator) using Rust's `aes-gcm` crate. Currently NOT re-exported from index.ts — only accessible via deep import. Low priority.

## Success criteria
1. MemoryStore works in Rust with the same query/store semantics.
2. FileAdapter + SqliteAdapter produce the same data shape.
3. The recommendation engine (port of `buildEmpiricalRecommendation` from 29.3) works end-to-end.

## Failure criteria
- Merging with the existing Rust `src/session/memory/` (different purpose — that's prompt-injection facts, not routing).
- Breaking the `SCHEMA_VERSION` migration path (v3 → v4 if the port changes the schema).

## Estimate
M (3-5 days). SqliteAdapter is the biggest piece.

## Defer note
R4 (EncryptedAdapter) is explicitly low-priority — not in the barrel, no consumers. Port only if requested.
