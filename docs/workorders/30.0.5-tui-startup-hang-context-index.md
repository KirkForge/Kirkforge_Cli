# Workorder 30.0.5 — TUI Startup Hang + Multi-MB System Prompt (context-index)

## Status: Fixed + follow-up fixed (commits `f842591`, `10162f8` on `dev`; verified e2e)

Dogfood session 2026-08-13. User symptom: `kf-code run` appears frozen
forever in the target repo (KirkForge-PicoSeries-picosentry). After fixing
that, a second bug surfaced: first request to the model carried a **7.1 MB /
>1M-token system prompt** → Ollama cloud 400 `prompt too long; exceeded max
context length by 1076589 tokens`. Both root causes live in the
context-index feature (ADR-037 Phase 4).

Extends WO 30.5 (context-index dir filter — OPEN in 30.0.0 index) and is
the interactive-mode sibling of the WO 27.2 e2e hang.

## Bug 1 — index walk enters `.claude/worktrees/` (and `.opencode/`)

**Root cause:** `ContextIndex::is_ignored_dir`
(`crates/kf-context-index/src/lib.rs`) skipped only `target|.git|
node_modules|.venv|venv|dist|build`. The cwd repo contained
`.claude/worktrees/` with **5 full duplicate worktrees (800 MB, 26.5k
`.py` files)** — tree-sitter-parsing 5 repo copies with zero progress
output at default `warn` log level. Not hung: grinding. Diagnosis:
`strace -e openat` showed a tight `openat` loop inside
`.claude/worktrees/agent-a5be1d04bf58588ad/...`; Ollama itself verified
responsive via direct `curl`.

**Fix:** add `.claude` and `.opencode` to the `matches!` ignore list
(1 line).

**Startup time:** cold index of the (now-correctly-scoped) repo ~20-27s;
subsequent runs load from `.kf-code/context-index/cache.json` (git-HEAD
keyed) instantly.

## Bug 2 — `imported_by` fan-out smears every unresolved edge into every result

**Root cause:** `ContextIndex::to_retrieval_result` filtered edges with
`e.resolved_file.as_ref().is_none_or(|rf| rf == &sym.file)` — the
`is_none_or` arm means **every unresolved import edge in the whole index**
(external/stdlib imports, the majority on a big Python repo) lands in
`imported_by` of *every* retrieved symbol. Top-10 retrieval then renders
10 lines averaging **649 KB each** (57,144 path mentions, 2,645 unique
files): `<relevant_symbols>` alone was 7.14 MB. Cloud model rejected:
`prompt too long … by 1,076,589 tokens`.

Diagnosed by pointing `ollama_host` at a logging proxy
(`/tmp/opencode/proxy.py`) and inspecting the captured request:
11 result lines, avg line len 649,497 chars, block 7,144,486 chars.

**Fix (2 changes):**

1. `crates/kf-context-index/src/lib.rs` — `imported_by` now requires
   `resolved_file == Some(sym.file)` (resolved-only, module-level
   attribution) and dedups `source_file` via a `HashSet`. Unresolved
   edges belong to no symbol. `ponytail:` comment documents the
   module-level ceiling (symbol-level edge model = upgrade path).
2. `src/session/prompt/mod.rs` — rendered `imported_by`/`called_by`
   lists capped at 10 entries + `+N more` marker. Defense in depth: any
   future index pathology must not be able to blow the system prompt to
   MBs. `ponytail:` comment names the ceiling.

## Bug 3 (follow-up, same dogfood session) — landlock `add_path` missing NUL termination → bash EINVAL

After Bugs 1-2 shipped, the first real TUI work session still "broke
completely": transcript showed 3× `bash` → `Invalid argument (os error 22)`
→ doom-loop breaker (`doom_loop_max_hits = 1`) → auto plan mode →
"Plan mode blocked" on everything.

**Root cause:** `landlock::add_path` passed
`path.as_os_str().as_bytes().as_ptr()` to `libc::open`, which reads a
**NUL-terminated** string — the byte after the `PathBuf` buffer was heap
garbage. Short paths hit it deterministically: the default bash workdir
`"."` (used whenever the model omits `workdir`) opened `".<junk>"`:
strace child evidence — `chdir(".") = 0` then
`openat(AT_FDCWD, ".\33\217M\337{", O_PATH) = -1 ENOENT`. Longer absolute
paths usually survived because the next heap byte happened to be 0,
which is why the model's retry *with* an explicit workdir worked.

**Fix (`10162f8`):** precompute `CString`s in `resolve_paths` (parent,
pre-fork — `pre_exec` stays allocation-free); `LandlockPaths` stores
`CString`s; `SYSTEM_READ_DIRS` becomes `&[&CStr]` `c"..."` literals.
Tests: landlock test constructors now go through `resolve_paths`.
`cargo test --lib landlock` 6/6; e2e bash-without-workdir PASS.

**Adjacent observed, NOT fixed (needs its own WO):** 4×
`Approval denied: approval responder dropped without a user decision`
early in the same TUI session (before the bash failures) — approval
prompts died without surfacing a decision. Unverified root cause;
confounded with 3 concurrent daemons (two stale debug builds) that were
killed during triage. If it recurs, capture `RUST_LOG=debug` from the
start.
