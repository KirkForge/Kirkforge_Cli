# Workorder 31.0 — Multi-Language Verification Loop

## Status: Planned

## Problem

The verification loop currently only fires for Rust projects (`cargo build`/`clippy`/`test`/`rustfmt`). When kf-code works on Python, JS/TS, Go, or any non-Rust project, the verifiers return `Skipped` — the generate→execute→verify→correct loop degrades to generate→execute→hope. The first real-world dogfood test (kf-code against KirkForge-MCP, a Python project, 2026-08-13) proved the agent can find bugs but can't auto-verify its fixes.

## Source

- Dogfood test output (2026-08-13): agent found 7 real issues in KirkForge-MCP but noted "the verification loop didn't fire because it's Python."
- The verifier architecture (`src/session/verifier/`) is already split by concern: `build.rs`, `lint.rs`, `test.rs`, `rustfmt.rs`, `git.rs`, `security.rs`. Each is a `Verifier` trait impl.
- The `VerifierSlots` registration (`src/session/executor/mod.rs:init_default_verifiers`) is where new verifiers plug in.

## Architecture decision

**Detection-based, not config-based.** The verifiers should DETECT the project language from the workspace (presence of `pyproject.toml`/`setup.py` → Python; `package.json` → Node; `go.mod` → Go; `Cargo.toml` → Rust) and run the appropriate tools. No config flag needed — the verifier sniffs the project type.

## Sub-workorders

### 31.1 — Python verification (`pytest` + `ruff`/`flake8` + `mypy`)
| # | Title | Est |
|----|-------|-----|
| 31.1 | Python verifier: detect pyproject.toml/setup.py → run pytest + ruff + mypy | M |

R-items:
- R1: `src/session/verifier/python_test.rs` — new verifier. Detect `pyproject.toml` or `setup.py` or `conftest.py` in the workspace. If found, run `python -m pytest {changed_files} --tb=short -x` (targeted, like the Rust test verifier). Parse output → `Verdict::Fixable` on failures.
- R2: `src/session/verifier/python_lint.rs` — run `ruff check {changed_files}` or `flake8` (detect which is installed). Parse output → `Verdict::Fixable` on lint errors.
- R3: `src/session/verifier/python_typecheck.rs` — run `mypy {changed_files}` if `mypy.ini` or `[tool.mypy]` in pyproject.toml. Parse output → `Verdict::Fixable` on type errors.
- R4: Register in `init_default_verifiers` alongside the Rust verifiers. Gate each on language detection (only fire if Python project detected).

### 31.2 — Node/TypeScript verification (`tsc` + `eslint`)
| # | Title | Est |
|----|-------|-----|
| 31.2 | Node verifier: detect package.json → run tsc + eslint | M |

R-items:
- R1: `src/session/verifier/node_test.rs` — run `npm test` or `npx vitest` (detect from package.json scripts).
- R2: `src/session/verifier/node_lint.rs` — run `npx eslint {changed_files}` or `npx tsc --noEmit`.

### 31.3 — Go verification (`go test` + `go vet`)
| # | Title | Est |
|----|-------|-----|
| 31.3 | Go verifier: detect go.mod → run go test + go vet | S-M |

### 31.4 — Language detection module
| # | Title | Est |
|----|-------|-----|
| 31.4 | `src/session/verifier/detect.rs` — detect project language from workspace markers | S |

Central detection: scan workspace for `Cargo.toml` (Rust), `pyproject.toml`/`setup.py` (Python), `package.json` (Node), `go.mod` (Go). Returns `Vec<ProjectLanguage>`. Each verifier checks this before deciding to fire. This replaces the current implicit "always Rust" assumption.

### 31.5 — Generic test-runner verifier (fallback)
| # | Title | Est |
|----|-------|-----|
| 31.5 | Fallback: if no language detected, try `make test` / `ctest` / bare `./test.sh` | S |

## Ordering

```
31.4 (detect) → 31.1 (Python) → 31.2 (Node) → 31.3 (Go) → 31.5 (fallback)
```

31.4 first (the detection module all verifiers depend on). Then 31.1 (Python — the dogfood target). Then the others.

## Success criteria

1. kf-code editing a Python file → pytest auto-runs after the edit → failures fed back as `Verdict::Fixable` → agent corrects → pytest re-runs → passes.
2. Same for Node (tsc + eslint) and Go (go test + go vet).
3. Rust projects unchanged (the existing verifiers fire as before).
4. Mixed-language projects: only the relevant verifiers fire per file.

## Failure criteria

- Running Rust verifiers on a Python project (noise + wrong output).
- Blocking the turn if pytest/tsc/go are not installed (should skip gracefully).
- Breaking the existing Rust verification flow.

## Gate

`cargo test --lib -p kf-code verifier::` — existing tests pass + new verifier tests pass.
