# Workorder 32.12 — WO 27.7 R2 — Click-in-Prompt Cursor Positioning

## Status: Done (`fced991`)

## Problem

WO 27.7 R2 — clicking inside the prompt to position the text cursor
— is explicitly deferred at `src/tui/events.rs:56-59`: "click-to-position
the text cursor inside the prompt / approval input is NOT implemented
here — our LineReader does not expose a set-position API cleanly."
Open since WO 27.7.

The mouse-click handler routes to the prompt area but stops short of
moving the cursor; the click is acknowledged but ignored for cursor
placement.

## Root cause

The `LineReader` widget does not expose a `set_position` / move-cursor
API, so the click handler has no target to call. The deferral is a
missing widget API, not a missing event.

## Approach

1. Add a `set_cursor_col(&mut self, col: usize)` (or equivalent) to
   the `LineReader` / input widget in `src/tui/widgets/input.rs` that
   clamps to the rendered line width and updates the internal cursor
   index.
2. In `src/tui/events.rs` click handler, map the click column (adjusted
   for the prompt prefix offset and horizontal scroll) to a character
   index and call `set_cursor_col`.
3. Keep the existing click-outside-prompt behavior unchanged.

## Files to touch

- `src/tui/events.rs`
- `src/tui/widgets/input.rs`

## Gate

- `cargo test --lib tui`

## Done condition

Clicking inside the prompt moves the text cursor to the clicked
column. Click outside the prompt keeps existing behavior. Cursor
position clamps to line bounds on click past end of input.
