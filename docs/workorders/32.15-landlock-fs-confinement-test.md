# Workorder 32.15 — WO 28.5 R3 — Landlock FS-Confinement Integration Test

## Status: Pending

## Problem

WO 28.5 R3 deferred a Linux-gated integration test that asserts landlock
filesystem confinement actually blocks out-of-scope reads. The intended
test: spawn a background `cat ~/.aws/credentials` from a confined bash
job and assert it fails with EACCES. Deferred because it requires a
landlock-capable kernel (Linux >= 5.13) and was not gating to ship R1/R2.

## Root cause

No technical blocker — the confinement code exists and works. The
deferral was test-environment availability: a landlock-capable kernel
wasn't guaranteed in CI at the time. The fix is to gate the test behind
a Cargo feature (`landlock-tests` or similar) and a runtime kernel
check so it runs only where supported.

## Approach

1. Add the test to the `src/session/bash_jobs.rs` test module.
2. Gate it behind a Cargo feature (e.g. `landlock-tests`) so it does
   not run by default and does not break non-landlock CI.
3. Add a runtime kernel-version / landlock-support guard inside the
   test so it skips (not fails) on kernels < 5.13 even when the feature
   is on.
4. The test spawns the confined `cat ~/.aws/credentials` and asserts
   EACCES (or equivalent denial) rather than the credential contents.

## Files to touch

- `src/session/bash_jobs.rs` (test module)

## Gate

- `cargo test --features landlock-tests` (or the chosen feature name)

## Done condition

The test exists, is Linux-gated (Cargo feature + runtime kernel
check), and passes on a landlock-capable kernel (>= 5.13). It skips
cleanly on unsupported kernels, not fails. No silent deferral.
