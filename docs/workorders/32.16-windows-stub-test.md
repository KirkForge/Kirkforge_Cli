# Workorder 32.16 — WO 28.8 R6 — Windows Stub Fallback Test

## Status: Pending

## Problem

WO 28.8 R6 deferred a `#[cfg(not(unix))]` test asserting the daemon
client's Windows stub fallbacks (`try_touch`, `try_list_recent`)
return `Ok(None)` instead of erroring. The stubs exist and are correct;
the test that locks in their contract was deferred because no Windows
runner was available locally to verify it.

## Root cause

Pure test-coverage gap. The `#[cfg(not(unix))]` code path is exercised
only on Windows; a unix dev machine cannot run it. The deferral was
"can't verify locally," not a code blocker.

## Approach

1. Add a `#[cfg(not(unix))]` test module to `src/daemon/client.rs`
   that calls `try_touch` and `try_list_recent` and asserts both
   return `Ok(None)`.
2. The test compiles only on Windows / non-unix, so it does not affect
   unix CI.
3. Wire the Windows CI job to run it (if a Windows job exists in
   `.github/workflows/ci.yml`; if not, note that as a separate gap).

## Files to touch

- `src/daemon/client.rs` (test module)

## Gate

- CI Windows job passes

## Done condition

The `#[cfg(not(unix))]` Windows stub fallback test exists, asserts
`try_touch` / `try_list_recent` return `Ok(None)`, and passes in the
Windows CI job. The contract is locked in, not just implied.
