# Workorder 32.17 — WO 28.16 R4 — Anthropic computer_use Coordinate-Vision Loop

## Status: Pending

## Problem

WO 28.16 R4 — the Anthropic `computer_use` coordinate-vision execution loop —
has been re-deferred THREE times (WO 25.18-R2 → WO 26.7-R4 → WO 28.16). This
is the most persistent deferral in the repo. R1-R3 shipped (adapter wire
format for the `computer_use` tool, default-OFF behind the `computer_use`
Cargo feature). R4 — the actual screenshot→action loop — never started.

What remains:

1. Screenshot capture via the CDP (Chrome DevTools Protocol) path.
2. The model-turn → coordinate-action execution loop: model emits a
   `computer_use` tool call with `{action, coordinate, ...}`, the host
   captures a screenshot, dispatches the action at the coordinate, and feeds
   the resulting screenshot back as the tool result for the next model turn.
3. `computer_use.hosted` config flag wiring (distinguishes hosted-CDE vs
   local-browser execution environments).

## Root cause

Each prior deferral kicked because R4 spans three layers at once (CDP capture,
turn loop, config) and no workorder isolated them. The persistent deferral is
a scope-discipline failure, not a technical blocker — R1-R3 proved the wire
format works; the loop is the unbuilt last mile.

## Approach

1. Implement screenshot capture over the existing CDP path (the
   `BrowserSessionOwner` pattern from AGENTS.md §7 keeps `Browser` alive
   alongside `Tab` — reuse it; do not drop the `Browser` before the
   screenshot returns).
2. Implement the turn loop: tool-call dispatch → coordinate-action →
   screenshot → tool-result. Terminate on model stop or operator interrupt.
3. Wire `computer_use.hosted` in the config layer (update `Default` impl,
   struct def, test `Config` literals per AGENTS.md §7 — `Config` field
   additions touch ALL of those sites).
4. Keep R4 behind the existing `computer_use` Cargo feature (default-OFF).

## Files to touch

- `src/tools/computer_use.rs` — screenshot capture, coordinate-action dispatch, turn loop
- `src/adapters/anthropic/` — wire the `computer_use` tool result back into the next turn
- `src/shared/config/` — `computer_use.hosted` flag (Default + struct + test literals)

## Gate

- `cargo test --features computer_use`

## Done condition

The coordinate-vision loop works end-to-end: screenshot → model →
coordinate-action → execute → screenshot fed back. `computer_use.hosted` is
configurable. Default-OFF is preserved. No silent deferral of any sub-piece.
