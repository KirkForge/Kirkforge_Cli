# Workorder 32.2 — Fix Stale plugin_verify Deferral Message

## Status: Pending

## Problem

`src/session/plugin_tools/native.rs:229-238` defines `deferred_message()` which
three plugin tools (`PluginVerify`, `PluginVerifyWorkspace`, `PluginAuditVerify`)
return to the user:

```
{cmd}: not yet implemented as a native Rust call (WO 29.1 Phase 1). The
orchestrator crate landed in WO 29.7 but its model client is still a stub
(PanickingClient); the verification pipeline + audit hash-chain need a real
model-backed path before these tools do real verification.
```

The message blames the **hash-chain** (WO 29.4) as a blocker — but WO 29.4 shipped:
- `src/shared/audit.rs:553` — `verify_chain()` implemented
- 32 tests pass (`memory_sink_verifies_chain_integrity`, `memory_sink_detects_tampered_chain`, etc.)
- `src/shared/audit.rs:1006` comment: "WO 29.4 hash-chain + sink ports"

The only real blocker is the `ModelClient` production impl (WO 29.7 residual — 1
`PanickingClient` test stub, 1 use site in `delegate.rs:77`). The message is stale
w.r.t. WO 29.4 and should point only at the `ModelClient` impl as the remaining
dependency.

## Root cause

The deferral message was written when WO 29.4 (hash-chain) was still planned. WO
29.4 shipped, but the message was never updated. The review (8th ed §3.3) flagged
this: "the deferral messages are stale and should be replaced."

## Approach

Update `deferred_message()` at `native.rs:229-238` to:
1. Remove the hash-chain blame (it shipped).
2. Point only at the `ModelClient` production impl (WO 29.7 residual) as the
   remaining blocker.
3. Keep the honest "not yet implemented" framing — the tools genuinely don't do
   real verification yet.

Suggested message:
```
{cmd}: not yet implemented as a native Rust call (WO 29.1 Phase 1). The
orchestrator crate (WO 29.7) and audit hash-chain (WO 29.4) both shipped, but
the ModelClient trait still has no production impl (PanickingClient stub only);
these tools need a real model-backed path before they do real verification.
```

## Files to touch

- `src/session/plugin_tools/native.rs:426` — the test asserts
  `content.contains("not yet implemented")`; verify it still passes after the
  message change (the phrase "not yet implemented" is retained, so it should).
