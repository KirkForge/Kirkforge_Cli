# Workorder 32.20 — WO 31.2 / 31.3 / 31.5 — Node, Go, Generic Verifiers

## Status: Pending

## Problem

Three multi-language verifiers from WO 31.x were scoped but never started:

1. **WO 31.2 — Node/TypeScript.** `node_test.rs` (npm test / vitest) +
   `node_lint.rs` (eslint / `tsc --noEmit`).
2. **WO 31.3 — Go.** `go_test.rs` (`go test`) + `go_vet.rs` (`go vet`).
3. **WO 31.5 — generic fallback.** `make test` / `ctest` / `./test.sh`.

The `Node` and `Go` variants already exist in
`src/session/verifier/detect.rs` (WO 31.4 shipped the detection layer). The
verifier pattern is established by the Python verifiers (WO 31.1 shipped).
This is pattern-following work, not greenfield design.

## Root cause

WO 31.1 (Python) shipped the pattern; WO 31.4 (detect) shipped the language
detection. The actual Node/Go/generic verifier implementations were sequenced
after Python and never picked up. The detection layer points at verifier
files that don't exist yet.

## Approach

1. Follow the Python verifier pattern (WO 31.1) exactly — one file per
   verifier, same `Verdict::Fixable` feedback shape on failure.
2. **Node**: `node_test.rs` runs `npm test` (or `vitest` if configured),
   `node_lint.rs` runs `eslint` and/or `tsc --noEmit`.
3. **Go**: `go_test.rs` runs `go test ./...`, `go_vet.rs` runs `go vet ./...`.
4. **Generic**: `generic_test.rs` tries `make test`, then `ctest`, then
   `./test.sh` — first that exists wins.
5. Wire each into `detect.rs` so the detection layer (already shipped)
   dispatches to the new files.
6. Non-zero exit / lint warnings → `Verdict::Fixable` with the command output
   attached, matching the Python verifier's contract.

## Done condition

All three language verifiers (Node, Go, generic) detect, run, and feed back
`Verdict::Fixable` on failures. `detect.rs` dispatches to the new files. The
Python verifier pattern is followed, not reinvented.
