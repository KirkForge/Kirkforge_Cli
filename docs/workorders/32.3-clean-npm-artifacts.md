# Workorder 32.3 — Clean Up Untracked npm/ Build Artifacts

## Status: Done (`npm/` directory removed; 0 files)

## Problem

The `npm/kf-plugin/` TS *source* was deleted in WO 29.9 (`548463b`/`3ddb2d7`).
Zero tracked files remain (`git ls-files npm/` → 0). Zero TS source files remain
(all `.ts` files in `npm/` are in `node_modules/` from deps).

But the directory still exists on disk with **3928 untracked files**:
- `npm/kf-plugin/dist/` — 117 `.js` + 117 `.d.ts` stale build artifacts
- `npm/kf-plugin/node_modules/` — installed deps
- `npm/kf-plugin/tsconfig.tsbuildinfo` — stale TS build cache

All gitignored (`.gitignore` has `dist/` + `*.tsbuildinfo` + `node_modules/`),
so they don't appear in `git status` and don't affect CI. But they make the
review's "npm/ deleted entirely" claim technically false (the directory exists),
and they're 3928 stale files cluttering the workspace.

## Root cause

WO 29.9 deleted the TS *source* files (`src/` directories under
`npm/kf-plugin/packages/` and `npm/kf-plugin/apps/`) but didn't clean up the
build output (`dist/`) or installed deps (`node_modules/`). The `.gitignore`
patterns hid them from `git status`, so they were invisible to the worker.

## Approach

```bash
rm -rf npm/
```

Then verify:
- `git status` — no change (nothing was tracked)
- `cargo check --workspace --all-targets` — still compiles (nothing in `npm/`
  is referenced by the Rust build)
- `find npm -type f 2>/dev/null | wc -l` → 0 (directory gone)

## Files to touch

- `npm/` — `rm -rf` (no tracked files, purely untracked artifacts)

## Gate

- `git status` shows clean tree (no change — nothing was tracked)
- `cargo check --workspace --all-targets` — compiles
- `find npm -type f 2>/dev/null | wc -l` → 0

## Done condition

`npm/` directory is gone. No stale build artifacts on disk. The review's "npm/
deleted entirely" claim is now literally true.
