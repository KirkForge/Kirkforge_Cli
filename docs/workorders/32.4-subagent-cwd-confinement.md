# Workorder 32.4 — Subagent CWD Confinement

## Status: Done (`landlock_extra_paths` includes `sandbox_dir` in `task_spawner.rs:322-344`)

## Problem

WO 30.1 shipped subagent worktree isolation — the coder persona gets an isolated
git worktree (`src/session/worktree.rs:14-99`, `git worktree add --detach`). But
bash `cd /` escapes the worktree — landlock is the real FS boundary, not the
worktree. The review (8th ed §5) flags this as a known limitation. It's been open
since WO 30.1 and is the dependency for WO 32.5 (parallel orchestration).

## Root cause

Git worktrees confine the *repository content* (checked-out files), not the
*process working directory*. A `cd /` in bash moves the process CWD outside the
worktree. Landlock FS confinement (`src/session/bash_runner/landlock.rs`) is the
real boundary — it restricts which paths the process can read/write regardless of
CWD. But landlock is applied per-bash-invocation, not per-worktree-session.

## Approach

The fix is NOT to confine CWD (that's fragile and bypassable). The fix is to
ensure landlock is applied with the worktree path as the workspace root for
subagent bash calls. Currently `resolve_paths(workspace, &[])` uses the parent
session's workspace. For subagent bash calls, it should use the worktree path.

1. In `src/session/task_spawner.rs` (or wherever the subagent's bash runner is
   configured), pass the worktree path as the workspace for landlock
   `resolve_paths()`.
2. This means subagent bash calls get landlock-confined to the worktree's path
   tree — `cd /` works but writes outside the worktree hit `EACCES`.
3. Verify: a subagent bash call that tries `cat /etc/passwd` or `touch /tmp/foo`
   fails with EACCES when landlock is enabled.

## Gitnexus impact

`dispatch_tool_call_batch` (HIGH risk, 3 processes: run_turn_collecting,
run_turn_inner, run_turn) is the hot path that dispatches bash calls. The change
is in how the workspace path is resolved for subagent calls, not in the dispatch
logic itself — so the impact is contained to the spawner config, not the
executor hot path.

## Files to touch

- `src/session/task_spawner.rs` — pass worktree path as workspace for landlock
- `src/session/bash_runner/landlock.rs` — verify `resolve_paths` accepts the worktree path
- `src/session/worktree.rs` — expose the worktree path for the spawner

## Gate

## Done condition

Subagent bash calls are landlock-confined to the worktree path. `cd /` no longer
escapes the FS boundary. Unblocks WO 32.5 (parallel orchestration).
