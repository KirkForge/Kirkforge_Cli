# Workorder 33.0 — CI Architecture Reset + Test Debt Elimination

## Status: In Progress

## Problem

The CI workflow (`.github/workflows/ci.yml`) and test suite have accumulated
historical patches on top of historical patches. Each problem was fixed
locally, but the architecture was never simplified. The result:

- Same targets compiled 4-5x per CI run (check, clippy, test, coverage, e2e)
- No concurrency cancellation (3 pushes = 3 full CI runs)
- Artificial `needs:` dependencies create sequential bottlenecks
- Ollama model tests run on every PR (expensive, flaky)
- Coverage rebuilds the entire workspace under instrumentation on every PR
- `--no-fail-fast` everywhere means broken suites run to completion
- Tests use real sleeps (1s, 2s, 500ms) instead of deterministic synchronization
- Tests mutate global env vars (PATH, KF_CODE_DATA_DIR, API keys) breaking parallelism
- `#[serial]` used to compensate for shared global state
- Real subprocess spawns (Cargo, Clippy, Chrome, Docker, DNS) in "unit" tests
- 64-process bash job spawn in tests
- Binary-spawn e2e tests that should be in-process integration tests

## Architecture target

Three explicit CI tiers:

```
PR / fast feedback (~2-5 min)
├── static (fmt + repo checks)
├── clippy (lint + compile gate)
├── fast-tests (nextest profile: ci-fast)
└── targeted-integration (changed packages only)

Post-merge (~10-15 min)
├── full-tests (nextest profile: ci-full)
├── windows
├── e2e (feature-gated, in-process where possible)
└── platform-build

Nightly / scheduled
├── ollama (real model tests)
├── coverage
├── exhaustive e2e
├── slow/external tests
├── dependency audit
└── benchmarks
```

## Gate

- `cargo test -p kf-budget-core --test adr_xref_drift`
- `cargo check --workspace --all-targets`
- CI YAML validates
- `git status` clean tree

## Success criteria

- PR CI runs in <5 min
- No redundant compilation
- No artificial sequential dependencies
- Ollama/coverage not on PR path
- Tests don't sleep, mutate global state, or spawn subprocesses unnecessarily
