# WO 33.11 — Profile: Measure Top-20 Slowest Tests

## Status: Pending

## Problem
We're guessing at which tests are slow. Need actual wall-clock data
before optimizing.

## Approach
1. Run `cargo nextest run --workspace --lib --no-fail-fast -j4` with
   `--verbose` or use nextest's slow-test reporting.
2. Collect per-test wall-clock times.
3. Sort descending. Report top-20.
4. Map each to a WO 33.12-33.14 fix category (sleep, env, subprocess).

Do NOT run `--workspace` if it hangs — run per-package instead:
```
cargo nextest run -p kf-code --lib -j4
cargo nextest run -p kf-budget-core -j4
cargo nextest run -p kf-routing -j4
cargo nextest run -p kf-orchestrator -j4
cargo nextest run -p kf-memory-store -j4
```

Use `--final-status-level slow` or parse JUnit XML for timings.

## Files
- `.config/nextest.toml` (if created by 33.5)
- Report: paste top-20 into `docs/workorders/33.11-slowest-tests.md`

## Gate
- Top-20 list with wall-clock times
- Each mapped to a fix category
