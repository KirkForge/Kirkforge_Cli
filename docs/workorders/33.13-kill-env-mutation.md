# WO 33.13 — Kill Global Env Mutation in Tests (Phase 2)

## Status: Pending

## Problem
Tests mutate global process environment (`std::env::set_var`,
`std::env::remove_var`) for:
- `KF_CODE_DATA_DIR` (session_index, config tests)
- `PATH` (verifier/security tests)
- `*_API_KEY` (Anthropic, Bedrock auth tests)
- `current_dir()` mutations

This breaks parallel test execution and forces `#[serial]` usage.

## Approach
1. Inject config/env via dependency injection, not global mutation.
2. Where code reads env vars directly, add a constructor that accepts
   the value as a parameter.
3. For tests that MUST touch env vars, isolate them:
   - Use `std::sync::Mutex` (not `#[serial]`) to serialize env access
   - Or: run in a subprocess via `Command::env()` instead of mutating
     the test process's env
4. Replace `KF_CODE_DATA_DIR` reads with an injected `data_dir` parameter.

## Files
- `src/session/session_index.rs` + tests
- `src/session/verifier/security.rs` + tests
- `src/adapters/anthropic/mod.rs` auth tests
- `src/adapters/bedrock/mod.rs` auth tests
- `src/session/config/mod.rs` + tests

## Gate
- `cargo nextest run -p kf-code --lib` (targeted modules) passes
- `grep -rn 'set_var\|remove_var' src/` shows only production code,
  not test code (except isolated subprocess tests)

## Done
Zero `std::env::set_var`/`remove_var` in test code. #[serial] count
reduced.
