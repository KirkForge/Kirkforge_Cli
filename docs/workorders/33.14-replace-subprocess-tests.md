## Problem
"Unit" tests spawn real subprocesses:
- Verifier tests spawn real `cargo`/`clippy`
- `tools/web_fetch` does real DNS NXDOMAIN (~10s each)
- `tools/computer_use` launches real Chrome
- `tools/bash` Docker-dependent tests
- `session/bash_jobs.rs` spawns 64 real `sleep 30` processes
- E2E scenarios spawn the kf-code binary

## Approach
1. Abstract `Command` execution behind a trait. Test with a fake
   executor that returns canned results.
2. For DNS: inject a resolver trait. Unit-test SSRF logic against
   fake responses. Keep 1 real DNS smoke test.
3. For Cargo/Clippy: mock the command runner. One integration test
   for real invocation.
4. For Chrome: fake browser driver. Keep browser tests in nightly.
5. For Docker: fake Docker client. One smoke test in nightly.
6. For 64-process bash job test: replace with fake process impl.
7. Collapse binary E2E tests into in-process integration tests using
   WireMock (the `wiremock_integration.rs` pattern already exists).
