# WO 33.16 — Config-Overwrite-on-Install Bug

## Status: Pending

## Problem
New installs overwrite existing `config.toml` with defaults, losing
user customizations. `load_or_create_config()` checks `path.exists()`
and only writes if the file doesn't exist — BUT if the data directory
changed between versions (e.g. XDG path change), the old config is
orphaned and a new default is written.

## Root cause
`config_path()` resolves via `data_dir()` which uses
`directories::ProjectDirs`. If the project name or qualifier changes,
the path changes. The old config still exists at the old path but
the new binary looks at a new path, sees nothing, and writes defaults.

## Approach
1. On startup, if config doesn't exist at the new path, check common
   legacy paths and migrate the config if found.
2. Add a `kf-code config migrate` subcommand for manual migration.
3. Never overwrite an existing config — `load_or_create_config` already
   does this, but add a test to pin the contract.
4. Log a warning if a legacy config is found and migrated.

## Files
- `src/session/config/mod.rs` — migration logic
- `src/session/mod.rs` — legacy path detection
- `src/main/` — `config migrate` subcommand

## Gate
- `cargo test -p kf-code --lib session::config` passes
- Test: existing config is NOT overwritten on install
- Test: legacy config is migrated to new path

## Done
Config survives version upgrades. Legacy paths checked + migrated.
