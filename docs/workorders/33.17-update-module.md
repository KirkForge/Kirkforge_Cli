# WO 33.17 — Update Module (Auto-Pull Latest from Main)

## Status: Pending

## Problem
No self-update mechanism. Users must manually run install.sh to get
new versions. We want: every commit on main = a version number, and
kf-code can self-update by pulling the latest release.

## Version scheme (per user spec)
- `0.3.X` — locked. We're at `0.3.8` currently (note: Cargo.toml says
  3.8.0 but the user wants 0.3.X semantics where 0.3 is locked and
  only the last digit moves, up to 100).
- Only commits on `main` increment the version.
- `0` and `3` don't move without explicit user agreement.
- Only the `8` moves: 8 → 9 → ... → 100, then we talk.

Wait — Cargo.toml currently says `3.8.0`. The user said "we are at
0.3.8". Need to clarify: is the current version `3.8.0` (Cargo.toml)
or `0.3.8` (user's mental model)? The user said "ensure that the 0.3
are locked until we both agree its moved and only the last one the 8
is moved up to 100". This means: `0.3.8` → `0.3.9` → ... → `0.3.100`.

## Approach
1. Add `kf-code update` subcommand that:
   - Fetches the latest release tag from GitHub API
   - Downloads + verifies checksum (reuse install.sh logic)
   - Replaces the binary in-place
   - Reports what changed (CHANGELOG since current version)
2. On startup, optionally check for new version (non-blocking, cached).
3. `scripts/bump-version.sh` — automate the per-commit version increment
   on main merges (CI job or post-merge hook).

## Files
- `src/main/` — `update` subcommand
- `src/main/handle_update.rs` (new)
- `scripts/bump-version.sh` — adapt for 0.3.X scheme
- `Cargo.toml` — version (0.3.8 per user, or 3.8.0 — clarify)

## Gate
- `cargo test -p kf-code --lib main` passes
- `kf-code update --check` reports current vs latest without installing
- Manual: `kf-code update` pulls + installs latest

## Done
`kf-code update` works. Version scheme is 0.3.X with auto-increment
on main commits.
