# WO 33.3 — Split CI into PR / Post-merge / Nightly

## Status: Pending

## Problem
One monolithic ci.yml does PR validation, full tests, Windows, E2E,
Ollama, coverage, and release builds. Different purposes, different
schedules, all blended together.

## Approach
Split into three workflow files:
1. `.github/workflows/ci-pr.yml` — static + clippy + fast-tests +
   targeted-integration. Triggers: PR to main/dev. Target <5 min.
2. `.github/workflows/ci-merge.yml` — full-tests + windows + e2e +
   platform-build. Triggers: push to main/dev. Target ~10-15 min.
3. `.github/workflows/ci-nightly.yml` — ollama + coverage + exhaustive
   e2e + slow tests + dep audit. Triggers: schedule (nightly) +
   manual. Target: no limit.

Move existing ci.yml content into the appropriate file. Delete old
ci.yml when done.

## Files
- `.github/workflows/ci.yml` → split into 3 files
- `.github/workflows/ci-pr.yml` (new)
- `.github/workflows/ci-merge.yml` (new)
- `.github/workflows/ci-nightly.yml` (new)

## Gate
- All 3 YAMLs valid
- PR workflow triggers on PR only
- Nightly triggers on schedule only

## Done
Three separate workflows with correct triggers.
