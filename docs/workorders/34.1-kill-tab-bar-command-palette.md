## Status: Partially done (WO 34.1)

Tab bar removed + header added; `ActiveTab::None` default; command palette
(Ctrl+K) shipped with all 12 actions; Ctrl+M/S/J/,/P direct shortcuts; F-key
fallback retained; Esc clears overlays; mouse row-0 tab-bar click removed.

**DEFERRED (step 5 — overlay-on-top-of-chat rendering):** overlays currently
render in the main content area (replacing the chat view, matching pre-34.1
behavior) instead of as centered/right-docked popups over a visible chat
surface. *Why:* centered-popup composition over a live chat surface needs a
`Clear`+popup layout pass that interacts with the approval-dialog / doom-banner
z-ordering — a bigger layout change than fits this session without risking
that z-ordering. *Remaining:* render each overlay into a centered `Rect` via
`Layout` inside `chunks[1]` (or a right-docked pane), preceded by `Clear` so
the chat shows through the borders; reconcile with the approval dialog + doom
banner z-order (both already use `Clear`+centered popups — copy that pattern).
*Tracked:* `ponytail:` comment in `src/tui/mod.rs:render_app`, this workorder

## Problem

`src/tui/widgets/tabs.rs:18` renders a persistent 6-tab bar
(`F1:Chat │ F2:Models │ F3:Plugins │ F4:Jobs │ F5:Settings │ F6:Sessions`)
that occupies screen real estate on every frame. `src/tui/app.rs:125-142`
defines `ActiveTab` with F-key mappings. Most users never touch
Models/Plugins/Settings during a coding session — the tabs are spatially
expensive and mentally noisy.

## Root cause

The TUI was designed as "expose every capability" rather than "show what
you need for the current task." The tab bar is the most visible symptom.

## Approach

1. **Remove the persistent tab bar** from `render_tab_bar` in
   `src/tui/widgets/tabs.rs`. The top of the screen becomes a simple
   header: app name + model + ready/busy indicator.
2. **Make Chat the permanent primary surface.** `ActiveTab::Chat` becomes
   the only non-overlay view. All other tabs become overlay drawers.
3. **Introduce a command palette (Ctrl+K).** A new overlay component
   (`src/tui/widgets/command_palette.rs`) that:
   - Shows a search input + filtered action list
   - Actions: "Change model", "Open sessions", "View jobs", "Open
     settings", "Search conversation", "Compact conversation", "Open
     plugins", "Show help", "Run tests", "Commit changes"
   - ↑↓ navigates, Enter activates, Esc closes
   - Fuzzy-matches the query against action names
4. **Route F2-F6 to direct shortcuts** as aliases:
   `Ctrl+M` → Models overlay, `Ctrl+S` → Sessions overlay,
   `Ctrl+J` → Jobs overlay, `Ctrl+,` → Settings overlay,
   `Ctrl+P` → Plugins overlay. F-keys still work as fallback for muscle
   memory but are not shown in the UI.
5. **Overlay rendering:** each former tab renders as a centered or
   right-docked overlay on top of the chat surface, not as a full-screen
   replacement. The chat surface stays visible underneath.
6. **`ActiveTab` enum:** keep it but add `ActiveTab::None` (chat-only
   mode). F-key/Ctrl-shortcut sets the active overlay tab; Esc clears it
   back to `None`. The tab bar is not rendered.
