# WO 34.11 — Doc audit: CHANGELOG, state.md, TECHNICAL.md vs codebase

## Status: Pending

## Problem

CHANGELOG.md and state.md have been neglected for multiple sessions. The
AGENTS.md workflow (lines 119-120, 124) mandates updating CHANGELOG.md +
state.md + TECHNICAL.md in the same commit as code changes, but this has
not been consistently followed. Documentation may be stale relative to
the actual codebase state after the WO 33 + kf-rbac + test optimization
sessions.

## Root cause

The doc-sync rule is in AGENTS.md but wasn't enforced by subagents. The
recent sessions (WO 33.6, 33.14, 33.15, 33.16, 32.17, 32.20, kf-rbac
JWKS, sleep elimination, env mutation, CI reset, build_docker_args,
check_job_cap) each updated docs individually, but cross-document
consistency was not verified. TECHNICAL.md may not reflect the CI
architecture reset (ADR-074), the JwksResolver trait, the
CommandRunner trait, or the new verifier modules.

## Approach

1. **Audit CHANGELOG.md**: read the full [Unreleased] section. Verify
   every entry matches a commit in `git log origin/dev`. Remove any
   entry that doesn't correspond to a real change. Add missing entries
   for commits that have no CHANGELOG line.
2. **Audit state.md**: verify every session entry matches reality. Check
   that the "Deferred items" section is current (items 3 is now DONE —
   computer_use R4 shipped in WO 32.17). Check that "Gate status"
   reflects the actual current gates. Remove stale entries.
3. **Audit docs/TECHNICAL.md**: verify the TUI section, verifier section,
   CI section, and adapter section reflect the current codebase. Key
   things to check:
   - Does TECHNICAL.md mention the CommandRunner trait (WO 33.14)?
   - Does it mention the JwksResolver trait (kf-rbac)?
   - Does it mention the Node/Go/Generic verifiers (WO 32.20)?
   - Does it mention the hosted computer_use beta (WO 32.17)?
   - Does the CI section reflect the ADR-074 reset (static job, no
     cargo check, Ollama nightly-only)?
   - Does the ADR count match `ls docs/adr/*.md | wc -l`?
   - Does the test section mention the nextest profiles?
4. **Audit docs/adr/README.md**: verify every ADR file has a row, every
   row's status matches the file header, and the count matches
   TECHNICAL.md. Run `cargo test -p kf-budget-core --test adr_xref_drift`
   to verify.
5. **Audit docs/workorders/README.md**: verify the WO index is current.
   Add WO 34 series entries.
6. **Cross-check**: for each "Done" item in state.md, grep the codebase
   to verify the change actually exists. For each "Pending" item, verify
   it's genuinely still pending (AGENTS.md §7: "stale cleanup items are
   a real risk").
7. **AGENTS.md verification**: confirm that the doc-sync rules
   (CHANGELOG, state.md, TECHNICAL.md) are explicitly in the worker
   contract. If they're not clear enough, strengthen the wording.
