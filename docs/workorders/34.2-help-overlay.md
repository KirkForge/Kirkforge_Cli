# WO 34.2 — /help overlay (stop polluting conversation)

## Status: Pending

## Problem

`src/tui/keys/slash_commands.rs:364-372` pushes the full help text (~80
lines of formatted command table) as a `ConversationEntry::new("system",
help_text(...))` into `state.conversation.messages`. This pollutes the
conversation history with documentation — the user has to scroll past it
every time they ask for help, and it persists in the session log.

## Root cause

/help was implemented as a conversation message because there was no
overlay infrastructure when it was written. The codebase now has overlay
infrastructure (search panel, slash-menu popup, approval dialog).

## Approach

1. Create `src/tui/widgets/help_overlay.rs` — a centered overlay that
   renders the help text in a scrollable bordered box with an Esc-to-close
   hint.
2. Add `state.ui.help_overlay_visible: bool` to `AppState`.
3. Change `/help` dispatch (slash_commands.rs:364) from
   `state.conversation.messages.push_back(...)` to
   `state.ui.help_overlay_visible = true`.
4. Render the overlay in `src/tui/mod.rs` render loop: if
   `help_overlay_visible`, render the help overlay on top of the chat
   surface.
5. Esc closes the overlay (add to events.rs key handler).
6. ↑↓ scrolls the help text (add a scroll state field).
7. The `help_text()` function stays — it generates the text. The overlay
   renders it instead of the conversation.

## Files to touch

- `src/tui/widgets/help_overlay.rs` — NEW
- `src/tui/app.rs` — add `help_overlay_visible` + scroll state
- `src/tui/keys/slash_commands.rs` — change /help dispatch
- `src/tui/mod.rs` — render overlay
- `src/tui/events.rs` — Esc/↑↓ handling when overlay visible

## Gate

- `cargo clippy -p kf-code --lib --tests -- -D warnings`
- `cargo fmt --check`
- `cargo nextest run -p kf-code --lib tui::`
- /help opens an overlay; conversation history stays clean; Esc closes

## Done condition

/help opens a scrollable overlay. The conversation is not polluted.
Session logs no longer contain help text.
