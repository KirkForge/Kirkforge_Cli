# WO 34.4 — Settings: config dump → semantic controls

## Status: Pending

## Problem

`src/tui/widgets/tabs.rs:257-341` renders Settings as raw config field
names: `default_model: {}`, `ollama_host: {}`, `auto_approve: {}`,
`sandbox_dir: {}`, `block_dotfiles: {}`, `bang_requires_approval: {}`.
This is configuration-file output masquerading as UI.

## Root cause

Settings was implemented as a direct config-struct dump with
`format!("   field_name:       {}", value)`. No semantic abstraction.

## Approach

1. Group settings semantically:
   - **MODEL**: Default model, Provider, Context window
   - **SAFETY**: Command approval (auto_approve → "Always ask" / "Auto-approve
     safe"), Sandbox (sandbox_dir → "Project" / "None"), Hidden files
     (block_dotfiles → "Blocked" / "Allowed")
   - **TOOLS**: Dry run, Follow symlinks
2. Use human-readable values, not config-struct values:
   - `auto_approve: true` → "Auto-approve safe commands"
   - `block_dotfiles: true` → "Blocked"
   - `sandbox_dir: Some("/path")` → "Project root"
3. Interactive: ↑↓ navigates, Enter cycles/toggles, Esc closes.
4. Keep a "Raw config" section at the bottom (collapsed) for developers
   who want to see the actual field values.
5. Don't add edit capability in this WO — that's a future task. This is
   about display, not editing.

## Files to touch

- `src/tui/widgets/tabs.rs` — rewrite `render_settings`

## Gate

- `cargo clippy -p kf-code --lib --tests -- -D warnings`

## Done condition

Settings displays "Command approval: Auto-approve safe" not
"auto_approve: true". Grouped by MODEL / SAFETY / TOOLS. Raw config
available in a collapsed section.
