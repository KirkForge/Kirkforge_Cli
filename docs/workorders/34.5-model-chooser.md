# WO 34.5 — Models tab → model chooser

## Status: Done

## Problem

`src/tui/widgets/tabs.rs:63-138` shows Models as a diagnostic dump:
connection state, uptime, model info, adapter routing, token usage, cost.
Those are different concepts mixed together. The primary action (switch
model) is buried among diagnostics.

## Approach

1. Split into a chooser list + a details section:
   - **Chooser**: radio-list of available models with ●/○ indicators.
     `↑↓` navigates, `Enter` switches, `Esc` closes.
   - **Details** (below the chooser or in a separate view): provider,
     context window, routing, cache, tokens, cost.
2. The chooser is the primary view; details are secondary (press `D` or
   `Enter` on a model to see details, `Esc` returns to chooser).
3. Available models come from the config's model list + any
   runtime-discovered Ollama models.
4. Current model is marked with ● and "Current" label.

## Files to touch

- `src/tui/widgets/tabs.rs` — rewrite `render_models` as chooser + details
- `src/tui/app.rs` — model list state if needed
- `src/tui/events.rs` — chooser navigation keys

Models shows a chooser first. Switching models is one Enter press.
