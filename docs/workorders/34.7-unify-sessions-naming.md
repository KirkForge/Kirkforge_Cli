# WO 34.7 — Unify Sessions/Threads/Forks naming

## Status: Pending

## Problem

The codebase uses multiple names for the same concept: `ActiveTab::Threads`
(F6, labeled "F6:Sessions"), `/sessions` command, `/resume` command,
`/fork` command, session picker. "Threads" is an implementation concept
that users don't understand.

## Approach

1. Rename `ActiveTab::Threads` to `ActiveTab::Sessions` in `app.rs`.
2. Update the label from "F6:Sessions" to just "Sessions" (no F-key
   prefix in the UI — WO 34.1 removes the tab bar).
3. The Sessions view shows:
   - **RECENT**: list of recent sessions with timestamp + message count
   - **FORKS**: list of forks with label
4. Actions: `Enter` resume, `Ctrl+F` search, `Ctrl+D` delete, `F` fork,
   `Esc` close.
5. `/sessions`, `/resume`, `/fork` slash commands still work but the
   primary interaction is through the Sessions overlay.
6. Remove the word "Threads" from user-visible UI. Keep it in code
   identifiers only if renaming would cause excessive churn (note in
   lessons.md if so).

## Files to touch

- `src/tui/app.rs` — rename `ActiveTab::Threads` → `ActiveTab::Sessions`
- `src/tui/widgets/tabs.rs` — update render function name + content
- `src/tui/events.rs` — update key dispatch
- `src/tui/mod.rs` — update render routing

## Gate

- `cargo clippy -p kf-code --lib --tests -- -D warnings`
- `cargo fmt --check`
- `cargo nextest run -p kf-code --lib tui::`

## Done condition

User-visible UI says "Sessions" everywhere. "Threads" is gone from the
interface. Forks are a subsection of Sessions.
