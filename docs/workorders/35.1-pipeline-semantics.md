# WO 35.1 — Real pipeline semantics for scout/coder/reviewer

## Status: Done

Note: single scout kept (the Approach sketch allowed "scout(s)"; a
multi-scout fan-out was not introduced, so gate test (d) — scouts still
overlap — is vacuous here). The prompt double-wrap fix rippled wider than
this WO knew: WO 35.2/35.3 added raw-prompt `run_task` callers
(`tools/workflow.rs` StepRunner used by jobs/runner.rs, TUI/Line
StepRunners), all now applying `build_task_prompt` themselves — the
`TaskSpawner` contract is prompt-verbatim.

## Problem

The "parallel orchestration" is a fan-out, not a pipeline. All three
roles start simultaneously
(`parallel_orchestrator.rs:96-101`, `tokio::join!`); the coder is told
"You may not have its context yet — proceed with your own judgment"
(189-193); the scout's summary lands in `ParallelResult.scout.summary`
and is used only for the final display string (`summary()`, 36-51) —
never passed to the coder; the reviewer's prompt is built from the task
description alone, so it reviews the task, not the coder's changes —
**in both parallel and sequential mode**. The module docs and scout
prompt ("Produce a concise context summary for the Coder", 187)
overclaim what the code does.

## Root cause

`build_role_prompt(role, persona, task)` takes only the original task
description; `spawn_role` passes nothing between roles; each subagent
gets a fresh temp conversation. No channel, no handoff, no phase
structure exists to sequence through.

## Approach

Restructure `run_parallel` into a real DAG with parallelism where it is
actually independent:

```
Scout(s)            ← may run concurrently (e.g. explore + risk scan)
   ↓ scout summary
Coder               ← own worktree (WO 35.2), prompt includes scout summary
   ↓ diff patch (WO 35.2 artifact return)
Reviewer            ← reviews the Coder's diff + summary, read-only
   ↓ verdict
ParallelResult      ← {scout_summaries, coder_patch, reviewer_verdict}
```

1. Scout phase: run scout (or N scouts) concurrently; collect
   summaries.
2. Coder phase: build the coder prompt as
   `role prompt + task + scout context`; run in its own worktree;
   capture the patch.
3. Reviewer phase: prompt includes the diff + the coder's change
   summary; verdict appended to `ParallelResult`.
4. `run_sequential` gets the same handoffs (it already sequences; it
   just shares the same blind prompts today).
5. Fix honest-doc debt found during verification:
   - Remove or wire the unwired `task_manager()` accessor
     (`parallel_orchestrator.rs:87-88` claims "/jobs view can render
     them" — `/jobs` never reads it; only its own test calls it).
   - Fix the double-wrapped prompts: `spawn_role` builds a role prompt
     that `run_task` wraps AGAIN via `build_task_prompt`
     (`task_spawner.rs:304`), so the coder sees two competing
     "You are..." preambles. One wrapper, not two.
6. Update `summary()` and the TUI consumer
   (`src/tui/commands/workflow.rs:219-244`) for the new result shape.
