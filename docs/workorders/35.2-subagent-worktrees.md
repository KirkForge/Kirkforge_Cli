# WO 35.2 — Per-subagent worktree isolation + artifact return

## Status: Pending

## Problem

Subagents (scout/coder/reviewer, `task` tool) all execute inside the
parent session's single sandbox/worktree. The comment "each subagent
gets its own TaskManager entry" (`parallel_orchestrator.rs:5-6`) is
lifecycle bookkeeping only. Two coders running in parallel mutate the
same filesystem; a reviewer reading concurrently sees half-written
state. This closes the DEFERRED item from WO 32.5 and `state.md:1311`.

## Root cause

`InProcessTaskSpawner::run_task` builds its `ToolContext` from the
parent `Config`: `access_from_config(&cfg)` + `cfg.security.sandbox_dir`
(`task_spawner.rs:152-190`). `WorktreeSession` exists
(`src/session/worktree.rs:14`, `git worktree add --detach`, cleanup on
Drop) but its only production call site is `run_session.rs:132` — one
per session, inherited by every subagent.

## Approach

1. In `run_task` (or a caller-provided option), create one
   `WorktreeSession::create(task_id, repo_root)` per subagent.
2. Clone the parent `Config`, set `cfg.security.sandbox_dir =
   Some(wt.path())` (mirroring `run_session.rs:136`) before
   `access_from_config` — sandbox_dir already fans out to path guard,
   Landlock, and bash workdir.
3. Hold the session binding across the turn loop so Drop fires at
   scope exit.
4. **Artifact return (the hard part):** `run_task` currently returns
   only a summary string; `WorktreeSession::Drop` runs
   `git worktree remove --force`, silently discarding uncommitted
   subagent edits. Before Drop, capture the work: `git diff HEAD` (+
   `git status --porcelain` for untracked) into a patch string or file
   under the parent's sandbox, and include it in the result so the
   caller/main agent can apply it. Read-only roles (scout/reviewer)
   can skip the worktree entirely or share one — only writers need
   isolation.
5. Gate behind `cfg.session.worktree_enabled` (already exists,
   `workflow.rs:215-218`); fallback is today's shared-sandbox behavior.

## Files to touch

- `src/session/task_spawner.rs` — worktree creation, config clone,
  patch capture, result type
- `src/session/parallel_orchestrator.rs` — `spawn_role` passes
  writer/reader role so only the coder gets a worktree
- `src/session/worktree.rs` — only if the patch-capture helper belongs
  here (`diff_patch()` method)

## Gate

- `cargo clippy -p kf-code --lib --tests -- -D warnings`
- `cargo fmt --check`
- `cargo nextest run -p kf-code --lib session:: task`
- New test: two concurrent coder subagents produce disjoint diffs
  (e.g. both edit different files; patches applied sequentially do not
  conflict)
- New test: subagent worktree Drop leaves no `kf-code-session-*` /
  stale worktree entries (`git worktree list` clean)

## Done condition

A coder subagent's filesystem writes land in its own worktree; its
edits return as an appliable patch; Drop cleans up; parallel coders
cannot mutate each other's workspace.
