# WO 35.3 — Cooperative cancellation + temp-dir cleanup

## Status: Pending

## Problem

`TaskManager::cancel()` (`src/tools/task.rs:248-258`) drops the
subagent future mid-flight. Verified consequences, all worse than the
review claimed:

1. **Temp dir leaks** — `run_task`'s cleanup
   (`remove_dir_all`, `task_spawner.rs:347`) is end-of-function, not
   Drop-based, so the `conversation.ndjson` + per-turn checkpoints +
   `.tmp` files leak on cancellation AND on every error path
   (log-open failure 240-243, executor-construction failure 248-256,
   any turn error `?` at 312-315).
2. **Foreground bash survives cancel** — tool calls run as detached
   `tokio::spawn` tasks (`dispatch.rs:293`); a dropped JoinHandle
   detaches (333-335), so the bash child (kill_on_drop) dies only at
   its own `tool_timeout_secs` — up to 120s after the user cancelled.
3. **Background bash jobs survive cancel** — they live in the global
   `BashJobRegistry` (`bash_jobs.rs:57`), orphaned but running.
4. **ParallelOrchestrator has no cancellation path at all** —
   `spawn_role` awaits `run_task` directly (165-168); its TaskManager
   entries are bookkeeping no one listens to.

## Root cause

The cooperative machinery already exists but is not wired:
`tokio-util` CancellationToken is used in `ToolContext`
(`tools/mod.rs:92`), bash (`tools/bash.rs:94`), workflow, jobs; the
executor has `cancelled: Arc<AtomicBool>` checks
(`turn.rs:363,973,1019`, `dispatch.rs:302,371-385`) and aborts
detached tasks on that flag; `run_task` even creates its own
`cancelled` flag (`task_spawner.rs:303`) — **nothing ever sets it**.
`TaskManager::cancel` has no path to any of it. The fix is wiring, not
building. (The existing `ceiling:` comment at `task.rs:505-510` names
exactly this upgrade path.)

## Approach

1. Replace `run_task`'s ad-hoc `cancelled` flag with a real
   `CancellationToken` threaded from `TaskHandle` → `run_task` →
   `run_turn_collecting` → executor (or minimally: have `cancel()`
   set the existing flag + fix the snapshot-at-dispatch issue,
   `helpers/mod.rs:74-82`).
2. On cancel: abort detached tool tasks, kill bash children
   (foreground via the token, background via the registry scoped to
   the subagent), then run cleanup — cooperatively, in `run_task`,
   instead of dropping the future.
3. Make temp-dir cleanup Drop-based (a guard struct whose Drop calls
   `remove_dir_all`) so error paths and panics clean up too.
4. Give the ParallelOrchestrator path a cancel path: select its
   `run_task` awaits against the TaskManager cancel signal (same
   pattern the `task` tool worker already uses), plus a
   `ParallelOrchestrator::cancel_all()`.

- New tests: (a) cancelled subagent's temp dir is removed (no

  kills the child within a bounded window (not tool_timeout_secs);
  (d) ParallelOrchestrator cancel_all stops in-flight roles.

## Done condition

Cancellation is cooperative end-to-end (model request aborted, tools
aborted, bash killed, cleanup run); temp dirs never outlive their
subagent on any path; the `ceiling:` comment at `task.rs:505-510` is
resolved and removed.
