# WO 35.5 — Cross-component integration tests (2 chains)

## Status: Pending

## Problem

The test footprint is large (276 files with test fns) but the two most
important cross-component behaviors have no integration coverage at
all (verified by grep over `tests/` + `crates/*/tests/`):

1. **Subagent lifecycle chain**: agent → subagent → permission →
   workspace → cancellation. Closest existing: unit tests
   (`executor/tests/loop_.rs:117,751` cancel-flag tests) and e2e
   approval scenarios (`tests/e2e/scenarios/tool_approval.rs`) —
   nothing crosses the components, and nothing covers
   `TaskManager::cancel` or the spawner at all.
2. **Context economics chain**: retrieval → compression → budget →
   provider → verification. Closest existing: per-component suites
   (kf-compress-core, kf-budget-core fixtures, live-Ollama
   `integration_test.rs:62`) — no end-to-end chain.

## Root cause

Components were built and tested in verticals; the seams between them
were never under test. The WO 35.1-35.3 changes land in exactly these
seams, so this WO follows them.

## Approach

Use the existing integration-test infrastructure (root `tests/`
harness, mock provider from `tests/mock_ollama.rs`) — no new
framework:

1. **Subagent chain** (requires 35.2 + 35.3): spawn a coder subagent
   against the mock provider; assert it (a) writes inside its own
   worktree, (b) its destructive tool call hits the parent approval
   forwarder, (c) `TaskManager::cancel` mid-turn kills the bash child
   and removes the temp dir, (d) the returned patch applies cleanly.
2. **Context chain**: build a session with a known file corpus; run a
   turn through retrieval (context index) → compression → budget
   accounting → mock provider; assert token accounting matches what
   the provider emitted and that verification ran on the result. Keep
   it deterministic with the mock provider (no live Ollama — that
   stays outside the default gate per AGENTS.md).

## Files to touch

- `tests/` — new integration test files (follow existing harness
  patterns in `tests/integration_test.rs`, `tests/mock_ollama.rs`)
- `docs/workorders/35.0-wo35-overview.md` — none

## Gate

- `cargo nextest run -p kf-code --test <new files>` — green
- `cargo clippy -p kf-code --all-targets -- -D warnings`
- `cargo fmt --check`
- Tests run in the default local gate (`scripts/test-fast.sh` must not
  need live Ollama)

## Done condition

Both chains fail when any seam breaks (spot-check by reverting a seam
locally), pass on the WO 35.1-35.3 implementation, and run in the
default gate.
