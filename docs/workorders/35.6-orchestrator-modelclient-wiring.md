# WO 35.6 — Wire the Executor into kf-orchestrator's ModelClient

## Status: Done (core scope trimmed per owner instruction; follow-ups below)

Completed (owner-trimmed scope):
1. `kf-orchestrator` added to kf-code deps (drags kf-routing,
   kf-memory-store, rusqlite — disclosed; regex/base64/sha2/hex already
   present).
2. `src/session/executor_adapter.rs` — `impl ModelClient for
   ExecutorAdapter` over `InProcessTaskSpawner::run_task_detailed`
   (new inherent method; the `TaskSpawner` trait signature unchanged).
3. Verify commands de-stubbed per their actual promises: `verify` runs
   the security emitter (deterministic — the WO's "run real model calls"
   premise did not match the tools' own descriptions); `audit_verify`
   walks the WO 29.4 hash chain; `verify_workspace` relabeled "not
   implemented (reducer not ported)".
4. ADR-075 records the Emission flattening decision (final assistant
   message + summed usage; session variant rejected — modes parse text).

## Problem

`crates/kf-orchestrator` (4.5k LOC, 71 tests: delegation,
decomposition, correction, workspace, artifact modes, event sink) has
zero runtime consumers — the workspace dep is declared but no crate
depends on it, and its own docs say `ModelClient` has no production
implementation (WO 29.7 deferral; `lib.rs:9-17`, `model.rs:6-8`). The
binary meanwhile runs a second, separate orchestration path
(`ParallelOrchestrator` → `InProcessTaskSpawner`). Overlap is real and
acknowledged in-code: two correction loops, two copies of the 14
security-regexes (`verifier.rs:8-15` ponytail note names the drift
risk), two event surfaces, two task/role concept sets.

## Root cause

Deliberate deferral (WO 29.7/30.0, honestly disclosed). This WO closes
the seam.

## Approach

1. Add `kf-orchestrator` to kf-code's deps; write
   `impl ModelClient for ExecutorAdapter` in `src/session/` wrapping
   the existing `InProcessTaskSpawner::run_task` template
   (`task_spawner.rs:78-349` already does 90% of the adapter job):
   map `TaskBrief.template` → persona/system prompt, run turns, sum
   `TurnEvent` usage into `Emission` token fields, echo the template
   into `Emission.format`.
2. Resolve the semantic mismatch the external review missed:
   `Emission` models ONE model turn; the Executor produces a
   multi-turn tool-using session. Decide + document: adapter returns
   the final assistant message as `content` with summed usage
   (recommended — modes parse text output), or extend `Emission` with
   a session variant. Record the decision in an ADR.
3. Replace the 3 `PanickingClient` stubs in production paths
   (`src/session/plugin_tools/native.rs` plugin-tools verify
   commands) with the adapter.
4. Adapt the crate's `EventSink` to the binary's event bus
   (`sink.rs:4-6` names this seam).
5. Reducer port (~500 LOC per state.md:1752) is explicitly OUT of
   scope here — separate WO if artifact-mode packets are needed.
6. Decide canonical-ness: this WO wires the seam and kills the stubs;
   whether `ParallelOrchestrator` is then reimplemented on top of
   kf-orchestrator is a follow-up decision (after 35.1's semantics
   land), not this WO.
