# WO 35.7 — Version badge consistency gate

## Status: Pending

## Problem

`Cargo.toml` says `0.3.10`, the README badge says `0.3.9`
(`README.md:6`). Neither `scripts/bump-version.sh` (never touches
README) nor `scripts/check-artifact-consistency.sh` (11 gates, no
version gate) catches the drift. Found by external review; trivial but
embarrassing given the release-hygiene work.

## Root cause

The badge is a hand-edited literal with no regeneration or check.

## Approach (smallest that works)

Add a gate to `scripts/check-artifact-consistency.sh`: extract
`version = "X"` from root `Cargo.toml` and `version-X` from the README
badge line; fail if they differ. Do NOT auto-rewrite the badge —
check-only keeps the script side-effect-free like its other gates.
Fix the current badge to 0.3.10 in the same commit.

## Files to touch

- `scripts/check-artifact-consistency.sh` — new gate (~10 lines)
- `README.md` — badge 0.3.9 → 0.3.10

## Gate

- `bash scripts/check-artifact-consistency.sh` → all gates pass
  including the new one
- Temporarily regress the badge → gate fails (verify, then restore)

## Done condition

Badge drift is CI-caught forever; current badge matches Cargo.toml.
