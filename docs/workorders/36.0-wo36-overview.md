# WO 36.0 — Series overview: close the WO 35 remainders, unify orchestration

## Status: In Progress

## Problem

WO 35 landed 7 workorders but left disclosed remainders. This series
closes them. The external review's scorecard gap that matters most is
Subagents (7.5 vs 9-9.5 for Codex/Claude/OpenCode) — every item below
moves that number by making the subagent runtime production-grade.

## The debts (from the WO 35 sessions, all verified)

1. **Unmeasured `rusqlite` in the release binary.** kf-code →
   kf-orchestrator → kf-memory-store drags bundled SQLite into a
   size-optimized binary (`opt-level=z`, fat LTO). Nobody measured.
2. **Background bash jobs survive subagent cancel** —
   `BashJobRegistry` has no owner tracking (WO 35.3 disclosure).
3. **Model streams aren't aborted mid-request** — cancel takes effect
   at the next event/adapter timeout, not immediately (WO 35.3).
4. **Parent prompt-cancel keeps snapshot tokens** — only subagent
   executors attach a live cancel token (WO 15.7 / 35.3).
5. **The unification is staged, not real** — `ExecutorAdapter`
   (ModelClient) has zero production callers; ParallelOrchestrator
   still runs its own path; `EventSink` isn't bridged (WO 35.6).
   Until this lands, we added a dependency without convergence.
