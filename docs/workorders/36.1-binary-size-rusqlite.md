# WO 36.1 — Measure the release binary; decide the rusqlite question

## Status: Pending

## Problem

WO 35.6 added `kf-orchestrator` as a kf-code dependency, dragging
`kf-memory-store` → `rusqlite` (bundled SQLite, C code) into the
release binary. The release profile is `opt-level = "z"` + fat LTO +
1 codegen unit — binary size is an explicit product constraint
(AGENTS.md §0). The dep was justified by a speculative future need
("ParallelOrchestrator-on-kf-orchestrator needs it anyway"), which is
exactly the reasoning the dep rule forbids. Nobody measured.

## Root cause

Missing measurement step before landing the dependency.

## Approach

1. Build the release binary at the dev tip in a clean worktree-local
   target dir: `cargo build --release -p kf-code`. Record size +
   build time (use `--timings` if useful).
2. Compare against the last release-tagged binary (v0.3.6 era is
   ancient; instead compare against a build with the orchestrator dep
   feature-gated off — add `kf-orchestrator = { path = ...,
   default-features = false }` behind a temporary local edit if a
   feature knob exists, or `git revert`-equivalent stash of the dep
   for the measurement build only — do NOT commit the revert).
3. Decision rule: if rusqlite adds more than ~5% to the compressed
   release artifact, add a `memory` feature to kf-orchestrator
   (default OFF in kf-code's dep declaration, ON for the crate's own
   tests) so the binary ships without SQLite until a production
   caller needs it. If under ~5%, keep it and record the number.
4. Record the numbers + decision in `docs/TECHNICAL.md` (dependencies
   section) and flip this WO to Done. If the gate lands, CHANGELOG.

## Files to touch

- `Cargo.toml` (only if the feature gate lands)
- `crates/kf-orchestrator/Cargo.toml` (only if gating)
- `docs/TECHNICAL.md`, this WO file, `CHANGELOG.md` (if gated)

## Gate

- Pasted `ls -l`/`du` numbers for both builds in the report and in
  TECHNICAL.md
- `cargo clippy -p kf-code --lib --tests -- -D warnings` +
  `cargo nextest run -p kf-orchestrator` still green after any gating
- Release artifact sizes from `ls -l target/release/kf-code` (and the
  .gz if the release workflow compresses — check `.github/workflows/release.yml`)

## Done condition

The rusqlite question has a measured answer committed to the docs,
and the binary ships the decided configuration.
