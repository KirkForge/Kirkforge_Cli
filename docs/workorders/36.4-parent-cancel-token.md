# WO 36.4 — Live cancel token for the parent session

## Status: Done

Implemented in `fix(wo36.4)`: `Executor::run` (the TUI's session loop)
installs a fresh per-turn `CancellationToken` via `set_cancel_token` at each
input (tokens are one-shot, so a prior turn's cancel must not leak into the
next); the cancel watcher cancels the current turn's token alongside the
`AtomicBool` flag — the flag and token fire together on the same Esc path.
Per-tool child tokens derive from it (`prepare_batch`), so parent cancel
cascades into in-flight tools while tool timeouts stay independently
triggerable; the stream-await race (WO 36.3) is live for the parent too.
Tests drive the REAL watcher through `cancel_tx.send(())`:
`esc_cancel_aborts_stalled_parent_stream` (stalled stream ends within a 2s
bounded window) and `esc_cancel_cascades_to_live_tool_token` (a tool parked
on its per-call token completes with `Cancelled` on Esc, not at
`tool_timeout_secs`). This resolves the last WO 35.3 deferral — 35.3 is now
Done.

## Problem

WO 35.3 disclosure: only subagent executors attach a live cancel
token. The parent session's prompt-cancel path still uses the WO 15.7
snapshot-token semantics — the token is a one-shot snapshot of the
`cancelled` flag at dispatch time, so a cancel pressed DURING a tool
call or between stream events relies purely on flag polling. With WO
36.3 landing stream-abort, the parent should get the same prompt
cancellation.

## Root cause

`set_cancel_token` is called only in the subagent spawn path
(`task_spawner.rs`); the TUI's cancel watcher (Esc) sets the
`AtomicBool` flag but never constructs/attaches a live token to the
parent executor.

## Approach

1. Find the TUI cancel path (Esc → executor cancel flag; grep
   `is_generating` cancel handling in `src/tui/` and the executor's
   public cancel surface). Attach a `CancellationToken` to the parent
   executor at turn start (or session start), cancelled by the same
   Esc path that sets the flag.
2. The flag and token must fire together everywhere — one small
   helper if the call sites multiply.
3. WO 15.7's snapshot semantics exist for per-tool-call tokens: keep
   child tokens as children of the parent token so per-call
   cancellation remains independently triggerable (tool timeout) while
   parent cancel cascades.
4. Test: parent turn with a stalled tool or stream (build on the WO
   36.3 mock), trigger the TUI-level cancel path (or the executor API
   the TUI calls), assert prompt cooperative exit.
