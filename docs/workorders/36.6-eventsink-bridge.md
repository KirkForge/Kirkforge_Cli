# WO 36.6 — EventSink → EventBus bridge

## Status: Pending (folds into WO 36.5 step 3)

## Problem

kf-orchestrator's `EventSink` (`crates/kf-orchestrator/src/sink.rs:4-6`)
names the seam: "Production wiring adapts it to the binary's
EventBus." Only `NullSink`/`RecordingSink` exist. Artifact events
(emitted/blocked/unterminated/truncated) vanish in production.

## Root cause

Deferred in WO 29.7, still deferred after WO 35.6.

## Approach

Per WO 36.5 step 3: bridge `ArtifactEvent` → the binary's event bus
(`src/shared/event_bus.rs`), or — if the bus's event types don't
accept foreign payloads cheaply — a `TracingSink` that logs artifact
events through the existing structured logging (they'd surface in the
session log). Either way the events stop being swallowed; the choice
and reason goes in TECHNICAL.md.

## Gate

- Unit test: events flow (bus assertion or assert-on-log capture
  where a log sink lands)
- Standard clippy/fmt

## Done condition

An artifact-mode emission produces a visible, testable event in the
binary — no silent sinks.
