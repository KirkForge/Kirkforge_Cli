# WO 38.2 — Liveness: async I/O discipline

## Status: Pending

## Problem (audit: liveness — root structural finding)

Slash-command handlers doing subprocess/network I/O are awaited
INLINE on the TUI event-loop task (`tui/mod.rs:926` →
slash_commands.rs:398). While awaiting, no render, no Esc, no
spinner. Findings:

1. **P0 — `/gh`**: sync `std::process::Command::output()` unbounded
   (`tui/commands/github.rs:22,256,288`) — stalled gh API = frozen
   TUI forever.
2. **P0 — `/jobs run-now`**: awaits the full job run inline
   (`tui/commands/jobs.rs:525`); job with no timeout = infinite
   freeze; 1h timeout = 1h freeze.
3. **P1 — `/commit --push`**: unbounded `git push` await, no
   kill_on_drop (`commit.rs:201-216`). `/test` 5-min default / 1-h
   max inline (`test.rs:107`). `!bang` 30s inline (`bang.rs:140`) —
   and the approval-Yes path comment claims the UI keeps draining;
   it does not.
4. **P1 — correction-loop formatter**: `child.wait().await` no
   timeout/kill_on_drop/null-stdin, OUTSIDE the per-tool timeout
   (`verifier/correction.rs:267-296`) — hung formatter hangs the
   turn; cancel leaks the child.
5. **P1 — plugin bus verifier**: sync unbounded subprocess under the
   bus Mutex on every file write (`verifier/bus.rs:276`,
   kf-plugin-host/verifier.rs:65) — hang holds the bus lock.
6. **P1 — `web_fetch` blocking DNS** (`SystemResolver` getaddrinfo
   ×2/fetch, no spawn_blocking — `web_fetch.rs:44-47,151,161`) —
   wedged resolver blocks runtime workers.
7. **P1 — worktree git ops**: blocking std::process, no timeout, in
   async contexts incl. session startup (`worktree.rs:26,43,77,115,
   124,134`; `run_session.rs:134`) — hung hook/NFS blocks app start.
8. **P2 — update client no timeout** (`handle_update.rs:111-117`);
   fallback clients discarding timeouts (`web_fetch.rs:75,427` etc).

## Approach

1. One architectural fix neutralizes 1-3: spawn the handler work
   (`tokio::spawn`), report via the existing event/dirty channels —
   the `/workflow run` background pattern (`workflow.rs:256`) is the
   template. Apply to gh, jobs run-now, commit-push, test, bang.
2. Formatter + plugin verifier: `tokio::time::timeout` +
   `kill_on_drop(true)` + `Stdio::null()` where stdin isn't needed —
   mirror bash_runner. Hooks already do this (5s) — verifiers get the
   same treatment.
3. web_fetch: `spawn_blocking` around resolution (or tokio
   lookup_host).
4. worktree git ops: `spawn_blocking` (they're one-shot, short) —
   smallest change vs converting to tokio::process everywhere.
5. Update client + fallback clients: builder timeout.

## Gate

clippy/fmt/nextest; new tests: gh/jobs handlers return immediately
(spawn observed, no inline await — assert via elapsed bound on the
COMMAND dispatch, not the background work); formatter kill-on-timeout
test (gated-start, event-driven); DNS resolution via spawn_blocking
covered by existing web_fetch tests still passing.

## Done condition

No unbounded await on the TUI event loop; no unbounded subprocess
wait in the executor turn path; DNS never blocks a runtime worker.
