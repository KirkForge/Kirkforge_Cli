## Problem (adversarial review of WO 35-37 code)

1. **P0 — `/workflow cancel` on the parallel path is a lying no-op**
   (`src/tui/commands/workflow.rs:114-123` vs `:222-247`): the flag is
   never read by the parallel branch; `ParallelOrchestrator::
   cancel_all()` has ZERO production callers. With
   `worktree_enabled=false` (the default — shared parent sandbox),
   cancel claims success while the coder keeps editing.
2. **P0/P1 — same-ms identity collisions** (`task_spawner.rs:65-74`):
   tags = `pid + as_millis()`. Two parallel `task` calls in one
   assistant message collide: (a) worktree path collision → stale
   recovery force-removes a LIVE sibling worktree, silent patch loss;
   (b) temp-dir collision (no config gate) → two subagents share one
   conversation.ndjson, first finisher deletes it under the other.
   Same class as the 37.1 owner-id fix: identity from a clock instead
   of the global counter.
3. **P1 — stale Esc kills the next turn** (`loop_.rs:179-195` watcher
   vs `:516-532` input arm): watcher's store-then-cancel can land
   after the fresh token install → new turn dies instantly. Needs an
   epoch/generation on the token slot or drain-before-install.
4. **P1 — pipeline never aborts between phases**
   (`parallel_orchestrator.rs:134-156`): scout failure stringifies
   into `"(failed: ...)"` and is handed to the coder as context; dead
   provider still burns two full sessions. No cancel check between
   phases; cancel-during-scout can't reach the not-yet-registered
   reviewer handle.
5. **P1 — handoffs unbounded + unsanitized** (`:253-265`): scout
   summary (model output shaped by repo file contents) injected raw
   into the coder PROMPT — trusted-position prompt injection, strictly
   worse than tool-result injection; no size bound (50-100KB coder
   prompts possible). Patch-marker spoofing via first-occurrence
   `split_once` (`:277-281`) is the P2 cousin.
6. **P1 — cancel not transitive to nested subagents**: a subagent's
   own `task(background=true)` children live in its private manager;
   outer cancel can't reach them.

## Approach

1. Store the orchestrator handle (Arc) in state; `handle_cancel`
   calls `cancel_all()` on it. Thread a shared cancel flag into
   `run_pipeline`; check before each phase; short-circuit on prior
   phase error instead of stringifying it into the handoff.
2. Tags from the global `NEXT_TASK_ID` (37.1) or `request.owner`;
   treat pre-existing temp dir as an error.
3. Token slot: generation counter — watcher cancels only if the
   generation it observed still matches; test Esc-then-new-input.
4. Handoffs: char bound (e.g. 8KB) + untrusted-data fencing
   (delimiters + instruction to ignore embedded directives) + patch
   in a delimited block; `extract_patch` splits at the LAST marker.
5. Nested cancel: set `parent_task_id`; derive nested
   `TaskRequest.cancel` from the parent executor's live token (the
   executor already holds it).
6. Tests per the review's gap list: cancel-between-phases, parallel
   workflow cancel end-to-end, marker-echo spoofing, same-ms double
   spawn, Esc-then-input window, adapter-error mid-pipeline.

## Gate

clippy/fmt/nextest + the six tests above (event-driven, no
sleep-races); existing pipeline sequencing tests stay green.

## Done condition

Cancel means cancel on every orchestration path; identities are
collision-proof; handoffs are bounded and fenced; no lying UI.
