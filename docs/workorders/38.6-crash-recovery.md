# WO 38.6 — Crash-corruption recovery

## Status: Pending

## Problem (recovery audit)

1. **P1 — torn conversation line never heals, next append fuses onto
   it** (conversation.rs:442-475 loader skips fragment; :127-149
   append O_APPENDs without leading newline) → both the crashed
   message and the next one permanently unparseable; only /compact
   ever rewrites.
2. **P1 — `StartedEmpty` (log corrupt, no checkpoint) surfaced
   nowhere** (conversation.rs:77-84; run_session.rs:226-230,
   line_mode.rs:79-81, tui/mod.rs:714-716) → `--continue` silently
   hands the user a brand-new session; Restored gets a banner,
   StartedEmpty gets nothing.
3. **P1 — `save_config` non-atomic** (config/mod.rs:252-258, 12 call
   sites) — torn write → all defaults → next save permanently erases
   user config.

## Approach

1. On `open()` with corrupt==true, heal: atomically rewrite from the
   parsed valid messages (`write_atomic` exists at :337).
2. StartedEmpty: mirror Restored — eprintln + TUI banner naming the
   path, stating the corrupt original was left in place for manual
   recovery.
3. save_config: temp + `rename_with_retry` (session_index.rs:180-212
   pattern).

## Gate

Standard + tests: torn-tail file heals on open; fused-append case
recovers; StartedEmpty produces the banner; config save survives a
simulated mid-write abort (write partial temp, verify original
intact).

## Done condition

A crash mid-write never costs the next message or the user's config;
silent data loss becomes a loud, recoverable event.
