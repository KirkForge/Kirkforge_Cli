## Problem (perf audit — magnitudes on realistic heavy sessions)

1. **P0 — checkpoint = full-history clone + full-file rewrite per
   TOOL CALL** (conversation.rs:190-292, called from dispatch.rs:371/
   569/595, turn.rs:513/155): ~1500 tool calls on a 10-25MB history =
   **12-40GB of disk writes**, ~1800 fsyncs + read_dir+sort prunes;
   50-150ms stall per late-session tool call. O(N²) cumulative.
2. **P0 — cargo build + clippy + test per EDIT, sequential, uncached,
   default-on** (verifier/handler.rs:88-122, correction.rs re-runs ×3):
   a 200-edit session on this repo ≈ **2-4 hours of stalls** plus
   orphaned cargo processes fighting the next turn (30s timeout stops
   the WAIT, not the process).
3. **P1 — 3-5 full-history BPE passes + 2 full clones per model
   ITERATION** (prompt/mod.rs:385-527): `Message.token_count` exists
   and is NEVER populated — all counting from scratch; dedup clones
   every tool message for equality (mod.rs:674-678); 1-8s CPU added
   to every late-session round-trip.
4. **P1 — memory store re-read from disk every iteration** (200 file
   opens+parses; prompt/mod.rs:210-233) AND the system-stem cache is
   permanently defeated because carryover/memory blocks are volatile
   → the prompt-cache savings never materialize (cache_stem.is_stable
   ~never true).
5. **P1 — top-N files re-read + re-minified per iteration**
   (stream.rs:89-117); context-index retrieval rebuilds TF-IDF vocab
   and re-embeds ALL 17k symbols per query despite CachedIndex
   embeddings existing on disk (lib.rs:1068-1103 — computed but never
   used by the query path).
6. **P1 — trace recorder clones full history per turn** on non-TUI
   paths (turn.rs:257-287): 300-turn line session → ~3.5GB trace.

## Approach (ordered by leverage)

1. Checkpoints: keep an incremental format (append segments or
   checkpoint every N appends / post-batch + post-turn only — NOT per
   tool). Minimum: drop the full `messages.clone()`, serialize under
   the existing lock.
2. Verifiers: coalesce per tool batch (one run per batch, not per
   edit), cache verdicts by (file, content-hash), `cargo check` for
   the hot path, spawn_blocking, kill on timeout.
3. Populate `Message.token_count` at append time; estimators use it
   (one BPE pass per new message); dedup by hash/len not clone.
4. Memory facts: mtime-cached; move volatile blocks (carryover,
   memory) out of the system message so the stem is stable and the
   provider KV cache actually hits.
5. (path,mtime)→minified cache; link CachedIndex embeddings into the
   query path; adjacency map instead of linear edge scans.
6. Trace records delta-only (messages since last turn).

## Gate

Standard + a perf smoke test (e.g. N=300-message synthetic history:
checkpoint bytes written and prompt-build time asserted sub-linear —
structural counters, not wall-clock thresholds).

## Done condition

A 10-hour heavy session stays flat: no quadratic checkpoint I/O, no
per-edit cargo storms, bounded per-iteration CPU, stable prompt stem.
