# WO 39.3 — Claude compat phase 2: dynamic agents + tool aliases

## Status: Pending

## Problem

`.claude/agents/*.md` (name/description/tools/model frontmatter +
prompt body) has no loader; kf-code personas are 3 hardcoded kinds.
Claude agent `tools` lists use Claude tool names (Read/Bash/Task…)
that don't exist here.

## Approach (~350-400 LOC)

1. `AgentDef {name, description, system_prompt, tools, model}` loader
   for `.claude/agents/*.md`.
2. `task_spawner.rs:298` unknown-persona fallback consults the
   registry: system prompt as preamble (extend the build_task_prompt
   seam), `tools` frontmatter → allowlist via the
   tools_for_persona pattern, `model` → per-call model plumbing
   (exists in task.rs).
3. **Tool-name alias table (~40 LOC const)**:
   Read→read_file, Write→write_file, Edit/MultiEdit→edit_file,
   Bash→bash, Glob→glob, Grep→grep, WebFetch→web_fetch,
   WebSearch→web_search, NotebookEdit→notebook_edit, TodoWrite→todo,
   Task/Agent→task. Applied in agent tool allowlists and command
   allowed-tools.
4. Prompt-alias suffix: when any Claude artifact is loaded, append
   one system-prompt paragraph mapping alias→native names (prose
   references can't be rewritten reliably — don't try).
5. Security note honored from the compat exploration: `.claude/`
   is model-writable in-session — agent defs influencing toolsets
   get the same `plugin_trust_workspace`-style opt-in or approval as
   workspace plugins.
6. `task` tool description lists discovered agents.

## Gate

Standard + tests: agent file loads, unknown persona routes through
it, alias allowlist filters (Task→task passthrough, Read→read_file),
model override reaches adapter_for_with_provider, trust gate blocks
unapproved agent dirs.

## Done condition

A Claude plugin's agent definitions run as kf-code subagents with
sane tool scoping — the ecosystem's markdown layer is fully consumed.
