# WO 39.4 — Claude compat phase 3: hook contract

## Status: Pending (deferrable — lowest wild frequency of the artifact classes)

## Problem

Claude hooks: settings-JSON event→matcher→command shape, JSON
payload on STDIN, exit-2 deny. kf-code hooks: filename-equality
events, KF_* env vars, stdin nulled. Exit-2 semantics already match;
ADR-0009 pins the full Claude JSON contract in-tree (drift-tested) —
the design work exists.

## Approach (~150-300 LOC)

1. `Stdio::piped()` + JSON writer in run_hook_script (payload per
   ADR-0009), KF_* env vars kept for back-compat.
2. Generic `pre-tool`/`post-tool` events (all tools, with per-tool
   matcher) added to KNOWN_EVENTS + emit sites alongside the existing
   bash/write_file-specific ones.
3. Event-name mapping: PreToolUse→pre-tool, PostToolUse→post-tool,
   UserPromptSubmit→pre-turn, SessionStart→session-start, Stop→
   post-turn, PreCompact→pre-compact. No equivalent: SessionEnd,
   Notification, SubagentStop — documented as unsupported.
4. Claude `settings.json` / `hooks.json` reader → hook registrations
   (matchers evaluated against tool name).

## Gate

Standard + tests: JSON payload shape pinned against ADR-0009's
drift-tested schema; matcher selectivity; exit-2 deny passthrough on
the new events.

## Done condition

A Claude plugin's hooks.json runs its hooks with the payload it
expects and the deny semantics it expects.
