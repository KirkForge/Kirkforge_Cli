# WO 40.2 — Windows cross-compile gate + one-pass fix

## Status: Done (P0 — this is the fix for the recurring 25+
fix(windows) commits)

## Problem

Every `fix(windows)` commit in the last 3 weeks (25+ of them) was
caused by Unix-only code (imports, constants, test helpers, env vars)
not gated behind `#[cfg(unix)]`. Linux clippy can't see these; only
`cargo clippy --target x86_64-pc-windows-gnu` catches them. That
command exists and works but was NEVER added to the local gate
script (`scripts/ci-local.sh`), so it was never run before pushing.

## Approach

1. **Add the gate**: `scripts/ci-local.sh` gains a mandatory step:
   `cargo clippy --target x86_64-pc-windows-gnu --workspace
   --all-targets -- -D warnings`. This runs AFTER the Linux clippy
   step. If it fails, the local gate fails — NO push happens until
   it's green.
2. **One-pass fix**: run the gate on the current dev tree. Fix EVERY
   Windows-only issue it finds in ONE commit — not 25 separate
   `fix(windows)` commits. Gate every unix-only import, constant,
   test helper, and production code path behind `#[cfg(unix)]` or
   `#[cfg(not(unix))]` equivalents.
3. **Add to AGENTS.md**: "Run `scripts/ci-local.sh` before EVERY
   commit — it includes the Windows cross-compile check. Never push
   without it."
4. **Update the CI workflow**: the Windows job in ci-merge.yml stays
   as the CI-side backstop, but the local gate is the primary
   defense.

## Files to touch

- `scripts/ci-local.sh` (add the step)
- `src/` and `crates/` (gate every unix-only item the gate finds)
- `AGENTS.md` (add the requirement)

## Gate

`scripts/ci-local.sh` exits 0 on the current dev tree (including the
Windows cross-compile step). `cargo clippy --target
x86_64-pc-windows-gnu --workspace --all-targets -- -D warnings`
passes clean.

## Done condition

The 25+ `fix(windows)` commit pattern is structurally impossible:
the local gate catches every Windows-only issue before push, and
AGENTS.md enforces running it.
