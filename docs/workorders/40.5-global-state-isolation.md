# WO 40.5 — Global state isolation (env/cwd/serial)

## Status: Pending

## Problem (GPT doc items 19-22, 53-55, Phase 2: kill global test
state)

1. **Env var mutation**: Anthropic auth, Bedrock auth, session
   index, verifier/security tests mutate `std::env::set_var()` /
   `remove_var()` — Rust tests run in parallel; global env is
   inherently hostile (items 19-22, 🔴 Very high).
2. **`KF_CODE_DATA_DIR`** set globally in session_index tests (item
   20, 🔴 High) — races with any other test reading the data dir.
3. **PATH mutation** in verifier/security tests (item 21, 🔴 High) —
   breaks other tests that spawn processes.
4. **`set_current_dir`** in glob/workflow tests (item 55, 🔴 High) —
   the flake audit (WO 38.12) found 4 ungated cwd mutations with a
   confirmed live victim pair.
5. **`#[serial]`** used to compensate for shared state (item 53, 🔴
   Very high) — serialization is the workaround; isolation is the
   fix.

## Approach

1. **Env injection**: where production code reads `std::env::var()`,
   accept an optional override in the tested function/struct (env
   is the fallback). Tests inject the value; no global mutation.
   Files: `src/session/config/` (KF_CODE_DATA_DIR),
   `src/adapters/auth.rs` (API keys), `src/session/verifier/
   security.rs` (PATH).
2. **Cwd injection**: `CwdGuard` RAII helper in
   `src/shared/test_util.rs` (hoist from `src/tools/workflow.rs`
   where it already exists as a private helper). Every test that
   mutates cwd uses the guard + a shared serializing mutex. Files:
   `src/tools/glob.rs`, `src/tui/commands/workflow.rs` (2 tests),
   `src/shared/session_mode.rs`.
3. **EnvGuard**: verify the existing `EnvGuard` (src/shared/
   test_util.rs) is used by EVERY test that touches env vars; grep
   for `set_var`/`remove_var` outside EnvGuard blocks and convert.
4. **Remove `#[serial]`** where the underlying shared state is
   eliminated by injection. Keep it only where the global state is
   inherent (process-global OnceLocks that can't be injected).
5. **Data dir**: make `session::data_dir()` accept an override
   (config field or function arg) so tests don't need to mutate
   `KF_CODE_DATA_DIR` at all.

## Files to touch

- `src/shared/test_util.rs` (CwdGuard + EnvGuard improvements)
- `src/session/mod.rs` (data_dir override)
- `src/tools/glob.rs`, `src/tui/commands/workflow.rs`,
  `src/shared/session_mode.rs` (CwdGuard)
- `src/adapters/auth.rs`, `src/session/verifier/security.rs`
  (env injection)
- Every test that calls `set_var`/`remove_var`/`set_current_dir`
  without a guard

## Gate

`grep -rn 'set_var\|remove_var\|set_current_dir' --include="*.rs"
src/ crates/ tests/ | grep -v '#\[cfg(test)\]\|test_util\|EnvGuard
\|//\|CwdGuard'` shows ZERO unguarded mutations. `grep -rn
'#\[serial\]' --include="*.rs" src/` shows only inherent-global
cases (BashJobRegistry OnceLock, budget listeners) with a comment
explaining why injection is impossible.

## Done condition

No test mutates global process state without a guard; no test
serializes for a reason that injection could fix; parallel test
execution is safe by construction.
