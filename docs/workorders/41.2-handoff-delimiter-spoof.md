# WO 41.2 — Handoff delimiter spoof test + structural escaping

## Status: Pending

## Problem (verified: PARTIALLY CONFIRMED)

WO 38.4 added untrusted-data fencing (`<<<BEGIN UNTRUSTED HANDOFF>>>`
/ `<<<END UNTRUSTED HANDOFF>>>`) with an 8KB cap and an instruction
rule. The patch-marker spoof IS mitigated (`rsplit_once` + test).
But the handoff-content delimiter is NOT escaped: a malicious handoff
can contain `<<<END UNTRUSTED HANDOFF>>>` inside its body to inject a
premature end marker. No test covers this case.

## Approach

1. **Test first**: add a test that feeds a handoff containing
   `<<<END UNTRUSTED HANDOFF>>>` inside the content and asserts the
   fence is not broken (the content is contained, not escaped).
2. **Fix**: escape the delimiters inside the handoff body — replace
   any literal `<<<END UNTRUSTED HANDOFF>>>` or
   `<<<BEGIN UNTRUSTED HANDOFF>>>` in the content with a neutralized
   form (e.g. `<<<END UNTRUSTED HANDOFF (escaped)>>>` or remove the
   angle brackets). Smallest change that makes the fence structurally
   sound.
3. **Test**: verify the escaped content renders correctly in the
   prompt (the model sees the text but cannot break the fence).
