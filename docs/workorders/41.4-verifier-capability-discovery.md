# WO 41.4 — Verifier capability discovery UI

## Status: Pending

## Problem (verified: PARTIALLY CONFIRMED)

The system honestly discloses which verifier categories are stubs
(`plugin_verify` prints "lint: emitter not ported", "overall: PASS
(security-only coverage)"). But there is no forward-looking
capability map — a UI/command that shows "security: active, lint:
stub, types: stub, graph: stub, build: active, git: active" so the
user (and the reviewer) can see at a glance what contributes to a
verdict.

Second: `OverallVerdict::Pass` means "security passed + nothing else
reported" — but the UI doesn't distinguish "PASS (full verification)"
from "PASS (security-only)".

## Approach

1. Add a `/verify-capabilities` slash command (or extend `/verify`
   output) that lists each verifier category with its status:
   active (has a producer) / stub (emitter not ported) / external
   (delegates to cargo/eslint/etc.). Source: the VerifierBus
   registration + the known stub set in native.rs.
2. In the pipeline result summary and the `plugin_verify` output,
   distinguish `PASS` from `PASS (security-only)` — the code already
   does this in `plugin_verify` (`native.rs`); surface it in the
   pipeline summary too.
3. Test: the capability list matches the registered verifiers; a
   stub category shows as stub.
