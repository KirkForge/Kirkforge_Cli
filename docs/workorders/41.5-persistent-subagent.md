# WO 41.5 — Persistent subagent lifecycle (AgentRun)

## Status: Pending (architectural — larger than the others)

## Problem (verified: PARTIALLY CONFIRMED)

`TaskHandle` persists in-memory for the session (the summary text is
queryable via `task_output`), but there is no durable store, no
`/jobs` integration, no transcript/artifact retrieval for completed
subagents. When the process exits, everything is gone. The reviewer's
"ephemeral" claim overstates (the handle IS retained in-session) but
is right that there's no persistent lifecycle.

Codex's model: persistent threads with `parentThreadId`,
`ancestorThreadId`, sandbox state, approval policy, transcript,
artifacts — all queryable post-completion.

## Approach (phased — smallest first)

1. **Phase 1**: persist `TaskHandle` summaries to the session log
   (or a sidecar) on completion — so `--resume` can show what
   subagents ran and their results. Smallest step: serialize the
   handle's summary/status/metadata to `~/.local/share/kf-code/
   tasks/<id>.json` on terminal state.
2. **Phase 2**: surface subagent results in `/jobs` (or a new
   `/tasks` command) — list completed subagents with their status,
   duration, and a link to the transcript.
3. **Phase 3** (deferred): full `AgentRun` object with workspace,
   model, permissions, budget, transcript, artifacts, verifier
   results — the reviewer's architectural ask. This is the
   convergence point where /jobs, replay, metrics, correction, and
   orchestration all operate on the same object.

Phase 1 is this WO. Phases 2-3 are follow-up WOs.

## Files to touch

- `src/tools/task.rs` (persist on terminal state)
- `src/session/mod.rs` (tasks data dir)
- `src/tui/commands/` (surface in /jobs or /tasks)

## Gate

Standard clippy (Linux + Windows cross-compile), fmt, nextest. Test:
a completed subagent's summary survives a process restart (write
JSON, read it back).

## Done condition

A completed subagent's result is durable; `--resume` can show what
ran. The ephemeral claim is closed for Phase 1.
