# WO 42.10 — Subagent persistence Phase 1 (WO 41.5 still open)

## Status: Pending

## Problem (verified: orchestration agent)

`TaskHandle` is in-memory only. No `/tasks` command exists. No durable store. On
process exit, everything is gone. The reviewer's "ephemeral" claim overstates (the
handle IS retained in-session via `task_output`) but persistence is genuinely absent.

## Approach (Phase 1 — smallest step)

1. On terminal state (Completed/Failed/Cancelled), serialize `TaskHandle` summary +
   metadata to `~/.local/share/kf-code/tasks/<id>.json`.
2. Add `/tasks` slash command — list persisted task summaries (id, status, persona,
   duration, truncated summary).
3. Test: completed task persists; cancelled task persists with Cancelled status;
   restart (re-read) shows the task.

## Gate

Standard. Test: JSON file exists with correct content; `/tasks` lists it.
