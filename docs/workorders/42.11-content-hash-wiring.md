# WO 42.11 — Wire content_hash in verifier path

## Status: Pending

## Problem (verified: performance agent)

`content_hash` is computed at `src/session/executor/dispatch.rs:104` and carried in
`FileWriteEvent` (`types.rs:307`) but no verifier reads it. It's dead data — schema
scaffolding with no production wiring.

## Approach

`VerifierHandler::verify_event` should cache verdicts keyed by `(file, content_hash)`.
If the same file+content was already verified, skip re-verification. This eliminates
redundant `cargo build`/`clippy`/`test` runs for unchanged content across correction
iterations.

## Gate

Standard. Test: same content_hash → 1 invocation; different content_hash → 2 invocations.
