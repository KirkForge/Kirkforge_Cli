# WO 42.12 — Populate Message.token_count at append time

## Status: Pending

## Problem (verified: performance agent)

`Message.token_count` (`src/shared/mod.rs:109`) is populated in exactly ONE non-test
path: `turn.rs:1134` (`usage.completion_tokens` from API response). Never populated
at append time for tool/user messages. Estimators call `count_tokens` (full BPE pass)
every iteration — 3-5 full-history BPE passes per model round-trip.

## Approach

1. Populate `token_count` at `ConversationLog::append` / `append_async` time.
2. `estimate_message_tokens` uses cached `token_count` if `Some`, else falls back to
   BPE.
3. Content-mutation sites (microcompaction, minification) clear the cached count.
4. Test: `token_count` is `Some` after append; estimator uses cached value; content
   mutation clears it.

## Gate

Standard. Test: append populates; estimator uses cache; mutation clears.
