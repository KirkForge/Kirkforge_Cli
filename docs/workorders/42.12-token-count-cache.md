# WO 42.12 — Populate Message.token_count at append time

## Status: Done

## Problem

`Message.token_count` (`src/shared/mod.rs:109`) is `Option<usize>` — populated in exactly ONE non-test path: `turn.rs:1134` (`usage.completion_tokens` from API response). Never populated at append time for tool/user messages. Estimators call `count_tokens` (full BPE pass) every iteration — 3-5 full-history BPE passes per model round-trip.

## Approach

1. `ConversationLog::append` / `append_async` populate `token_count` when `None` (don't overwrite the API-provided value for assistant messages).
2. A shared `estimate_message_tokens` free function (`prompt/mod.rs`) returns the cached `token_count` when `Some`, falling back to BPE counting when `None`.
3. All per-module `estimate_message_tokens` copies (`PromptBuilder`, `compaction`, `microcompaction`, `summarizer`) delegate to the shared function.
4. Content mutation sites clear `token_count = None` so the next estimation re-counts:
   - `truncate_tool_results`, `dedup_adjacent_tool_results`, `minify_old_messages`, `stub_old_tool_results`, context_index injection (`prompt/mod.rs`)
   - stub + condense paths (`compaction.rs`)

No new dependency. No struct layout change. Transparent cache.

Standard clippy, fmt, nextest. All passing.
