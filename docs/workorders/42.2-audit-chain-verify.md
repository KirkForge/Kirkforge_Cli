# WO 42.2 — Audit chain verification on restart

## Status: Pending

## Problem (verified: security agent)

`FileAuditSink::new` (`src/shared/audit.rs:583`) initializes `last_hash = initial_hash()`
every time — does NOT read the existing file to resume the chain. The first new event's
`chain_hash` is computed from genesis, not from the last pre-restart event. The chain
breaks across every restart. `FileAuditSink` has no `verify_chain` method — tamper
detection exists only for the in-memory test sink. The "tamper-evident" claim is
unfulfilled for the production path.

## Approach

1. On `FileAuditSink::new`, read the last line of the existing audit file to resume
   `last_hash` from the last event's `chain_hash`.
2. Add `FileAuditSink::verify_chain` that replays the file and checks every
   `chain_hash` matches the previous event's output.
3. Call `verify_chain` on startup — log a warning (not crash) if the chain is broken.
4. Test: write events, restart, verify chain continues from last event; tamper with
   a line, verify detection.

## Gate

Standard. New tests: chain resumes across restart, tamper detected.
