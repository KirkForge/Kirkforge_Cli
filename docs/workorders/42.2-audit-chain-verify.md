# WO 42.2 — Audit chain verification on restart

## Status: Done

## Problem

`FileAuditSink::new` initialized `last_hash = initial_hash(hmac_key)` every
time — it did NOT read the existing file to resume the chain. The first new
event's `chain_hash` was computed from genesis, not from the last pre-restart
event. The chain broke across every restart. `FileAuditSink` also had no
`verify_chain` method — tamper detection existed only for the in-memory test
sink (`MemoryAuditSink::verify_chain`).

## Approach

1. `FileAuditSink::new`: after creating the parent dir, read the last line of
   the existing audit file and parse the previous event's `chain_hash`. Use
   that as `last_hash`. Missing/empty file → `initial_hash`. Unparseable last
   line → `tracing::warn!` + `initial_hash` fallback.
2. `FileAuditSink::verify_chain(&self) -> bool`: read the whole file, replay
   every event, verify each `chain_hash` matches a fresh computation. Mirrors
   `MemoryAuditSink::verify_chain` and the `verify_audit_jsonl` walker in
   `plugin_tools/native.rs`. Missing/empty file → `true` (trivial intact
   chain). Parse/read error → `false` (cannot prove integrity).
3. `create_audit_sink`: after constructing the `File` sink, call
   `verify_chain` and `tracing::warn!` if broken. Non-fatal — the sink still
   appends, but the operator is told the historical chain can no longer be
   trusted.
4. Tests: chain resumes across a simulated restart; tamper detection; empty
   /missing file trivially intact; factory warns (non-fatally) on a broken
   chain.

## Gate
