# WO 42.3 — Secret scrubbing — expand coverage

## Status: Done

## Problem

`is_secret_env_name` in `src/session/bash_runner/mod.rs` only matched `*_API_KEY`, `*_TOKEN`, `*_SECRET` and exact `API_KEY`, `TOKEN`, `SECRET`. It missed common credential env-var shapes:

- `AWS_SECRET_ACCESS_KEY` (ends with `_ACCESS_KEY`, not `_API_KEY`)
- `AWS_ACCESS_KEY_ID` (ends with `_ID`)
- `*_PASSWORD`
- `*_PRIVATE_KEY`
- `*_CREDENTIAL`
- `*_PASS`
- `*_CONN_STRING` / `*_CONNECTION_STRING`

## Approach

Expand the suffix list in `is_secret_env_name` to add: `_ACCESS_KEY`, `_PASSWORD`, `_PRIVATE_KEY`, `_CREDENTIAL`, `_PASS`, `_CONN_STRING`, `_CONNECTION_STRING`. Add exact matches for `AWS_SECRET_ACCESS_KEY` and `AWS_ACCESS_KEY_ID` (the `_ID` suffix is too generic to match as a pattern). Updated the existing test `is_secret_env_name_matches_credential_shapes` with assertions for the new patterns.

## Gate

`cargo nextest run -p kf-code --lib --locked -- bash_runner` — all 65 tests pass.
