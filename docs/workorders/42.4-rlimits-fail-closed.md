# WO 42.4 — rlimits/unshare — fail-closed instead of silent failure

## Status: Done

## Problem

The entire rlimit block in `setup_rlimits` was wrapped in `#[allow(unused_must_use)]`. If `setrlimit` or `unshare(CLONE_NEWNET)` failed, the child ran with no CPU/memory/filesize cap (or network access despite `--no-network`) — silently, with no error.

## Approach

Replace `#[allow(unused_must_use)]` with explicit error handling matching the landlock/seccomp fail-closed discipline:

- If `setrlimit` or `unshare` fails AND `cfg.harden` is true: return an `Err` from the `pre_exec` closure (refuse to spawn). The child does NOT run without the requested hardening.
- If `cfg.harden` is NOT set: emit a warning via `eprintln!` (the only async-signal-safe channel in pre_exec) and proceed. Matches the prior non-fail-closed behaviour for the non-hardened path.

Applied to both the Linux and non-Linux Unix variants. The non-Linux variant's `unshare(CLONE_NEWNET)` call is also fail-closed (it requires `no_network`, which implies `harden`).

## Tests

- `run_shell_nonharden_proceeds_with_rlimits`: verifies the non-hardened path spawns and succeeds.
- `run_shell_harden_no_network_failcloses_on_unshare_error`: with `harden=true` + `no_network=true`, `unshare(CLONE_NEWNET)` fails without CAP_SYS_ADMIN (common CI/non-root case) — the spawn is refused. Skipped when running as root.
