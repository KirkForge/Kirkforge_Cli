# WO 42.4 — rlimits/unshare: fail-closed instead of silent failure

## Status: Pending

## Problem (verified: security agent)

`src/session/bash_runner/mod.rs:163` wraps the entire rlimit block in
`#[allow(unused_must_use)]`. If `setrlimit` fails, the child runs with NO CPU/memory/
filesize cap. Same for `unshare(CLONE_NEWNET)` at line 185 — silent failure means the
child has network access despite `--no-network`. Landlock/seccomp were held to
fail-closed; rlimits/netns were not.

## Approach

Replace silent failure with fail-closed: if `setrlimit` or `unshare` fails AND
`--harden` is set, refuse to spawn (return Err). If `--harden` is not set, log a warning
but proceed (current behavior for the non-hardened path). This matches the landlock/
seccomp discipline.

## Gate

Standard. Test: hardened path refuses spawn on setrlimit failure; non-hardened path
warns and proceeds.
