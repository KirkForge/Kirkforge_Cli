# WO 42.6 — Performance: WO 38.9 items 2-6

## Status: Pending

## Problem (verified: performance agent)

WO 38.9 is ~30% done. Item 1 (checkpoint clone removal) landed. Items 2-6 are open:

2. Verifier coalescing: sequential, per-edit, no verdict cache. `content_hash` is dead
   data — computed but never read by any verifier.
3. Token counting: `Message.token_count` never populated at append time. Estimators
   re-BPE every iteration (3-5 full passes per model round-trip).
4. Context index: vocab rebuilt + symbols re-embedded per query. Cached embeddings
   computed at save time but never used by the query path.
5. Memory store: disk re-read every build. No mtime cache.
6. Prompt building: stem cache defeated by carryover (volatile block in the key).

## Approach (ordered by leverage)

1. Populate `Message.token_count` at append time (conversation.rs). Estimators use
   cached value. One BPE pass per new message, not per iteration.
2. Wire `content_hash` into `VerifierHandler` — cache verdict by (file, content_hash).
   Skip re-verification when content unchanged.
3. Run verifiers concurrently via `spawn_blocking` + `join_all`.
4. Move volatile blocks (carryover/memory) out of the system-prompt stem so the
   cache key is stable.
5. Link `CachedIndex.embeddings` into the query path instead of rebuilding vocab.
6. Cache memory facts with mtime invalidation.

## Gate

Standard. Performance smoke test: N=300-message history, sub-linear scaling.
