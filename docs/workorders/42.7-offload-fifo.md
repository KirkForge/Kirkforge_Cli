# WO 42.7 — Offload store: fix false FIFO + add byte cap

## Status: Pending

## Problem (verified: performance agent)

`InMemoryOffloadStore` (`crates/kf-compress-core/src/store.rs:37`) has only `max_entries`
— no byte cap. Eviction takes `guard.keys().take(excess)` — HashMap iteration order is
random, not FIFO despite the `ponytail:` comment at line 61 claiming "evict FIFO if
throughput matters." The comment is aspirational; the code is random.

## Approach

1. Replace `HashMap` with `IndexMap` (or `Vec<(K,V)>` + `HashMap<K, usize>`) for
   insertion-order iteration. Evict oldest first.
2. Add `max_bytes: u64` cap. Track total bytes. Evict oldest entries until under cap.
3. Fix the false `ponytail:` comment or make the code match it.

## Gate

Standard. Test: eviction order is FIFO; byte cap triggers eviction.
