# WO 42.9 — PipelineOrchestrator rename + patch application (WO 41.1 still open)

## Status: Done (shipped via WO 41.1)

## Problem (verified: orchestration agent)

`ParallelOrchestrator` name is stale — the pipeline is sequential (WO 35.1 collapsed
run_parallel/run_sequential). `coder_patch` is extracted but never applied to the parent
workspace. With `worktree_enabled=true`, `/workflow run --parallel` reports a successful
Coder change while the user's repository is unchanged — the patch is dead text in a struct.

## Approach

1. Rename `ParallelOrchestrator` → `PipelineOrchestrator`, `ParallelResult` →
   `PipelineResult`. Update all call sites.
2. After pipeline completes, if `coder_patch.is_some()`:
   - Default (`auto_apply_patch=false`): surface patch in TUI with hint to apply.
   - Opt-in (`auto_apply_patch=true`): `git apply` in parent workspace CWD after
     Reviewer phase. On conflict/dirty-tree, surface error event (not silent loss).
3. Add `auto_apply_patch` config knob to `SessionConfig`.

## Gate

Standard. Tests: patch applied to parent; patch surfaced not applied; dirty-tree
conflict → error.
