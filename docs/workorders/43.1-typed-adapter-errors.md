# WO 43.1 — Retire string-probe error classification

## Status: Done (ollama migrated; openai/anthropic/bedrock/vertex deferred)

## Problem

`src/main/error.rs:52-73` classifies every process-fatal error by probing the
lowercased message:

```rust
let msg = format!("{e:#}").to_lowercase();
if msg.contains("connection refused")
    || msg.contains("failed to connect")
    || msg.contains("dns error")
    || msg.contains("timed out")
    || msg.contains("model not found")
    || msg.contains("model unreachable")
{ ... } else if msg.contains("denied")
    || msg.contains("permission") ...
```

Backlog claims ~8 call sites — WRONG. It is a single funnel: the
`From<anyhow::Error> for KirkForgeError` impl (error.rs:29) is invoked at
exactly ONE production site, `src/main/cli_dispatch.rs:238`
(`.map_err(KirkForgeError::from)` on the single dispatch result declared at
cli_dispatch.rs:121). The enum itself (4 variants, error.rs:14-27) and the
exit-code contract (3/4/5, error.rs:80-87, pinned in `src/cli.rs:28` and the
`hint_*`/`downcast_*` tests at error.rs:121-179) are the right shape — keep them.

Typed downcasts already exist (WO 14.3): `ManifestError -> ConfigParse`
(error.rs:42), `kf_plugin_host::ToolError -> AccessDenied` (error.rs:45).

All model adapters still return bare `anyhow` from `stream()`, so their
failures hit the probe: `oellama.rs`, `ollama_ndjson.rs`, `openai_compat/`,
`anthropic/` (+`sse.rs`), `anthropic_bedrock.rs`, `anthropic_vertex.rs`
(+`bedrock_signing.rs`, `vertex_auth.rs`), wrapped by `caching.rs` — all via
executor -> `run_session` -> cli_dispatch.rs:238. Probe phrases match reqwest
error chains ("connection refused", "dns error", "timed out") and Ollama's
`{"error":"model not found"}` payload (pinned by ollama_ndjson.rs:916-922).

## Root cause

Adapter failure modes (unreachable host, missing model, auth/policy denial)
are erased into `anyhow::Error` at the adapter boundary, forcing the process
exit classifier to re-derive them from Display strings — fragile against
provider phrasing changes and locale/case drift.

## Approach

1. Add a small typed error in the adapters crate root, e.g.
   `AdapterError { Unreachable, ModelNotFound, Denied, Other }`, converted
   into `anyhow` with `#[source]` preserved at each `stream()` error path.
2. Add `downcast_ref::<AdapterError>()` arms in
   `From<anyhow::Error> for KirkForgeError` (error.rs:42-47 block), mapping
   Unreachable/ModelNotFound -> ModelUnreachable, Denied -> AccessDenied.
3. Migrate adapters one at a time (ollama first — it owns "model not found"),
   running the hint_*/downcast_* tests after each.
4. Delete the `contains()` fallback (error.rs:52-73) only when the remaining
   producers are typed; keep `General` as the catch-all.

## Files

- src/main/error.rs (fallback + downcast arms)
- src/adapters/mod.rs (AdapterError definition, stream() error paths)
- src/adapters/ollama_ndjson.rs, oellama.rs, openai_compat/, anthropic/,
  anthropic_bedrock.rs, anthropic_vertex.rs (per-adapter migration)

## Gate

`scripts/test-fast.sh`; `cargo clippy --all-targets -- -D warnings`;
`cargo fmt --check`. Existing `hint_*` + `downcast_*` tests stay green; add
one downcast test per migrated adapter.
