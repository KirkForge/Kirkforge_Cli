# WO 43.10 — Cross-session state preservation policy

## Status: Planned

## Problem

Backlog claim: "KirkForge has session-scoped state only; when WO 41.5
(cross-session AgentRun) lands, it needs a source-of-truth preservation
policy table." Half drift:

- **WO 41.5 already landed (Phase 1)** — `docs/workorders/41.5-persistent-subagent.md:3`
  `Status: Done`. Task summaries persist to `tasks/<id>.json`
  (`src/session/mod.rs:169` `tasks_dir()`; `src/tools/task.rs`
  `PersistedTask`), surfaced via `/tasks`. Phases 2–3 (full `AgentRun`)
  remain deferred (41.5:71-79).
- **"Session-scoped state only" is false.** Durable state already on disk:
  session NDJSON + `.index.ndjson` cache (`src/session/session_index.rs`),
  undo snapshots `undo/<session_id>/<n>.snap` (`src/session/undo.rs`),
  carryover profile (`src/session/carryover.rs:17` `CarryoverProfile`),
  task summaries, job store `jobs/<id>/` (`src/jobs/store.rs`), usage.jsonl.
- **Ephemeral, process-global:** `SLICED_LISTENERS`
  (`src/session/budget.rs:112-119`, session-keyed HashMap, cleared on
  teardown at `src/session/executor/mod.rs:370-371` — WO 38.8) and
  `GLOBAL_REGISTRY` for background bash jobs (`src/session/bash_jobs.rs:70`).
  Background bash job state dies with the process; nothing records that a
  job was running at exit.

The real gap: no single table classifying every state field as
survives-session-death vs ephemeral, so each new subsystem re-decides (and
WO 41.5 Phase 3's AgentRun has no contract to build against).

## Root cause

Durable state accreted per-subsystem without a shared classification
policy; persistence is decided ad hoc at feature level.

## Approach

Depends on WO 41.5 Phase 3 (AgentRun) for the transcript/artifact fields;
the table itself does not block on it.

1. Write the field-classification table into `state.md`: every state store
   (disk + in-memory globals above), columns = field, owner module, class
   (survives / ephemeral), persistence mechanism, teardown/cleanup path.
2. Classes already correctly ephemeral (sliced listeners, cancel tokens,
   sandbox read-gate marks, verifier slot registrations): document, change
   nothing.
3. Implement persistence for the one surviving-class gap: background-bash
   job summary lines (id, command, status-at-exit) appended to the existing
   jobs store pattern so `--resume` can report "these jobs died with the
   session". Reuse `jobs_dir()` layout; no new subsystem.
4. AgentRun-bound fields (transcript, artifacts, verifier results): table
   marks them "survives — blocked on WO 41.5 Phase 3"; do not implement here.

## Files

- `state.md` (policy table + session-state section)
- `src/session/bash_jobs.rs` (exit-time summary persistence)
- `src/session/mod.rs` (reuse `jobs_dir()`; no new dir helper unless needed)
- `docs/TECHNICAL.md` (doc-sync: state-management section)

## Gate

`scripts/test-fast.sh`, `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check`. Test: kill a session with a running background job →
summary line persisted and listed on resume.

## Done

Policy table is the single source of truth for what survives session death;
the one undocumented surviving-class gap (background bash) is persisted;
ephemeral classes are documented as intentional.
