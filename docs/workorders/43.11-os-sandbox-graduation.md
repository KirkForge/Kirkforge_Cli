# WO 43.11 — Landlock/seccomp sandbox graduation decision

## Status: Planned

## Problem

The backlog claim ("sandbox.rs only rlimits + trust tiers; Landlock/seccomp deferred per ADR-054; graduate landlock from test-only to production") is significantly drifted. Verified state:

- ADR-054 is `rlimit-sandbox-hardening`; its deferral of seccomp was superseded by the WO 30.4 amendment (opt-in `seccomp` Cargo feature, `seccompiler`, `src/session/bash_runner/seccomp.rs:200,230`).
- Landlock is NOT test-only — the WO 27.1 amendment shipped it **default-on for Linux** on the bash path, fail-closed, with the `--i-accept-unsandboxed` escape hatch (`docs/adr/054-rlimit-sandbox-hardening.md:111-136`). Code: `apply_landlock` (`src/session/bash_runner/landlock.rs:208`) applied in the `pre_exec` hook (`bash_runner/mod.rs:234-248`), paths resolved at mod.rs:650 (`resolve_paths`, landlock.rs:168) and passed at mod.rs:656. WO 32.15 (Done) only added the integration test.
- The real residual the backlog circled but mis-named: the **plugin tool spawn path passes `None` for landlock**. `src/session/plugin_tools/wrapper.rs:254`: `setup_rlimits(&mut command, &self.sandbox, None);` — plugin subprocesses get rlimits (and seccomp if the feature is on) but **no filesystem confinement**. Same in the standalone host crate: `crates/kf-plugin-host/src/tool.rs:107`, `hook.rs:67`, `verifier.rs:85` (rlimits only, via `crates/kf-plugin-host/src/rlimits.rs`). The `crates/kf-plugin-host/src/sandbox.rs:15` ponytail note ("landlock/seccomp deferred per ADR-054... ride 21.7-R1's landlock integration when available") is stale — that integration landed.

## Root cause

`setup_rlimits` grew landlock as a third parameter (`Option<LandlockPaths>`, mod.rs:146); the plugin wrapper was never updated to resolve and pass paths.

## Approach

1. Graduate landlock to the production plugin path: in `wrapper.rs` resolve `landlock::resolve_paths(&cwd, extra)` for the tool's sandbox cwd (`sandbox_dir`, wrapper.rs:239) plus the plugin root, and pass `Some(paths)` at wrapper.rs:254. Fail-closed + `accept_unsandboxed` semantics come free from the existing `pre_exec` body (mod.rs:234-248).
2. Correct the stale `sandbox.rs:15` ponytail comment to point at the shipped bash_runner landlock.
3. Keep seccomp **opt-in** (recommend retaining the deferral): ADR-054's future-work gate — "flip default-on after real-workload allowlist tuning (cross-arch coverage)" — still stands; no evidence yet to flip it.
4. kf-plugin-host crate spawn paths (tool.rs/hook.rs/verifier.rs) stay rlimits-only: landlock lives in the bin's `src/` and the lib cannot import it; duplicating ~150 lines for the standalone host is not earned. Note this ceiling in the corrected comment.

## Files

- `src/session/plugin_tools/wrapper.rs`
- `crates/kf-plugin-host/src/sandbox.rs` (comment only)

## Gate

`cargo nextest run -p kf-code --lib --locked -- plugin` on Linux ≥5.13; existing `landlock_blocks_write_outside_workspace`-style assertion ported to one plugin-tool test; full local gate.

## Done

Plugin tool subprocesses on Linux are FS-confined like bash children; seccomp deferral explicitly retained per ADR-054 future-work; stale comment corrected.
