# WO 43.12 — Finish Windows test parity

## Status: Done

## Problem

Backlog says Windows test parity is "explicitly work in progress". Drift —
the heavy lifting shipped. `docs/workorders/7.6-windows-test-parity.md:3` is
`Status: Done`, and the CI referenced by its Problem section no longer exists
in that shape: `ci.yml` was split into `ci-pr.yml` / `ci-merge.yml` /
`ci-nightly.yml` (ADR-074). The Windows job now lives at
`.github/workflows/ci-merge.yml:192-220`: `runs-on: windows-latest`, runs the
full suite `cargo nextest run --profile ci-full --workspace --no-fail-fast
--locked` (:220), and is blocking — the only remaining `continue-on-error`
in `.github/` is `ci-nightly.yml:167`, the informational `cargo audit` step,
unrelated to tests. ADR-025 is indexed "Accepted (fully implemented)"
(`docs/adr/README.md:68`).

Windows-specific code is native, not skipped: `#[cfg(windows)]` impls at
`src/session/bash_runner/mod.rs:821` (ExitStatus), `src/main/line_mode.rs:487`
(`read_approval_answer_pollable` — no /dev/tty), `src/daemon/client.rs:517,582`,
`src/main/cli_dispatch.rs:204,217`, `src/session/verifier/security.rs:184,191`,
`src/tools/atomic_write.rs:73`. All `#[ignore]`d tests are environment-gated
(Ollama, Docker, Chrome, tmux/display, setrlimit) — none Windows-specific.

Residual gaps (the honest remainder):
1. **Doctests never run on Windows** — `--doc` runs only in the Linux
   full-tests job (`ci-merge.yml:186`); the windows job (:220) has no `--doc`.
2. **No Windows signal at PR tier** — `ci-pr.yml` is ubuntu-only; Windows
   failures surface first at merge (ADR-074 tier choice, but late feedback).
3. **Unquantified `#[cfg(unix)]` test gating** — 157 `cfg(unix)` occurrences
   in `src/`; how many hide tests that could run on Windows was never audited.

## Root cause

Parity was declared Done against the old single-job CI; the tier reset
(ADR-074) re-introduced two seams (doctests, PR tier) that nobody re-checked,
and the cfg(unix) audit step from WO 7.6's approach (item 2) was never
recorded as evidence.

## Approach

1. Add a `cargo test --locked --doc --workspace --no-fail-fast` step to the
   `ci-merge.yml` windows job (mirror of :186) — or document the exclusion
   in the job comment if doctests can't pass; either way the seam is closed
   explicitly.
2. Audit the 157 `cfg(unix)` sites once: split "Unix-only impl" from
   "Unix-gated test that could run on Windows"; ungate the latter
   (expect single digits; land as test-only diffs).
3. Optional, only if merge-tier latency proves annoying: a PR-tier
   windows build+clippy-only job. Do NOT add a full PR windows test job —
   that re-pays the cost ADR-074 was designed to avoid.

## Files

- `.github/workflows/ci-merge.yml`
- whichever test files the `cfg(unix)` audit ungates
- `docs/workorders/7.6-windows-test-parity.md` (append residual-close note)

## Gate

`scripts/ci-local.sh` locally; on push, the ci-merge windows job green
including the new `--doc` step; ungated tests pass on windows-latest.

## Done

Every test class that runs on Linux either runs on Windows in CI or has a
written, located reason not to; the `cfg(unix)` audit exists as evidence
rather than assumption.
