# WO 43.13 — Triage the 18 unimplemented spec tasks (TECHNICAL.md)

## Status: Planned

## Problem

`docs/TECHNICAL.md:1430` "Planned tasks (honest deferral)" — prose at :1432 says
"18 spec tasks are not yet implemented", but the table at :1435-1455 has **19
rows**. The count drifted when a row was added without bumping the number
(:1393 says 30 tasks cover 18 of 40 slots; 18 + 19 + 3 unmapped = 40, confirming
19 is the real row count).

The 19 rows, grouped:

- **A — code intelligence (5)**: 1 Find Dead Code, 2 Dependency Graph Accuracy,
  3 Call Graph Generation, 4 Explain Module, 5 Cross-Repository Search.
- **B — refactor scale (1)**: 9 Split Giant File.
- **D — non-Rust setup (1)**: 18 Add REST Endpoint.
- **E — standalone verification (3)**: 22 Build, 23 Formatter, 24 Lint.
- **F — scale (1)**: 27 Large Repository Navigation.
- **G — multi-file / review (3)**: 32 Large Refactor, 33 Merge Conflict
  Resolution, 35 Regression Detection.
- **H — metrics (5)**: 36 Token Efficiency, 37 Dollar Cost, 38 Time,
  39 Retry Count, 40 Human Intervention.

Additionally :1457-1458 discloses 3 spec tasks with no mapping at all (Fix
Compilation Error, Fix Integration Test, Implement Missing Trait).

No row has ever been classified: each is "a future workorder" with no verdict on
whether it will ever be one.

## Root cause

The table is a backlog dump, not a triage. Rows accumulated (count drifted by
one) without a decision gate forcing each item to become implement / defer /
delete.

## Approach

1. Fix the count drift (say 19, or remove a row deliberately).
2. Classify each row:
   - **implement** — deterministic verify is cheap and the feature is
     user-visible (candidates: 22/23/24 standalone verification tasks).
   - **defer-with-ADR** — real but blocked on a concrete missing capability;
     write the ADR naming the blocker (candidates: 27 needs a Linux-scale index
     fixture; A-category tasks depend on tree-sitter symbol-graph queries).
   - **delete-from-spec** — no longer represents a differentiating capability
     (candidates among the H metrics tasks that overlap Budget Challenge
     telemetry, ADR-0066).
3. Decide the fate of the 3 unmapped tasks — same three verdicts; they are
   currently tracked only in a prose aside.
4. Update the TECHNICAL.md table in the same commit: add a Triage column
   (implement / deferred → ADR-id / dropped) and reconcile the counts.
5. Every deferral gets a state.md pending entry (defer-disclosure rule);
   every deletion notes what replaced it or why it never mattered.

## Files

- `docs/TECHNICAL.md`
- `docs/adr/` (new ADRs only for deferred groups needing a blocker pinned)
- `state.md`

## Gate

Docs-only: `cargo test -p kf-budget-core --test adr_xref_drift` (ADR status
consistency), `scripts/ci-local.sh quick`.

## Done

Prose count matches table rows (19), every row plus the 3 unmapped tasks
carries a verdict, each deferral points at an ADR, each deletion is justified.
