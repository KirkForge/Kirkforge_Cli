# WO 43.14 — cargo-mutants nightly gate (targeted modules)

## Status: Planned

## Problem

Backlog claims "Stryker/cargo-mutants for survival gap detection". Verified: neither tool is mentioned anywhere in docs/, scripts/, or .github/ (grep for `mutant|stryker` → 0 hits). Current gates measure execution, not assertion strength:

- `scripts/test-fast.sh:10` — nextest `ci-fast` profile, `--lib --bins` (pre-commit gate)
- `scripts/test-full.sh:8` — nextest `ci-full` profile, all workspace tests (pre-merge)
- `.github/workflows/ci-nightly.yml:21-52` — nightly `coverage` job (cargo-llvm-cov, lcov artifact + `scripts/check-cov-regression.sh`)

Line coverage is green while assertions can be weak: a test that executes `safe_relative_path` but asserts nothing meaningful still counts as covered. Surviving mutants are the unmeasured gap.

Nightly hook point exists: `.github/workflows/ci-nightly.yml` already runs slow/exhaustive jobs (coverage, ollama, e2e-exhaustive, audit, release-build) on cron `0 2 * * *` + workflow_dispatch, with the `taiki-e/install-action@v2` pattern for dev tools (lines 37-40, 75-78, 154-157).

Security-critical targets (verified paths):
- `crates/kf-routing/src/path_safety.rs` (1084 lines; `safe_relative_path`:182, `is_inside_cwd`:163)
- `src/session/bash_runner/mod.rs` (`scrub_secrets_from_child_env`:592)
- `src/shared/audit.rs` (1553 lines, audit chain hash/append)
- `src/session/executor/sandbox.rs`, `src/session/sandbox_posture.rs`, `crates/kf-plugin-host/src/sandbox.rs`

## Root cause

No gate measures whether tests would fail if security-critical logic were broken. Coverage % (nightly job) rewards execution, not assertion power — the assertion-strength axis has no signal at all.

## Approach

1. Add a `mutants` job to `.github/workflows/ci-nightly.yml`: install cargo-mutants via `taiki-e/install-action@v2` (same pattern as cargo-nextest/cargo-audit), run against the four target areas file-scoped (`cargo mutants --file crates/kf-routing/src/path_safety.rs` etc., or `-p` package scoping), upload `mutants.out.json` + md report as artifacts. `timeout-minutes: 40`.
2. Start informational (`continue-on-error` style reporting like the audit job's informational pass, ci-nightly.yml:165-167): record baseline survival score per module in the job summary. Ratchet to blocking per-module only after a baseline exists.
3. Optional local runner `scripts/run-mutants.sh` (thin wrapper, mirrors test-fast.sh fallback style) — NOT wired into `scripts/ci-local.sh` or any pre-commit/pre-merge gate. Full-mutation runs are slow; nightly-only by design (ADR-074 tiering).
4. Fix the top surviving mutants in the four target modules (strengthen assertions at the root, not the test-count).

Explicitly: cargo-mutants is a dev tool installed in CI via install-action — it is NOT added to any Cargo.toml. The no-new-runtime-deps rule (size-optimized release profile) is unaffected.

## Files

- `.github/workflows/ci-nightly.yml` (new `mutants` job)
- `scripts/run-mutants.sh` (new, optional local wrapper)
- security modules above only if mutant kills require assertion fixes

## Gate

- Nightly `mutants` job green on workflow_dispatch; artifacts present.
- Baseline survival % recorded in job summary for all four target areas.
- `scripts/ci-local.sh`, `scripts/test-fast.sh`, `scripts/test-full.sh` untouched (mutation testing is not the pre-commit gate).
- Standard clippy/fmt/check still green.

## Done

Survival baseline for path safety, secret scrubbing, audit chain, and sandbox exists as a nightly artifact; weakest assertions in those modules strengthened.
