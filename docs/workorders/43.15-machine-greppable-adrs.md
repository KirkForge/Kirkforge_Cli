# WO 43.15 — Machine-greppable ADR predicate blocks

## Status: Done

## Problem

Backlog claims "predicate format for agent consumption" for ADRs. Verified current state — ADRs are prose with only ONE machine-parsed field (status), via `crates/kf-budget-core/tests/adr_xref_drift.rs`:

- `docs/adr/README.md:24-25` Index table `| ADR | Title | Status | Series |` — parsed by `parse_index_table` (adr_xref_drift.rs:48)
- ADR file status headers in 3 formats parsed by `parse_status_header` (adr_xref_drift.rs:139-160): `- **Status:** X` bullet form, `**Status:** X` bare-bold, `## Status` heading form
- `crates/X` prose literals checked for existence by `extract_crate_refs` (adr_xref_drift.rs:268) — reverse direction only, no declared affects-crates per ADR

Not machine-greppable today:
- **supersedes/superseded-by**: ADR-048/049 are `Superseded` (docs/adr/README.md:91-92) but the replacement relationship lives only in prose
- **implemented**: compound statuses are freeform strings — `Accepted (partially implemented)` (README.md:87, :115), `Accepted (amended)` (:33, :97), `Accepted (fully implemented)` (:68). An agent cannot filter "accepted but unimplemented"
- **affects-crates**: no per-ADR declaration; the drift test only validates crate mentions that happen to appear in prose

## Root cause

ADR metadata lives in two places (file header + index table) as freeform status strings; every other dimension (supersedes, implementation state, affected crates) is prose-only. The existing drift test proves the parse pattern works but has nothing structured to parse.

## Approach

1. Define ONE minimal predicate block, an HTML-comment or fenced block at the top of each ADR file with exactly four keys:
   `status:` (keyword only: accepted/rejected/superseded/deferred), `implemented:` (true/false/partial), `supersedes:` (list of ADR numbers, may be empty), `affects-crates:` (list of crate names, may be empty). No schema beyond these four — YAGNI.
2. Extend `adr_xref_drift.rs` with a `parse_predicate_block` in the existing `split`/`strip_prefix` style (no regex, no new deps): when a block is present, assert (a) `status` keyword agrees with the file's Status header, (b) every `affects-crates` entry is a dir under `crates/`, (c) every `supersedes` number resolves to an existing ADR file.
3. Pilot first: add blocks to the ADRs where `implemented` actually carries information — the compound-status ones (004, 025, 029, 044, 048, 049, 054, 073). Test enforces cross-checks only for ADRs that have a block.
4. Backfill remaining ADRs mechanically (block derives from existing header + index row) as a follow-up commit; flip the test to require a block on every ADR only after backfill.

## Files

- `crates/kf-budget-core/tests/adr_xref_drift.rs` (extend)
- `docs/adr/004-…, 025-…, 029-…, 044-…, 048-…, 049-…, 054-…, 073-…` (pilot blocks)

## Gate

- `cargo test -p kf-budget-core --test adr_xref_drift` green (existing 3 ADR tests + new predicate tests).
- A deliberate mismatch (flip `implemented` vs compound status) fails the test — verified by temporarily breaking one pilot ADR.
- Standard clippy/fmt/check green; no new dependencies.
