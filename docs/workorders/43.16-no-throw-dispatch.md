# WO 43.16 — No-throw dispatch hub (Result-typed)

## Status: Planned

## Problem

Backlog claims the tool/event dispatch path needs "Result type instead of
panics/errors". Mostly already built — the claim drifts; what remains is
finishing and pinning the contract.

Verified current state (`src/session/executor/dispatch.rs`):
- All three batch phases are `anyhow::Result`-typed: `prepare_batch` (:229),
  `spawn_batch` (:305), `collect_batch` (:514).
- Tool bodies are wrapped in `AssertUnwindSafe(...).catch_unwind()` under
  timeout (:677-698): a panicking tool becomes
  `ToolOutcome::Failure(Internal { "tool panicked: …" })`, not an unwind
  through the executor loop.
- JoinError (task panicked/cancelled) leaves the index unrecorded → Phase 3
  appends a placeholder result (:367-373).
- Dropped event receivers use `send_or_warn!`, not unwraps (:530, :550).

Remaining non-test panic sites in dispatch-reachable code:
1. `dispatch.rs:421` — `.expect("file call has resolved path")` on the
   Phase-2.5 deferred-file path.
2. `src/session/executor/mod.rs:380` —
   `.expect("stratum_store set above")` (local invariant, set at :374-376).
3. `src/session/executor/mod.rs:494` — `shared_cfg.read().unwrap()` on a
   just-constructed RwLock (poison-only).
Everything else grepped in `executor/` and `verifier/bus.rs` sits inside

## Root cause

The no-throw contract was implemented incrementally (WO 15.7/38.x) but never
finished at the edges nor pinned: three reachable panic sites remain, and
nothing prevents new `unwrap`/`expect` from landing in dispatch code.

## Approach

1. `dispatch.rs:421`: drop the `expect` — restructure so Phase 1 routes
   file calls without a resolved path into the `skipped` buffer with a
   Failure outcome (the invariant becomes a guarded branch).
2. `mod.rs:380`: pass the store through the branch that guarantees it, or
   `unwrap_or_else` + `tracing::error!` + skip listener registration.
3. `mod.rs:494`: use the repo's established poison pattern
   `.unwrap_or_else(|e| e.into_inner())` (as `budget.rs:131` already does).
4. Pin the contract: one test asserting a panicking registered tool yields
   `Failure(Internal)` (extends the catch_unwind path), plus a grep gate in
   `scripts/ci-local.sh` (or a kf-testdoctor check) rejecting new non-test
   `unwrap`/`expect`/`panic!` in `src/session/executor/dispatch.rs`.
5. Add the refactor-on-touch policy line for the top-5 long functions to
   `AGENTS.md` §7 (context only — no standalone refactor WO).
