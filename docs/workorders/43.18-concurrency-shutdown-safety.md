# WO 43.18 — Abrupt-exit safety: line-mode SIGINT, audit flush, grep blocking

## Status: Planned

## Problem

Segment audit (concurrency/cancellation/shutdown). Most of the segment is
clean (see Root cause); three verified gaps survive.

1. **Line mode has no SIGINT handler.** TUI installs one
   (`src/tui/mod.rs:362-383`), the daemon too (`src/daemon/mod.rs:38-72`),
   but `src/main/line_mode.rs` registers nothing. Ctrl-C in line mode
   (`--no-tui`, piped stdout, `-p` one-shot) takes the default SIGINT kill:
   no executor cancel, no carryover save (TUI does this at teardown,
   `src/tui/mod.rs:436-440`), and in-flight tool children are ORPHANED —
   they sit in their own process groups (`src/session/process_group.rs:32-43`,
   `setpgid(0,0)`), so they neither get the terminal signal nor a
   `kill_on_drop` (runtime never drops the `Child`). A destructive bash
   keeps running after the agent that spawned it is dead.

2. **Audit entries are buffered until Drop, which abrupt exits skip.**
   `AuditLog` wraps a `BufWriter` (`src/shared/audit.rs:122`); `write_entry`
   (`:201-216`) never flushes — only `Drop` (`:219-229`) does. Release uses
   `panic = "abort"` (`Cargo.toml:340`): the WO 38.2 panic hook
   (`src/tui/mod.rs:159-186`) restores the terminal but runs no Drops, so
   the last ≤8KB of destructive-call records vanish on panic, SIGKILL, or
   line-mode SIGINT — exactly the exits an audit trail exists for. The
   transcript is NOT at risk (`conversation.rs:135-152` `sync_all` per
   append); trace batching is deliberate (WO 10.5).

3. **Grep tool blocks the async runtime.** `Grep::execute` (async) calls
   blocking std process/fs directly: `rg_available()` runs `rg --version`
   (`src/tools/grep.rs:13-19`), `run_rg` does `cmd.output()` (`:58`), and
   the fallback does a full `std::fs` walk + `read_to_string` loop
   (`:217-243`). rg on a large tree stalls a tokio worker for seconds.
   WO 38.3 swept web_fetch DNS and worktree git but missed this file;
   the repo pattern is `spawn_blocking` (`src/tui/keys/slash_commands.rs:671-679`,
   `src/session/worktree.rs:19-31`).

Dismissed as benign (verified): no std lock held across `.await` anywhere
(best-practice comment at `src/session/mcp_client/mod.rs:1263-1271`); bash
runner/hooks cancellation is exemplary (`bash_runner/mod.rs:684-737`,
`hooks.rs:640-660`: kill_on_drop + biased select + group kill + bounded
drain joins); TUI teardown order is defined (`tui/mod.rs:396-449`);
fire-and-forget spawns are channel-bounded (`caching.rs:310`, MCP shutdown
watch `http.rs:626-633`); zero `.recv().unwrap()` outside tests; zero
`reqwest::blocking`.

## Root cause

Graceful-shutdown work was done per-surface (TUI, daemon, bash runner) but
never audited for the exits that bypass it: default-SIGINT line mode and
panic-abort. The 38.3 blocking sweep was grep-based, not tool-trait-based,
so the grep tool escaped it.

## Approach

1. `AuditLog::write_entry`: flush the BufWriter after each `writeln!`
   (`audit.rs:209-215`). Audit writes are low-frequency (one line per
   destructive call); per-entry flush is the whole fix for panic/SIGKILL loss.
2. Line mode: register `tokio::signal::ctrl_c` in `run_line_mode` that
   mirrors TUI teardown — cancel the executor channel, save carryover, let
   runtime drop kill in-flight children (`kill_on_drop` fires on graceful
   task drop). Reuse the existing shutdown `AtomicBool` plumbing
   (`line_mode.rs:404-501`).
3. `Grep::execute`: move `rg_available`/`run_rg`/fallback walk into
   `tokio::task::spawn_blocking` (38.3 pattern; `PathGuard` check stays
   inside the closure — it is sync and `Send`).
4. One pinning test each: audit entry readable on disk immediately after
   `write_entry`; line-mode ctrl_c flips the shutdown path (event-driven,
   no wall-clock sleep).

Not doing: no shutdown-order enum for registry teardown (order is already
correct in practice — executor Drop clears listeners `executor/mod.rs:1291-1297`,
teardown saves carryover, AuditLog flushes at step 1 regardless of order);
no panic-hook audit flush (subsumed by per-entry flush); no switch off
`panic = "abort"` (pinned in state.md architecture notes).

Coordinate with WO 38.10-P2 ("Ctrl-C polish", deferred bucket) and WO 43.10
(state persistence policy — this WO is runtime mechanics, not persistence).
