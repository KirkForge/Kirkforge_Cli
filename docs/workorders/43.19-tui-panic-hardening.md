# WO 43.19 — TUI unicode-cursor fix + render-path test coverage

## Status: Planned

## Problem

src/tui = 31,466 lines, 628 tests (536 `#[test]` + 92 `#[tokio::test]`) — but
concentrated in commands/keys. Worst module ratios (verified `grep -c`):

| File | Lines | Tests |
|------|-------|-------|
| commands/jobs.rs | 911 | 4 (indirect via commands/mod.rs) |
| widgets/chat/lines.rs | 561 | 0 |
| syntax/language.rs | 357 | 0 |
| rendering/table.rs | 158 | 0 |
| rendering/format.rs | 99 | 0 |

Unicode-slicing audit result (severity-honest): the render paths are already
largely panic-hardened — zero non-test `.unwrap()`/`.expect(` in widgets/,
rendering/, events.rs; `case_fold_with_mapping` (search.rs:90) is
boundary-correct; syntax/mod.rs advances by `len_utf8`; PTY tail cut is
boundary-safe (events.rs:477); textwrap `.max(1)` guards (38.11). The classic
ratatui emoji-slice crash does NOT currently exist. One real bug found:

- `set_cursor_line_col` (app.rs:872-889) mixes units: `cursor_position =
  char_idx + col.min(...)` where `char_idx` is a BYTE offset (from
  `char_indices()`) but `cursor_position` is a CHAR index everywhere else
  (cursor_byte app.rs:804-811, keys/mod.rs:1299, text.rs:95-104). Click in
  prompt with any multibyte char on an earlier line → cursor lands wrong
  (clamped to end). Not a panic (`char_indices().nth` clamps); a correctness
  bug. Tests at events.rs:1875-1881 are ASCII-only, so it ships green.

Secondary: `selftest.rs` (full-pipeline TestBackend harness built for exactly
this) has no emoji/CJK/combining-char scenario and one narrow geometry
(40x10, selftest.rs:1091). Truncation helpers are safe but scattered (5
copies; sessions.rs:255 byte-slices with an ASCII-id comment as the only
guard).

Boundary: NOT 43.5 (PlaceholderTab opacity), NOT 43.16 (dispatch panic
sites). Long fns in src/tui (dispatch_turn_event 393, render_markdown 330,
render_chat 325, approval 283, run_event_loop 250) stay refactor-on-touch
per 43.0.

## Root cause

`set_cursor_line_col` was added in WO 32.12 without a shared cursor-unit
convention; byte offsets and char indices read identical on ASCII test
fixtures, so the mismatch was invisible. Coverage gap: render logic
extracted into pure modules (lines.rs, format.rs, table.rs) never got the
tests the god-functions they were split from never had either.

## Approach

1. Fix `set_cursor_line_col`: count chars skipped per line (not byte
   offsets); clamp col against the line's char count. One function.
2. Multibyte regression tests: extend events.rs:1875 tests with emoji/CJK
   fixtures (click mid-emoji-line asserts exact char index).
3. Add selftest.rs scenarios: emoji + CJK + combining-char chat content
   through full `render_app` at 120x40 AND 20x8; search-highlight query
   overlapping a multibyte char; tool card with emoji output.
4. Direct unit tests for the zero-test pure modules: chat/lines.rs
   (grouped_tool_header, tool_card_lines, render_entry_lines),
   rendering/format.rs, rendering/table.rs.
5. Leave truncate helpers as-is (all safe); no consolidation — YAGNI.

No TUI rewrite, no new deps, no struct changes.
