# WO 43.2 — Bounded EAGAIN/EINTR retry on the atomic-write primitive

## Status: Planned

## Problem

`src/tools/atomic_write.rs:53-62` — `write_fsync_rename` propagates every error
from `open`/`sync_all`/`rename` verbatim:

```rust
let mut file = OpenOptions::new().write(true).create_new(true).open(tmp)?;
file.write_all(contents)?;
file.sync_all()?;
drop(file);
rename_with_retry(tmp, target)
```

No `Interrupted` (EINTR) retry: `open`, `fsync`, and the Unix `rename`
(`atomic_write.rs:90-93`, single-shot `std::fs::rename`) can all return EINTR
under signal load; a tool write fails spuriously. Callers: `edit_file.rs:320,409`,
`write_file.rs:166`, `notebook_edit.rs:196`.

Verified against `src/tools/atomic_write.rs:53-62` — no EAGAIN/EINTR handling
exists in this file or any other copy.

## Root cause

Each syscall site retries nothing; the only retry in the file is the Windows
rename path. There is no shared "retry spurious error" wrapper for the
open/fsync/rename sequence.

## Approach

1. Add a private helper in `src/tools/atomic_write.rs`:
   ```rust
   fn retry_interrupted<T>(mut f: impl FnMut() -> std::io::Result<T>) -> std::io::Result<T> {
       const MAX_ATTEMPTS: usize = 10;
       for attempt in 0..MAX_ATTEMPTS {
           match f() {
               Ok(v) => return Ok(v),
               Err(e) if e.kind() == std::io::ErrorKind::Interrupted
                   && attempt + 1 < MAX_ATTEMPTS =>
               {
                   std::thread::sleep(std::time::Duration::from_millis(1));
               }
               Err(e) => return Err(e),
           }
       }
       unreachable!("retry loop returns or errors before exhausting attempts")
   }
   ```
2. Wrap the three EINTR-able calls: `open(tmp)` (line 57), `file.sync_all()`
   (line 59), and the Unix rename arm (line 92, `#[cfg(not(windows))]`).
3. Unit test: closure-based — a fake `FnMut` failing N-1 times with
   `ErrorKind::Interrupted` then succeeding; assert success, and assert a
   non-Interrupted error passes through on first hit.

Cap is 10 attempts / 1ms, not the claimed 1000/1ms: 10 matches the house
precedent `MAX_ATTEMPTS = 10` in `rename_with_retry` (`atomic_write.rs:75`);
1000×1ms stalls a sync tool path for a full second under signal storm.
