No file locking anywhere (grep flock/fs2: none). Concurrent index/usage writers are last-writer-wins at worst — index is atomic + rebuildable, so no fix needed. Not in scope: 43.2 (EINTR retry), 43.10 (state policy), 42.7 (offload eviction).

## Root cause

Durability policy is inconsistent: the conversation log got per-message fsync + heal (WO 38.6/38.9), but the audit trail — the record you need *after* a crash — is the least durable store in the repo, two append-only writers use in-place truncation, and load paths treat a torn tail as fatal where a 5-line skip would do.

## Approach

1. `AuditLog::write_entry` (audit.rs:201-216): write + `sync_data` per entry, drop the BufWriter. Audit volume is destructive-calls-only; per-entry fsync is the point of an audit log.
2. `FileAuditSink`: add `impl Drop` → flush; in `new()`, if the **final** line is unparseable, truncate it before resuming the chain (torn tail ≠ tamper); `verify_chain` skips an unparseable final line the same way.
3. `load_messages` (conversation.rs:506-539): treat a per-line UTF-8 error like a corrupt line (skip + `corrupt = true`) instead of failing the whole file — read via `read_until(b'\n')` + `String::from_utf8_lossy`.
4. task.rs:505-513 and kf-context-index lib.rs:1214-1219: replace `std::fs::write` with same-dir temp + rename (crate-local helper mirroring carryover.rs:247-251; kf-context-index cannot import src/tools).
5. `CachedIndex`: add `#[serde(default)] pub format_version: u32` (const CURRENT = 1); `load()` returns a rebuild signal on mismatch instead of trusting serde defaults forever.

## Gate

Standard clippy/fmt/nextest + new tests: (a) SIGKILL-sim — write N audit entries without Drop, read file, all N present; (b) torn final audit line → chain resumes from last intact hash, `verify_chain` true; (c) session log with mid-file invalid UTF-8 byte → earlier/later valid lines survive; (d) cache.json partial write (kill between write and rename) → old cache intact.

## Done

Audit records survive SIGKILL; no torn tail can brick /resume, chain verification, or the context-index cache; all single-file stores write atomically or tolerate their own torn writes.
