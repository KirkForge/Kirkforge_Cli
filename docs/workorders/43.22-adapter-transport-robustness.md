# WO 43.22 — Adapter transport/streaming robustness residual

## Status: Done

## Problem

Transport layer is mostly solid (shared retry, idle timeouts, WO 38.5/36.3
truncation+cancel semantics). Verified gaps remain:

1. **Bedrock truncation laundered into success.** The envelope wrapper
   injects `data: [DONE]` at every stream end (anthropic_bedrock.rs:199),
   and the Anthropic parser maps `[DONE]` → `Done{Stop, usage: None}`
   (anthropic/sse.rs:99-104). A mid-turn transport drop emits an Error
   frame (anthropic_bedrock.rs:192-195) then `Done{Stop}` — bypassing the
   truncation path every other adapter hits (turn.rs:1222) and discarding
   accumulated usage. Anthropic/openai_compat emit `Done{Error}` on
   EOF-without-terminal (sse.rs:235-258, openai_compat/mod.rs:322-350);
   ollama_ndjson emits no Done and turn.rs:1222-1255 catches it.
2. **Retry-After ignored on 429.** send_with_retry (mod.rs:122-134) sleeps
   computed backoff only; header never read (repo-wide grep: zero hits).
3. **Deterministic jitter.** retry_backoff (shared/mod.rs:1036-1041)
   derives jitter from attempt number — parallel subagents
   (task_spawner, max_bg_tasks=4) hitting 429 sleep identically →
   synchronized retry waves on a shared gateway.
4. **Usage=None → silent cost undercount.** turn.rs:1148 `if let Some(u)`;
   providers that omit usage skip record_turn + CostStats entirely —
   session reads zero-cost. No estimator fallback despite the WO 42.12
   token_count cache.
5. **Undisclosed unknown-event drops.** anthropic/sse.rs:206 `_ => {}`
   (ping is correct to drop, but silent for all unknown types — WO 43.8
   flagged; still no comment); openai_compat frames with no
   choices/usage silently ignored (openai_compat/mod.rs:193-246).
6. **No connect_timeout.** build_reqwest_client (mod.rs:64-72) sets only
   tcp_nodelay; SYN blackhole burns the full 120s request timeout
   before retry classification.
7. **Vertex OAuth per turn, unretried.** Token fetched per stream() call
   (anthropic_vertex.rs:127) outside send_with_retry — correct for 1h
   expiry but adds a roundtrip and fails hard on transient OAuth errors.

## Root cause

Adapters converged on shared framing/retry primitives piecemeal (WO 32.13,
38.5, 36.3); the Bedrock wrapper predated the WO 38.5 truncation semantics
and its `[DONE]` injection was never re-examined. Retry/timeout knobs were
never revisited after subagent parallelism made the client a herd member.

## Approach

1. Bedrock: forward `[DONE]` only when a terminal (`message_stop`) frame
   was seen; otherwise let EOF produce `Done{Error}` via the existing
   parser path (delete the unconditional send at :199).
2. send_with_retry: parse `Retry-After` (seconds form) and sleep
   `max(header, retry_backoff(attempt))`.
3. retry_backoff: mix SystemTime nanos into the jitter term (no new dep).
4. turn.rs Done handler: when `usage.is_none()`, estimate from cached
   `token_count` (WO 42.12) and emit CostStats marked estimated.
5. Disclosure comments at sse.rs:206 and openai_compat frame dispatch.
6. build_reqwest_client: add `.connect_timeout(10s)`.
7. Vertex: cache token with expiry margin inside the adapter.

## Done

All 7 Approach items shipped on branch `wo/wo43.22` (commits ef3f33df,
b7ca2da2, 7cdec39f, 1d57e3b7, aa20dcaf, d35345a5, caed29b5):

1. **Bedrock [DONE] gating** — `parse_bedrock_event_stream` tracks
   `saw_message_stop` (new `is_message_stop` helper: cheap substring
   pre-check + JSON type verify, so prose containing the literal
   `"message_stop"` can't false-positive). `data: [DONE]` is forwarded
   only when the terminal frame was seen; a mid-stream drop flows to
   the parser's EOF path → `Done{Error}` with accumulated usage.
   Tests: `parse_bedrock_event_stream_transport_drop_yields_done_error`,
   `parse_bedrock_event_stream_complete_stream_yields_done_stop`,
   `is_message_stop_*`.
2. **Retry-After** — new `retry_delay(retry_after, attempt)` sleeps
   `max(header_secs, retry_backoff(attempt))`; seconds form only
   (HTTP-date ignored). Test:
   `retry_delay_honors_retry_after_over_computed_backoff`.
3. **Jitter de-herding** — `retry_backoff` jitter is now
   `subsec_nanos % cap` (cap unchanged: 250ms/attempt, 1s overall);
   bounds and monotonicity preserved; existing range tests still pass.
   Test: `backoff_jitter_varies_across_calls`.
4. **Usage-None cost fallback** — `stream_iteration` Done handler
   synthesizes a `TokenUsage` (prompt = preamble per-message estimates
   via the WO 42.12 cache; completion = appended assistant message's
   cached `token_count`) and rides the same record_turn + CostStats +
   CacheStats path. Estimated marking follows the existing convention
   (plain counts, like CacheStats' estimated `stem_tokens`) + a
   `tracing::info!` "reporting estimated token counts" line; adding an
   `estimated` field to the TurnEvent would have churned 8 files
   outside this WO's list — deferred, see below.
5. **Disclosure comments** — sse.rs unknown-event arm and
   openai_compat's no-choices/no-usage frame dispatch now document the
   intentional drops. No behavior change.
6. **connect_timeout(10s)** — adapters' `build_reqwest_client` only;
   `shared/mod.rs`'s second `build_reqwest_client` (MCP etc.) is out of
   WO scope and untouched.
7. **Vertex token cache** — `service_account_token` returns the full
   `yup_oauth2::AccessToken`; the adapter caches it in a
   `tokio::sync::Mutex` and refetches only when `is_expired()` (which
   carries yup's built-in 1-minute margin). Ceiling noted in code: a
   token with no server expiry is cached for the adapter's lifetime
   (GCP always sends expires_in).
