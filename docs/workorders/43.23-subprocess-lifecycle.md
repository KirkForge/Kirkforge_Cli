# WO 43.23 — Subprocess lifecycle: parent-death orphans, MCP idle-kill, unguarded host-crate spawns

## Status: Planned

## Problem

Shared infra is good: `setup_process_group`/`kill_process_group`/`reap_child`
(`src/session/process_group.rs:32-101`) give setpgid+killpg+bounded reap, and
bash jobs, hooks, MCP, and the plugin wrapper all use it. Verified gaps:

- **No parent-death coverage.** Grep finds no `PR_SET_PDEATHSIG` anywhere
  (seccomp.rs only sets NO_NEW_PRIVS). `panic = "abort"` (`Cargo.toml:340`;
  the WO 38.2 hook restores the terminal only, `src/tui/mod.rs:158-159`)
  means abort/SIGKILL runs no Drop — and children sit in their own background
  process groups, so they get no terminal signal either. Result: abort or
  SIGKILL orphans every MCP server, bash job, and plugin tool.
- **Normal exit leaks background jobs.** `GLOBAL_REGISTRY`
  (`src/session/bash_jobs.rs:70`) is a `OnceLock` static: never dropped, so
  `kill_on_drop` never fires, and no exit path cancels running jobs (only the
  `/jobs` TUI commands call cancel/clean). `bash(background=true)` + quit
  leaves a live orphaned process group. (Distinct from 43.10 registry
  persistence; this is process survival.)
- **MCP idle-kill.** `READER_IDLE_TIMEOUT` = 10s (`src/session/mcp_client/mod.rs:106`)
  applies to the reader unconditionally (`mod.rs:583-607`), while
  `REQUEST_TIMEOUT` is 30s and stdio MCP has no keepalive requirement. A
  server silent >10s between calls is marked dead → next call respawns
  (`src/session/mcp_client/manager.rs:212-226`), killing server-side state; a
  tool slower than 10s without progress notifications fails as Disconnected.
  Also: production has no graceful disconnect (`disconnect` is `#[cfg(test)]`,
  `mod.rs:907,1228`); Drop SIGKILLs (`mod.rs:1275-1310`) with best-effort
  detached reap (`spawn.rs:44-47`); reconnect has no backoff. Framing is
  solid: line-delimited, non-JSON stdout lines traced+skipped (`mod.rs:617-620`),
  stderr drained (`spawn.rs:12-41`); `MAX_LINE_LEN` is only checked after the
  newline (`mod.rs:589`) — unbounded buffer growth pre-newline (minor).
- **Hooks (session path): solid.** 5s timeout + killpg + capped output +
  exit-2 deny / fail-open (`src/session/hooks.rs:584-719`). Plugin hooks ride
  the same `run_hook_script`.
- **Plugin wrapper (bin): solid.** Timeout `tool_timeout_secs` (default 120,
  clamp 1-3600) + killpg + reap + cancel token (`src/session/plugin_tools/wrapper.rs:240-369`).
  (Landlock `None` is 43.11's, not duplicated.)
- **kf-plugin-host crate: two unguarded spawns.** `PluginVerifier` has a 5s
  killpg watchdog (`crates/kf-plugin-host/src/verifier.rs:29,118-150`), but
  `PluginTool::execute` (`crates/kf-plugin-host/src/tool.rs:90-129`) and
  `PluginHook::run` (`crates/kf-plugin-host/src/hook.rs:59-95`) are blocking
  `std::process` calls with NO timeout, NO process group, and unbounded
  `.output()` buffering. Unwired in the bin today (it uses `PluginToolWrapper`),
  so latent — but exported public API.
- Bash jobs watcher/reap/watchdog are sound (`bash_jobs.rs:265-399`); drain
  timeout output drop (`:352-367`) is already 43.8; concurrency races are 43.18.

## Root cause

Per-site kill/reap discipline exists, but nothing covers *parent death*
(abort and clean exit both leak), MCP liveness conflates "silent" with
"dead", and kf-plugin-host predates the process-group helpers.

## Approach

1. Add `prctl(PR_SET_PDEATHSIG, SIGKILL)` to `setup_process_group`'s
   pre_exec (Linux; no-op elsewhere) — direct children die with the parent
   on abort/SIGKILL/quit with zero Drop dependence. One helper, all
   subsystems inherit.
2. Cancel running background jobs on session teardown (TUI shutdown +
   line-mode exit) — a small sweep next to the existing shutdown wiring.
3. MCP: arm `READER_IDLE_TIMEOUT` only while `pending` is non-empty (idle
   server stays connected; hung in-flight request still bounded).
4. kf-plugin-host: port the verifier's existing watchdog pattern
   (`verifier.rs:118-150`) into `PluginTool::execute` and `PluginHook::run`
   (process_group(0) + bounded wait + killpg). Reuse the one pattern, no
   framework.
