## Root cause

No gate checks assertion quality. Smoke tests ("doesn't panic") accumulated
and names drifted from bodies. cargo-mutants (43.14) finds these mechanically
later; this WO fixes the known ones first.

## Approach

1. Fix named weak tests to assert observable state: reqwest client config,
   capture output for "quiet" tests, `pending` untouched in mcp noops,
   register a hook + marker in hooks.rs:1546.
2. Delete tests that cannot fail (mcp_client:1731 empty-map noop).
3. Upgrade `glob_match_total_unicode` to at least assert determinism.
4. Repoint stale kf-rbac ignore reason at state.md pending.
5. Optional, only if cheap: assert-free-body heuristic in kf-testdoctor
   (suggest.rs already parses test sources).

## Done

Test-only changes; no production behavior touched. Commits on `wo/wo43.24`
(off dev `e1e5e6b2`), final HEAD see `git log`. All edited tests verified
able to fail: each asserts observable state.

1. `src/adapters/mod.rs` — `build_reqwest_client_returns_a_working_client`
   (renamed): reqwest exposes no config getters (no timeout/tcp_nodelay
   accessors), so the observable contract is behavioral — the built client
   completes a `GET` round trip against a loopback `tokio::net::TcpListener`
   (status 200, body "ok", request line checked). Deliberately NOT asserting
   `connect_timeout` — WO 43.22 adds it concurrently; the round-trip holds
   under both versions.
2. `src/session/hooks.rs` — `test_run_with_context_fires_in_process_hook`:
   registers a `MarkerHook` (`PostHook`, the hook class `run_with_context`
   actually fires, hooks.rs:363) incrementing an `AtomicUsize` + capturing
   `ctx.event`. Asserts: fires exactly once for the matching event, receives
   the fired event's context, and does NOT fire for a non-matching event.
3. `src/shared/access/mod.rs` — added `capture_tracing_output` helper
   (scoped `with_default` subscriber + `MakeWriter` into a shared buffer;
   `tracing-subscriber` already a direct dep). The two `*_is_quiet` tests
   now capture and assert no "unsandboxed" warning; the default-guard test
   was renamed `..._emits_warning` and asserts the warn DOES fire — this
   also validates the capture harness (the quiet assertions are not
   vacuously green).
4. `src/session/mcp_client/mod.rs` —
   `test_dispatch_response_null_id_is_routed_correctly` now inserts an
   unrelated waiter ("other") and asserts after a null-id dispatch that
   (a) the pending entry survives (not stolen/drained) and (b) the waiter
   is unresolved (`rx.try_recv().is_err()`, same pattern as :2004 sibling).
   Edits confined to the test region (WO 43.23 owns reader-timeout logic).
5. Deleted the two can't-fail noops:
   `test_dispatch_response_unknown_id_is_noop`,
   `test_fail_all_pending_empty_map_is_noop` (both had zero assertions).
6. `src/shared/permission.rs` — `glob_match_total_unicode` now asserts
   determinism: two calls with identical inputs must agree
   (`prop_assert_eq!`), matching the ASCII sibling.
7. `crates/kf-rbac/tests/jwt.rs` — ES512 `#[ignore]` reason and doc comment
   repointed from "tracked in WO 32.10" (Done, `c20c833`) to
   "tracked in state.md pending".
8. `*_does_not_panic`/`*_is_noop` smoke class: left in place per WO scope —
   they document no-panic contracts; the mechanical sweep is covered by the
   cargo-mutates gate (WO 43.14, Done).
