# WO 43.26 — Unguarded subprocess spawns (workflow bash, plugin-bus verifier)

## Status: Planned

## Problem

Fresh segment audit (round 4). Two independent subprocess spawn paths have no
timeout, no cancel token, and no `kill_on_drop` — a hung child blocks the
caller indefinitely and cannot be cancelled. These are the same class 43.23
covered for `kf-plugin-host` tool/hook, but in different modules, and 43.18
only swept the grep tool for runtime blocking.

1. **Workflow bash steps** (`src/tools/workflow.rs:266,370`): `run_bash` and
   the batch Bash arm spawn `tokio::process::Command::new("sh").arg("-c").arg(
   command).output()` with NO `.timeout()`, NO `kill_on_drop`, and no select
   on the workflow cancel token (the token is only wired into the Tool branch,
   `workflow.rs:331,405`). `output()` consumes the child and waits
   indefinitely. A template bash step like `sleep infinity` or a stuck build
   hangs the workflow_run tool until the executor's outer tool timeout, and
   cannot be cancelled. The foreground bash tool routes through
   `run_shell_with_token` (`bash.rs:437`) which has token+timeout; this is a
   parallel unguarded implementation.

2. **`PluginBusVerifier::verify`** (`src/session/verifier/bus.rs:279`): calls
   `self.inner.run(&env)` synchronously — spawns a blocking subprocess on the
   caller's tokio worker with NO timeout, NO `kill_on_drop`, NO process group.
   `VerifierBus::run` is invoked from the executor's async verification path;
   a hung plugin verifier script blocks the worker thread indefinitely. The
   event-driven legacy path (`plugin.rs:90`) uses `spawn_blocking` — the bus
   path is the inconsistent one.

## Root cause

The graceful-spawn pattern (token + timeout + kill_on_drop) was implemented
per-path, and two newer paths (workflow bash, plugin bus verifier) did not
inherit it.

## Approach

1. workflow.rs: wrap both bash spawns with `tokio::time::timeout` on the
   step timeout and select on the workflow cancel token; set `kill_on_drop`.
2. bus.rs: move the plugin-verifier run behind `spawn_blocking` (matching
   `plugin.rs:90`) with a timeout and `kill_on_drop` (mirror `hooks.rs:640-660`).
3. One pinning test each: workflow bash step cancelled via the token;
   plugin-bus verifier respects a timeout.

- `src/session/verifier/bus.rs`

No unguarded subprocess in the workflow or plugin-bus paths: every spawn has a
