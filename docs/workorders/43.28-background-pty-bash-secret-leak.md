# WO 43.28 — Background/PTY bash secret leakage (env scrub gap)

## Status: Planned

## Problem

Fresh security audit (round 4). The foreground bash path scrubs
credential-shaped env vars before spawning the child shell
(`bash_runner/mod.rs:645` → `scrub_secrets_from_child_env`, `:592-598`), but
two other spawn paths never apply it. This defeats the documented threat
model ("the model's bash tool must not be able to read provider/session
secrets even with approval", `bash_runner/mod.rs:587-591`).

1. **Background/scheduled bash jobs** (`src/session/bash_jobs.rs:191-196`):
   `BashJobRegistry::spawn` builds the command with only
   `.args(["-c", command])` and inherits the parent's entire environment —
   no `scrub_secrets_from_child_env`, no `env_clear`, no `env("PATH", ...)`.
   The daemon scheduled-jobs runner routes through the same path
   (`jobs/runner.rs:107-119`). The model can run
   `bash(background=true, command="printenv | grep -iE 'ANTHROPIC|_API_KEY|_TOKEN|_SECRET'")`
   and read the captured stdout via `bash_status`, bypassing the scrub. Not
   covered by WO 42.3 (which only adjusted the suffix list on the foreground
   path).

2. **PTY/interactive path** (`src/session/bash_runner/pty.rs:26-34`): spawns
   `sh -c <model-supplied command>` with no env scrub (inherits full env), no
   rlimit/landlock, no process group, and no timeout — the read loop at
   `:38-51` blocks until EOF. Mitigated: feature-gated off by default.

## Root cause

The secret-scrub was applied to the foreground `run_shell_with_token` path
only; the background-job and interactive-PTY spawn paths (which reuse the same
shell) were never routed through it.

## Approach

1. Factor the env-scrub into a shared helper and apply it in
   `bash_jobs::spawn` (and the `jobs/runner.rs` scheduled path it feeds).
2. Apply the same scrub (and, where feasible, a timeout/kill) to the PTY
   path; if the PTY path is intentionally a dev-only escape hatch, gate it
   behind an explicit flag and document the caveat.
3. One pinning test: a background job cannot observe a secret-shaped env var.

## Files

- `src/session/bash_jobs.rs`
- `src/jobs/runner.rs`
- `src/session/bash_runner/pty.rs`

## Gate

`scripts/test-fast.sh`, `cargo clippy --all-targets -- -D warnings`,

## Done

No bash surface (foreground, background, scheduled, PTY) exposes credential
env vars to the model.
