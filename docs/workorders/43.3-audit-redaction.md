# WO 43.3 — Audit-log redaction residual gap

## Status: Planned

## Problem

The backlog asks to "port the redaction.cjs pattern — strip env vars, API keys, file contents from audit log entries". Partially drifted — key-shape redaction already exists and 42.3 covered child-env scrubbing, not logs:

- `redact_args` (`src/shared/audit.rs:867`) already drops `content`/`old_string`/`new_string`, keeps `path`, blanks all other keys for `Tool` entries (tested at audit.rs:943).
- WO 42.3 expanded `is_secret_env_name` (`src/session/bash_runner/mod.rs:561`) — but that scrubs the **child process env** (`scrub_secrets_from_child_env`, mod.rs:592), never log lines.

Residual gaps — free-text fields that reach the audit log **unredacted**:

1. bash `command` is kept verbatim (truncated to 1 KiB) — `audit.rs:875-881`:
   `"command" if tool == "bash" => { ... truncate_string(cmd, 1024) }`. Inline secrets reach disk: `export GITHUB_TOKEN=ghp_x`, `curl -H "Authorization: Bearer sk-ant-..."`. Emit sites: `src/session/executor/turn.rs:647,698,897`, `pre_run.rs:147`, `dispatch.rs:587,748`.
2. `PluginTool.args_summary` — `src/session/plugin_tools/wrapper.rs:236`: `let args_summary: String = args_json.chars().take(200).collect();` — first 200 chars of raw args JSON, written via `log_plugin_tool` (wrapper.rs:378, audit.rs:100-113). Plugin tool args can carry file contents/secrets; `redact_args` is not applied.
3. `Hook.reason` passthrough (audit.rs:88-97, emit `src/session/hooks.rs:256,293,299`) — verdict reasons may quote command text/stderr. Lower severity.

## Root cause

Redaction exists only as key-shape filtering on the `Tool` variant. Retained free-text fields (bash command, plugin args summary, hook reason) get no value-level scrubbing, so anything embedded in a command string or plugin args is logged as-is.

## Approach

1. Add a `scrub_free_text(&str) -> String` in `src/shared/audit.rs`: replaces `NAME=value` tokens where NAME matches the credential shapes (share the list from `is_secret_env_name` — make it `pub(crate)` in `bash_runner/mod.rs:561` or move the suffix list to `shared`), plus common token literals (`Bearer ...`, `sk-...`, `ghp_...`, `AKIA...`).
2. Apply in `redact_args` to the retained bash `command` (after truncation).
3. Apply to `args_summary` before `log_plugin_tool` (wrapper.rs:236).
4. Apply to `Hook.reason` at the `AuditEntry::hook` constructor.
5. Tests: assert a logged `bash` command containing `GITHUB_TOKEN=ghp_x` and a `Bearer sk-...` header comes back scrubbed; assert plugin `args_summary` scrubbed.

## Files

- `src/shared/audit.rs`
- `src/session/bash_runner/mod.rs` (expose the name list)
- `src/session/plugin_tools/wrapper.rs`

## Gate

`cargo nextest run -p kf-code --lib --locked -- audit` + full local gate (`scripts/test-fast.sh`, clippy, fmt).

## Done

All free-text fields that survive key-shape redaction are value-scrubbed before write; tests cover bash-command, plugin-args, and hook-reason paths.
