# WO 43.32 — Bash env-override layer dead in production

## Status: Planned

## Problem

Fresh segment audit (round 4). `apply_env_overrides` is imported under
`#[cfg(test)]` (`src/session/config/mod.rs:64`) and only invoked inside the
`mod tests` block (call sites at `mod.rs:1078+`). The production load path
`load_config` (`mod.rs:100-132`) reads defaults then the TOML file and
returns — it never calls `apply_env_overrides`. So every `KF_CODE_*` var the
module header documents as production layer-2 (`mod.rs:3-7`: `KF_CODE_MODEL`,
`KF_CODE_HOST`, `KF_CODE_AUTO_APPROVE`, `KF_CODE_SANDBOX_DIR`,
`KF_CODE_PLUGIN_SIGNATURE_VALIDATION`, `KF_CODE_REJECT_ON_EXCESS_PLUGIN_TRUST`,
etc.) is silently ignored in the shipped binary. A user who sets
`KF_CODE_AUTO_APPROVE=true` (documented at `config/mod.rs:12`, relied on by
`tests/e2e/scenarios/auto_approve_skip.rs:4`) gets default-deny;
`KF_CODE_SANDBOX_DIR` is never honored; security toggles are inert.

## Root cause

The env-override layer was written and tested but never wired into the
production `load_config` path — an env_layer function that is
test-only-by-accident.

## Approach

Call `apply_env_overrides(&mut cfg)` in `load_config` after the TOML merge
(and before returning). Keep the test harness working (it exercises the same
function). Add a pinning test that sets a `KF_CODE_*` var and asserts it is
honored by `load_config`.

## Files

- `src/session/config/mod.rs`

## Gate

`scripts/test-fast.sh`, `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check`. Env-override test green.

## Done

`KF_CODE_*` environment overrides are honored in production config loading,
matching the documented layer-2 contract.
