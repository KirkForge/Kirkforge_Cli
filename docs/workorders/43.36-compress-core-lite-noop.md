# WO 43.36 — kf-compress-core Lite mode is a no-op (identical to Off)

## Status: Planned

## Problem

Fresh crates audit (round 4). `Pipeline::run` gates with
`if !mode.runs_transforms() || !mode.offloads_bloat() { return content; }`
(`crates/kf-compress-core/src/pipeline.rs:162`). `Mode::Lite` has
`runs_transforms()==true` but `offloads_bloat()==false`, so the gate
short-circuits and returns the input before the transform loop at `:167-171`.
Lite is documented/described as "light compression", yet it never applies any
transform — it is a no-op indistinguishable from Off, defeating the Lite tier
entirely.

## Root cause

The gate conflates the two orthogonal mode dimensions (transforms vs
offloading): Lite wants transforms but no offload, and the `||` short-circuit
treats either as "do nothing".

## Approach

Restructure the gate to only skip transforms when `!runs_transforms()` and
only skip offload when `!offloads_bloat()` (independent `if`s), so Lite runs
transforms without offloading. Add a pinning test that Lite actually
transforms content.

## Files

- `crates/kf-compress-core/src/pipeline.rs`

## Gate

`cargo test -p kf-compress-core`, `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check`. New Lite-transform test green.

## Done

`Mode::Lite` applies content transforms (without offloading), distinct from
`Off`.
