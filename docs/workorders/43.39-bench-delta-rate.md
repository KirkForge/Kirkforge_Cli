# WO 43.39 — kf-bench markdown-delta baseline computation contradicts the regression signal

## Status: Planned

## Problem

Fresh crates audit (round 4). `write_markdown_delta`
(`crates/kf-bench/src/lib.rs:410-419`) derives a "baseline" rate from
`delta.tasks` (the union of task names). A task present only in the current
report has `baseline_success=false`, so it counts as a baseline failure; a task
only in baseline counts as a baseline success. This shifts both the displayed
`X%` and `Y%` in "Success rate: X% → Y%" away from the true rates carried in
the summaries (which is what `compare_with_threshold` correctly uses). The
rendered delta row no longer matches the regression decision the report is
showing — misleading when task sets differ between baseline and current.

## Root cause

The delta render recomputes baseline/current from the union-set task list
instead of using the already-available per-report summary rates.

## Approach

Use `delta.baseline.summary.tasks_passed / tasks_run` and the current report's
summary for the two rates (matching `compare_with_threshold`), rather than
recomputing from the union task set. Add a pinning test where baseline and
current task sets differ and assert the rendered percentages match the
summaries.

## Files

- `crates/kf-bench/src/lib.rs`

## Gate

`cargo test -p kf-bench`, `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check`. New delta-render test green.

## Done

The markdown delta report's success rates match the true per-task summaries
and the regression decision, regardless of task-set differences.
