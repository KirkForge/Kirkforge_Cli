# WO 43.5 — Eliminate live panic paths and honored no-op stubs

## Status: Planned

## Problem

Three backlog claims; one is drift, two are real.

**1. scout.rs panic claim — DRIFT, not a live path.** `src/session/executor/scout.rs:138`
is `unimplemented!("stub tool: no real implementation")`, but it lives inside
`#[cfg(test)] mod tests` (mod opens at :103). `StubTool` (:115) is a test fixture
constructed only by the `stub()` helper (:142) for filter tests; the comment at
:136-137 states the `run` body is unreachable from those tests. It is compiled
out of release builds. No action needed beyond closing the claim.

**2. PlaceholderTab ergonomics — real.** `src/tools/computer_use.rs:101-131`
(backlog said 98-150; the impl ends at 131): 9 methods (`navigate`, `click`,
`click_xy`, `type_text`, `keypress`, `scroll`, `screenshot`, `wait_for`,
`evaluate`), all returning `Err(anyhow::anyhow!("Chrome tab not initialized"))`.
Fallback story: registered when `computer_use` is enabled + vision supported but
no Chrome handle exists — `src/tools/mod.rs:286` and `src/main/run_session.rs:394,398`.
ADR-0021:37 pins the intent (register cheap, fail gracefully). The gap: the tool
is advertised to the model, every action fails, and the error never says Chrome
is missing or how to fix it. Behavior is pinned by tests at :1193-1254.

**3. Adapter config no-ops — real.** `src/adapters/mod.rs:345-377`: 8 trait
defaults with empty bodies — `set_json_mode` (:345), `set_response_format` (:347),
`set_seed` (:354), `set_extended_thinking` (:358), `set_budget_tokens` (:361),
`set_max_tokens` (:364), `set_streaming_timeout` (:370), `set_computer_use_dims`
(:377). The executor calls all 8 at construction (`src/session/executor/mod.rs:224-242`)
and re-applies 5 on refresh (:545-559). Override matrix: anthropic overrides all 8;
bedrock/vertex 6 (no `max_tokens`, no `computer_use_dims`); openai_compat and
oellama 4 (json_mode, response_format, seed, streaming_timeout only); the caching
wrapper forwards 6 (no seed, no max_tokens). So `max_tokens` with Ollama, or
`budget_tokens` with OpenAI-compat, is silently accepted and discarded.

## Root cause

Degradation is silent at the boundary: config values and no-Chrome state are
accepted without complaint, then fail generically far from the cause. (The scout
claim was stale — test code mistaken for production code.)

## Approach

1. Close the scout claim as drift; no code change.
2. PlaceholderTab: one shared `const` error message naming the cause and remedy
   ("Chrome/Chromium not available; computer_use requires a local install or
   `computer_use.hosted = true`"), used by all 9 methods. Update the pinned
   tests (:1193-1254) in the same commit. Keep the placeholder itself (ADR-0021).
3. Adapter no-ops: setters can't return errors without a trait break, so make
   the default bodies disclose the discard — `tracing::warn!` once per setter
   when called with a non-default value (e.g. `seed.is_some()`, `max_tokens != 0`).
   Overriding adapters are unaffected.

No live panic path remains claimed (scout verified test-only); PlaceholderTab
