# WO 43.6 — Wire kf-rbac into the daemon

## Status: Planned

## Problem

Verified orphan: `kf-rbac` is a workspace + default member (`Cargo.toml:21,37`) and a `[workspace.dependencies]` entry (`Cargo.toml:71`), but the root package does not depend on it and grep shows zero `kf_rbac` imports under `src/` — only `crates/kf-rbac` itself and docs (WO 35.0 overview already flagged this at `docs/workorders/35.0-wo35-overview.md:45`). The crate compiles and its tests pass (`cargo test -p kf-rbac`) while gating nothing.

Meanwhile the daemon's only auth is all-or-nothing: `DaemonState::check_auth` (`src/daemon/mod.rs:423`) compares one shared bearer token from `KF_CODE_DAEMON_TOKEN_FILE` (constant-time, mod.rs:431) and returns `Ok(())`/`Err` — no roles. All 9 request ops (`Request`, mod.rs:213-292: Ping, List, Resolve, Touch, Shutdown, Claim, QuitAll, NotifyJobsChanged, InstanceRegister) get identical access; `server.rs` calls `check_auth` at 9 sites (222, 309, 324, 338, 356, 366, 376, 391, 401). A read-only consumer token cannot exist; a token either shuts down the daemon or does nothing.

## Root cause

WO 29.5 ported the RBAC library but no consumer was ever wired; the daemon (WO 19.5) predates it and grew a single-token check instead.

## Approach

Small first integration — permission tiers on the existing daemon ops; no JWT/OIDC, no tenant model:

1. Add `kf-rbac.workspace = true` to kf-code's `[dependencies]`.
2. Map the token to an `Actor` (`crates/kf-rbac/src/rbac.rs`): `actor_from_api_key` against a new optional `KF_CODE_DAEMON_ROLE` (fallback `admin`) — single-token deployments keep today's behaviour as Admin.
3. One helper `required_permission(&Request) -> Permission` using the existing 16-variant enum (rbac.rs:50-71): `Shutdown`/`QuitAll` → `OperatorRestart`; `List`/`Resolve`/`Touch`/`Claim` → `ViewerResults`; `Ping`/`NotifyJobsChanged`/`InstanceRegister` → unauthenticated-when-auth-off, else `ViewerStatus`.
4. After `check_auth` succeeds, check `kf_rbac::has_permission(&actor, perm)` (rbac.rs:210); deny with `Response::error("forbidden: ...")`.
5. Tests: viewer-role token can `List` but gets an error on `Shutdown`; no-token behaviour unchanged.

## Files

- `Cargo.toml` (root `[dependencies]`)
- `src/daemon/mod.rs` (`DaemonState`: role/actor + `required_permission`)
- `src/daemon/server.rs` (permission check at the existing `check_auth` sites)

## Gate

`cargo nextest run -p kf-code --lib --locked -- daemon` + full local gate. `cargo test -p kf-rbac` still green.

## Done

`kf-rbac` permission checks gate real daemon requests; the crate is no longer orphaned; single-token deployments see no behaviour change.
