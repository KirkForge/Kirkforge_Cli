# WO 43.8 — Silent error-handling triage (.ok(), unwrap_or_else, catch-all arms)

## Status: Planned

## Problem

Backlog counts drifted. Verified (grep, tests excluded):

- `.ok()`: claimed 18 — actual 137 raw hits. Most are benign by design:
  optional env vars (~12), `.parse().ok()` defaults (~20), temp-file
  `remove_file(&tmp).ok()` cleanup (~15, src/tools/read_file.rs:228-632),
  cache-miss `read_to_string(..).ok()?` (~10), tree-sitter `utf8_text.ok()?`
  (kf-context-index), test-support files.
- `.unwrap_or_else`: claimed 20 — actual 367 raw, 185 after excluding the
  `lock().unwrap_or_else(|e| e.into_inner())` poison-recovery idiom
  (~180 sites, e.g. src/shared/event_bus.rs:193-330) which is the correct
  pattern, not debt. Remainder is mostly `unwrap_or_else(|| default)` value
  defaults — benign. Low-medium risk read: correct.
- `_ => {}`: claimed 48 — actual 43. Claimed "7 moderate-risk event drops" —
  NOT verified; reading them yields ~2 moderate (below), the rest are enum
  forward-compat (crossterm `Event`, `ResponseFormat::None`, KeyCode) or
  by-design accumulators.

## Root cause

No triage: error-context discards, defaults, and forward-compat arms are
indistinguishable in review, so the few risky ones hide among the benign.

## Approach

Triage table, NOT a blanket rewrite. Fix the risky, leave the benign.

Fix (add real error context via anyhow / warn):
1. `src/session/executor/mod.rs:215` — `data_dir().ok()` -> audit path `None`
   -> `AuditLog::new(None)` silently drops every audit entry with NO warn
   (audit.rs:128; the open-failure path warns, this one doesn't). Riskiest:
   security-relevant silent disable. Downgrade: `warn!` + disable, or propagate.
2. `crates/kf-memory-store/src/adapters/sqlite.rs:360` —
   `stmt.query_row(..).ok()` conflates QueryReturnedNoRows with DB/IO errors:
   a failed read reports "object not found". Match on
   `Err(rusqlite::Error::QueryReturnedNoRows)` -> None, propagate the rest.
   Same shape at sqlite.rs:412 (stats) — lower stakes.
3. `src/session/bash_jobs.rs:352-367` — drain-task `.ok()` x2 (timeout/join)
   -> empty stdout/stderr, job still marked Completed: silent output loss.
   At least record dropped-bytes/timeout in the job result.
4. `src/adapters/anthropic/sse.rs:206` — `_ => {}` drops unknown SSE event
   types without trace: a new server event kind vanishes. `debug!` the type.
5. `src/session/mcp_client/mod.rs:798-801` — sampling `StreamEvent::Error`
   is `warn!`ed but the partial text is returned as a complete completion.
   Bail on first error instead.

Leave (benign by design — do not churn):
- Poisoned-lock `into_inner()` recoveries; `unwrap_or_else(|| default)`.
- Temp-file cleanup `.ok()`; optional-env `.ok()`; parse-fallback `.ok()`.
- Cache-miss `.ok()?` readers (`metrics.rs`, `session_index.rs`, `caching.rs:81`
   — a corrupted cache silently re-misses; acceptable, note only).
- Forward-compat arms: `tui/mod.rs:1110,1124`, `tui/events.rs:104`,
   `adapters/mod.rs:704,864`, `anthropic/mod.rs:399`, `hooks.rs:557`.
- Accumulators: `executor/turn.rs:253`, `task_spawner.rs:526` (count-only
  consumers of TurnEvent).
