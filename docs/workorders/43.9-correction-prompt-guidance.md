# WO 43.9 — Per-failure correction prompt guidance

## Status: Planned

## Problem

`crates/kf-routing/src/correction.rs:160-165` — `correction_prompt()` emits one
generic string for every failure:

```rust
format!(
    "targeted correction: overall={:?}, broken_edges={}, lint_errors={}",
    packet.verification.overall, packet.graph.broken_edges, packet.verification.lint.errors
)
```

The `ponytail:` block at :150-159 pins the ceiling: placeholder, not the real
`buildCorrectionPrompt` template (which lives in TS `correction-core`); the
model gets a generic prompt instead of one tailored to the specific verifier
failure. Note the string also ignores `types.errors` and all security counts.

**Dependency check — WO 32.11 exists and is closed as disclosure-only.**
`docs/workorders/32.11-classifier-memory-pathguard.md`, Status: "Done
(comment-only cleanup; all three deferrals disclosed, not implemented)". Its
item 2 is exactly this placeholder: blocker = porting the real template needs
the orchestrator's model-call layer (WO 29.7, not shipped); remaining work =
"port the template into `kf-orchestrator`" (crate exists at `crates/kf-orchestrator`).
So 32.11 tracked the deferral; it did not implement anything. This WO must not
duplicate that scope.

## Root cause

The pure decision function distinguishes failure classes internally (security
escalation at :227, broken-edges at :237, lint/types via `overall`) but the
prompt it emits collapses them all into one line — the class information is
computed and then thrown away.

## Approach

1. Scope line (keeps this disjoint from 32.11's remaining work): no template
   port, no model-call layer, stays inside the pure `kf-routing` crate.
2. Replace the single `format!` with a match on failure class, using the
   packet's own fields: security findings (with critical/high counts and the
   affected paths if non-empty) → "address the reported security findings";
   `broken_edges > 0` → "restore or update the broken imports"; lint errors →
   "fix the reported lints"; types errors → "fix the type errors"; fallback →
   the current generic line. First matching class wins, security first
   (mirrors `decide_correction` precedence).
3. Tests: existing tests only assert `correction_prompt.is_some()` /
   truthiness (:544, :602, :625) — they keep passing. Add one test per failure
   class asserting the class-specific guidance substring appears.
4. Update the `ponytail:` comment: the "no per-failure guidance" ceiling is
   lifted; the template port remains deferred under 32.11's remaining work.
