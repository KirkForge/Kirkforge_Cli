# WO 44.28 — Phase 2.5 symlink-swap re-verification is unreachable on the allowed path

## Status: Planned

## Problem
The WO 38.1 symlink TOCTOU defense (`symlink_swap_denied`, `src/session/executor/dispatch.rs:724-738`) is
nested inside the `GuardVerdict::Denied` arm of the read-before-edit gate
(`src/session/executor/dispatch.rs:448-493`):

```rust
let needs_read_gate = name == "edit_file" || (name == "write_file" && path.exists());
if needs_read_gate {
    if let GuardVerdict::Denied(msg) = self.sandbox.check_edit(...).await {
        ...
        if let Some(msg) = symlink_swap_denied(&path) {   // ← only runs when ALREADY denied
```

The comment at dispatch.rs:453-462 says the walk runs "right before the body closes the
final-component and parent-swap cases **for reads and writes**", and commit `cfad1342`
(WO 38.1) intended "symlink component walk before the body". But:

1. When `check_edit` returns `Allowed` (the normal case — the model read the file earlier,
   which is exactly the attack precondition), the walk never runs; the tool body executes at
   dispatch.rs:497 with no symlink re-check. The walk only changes the *message* of a denial
   that was already happening for a different reason.
2. `read_file`/`read_image` never reach the walk at all: `needs_read_gate` is false for reads
   (dispatch.rs:447), so even the denied-path walk is edit/write-only. The in-tree test
   `symlink_swap_denied_blocks_swapped_file` (dispatch.rs:766-783) is explicitly documented as
   "the read-side `.ssh` swap case from the audit" — yet production never runs the walk on any
   read.

Attack shape (unchanged since WO 38.1 claimed it closed): batch `[bash, edit_file]` where the
bash call replaces a validated parent dir or the target file with a symlink between Phase-1
canonicalization and the Phase-2.5 body. Phase 1 resolved the real path; the gate passes
(file was read); the body then opens attacker-controlled symlink target.

## Root cause
The `if let GuardVerdict::Denied` binding placed the re-verification inside the denial branch
instead of before the gate, so the defense executes only on calls that were already blocked.
Reads were never wired into the walk despite the test naming the read-side case as the
motivating audit finding.

## Approach
1. Hoist `symlink_swap_denied(&path)` out of the `Denied` arm: run it unconditionally in
   Phase 2.5 for every deferred file call (read_file, read_image, write_file, edit_file)
   right before `run_prepared_call` (dispatch.rs:497), inserting the existing
   `ToolOutcome::Failure(AccessDenied)` result on a hit (mirrors dispatch.rs:463-478).
2. Keep the existing read-gate denial branch as-is; it no longer needs its own symlink copy.
3. Add a regression test in `src/session/executor/tests/dispatch.rs`: batch where a helper
   swaps the target for a symlink after Phase 1 but before Phase 2.5, with the file
   pre-marked read (gate allows) — the body must NOT run. Plus the read-side variant
   (`read_file` on a swapped final component).
4. Update the `ponytail:` walk-to-open residual-window comment to keep pointing at the
   openat2 upgrade path.
