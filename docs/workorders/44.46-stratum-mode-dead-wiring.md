# WO 44.46 — Stratum mode config is dead wiring: config/env/stratum_mode tool never set the session mode

## Status: Done

## Problem

Every user-facing path for choosing the Stratum compression mode fails to
reach `SESSION_MODE`, the process global the production compression path
actually reads:

1. **Config + env are resolved but only logged.** `active_mode()`
   (`src/session/stratum.rs:565-574`) resolves `tools.stratum_mode`
   (`src/shared/config/tools.rs:168`; parses per the test at
   `config/tools.rs:284-291`) and `STRATUM_MODE`, with correct precedence.
   Its ONLY caller is `StratumSessionStartHook::handle`
   (`src/session/stratum.rs:516-528`), which formats the mode into a
   `tracing::info!` line and returns. It never calls `set_session_mode`.
2. **The session-mode global starts and stays `Full`.** `SESSION_MODE`
   inits to `Mode::Full` (`src/shared/session_mode.rs:22-26`). Grep confirms
   the ONLY production mutation is the budget's Lite→Full escalation
   (`src/session/budget.rs:372-388`). No code ever applies the
   config/env-resolved mode.
3. **The `stratum_mode` tool doesn't set either.** Its description promises
   "Show the active compression mode, or set it for this invocation", but
   `StratumMode::run` (`src/session/stratum.rs:348-372`) parses `value`,
   echoes mode/description, and returns — no `set_session_mode` call. The
   "show" path also always reports the parsed/default mode (`Mode::Full`
   when `value` is absent), never `current_session_mode()`, so it cannot
   even report the escalation state truthfully.
4. **Effect:** the budget-slice compression listener — the only automatic
   production consumer — reads `current_session_mode()`
   (`src/session/stratum.rs:97-103`, registered from
   `src/session/executor/mod.rs:386,1030`) and therefore always compresses
   at `Full`. A user who sets `stratum_mode = "off"` (pass-through, e.g. for
   debugging or deterministic prompts) still gets `MinifyTransform` applied
   to sliced tool-result source code; `lite`/`ultra` tiering is equally
   ignored. This is the remaining Lite-vs-Off gap after 43.36 fixed the
   crate-level no-op.

## Root cause

WO 28.2 moved the global to `shared/session_mode.rs` and documented that the
session-start hook's resolved mode should drive it ("auto-escalation must
outlive a single `StratumSessionStartHook` call", `stratum.rs:80-84`) — but
the write side (`set_session_mode(active_mode(...))`) was never added; only
the budget escalation writes, so the config layer resolves a mode that
nothing consumes.

## Approach

1. In `StratumSessionStartHook::handle`, after resolving `mode`, call
   `crate::shared::session_mode::set_session_mode(mode)` (keep the log line).
2. In `StratumMode::run`: when `value` parses, call `set_session_mode(m)`;
   when absent, report `current_session_mode()` instead of hardcoded
   `Mode::Full`.
3. Tests: (a) hook with config `stratum_mode = "off"` → `current_session_mode()
   == Mode::Off` and a slice through `default_budget_sliced_listener` returns
   the input unchanged; (b) `stratum_mode` tool with `value=ultra` then read
   back reports ultra; (c) escalation still flips Lite→Full under Approaching
   budget (existing test at `budget.rs:1724-1749` must stay green).

## Files

- `src/session/stratum.rs`
- (test-only touches) `src/session/budget.rs` existing escalation test

## Gate

`scripts/test-fast.sh`, `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check`. New tests green; `set_session_mode` tests use the
existing `#[serial]` + `SessionModeGuard` pattern (`session_mode.rs:43-71`).
## Done

All four user-facing paths now reach `SESSION_MODE`, the process-global
the production compression path reads:

1. **Session-start hook writes the resolved mode.**
   `StratumSessionStartHook::handle` (`src/session/stratum.rs:516-528`)
   now calls `set_session_mode(mode)` immediately after
   `active_mode(Some(&self.config))` resolves the config/env precedence,
   before the `tracing::info!` line. The config value
   (`tools.stratum_mode`) and `STRATUM_MODE` env now reach
   `SESSION_MODE` before the first budget-slice decision. The budget's
   Lite→Full auto-escalation (`budget.rs:379-388`) still mutates this
   global after the hook writes it, so escalation semantics are
   preserved.

2. **`stratum_mode` tool sets and reports the live mode.**
   `StratumMode::run` (`src/session/stratum.rs:348-372`) now calls
   `set_session_mode(m)` when `value` parses, and reports
   `current_session_mode()` (not a hardcoded `Mode::Full`) when `value`
   is absent. The tool's "set it for this invocation" contract is now
   fulfilled, and the show path reflects the budget's auto-escalation
   state.

3. **Pipeline selection already honored `Mode::Off` (WO 43.36 gate).**
   `CompressionPipeline::run` (`crates/kf-compress-core/src/pipeline.rs:162-164`)
   returns the input unchanged when `!mode.runs_transforms()` — i.e.
   `Mode::Off` is pass-through. With the wiring fixed in (1) and (2),
   `default_budget_sliced_listener` (`stratum.rs:97-103`) reads
   `current_session_mode()` and forwards it to `compress_with_store`,
   so `off`/`lite`/`ultra` now select the right pipeline. No crate-level
   change was needed here — 43.36 fixed the gate; this WO connected
   config → runtime → that gate.

4. **Tests added** (`src/session/stratum.rs` test module, all `#[serial]`
   with `SessionModeGuard`):
   - `session_start_hook_propagates_config_off_to_session_mode` —
     config `stratum_mode = "off"` → `current_session_mode() == Mode::Off`
     after the hook runs.
   - `session_start_hook_propagates_config_lite_to_session_mode` —
     same for `lite`.
   - `stratum_mode_tool_sets_and_reports_live_session_mode` —
     `value=ultra` sets `SESSION_MODE=Ultra`; a follow-up no-value call
     reports `ultra`, not `Full`.
   - `stratum_mode_tool_sets_off_disables_compression` —
     `value=off` then `default_budget_sliced_listener` returns the
     sliced display unchanged.
   - The pre-existing `test_session_start_hook_returns_ok` was marked
     `#[serial]` + `SessionModeGuard` (it now mutates `SESSION_MODE`)
     and gained an assertion that the default config sets `Mode::Full`.

   Existing escalation tests in `src/session/budget.rs`
   (`test_apply_budget_slice_auto_escalates_lite_to_full_on_approaching`,
   `test_pre_compact_hook_runs_stratum_compression`,
   `test_apply_budget_slice_dispatches_to_sliced_listener`) stay green —
   verified by running `cargo test --lib session::budget::` (42 passed,
   0 failed).
