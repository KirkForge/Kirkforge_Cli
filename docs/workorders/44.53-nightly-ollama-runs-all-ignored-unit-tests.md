# WO 44.53 — Nightly ollama job runs every kf-code #[ignore] test and is red-by-construction

## Status: Done

## Problem

`.github/workflows/ci-nightly.yml:112-115` runs:

```
cargo nextest run --profile nightly --run-ignored all --no-fail-fast --locked -p kf-code
```

with the comment "-p kf-code scopes to the integration tests". That comment is
wrong three ways, verifiable from this checkout:

1. `-p` is **package** selection, not test-target selection. The nightly
   profile has no `default-filter` (`.config/nextest.toml:55-60`), so `all()`
   applies: every test target in kf-code runs — and kf-code is a bin-only
   crate (`Cargo.toml:48`, no `[lib]`), so all `src/**` unit tests are bin
   tests selected by `-p kf-code`.
2. With `--run-ignored all`, that includes ignored tests whose own reasons say
   the nightly runner cannot satisfy them. `src/tui/clipboard.rs:47-55`:
   `#[ignore = "requires a display server (skipped on headless CI)"]`, and the
   body **panics** on `Err` ("clipboard unavailable in this environment (test
   was run headless?)"). ubuntu-latest is headless → deterministic FAIL since
   WO 40.3 added this invocation (`e624d580`). The job cannot have been green.
3. The comment's own justification — "(real-network JWKS smoke etc.)" — points
   at `crates/kf-rbac/tests/jwt.rs:402`, which lives in the **kf-rbac**
   package and is therefore NOT selected by `-p kf-code` at all. The stated
   purpose isn't achieved either.

Secondary cost: the job also runs every slow real-subprocess unit ignore —
`src/session/verifier/build.rs:389`, `lint.rs:360`, `test.rs:394` each spawn
real cargo; `src/session/bash_jobs.rs:1037` spawns 64 sleep-30 processes —
inside a 20-minute job whose point is Ollama integration coverage. Noise +
timeout risk drown the signal the job exists for.

Nightly doesn't gate merges, so a permanently red job is a dead gate: the
intended signal (integration-test regressions, ignored Ollama tests) is buried
in guaranteed failures nobody reads.

## Root cause

The invocation conflates package selection with test-target scoping, and no
target filter exists in the nightly profile to correct it. The wrong comment
survived review because the job is informational-only and nobody looked at a
red nightly.

## Approach

1. Scope the run to the integration binary the comment names, mirroring
   `scripts/run-integration-tests.sh:30`:
   `cargo nextest run --profile nightly --run-ignored all --no-fail-fast --locked -p kf-code --test integration_test`
2. Fix the comment at ci-nightly.yml:112-114 to describe the actual scope.
3. Leave clipboard-class unit ignores alone (staying ignored-only is correct);
   they simply must not be swept in by a package-wide `--run-ignored all`.
4. Optional, only if cheap: if the JWKS ignore is genuinely wanted nightly,
   note that it needs a separate `-p kf-rbac` run — otherwise say so in the
   comment and drop the reference.
