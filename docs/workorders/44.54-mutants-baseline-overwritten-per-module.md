# WO 44.54 — Nightly mutants job overwrites its baseline; only the last module survives

## Status: Done

## Problem

The nightly `mutants` job runs four sequential `cargo mutants` invocations,
one per module (`.github/workflows/ci-nightly.yml:200-214`):

```
cargo mutants --file crates/kf-routing/src/path_safety.rs -j 2
cargo mutants --file src/session/bash_runner/mod.rs -j 2
cargo mutants --file src/shared/audit.rs -j 2
cargo mutants --file src/session/executor/sandbox.rs -j 2
```

None passes an output path, so every run writes the **default**
`mutants.out.json` / `mutants.out.txt` at the repo root, overwriting the
previous module's results. The artifact step (`:216-223`) uploads those two
single files, and the "Record baseline survival score" step (`:225-241`) cats
the same single `mutants.out.json` into the job summary.

Net effect: the recorded baseline is **executor/sandbox only** — 3 of the 4
modules (path_safety, bash_runner secret-scrub, audit chain) are silently
discarded. WO 43.14's deliverable was "Survival baseline for path safety,
secret scrubbing, audit chain, and sandbox exists as a nightly artifact"
(`docs/workorders/43.14-mutation-testing.md:51`) — the shipped job produces
it for one module. The 40-minute job burns full mutation runs whose results
are then thrown away, and the summary misrepresents which baseline it shows.

`scripts/run-mutants.sh:24-27` has the identical overwrite locally (loop over
the same four files with no output separation).

## Root cause

cargo-mutants writes `mutants.out.*` fresh per invocation in the CWD by
default; four sequential invocations in one workspace share and overwrite
that file, and both the artifact path list and the summary read only the one
file.

## Approach

1. Give each run a distinct output prefix (`cargo mutants -o <dir>` per
   module, e.g. `mutants-out/path_safety/`), **or** collapse to a single
   invocation with repeated `--file` filters if the flag is repeatable on the
   installed cargo-mutants version (verify with `cargo mutants --help` first).
2. Update the artifact `path:` (`:221-223`) and the summary step (`:225-241`)
   to loop over all four outputs, labeled per module.
3. Mirror the same output separation in `scripts/run-mutants.sh`.

## Done

Each of the 4 `cargo mutants` runs now writes to its own `-o <dir>` output
directory so runs no longer overwrite each other. cargo-mutants creates
`<dir>/mutants.out/` (containing `outcomes.json`, `missed.txt`, `caught.txt`,
…) — confirmed against cargo-mutants main (`src/output.rs:22`,
`src/main.rs:472` `--output`/`-o` flag).

### Files changed
- `.github/workflows/ci-nightly.yml` (`mutants` job):
  - 4 run steps now pass `-o mutants-out/<slug>` (path_safety, bash_runner,
    audit, sandbox).
  - Upload-artifact step now uploads the whole `mutants-out/` tree (covers
    all 4 modules) instead of the never-emitted flat `mutants.out.json` /
    `mutants.out.txt`.
  - Summary step now loops over the 4 `outcomes.json` files, labeled per
    module, instead of cating a single overwritten file.
- `scripts/run-mutants.sh`: mirrors the same per-module `-o` separation
  locally; slugs derived from the file basename (`OUT_BASE` env override).

### Side bug fixed in same commit
The pre-existing workflow referenced `mutants.out.json` / `mutants.out.txt`
(flat files at repo root) — files cargo-mutants never emits. The artifact
upload silently uploaded nothing and the summary always fell through to the
"not produced" branch. Fixed by pointing both at the real
`<dir>/mutants.out/outcomes.json` paths.
