# WO 44.55 — e2e test target is invisible to the PR gate and locally downgraded to a warning

## Status: Planned

## Problem

The e2e suite is a `[[test]]` target gated behind `required-features =
["e2e-tests"]` (`Cargo.toml:265-268`). Two gates claim to cover it but don't:

1. **PR clippy.** `.github/workflows/ci-pr.yml:124-126` comments: "--features
   e2e-tests keeps the gated e2e crate under the lint gate so it cannot
   silently rot." The actual command (`:149`) is
   `cargo clippy --lib --bins --features e2e-tests --locked` — `--lib --bins`
   performs **target selection** and never compiles `[[test]]` targets, with
   or without the feature. `tests/e2e/**` gets zero compile/lint coverage on
   PRs. The PR fast-tests step (`:186`, `--lib`) likewise never builds it, and
   `changed-packages.sh:128` maps `tests/*` to kf-code, so a PR that changes
   only `tests/e2e/` runs only kf-code lib tests — never the changed code.
2. **Local full gate.** `scripts/ci-local.sh:116` probes
   `cargo test --test e2e --features e2e-tests --no-run --locked
   >/dev/null 2>&1` — build output discarded — and on failure prints
   "WARNING: e2e crate did not build locally; skipping e2e suite"
   (`:119-121`) and continues. `ci-local.sh full` exits green with a broken
   e2e compile, while its header claims it mirrors ci-merge.

Coverage that does exist is post-merge only: ci-merge clippy
`--all-targets --features e2e-tests` (`.github/workflows/ci-merge.yml:108`)
and the merge `e2e` job (`:257`). Bite: a PR that breaks `tests/e2e/` compile
is fully green in PR CI, lands, and turns main/dev red (the exact
fix-forward-on-main pattern AGENTS.md §4 exists to prevent).

## Root cause

Cargo target-selection flags (`--lib --bins`) exclude test targets
independently of feature flags; both the PR comment and the lenient local
probe assume the feature flag alone reaches the e2e target. The local probe
additionally treats build failure as environment noise rather than breakage.

## Approach

1. `ci-pr.yml` clippy step: extend the target set with the one test target —
   `cargo clippy --lib --bins --test e2e --features e2e-tests --locked -- -D warnings`.
   (Cheap: one extra target, still skips the other ~38 test binaries.)
2. `scripts/ci-local.sh:116-121`: on probe failure, re-run the build with
   output visible and FAIL the step instead of warning-and-skipping (or
   capture to a log file and cat it on failure). Keep the skip only for
   "nextest absent", which is a tooling gap, not a code break.
3. Fix the stale comment at ci-pr.yml:124-126 to describe the new reality.

## Files

- `.github/workflows/ci-pr.yml`
- `scripts/ci-local.sh`

## Gate

- `bash -n scripts/ci-local.sh`.
- Verification on a scratch branch: introduce a deliberate syntax error in
  `tests/e2e/main.rs` → PR clippy command from step 1 must fail; revert.
- Happy path: `cargo clippy --lib --bins --test e2e --features e2e-tests --locked`
  passes on current HEAD.
