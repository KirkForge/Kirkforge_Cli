# Workorder 45.1 — Cross-cutting AgentRun identity contract

## Status: Done

## Problem

An external reviewer claimed: *"KirkForge lacks a unified durable execution
identity. Task/Session/Job/Workflow/Delegation/Executor turn partially overlap
but no canonical AgentRun/Turn/Item identity like Codex's thread/turn/item
lifecycle exists. Everything should reference one unit of execution."*

**Verdict: CONFIRMED** (with the caveat that the gap is already *partially*
tracked — WO 41.5 Phase 3 names the object, WO 43.10 names the missing
contract, TECHNICAL.md:1401-1406 names it as "the convergence point … deferred".
What is NOT tracked is the cross-cutting **ID-threading contract** that those
three references all assume but none specify.)

### Evidence — the identity islands (file:line in this checkout)

Six execution-identity types coexist with **no shared parent ID** threading them:

### What the reviewer got right (CONFIRMED)

1. **Partial overlap with no canonical parent.** `parent_task_id` threads
   task→task (`src/tools/task.rs:805`, `src/tools/task.rs:132`) and `owner`
   threads task→bash job (`src/session/bash_jobs.rs:59`). But neither reaches
   `session_id` (the Executor's `session_id` at `mod.rs:100` never becomes a
   parent of `task_id`), neither reaches `run_id` (the jobs system mints its
   own `run_id` at `src/jobs/schedule.rs:97` in a separate namespace), and
   neither reaches `TurnRecord` (replay has no id field at all — `replay.rs:45`
   carries only `turn: u32`).

2. **`RunRecord` is a dead library type.** `RunRecord` (`types.rs:60`) with
   its `run_id`+`task_id` pair looks like the canonical unit — but
   `write_run_record` (`store.rs:344`) is **never called from `src/`**
   (`grep -rln write_run_record src/` → empty). The production delegate path
   constructs `Orchestrator` with `memory: None`
   (`src/session/executor_adapter.rs:288`), and the `Executor`'s
   `memory_store` field (`mod.rs:113`) is `crate::session::memory::MemoryStore`
   — a **different type** (`src/session/memory/mod.rs:48`, the markdown fact
   store), not `kf_memory_store::MemoryStore`. The two `MemoryStore` types are
   unrelated; the comment at `src/shared/memory.rs:14` calls this out. So the
   one struct that *could* be the unified record is unwired.

3. **Cancellation is fragmented across 3 mechanisms.**
   - `TaskCancel { flag, token }` (`src/tools/task.rs:71`) — subagent tasks;
     cascaded via `cascade_parent_cancel` (`:32`).
   - `BashJobRegistry::cancel_by_owner(task_id)` (`src/session/bash_jobs.rs`)
     — background bash; triggered from `TaskManager::cancel` (`task.rs:384`).
   - `RunStatus::Cancelled` (`src/jobs/schedule.rs:143`) — scheduled jobs;
     independent of the task cancel path.
   A unified `AgentRun` would give all three a single cancel handle keyed by
   `run_id`.

4. **Persistence is per-subsystem with no shared key.**
   - Sessions: `<data_dir>/sessions/<id>.conv.ndjson` + `.index.ndjson`
     (`src/session/session_index.rs`).
   - Subagents: `<data_dir>/tasks/<id>.json` — `PersistedTask`
     (`src/tools/task.rs:445`), `parent_task_id` at `:460`.
   - Background bash: `bg-exits.ndjson` — `BgJobExitSummary`
     (`src/session/bash_jobs.rs:40`), `session_id` at `:47`.
   - Scheduled jobs: `jobs/<job_id>/<run_id>/run.json` — `JobRunSummary`
     (`src/jobs/schedule.rs:96`).
   - Replay: `<session_id>.trace.ndjson` — `TurnRecord` (`replay.rs:45`), no
     foreign key to any of the above.
   None of these stores can be joined on a single id.

5. **Replay/metrics are identity islands.** `TurnRecord` (`replay.rs:45`) has
   no `session_id`/`task_id`/`run_id` field — a replay trace can't be
   attributed to a subagent or a job. `TaskMetadata.token_estimate`
   (`task.rs:130`) is "currently always `None`" per its own doc. `RunRecord`
   carries the richest metrics (`types.rs:83-99`: tokens, duration_ms, turns,
   verifier_overall) but is never populated.

### What the reviewer overstated (PARTIALLY CONFIRMED, not full)

- "No canonical identity" — `parent_task_id` IS the canonical parent for the
  subagent tree (`task.rs:132`, `task.rs:805`, surfaced in `PersistedTask`
  at `:460` and `TECHNICAL.md:1306`). The reviewer missed this. The real gap
  is that the parent link stops at the task boundary: it doesn't thread up to
  `session_id` or down to `TurnRecord`/`BashJob`/`JobRunSummary`/`Workflow`.
- "Everything should reference one unit" — the *durable* record (`RunRecord`)
  already exists in `kf-memory-store` with the right shape (`run_id` +
  `task_id` + metrics + emissions). The gap is that it's unwired, not that it
  doesn't exist.

## Root cause

The identity accreted per-subsystem: each WO series (30.x jobs, 35.x task
cancel, 38.x trace replay, 41.5 subagent persist, 43.10 cross-session state)
added a durable record scoped to its own subsystem, with the parent link
threaded only as far as that subsystem needed. WO 41.5 Phase 3 named the
convergence object (`AgentRun`) but deferred it; WO 43.10 named the missing
contract ("WO 41.5 Phase 3's AgentRun has no contract to build against");
`TECHNICAL.md:1401-1406` names it "the convergence point … deferred". So the
gap is known and tracked at the *object* level — but the **ID-threading
contract** (which id is the parent of which, what foreign key each store
carries, how cancel/persist/replay/metrics key off the one id) was never
written. That contract is the prerequisite 41.5 Phase 3 and 43.10 both assume.

## Approach

This WO is the **contract spec**, not the implementation (41.5 Phase 3 remains
the impl tracker). It defines the threading 41.5 Phase 3 needs and 43.10 said
was missing.

1. **One canonical id: `run_id: String`** (reuse the `RunRecord.run_id`
   shape at `types.rs:61`, not the jobs-system `run_id` at `schedule.rs:97`
   which is job-run-scoped). Every execution-bearing record carries it.
2. **Parent threading (Codex thread/turn/item analogue):**
   - `Session` → `run_id` (root run; the session IS the top-level run).
   - `Task` → `run_id` (subagent run) + `parent_run_id: Option<String>`
     (replaces `TaskMetadata.parent_task_id` at `task.rs:132`; the task's
     `task-<N>` id stays as a *child* identifier within the run).
   - `TurnRecord` → `run_id` + `turn: u32` (the item; the missing foreign
     key at `replay.rs:45`).
   - `BashJob` → `run_id` (replaces the `owner: Option<String>` tag at
     `bash_jobs.rs:59` with the run id; `owner` becomes the run id).
   - `JobRunSummary` → `run_id` (the scheduled-job run; the jobs-system
     `run_id` at `schedule.rs:97` becomes the AgentRun `run_id`, not a
     separate namespace).
   - `Workflow` step execution → `run_id` (a workflow run spawns one
     `run_id` per step, with `parent_run_id` = the workflow's run).
3. **Unify the three cancel paths onto `run_id`:** `TaskCancel`,
   `cancel_by_owner`, and `RunStatus::Cancelled` all key off the run id; one
   `cancel(run_id)` reaches the subagent, its bash jobs, and its scheduled
   job. (The `TaskManager::cancel` cascade at `task.rs:384` already does
   task→bash; this extends it one level up to run→task→bash.)
4. **Wire `RunRecord` into production:** the `Orchestrator` constructed in
   `src/session/executor_adapter.rs:276` passes `memory: None` — wire it to
   a `kf_memory_store::MemoryStore` and have the delegate path call
   `write_run_record` on terminal state. This is the single change that
   turns the dead library type into the live canonical record. (41.5 Phase 3
   owns the subagent slice; this WO owns the cross-subsystem wiring.)
5. **Replay gets the foreign key:** add `run_id: String` to `TurnRecord`
   (`replay.rs:45`) so a replay trace attributes to a run. Smallest change,
   unblocks "show me the replay for subagent task-7".

### Scope discipline (what this WO does NOT do)

- Does NOT rename `TaskHandle`/`SessionId`/`BashJob` — those remain the
  *operational* types. `AgentRun` is the *durable record* they reference.
- Does NOT replace `PersistedTask` — `PersistedTask` (`task.rs:445`) becomes
  a view over the `AgentRun` row (or is subsumed; 41.5 Phase 3 decides).
- Does NOT touch the `crate::session::memory::MemoryStore` (the fact store) —
  the unified record lives in `kf_memory_store::MemoryStore` (the run store).
  The name collision is pre-existing and documented (`shared/memory.rs:14`).
- Does NOT unify the two verifier-bus traits (AGENTS.md §7 forbids; that's a
  separate concern).

## Done

Shipped: the contract definition + minimal threading. Every execution unit
now carries a `run_id` that traces back to its parent session.

### What landed

1. **Canonical `RunId` newtype** (`src/shared/mod.rs`): `RunId(Arc<str>)`
   with `Display`, `From<String>`/`From<&str>`, and `Serialize`/`Deserialize`
   (plain-string on the wire). Arc-backed so cloning through `ToolContext`
   / `TaskRequest` / `BashJob` adds no copy cost over the existing
   `session_id: String`.

2. **`TurnRecord.run_id: String`** (`src/session/replay.rs:45`): the missing
   foreign key. `serde(default)` so pre-WO 45.1 trace lines deserialize with
   `run_id: ""`. Set from `self.session_id` in `executor/turn.rs:270`.
   Tests: `turn_record_run_id_round_trips_through_ndjson`,
   `turn_record_legacy_line_without_run_id_loads_with_empty_run_id`.

3. **`BashJob.run_id: String`** (`src/session/bash_jobs.rs:53`): stamped
   by `BashJobRegistry::set_run_id` (new method), called once at session
   start from `line_mode.rs:151` and `tui/mod.rs:810`. `owner` (task id)
   is unchanged and stays independent — `run_id` is the session, `owner`
   is the task. Tests: `set_run_id_threads_into_spawned_job`,
   `run_id_serializes_as_plain_string`.

4. **`JobRunSummary.parent_run_id: Option<String>`** (`src/jobs/schedule.rs:97`):
   `serde(default, skip_serializing_if = "Option::is_none")` so legacy
   run summaries deserialize with `None` and `None` is omitted on the wire.
   Test: `job_run_summary_parent_run_id_defaults_none_and_round_trips`.
   The 3 `runner.rs` construction sites and the `store.rs` test pass `None`
   for now (daemon-scheduled jobs have no owning session); 41.5 Phase 3
   wires `Some(session_id)` when a session triggers a run.

5. **`StepOutput.run_id: Option<String>`** and
   **`WorkflowSummary.run_id: Option<String>`** (`crates/kf-workflow/src/lib.rs`):
   `None` for workflows run outside a session (bench, tests, scheduled
   jobs). The 16 `StepOutput` literals + 6 `WorkflowSummary` literals all
   pass `None` for now; 41.5 Phase 3 sets `Some(session_id)` when a session
   runs a workflow.

6. **`TaskMetadata.parent_run_id: Option<String>`** and
   **`PersistedTask.parent_run_id: Option<String>`** (`src/tools/task.rs`):
   threaded from `ctx.run_id` at the background-spawn site (`task.rs:807`).
   `serde(default)` on `PersistedTask` so legacy `tasks/<id>.json` files
   deserialize with `None`. Tests: `background_task_inherits_parent_run_id_from_context`,
   `persisted_task_carries_parent_run_id_from_metadata`.

7. **`ToolContext.run_id: Option<String>`** (`src/tools/mod.rs:111`):
   threaded from the executor's `session_id` in `dispatch.rs:715`
   (the production path) and defaults to `None` in tests/bench.

8. **`Executor::run_id()` accessor** (`src/session/executor/mod.rs:464`):
   returns `Option<RunId>` — `None` when `session_id` is empty.

### Threading contract (the spec this WO defines)

- **Session** → `run_id` = `session_id` (the root `RunId`).
- **Task** → `parent_run_id` = spawning session's `run_id`; the task's
  own id stays `task-<N>` (unchanged).
- **TurnRecord** → `run_id` = the session that recorded the turn.
- **BashJob** → `run_id` = the session (set via `registry.set_run_id`);
  `owner` = task id (unchanged, independent).
- **JobRunSummary** → `run_id` = job-run id (unchanged); `parent_run_id`
  = scheduling session's `run_id` (new, `Option`).
- **Workflow** → `StepOutput.run_id` / `WorkflowSummary.run_id` =
  session's `run_id` (new, `Option`).

### Scope discipline (what this WO does NOT do — deferred)

- Does NOT wire `RunRecord` into production (`executor_adapter.rs:288`
  `memory: None` → wired store). That's 41.5 Phase 3's territory; this
  WO defines the contract 41.5 Phase 3 builds against, not the durable
  record wiring. Tracked in WO 41.5 Phase 3.
- Does NOT unify the three cancel paths onto `run_id` (`TaskCancel`,
  `cancel_by_owner`, `RunStatus::Cancelled`). This WO threads the id;
  the cancel unification is a follow-up (41.5 Phase 3 or a 45.x).
- Does NOT rename `TaskHandle`/`SessionId`/`BashJob` — those remain the
  operational types. `RunId` is the durable-record key they reference.
- Does NOT replace `PersistedTask` — `PersistedTask` becomes a view over
  the `AgentRun` row (41.5 Phase 3 decides).
- Does NOT touch `crate::session::memory::MemoryStore` (the fact store)
  — the unified record lives in `kf_memory_store::MemoryStore` (the run
  store). The name collision is pre-existing and documented.
