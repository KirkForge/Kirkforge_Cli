# WO 45.17 — Split `crates/kf-workflow/src/lib.rs` (2707 lines / 105477 bytes)

## Status: Planned

## Problem

`crates/kf-workflow/src/lib.rs` is **2707 lines / 105477 bytes** (verified via
`wc -l` / `wc -c`). It is a single-file crate that bundles schema types,
reference resolution, the workflow executor, and file discovery:

1. **Schema types** — `StepKind`, `Step`, `Budget`, `Workflow` (+ impl),
   `StepOutput`, `StepRequest`, `BatchErrors` (lines 41–456, ~420 lines).
2. **Reference + condition evaluation** — `resolve_step_refs`, `extract_field`,
   `evaluate_condition` + `CONDITION_TIMEOUT_SECS` (lines 465–605, ~140 lines).
3. **`WorkflowExecutor`** — struct + impl, the largest impl block
   (lines 607–1272, **~665 lines**). This is the core execution loop with
   dependency resolution, batch dispatch, fan-out/fan-in, on-error routing,
   budget-exceeded handling.
4. **`WorkflowSummary` + discovery** — summary struct + `find_workflow_file`
   + `user_workflow_dir` (lines 1274–1323, ~50 lines).
5. **Inline tests** (lines 1326–2707, ~1380 lines).

No submodules exist — the crate is one file.

## Root cause

The workflow engine grew from a simple agent-step DAG (WO-2 era) to support
bash/tool steps, fan-out/fan-in, conditions, on-error routing, budget limits,
and critique — all added to `WorkflowExecutor::run` and its helpers in one
file. The executor impl alone (665 lines) is larger than many complete
modules.

## Approach

Opportunistic extraction (no behavior change, pure code movement into
submodules within the same crate):

1. **`executor.rs`** (new, ~680 lines) — move `WorkflowExecutor` struct +
   impl. Re-export via `pub use executor::WorkflowExecutor;` in `lib.rs`.
2. **`refs.rs`** (new, ~150 lines) — move `resolve_step_refs`, `extract_field`,
   `evaluate_condition`, `CONDITION_TIMEOUT_SECS`. These are pure functions
   over `HashMap<String, StepOutput>` with no executor state dependency.
3. **`discovery.rs`** (new, ~40 lines) — move `find_workflow_file` and
   `user_workflow_dir`.
4. **`lib.rs`** keeps: crate docs, schema types (`StepKind`, `Step`, `Budget`,
   `Workflow`, `StepOutput`, `StepRequest`, `BatchErrors`, `StepRunner` trait),
   `WorkflowSummary`, module declarations + re-exports, inline tests.
