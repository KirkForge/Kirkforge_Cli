# WO 45.19 — Split `src/session/prompt/mod.rs` (2693 lines / 102144 bytes)

## Status: Planned

## Problem

`src/session/prompt/mod.rs` is **2693 lines / 102144 bytes** (verified via
`wc -l` / `wc -c`). It already has three submodules (`cache_stem.rs`,
`compaction.rs`, `microcompaction.rs`, `summarizer.rs`), but `mod.rs` still
holds:

1. **Token-counting helpers** — `count_tokens`, `estimate_message_tokens`
   (lines 17–45, ~30 lines).
2. **Mini template renderer** — `render_template`, `render_range`,
   `push_value`, `skip_tag_line`, `standalone_line`, `rest_starts_with_line_end`,
   `skip_ws_eol`, `is_truthy` (lines 53–265, **~210 lines**). This is a
   self-contained handlebars-subset renderer with its own `ponytail:` ceiling
   annotation and construct-freeze test.
3. **`SystemStemKey`** — hashable key for memoised system prompt stem
   (lines 299–338, ~40 lines).
4. **`PromptBuilder` impl** — `new`, `build`, `build_stable`, `build_dynamic_suffix`,
   `load_memory_block`, `estimate_stem_tokens`, `build_stem`,
   `cache_hit_probability`, `build_with_top_files`, `build_messages`,
   `build_messages_with_compaction`, `assemble_messages`,
   `truncate_tool_results`, `dedup_adjacent_tool_results`,
   `estimated_tokens`, `minify_old_messages`, `stub_old_tool_results`,
   `truncate_to_budget`, `attach_pending_image` (lines 339–1116,
   **~777 lines** — the core of the module).
5. **`synthetic_extension_for`** helper (lines 1122–1156).
6. **Inline tests** (lines 1158–2693, ~1535 lines).

## Root cause

The template renderer was inlined to avoid a handlebars dependency (per the
`ponytail:` comment at line 64 — re-added only if the template needs
`{{else}}`, helpers, or partials). It is a complete, self-contained subsystem
that never got its own module. `PromptBuilder` itself is the module's core
and should stay, but the renderer is cleanly separable.

## Approach

Opportunistic extraction (no behavior change, pure code movement):

1. **`template.rs`** (new, ~220 lines) — move the entire mini template
   renderer: `render_template`, `render_range`, `push_value`, `skip_tag_line`,
   `standalone_line`, `rest_starts_with_line_end`, `skip_ws_eol`, `is_truthy`.
   These are pure functions over `&str` + `serde_json::Value` with no
   dependency on `PromptBuilder` state. Move the
   `test_render_matches_handlebars_reference` + `test_template_construct_freeze`
   tests into `template.rs`'s own `#[cfg(test)]` module.
2. **`mod.rs`** keeps: token helpers, `SystemStemKey`, `PromptBuilder` + all
   build methods, `synthetic_extension_for`, submodule declarations, inline
   tests for `PromptBuilder`.

### Split map

| Section | Lines (current) | Destination |
|---|---|---|
| Token helpers | 17–51 | stays in `mod.rs` |
| Template renderer (all fns) | 53–265 | `template.rs` |
| `SystemStemKey` | 299–338 | stays in `mod.rs` |
| `PromptBuilder` impl | 339–1116 | stays in `mod.rs` |
| `synthetic_extension_for` | 1122–1156 | stays in `mod.rs` |
| template tests | subset of 1158–2693 | `template.rs` |

**Note:** `PromptBuilder` impl (777 lines) is large but it is the module's
core responsibility — splitting it further would create artificial seams
between tightly-coupled message-assembly methods. The template renderer is
the one clean boundary. This WO does NOT split `PromptBuilder` itself.
