# WO 45.20 — Split `src/tools/task.rs` (2639 lines / 99487 bytes)

## Status: Planned

## Problem

`src/tools/task.rs` is **2639 lines / 99487 bytes** (verified via `wc -l` /
`wc -c`). It is a single file bundling task-lifecycle types, the task manager,
durable persistence, the `task` tool, and the `task_output` tool:

1. **Globals + cancel wiring** — `NEXT_TASK_ID`, `next_unique_id`,
   `cascade_parent_cancel` (lines 1–46, ~46 lines).
2. **Task-lifecycle types** — `TaskRequest`, `TaskCancel`, `TaskStatus` (+ impl),
   `TaskMetadata` (+ impl), `TaskListEntry`, `format_task_entry`,
   `format_duration_ms`, `TaskHandle` (+ impl) (lines 48–270, ~220 lines).
3. **`TaskSpawner` trait** (lines 270–324, ~55 lines).
4. **`TaskManager`** — struct + impl + `task_id_rank` + Default
   (lines 324–432, ~110 lines).
5. **Durable subagent summaries (WO 41.5)** — `PersistedTask` struct + impl +
   `persist_to_disk` + `load_persisted_tasks` (lines 434–570, **~140 lines**).
   This is a self-contained persistence layer (JSON read/write to disk).
6. **`TaskConcurrencyMode` enum + Display + FromStr** (lines 570–597, ~30 lines).
7. **`Task` tool** — struct + impl + `Tool` impl (lines 599–920, **~320 lines**).
   This is the built-in `task` tool that spawns subagents.
8. **`TaskOutput` tool** — struct + impl + `Tool` impl (lines 921–990, ~70 lines).
9. **Inline tests** (lines 990–2639, ~1650 lines).

## Root cause

The task subsystem accreted from a simple `task` tool (WO-2) to include
cooperative cancellation (WO 35.3), process-global IDs (WO 37.1/38.4), durable
summaries (WO 41.5), and concurrency modes — all in one file. The `Task` tool
impl (320 lines) and the persistence layer (140 lines) are the two clearest
separable chunks.

## Approach

Opportunistic extraction (no behavior change, pure code movement):

1. **`persist.rs`** (new, ~150 lines) — move `PersistedTask` struct + impl +
   `persist_to_disk` (method on `TaskHandle` — will need to be a free fn or
   re-import `TaskHandle`) + `load_persisted_tasks`. This is a self-contained
   JSON disk I/O layer with no dependency on `TaskManager` or the `Task` tool.
2. **`task_tool.rs`** (new, ~330 lines) — move `Task` struct + impl + `Tool`
   impl. Re-export `pub use task_tool::Task;` from `task.rs`. The `Task` tool
   depends on `TaskSpawner`, `TaskManager`, `TaskRequest` — all stay in
   `task.rs` and are `pub(crate)`/`pub`.
3. **`task.rs`** keeps: globals, lifecycle types, `TaskSpawner` trait,
   `TaskManager`, `TaskConcurrencyMode`, `TaskOutput` tool, helpers,
   `mod persist; mod task_tool;` declarations + re-exports, inline tests for
   `TaskManager`/`TaskHandle`/lifecycle types.
