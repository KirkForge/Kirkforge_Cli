# WO 45.52 — workorders/README.md WO 34 prose contradicts its own table

## Status: Done

## Problem

`docs/workorders/README.md` has a self-contradiction in the Series 34
section: the summary prose says all 11 implementation WOs are pending,
but the table immediately above marks 10 of them Done.

- `docs/workorders/README.md:711-714` (the prose under the Series 34
  table) says:
  `**12 sub-workorders.** All 11 implementation workorders (34.1-34.11)
  are pending; only the planning commit (\`d94c575\`) has landed. WO 34.11
  (this doc audit) is in progress. The series is the TUI IA reset — no
  Rust architecture changes, no new ADRs expected.`
- The table directly above (lines 697-709) marks:
  - 34.0 — In Progress
  - 34.1 — Partially done (WO 34.1)
  - 34.2 through 34.10 — Done
  - 34.11 — Done
- The WO file headers agree with the table, not the prose:
  - `docs/workorders/34.11-doc-audit.md` → `## Status: Done`
  - `docs/workorders/34.2-help-overlay.md` → `## Status: Done`
  - `docs/workorders/34.3-simplify-status-bar.md` → `## Status: Done`
  - (34.4-34.10 all → `## Status: Done`, verified via `grep '^## Status'
    docs/workorders/34.*.md`)
- So the prose ("All 11... are pending; only the planning commit has
  landed") is stale — it describes the state at the planning commit
  (`d94c575`) before any of the implementation WOs shipped.

## Root cause

The Series 34 summary paragraph was written at series-creation time
(after the planning commit `d94c575`) and never updated as the
implementation WOs landed. The table rows were updated per-WO on close
(correctly), but the trailing prose block was not. This is a
doc-sync miss — AGENTS.md §9 ("Doc-sync discipline") requires the WO
README index to track reality; the table does, the prose does not.

Note: the WO status drift test (`crates/kf-budget-core/tests/adr_xref_drift.rs`,
`wo_status_headers_match_readme_index`) passes because it checks WO
**file headers** against the README **table rows** — it does not parse
the free-text summary paragraphs. So this prose staleness is not
caught by the automated gate; it is a manual-audit-only finding.

## Approach

Rewrite the `docs/workorders/README.md:711-714` summary paragraph to
match the table. Replace "All 11 implementation workorders (34.1-34.11)
are pending; only the planning commit (`d94c575`) has landed. WO 34.11
(this doc audit) is in progress." with a sentence reflecting that 34.2
through 34.11 shipped (Done), 34.1 is partially done (tab bar removed +
command palette shipped; the deferred step is true overlay-on-top-of-chat
rendering — see the `ponytail:` comment in `render_app`), and 34.0
remains In Progress as the series overview. Keep the "no Rust
architecture changes, no new ADRs expected" sentence (still true).

Do NOT edit the table rows — they are correct. Do NOT edit the WO 34
file headers — they are correct and the drift test enforces them.
