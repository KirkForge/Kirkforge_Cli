# WO 45.53 — too_many_arguments: mechanical single-caller params-struct refactors

## Status: Done

## Problem

External review found 22 `#[allow(clippy::too_many_arguments)]` suppressions
across the workspace (actual count: 23 — see verification in WO 45.54).
Most are REASONED tradeoffs with documented `// reason:` comments. But
three sites are SMELL cases: no reason comment, and crucially, each has
**exactly one call site**, making a params-struct refactor mechanically
safe (def + 1 caller = 2 files touched, no behavior change).

The three mechanical candidates:

1. **`spawn_executor`** — `src/tui/mod.rs:765` — 21 parameters, 1 caller
   (`src/tui/mod.rs:661`). This is the widest function in the codebase.
   The params mix session resources (adapter, tools, config, conversation,
   plugin_registry) with mpsc channel ends (11 channel rx/tx pairs). A
   params-struct would cut the signature from 21 args to 1, and the single
   call site is 95 lines away in the same file.

2. **`teardown`** — `src/tui/mod.rs:416` — 13 parameters, 1 caller
   (`src/tui/mod.rs:745`). All 13 are mpsc sender ends + `handle` +
   `terminal`. The function body just drops the senders and awaits the
   join handle with a timeout. A `TeardownChannels` struct would group
   the 11 senders cleanly.

3. **`run_workflow`** — `src/tools/workflow.rs:141` — 9 parameters, 1
   caller (`src/tools/workflow.rs:120`). The params are a mix of template
   + vars + spawner + toolset + cancel_token + flags + deny_list +
   path_guard. A `WorkflowRunParams` struct would reduce the signature;
   the single caller already constructs most args inline.

## Root cause

These three functions grew their parameter lists incrementally as
features were added (mpsc channels for undo, plan, config, plugin_reload,
persona, bg commands, conn_probe — each added a new param). No single
addition crossed the clippy threshold, but the accumulation did. The
suppressions were added instead of refactoring because each addition
was small and the function was "already wide." The lack of a `// reason:`
comment (unlike the 10 REASONED sites) confirms these were silenced
without justification.

## Approach

Refactor each into a params-struct. Each has exactly 1 caller, so the
diff is mechanical (struct definition + 2-site update). No behavior
change.


The single caller at `src/tui/mod.rs:661` constructs the struct. The
`#[allow(clippy::too_many_arguments)]` is removed from `spawn_executor`.

Note: `Executor::run` (`src/session/executor/loop_.rs:149`) has a
**REASONED** suppression with `// reason: each arg is a distinct mpsc
channel end; grouping would obscure the wiring.` — that function is
the AGENTS.md §7 refactor-on-touch list and is NOT touched here. The
distinction: `Executor::run` is a public API on the executor itself
(the caller owns the channels separately); `spawn_executor` is a
private TUI helper that bundles everything in one call.

### Commit-per-function deviation
The WO said "commit per function" (3 commits). `spawn_executor` and
`teardown` share a single call-site region in `run_tui` (both call sites
are in the same function body, ~80 lines apart), so refactoring one
without updating the other's call site would leave an intermediate
state that does not compile. They are committed together (2 commits
total instead of 3) to keep each committed state compiling, per
AGENTS.md "each edit compiles, each task is a gated commit."
