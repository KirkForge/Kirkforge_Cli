## Root cause

The 13 REASONED/REASONED* sites are deliberate tradeoffs: entry points
that own independent session resources (`run_tui`, `run_line_mode`),
mpsc channel wiring that resists grouping (`Executor::run`,
`run_event_loop`), running-total accumulators (`emit_turn_events`),
independent optional payloads (`emit_tool_event_and_correct`), and a
TOCTOU-avoidance pre-resolved path (`record_tool_result` — the doc
comment at `turn.rs:596-600` explains that re-resolving the path in
Phase 3 would open a TOCTOU window where a parallel tool flips guard
state between Phase 1 and Phase 3).

The 10 SMELL sites fell into two sub-groups:
1. **Single-caller TUI helpers** (`spawn_executor`, `teardown`,
   `run_workflow`) — grew by mpsc-channel accretion, never refactored
   because each addition was small. Mechanical fix → WO 45.53.
2. **High-risk hub functions** (`adapter_for_with_provider`,
   `build_anthropic_body`) — these are called from 21 and 33 sites
   respectively. A params-struct would be cleaner, but the blast radius
   is CRITICAL (49 and 34 impacted symbols). These are NOT mechanical.

## Approach

### WO 45.53 (separate WO — mechanical, low-risk)

Refactor the 3 single-caller SMELL sites into params-structs. See WO 45.53.

### This WO — deferred high-risk hubs (documentation only)

The two CRITICAL-risk SMELL sites are documented but NOT scheduled for
refactoring. They are deferred because:

1. **`adapter_for_with_provider`** (13 params, 21 callers, CRITICAL):
   Impact analysis shows 49 impacted symbols, 6 execution flows, 7
   modules. AGENTS.md §7 already names this function indirectly: "When
   adding fields to `Config`, update ALL of: ... `adapter_for_with_provider`
   call sites." A params-struct (`AdapterConfig` or similar) would
   centralize the 13 provider-routing params, but the 21 call sites are
   spread across `src/adapters/mod.rs` (11 self-calls in tests +
   routing), `src/main/run_session.rs`, `src/session/adapter_swap.rs`
   (2 calls), `src/session/bench.rs`, `src/session/task_spawner.rs`,
   `src/tui/commands/persona.rs`, and 4 test files. This is a
   dedicated-refactor WO, not a drive-by. **Recommendation**: defer
   until the next time the function's signature changes for a feature
   reason (refactor-on-touch), then introduce the struct as part of
   that change.

2. **`build_anthropic_body`** (9 params, 33 callers, CRITICAL):
   Impact analysis shows 34 impacted symbols, all within the Anthropic
   module. The 33 call sites are almost all in `anthropic/mod.rs` (31
   self-calls in test + stream paths) plus `anthropic_bedrock.rs` and
   `anthropic_vertex.rs`. A `AnthropicBodyParams` struct would reduce
   repetition at call sites (many calls pass the same 9 args in
   sequence). But 33 call sites = a large diff with high regression
   surface. **Recommendation**: defer until the next Anthropic body-
   construction change (e.g., a new model family requiring a new param),
   then introduce the struct as part of that change.

### The `// reason:` comment policy

Going forward, any new `#[allow(clippy::too_many_arguments)]` MUST have
a `// reason:` comment explaining the tradeoff. The 10 existing REASONED
sites follow this pattern. The 3 REASONED* sites (bash_jobs, correction,
collect_batch) should have `// reason:` comments added when they are
next touched (refactor-on-touch). The 5 deferred SMELL sites that are
not mechanical (computer_use, wrapper, approval, build_with_top_files)
should get `// reason:` comments explaining why they are left as-is.
