# WO 45.59 — Nightly job for subprocess-lifecycle #[ignore]d tests

## Status: Planned

## Problem

An external audit flagged 77 `#[ignore]`d tests. The real count in the main
checkout is **28** actual `#[ignore]` attributes (the "77" includes comments
that mention `#[ignore]` and 28 duplicate copies in `.worktrees/dev-integration`).

The subprocess-lifecycle / timeout-handling area has had repeated real bugs
(PDEATHSIG gaps, unguarded spawns, watchdog timing — WO 43.23, WO 44.20,
WO 44.48). The concern: lifecycle code only gets exercised when someone runs
`--ignored` locally, not on every CI push.

Most lifecycle paths ARE covered by non-ignored sibling tests that run on
every push (see Root cause). But two timeout-specific branches have **no
non-ignored coverage**, and **no nightly CI job runs the subprocess-lifecycle
ignores**. The nightly `ollama` job (ci-nightly.yml:120) runs only
`-p kf-code --test integration_test` — the 7 Ollama ignores. The 13
subprocess-lifecycle ignores in `src/**` are not run by any CI job.

## Root cause

### What's already covered on every push (non-ignored siblings)

The following lifecycle paths run in ci-fast / ci-full on every PR and merge,
because the covering test is NOT `#[ignore]`d:

| Lifecycle path | Non-ignored test | File:line |
|---|---|---|
| PDEATHSIG (parent abort → child dies) | `child_dies_when_parent_aborts` | `src/session/process_group.rs:296` |
| pgrp kill (kill_process_group) | `kill_process_group_kills_child` | `src/session/process_group.rs:268` |
| reap_child timeout | `reap_child_times_out_on_slow_process` | `src/session/process_group.rs:248` |
| run_shell timeout → kill | `run_shell_timeout_preserves_partial_stdout` | `src/session/bash_runner/mod.rs:1046` |
| hook timeout → pgrp kill | `test_run_hook_timeout_kills_descendants` | `src/session/hooks.rs:951` |
| bash_job cancel → kill/reap | `test_cancel_by_owner_kills_owned_job` | `src/session/bash_jobs.rs:1289` |
| watchdog (watcher death → Failed) | `test_watchdog_flips_running_to_failed_on_watcher_death` | `src/session/bash_jobs.rs:1248` |
| build verifier (fake runner) | `test_build_error_via_fake_runner` + 4 siblings | `src/session/verifier/build.rs:252` |
| lint verifier (fake runner) | `test_lint_*_via_fake_runner` | `src/session/verifier/lint.rs` |
| test verifier (fake runner) | `test_test_*_via_fake_runner` | `src/session/verifier/test.rs` |
| hook fail-open (exit 1) | `test_pre_tool_hook_exit_one_allows_and_warns` | `src/session/executor/tests/approval/auto.rs:1053` |

These were verified by grep: each is a regular `#[tokio::test]` / `#[test]`
with no `#[ignore]` attribute. The PDEATHSIG driver
(`child_dies_when_parent_aborts`) is itself non-ignored and internally spawns
the ignored `pdeathsig_helper` via `--ignored` — so the PDEATHSIG path runs
on every push through a non-ignored entry point.

### What's NOT covered on any push (ignore-only, no nightly job)

Two timeout-specific branches have no non-ignored sibling:

1. **bash_jobs watcher timeout branch** — `test_timeout_reaps_child_and_preserves_partial_output`
   (`src/session/bash_jobs.rs:1114`, `#[ignore = "spawns real subprocess + 6s timeout wait"]`).
   This is the ONLY test that exercises the watcher's
   `tokio::time::sleep(timeout)` → `kill_process_group` → `Err("Timed out")`
   branch (bash_jobs.rs:341). The non-ignored `test_cancel_by_owner_kills_owned_job`
   covers the *cancel* path (different branch: `cancel()` →
   `kill_process_group_by_pid`). The non-ignored
   `test_watchdog_flips_running_to_failed_on_watcher_death` covers the
   *watcher-panic* path. Neither touches the timeout-detection branch.

2. **scheduled-job timeout** — `bash_job_timeout_is_enforced`
   (`src/jobs/runner.rs:427`, `#[ignore = "spawns real sleep 30 subprocess + 2s timeout wait"]`).
   This is the ONLY test that verifies `run_job` enforces `job.timeout`. No
   non-ignored sibling exists.

Both are inherently wall-clock-bound (6s / 2s real timeout waits) and cannot
be made deterministic without a `ProcessSpawner` trait abstracting
`tokio::process::Child` — which WO 33.14 explicitly deferred as
over-engineering (96 direct callers of `BashJobRegistry::spawn` across 18
modules, CRITICAL blast radius). The `ponytail:` ceiling comment at
`bash_jobs.rs:1054-1058` documents this deferral.

### Why not just un-ignore them?

The tests are `#[ignore]`d for genuine reasons:
- 6s and 2s real-time waits exceed the PR-feedback budget (ci-fast: 30s
  slow-timeout, but these add 8s of serial wall-clock to a `--lib --bins` run
  that targets <60s total).
- They spawn real `sleep 30` subprocesses that must be reaped.

The WO 33.14 pattern (replace with a fake runner) doesn't apply here without
the ProcessSpawner trait. The correct fix is a **nightly job** that runs these
specific ignored tests with a generous timeout — mirroring how the nightly
`ollama` job already runs the Ollama ignores.

### Nightly CI gap

`.github/workflows/ci-nightly.yml` has 5 jobs: `coverage`, `ollama`,
`e2e-exhaustive`, `audit`, `mutants`, `release-build`. None runs the
`src/**` subprocess-lifecycle ignores. The `ollama` job (line 120) is scoped
to `--test integration_test` (WO 44.53 fix), so it deliberately excludes
`src/**` unit ignores. There is no `subprocess-lifecycle` nightly job.

## Approach

Add a `subprocess-lifecycle` job to `.github/workflows/ci-nightly.yml` that
runs the specific `#[ignore]`d subprocess-lifecycle tests with
`--run-ignored all`, scoped to avoid the WO 44.53 red-by-construction trap
(don't use bare `-p kf-code` — that sweeps in `src/tui/clipboard.rs:48` which
panics headless).

Two options, pick the cheaper:

**Option A (narrow, recommended):** run only the two genuinely under-tested
tests by name, with `--run-ignored all` and an `--exact` filter:

```
cargo nextest run --profile nightly --run-ignored all --no-fail-fast --locked \
  -p kf-code --lib --bins \
  -E 'test(test_timeout_reaps_child_and_preserves_partial_output) | test(bash_job_timeout_is_enforced)'
```

This runs 2 tests, ~8s wall-clock, covers the two ignore-only branches. No
chance of sweeping in the clipboard panic or the 64-subprocess stress test.

**Option B (broader):** run all 13 subprocess-lifecycle ignores via a filter
that excludes the known-bad ones (clipboard, computer_use, e2e):

```
cargo nextest run --profile nightly --run-ignored all --no-fail-fast --locked \
  -p kf-code --lib --bins \
  -E 'test(#ignore) and not test(clipboard) and not test(browser_session) and not test(plugin_watcher)'
```

This is ~80s wall-clock (dominated by the 58s `test_job_cap_enforced_when_all_running`
stress test) and gives nightly coverage of all subprocess-lifecycle ignores.
Use the nightly profile (600s slow-timeout) so the 58s stress test doesn't SLOW-flag.

Prefer Option A unless the broader coverage is explicitly wanted — the other
11 subprocess ignores already have non-ignored siblings covering the same
kill/reap paths, so running them nightly adds little signal beyond what every
push already gets.

### Why not make the two tests deterministic instead?

The bash_jobs watcher timeout uses `tokio::time::sleep(timeout)` inside a
`tokio::spawn`'d watcher task that also does `child.wait().await` (real
syscall on a real process). `tokio::time::pause()` (mock time) won't advance
the real `wait()` future. A deterministic test would need either:
- a `ProcessSpawner` trait (deferred by WO 33.14 — CRITICAL blast radius), or
- a `Sleep` abstraction injectable into the watcher (new trait, new test
  surface, for 2 tests).

Both are over-engineering for 2 tests that take 8s combined. A nightly job is
the ponytail solution: the tests already exist and pass; they just need a CI
slot that runs them.
