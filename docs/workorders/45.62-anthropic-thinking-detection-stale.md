# WO 45.62 — Anthropic extended-thinking detection is stale; misses all current model families

## Status: Done

## Done

Replaced the stale substring check
(`lower.contains("claude-3-7-sonnet") || lower.contains("claude-4")`) with
a single shared helper `anthropic_supports_thinking(model_id)` in
`src/adapters/mod.rs`. Both call sites now use it:
- `anthropic_model_info` (src/adapters/mod.rs)
- `build_anthropic_body` (src/adapters/anthropic/mod.rs)

The helper covers current and future Claude families via a pattern:
all `claude-*` models support thinking EXCEPT Haiku (never supports
thinking) and the pre-3.7 Claude 3 family (3-opus, 3-sonnet, 3-5,
3-haiku). A `ponytail:` comment pins the ceiling (substring heuristic,
not a maintained model table) and the upgrade path (replace with an
explicit capability table when the family count grows).

Added 9 tests (3 per adapter: anthropic, anthropic_bedrock,
anthropic_vertex) for current model families:
- `claude-sonnet-5` → thinking
- `claude-opus-4-8` → thinking
- `claude-haiku-4-5` → no thinking

Backward-compatible: all existing tests for `claude-3-7-sonnet`,
`claude-4`, `claude-3-5-sonnet`, `claude-3-opus` still pass unchanged.

Deferrals:
- Warn-log for unknown Claude models: NOT added. `model_info()` is
  called every turn (72 call sites) — a warn inside the helper would
  spam the log. The broader pattern is fail-safe (defaults to
  thinking-enabled for unknown `claude-*` models except the explicit
  exclusions), which is the safer default than silent no-thinking.
  The WO said "Consider" — this is a decision, not a deferral.

## Problem

`supports_thinking` detection is hardcoded to old model-name substrings
(`src/adapters/anthropic/mod.rs:224`):

```rust
let supports_thinking = lower.contains("claude-3-7-sonnet") || lower.contains("claude-4");
```

This is checked at `mod.rs:339` — extended thinking is only sent on the
wire if `extended_thinking && supports_thinking`. The substring
`"claude-4"` does NOT appear in `claude-sonnet-5`, `claude-opus-4-8`,
`claude-haiku-4-5`, or any current-shipping model family. With default
config (`extended_thinking = true`), a user on any current model gets
silently no extended thinking sent — no error, just a request that looks
identical to a non-thinking call.

The same stale check is shared by all three Anthropic adapters via
`anthropic_model_info` (called from `anthropic_bedrock.rs:63` and
`anthropic_vertex.rs:106`), so it's a three-times-repeated bug.

## Root cause

Model-identity logic is hardcoded to specific name strings instead of
derived from a maintained capability table. Every new Anthropic model
release requires a manual substring update that nobody remembers to do.

## Approach

1. Replace the substring check with a maintained model-capability table
   (or at minimum, a broader pattern: `lower.starts_with("claude-") &&
   !lower.contains("haiku") && !lower.contains("3-")` — all Claude 4+
   models support thinking except Haiku; or an explicit allow-list of
   model prefixes that support thinking).
2. The table should be in ONE place (shared by all three adapters) —
   it already is via `anthropic_model_info`, so the fix is one function.
3. Tests: `claude-sonnet-5`, `claude-opus-4-8`, `claude-haiku-4-5` all
   get the correct `supports_thinking` value (true for sonnet/opus,
   false for haiku if that's the current API behavior — verify against
   Anthropic's docs).
4. Consider: make the detection fail-loud (warn log) for unknown Claude
   models rather than silently defaulting to no-thinking.

## Files

- `src/adapters/anthropic/mod.rs` (the `anthropic_model_info` function)
- Bedrock and Vertex inherit the fix (no separate changes needed)
