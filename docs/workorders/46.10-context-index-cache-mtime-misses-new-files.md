# WO 46.10 — context-index mtime_rebuild misses new files not in cache

## Status: Done

## Problem

**Location:** `crates/kf-context-index/src/cache.rs:131-203`

`mtime_rebuild` only checked files in `cached.file_mtimes`; NEW files
added to the repo were never detected. Latent (production uses
`incremental_rebuild`, which gets new files from `git_diff_files`).

## Root cause

The mtime-diff loop iterated only `cached.file_mtimes`, so a file
added after cache-write was invisible — it had no mtime entry to
compare against. `incremental_rebuild` doesn't have this bug because
`git diff --name-only` lists newly-added files.

## Fix

After the mtime-diff loop, walk `repo_root` with `walkdir` (reusing the
`is_ignored_dir` filter from `index_dir`, now `pub(crate)`) for
indexable files whose path is not in `cached.file_mtimes`. Add those
to `changed_paths` so the existing re-index loop picks them up.

`is_ignored_dir` was bumped from private to `pub(crate)` so the scan
reuses the same `target`/`.git`/`node_modules` skip list as
`index_dir` — no filter drift.
