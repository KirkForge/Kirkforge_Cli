## Done

Added the `[verify].type` validation block (copied verbatim from
ci-pr.yml:44-75) into the ci-merge.yml `static` job's python3 heredoc.
The merge gate now rejects a bench TOML with a missing or unknown
`[verify].type` (one of `test_passes`/`file_contains`/`command_exits_zero`)
before the bench suite fails to load. Single YAML-file change, no Rust.

Gate: `python3 -c "import yaml; yaml.safe_load(open('.github/workflows/ci-merge.yml')); print('YAML OK')"`
→ `YAML OK`. `cargo fmt --check` → exit 0. `scripts/test-fast.sh`
→ 4765 passed / 15 skipped under `--no-fail-fast` (one documented

see lessons.md. Not a WO 46.11 regression; YAML-only change cannot
affect Rust test logic). Validation logic confirmed against the real
30 bench TOMLs (all pass) + a negative test (catches `output_contains`
typo + missing type).
