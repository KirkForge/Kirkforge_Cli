# WO 46.13 — plugin_consent_ledger defaults to false — WO 45.61 fix only matters when ledger is opt-in

## Status: Done

## Problem

**Location:** `src/shared/config/tools.rs:245`

WO 45.61 fixed the bypass where the ledger was skipped when signatures are on. But plugin_consent_ledger defaults to false, so in the out-of-the-box config the content-hash gate doesn't run at all. The signed-manifest-only trust model remains the default-user exposure. Fix: default plugin_consent_ledger to true when verify_signatures is also true (the exact scenario the bug lived in), or document the TOFU opt-in model explicitly. Claude's review flagged this as a deliberate decision needing documentation.

See Problem section — identified by the post-WO-45 area audit + external review.

## Done

Option (a): defaulted `plugin_consent_ledger` to `true`, matching
`plugin_signature_validation`'s default. Both gates now run in the
out-of-the-box config (both `Default::default()` and bare toml with
omitted fields). The WO 45.61 fix (ledger layers on top of signatures)
is no longer inert in the default config — a signed manifest + swapped
command script is now rejected by the content-hash ledger by default.

The coupling is at the DEFAULT level, not runtime: both default on
independently. Runtime coupling (forcing ledger on when signatures are
on) would override explicit user opt-out, which is wrong — a user who
deliberately sets `plugin_consent_ledger = false` gets that.
