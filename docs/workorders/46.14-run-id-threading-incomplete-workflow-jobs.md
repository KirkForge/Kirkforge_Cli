# WO 46.14 — run_id/parent_run_id always None in workflow and scheduled jobs — WO 45.1 identity gap

## Status: Done

## Problem

**Location:** `crates/kf-workflow/src/executor.rs, src/jobs/runner.rs`

WO 45.1 added run_id fields to StepOutput, WorkflowSummary, and JobRunSummary, but all construction sites hardcode None in production. The identity contract is incomplete for workflows and scheduled jobs. Fix: thread the session run_id into workflow execution and job scheduling at the call sites.

## Root cause

See Problem section — identified by the post-WO-45 area audit + external review.

## Approach

Read the Problem section's fix recommendation. Implement the minimal
correct fix. Add tests where practical.

## Files

crates/kf-workflow/src/executor.rs, src/jobs/runner.rs

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check`.

## Done

Threaded the session `run_id` into all production workflow and job
construction sites:

- **`WorkflowExecutor`**: added `run_id: Option<String>` field +
  `with_run_id()` builder. A `stamp_run_id` helper overwrites
  `StepOutput.run_id` on every output and the final `WorkflowSummary.run_id`
  at both return points (budget-exceeded + normal completion). The 6
  internal `StepOutput` literals keep `run_id: None` — the stamp overwrites
  them post-construction (no code path reads `run_id` mid-execution).
- **Workflow callers** (3 production sites) add `.with_run_id(...)`:
  - `src/tools/workflow.rs` → `ctx.run_id` (via new `WorkflowRunArgs.run_id`
    field, since `ctx` isn't in scope inside `run_workflow`).
  - `src/tui/commands/workflow.rs` → `state.session.session_id` (captured
    before the `tokio::spawn` since `state` can't cross `'static`).
  - `src/main/line_mode.rs` → `session_id` param.
- **`run_job`**: added `parent_run_id: Option<String>` param, threaded
  through `run_bash_job`, `run_workflow_job`, and `record_failure`. All 3
  `JobRunSummary` literals now set `parent_run_id` from the param.
  - TUI `/jobs run-now` (`src/tui/commands/jobs.rs`) → `Some(session_id)`.
  - daemon (`src/jobs/daemon.rs`) → `None` (no owning session, per
    `JobRunSummary.parent_run_id` doc).
  - 6 test callers → `None`.
- For workflow jobs, `parent_run_id` is also threaded into the
  `WorkflowExecutor::with_run_id`, so workflow step outputs spawned by a
  scheduled job carry the triggering session's identity.

`run_workflow_job` grew to 8 params → `#[allow(clippy::too_many_arguments)]`
added (matches the repo convention; tracked in WO 45.54 audit).

Gate: `scripts/test-fast.sh` (4765 passed, 15 skipped) + `cargo clippy
--all-targets -- -D warnings` + `cargo fmt --check` + `cargo check
--workspace --all-targets` — all green. Two pre-existing concurrency flakes
(`test_always_approve_rule_round_trips_to_next_turn`,
`same_ms_double_spawn_gets_distinct_worktrees`) manifest under extreme
parallel load but pass in isolation and with `--test-threads=4`; both are
documented in state.md "Known flakes" and unrelated to this change.
