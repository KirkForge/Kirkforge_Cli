# WO 46.15 — kf-memory-store self-deadlock in write_run_and_emissions fallback (CRITICAL)

## Status: Done

## Problem

**Location:** `crates/kf-memory-store/src/store.rs:401-450`

write_run_and_emissions acquires self.lock (line 401), then calls write_emission_records (line 448) and write_run_record (line 449) — both re-acquire self.lock (lines 289, 345). std::sync::Mutex is non-reentrant → blocks forever. Triggered when FileAdapter/InMemoryAdapter is used (SQLite open failure fallback).

## Done

Extracted the lock-held bodies of `write_emission_records` and
`write_run_record` into `write_emission_records_inner` / `write_run_record_inner`
(lock-free; operate on `&self.adapter` only). The public methods acquire
`self.lock` and delegate. `write_run_and_emissions` acquires the lock once
and calls the `_inner` helpers directly on the sequential-fallback path
(lines 470-471), so `self.lock` is never re-acquired while held → no
self-deadlock. Public API signatures unchanged.

Added two regression tests in `tests/integration.rs`:
- `store_write_run_and_emissions_fallback_on_in_memory_no_deadlock`
- `store_write_run_and_emissions_fallback_on_file_adapter_no_deadlock`

Both drive `write_run_and_emissions` through the fallback path
(`write_run_and_emissions_tx` returns `Ok(false)`) that previously
self-deadlocked. If either test returns at all, the deadlock is gone.
