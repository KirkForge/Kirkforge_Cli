# WO 46.16 — Plugin hot-reload watcher dropped at call site — silently dead

## Status: Done

## Problem

**Location:** `src/tui/mod.rs:509`

`let _watcher = spawn_plugin_watcher(...)` drops the `Debouncer` immediately; the worker thread exits; `watch_rx` sees channel close; no reloads ever reach TUI. The 'watcher started' info log fires once, then nothing. Fix: bind without underscore on a field of `AppState`.

## Root cause

Identified by external model audits (DeepSeek + MiniMax). See
/home/henrik/madlab/github/desktop/ds-bugs.md and mm-bugs.md for full evidence.

The `_watcher` name was a red herring — `let _x = guard` keeps the value
alive until end of scope (only bare `let _ = guard` drops immediately).
The actual bug: the local `spawn_plugin_watcher` wrapper in
`src/tui/mod.rs` returned `()`, so the `Debouncer` had nowhere to escape
to — it was dropped at the wrapper's closing brace (line 527). The
worker thread in `loader.rs` then exited, `watch_rx.recv()` returned
`None`, and the spawned reload task exited silently. No plugin reloads
ever reached the TUI.

## Approach

Read the Problem section's fix recommendation. Implement the minimal
correct fix. Add tests where practical.

## Fix

Made the local `spawn_plugin_watcher` wrapper in `src/tui/mod.rs` return
the `Option<Debouncer<RecommendedWatcher>>` it gets from
`crate::session::plugin_tools::spawn_plugin_watcher`, and bound it at
the call site (`run_tui`, line 651) to a local `_plugin_watcher` that
lives for the lifetime of `run_tui` (which spans the entire event loop).
The leading underscore silences `unused_variable` but does NOT drop the
value — it stays alive until `run_tui` returns.

Chose the local-over-`AppState`-field approach because `AppState` is
dropped at the same place the local would be (end of `run_tui`), so the
field would be a larger diff with no lifetime benefit. The guard is owned
by `run_tui`'s stack frame, which outlives the event loop.

No new deps. No `AppState` field. No new tests (the watcher is
timing-sensitive and already covered by an integration test in
`src/session/plugin_tools/tests.rs` that writes a manifest, starts the
watcher, modifies the manifest, and asserts the reload signal fires
within 3s — that test was passing but exercising a code path that was
dead in the TUI).
