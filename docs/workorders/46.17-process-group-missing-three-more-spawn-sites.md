## Done

Two of the three reported sites were missing `setup_process_group`;
the third was already fixed by WO 43.23.

- **Site 1 — `src/session/verifier/correction.rs` `apply_command_fix`
  (lines 310-329): ALREADY FIXED, no change.** Line 312 already calls
  `crate::session::process_group::setup_process_group(&mut proc)` and
  line 329 calls `kill_process_group(&mut child)` on timeout. This was
  landed by WO 43.23 (see state.md "WO 43.23: subprocess lifecycle"). The
  spec's line citation (310-329) was stale. Disclosed here per the
  no-silent-deferral rule; not a regression — the underlying bug it
  described was already closed.
- **Site 2 — `src/session/verifier/security.rs` `trufflehog_scan`
  (lines 224-249): FIXED.** Hoisted the inline `tokio::process::Command`
  out of the `tokio::time::timeout(.., <cmd>.output())` call into a
  `let mut trufflehog_cmd`, added
  `crate::session::process_group::setup_process_group(&mut
  trufflehog_cmd)` before `.output()`. A hung trufflehog (and any Go
  detector helpers it spawns) now sits in its own process group so a
  later `killpg` reaches the grandchildren; `kill_on_drop` alone left
  them holding the stdout pipe open past the 60s timeout.
- **Site 3 — `src/tools/bash.rs` `Bash::run_docker` (lines 178-184):
  FIXED.** Hoisted the inline `tokio::process::Command::new("docker")`
  chained into `.spawn()` into a `let mut docker_cmd`, added
  `crate::session::process_group::setup_process_group(&mut docker_cmd)`
  before `.spawn()`. A timeout-driven kill now reaches
  container-spawned helper processes too; `kill_on_drop` only reaped the
  direct `docker` child, leaving in-container grandchildren holding the
  stdout/stderr pipes open past the timeout (same class as WO 46.2 /
  43.23).

Pattern mirrors `tools/workflow.rs:279-288` (`let mut cmd = ...;
setup_process_group(&mut cmd); let child = cmd.spawn()?`). Fully-qualified
path used (no new `use`), matching the existing `correction.rs:312`
style. No new deps. No new tests — the existing
`test_trufflehog_timeout_does_not_block` and
`bash_run_docker_returns_spawn_err_when_docker_config_none` still pass;
the change is additive (a `pre_exec` hook on the `Command`) and the
spawn contract is unchanged.
