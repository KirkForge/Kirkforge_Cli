**Location:** `src/session/parallel_orchestrator.rs:419`

Added `crate::session::process_group::setup_process_group(&mut cmd)`
before `.spawn()` in `apply_patch_to_parent`
(`src/session/parallel_orchestrator.rs:427`), mirroring the pattern in
`tools/workflow.rs:288`. The builder chain was rebound to a `let mut cmd`

`use` line), matching `correction.rs:312`. No new deps, no new files.

Effect: on the 30s timeout, `kill_on_drop` now reaps the whole `git apply`
process group (Unix `killpg` / Linux `PR_SET_PDEATHSIG`), so a hook-spawned
grandchild can no longer survive the timeout and keep pipes open. The 7
other spawn sites in the repo already had this; this was the lone miss.
