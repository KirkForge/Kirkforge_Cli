# WO 46.21 — web_fetch buffers entire HTTP body before size cap — OOM from untrusted server

## Status: Done

## Problem

**Location:** `src/tools/web_fetch.rs:222-238`

response.bytes().await buffers the entire HTTP body into memory, and only after it completes is MAX_BODY_BYTES (1 MiB) checked. A server streaming a multi-GB body within the 30s FETCH_TIMEOUT OOMs the process. Fix: stream via response.bytes_stream() and enforce the cap incrementally.

## Root cause

Identified by external model audits (DeepSeek + MiniMax). See

## Done

Streamed the response body via `response.bytes_stream()` with incremental
`MAX_BODY_BYTES` enforcement — the cap is checked per chunk BEFORE extending
the buffer, so a server streaming a multi-GB body within the 30s timeout is
aborted at the 1 MiB boundary instead of OOMing the process. No new deps
(`tokio_stream::StreamExt` was already a workspace dep; `bytes_stream()` is
gated by reqwest's `stream` feature, already enabled).

`src/tools/web_search.rs` checked: uses `resp.json().await` (incremental
deserialization) and `resp.text().await` only on the non-2xx error path
(small error bodies). No equivalent unbounded-body pattern — not in scope.
