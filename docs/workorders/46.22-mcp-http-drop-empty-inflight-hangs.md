# WO 46.22 — McpClient::Http Drop arm empty — in-flight calls hang 60s on swap

## Status: Done

## Problem

**Location:** `src/session/mcp_client/mod.rs:1303-1330`

McpClient::Http(_) => {} doesn't fail pending requests or signal shutdown. On config-reload swap, in-flight JSON-RPC calls sit until REQUEST_TIMEOUT (60s) per call × N concurrent. Fix: take the shutdown_tx from the transport, send (), call fail_all_pending.

Identified by external model audits (DeepSeek + MiniMax). See
/home/henrik/madlab/github/desktop/ds-bugs.md and mm-bugs.md for full evidence.

## Done

Fixed in `src/session/mcp_client/mod.rs` + `http.rs`. The `McpClient::Http`
Drop arm now takes `shutdown_tx` and sends `()` (mirrors the Stdio arm's
`reader_shutdown_tx` send). The SSE reader task already calls
`fail_all_pending` at every shutdown branch (http.rs:630/750/764), so
in-flight requests fail immediately instead of waiting the full
`REQUEST_TIMEOUT` (60s) × N.

Field `_shutdown_tx` renamed to `pub(super) shutdown_tx` so the Drop impl in
the parent module can take it. The `#[cfg(test)] disconnect()` method was
updated to the new field name.

No new deps. No shared files edited.
