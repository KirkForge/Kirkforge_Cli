# WO 46.25 — ci-local.sh set -e defeats run_step — failing step kills CI before remaining gates run

## Status: Done

## Problem

**Location:** `scripts/ci-local.sh:23-35`

run_step catches a command failure and appends to failures[], then return 1. But with set -e (line 11), returning non-zero from run_step terminates the whole script immediately. Any failing step kills CI before the release-build/audit/full coverage gates run, and the final summary is never printed. The failures[] machinery is dead code.

## Root cause

Identified by external model audits (DeepSeek + MiniMax). See
/home/henrik/madlab/github/desktop/ds-bugs.md and mm-bugs.md for full evidence.

## Approach

Read the Problem section's fix recommendation. Implement the minimal
correct fix. Add tests where practical.

## Files

scripts/ci-local.sh

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check`.

## Done

Removed the `return 1` on `run_step`'s failure path. The failure is
already recorded in `failures[]`; falling through (instead of returning
non-zero) keeps `set -e` from killing the script on the first failing
step, so the remaining gates run and the final summary reports every
failure and exits non-zero. The `failures[]` machinery is now live.
