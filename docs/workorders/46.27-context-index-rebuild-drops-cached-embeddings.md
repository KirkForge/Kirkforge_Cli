# WO 46.27 — mtime_rebuild/incremental_rebuild silently drop cached embeddings

## Status: Done

## Problem

**Location:** `crates/kf-context-index/src/cache.rs:96,175`

Both `mtime_rebuild` and `incremental_rebuild` called
`from_symbols_and_edges_and_calls`, which constructs a fresh
`ContextIndex { embeddings: Vec::new() }`, defeating WO 38.9 item 5's
caching invariant. Cached embeddings were silently dropped on every
rebuild. The no-op early-return paths (cache.rs:86,136,166) already used
`from_cached` (which preserves embeddings); only the "files changed"
paths dropped them.

## Root cause

`from_symbols_and_edges_and_calls` hard-codes `embeddings: Vec::new()`.
The rebuild paths used it instead of `from_cached` (which preserves
embeddings). Swapping alone is insufficient: `retain` shifts symbol
positions, so cached `symbol_idx` values would point at the wrong
symbols. The fix builds an old→new index map before dropping changed-file
symbols, then re-indexes surviving embeddings to their new positions.

## Approach

Read the Problem section's fix recommendation. Implement the minimal
correct fix. Add tests where practical.

## Files

- `crates/kf-context-index/src/cache.rs` — extracted shared
  `drop_changed` private helper that builds an old→new symbol index
  map before retain, preserves + re-indexes surviving embeddings, and
  filters edges/call_edges. Both `incremental_rebuild` and
  `mtime_rebuild` now call it instead of
  `from_symbols_and_edges_and_calls`. Added `SymbolEmbedding` to imports.
