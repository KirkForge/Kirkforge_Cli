# WO 46.28 — prune_oldest_in_dir ignores keep semantics — silent leak of oldest sessions

## Status: Done

## Problem

**Location:** `src/session/session_index.rs:430-481`

Doc says 'keep K, delete N' but the slice is entries[keep..keep+delete_count] — only delete_count are deleted. With keep=3, delete_count=2, len=10 it deletes 2 and leaves 8 (3 newest + 5 oldest leaked). Fix: slice entries[..keep] (delete everything except newest keep).

## Root cause (actual — corrected from the workorder's framing)

The workorder's proposed fix (`entries[..keep]`, "delete everything
except the newest K") is WRONG. The documented contract (4 places:
module doc, `prune_oldest` doc, `sessions.rs` module doc, and
`SESSIONS_HELP`) is "delete the OLDEST N, keep K most recent" with
defaults N=5, K=10. Deleting everything-beyond-keep would make
`/sessions prune` (defaults) erase 85 of 100 sessions — a data-loss
surprise the help text explicitly promises against.

The real bug: entries are sorted newest-first, and
`entries[keep..keep+delete_count]` deletes the N sessions immediately
*after* the keep window — NOT the oldest. With keep=10, delete=5,
len=16, indices 10..15 are deleted and the absolute oldest (index 15)
SURVIVES, contradicting "delete the oldest N". delete-at-most-N is
the correct intent.

## Fix

Slice `&entries[keep..threshold]` → `&entries[len - delete_count..]`
(the tail = the N oldest in a newest-first list). The existing guard
`len > keep + delete_count` guarantees `len - delete_count > keep`, so
the delete window never overlaps the keep window. `threshold` stays
for the guard only.

Fixed `test_prune_oldest_deletes_oldest`: its name + comment said
"oldest" but its assertion matched the bug (deleted the MIDDLE
session 02, kept the oldest 01). Corrected to assert the oldest
(01) is deleted.

Added `test_prune_oldest_in_dir_deletes_oldest_not_just_beyond_keep`
using the workorder's exact params (keep=3, delete=2, len=6): pins
that the oldest 2 are deleted and the 2 just-beyond-keep survive.

No doc-comment changes: the existing "the oldest ones" wording
becomes accurate once the impl matches it.
