# WO 46.3 — Daemon concurrency semaphore starved by long-lived instance push channels

## Status: Done

## Problem

**Location:** `src/daemon/server.rs:75,107,254`

Semaphore::new(16) permit is held for the entire handle_client lifetime, including long-lived InstanceRegister push channels. 16+ connected TUI instances permanently consume all permits, blocking new connections (e.g. kf-code run --attach). Fix: release the permit before entering the push loop for instance connections.

## Root cause

See Problem section — identified by the post-WO-45 area audit + external review.

## Approach

Read the Problem section's fix recommendation. Implement the minimal
correct fix. Add tests where practical.

## Files

src/daemon/server.rs

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +

## Done

Released the `Semaphore::new(16)` permit before entering the
`handle_instance_register` push loop.

Root cause: the `OwnedSemaphorePermit` acquired in the per-connection spawn
closure (`server.rs:107`) was bound to `_permit` and held for the entire
`handle_client` lifetime. `InstanceRegister` connections are long-lived push
channels that park indefinitely in `rx.recv().await` (`server.rs:498`), so 16+
attached TUI instances permanently consumed all 16 permit slots, blocking new
connections (`kf-code run --attach`).

Fix (smallest correct diff, `src/daemon/server.rs` only):
- Renamed `_permit` → `permit` and passed it into `handle_client` as an
  `OwnedSemaphorePermit` parameter.
- `drop(permit)` immediately before the `handle_instance_register` handoff —
  after the auth + version handshake is complete, since the permit should
  guard the handshake, not the entire push-channel connection lifetime.
- Request/response connections keep the permit for their whole (short)
  lifetime; only the long-lived instance push path releases it early.

Gate: clippy --all-targets -D warnings PASS, fmt --check PASS,
check --workspace --all-targets PASS, daemon tests (22/22) PASS including
`instance_register_receives_pushed_events` (exercises the fix path).
