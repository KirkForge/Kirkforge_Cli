# WO 46.32 — Daemon Unix socket has no explicit perms + auth token length leaks via timing

## Status: Done

## Problem

**Location:** `src/daemon/server.rs:63-64`

After bind, no set_permissions(0o600) — with default umask 0o022, socket is 0o755 (world-readable/connectable). If no token configured, anyone local can call List/Ping/Shutdown. Even with a token, ct_eq leaks token length via timing (mismatched-length returns immediately). Fix: set_permissions(0o600) after bind; pad token to fixed length before ct_eq.

## Root cause

Identified by external model audits (DeepSeek + MiniMax). See
/home/henrik/madlab/github/desktop/ds-bugs.md and mm-bugs.md for full evidence.

## Approach

Read the Problem section's fix recommendation. Implement the minimal
correct fix. Add tests where practical.

## Files

- src/daemon/server.rs — set_permissions(0o600) after bind (fail closed);
  `tracing::warn!` when no auth token configured; test
  `daemon_socket_is_owner_only` asserts mode == 0600.
- src/daemon/mod.rs — `check_auth` now SHA-256-hashes both token sides to a
  fixed 32-byte digest before `ct_eq` (`sha2` already a root dep — no new
  dep, no size cost). This is the single gate all server.rs call sites use,
  so the fix lands at the root, not per-call-site.

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check`.

## Done

- Socket perms: bind → chmod 0600 immediately; failure to chmod aborts the
  daemon (fail closed). Known micro-window between bind and chmod where
  umask perms apply — closing it would need a private parent dir; accepted.
- Token timing: fixed-length digest comparison; timing no longer depends on
  token length. Semantics unchanged (existing check_auth tests pass).
- No-token: warn only. Refusing would regress the documented admin-fallback
  behavior (WO 43.6 RBAC).
