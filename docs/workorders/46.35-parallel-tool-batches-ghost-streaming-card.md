# WO 46.35 — Parallel tool batches leave a ghost streaming card and mis-pair result entries

## Status: Done

## Problem

**Location:** `src/tui/events.rs:195-216`

When the model requests multiple tool calls in one turn, ToolStart
placeholders are pushed back-to-back. When ToolResult A arrives,
dispatch_turn_event checks last.streaming (true for B's still-open
placeholder), pops B's card and substitutes A's result. B's placeholder
is never popped. Ghost card corruption; common for multi-file edits.

## Root cause

Identified by external model audits (DeepSeek + MiniMax). See
/home/henrik/madlab/github/desktop/ds-bugs.md and mm-bugs.md for full evidence.

## Approach

Read the Problem section's fix recommendation. Implement the minimal
correct fix. Add tests where practical.

src/tui/events.rs

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +

## Done

- `src/tui/events.rs` — ToolResult arm now calls `remove_tool_placeholder`,
  which searches backwards for the newest streaming card whose content
  starts with `🔧 {name} ` (name-boundary safe; survives PTY chunk
  appends). Falls back to the old pop-back-when-streaming for
  header-stripped (>64 KiB truncated) PTY cards. Regression tests:
  parallel distinct-name batch, parallel same-name batch.
- `src/session/executor/turn.rs` — trace recording now fills the newest
  same-name `RecordedToolCall` with an empty result first
  (`fill_recorded_tool_result`), so parallel same-name calls each keep
  their output. Unit tests included.
- DEFERRED: exact call-id pairing. `TurnEvent::ToolStart`/`ToolResult`
  carry no call id; adding one means touching every emitter
  (helpers/outcome.rs, pre_run.rs, dispatch.rs, turn.rs). Name-based
  matching remains the ceiling. Tracked in this WO.
