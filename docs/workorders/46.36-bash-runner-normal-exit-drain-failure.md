# WO 46.36 — bash_runner normal-exit path can spuriously fail + leak grandchild holding the pipe

## Status: Done

## Problem

**Location:** `src/tools/bash_runner/mod.rs:718-730`

When the shell exits 0 but a backgrounded grandchild inherited the pipes, join_drain waits 5s then returns Err(ShellError::Drain). The tool reports a Drain failure for a command that exited 0, and the grandchild is not killed (normal-exit branch never calls kill_process_group).

## Done

Committed on `wo/wo46.36`. Actual file location was
`src/session/bash_runner/mod.rs` (WO said `src/tools/bash_runner/` — stale
path).

- `run_shell_with_token` normal-exit branch now uses a new
  `join_drain_or_note` helper: on a Drain failure (grandchild holds the
  pipe) it returns the (empty) stream plus a note
  `[stdout not captured: a background process still holds the pipe (...)]`
  appended to the affected stream, instead of `Err(ShellError::Drain)`.
  The shell's real exit status is preserved — exit 0 reports Success.
- Timeout/cancelled paths keep `join_drain` + `kill_process_group`
  unchanged (a stuck drain after a group kill is a real anomaly).
- Grandchild is NOT killed on normal exit: fix scope is "don't fail the
  call"; the backgrounded process may be intentional. (Orphan survives —
  bounded by its own lifetime.)
- Tests: `test_join_drain_or_note_failed_drain_returns_note` (instant,
  io-error arm), `test_join_drain_or_note_completed_drain_passes_through`
  (pass-through arm), and `#[ignore]`d e2e
  `run_shell_normal_exit_with_grandchild_holding_pipe_succeeds`
  (`echo ...; sleep 10 &` — waits out the 5s DRAIN_JOIN_TIMEOUT; verified
  with `--include-ignored`, passed in 10.04s).
