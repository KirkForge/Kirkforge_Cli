# WO 46.37 — web_fetch/web_search ignore tool cancel token — cancelled turn waits full 30s

## Status: Done

## Problem

**Location:** `src/tools/web_fetch.rs:205,222`

ctx.token is taken but never raced against network awaits. A cancelled turn waits the full FETCH_TIMEOUT (30s) per fetch. Fix: wrap each .await in tokio::select! against ctx.token.cancelled().

## Root cause

Identified by external model audits (DeepSeek + MiniMax). See
/home/henrik/madlab/github/desktop/ds-bugs.md and mm-bugs.md for full evidence.

## Approach

Read the Problem section's fix recommendation. Implement the minimal
correct fix. Add tests where practical.

## Files

src/tools/web_fetch.rs, src/tools/web_search.rs

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check`.

## Done

All awaits in `WebFetch::run` (DNS guard join, `client.execute`, each body
stream chunk) and `WebSearch::run` (the whole `search_brave` future) are now
raced against `ctx.token.cancelled()` via `tokio::select! { biased; ... }`,
returning `ToolError::Cancelled` — same pattern as WO 46.8 (grep/glob).
Dropping the in-flight reqwest future aborts the request.

Tests: `cancelled_fetch_returns_promptly` (web_fetch, wiremock 15s delay +
mid-flight cancel, must return Cancelled within 5s) and
`cancelled_token_returns_cancelled` (web_search, network-free).
