# WO 46.38 — verify_task cmd.env() doesn't env_remove() first — leaked parent env affects gate

## Status: Done

## Problem

**Location:** `crates/kf-bench/src/lib.rs:182-184,203-205`

Curated env is set on top of inherited parent env. verify-only never strips it; a leaked parent value silently affects the gate. Fix: cmd.env_remove(KF_CODE_BUDGET_CEILING) before cmd.env(K, V).

## Root cause

Identified by external model audits (DeepSeek + MiniMax). See
/home/henrik/madlab/github/desktop/ds-bugs.md and mm-bugs.md for full evidence.

## Approach

Read the Problem section's fix recommendation. Implement the minimal
correct fix. Add tests where practical.

## Files

crates/kf-bench/src/lib.rs

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check`.

## Done

Both verify command-construction sites (`TestPasses`, `CommandExitsZero`)
now call `cmd.env_remove(BUDGET_CEILING_ENV)` before applying the task's
curated env, so a leaked parent `KF_CODE_BUDGET_CEILING` can no longer
affect the gate when a task pins no ceiling. Regression coverage added as
a leak phase in `verify_task_inherits_curated_budget_env` (red without the
fix, green with it).
