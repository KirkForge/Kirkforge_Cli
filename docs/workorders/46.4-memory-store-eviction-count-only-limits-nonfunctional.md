# WO 46.4 — kf-memory-store eviction is count-only — TTL and max_entries limits are non-functional

## Status: Done

## Problem

**Location:** `crates/kf-memory-store/src/store.rs:78-107`

evict_expired and evict_overflow only COUNT evictable entries, never DELETE. No delete method in MemoryAdapter trait or SqliteAdapter. TTL and max_entries limits are completely non-functional (unbounded growth). Fix: add delete() to MemoryAdapter trait, implement for both FileAdapter and SqliteAdapter, call in eviction.

## Root cause

See Problem section — identified by the post-WO-45 area audit + external review.

## Approach

Read the Problem section's fix recommendation. Implement the minimal
correct fix. Add tests where practical.

## Done

- Added `fn delete(&self, id: &str) -> Result<()>` to the `MemoryAdapter`
  trait (`crates/kf-memory-store/src/adapters/mod.rs`), positioned between
  `read` and `query`. Required method (no default) — all three impls get an
  explicit impl; no external implementors exist (grep-verified).
- Implemented `delete` for `InMemoryAdapter` (`adapters/in_memory.rs`):
  `retain(|o| o.id != id)`. Deleting a missing id is a no-op.
- Implemented `delete` for `FileAdapter` (`adapters/file.rs`): acquire lock,
  ensure loaded, `retain(|o| o.id != id)`, flush only if something was
  removed (avoids unnecessary disk writes). Deleting a missing id is a no-op.
- Implemented `delete` for `SqliteAdapter` (`adapters/sqlite.rs`):
  `DELETE FROM observations WHERE id = ?1`. Deleting a missing id is a no-op
  (DELETE on absent row affects 0 rows, no error).
- Rewrote `evict_expired` (`store.rs:78`): queries all, filters expired by
  timestamp < cutoff, calls `adapter.delete(id)` for each, returns count.
- Rewrote `evict_overflow` (`store.rs:98`): queries all (newest-first DESC),
  drops the first `max_entries` (newest), deletes the rest (oldest), returns
  count. Early-returns 0 when not over the limit.
- Removed the `ponytail:` ceiling comment ("the generic adapter has no
  DELETE...") — the ceiling is lifted; this WO is the upgrade path it named.
- Tests added in `tests/integration.rs`:
  - `in_memory_delete_removes_entry` — delete + no-op-on-missing.
  - `file_adapter_delete_removes_and_persists` — delete flushes to disk
    (verified by re-opening the file).
  - `sqlite_delete_removes_entry` — delete + no-op-on-missing.
  - `store_evict_expired_actually_deletes` — TTL eviction deletes the old
    entry, keeps the new one.
  - `store_evict_overflow_actually_deletes_oldest` — overflow eviction
    deletes the oldest entries, keeps the newest `max_entries`.
  - `store_evict_overflow_actually_deletes_on_sqlite` — same on SqliteAdapter.
  - Existing `store_evict_overflow_reports_excess` and
    `store_evict_expired_counts_old_entries` still pass (return value is
    still the count evicted).
- Gate: `cargo test -p kf-memory-store` (42 passed), `scripts/test-fast.sh`
  (4761 passed, 15 skipped), `cargo clippy --all-targets -- -D warnings`
  (clean), `cargo fmt --check` (clean), `cargo check --workspace --all-targets`
  (clean).
