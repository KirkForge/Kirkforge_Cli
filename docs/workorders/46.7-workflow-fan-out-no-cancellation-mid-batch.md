# WO 46.7 — WorkflowExecutor::run_fan_out does not honour cancellation mid-fan-out

## Status: Done

## Problem

**Location:** `crates/kf-workflow/src/executor.rs:130`

run_fan_out doesn't check cancellation between spawns or abort the JoinSet on cancel. All N child tasks run to completion after Esc. Fix: select between JoinSet::join_next and the cancel token; abort remaining tasks on cancel.

See Problem section — identified by the post-WO-45 area audit + external review.

## Done

`run_fan_out` now races `join_set.join_next()` against the cancellation
flag via `tokio::select!`. On cancel, `join_set.abort_all()` drops the
remaining children and the function bails `"workflow cancelled"`
(matches the driver's bail string so `workflow.rs` classifies it as
cancellation). Signature gained `cancellation: Option<&AtomicBool>`;
the single call site (`run`) passes the flag through.

Test: `fan_out_aborts_on_cancel_mid_fan_out` — `max_parallel=1` so
children start one at a time; the first child flips the cancel flag;
asserts the workflow errors with "cancelled" and fewer than all 4
children started.

clean; cargo fmt --check clean. test-fast flaked on one pre-existing

WO 35.3, unrelated to kf-workflow) that passes in isolation — see
