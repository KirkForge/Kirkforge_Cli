# WO 46.8 — grep/glob spawn_blocking tasks not cancellable by tool timeout — hung subprocess leaks

## Status: Done

## Problem

**Location:** `src/tools/grep.rs:42`, `src/tools/glob.rs:89`

spawn_blocking + cmd.output() is not cancellable by the tool timeout. A hung rg leaks a blocking-pool thread and subprocess past the timeout. Fix: use tokio::process::Command with kill_on_drop + a timeout race instead of spawn_blocking + std::process.

## Root cause

See Problem section — identified by the post-WO-45 area audit + external review.

## Approach

- grep `run_rg`: switched from `spawn_blocking` + `std::process::Command` to
  `tokio::process::Command` with `kill_on_drop(true)` + a `tokio::select!`
  race against `ctx.token.cancelled()`. On cancel the `Child` is dropped →
  `kill_on_drop` reaps `rg`. Added an async `rg_available_async` probe so the
  version check also uses `tokio::process` + `kill_on_drop` (no
  `spawn_blocking` round-trip). Extracted the JSON parse into a shared
  `parse_rg_output` helper used by both the new async `run_rg` and the
  test-only sync `run_rg_blocking` (kept for the existing regression test).
- grep fallback walk: wrapped the `spawn_blocking` in a `tokio::select!`
  against `ctx.token.cancelled()` → returns `ToolError::Cancelled` promptly.
  The blocking-pool thread keeps walking to completion (spawn_blocking can't
  be killed), but the tool returns immediately and the leaked thread is
  bounded by the walk finishing on its own (no subprocess to leak).
- glob `run`: same `tokio::select!` wrap around the `spawn_blocking` walk.
  Same caveat — the blocking thread finishes on its own, but the tool
  returns `Cancelled` promptly and no subprocess leaks.
- Pattern reference: `session/plugin_tools/wrapper.rs:324`
  (`Finish::Cancelled` via `ctx.token.cancelled()`), `session/bench.rs:61`
  (timeout + kill_on_drop), `session/verifier/security.rs:236`
  (`tokio::time::timeout` + `kill_on_drop`).
- No new deps. `tokio` already has `features = ["full"]` so
  `tokio::process` is available. Signature unchanged: `run(&self, ctx:
  &ToolContext, args)` — only the body changes; `_ctx` → `ctx`.
