# WO 47.1 — Table-driven verifier registration (11 of 16 verifiers share the same 90-160-line shape)

## Status: Done

## Problem

11 of 16 verifiers (node_test, node_lint, go_test, go_vet, generic_test, python_test, python_lint, python_typecheck, build, lint, test) are the same shape: run command, parse output, emit verdict. Table-driven registration collapses ~800 lines. Also collapse init_default_verifiers (~700 lines of 16x struct-impl-register boilerplate at executor/mod.rs:617) into a registration table (~650 saved). Combined: ~1,450 lines.

Source: post-WO-46 size audit (kf-code-review.md, 2026-08-27). The codebase is
~110K production lines vs a ~30K lean-agent baseline; this WO is part of the
"Lean KirkForge" convergence toward ~85-88K.

## Root cause

Accumulation across WO series — features added per-WO with default features
and no size gate at add/remove time; crate boundaries drawn early never
revisited; process artifacts (tests, docs, dev tooling) counted as codebase.

## Approach

Read the Problem section. Implement the minimal correct reduction. Where a WO
deletes code, verify no production consumer breaks (grep + cargo check).
Where it moves code, keep public APIs stable or update all consumers.

## Files

src/session/verifier/**, src/session/executor/mod.rs

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check` + `cargo check --workspace --all-targets`. For deletions:
`git grep` proves zero production references before removal.

## Done

Shipped on `wo/wo47.1` (not merged/pushed). Two reductions, behavior-preserving:

1. **Registration table** (`executor/mod.rs` `init_default_verifiers`):
   the 14 per-verifier `struct XV; impl Verifier; register` blocks
   (~300 lines) became one `FnVerifier` + a 14-row `(name, priority,
   boxed verify fn)` table + one register loop. Names, priorities
   (1-13), registration order, and the returned count are identical —
   pinned by `executor::tests::verifier_cross::
   rebuild_plugin_verifiers_keeps_every_built_in` (green). The three
   runner-injecting verifiers (lint/build/test) receive
   `SystemCommandRunner` via a fn-local `static` so the boxed future
   borrows a `'static` ref and the rows still coerce to fn pointers.

2. **Shared verifier prelude** (`verifier/helpers.rs`): `modified_path`,
   `language_gate` (ext allowlist + root walk + language confirm,
   returning `Gate::Root/Gate::Skip` — not a `Result`, a skip is a
   normal outcome and `Verdict` trips `result_large_err`),
   `head_body`/`tail_body` (the two output-truncation shapes),
   `command_finding` (the empty-replacement `FixSuggestion` ctor), and
   `tool_on_path` (the toolchain probe; dedupes `pick_go` ×2, make/
   ctest/npm/npx probes). The 8 marker-gated modules (node_test,
   node_lint, go_test, go_vet, python_test, python_lint,
   python_typecheck, generic_test) now share these; skip messages are
   byte-identical (per-file tests unchanged and green).

Net: −161 lines (479+/640−), all inside the WO's file scope. The WO's
~1,450-line estimate was audit-inflated: it counted the Rust trio
(build/lint/test, which inject `CommandRunner` and parse cargo/clippy
JSON — genuinely different shape, only their registration collapsed)
and the per-file test suites (kept as the regression net).

Gate (fast, per worker prompt): `cargo check --workspace --all-targets`
clean; `cargo clippy -p kf-code --all-targets -- -D warnings` clean;
`cargo fmt --check` clean; targeted tests 318/318 (`test(/verifier/)`:
all 8 module suites + handler/bus/correction + helpers) and 202/202
(`test(/executor/)`: incl. both verifier_cross pins). Phase-B impact:
`init_default_verifiers` upstream CRITICAL (1 direct caller, feeds
run_line_mode/run_tui/main/run_task) — mitigated by the
behavior-preserving design + name/priority pins; detect_changes vs
index showed only line-shift noise on neighboring fns (graph index is
main-checkout-based; actual hunks verified confined to
`init_default_verifiers` + imports).
