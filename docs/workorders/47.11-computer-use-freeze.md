# WO 47.11 — Freeze/delete computer_use (513 lines, default-off mini browser framework)

## Status: Done

## Problem

computer_use is default-off (WO 43.20 gated it) and contains a mini browser framework. Decision needed: freeze (keep, no investment) or delete (remove 513 lines + the feature flag). If Claude-compat computer-use demand materializes, unfreeze.

Source: post-WO-46 size audit (kf-code-review.md, 2026-08-27). The codebase is
~110K production lines vs a ~30K lean-agent baseline; this WO is part of the
"Lean KirkForge" convergence toward ~85-88K.

## Root cause

Accumulation across WO series — features added per-WO with default features
and no size gate at add/remove time; crate boundaries drawn early never
revisited; process artifacts (tests, docs, dev tooling) counted as codebase.

## Approach

Read the Problem section. Implement the minimal correct reduction. Where a WO
deletes code, verify no production consumer breaks (grep + cargo check).
Where it moves code, keep public APIs stable or update all consumers.

## Files

src/tools/computer_use.rs, src/main/chrome_launcher.rs, Cargo.toml

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check` + `cargo check --workspace --all-targets`. For deletions:
`git grep` proves zero production references before removal.

## Done

**Decision: FREEZE** (status quo — keep, no investment). Not deleted.

- WO 43.20 already did the reduction this audit wanted: `computer_use` is a
  real feature gating `dep:headless_chrome`, default OFF; default builds
  compile PlaceholderTab and exclude the Chrome dep (~1-2 MB saved). Freeze
  costs nothing in default builds — zero dep-graph, zero binary impact.
- The "513 lines" premise was stale: the surface is 1970 lines
  (`src/tools/computer_use.rs`) + 235 (`src/main/chrome_launcher.rs`) plus
  config/adapter-wire/registration surface across ~21 files. The adapter
  wire format (`computer` tool type, `anthropic-beta` header,
  `computer_tool_result` parsing) is live Anthropic-compat code (WO 45.31),
  and WO 47.33 added an SSRF gate to it — the code is maintained, not
  rotting. Deleting it would be a large cross-cutting removal regressing
  documented Claude-compat behavior — not the minimal correct reduction.
- Action taken: `ceiling: FROZEN (WO 47.11)` comment pinned at the feature
  in `Cargo.toml` (unfreeze condition + delete-precondition documented
  there). No code changes — `src/tools/computer_use.rs` and
  `src/main/chrome_launcher.rs` untouched.
- Unfreeze condition: Claude-compat computer-use demand materializes.
  Delete precondition: a dedicated cross-cutting WO (~21 files).

Gates (comment/docs-only change): `cargo check --workspace --all-targets`,
`cargo clippy -p kf-code --all-targets -- -D warnings`, `cargo fmt` — all
green (head 15ad6877 + this commit).
