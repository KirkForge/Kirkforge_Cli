# WO 47.13 — TUI command diet (trim set ≈ 3-4K shipped lines)

## Status: Done

## Problem

37 slash commands; the trim set (doom banner, persona, gh, mentions, carryover display, cron scheduling inside /jobs, route, metrics) ≈ 3-4K shipped lines. Each is wired but low-value vs mass. Cut or gate the low-traffic commands.

Source: post-WO-46 size audit (kf-code-review.md, 2026-08-27). The codebase is
~110K production lines vs a ~30K lean-agent baseline; this WO is part of the
"Lean KirkForge" convergence toward ~85-88K.

## Root cause

Accumulation across WO series — features added per-WO with default features
and no size gate at add/remove time; crate boundaries drawn early never
revisited; process artifacts (tests, docs, dev tooling) counted as codebase.

## Approach

Read the Problem section. Implement the minimal correct reduction. Where a WO
deletes code, verify no production consumer breaks (grep + cargo check).
Where it moves code, keep public APIs stable or update all consumers.

## Files

src/tui/commands/**, src/tui/widgets/**

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check` + `cargo check --workspace --all-targets`. For deletions:
`git grep` proves zero production references before removal.

## Done

Gated (reversible, coordinator directive — no deletions) behind
`[display] extra_commands` (config.toml, default empty = off, live via
`/reload`); config-flag chosen over a default-off cargo feature so the
gated code stays compiled and tested by every default gate:

- `/gh` → `"gh"`; `/route` → `"route"`; `/metrics` → `"metrics"`;
  `/carryover` → `"carryover"` (display command only — the cross-session
  profile machinery stays).
- `/plan` `/explore` `/coder` → `"personas"` (commands only — persona
  machinery stays ungated: `/workflow` and the doom-banner Plan action
  run through it; `/implement` stays).
- `/jobs` cron surface (`schedule|scheduled|run-now|logs`) →
  `"jobs-schedule"` (background-bash `/jobs` surface stays always-on).
- `@`-mention expansion + completion → `"mentions"` (input sent verbatim
  when off).

Gated commands are hidden from `/help` + Tab completion and answer with
an enable-hint message. Mechanism: `EXTRA_KEYS` +
`extra_enabled`/`command_enabled` in `src/tui/keys/slash_commands.rs`;
new `DisplayConfig.extra_commands` field (CONFIG_FIELD_COUNT 107→108,
merge_toml handled; no env override — precedented Vec skip class).

DEFERRED / left as-is (disclosed):
1. **Doom banner NOT gated** — it is the doom-loop runaway warning
   interrupt (safety UI, WO 43.31 regression-pinned), not a cosmetic
   extra. Gating it default-off removes loop protection; that is a
   product decision, not a diet item.
2. **Line-mode `/carryover show|clear` (src/main/line_mode.rs) not
   gated** — outside this WO's file scope (TUI diet); parity follow-up
   if wanted.
3. Shipped-line count NOT reduced (no code deleted) — the coordinator
   explicitly chose gating over cutting; the size-trim goal moves to
   whichever WO later flips these gates to deletions.

New tests: `extra_keys_triggers_exist_in_commands_table`,
`gated_commands_hidden_by_default`,
`gated_commands_enabled_via_config`, `extra_disabled_msg_names_command_and_key`
(slash_commands.rs); `scheduled_surface_disabled_by_default` (jobs.rs).
Existing tests re-keyed to an all-extras fixture (intent preserved).
