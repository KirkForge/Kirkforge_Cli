# WO 47.14 — Unify the two verifier trait systems (LAST + riskiest)

## Status: Done

## Problem

Two live verifier architectures: Verifier/VerifierSlots (event-driven) and
BusVerifier/VerifierBus (context-based). AGENTS.md §7 currently forbids
unifying them in one pass — this WO is the explicit exception request: do it
AFTER 47.1 (table-driven) lands, one consumer at a time (~400-500 lines).
Requires an AGENTS.md §7 amendment.

Source: post-WO-46 size audit (kf-code-review.md, 2026-08-27). The codebase is
~110K production lines vs a ~30K lean-agent baseline; this WO is part of the
"Lean KirkForge" convergence toward ~85-88K.

## Root cause

Accumulation across WO series — features added per-WO with default features
and no size gate at add/remove time; crate boundaries drawn early never
revisited; process artifacts (tests, docs, dev tooling) counted as codebase.

## Approach

Read the Problem section. Implement the minimal correct reduction. Where a WO
deletes code, verify no production consumer breaks (grep + cargo check).
Where it moves code, keep public APIs stable or update all consumers.

Note: WO 47.1 (table-driven registration) had NOT landed when this session

   `register_plugin_verifiers_into_bus` + `as_verifier_parts` (+ kept tests).
   Module docs state the env-var migration for plugin script authors.
2. `src/session/executor/mod.rs` (scope creep, disclosed): deleted the

3. `src/session/verifier/bus.rs`: trait-coexistence doc rewritten
   (unification in progress, ledger of what migrated); the env-var
   divergence `ceiling:` resolved to the single `KF_VERIFIER_NAME` +
   `KF_CHANGED_FILES` contract; the env-leak security pin (previously on the
   deleted adapter) re-landed on the bus path
   (`add_plugin_verifier_does_not_leak_session_env`).
4. `src/session/executor/tests/verifier_cross.rs`: the WO 44.29 guard
   (`rebuild_plugin_verifiers_keeps_every_built_in`) reworked to
   `reload_plugins_keeps_every_built_in_verifier` driving `reload_plugins`

Net: −640 lines added/removed delta ≈ −390 net (plugin.rs 519→155;
executor/mod.rs −60; tests reworked in place). Behavior deltas (disclosed):

- Plugin verifiers no longer run on read_file/bash/edit events via the
  event-driven path — the bus fires only after write_file/edit_file. A
  plugin verifier that guarded bash commands loses that hook until
  `VerifyContext` carries the event (remaining work, step 2).
- Plugin verifier scripts receive `KF_VERIFIER_NAME` + `KF_CHANGED_FILES`
  only; the adapter's `KF_EVENT_KIND`/`KF_EVENT_JSON` are retired.
- In exchange: no more double execution of every plugin verifier per
  file-modifying tool call, and no more duplicate CorrectionResults for a
  single failing finding (previously one from each path).

AGENTS.md §7 was NOT amended (per coordinator instruction: only when the old
trait is fully deleted — it is not; the §7 "don't unify in one pass" rule
remains accurate for every consumer EXCEPT the plugin path migrated here,
which this WO file documents as the sanctioned exception).

### Migration plan (remaining consumers, in order — each is one gated commit)

The end state: ONE trait (`BusVerifier`), `Verifier`/`VerifierSlots`
deleted. The blocker shaping the order: the event-driven pipeline needs
(a) the event payload, (b) fix suggestions for the correction loop, and
(c) bounded async concurrency (WO 47.26). The survivor trait must grow
those before the built-ins can move.

1. **Extend `VerifyContext`** with the triggering `BusEvent` (path, diff,
   content_hash) and give `VerdictEntry` an optional `FixSuggestion`
   payload. Purely additive; bus.rs + types.rs only.
2. **Decide + implement the async story** (the WO 43.26 deferred decision):
   either make `BusVerifier::verify` async (breaking the sync
   `VerifierBus::run` callers in dispatch.rs, which hold the bus mutex on a
   tokio worker — must move to `spawn_blocking` per verifier or an async
   lock) or keep the trait sync and have the handler wrap each verifier in
   `spawn_blocking` + `tokio::time::timeout` (preserves WO 47.26 bounded
   concurrency). Recommended: sync trait + spawn_blocking in the driver —
   smaller contract change, keeps `catch_unwind` (WO 47.19) as-is.
3. **Migrate the 14 built-in verifiers** (security, lint, build, git,
   rustfmt, test, python_test, python_lint, python_typecheck, node_test,
   node_lint, go_test, go_vet, generic_test): each `verify_*` free fn
   returns `Vec<VerdictEntry>` (with fix payloads where the correction loop
   auto-fixes today: rustfmt, lint quickfixes). This is where WO 47.1's
   table-driven registration folds in — register via one table of
   (name, priority, verify_fn) instead of 14 struct impls.
4. **Migrate `VerifierHandler`/`CorrectionLoop`** onto the extended bus:
   handler drives `dyn BusVerifier` (spawn_blocking + timeout + panic
   guard + verdict cache unchanged); correction loop consumes
   `FixSuggestion` from `VerdictEntry`.
5. **Delete the old trait**: `Verifier`, `VerifierSlots`, `Verifier`
   re-exports from `verifier/mod.rs`; port the slot/handler/correction
   tests; THEN amend AGENTS.md §7 (doc-sync rule) and this file's plan
   closes.

Deferred: steps 1-5 above (this session landed the plugin consumer only).
Why: full migration is multi-session scale (~1.5-2K lines across handler,
correction loop, 14 verifiers, and their test suites); the coordinator
scoped session 1 to the first consumer + plan. Tracked here (this WO's
migration plan) + state.md pending entry owned by the coordinator.
