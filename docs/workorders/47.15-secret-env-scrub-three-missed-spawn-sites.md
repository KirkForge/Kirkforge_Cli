# WO 47 — Secret-env scrub missing at 3 spawn sites: docker, shell hooks, verifier formatter

## Status: Done

## Problem

CRITICAL — credential leak. (1) src/tools/bash.rs:183 `Command::new("docker")` never calls scrub_secrets_from_child_env — container children see ANTHROPIC_API_KEY/*_TOKEN via `docker run alpine printenv`. (2) src/session/hooks.rs:623 `Command::new("bash")` sets only KF_* vars, never scrubs — a hook running printenv exfiltrates session credentials. (3) src/session/verifier/correction.rs:307 formatter spawn inherits full parent env — PATH-shadowed rustfmt shim exfiltrates keys. The contract comment at bash_runner/mod.rs:608-611 enumerates the paths that scrub; these 3 are the regression. Fix: one scrub_secrets_from_child_env call per site (mirror bash_jobs.rs:240). Reproducers in mm-bugs.md C1/H1 and ds-bugs.md H2.

Source: multi-model audit vetting 2026-08-27 (mm-bugs.md, ds-bugs.md, kimi-bugs.md,
sonnet-bugs.md, gpt-bugs.md). Top-severity claims verified against the code at
dbfd8bb0 before filing.

## Root cause

See Problem — per-site. Cross-cutting theme: invariants enforced at one layer
(pre_run, session daemon) instead of the component that owns the operation;
and WO fixes applied at one site of a duplicated pattern.

## Approach

Read the Problem section. Implement the minimal correct fix. Where a fix
closes a class (scrub, gating, anchoring), grep for sibling sites of the same
pattern before considering it done.

## Done

Fixed: one `crate::session::bash_runner::scrub_secrets_from_child_env(&mut cmd)`
call per site (fully-qualified, mirroring bash_jobs.rs:240 — no import churn):

- `src/tools/bash.rs` `run_docker` — scrub before the docker spawn.
- `src/session/hooks.rs` `run_hook_script` — scrub after
  `setup_process_group`, BEFORE the KF_* env-var loop so explicit sets win.
- `src/session/verifier/correction.rs` `apply_command_fix` — scrub before
  the config-string formatter spawn.

  command>` inherits full env; file-driven bench verify commands could
