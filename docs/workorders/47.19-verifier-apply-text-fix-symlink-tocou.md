# WO 47 — Verifier apply_text_fix symlink-swap TOCTOU + VerifierBus catch_unwind double-panic

## Status: Done

## Summary

Two commits on `wo/wo47.19`:

1. `dc4817e3` — `apply_text_fix` and the sibling `apply_command_fix`
   (formatter path, same class) now run the `symlink_swap_denied` walk
   (made `pub(crate)` in dispatch.rs) before the write/spawn. A swapped
   or pre-existing symlinked `fix.file` is refused instead of
   O_TRUNC-ing the link target. Two unix canary tests
   (`test_apply_text_fix_symlink_target_refused`,
   `test_apply_command_fix_symlink_target_refused`) pin both sites.
   Note: the walk carries the same `ponytail:` ceiling as dispatch.rs —
   not atomic with the write; upgrade path openat2(RESOLVE_NO_SYMLINKS).
2. `93c6fe6d` — (a) `VerifierBus::run`'s catch_unwind panic handler
   called `verifier.name()` (arbitrary verifier code) while handling a
   caught panic — a panic there escapes the catch and unwinds through
   the executor's held `Mutex<VerifierBus>` guard, poisoning it;
   `name()` is now captured before the catch, making the handler
   panic-free. (b) `emit_tool_event_and_correct` locked that mutex with
   `if let Ok(..)`: once poisoned, every later file-modifying call
   silently skipped ALL bus verification for the rest of the session;
   now recovers via `unwrap_or_else(into_inner)` (repo poison
   convention, WO 38.2 / 20.0.4 / 30.0.0-H1).

Gate (all green, head `93c6fe6d`): test-fast 4783 passed / 16 skipped,
clippy `-D warnings` clean, fmt clean, `cargo check --workspace
--all-targets` clean.

## Problem

HIGH. (1) src/session/verifier/correction.rs:209-249 — apply_text_fix does path.exists() → read_to_string → replacen → std::fs::write with no symlink check. A same-batch bash call can swap the target between probe and write; the auto-fix O_TRUNCs ~/.ssh/id_rsa. The dispatch.rs symlink_swap_denied walk covers file TOOLS, not the verifier's own file I/O. Fix: call symlink_swap_denied(path) (make it pub(crate)) before the write. (2) correction.rs / bus.rs:169 — AssertUnwindSafe catch_unwind around verifier bodies holding a Mutex: a panic while poisoned re-panics inside the catch (double-panic = abort). Fix: lock via unwrap_or_else(into_inner) inside the caught closure, or drop the guard before any fallible op.
