# WO 47.2 — Generic env-override loader (91 hand-parsed KF_* vars in 4 layers)

## Status: Done

## Problem

src/session/config/env_overrides.rs hand-parses 91 KF_* env vars with ~116 if-lets in merge.rs on top. A generic dotted-path parser (env var name maps to config path, type from the field) replaces both wholesale (~550 lines) and prevents future drift (add a field, env var works automatically).

Source: post-WO-46 size audit (kf-code-review.md, 2026-08-27). The codebase is
~110K production lines vs a ~30K lean-agent baseline; this WO is part of the
"Lean KirkForge" convergence toward ~85-88K.

## Root cause

Accumulation across WO series — features added per-WO with default features
and no size gate at add/remove time; crate boundaries drawn early never
revisited; process artifacts (tests, docs, dev tooling) counted as codebase.

## Approach

Read the Problem section. Implement the minimal correct reduction. Where a WO
deletes code, verify no production consumer breaks (grep + cargo check).
Where it moves code, keep public APIs stable or update all consumers.

## Done

Replaced both hand-enumerated override layers with one generic serde
overlay (net −~700 production lines: merge.rs 453 → ~200, env_overrides.rs
628 → ~230, plus the ~110-line TOML/env literal tables deleted from the
drift-guard test).

**How it works.** `merge_toml_into_config` (merge.rs) serializes the
current `Config` to its flat TOML form, inserts one override key at a
time (dot-path aware, deep-merging sub-tables), and decodes back via
serde — the `#[serde(flatten)]` on `Config` does key routing, typing,
defaults, and alias handling. A key whose value doesn't fit is skipped
(prior value kept), so a bad value can never wipe unrelated fields
(pinned by `bad_typed_key_does_not_wipe_sibling_keys`). `apply_env_overrides`
(env_overrides.rs) derives the config key from the var name
(`KF_CODE_FOO_BAR` → `foo_bar`), coerces the value using the current
config's serialized form as the type guide, and feeds the result through
the same overlay + a shared `normalize()` (tilde expansion, empty→None
for Option paths, min-clamps). **A new Config field is now reachable
from config.toml and `KF_CODE_<FIELD>` with zero loader changes** (the
WO's "prevents future drift" goal). Irregular names live in a 24-entry
`KEY_MAP`; three whole-section/validated vars (adapter_routing,
plugin_sources, task_concurrency_mode) are applied post-overlay with
their documented replace/validate semantics.

The old "serde flatten+default is broken (#2230)" claim (commit 8caff890)
was re-verified empirically and is stale for the current struct shapes:
partial flat files, unknown keys (dropped), the compaction alias, and
partial sub-tables all deserialize correctly. The stale comment in
`load_config` was corrected.

**Serde gotchas found and handled** (each pinned by a test):
- Inserting an alias key (`compaction_use_llm`) while the serialized base
  holds the primary (`compaction_use_heuristic`) is a duplicate-field
  error → aliases are swapped to the primary at insert time, primary
  wins when both are set (old if/else-if order preserved).
- `memory_auto_populate` is declared by BOTH ToolConfig and
  DisplayConfig; the custom SessionConfig Deserialize between them hides
  the key from DisplayConfig, and serialization writes display's copy
  (last writer) → the incoming value is mirrored onto both fields
  directly (old env behavior: both; old file behavior: display only).
- `skip_serializing` fields (seed) cannot be lost by the round-trip:
  seed is only set post-load (run_session.rs:104), and both overlay
  entry points run only inside `load_config`.

**Behavior deltas (all intentional, disclosed):**
1. ADDITIVE: config.toml can now set previously merge-skipped fields
   (docker, sandbox, permission_rules, mcp_servers, lsp_servers,
   max_plugin_trust, stratum_mode, budget_approaching_ratio, …) — typed
   through serde like everything else.
2. ADDITIVE: derived env vars for previously env-less fields; Vec<String>
   fields take comma-separated lists (e.g. `KF_CODE_DENY_URLS=a,b`),
   pinned by `test_env_derived_list_var`.
3. `KF_CODE_SANDBOX_DIR=""` now lands as `Some("")` — the documented
   unsandboxed opt-out (WO 28.1 contract text). Previously the env layer
   mapped "" to `None`, which `freeze_launch_sandbox` silently
   re-sandboxed to cwd, breaking the documented env opt-out. No test
   pinned the old reading. Pinned by
   `test_env_sandbox_dir_empty_is_explicit_opt_out`.
4. `KF_CODE_COMPACTION_USE_HEURISTIC` now accepts 1/yes/0/no
   (parse_bool_env) like every other bool var (was strict "true"/"false"
   only).
5. Map fields ([adapter_routing], [plugin_sources], [price_overrides],
   [routing_model_map], [plugin_sources]) now deep-merge from the file
   layer instead of replacing — identical outcome at load time (base
   maps are empty), and the env vars for adapter_routing/plugin_sources
   still replace the whole section per their documented contract.

**Known limitation (pre-existing, unchanged):** a config file with the
legacy `worktree_enabled`/`auto_apply_patch` bools still gets
`artifact_policy = "direct_write"` from the serialized base (explicit
string wins), i.e. legacy bools are ignored — exactly the old
merge-layer behavior (it skipped those keys too). Fixing it would
require stripping `artifact_policy` from the trial when legacy bools are
present; deferred as it is not a regression.
