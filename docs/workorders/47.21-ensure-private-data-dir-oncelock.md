# WO 47 — ensure_private_data_dir OnceLock caches the first path globally — variable data dirs break

## Status: Planned

## Problem

HIGH — explains multiple known test flakes. src/session/mod.rs:73-90 uses a process-global OnceLock: the closure runs once with the FIRST dir and never re-executes. After any earlier call, tasks_dir()/jobs_dir() do not create subdirectories for a NEW KF_CODE_DATA_DIR value → NotFound. Also defeats the thread-local DataDirGuard isolation (first env-override wins globally) — the root cause of the EnvGuard-vs-DataDirGuard test races in task/persist.rs, tui/commands/tasks.rs, adapters/auth.rs (kimi-bugs). Fix: track created dirs in a Mutex<HashSet<PathBuf>> (create each distinct path once) instead of OnceLock; migrate the racing tests to DataDirGuard.

Source: multi-model audit vetting 2026-08-27 (mm-bugs.md, ds-bugs.md, kimi-bugs.md,
sonnet-bugs.md, gpt-bugs.md). Top-severity claims verified against the code at
dbfd8bb0 before filing.
