# WO 47 — ensure_private_data_dir OnceLock caches the first path globally — variable data dirs break

## Status: Done (code) — flake-verification caveat below

## Outcome

- `ensure_private_data_dir` now tracks created paths in a
  `OnceLock<Mutex<HashSet<PathBuf>>>`: each DISTINCT path is created + chmod
  0o700 exactly once; a path only enters the set after `create_dir_all`
  succeeds, so a deleted tempdir is re-created on the next call. A new
  `KF_CODE_DATA_DIR` value (or `DataDirGuard` override) now actually gets its
  `tasks/`/`jobs/` subdirs — the NotFound class is gone.
- `src/tools/task/persist.rs` tests: `env_guard_tmp()` → `data_dir_tmp()`
  (`DataDirGuard`, thread-local; no env mutation). Safe because the persist
  worker is a `tokio::spawn` on the same current_thread test runtime.
- `src/tui/commands/tasks.rs` tests: all 7 `EnvGuard("KF_CODE_DATA_DIR")`
  sites → `DataDirGuard`. `tasks_dir_respects_env_override` renamed
  `tasks_dir_respects_data_dir_override` (it now exercises the override, not
  the env var; the env path stays covered by
  `session::data_dir_respects_env_override` under the shared test lock).
- `src/adapters/auth.rs` tests: module-local `static ENV_LOCK:
  std::sync::Mutex<()>` serializes the `*_API_KEY` env mutations (these race
  provider env vars, not the data dir — per WO, lock chosen over unique key
  names to keep realistic provider names).

## Flake-verification caveat (honesty over claim)

`same_ms_double_spawn_gets_distinct_temp_dirs` /
`same_ms_double_spawn_gets_distinct_worktrees` do NOT route through
`ensure_private_data_dir` at all — `create_task_temp_dir` /
`WorktreeSession::create` use `std::env::temp_dir()` directly, and each
nextest test runs in its own process (fresh OnceLock). Their residual flake
is a 10s inner readiness deadline starved when ~50 parallel test processes
oversubscribe 8 cores (load avg 43 with sibling worktree agents' cargos
running). Observed: PASS solo and in full-suite run 1 (4781/4781); FAIL in
an earlier 51-test filtered run and full-suite run 2 under peak load. The
OnceLock fix removes the env-race flake class for the persist/tasks suites;
the same_ms pair needs its own remedy (deadline bump or a nextest per-test
slow-timeout override — follow-up filed in state.md).

## Problem

HIGH — explains multiple known test flakes. src/session/mod.rs:73-90 uses a process-global OnceLock: the closure runs once with the FIRST dir and never re-executes. After any earlier call, tasks_dir()/jobs_dir() do not create subdirectories for a NEW KF_CODE_DATA_DIR value → NotFound. Also defeats the thread-local DataDirGuard isolation (first env-override wins globally) — the root cause of the EnvGuard-vs-DataDirGuard test races in task/persist.rs, tui/commands/tasks.rs, adapters/auth.rs (kimi-bugs). Fix: track created dirs in a Mutex<HashSet<PathBuf>> (create each distinct path once) instead of OnceLock; migrate the racing tests to DataDirGuard.

Source: multi-model audit vetting 2026-08-27 (mm-bugs.md, ds-bugs.md, kimi-bugs.md,
sonnet-bugs.md, gpt-bugs.md). Top-severity claims verified against the code at
dbfd8bb0 before filing.
