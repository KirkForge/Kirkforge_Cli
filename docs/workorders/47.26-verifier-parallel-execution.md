# WO 47 — Verifiers run sequentially per turn (up to 7 min) + sync preamble reads + unbounded verdict cache

## Status: Planned

## Problem

HIGH perf. (1) VerifierHandler::verify_event runs 14 verifiers SEQUENTIALLY (mm-H22) — worst case ~7min/turn when tools are slow. They're independent — run them concurrently (join_all / JoinSet) bounded by a small semaphore. (2) build_stream_preamble does sync std::fs::read_to_string for up to 50 files per turn (mm-H23) — move to spawn_blocking or batch. (3) verifier_cache is an unbounded HashMap keyed by (PathBuf, u64) (mm-H26) — add a cap with simple eviction.

Source: multi-model audit vetting 2026-08-27 (mm-bugs.md, ds-bugs.md, kimi-bugs.md,
sonnet-bugs.md, gpt-bugs.md). Top-severity claims verified against the code at
dbfd8bb0 before filing.

## Root cause

See Problem — per-site. Cross-cutting theme: invariants enforced at one layer
(pre_run, session daemon) instead of the component that owns the operation;
and WO fixes applied at one site of a duplicated pattern.

## Approach

Read the Problem section. Implement the minimal correct fix. Where a fix
closes a class (scrub, gating, anchoring), grep for sibling sites of the same
pattern before considering it done.
