# WO 47 — HTTP MCP bearer token silently ignored + EventBus buffer identity collision

## Status: Done

Both defects fixed on `wo/wo47.28`:

1. `http.rs`: `connect` builds `Authorization: Bearer <token>` once when
   `bearer_token` is non-empty and threads it into the SSE reader and poster
   tasks; `open_sse_stream` and `post_request` attach it per-request,
   mirroring the `mcp-session-id`/`last-event-id` wiring. Omitted when the
   token is empty. Three new tests cover send/omit on POST and send on GET.
2. `event_bus.rs`: `State.buffer` now stores `(identity_key, Event)`; the
   post-handler removal matches the same hash the idempotency cache uses.
   Regression test parks one stream's handler and asserts a same-
   sequence+kind event from another stream removes only its own entry.

## Problem

MEDIUM. (1) src/session/mcp_client/http.rs:55-70 — McpServerConfig.bearer_token is parsed but never attached as an Authorization header; the client calls the remote MCP server unauthenticated. Fix: add `Authorization: Bearer <token>` to the SSE GET and POST when non-empty. (2) event_bus.rs emit removes the in-flight event by (sequence, kind) only, but identity/dedup uses (kind, stream_id, sequence, timestamp, value) — two streams sharing sequence+kind can remove each other's entry (GPT #6, mm P3). Fix: remove by the same identity hash used for idempotency.
