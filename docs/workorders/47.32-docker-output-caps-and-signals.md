# WO 47 — Docker bash path: unbounded output buffering + timeout/signal codes conflated

## Status: Done

## Problem

MEDIUM. (1) src/tools/bash.rs:203-212 — docker path uses read_to_end into unbounded Vecs, bypassing MAX_BASH_OUTPUT_BYTES the non-docker path enforces; a runaway container command OOMs the process. Fix: drain_capped(stdout, MAX_BASH_OUTPUT_BYTES) + cap_to_string (as run_shell_with_token does). (2) bash.rs docker timeout/cancel branches conflate exit codes — a timeout-killed container reports generic failure, not timeout (mm-H18).

## Done

Two gated commits on `wo/wo47.32` (no merge/push per workorder):

1. `a117c91d` — defect 1: both container streams now drain through
   `drain_capped(stream, MAX_BASH_OUTPUT_BYTES)` + `cap_to_string`
   (same pattern as `run_shell_with_token` and workflow bash); joined
   via `join_capped_drain` (join/io failure → empty capture, same
   semantics as the old unwrap-or-default chain).
2. `2031ee7f` — defect 2 (mm-H18): the timeout branch no longer returns
   `ShellError::Cancelled`; it kills, joins the capped drains under the
   same 1s zombie ceiling, and returns `docker_timeout_result(...)` —
   exit code 9 + the `[timed out after N seconds]` stdout marker, the
   exact convention the non-docker path emits — which `Bash::run`'s
   existing `is_timeout_marker` branch maps to `ToolError::Timeout
   { after_secs }` with zero tool-layer changes. Unit test
   `docker_timeout_result_is_timeout_marker_shaped` pins the marker
   shape, truncation marker, and end-to-end detector recognition.

Untestable without a Docker daemon (disclosed): the post-spawn wiring
itself (spawn → drain → join). Precedent: this file's real-Docker smoke
test is `#[ignore]`d; the pure helper closes the runnable-check gap.
`drain_capped`/`cap_to_string`/`is_timeout_marker` behavior is unit-
tested in `bash_runner`.
