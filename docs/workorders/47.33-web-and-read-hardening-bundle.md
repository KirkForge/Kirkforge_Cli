## Problem

MEDIUM bundle (6 items). (1) web_fetch: '::' (IPv6 unspecified) not classified internal (GPT #11). (2) web_fetch DNS pinning fails OPEN if the pinned-client construction errors (GPT #10) — fail closed. (3) web_fetch body cap is a fixed 1MiB, ignores Config max_tool_result_chars (mm-H29). ## Done

All 6 items, one commit on `wo/wo47.33` (not merged/pushed — parallel-wave
worktree):

1. `is_internal_addr` V6 branch now checks `v6.is_unspecified()` — `::`
   classified internal, matching the V4 `0.0.0.0` rule. Tests:
   `rejects_ipv6_unspecified_literal`, extended
   `host_is_literal_internal_ip_internal_v6_is_true`.
2. `resolve_and_pin_dns` pinned-client `.build()` failure now `.map_err(|_|
   ())?` — deny (fail closed), no unpinned fallback. Sibling site closed:
   `fallback_client()` (used by `WebFetch::new` and tests) now keeps
   `redirect::none()` so a builder fallback can't silently re-enable
   redirect-following.
3. Tool-local `DEFAULT_MAX_TOOL_RESULT_CHARS` (4_000) truncation deleted —
   the executor's config-driven `truncate_tool_output` (turn.rs, applied to
   every tool outcome with `Config.tools.max_tool_result_chars`) is the
   single source of truth. `MAX_BODY_BYTES` (1 MiB) stays as the
   transport/memory cap.
4. `ReadFile::run` streams via `BufReader::read_until(b'\n')`, retaining
   only the `[offset, offset+limit)` window; whole-file raw bytes kept only
   while `offset == 0 && lines_seen < limit` so the whole-file display stays
   byte-exact (CRLF + trailing newline pinned by test). Per-chunk UTF-8
   validation preserves the old `read_to_string` error behavior; total byte
   count tracked in-loop for the minify threshold/header. Tests:
   `deep_offset_window_returns_correct_lines`,
   `whole_file_read_preserves_crlf_and_trailing_newline`.
5. evaluate() SSRF: Rust-side static gate denies expressions referencing
   high-signal internal-host literals (localhost / 127.0.0.1 / 0.0.0.0 /
   ::1 / 169.254. / 192.168. / metadata.google.internal); JS preamble
   extended to WebSocket / EventSource / sendBeacon. Ceiling (documented on
   the const): same-origin iframe `contentWindow` laundering and `location`
   navigation remain — upgrade path CDP request interception. Tests:
   `evaluate_rejects_loopback_reference`,
   `session_evaluate_rejects_loopback_reference`,
   `evaluate_allows_benign_expression`.
6. `scan_files` reads at most `MAX_SCAN_BYTES` (1 MiB) per file via
   `BufReader::take`; oversized files scan the truncated prefix. Ceiling
   pinned by test (`pattern_beyond_scan_cap_is_not_reported`) + const
   comment. Test: `oversized_file_scans_prefix`.
