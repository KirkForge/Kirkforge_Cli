# WO 47 — Untrusted-content delimiters for tool output (prompt-injection defense) + template push_value hardening

## Status: Planned

## Problem

MEDIUM. (1) web_fetch/web_search/read_file return untrusted content verbatim into the model's next-turn context (DS-M5) — a hostile page embedding 'Ignore your system prompt... rm -rf...' is treated as instructions, steering to the bash tool. Defense-in-depth: wrap untrusted content in visible <untrusted_content>...</untrusted_content> delimiters + add an explicit data-not-instructions rule to the system prompt. (2) template.rs push_value (136-141) emits substitutions unescaped — no user-controllable value flows through {{var}} today, but a future addition re-injects model output. Cheap hardening: length cap 1024 + reject control characters in push_value (mm-H3).

Source: multi-model audit vetting 2026-08-27 (mm-bugs.md, ds-bugs.md, kimi-bugs.md,
sonnet-bugs.md, gpt-bugs.md). Top-severity claims verified against the code at
dbfd8bb0 before filing.

## Root cause

See Problem — per-site. Cross-cutting theme: invariants enforced at one layer
(pre_run, session daemon) instead of the component that owns the operation;
and WO fixes applied at one site of a duplicated pattern.
