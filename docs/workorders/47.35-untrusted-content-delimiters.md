# WO 47 — Untrusted-content delimiters for tool output (prompt-injection defense) + template push_value hardening

## Status: Done

## Problem

MEDIUM. (1) web_fetch/web_search/read_file return untrusted content verbatim into the model's next-turn context (DS-M5) — a hostile page embedding 'Ignore your system prompt... rm -rf...' is treated as instructions, steering to the bash tool. Defense-in-depth: wrap untrusted content in visible <untrusted_content>...</untrusted_content> delimiters + add an explicit data-not-instructions rule to the system prompt. (2) template.rs push_value (136-141) emits substitutions unescaped — no user-controllable value flows through {{var}} today, but a future addition re-injects model output. Cheap hardening: length cap 1024 + reject control characters in push_value (mm-H3).

Source: multi-model audit vetting 2026-08-27 (mm-bugs.md, ds-bugs.md, kimi-bugs.md,
sonnet-bugs.md, gpt-bugs.md). Top-severity claims verified against the code at
dbfd8bb0 before filing.

## Root cause

See Problem — per-site. Cross-cutting theme: invariants enforced at one layer
(pre_run, session daemon) instead of the component that owns the operation;
and WO fixes applied at one site of a duplicated pattern.

## Approach

Read the Problem section. Implement the minimal correct fix. Where a fix
closes a class (scrub, gating, anchoring), grep for sibling sites of the same
pattern before considering it done.

## Done

Two commits on `wo/wo47.35` (not merged/pushed):

1. `ba9e0ae1` — `wrap_untrusted` helper (web_fetch.rs, pub(crate), shared by
   all three tools) wraps the Success content of web_fetch + web_search and
   the FileContent content of read_file in `<untrusted_content>` /
   `</untrusted_content>` delimiters. read_file's whole display (header +
   body) rides inside the delimiters — conservative; splitting the header
   out would double the diff for no security gain. The empty-file marker is
   tool-generated and stays unwrapped. prompts/system.hbs gains one
   Guidelines sentence pinning the data-not-instructions contract; both
   golden constants in template.rs re-captured per the template-edit
   contract (inserted text is tag-free literal; render derivable exactly).
   web_search's wrap has no direct test (success path needs live Brave
   HTTP); helper unit-covered via web_fetch/read_file integration tests.
2. `426a0eff` — push_value hardening: values over 1024 chars or containing
   control chars (newlines included) are dropped, not emitted; ponytail:
   ceiling comment documents it. No production template value (model name,
   tool names, bools) can trip the guard.
