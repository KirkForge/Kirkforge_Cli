# WO 47.4 — Fold kf-routing + kf-memory-store into kf-orchestrator (0 direct src/ refs)

## Status: Done

## Problem

kf-routing and kf-memory-store have 0 direct src/ references — only kf-orchestrator consumes them. The /workflow→orchestrator→memory-store→routing chain is 12.1K LOC across 4 crates. Folding routing+memory into orchestrator (or a single kf-orchestration crate) removes 2 workspace members (~2K lines of crate boundary/boilerplate). kf-plugin-sdk similarly has no external consumer — fold into kf-plugin-host.

Source: post-WO-46 size audit (kf-code-review.md, 2026-08-27). The codebase is
~110K production lines vs a ~30K lean-agent baseline; this WO is part of the
"Lean KirkForge" convergence toward ~85-88K.

## Root cause

Accumulation across WO series — features added per-WO with default features
and no size gate at add/remove time; crate boundaries drawn early never
revisited; process artifacts (tests, docs, dev tooling) counted as codebase.

## Approach

Read the Problem section. Implement the minimal correct reduction. Where a WO
deletes code, verify no production consumer breaks (grep + cargo check).
Where it moves code, keep public APIs stable or update all consumers.

## Files

crates/kf-routing/**, crates/kf-memory-store/**, crates/kf-orchestrator/**, crates/kf-plugin-sdk/**

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check` + `cargo check --workspace --all-targets`. For deletions:
`git grep` proves zero production references before removal.

## Done

Branch `wo/wo47.4` (not merged/pushed). Workspace 13 → 10 members.

- **kf-routing → kf-orchestrator `routing` module** (git mv, history
  preserved; `routing/routing.rs` renamed `engine.rs` to satisfy
  `clippy::module_inception`, matching the original `routing-engine.ts`
  port). lib.rs re-exports preserved, so the orchestrator's public surface
  (`kf_orchestrator::DelegationMode/OverallVerdict/TaskProfile`, consumed
  by src/session/executor_adapter.rs) is unchanged. proptest regressions
  file moved with the module.
- **kf-memory-store → kf-orchestrator `memory` module** (store/time/types
  + adapters/). Its tests/integration.rs is now
  crates/kf-orchestrator/tests/memory_store.rs. rusqlite/libc/windows-sys
  moved into kf-orchestrator's Cargo.toml (same versions, target-gated
  identically).
- **kf-plugin-sdk → kf-plugin-host `sdk` module** with the SDK surface
  re-exported at the host root (`kf_plugin_host::{Plugin, Capability,
  TrustTier, ...}`). The WO's "no external consumer" premise was WRONG:
  src/ had ~60 `kf_plugin_sdk::` refs across 14 files. A cargo dependency
  rename (`kf-plugin-sdk = { package = "kf-plugin-host" }`) was attempted
  and REJECTED by cargo ("depends on crate kf-plugin-host multiple times
  with different names" — kf-code also depends on the host directly), so
  the refs were mechanically renamed `kf_plugin_sdk::` →
  `kf_plugin_host::` in the same commit (compile-verified by
  `cargo check --workspace --all-targets`).
- Cross-layer refs updated: root Cargo.toml (members/default-members/
  workspace.deps + comments), scripts/changed-packages.sh (reverse-dep
  table now has zero edges), scripts/run-mutants.sh + ci-nightly.yml
  mutants path, docs/TECHNICAL.md (diagram, satellites section, rusqlite
  chain note, both crate tables), two path comments in src/shared/.
- Gate (fast, per worker prompt): `cargo check --workspace --all-targets`
  clean; `cargo clippy -p kf-orchestrator -p kf-plugin-host -p kf-code
  --all-targets -- -D warnings` clean; `cargo test -p kf-orchestrator -p
  kf-plugin-host` 330/330 (205 lib incl. moved routing+memory unit tests,
  44 memory_store integration, 81 plugin-host incl. sdk tests);
  `adr_xref_drift` green; `cargo fmt --check` clean.
