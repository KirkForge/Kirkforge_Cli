# WO 47.7 — MCP transport trait (every op exists 3×: enum + stdio_* + http)

## Status: Done

## Problem

McpClient has every operation in triplicate: the enum dispatch + a stdio_* method + an http method. A transport trait (Stdio + Http impls) collapses the duplication (~180 lines) and makes future transports (SSE, WebSocket) single-impl.

Source: post-WO-46 size audit (kf-code-review.md, 2026-08-27). The codebase is
~110K production lines vs a ~30K lean-agent baseline; this WO is part of the
"Lean KirkForge" convergence toward ~85-88K.

## Root cause

Accumulation across WO series — features added per-WO with default features
and no size gate at add/remove time; crate boundaries drawn early never
revisited; process artifacts (tests, docs, dev tooling) counted as codebase.

## Approach

Read the Problem section. Implement the minimal correct reduction. Where a WO
deletes code, verify no production consumer breaks (grep + cargo check).
Where it moves code, keep public APIs stable or update all consumers.

## Files

src/session/mcp_client/**

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check` + `cargo check --workspace --all-targets`. For deletions:
`git grep` proves zero production references before removal.

## Done

`McpClient` (enum Stdio|Http) → struct wrapping `Box<dyn McpTransport>`.
The private `McpTransport` trait (mod.rs) carries only the transport
primitives — `server_name`, `is_alive`, `send_request`, `send_notification`,
`set_sampling` (default no-op), `pending` (test-only), `disconnect`
(test-only) — with manually pin-boxed futures (dyn-compatible, no
async-trait dep). Every MCP operation (`tools/list`, `tools/call`,
`resources/*`, `prompts/*`) is now a single shared impl on `McpClient`
routing through `send_request`; the initialize handshake (duplicated in
both connect paths) collapsed into one `initialize_handshake` helper
(capabilities differ: stdio advertises `roots`, HTTP does not). Each
transport owns its `impl Drop` (moved out of the enum's match). The
HTTP `call_tool` now uses the shared, richer
`tool_result_from_content_blocks` (image/audio/resource placeholders
instead of a raw JSON dump for non-text blocks) — deliberate unification
on the stdio behavior; the 6 http-only tests of the deleted simpler
helper were removed (the shared helper's tests in mod.rs cover the
paths). Net −310 lines (927 deletions / 617 insertions across mod.rs +
http.rs). manager.rs/spawn.rs/error.rs untouched — the wrapper API
(connect/is_alive/set_sampling/call_tool/list_*/read_resource/get_prompt)
is unchanged. Gate: `cargo check --workspace --all-targets` clean,
`cargo clippy -p kf-code --all-targets -- -D warnings` clean,
`cargo nextest run -p kf-code --lib mcp_client` 81/81, `cargo fmt
--check` clean (fast-gate scope per worker prompt; full suites not run).
