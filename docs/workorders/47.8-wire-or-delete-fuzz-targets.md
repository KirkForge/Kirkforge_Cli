# WO 47.8 — Wire or delete the 9 fuzz targets (100% unwired dead weight)

## Status: Done

## Problem

9 fuzz target files exist in fuzz/ but only 5 are wired in Cargo.toml, and NONE run in CI or any script. Either wire them into a nightly fuzz job (cargo-fuzz with a time budget) or delete the unwired ones. Dead weight that signals testing the codebase doesn't have.

Source: post-WO-46 size audit (kf-code-review.md, 2026-08-27). The codebase is
~110K production lines vs a ~30K lean-agent baseline; this WO is part of the
"Lean KirkForge" convergence toward ~85-88K.

## Root cause

Accumulation across WO series — features added per-WO with default features
and no size gate at add/remove time; crate boundaries drawn early never
revisited; process artifacts (tests, docs, dev tooling) counted as codebase.

## Approach

Read the Problem section. Implement the minimal correct reduction. Where a WO
deletes code, verify no production consumer breaks (grep + cargo check).
Where it moves code, keep public APIs stable or update all consumers.

## Files

fuzz/**, .github/workflows/ci-nightly.yml

## Gate

`scripts/test-fast.sh` + `cargo clippy --all-targets -- -D warnings` +
`cargo fmt --check` + `cargo check --workspace --all-targets`. For deletions:
`git grep` proves zero production references before removal.

## Done

Deleted the entire `fuzz/` directory (9 target files + `Cargo.toml` + `Cargo.lock`). Decision: delete, not wire. The 9 targets were 100% unwired dead weight — `fuzz/` is its own `[workspace]` (excluded from `cargo check --workspace`), only 5 of 9 targets were even registered in `fuzz/Cargo.toml` (4 orphaned files), and zero CI jobs or scripts ran `cargo-fuzz`. A nightly job wiring targets that have caught nothing in their multi-year existence adds CI cost for no signal; the owner can re-add fuzzing later with a real integration if it earns its place.

No production consumers: `fuzz/` is not a workspace member (root `Cargo.toml` lists no `fuzz` path), and the only non-doc reference was a path-skip comment in `scripts/check-cov-regression.sh:86` (`fuzz/` listed as a path to skip — a no-op now that the dir is gone). Doc references in `docs/archive/workorders/` are historical WOs (24.7, 21.9, 20.8.0) and are left as-is.
