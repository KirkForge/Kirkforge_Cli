# WO 48 — minify_shell drops heredoc body lines starting # — disk write-back deletes them

## Status: Done

## Problem

P1. src/shared/minify/lang.rs:867 — the shell minifier is heredoc-blind: a heredoc body line starting with # (comments in configs, cron entries) is stripped as a comment. Verified by compiling the production fn: read_file→envelope→write_file round-trip DELETES the lines on disk. Disclosed as out-of-scope by 48.1's agent but never tracked. Fix: track heredoc state (<<EOF ... EOF delimiter matching); only strip # outside heredocs and outside strings.

## Done

Branch `wo48.11`, commit `fix(minify): shell heredoc bodies survive minify_shell`.

- `shell_heredoc_opens` scans command lines quote-aware for `<<DELIM` /
  `<<-DELIM` / `<<'DELIM'` / `<<"DELIM"` (space after `<<` allowed, `<<<`
  here-strings and word-start `#` comment tails inert, `a#b<<EOF` still opens).
- `minify_shell` keeps a FIFO of open heredocs; body lines pass through
  verbatim (no comment strip, no blank collapse) until the terminator
  (exact line match; tab-stripped match for `<<-`). Blank-line collapse
  moved inline so bodies round-trip byte-exact.
- Fails safe: a never-matching terminator (e.g. `<<$VAR`) treats the rest of
  the file as body — over-retention, never deletion.
