# WO 48 — minify_js_like truncates at // inside regex literals — js/ts corruption on the disk write-back chain

## Status: Planned

## Problem

P1. src/shared/minify/lang.rs:709 — the // comment stripper is regex-literal-blind: /https?:\/\// truncates at the first // inside the regex, eating the newline. 48.1's sibling-grep claimed js was string-aware — it is, for quotes, but not regex literals. Affects js/ts on the same read_file→edit→write disk chain. Fix: track regex-literal state (a / that follows an operator/(-position opens a regex; division context vs regex context), or simpler: require // to be preceded by whitespace/start/([=:,;! and not be inside a string or regex.

Source: post-WO-48 sweep audit (kf-code-review.md, 2026-08-28, HEAD 9f498f2b).

See Problem. Theme: per-language minifier patches instead of one lexer pass;
gate conditions checked at one site but not siblings; nightly CI never validated.
