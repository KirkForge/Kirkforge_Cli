## Problem

P2. src/shared/minify/lang.rs (ruby arm) — same class as 48.11/48.12: ruby # comments stripped inside heredocs and inside %-delimited strings; =begin/=end block comments not handled. Fix together with 48.11's heredoc state (share the scanner) + ruby =begin/=end awareness.

Source: post-WO-48 sweep audit (kf-code-review.md, 2026-08-28, HEAD 9f498f2b).

src/shared/minify/lang.rs

## Done

Replaced the stateless line stripper with the 48.11-style stateful line
loop in `minify_ruby`: FIFO heredoc queue (`<<~`/`<<-` indent-tolerant,
`<<'ID'`/`<<"ID"` quoted, `<<<` ignored, terminator = trimmed/column-0
match, body verbatim), %-literal tracking across lines (`%q(...)`,
`%w[...]`, `%{...}`, `%!...!` — bracket delimiters nest, `\` escapes,
opened only when `%` sits at term position so modulo stays modulo), and
column-0 `=begin`/`=end` block-comment stripping. One `ruby_scan_code`
walks each code line (quotes → %-literal → heredoc/percent arms; first
`#` outside literals ends the scan). Over-opens (e.g. `x <<y` shift)
only skip stripping — content is never deleted (48.11's safe direction).
Magic comments (`# encoding`, `# frozen_string_literal`) still kept;
real comments still stripped.

Tests: heredoc `#` bodies survive (incl. `<<~`/`<<-'`), multi-line `%q`
with nested brackets survives, modulo doesn't eat the file, `=begin`/
`=end` stripped, envelope round-trip for heredoc + `%q`.

Fast gates green: `cargo check --workspace --all-targets`,
`cargo clippy -p kf-code --all-targets -- -D warnings`,
`cargo test -p kf-code --lib shared::minify` (85/85, 5 new),
`cargo fmt --check`.
