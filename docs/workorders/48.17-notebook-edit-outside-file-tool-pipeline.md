Audit finding (not fixed here, disclosed): `PathGuard::check_write`
returns the RAW literal as its "resolved" path
(`GuardVerdict::Allowed(path.to_path_buf())`, access/mod.rs) — the
sandbox-branch canonicalization is used only for containment. So for
ALL write-class tools (write_file/edit_file/notebook_edit) the
Phase-1 "resolved" path == the model-supplied literal, the hook
substitution is an identity, and the Phase-2.5 symlink walk therefore
denies ANY symlinked parent component on a write path. Reads
canonicalize (`check_traversal` returns the canonical path), so the
WO 38.1 "body opens the resolved path" contract is only fully realized
for read tools. Making `check_write` return the canonical path is a
cross-tool behavior change that needs its own WO (candidate: 48.x).
