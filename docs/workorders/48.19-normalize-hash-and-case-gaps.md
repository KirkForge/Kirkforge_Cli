# WO 48 — normalize_for_safety mid-word # truncation + permission deny-glob case mismatch

## Status: Done

## Problem

P2. src/shared/bash_safety.rs normalize_for_safety + src/shared/permission.rs deny path. (1) A mid-word # in a token truncates it (foo#bar → foo), blinding the normalized-only gates (redirect/tee/deny-list scans) to the real token. (2) The deny glob compares a case-sensitive pattern against the lowercased value — uppercase deny rules are silently dead. Fix: (1) only treat # as comment-start at whitespace/start-of-token in the normalizer (it is a normalizer, not a stripper — but verify each consumer); (2) lowercase the deny pattern in the glob comparison (mirror 44.21's prefix handling).

Source: post-WO-48 sweep audit (kf-code-review.md, 2026-08-28, HEAD 9f498f2b).

## Root cause

See Problem. Theme: per-language minifier patches instead of one lexer pass;
gate conditions checked at one site but not siblings; nightly CI never validated.

Read the Problem section. Minimal correct fix. Grep for sibling sites.

## Done

1. `normalize_for_safety` (src/shared/bash_safety.rs): `#` now breaks only
   at start of input or after whitespace (bash word-start), so `foo#bar`
   survives intact and nothing after a mid-word `#` is dropped. The
   redirect/tee scans and the step-8 deny-list token scan see the real
   tokens again. Approach: normalizer fix (the conservative path) — the
   full permission + bash_safety proptests passed unchanged (410/0), so the
   old mid-word truncation was NOT load-bearing. Pins:
   `normalize_keeps_mid_word_hash`,
   `redirects_to_dangerous_path_sees_past_mid_word_hash`,
   `check_bash_command_str_blocks_denied_path_after_mid_word_hash`.
   Commit `7f812376`.
2. `deny_command_matches` (src/shared/permission.rs): the glob branch now
   compares `pattern_lower` (star-promoted + lowercased) against the
   lowercased clause — uppercase deny rules are no longer silently dead.
   Mirrored in `rule_subsumes`' promotion surface (the advisory model of
   that runtime surface, same as 44.21's prefix surface). Allow/Ask
   patterns stay case-sensitive (documented, fail-closed to Ask). Pins:
   `test_evaluate_deny_command_uppercase_pattern_blocks` (deny `RM*`
   blocks `rm -rf /` variants),
   `shadow_deny_uppercase_pattern_shadows_lowercase_allow`.
   Note: `#` after a shell metacharacter without whitespace (`;#c`) is kept
   in the normalized string rather than treated as a comment — more text in
   the normalized form fails closed (deny/prefix scans see more), so it is
   the safe side of the conservative fix.
   Fast gates: workspace check --all-targets, clippy -p kf-code -D
   warnings, shared::permission (106/0) + shared::bash_safety + proptest
   suites (410/0), fmt — all green.
