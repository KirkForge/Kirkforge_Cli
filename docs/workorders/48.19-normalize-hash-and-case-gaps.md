# WO 48 — normalize_for_safety mid-word # truncation + permission deny-glob case mismatch

## Status: Planned

## Problem

P2. src/shared/bash_safety.rs normalize_for_safety + src/shared/permission.rs deny path. (1) A mid-word # in a token truncates it (foo#bar → foo), blinding the normalized-only gates (redirect/tee/deny-list scans) to the real token. (2) The deny glob compares a case-sensitive pattern against the lowercased value — uppercase deny rules are silently dead. Fix: (1) only treat # as comment-start at whitespace/start-of-token in the normalizer (it is a normalizer, not a stripper — but verify each consumer); (2) lowercase the deny pattern in the glob comparison (mirror 44.21's prefix handling).

Source: post-WO-48 sweep audit (kf-code-review.md, 2026-08-28, HEAD 9f498f2b).

See Problem. Theme: per-language minifier patches instead of one lexer pass;
gate conditions checked at one site but not siblings; nightly CI never validated.
