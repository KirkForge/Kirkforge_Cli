# WO 48 — Pre-tool hooks run twice per file-tool call — second run is post-mutation (WO 43.30 tail)

## Status: Done

## Problem

P1. src/session/executor/turn.rs:717-750 re-invokes pre-tool-{name} in record_tool_result (Phase 3, AFTER the write/edit executed in Phase 2.5) on top of the Phase-1 gate (pre_run.rs:303). A divergent second evaluation denies recording while disk already changed — the exact contract WO 43.30 closed, surviving in the second-run window. Plus doubled hook side-effects/latency every file call. Fix: one pre-tool evaluation per call — either drop the Phase-3 run or make it a no-op-when-already-gated; document the single-gate contract.

Source: post-WO-47 baseline audit (kf-code-review.md, 2026-08-28, HEAD e4725bd6).
