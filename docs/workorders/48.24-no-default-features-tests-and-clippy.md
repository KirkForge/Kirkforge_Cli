Disclosed follow-up from WO 48.21 (count_tokens minimal-build work left these

build (`cargo build --release --no-default-features`) as supported.

## Problem

Verified by reproduction on the branch point (`ae7dbd57`), not trusted from
the ticket:

1. `cargo clippy --workspace --lib --no-default-features -- -D warnings` fails
   with 4 errors:
   - `src/session/skills.rs:174` — `unused_mut`: `register_folded_skills`
     declares `let mut count = 0;` but the only mutation (`count += 1`) is
     inside a `#[cfg(feature = "kf-plugin-tools")]` block, which
     no-default-features compiles out.
   - `src/session/executor/helpers/mod.rs:31` — `dead_code`: the
     `apply_budget_slice` wrapper. Both callers (turn.rs) sit inside
     `#[cfg(feature = "budget")]` blocks, so under no-default-features the
     wrapper has zero callers and its `not(budget)` pass-through arm is
     unreachable by construction.
   - `src/session/executor/turn.rs:748` and `:837` — `redundant_locals`: the
     `#[cfg(not(feature = "budget"))] let outcome = outcome;` placeholder
     rebinds. Under default features these lines are compiled out (why the
     default-build clippy gate never caught them); under no-default they are
     no-op rebindings of a binding that already exists in scope.
2. `cargo test --workspace --no-default-features` (without `--lib`) fails to
   compile **two** integration test files with E0432/E0433 —
   `tests/context_economics_test.rs` (named in the ticket) and
   `tests/budget_wiring_test.rs` (same disease, undisclosed in the ticket):
   un-gated imports of `kf_budget_core`, `kf_compress_core`,
   `kf_code::session::budget`, `kf_code::session::stratum`, plus
   `SessionStores` field refs (`budget`, `budget_store`, `stratum_store`)
   that only exist under the `budget`/`stratum` features.

## Approach

- `skills.rs`: restructure `register_folded_skills` to early-return from the
  gated block (`return 1`) and return `0` at the end — no `mut`, no cfg on
  the binding. Behavior identical under both configs.
- `helpers/mod.rs`: **delete** the `apply_budget_slice` wrapper rather than
  cfg-gate it. It was a pure 1:1 forwarder to
  `session::budget::apply_budget_slice` (identical signature —
  `SharedStore = Arc<dyn OffloadStore>`); its only reason to exist (a
  feature-neutral signature for un-gated callers) is dead because both call
  sites are already inside `#[cfg(feature = "budget")]`. The cfg choke point
  stays where it already is (the turn.rs call sites) — mirroring the WO 48.9
  one-choke-point pattern.
- `turn.rs`: the two call sites call
  `crate::session::budget::apply_budget_slice` directly; the two
  `#[cfg(not(feature = "budget"))] let outcome = outcome;` lines are deleted
  (the binding from the preceding line remains in scope and is used below).
- Tests: `#![cfg(all(feature = "budget", feature = "stratum"))]` at the top
  of both files (the `tests/e2e` inner-attribute pattern). Honest gate: both
  files exercise budget slicing / stratum listeners end-to-end; there is no
  meaningful subset to keep under no-default-features. Scope creep (disclosed
  per AGENTS rule 7): `tests/budget_wiring_test.rs` was not named in the WO
  scope but has the identical un-gated-import disease; fixing only
  `context_economics_test.rs` would leave `cargo test --workspace
  --no-default-features` still failing to compile.
