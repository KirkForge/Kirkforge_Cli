# WO 48 — Heredoc scanners resume ON the closing quote — second opener on same line invisible (shell + ruby)

## Status: Planned

## Problem

P1. src/shared/minify/lang.rs:1187 (shell) + :1041 (ruby) — shell_heredoc_opens resumes scanning ON the quote that closes a quoted delimiter and re-reads it as an OPENING quote, so any second heredoc opener later on the same line is invisible: diff <(cat <<'A') <(cat <<'B') → B's body comment-stripped → write-back deletes # lines. Ruby arm has the identical bug (foo(<<'A', <<'B')). Fix: one-token each — advance past the closing quote (i = j + 1 for quoted delims) so resume starts AFTER it.
