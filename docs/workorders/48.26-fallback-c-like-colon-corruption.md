# WO 48 — fallback_c_like inserts a space after every colon — std::cout becomes std: : cout on disk write-back

## Status: Done

## Problem

P1. src/shared/minify/expand.rs:362-375 — the fallback formatter's ':' arm inserts a space after EVERY colon; C/C++/Java have no external formatter arm, so every envelope write-back in those languages writes non-compiling code to disk (std::cout → std: : cout, use std::… → use std: : …). Untracked since expand.rs was created. Fix: only pad around :: used as a scope-resolution/namespace separator is hard to detect — simplest correct: don't pad after a colon unless followed by another colon (the :: case gets one space around the PAIR), and never pad a colon adjacent to identifier chars on the inside. Test: std::cout, use std::io, http:// in strings, ternary a ? b : c all round-trip byte-identical.

Source: Sweep 3 (kf-code-review.md, 2026-08-29, HEAD ae7dbd57).

## Done

- `':'` arm in `fallback_c_like` (src/shared/minify/expand.rs):
  - `::` pair emitted verbatim as one unit (no eat/pad) — `std::cout`, `use std::io`, `std :: cout` all round-trip.
  - Single `:` followed by a space: normalize to exactly one space (label intent, `case 1: break` round-trips; the old eat-then-maybe-readd lost the space for ident-glued colons).
  - Single `:` otherwise: pad only when the next char is not alphanumeric/`_` and not the existing `\n ; , ) }` exclusion set — collapsed ternaries (`a?b:c`) and type keys (`map[string]int`) stay glued.
- Tests: `fallback_c_like_colons_round_trip_byte_identical` (std::cout, http:// in string, ternary `cond ? a : b`, `case 1:`, `default:`), `fallback_c_like_rust_scope_resolution_round_trips` (`use std::io;`), `fallback_c_like_never_splits_double_colon`, `fallback_c_like_envelope_expansion_keeps_colons` (full minify→envelope→expand pipeline, cpp arm is deterministic — no external formatter).
- Trade-off: model-collapsed `case 1:break;` no longer gains a space (stays glued, still valid code). Correctness of round-trips beats that cosmetic padding.
