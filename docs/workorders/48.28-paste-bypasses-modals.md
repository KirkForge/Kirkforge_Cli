## Done

2026-08-29 (worktree `wo48.28`, branch `wo/wo48.28`). Both `Event::Paste`
arms in `dispatch_kb_events` (src/tui/mod.rs) now gate on
`modal_captures_keys(state)` — the same modal set that consume-all-gates

file completer / search mode are deliberately NOT gated — typing flows into
the input there, so paste may too. `apply_paste` itself unchanged.
Regression test `paste_while_modal_open_does_not_reach_input` drives the
real `dispatch_kb_events` router: paste under the picker and under the
help overlay never reaches the input buffer (and no flash), while the
no-modal case still inserts + flashes. gitnexus impact (dev index):
LOW — 1 direct caller (`run_event_loop`). Fast gates green (see commit).
