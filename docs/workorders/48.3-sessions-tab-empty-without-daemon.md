# WO 48 — WO 47.12 regression: Sessions tab shows 'No recent sessions' in default (daemon-less) config

## Status: Done

## Problem

P1 REGRESSION from 47.12. session_picker is only populated by daemon-push-driven refresh_sessions (tui/mod.rs:1121, daemon_events.rs:103); pre-47.12 the auto-started daemon fed it by side effect. open_overlay primes Jobs but not Sessions (keys/mod.rs:851). Fix: prime the sessions list from the on-disk session index (the same fallback 47.12 wired into daemon/client) when opening the Sessions tab.

## Done

2026-08-28, branch `wo/wo48.3`. Root cause: the three tab-switch sites in
`src/tui/keys/mod.rs` (`open_overlay`, command-palette Enter, F-key arm)
each primed Jobs cold-start (`jobs_dirty`) but none primed Sessions
(`sessions_dirty`), so `refresh_sessions` — which already falls back to the
on-disk session index via `try_list_recent` (WO 47.12) — never ran without
a daemon push. Fix: one shared `prime_overlay_cold_data(state, tab)` helper
called from all three sites, tripping `jobs_dirty`/`sessions_dirty` on cold
entry; the draw loop's existing dirty-flag handlers fetch. Startup picker
path (`run_session.rs:215`) already routed through `try_list_recent` — no
change needed. Test: `prime_overlay_cold_data_trips_sessions_and_jobs_flags`.
Gates: cargo check --workspace --all-targets, clippy -p kf-code --all-targets
-D warnings, targeted tui/daemon tests, fmt — all green.
