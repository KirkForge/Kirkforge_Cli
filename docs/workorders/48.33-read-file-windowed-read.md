# WO 48 — read_file scans to EOF even for offset=100000,limit=20 — O(file) cost for an O(window) request

## Status: Planned

## Problem

MEDIUM. src/tools/read_file.rs:93-146 — the streaming loop reads every line to EOF because offset-beyond-length detection and the offset>=raw_total check need raw_total. With max_read_size=0 (unlimited, API-permitted) an offset=900M request scans 900M+ bytes for 10 lines. FIX: when offset>0 and the file is seekable, skip N lines with a counting pass that DISCARDS (no buffering beyond one line) until offset reached — the memory is already bounded, so the win is stopping early when the window is filled AND offset is satisfied (no need for raw_total when the window completes: only the offset-beyond-EOF error needs it, and that can be detected by window-empty + EOF). Keep whole-file semantics for offset=0.
