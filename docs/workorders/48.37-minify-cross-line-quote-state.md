# WO 48 — minify shell/ruby have no cross-line quote state — multi-line string contents deleted on write-back

## Status: Planned

## Problem

P1. src/shared/minify/lang.rs — minify_shell and minify_ruby are line scanners with no cross-line string state: a multi-line "..."/'...' literal spanning lines loses #-leading body lines (treated as comments) and blank lines collapse — deleted on the default-on read→envelope→write-back chain. WO 48.11's own spec said 'outside strings' — the string half never shipped for these two languages (python/js got it in 48.1/48.12). Fix: carry quote state across lines in both scanners (the 48.1 string_char idiom, adapted to the FIFO heredoc structure). Tests: multi-line string with # lines round-trips (sh + rb); heredoc-inside-string and string-inside-heredoc both correct.

Source: Sweep 4 (kf-code-review.md, 2026-08-29, HEAD 357ac36e). 1 P1 (cross-line quote state — the 48.11 spec's unshipped half), 6 P2 + 1 CI-rung gap. Two TUI findings are REPRODUCED with probes in the sweep report.

## Root cause

Line-scanner patches without cross-line state; teardown paths not covered by Drop; feature combos without CI rungs.
