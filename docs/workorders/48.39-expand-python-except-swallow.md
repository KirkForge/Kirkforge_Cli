# WO 48.39 — fallback_python swallows code after except blocks; lone pass over-dedents (IndentationError); multi-line string interiors trimmed

## Status: Done

## Problem

P2. src/shared/minify/expand.rs `fallback_python` — the re-indent heuristic guesses block depth from statement names:

1. Code after an `except` body stays at except depth (no statement in the body ever decrements) — following top-level code gets written inside the except block (wrong code on disk via the envelope write-back chain).
2. A block ending in `return`/`pass` decrements depth, then `else:`/`except`/`finally` unconditionally pre-dedents again — the header lands one level too shallow → IndentationError on disk.
3. `line.trim()` + indent-prefix is applied to every line including multi-line string interiors — string contents get trimmed/re-indented (corruption on write-back).

Fix: replace the statement-name heuristic with block-opener tracking (def/if/elif/else/for/while/try/except/finally/with/class push depth when they end a line with `:`); dedent tokens (return/break/continue/pass) never change depth — only block structure does; leave multi-line string interiors verbatim (string-state tracking, same idiom as the minifiers).

## Root cause

The heuristic inferred Python block structure from keywords, but Python carries structure in indentation + block openers only. The minifier (`minify_python`) preserves the input's indentation verbatim, so the expander was throwing away the one authoritative signal (leading whitespace) and guessing instead.

## Approach

- Width stack of open block levels; pop while the line's leading-whitespace width is below the top (the dedent signal).
- Block openers (opener keyword + trailing `:` outside strings) arm a pending level, pushed from real width when present or synthetically when the model collapsed indentation (the collapsed-input case the old heuristic aimed at).
- Continuation headers (else/elif/except/finally) pop one extra level only when the width did not already dedent (collapsed input).
- Triple-quoted string state carried across lines (escape-aware, `#`-comment-aware — same idiom as `minify_python`); interior lines emitted verbatim, trailing spaces preserved on lines that continue a triple literal.
- Ceiling (ponytail:): widths compared relatively, output normalized to 4-space units — paren-aligned continuation lines are re-normalized; fully-collapsed input cannot dedent non-header blocks (no signal exists). Upgrade path: real tokenizer.
