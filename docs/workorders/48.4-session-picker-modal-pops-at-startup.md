# WO 48 — daemon ThreadsChanged opens the session-picker MODAL at every TUI startup

## Status: Done

## Problem

P1. daemon registration/Touch/claim-release push ThreadsChanged (daemon/server.rs:421,524,338) → refresh_sessions sets session_picker=Some (fork.rs:234) → renders as the FULL-SCREEN 'Resume a recent session' modal capturing keys (tui/mod.rs:1412, keys/mod.rs:1036). With the daemon on, the modal pops at every startup; Enter can silently resume a different session. Fix: background refresh should update the tab's data, not open the modal; modal opens only on explicit user action (/resume, picker).

Source: post-WO-47 baseline audit (kf-code-review.md, 2026-08-28, HEAD e4725bd6).

## Done

Branch `wo/wo48.4`, merge commit pending. Both problems fixed:

**P1 — modal pops at startup.** Split the dual-purpose
`session_picker` field: a new data-only `SessionState::recent_sessions`
(`Vec<SessionEntry>`) is what background refresh writes
(`refresh_sessions`, fork.rs) and what the Sessions tab RECENT section
(tabs.rs) and the welcome screen (welcome.rs) render. The
`session_picker: Option<SessionPicker>` field is now modal-presentation
only and is set exclusively by `/resume` with no arguments (explicit user
action). The standalone pre-loop startup picker (`run_session_picker`,
main/run_session.rs) was already explicit — untouched. Sibling-site sweep:
grep of every `session_picker` consumer (render tui/mod.rs:1413, keys
keys/mod.rs, welcome, tabs, fork) — all updated or verified in-place.

**P2 — nav keys drop the modal.** `handle_session_picker_keys`
(keys/mod.rs) `take()`s the picker but returned `None` (without restoring)
for any key that was neither confirm nor cancel — so the first advertised
k/j/↑/↓ dropped the modal and leaked the key onward. Now the picker is
restored while still open; consumed keys stop propagation
(`Some(Ok(()))`), unconsumed keys fall through as before. Chose honoring
the advertised nav keys over shrinking the help text (smaller change,
better UX).

Regression tests: `refresh_sessions_updates_data_without_opening_picker`
(fork.rs), `session_picker_nav_keys_keep_modal_open` (keys/mod.rs);
welcome tests moved to the data field.

Gates (fast, per WO; full suites deferred to CI):
`cargo check --workspace --all-targets` clean; `cargo clippy -p kf-code
--all-targets -- -D warnings` clean; `cargo fmt --check` clean; targeted
tests 53 passed / 0 failed (session_picker 13, welcome+keys+fork 39,
refresh_sessions 1).
