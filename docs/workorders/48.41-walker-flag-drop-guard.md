# WO 48 — Walker cancel flag only set on one of three teardown paths — timeout/abort leaves walkers scanning

## Status: Done

## Problem

P2. src/session/executor/dispatch.rs:783 (tool timeout) + :446 (JoinHandle abort) drop the tool future before the select-arm store() runs — the 48.34 AtomicBool never flips, detached glob/grep walkers scan the whole tree past a reported Timeout. Fix: Drop guard on the flag (struct CancelFlag(Arc<AtomicBool>) with Drop setting it), created at walker spawn, so ALL teardown paths set it. Tests: timeout path sets the flag (simulate drop).

Source: Sweep 4 (kf-code-review.md, 2026-08-29, HEAD 357ac36e). 1 P1 (cross-line quote state — the 48.11 spec's unshipped half), 6 P2 + 1 CI-rung gap. Two TUI findings are REPRODUCED with probes in the sweep report.

## Done

`WalkerCancel(Arc<AtomicBool>)` drop guard (glob.rs, `pub(crate)`,
imported by grep.rs) — `impl Drop` stores `true` (Relaxed). Created beside
each walker spawn, owned by the tool `run()` future (bound as
`_walker_cancel`, never read, only dropped). ANY teardown flips the flag:
cancel-arm return, normal return, tool timeout
(`run_prepared_call`'s `tokio::time::timeout`), JoinHandle abort
(collect-loop `h.abort()`). The 48.34 explicit `cancel_flag.store(true)`
in both select arms was deleted — Drop subsumes it (subsumption is also
why the normal-return path harmlessly flips the flag after the walk
already finished: nobody reads it anymore).

dispatch.rs: NO code change — it is where the future is dropped; the fix
belongs in the future being dropped (the tool bodies). The guard lives in
glob.rs rather than tools/mod.rs to keep edits inside the WO file list
and off shared-file conflict surfaces.

Tests: `walker_cancel_guard_flips_when_dropped_before_completion` (glob)
+ `fallback_walk_cancel_guard_flips_when_dropped_before_completion`
(grep) — walker thread spawned and in flight, guard dropped (the
timeout-path teardown simulated), flag observed set. Drop is
synchronous, so the assertion is race-free; the flag-stops-walk half of
the contract is the existing 48.34 tests.

Gates (fast, per WO): `cargo check --workspace --all-targets` green;
`cargo clippy -p kf-code --all-targets -- -D warnings` green; `cargo
fmt --check` green; targeted — glob 16/16, grep 35/35 (51/51 combined,
incl. both new tests), executor dispatch 26/26. gitnexus impact:
Glob::run MEDIUM (11 callers, all in-file tests), Grep::run HIGH (15
callers, all in-file tests — breadth via the 41-impl `Tool::run`
interface; 0 processes affected); no signature or normal-path behavior
change.
