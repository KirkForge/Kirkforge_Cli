# WO 48.44 — feature-combo CI rung (pty / devtools / computer_use / no-default-features never compiled by CI)

## Status: Done

## Problem

P2. The pty, devtools, and computer_use feature combos — and the
`--no-default-features` build pinned as supported by ADR-0017 — compile in
exactly zero CI jobs. PR CI (`ci.yml`) and merge CI (`ci-merge.yml`) build
default features only. WO 48.31's verification needed `--features pty`
locally; WO 48.9 fixed the broken `--no-default-features` build and
explicitly DEFERRED its CI job (never landed). The class rots silently:
nothing fails when a supported combo stops compiling.

Proof the rot is real: this WO's local verification found `--features
devtools --all-targets` RED on `origin/dev` — WO 48.31 (commit 2d0ba5cc)
inserted `call_id: String::new()` into a `kf_bench::TaskResult` test literal
in the devtools-gated `src/session/bench.rs`, a struct that has no such
field (E0560). No CI job compiles that code, so it shipped broken.

## Root cause

CI feature coverage is a single point (default features). Every opt-in
feature is a supported configuration surface with no gate; deferral of the
48.9 CI job left the whole class ungated.

## Approach

1. Fix the live breakage: delete the stray `call_id` field from the
   `TaskResult` literal in `bench_summary_accumulates_tokens`
   (src/session/bench.rs). One line, root cause: the field never existed on
   that struct; 48.31 over-applied the TurnEvent edit.
2. Add one nightly job `feature-combos` to `.github/workflows/ci-nightly.yml`
   (ADR-074 tiering: nightly, not PR-gating) with four
   `cargo check --workspace --all-targets --locked` steps:
   `--features pty`; `--features devtools`;
   `--features devtools,computer_use`; `--no-default-features`.
   Job shape mirrors the existing nightly jobs (checkout / pinned
   dtolnay toolchain / Swatinem rust-cache `key: nightly-feature-combos` /
   timeout-minutes: 45 — the four checks took ~18 min warm locally).
