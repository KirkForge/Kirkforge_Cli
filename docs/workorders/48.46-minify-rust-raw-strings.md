# WO 48.46 — minify_rust_inner raw-string-blind — `//` inside r#"…"# comment-strips content → invalid Rust

## Status: Done

## Problem

P1. src/shared/minify/lang.rs:562-634 — `minify_rust_inner` lacks raw-string
awareness: in `r#"{"repo": "http://x"}"#` the quote before `http` closes the
tracker's string, so the URL's `//` lands outside a tracked string and the
line-comment arm strips to EOL → content gone, invalid Rust on write-back.
Port 48.40's raw-string scanner (r#-detection: `r"`/`r#*"` open, close on `"`
plus N `#`; `b`/`br` prefixes) into `minify_rust_inner`'s string tracking —
raw strings emit verbatim to their closer; `//` and `/*` don't comment-strip
inside them.

## Root cause

First-pass char scanner tracks only normal quote pairing; 48.40 fixed the
second pass (`strip_test_blocks`) and left the first pass raw-string-blind as
its known ceiling.

## Approach

Reuse 48.40's `open_string()` lookback unchanged: on an opening `"` outside a
string, classify by the emitted bytes before it (`r`/`br` + N `#`); raw
strings copy verbatim to `"` + N `#` (no escape handling, no comment
detection). One guarded arm before the normal string-open arm.
