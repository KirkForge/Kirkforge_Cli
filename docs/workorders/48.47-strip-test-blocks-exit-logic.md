# WO 48 — strip_test_blocks exit needs a brace pair after entry — one-liner test mod empties the rest of the file; brace-less mod deletes the next fn

## Status: Planned

## Problem

P1 ×2. lang.rs:442-538 — (1) a one-liner #[cfg(test)] mod tests {...} (no braces after the entry line) makes the scanner run to EOF deleting everything after; (2) brace-less #[cfg(test)]\nmod tests; deletes the following function. Fix: on entry, if the entry line itself contains the closing brace, consume just that line; for brace-less (line ends with ;), consume the two marker lines only. ALSO fold in the sweep-5 P2: block comments /* */ with odd quotes inside break brace counting (48.40 regression) — track block-comment state alongside string state.

Source: Sweep 5 (kf-code-review.md, 2026-08-29, HEAD fae3ada2). 3 P1 (minify rust/py entry-exit logic — the un-treated half of the 48.x scanner wave), 4 P2. All verified with adversarial round-trip harnesses.

Per-language scanner patches fixed quote-INTERIOR state but never entry/exit decision logic (docstring detection, raw-string entry, module-exit matching); teardown fail-open patterns recurring (channel vs Drop guard); byte-vs-column width.
