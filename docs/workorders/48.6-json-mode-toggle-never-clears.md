# WO 48 — set_json_mode(false) never clears response_format — hot-reload keeps json_object forever; Anthropic arm never worked

## Status: Done

## Problem

P2. All 6 adapters: set_json_mode(true) sets response_format, but set_json_mode(false) leaves it set — a /model or /reload toggling json off keeps sending json_object. Separately the Anthropic adapter's json_mode arm is empty (no prefill exists). Fix: clear response_format on false in every adapter; implement or honestly disable the Anthropic arm.

Source: post-WO-47 baseline audit (kf-code-review.md, 2026-08-28, HEAD e4725bd6).

## Root cause

See Problem. Cross-cutting theme: fixes applied at one layer/site of a duplicated
pattern (adapters, hooks, gates) leaving sibling sites divergent.

## Approach

Read the Problem section. Minimal correct fix. Grep for sibling sites of the same
pattern before considering it done.

## Files

src/adapters/*.rs

## Gate

Fast gates: cargo check --workspace --all-targets + clippy -p <touched> +
targeted tests + fmt. CI verifies the full suite.

## Done

All 6 adapters (`oellama`, `anthropic`, `openai_compat`, `anthropic_vertex`,
`anthropic_bedrock`, `caching`) now clear `response_format = None` in
`set_json_mode(false)` — the inverse of the `true` arm — so a hot-reload
(`/model`, `/reload`) toggling json mode off stops sending
`response_format: json_object` / `"format": "json"`. On `CachingAdapter`
this also fixes the cache key (`response_format` feeds `CacheKey`), so a
stale cached JSON response can no longer replay after toggle-off. Each
adapter's existing toggle test extended with clear-on-false assertions.

Anthropic-family `Some(JsonObject)` arm in `build_anthropic_body` (shared by
anthropic/bedrock/vertex): honest-disable per owner directive — the comment
claiming a "system-prefill" that never existed is replaced by a warn-once
(`std::sync::Once`) + `ponytail:` comment naming the upgrade path
(system-prompt suffix + assistant prefill `{`). No wire-format change.

Known limit (observed, not fixed — executor is a shared file, out of WO
scope): `reload_config` (src/session/executor/mod.rs:597) pushes
`set_json_mode` but never `set_response_format`, so an explicit
`response_format = "json_schema"` config change still needs an executor
restart to take effect. Adapters are now self-consistent either way.

Fast gates: `cargo check --workspace --all-targets`,
`cargo clippy -p kf-code --all-targets -- -D warnings`,
`cargo test -p kf-code --lib adapters::` (437 passed, incl. the 6 extended
toggle tests), `cargo fmt --check` — all green. Full suite + Windows cross
gate deferred to merge-time CI per owner fast-gates directive.
