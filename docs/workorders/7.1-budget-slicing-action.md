# Workorder 7.1 — Implement Plugin3 Budget Slicing Action

## Status: Planned

## Problem

The Plugin3 budget hooks (session-start, post-tool-bash, post-tool-write_file,
pre-compact) observe and report token usage but do not **act** on it. The core
value proposition of Plugin3 per ARCHITECTURE.md is: "slices or compacts
oversized tool results when the budget is approached." Currently the hooks only
log warnings — they do not mutate tool results before they enter the
conversation. The budget guard is a passive monitor, not an active guard.

## Root cause

The hooks were implemented with full event context (HookContext.tool_result)
in WO 6.7, but the slicing/compacting action was deferred because it requires
wiring into the executor's turn loop to intercept tool results *before* they're
appended to the conversation.

## Files to touch

- `src/session/executor/turn.rs` — after tool execution and before the result
  is appended to the conversation, call the budget check. If the budget is
  `Over` or `Approaching` and the tool result is oversized, slice it (head + tail
  with a slice marker) and store the full content in the offload store. The
  sliced result enters the conversation; the full result is retrievable via
  `store_get`.
- `src/session/budget.rs` — add a `check_and_slice(result: &str, budget: &TokenBudget) -> BudgetAction` function that returns either `Keep(result)` or `Sliced { sliced_result, stored_key }`. Use `plugin3_core::slicing::HeadTailSlicer` for the slicing.
- `src/session/hooks.rs` — no change needed (hooks already receive tool_result).
- `src/shared/mod.rs` — `ToolOutcome::text_content()` already exists.

## Approach

1. Add `BudgetAction` enum to `budget.rs`: `Keep(String)` or
   `Sliced { display: String, key: String }`.
2. Implement `check_and_slice` using `plugin3_core::slicing::HeadTailSlicer`
   and `plugin3_core::store::InMemoryOffloadStore`. The slice target is
   `budget.remaining()` — if the result is larger than remaining, slice to fit.
3. In `turn.rs`, after `handle_tool_outcome` and before the result is appended,
   call `check_and_slice` on the result text. If `Sliced`, replace the result
   content with the sliced version and store the full content.
4. The `pre-compact` hook already resets `budget.used = 0` when over/approaching
   — keep that behavior so the budget recovers after compaction.
5. Add unit tests for `check_and_slice`: under-budget (keep), over-budget (slice),
   exact-fit (keep).
