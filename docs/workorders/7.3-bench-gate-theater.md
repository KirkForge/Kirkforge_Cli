# Workorder 7.3 — Fix Bench CI Gate Theater

## Status: Planned

## Problem

The bench CI job has a step named "Fail if success rate drops below 10%"
(`ci.yml:298-310`) that is structurally incapable of failing. The Python
snippet exits 0 (success) when the rate is below 0.1, which causes the `if`
body to run and emit only a `::warning::` (non-gating). When rate >= 0.1,
Python exits 1, the `if` body is skipped, and the step succeeds. The step
name is a lie — it never fails regardless of bench success rate.

Additionally, three steps in the bench job have `continue-on-error: true`
(baseline download, comparison, PR comment), making the entire job
informational-only despite the "Fail if" step name.

## Root cause

The bench gate was wired as a proof-of-concept and the failure logic was
inverted during implementation.

## Files to touch

- `.github/workflows/ci.yml` — fix the "Fail if success rate drops below 10%"
  step:
  1. Correct the Python exit logic: exit 1 (failure) when rate < threshold,
     exit 0 when rate >= threshold.
  2. Decide: keep informational (with an honest step name like "Report bench
     success rate") or make it gating with a real threshold. Recommendation:
     keep informational for now (the bench uses qwen2.5:0.5b which is weak and
     noisy), but rename the step to "Report bench success rate" so it doesn't
     claim to be a gate.
  3. Remove `continue-on-error: true` from the comparison and PR-comment steps
     if they should be real (or keep them with honest naming).
- `docs/adr/045-continuous-eval-pipeline.md` — update to honestly describe the
  gate as informational with an upgrade path to gating.

## Approach

1. Rename the step to "Report bench success rate" (honest).
2. Fix the Python: `sys.exit(1 if rate < 0.1 else 0)` — but wrap in
   `continue-on-error: true` so the job stays green and the warning is emitted.
3. OR: make it a real gate with `continue-on-error: false` and a low threshold
   (e.g., 0.1) that only catches catastrophic regressions.
4. Update ADR-045 to match whatever is chosen.

## Gate

CI validation only — push to a PR branch and confirm the bench job step name
matches its actual behavior.

## Done condition

- No CI step claims to be a gate when it isn't.
- ADR-045 honestly describes the bench gate's gating status.
- The bench job step names match their actual behavior.
