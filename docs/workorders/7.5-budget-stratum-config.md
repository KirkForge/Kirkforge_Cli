# Workorder 7.5 — Budget and Stratum Config Fields

## Status: Done

## Problem

Three config fields were listed in workorders 6.6 and 6.7 but silently
dropped during implementation:
- `stratum_mode` (off/lite/full/ultra) — Stratum mode selection is only via
  tool args or `STRATUM_MODE` env var, not config.
- `budget_ceiling` (default 200_000) — hard-coded in `TokenBudget::default()`.
- `budget_approaching_ratio` (default 0.8) — hard-coded in
  `TokenBudget::default()`.

These should be user-configurable in `config.toml` so users can tune budget
and compression behavior without environment variables or recompilation.

## Root cause

The config fields were deferred as "not needed for MVP" during the fold-in.
They're now needed for the budget slicing action (WO 7.1) to be tunable.

## Files to touch

- `src/shared/config/tools.rs` — add three fields to `ToolConfig`:
  - `stratum_mode: Option<String>` (default `None` = use Stratum's default `full`)
  - `budget_ceiling: usize` (default `200_000`)
  - `budget_approaching_ratio: f64` (default `0.8`)
- `src/session/budget.rs` — `shared_budget()` should read
  `budget_ceiling` and `budget_approaching_ratio` from config instead of
  using `TokenBudget::default()`. This requires passing config into the budget
  initialization.
- `src/session/stratum.rs` — `StratumSessionStartHook` should read
  `stratum_mode` from config instead of only checking `STRATUM_MODE` env var.
- `config.toml.example` — add documented examples for the three new fields.
- `state.md` — remove the config-field deferrals from the deferred-items table.

## Approach

1. Add the three fields to `ToolConfig` with serde defaults.
2. In `budget.rs`, change `shared_budget()` to accept config parameters or
   read from a config snapshot.
3. In `stratum.rs`, read `stratum_mode` from config with env-var override.
4. Add a unit test that verifies config values override defaults.
