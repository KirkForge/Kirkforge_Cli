# Workorder 7.7 — KVB Verifier Bus Bridge (ADR-028)

## Status: Planned

## Problem

ADR-028 (Verifier Bus Unification) is design-only. It describes a
cross-language bridge between the Rust verifier bus and the TS orchestrator's
verifier surface. No bridge code ships. The Rust `BusVerifier` (ADR-043)
partially fills this gap, but the full unification vision — a single verifier
registry that both Rust and TS verifiers register into — is unshipped.

## Root cause

The KVB bridge was designed before the plugin fold-in. The fold-in
eliminated the TS orchestrator for Plugin3 (it's now a Rust call), reducing
the need for a cross-language bridge. The bridge is still needed for the
Node SDK plugin (`kirkforge-plugin`), which ships TS-based verifiers.

## Files to touch

- `src/session/verifier/bus.rs` — extend the `VerifierBus` to accept
  plugin-declared verifiers (from `Capability::Verifier` in `kirkforge.toml`).
  Currently plugin verifiers are handled by the old `Verifier` trait path
  (`verifier/plugin.rs`); the bus should unify them.
- `crates/kirkforge-plugin/src/lib.rs` — the `Verifier` capability type
  already exists. No change needed to the manifest format.
- `src/session/verifier/plugin.rs` — wire plugin verifiers into the bus
  instead of the old event-driven path.
- `docs/adr/028-verifier-bus-unification.md` — update status from design-only
  to implemented (or partially implemented).

## Approach

1. Extend `VerifierBus` to hold plugin verifier entries (name, priority,
  command path).
2. When a plugin declares a `Verifier` capability, register it in the bus.
3. The bus runs plugin verifiers via the same `PluginToolWrapper` subprocess
  path as plugin tools.
4. Plugin verifier results are injected into the conversation as tool results,
  same as built-in verifiers.
5. Update ADR-028 to reflect what shipped.
