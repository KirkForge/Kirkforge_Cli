# Workorder 7.8 — Bench Task Expansion and Realism Pass

## Status: Planned

## Problem

The bench harness has 10 tasks (3 easy, 5 medium, 2 hard). WO 6.1 fixed the
empty-toolset issue so tasks are now winnable, but the task set is thin:
- Only 10 tasks — not enough to detect regressions in specific capability
  areas (e.g., refactoring, debugging, multi-file edits).
- 5 tasks operate on the real repo (no setup files) — these are fragile
  because they depend on the repo's current state.
- No tasks test the verification loop (model makes a mistake, verifier
  catches it, model fixes it).
- No tasks test plugin tool usage (stratum, budget, draw).
- No tasks test multi-file refactoring.

## Root cause

The bench tasks were created as an MVP (5 initial + 5 added in WO 6.1). No
expansion pass has been done.

## Files to touch

- `benches/tasks/` — add 10 new tasks (total 20):
  - `fix_clippy_naming` (easy) — fix a clippy::needless_lifetimes warning
  - `add_struct_field` (medium) — add a field to a struct + update all
    construction sites (multi-file)
  - `extract_trait` (hard) — extract a trait from an impl block
  - `fix_borrow_error` (medium) — fix a borrow checker error
  - `add_enum_variant` (easy) — add a variant to an enum + update match arms
  - `inline_function` (medium) — inline a function + remove it
  - `add_test_module` (easy) — add a `#[cfg(test)] mod tests` block
  - `fix_lifetime_error` (hard) — fix a lifetime annotation error
  - `rename_module` (hard) — rename a module file + update all `mod` declarations
  - `add_error_variant` (medium) — add an error variant + update error handling
- `crates/kirkforge-bench/src/lib.rs` — no change needed (task format is
  stable).
- `docs/adr/038-task-benchmark-harness.md` — update task count.

## Approach

1. Write each task as a TOML file with self-contained `setup` files (synthetic
   Cargo projects) so they don't depend on the real repo state.
2. Each task has a `prompt` that describes the change, a `setup` with the
   initial files, and a `verify` that checks the result.
3. Test each task locally with `kirkforge bench verify-only --tasks benches/tasks/
  --task <name>` to confirm the verify spec works.
4. Difficulty ratings: easy = single-file single-change, medium = multi-change
  or cross-file, hard = refactoring or complex type system.

## Gate

```
cargo fmt --check && cargo test --locked --workspace --no-fail-fast --all-features
kirkforge bench verify-only --tasks benches/tasks/
```

## Done condition

- 20 total bench tasks (10 existing + 10 new).
- All tasks have self-contained setup files (no real-repo dependency).
- `kirkforge bench verify-only` passes for all 20 tasks.
- ADR-038 updated with new task count.
- Depends on: nothing.
