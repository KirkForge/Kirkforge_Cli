# Workorder 7.9 — Context Index Phase 7: Embeddings and Graph-Walk Retrieval

## Status: Planned

## Problem

The context index (`kirkforge-context-index`) currently retrieves symbols by
substring match. ADR-037 Phase 7 calls for embeddings-based retrieval and
graph-walk traversal — finding semantically related symbols by walking the
import/call graph rather than just matching names. This is listed as "Future"
in `state.md:58` and is the single biggest capability gap in the context
system.

## Root cause

Phase 7 was always planned as a future upgrade after Phases 1-6 (4 languages,
import edges, call-graph edges, disk caching) shipped. The infrastructure is
in place (the graph exists); the retrieval algorithm is substring-only.

## Files to touch

- `crates/kirkforge-context-index/src/lib.rs` — add:
  - `embeddings.rs` (new) — symbol embedding generation. Use a lightweight
    approach: TF-IDF or code-specific features (symbol name, kind, doc
    comments, surrounding code) rather than a heavy ML model. The goal is
    semantic similarity without a runtime model dependency.
  - `graph_walk.rs` (new) — graph-walk retrieval: given a starting symbol,
    walk the import/call graph to find related symbols within N hops. Rank
    by hop distance + embedding similarity.
  - Update `retrieve()` to optionally use graph-walk when the query is a
    symbol name (not a substring).
- `src/session/prompt/mod.rs` — update the retrieval call to pass the query
  type (symbol name vs free text) so the index can choose the right strategy.
- `docs/adr/037-repo-graph-context-retrieval.md` — update Phase 7 status.

## Approach

1. **Embeddings**: generate a sparse vector per symbol from:
   - Symbol name (tokenized)
   - Symbol kind (function/struct/enum)
   - Doc comments (if any)
   - Import path
   Store embeddings in the cache JSON alongside symbols.

2. **Graph-walk**: given a query symbol, BFS/DFS the import and call graphs
   up to N hops (default 2). Collect visited symbols. Rank by:
   - Hop distance (closer = more relevant)
   - Embedding cosine similarity to the query
   - Symbol kind (functions preferred over modules)

3. **Hybrid retrieval**: if the query matches a known symbol name exactly,
   use graph-walk. If it's free text, use embedding similarity. If it's a
   substring, use the existing substring match.

4. **No heavy deps**: do NOT add `candle`, `ort`, or any ML runtime. Use
   pure-Rust sparse vector math (dot product on `Vec<f32>`). The embeddings
   are structural (TF-IDF over code tokens), not neural.
