# Workorder 8.5 — ADR Index Table: Add All Missing ADRs

## Status: Planned

## Problem
The `docs/adr/README.md` index table only contains 31 rows for 68 ADR files. The 3-digit native ADRs (019-050) are listed in a bulleted section below the table but NOT in the table itself. The `adr_xref_drift` test was fixed in WO 8.0 to handle both naming conventions, but the index table is still incomplete — a newcomer reading the table sees only half the ADRs.

## Root cause
The table was originally for the 4-digit Plugin3 ADRs only. Native CLI ADRs (3-digit) were appended as a bulleted list. The table and list should be unified.

## Files to touch
- `docs/adr/README.md` — restructure:
  - Option A: One unified table with all ADRs (both 3-digit and 4-digit), sorted by number
  - Option B: Two tables (Plugin3 ADRs + Native CLI ADRs) with clear headers
  - Recommended: Option A — one table, sorted by number, with a "Series" column (Plugin3 / CLI)
- Remove the bulleted list (now redundant with the table)

## Approach
1. Read all ADR files in `docs/adr/` and extract their number, title, and status
2. Build a single sorted table with columns: ADR | Title | Status | Series
3. Replace the two-section format (table + bullets) with the unified table
4. Run `cargo test -p plugin3-core --test adr_xref_drift` to confirm the test still passes

## Gate
```
cargo fmt --check && cargo test -p plugin3-core --test adr_xref_drift --test readme_drift
```

## Done condition
- All 68 ADRs are in a single index table
- No bulleted list of ADRs remains
- `adr_xref_drift` passes
- `readme_drift` passes
