# Workorder 8.6 — Stratum Mode Integration with Budget Guard

## Status: Planned

## Problem
Stratum (input-side compression) and Plugin3 (output-side budget guard) operate independently. When the budget guard slices a tool result, the sliced content enters the conversation raw — Stratum doesn't know it was sliced. When Stratum compresses a tool output, the budget guard doesn't know the compressed size. The two systems should coordinate: when budget is `Approaching`, Stratum should switch to `full` or `ultra` mode automatically; when Stratum compresses, the budget guard should track the compressed size.

## Root cause
The two systems were designed separately and wired independently. No coordination layer exists.

## Files to touch
- `src/session/budget.rs` — when slicing, emit a `BudgetSlicedEvent` with the original and sliced sizes
- `src/session/stratum.rs` — listen for `BudgetSlicedEvent` and escalate compression mode
- `src/session/executor/turn.rs` — after budget slicing, check if Stratum should also compress the result
- `src/session/hooks.rs` — the `PreCompactHook` should also trigger Stratum compression

## Approach
1. Define a `BudgetSlicedEvent` that carries `{original_size, sliced_size, key}`
2. When the budget guard slices a result, also run Stratum compression on the remaining head+tail
3. When Stratum is in `lite` mode and budget is `Approaching`, auto-escalate to `full`
4. Track the combined effect: budget.used should reflect the post-Stratum-compression size
