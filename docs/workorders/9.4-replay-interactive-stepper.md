# Workorder 9.4 — Replay Interactive Stepper

## Status: Planned

## Problem
The execution replay system (`src/session/replay.rs`, 289L) records
`TurnRecord`s to a `.trace.ndjson` file and can load + format them for
terminal output (`format_turn`). The `kirkforge replay <id>` CLI command
exists and prints turns. But replay is **non-interactive**: it dumps all
turns (or a range with `--from`/`--to`) as text. There is no step-forward /
step-backward / inspect-context-window / inspect-patch interaction. The
ChatGPT sixth-pass review named "time-travel debugging (Planner → Thought 18
→ Tool 4 → Context Window 2 → Patch, inspectable)" as a missing item. The
recording half shipped; the interactive inspector half did not.

## Root cause
Replay was built as a log reader (record → load → print), not as an
interactive TUI. The `format_turn` function produces a fixed text rendering;
there's no step state, no input loop, no inspector for the per-thought /
per-tool-call / per-context-window detail.

## Files to touch
- `src/session/replay.rs` — add a `ReplayStepper` struct that holds
  `Vec<TurnRecord>` + current index + a render function. Methods:
  `step_forward()`, `step_back()()`, `jump_to(n)`, `current()`,
  `render_current() -> String` (detailed view of the current turn including
  full prompt messages, full model response, full tool call args + results,
  not the 200/300-char truncated `format_turn`)
- `src/cli.rs` / `src/main/mod.rs` — `kirkforge replay <id>` gains an
  `--interactive` flag. When set, instead of printing all turns, it enters a
  ratatui loop with keybindings: `j`/`k` or ↓/↑ to step, `g` to jump,
  `q` to quit, `Enter` to expand the current turn's detail
- `src/tui/replay.rs` (new) — a minimal ratatui app: a single scrollable pane
  showing the current turn, with a key handler for step/jump/quit/expand

## Approach
1. Build `ReplayStepper` as a pure struct with no TUI dependency — testable
   in isolation
2. Add unit tests for step_forward/step_back/jump_to/render_current
3. Wire `--interactive` flag in CLI; when set, spawn the ratatui replay app
4. The TUI app reads the trace file once, holds the records in memory, and
   renders the current turn's full detail on each keypress
5. Keybindings match the existing TUI conventions (vim-style j/k)
