# Workorder 9.7 — Tree-Sitter VFS Minification

## Status: Done

## Problem
`src/tui/commands/mentions.rs` has a `minify_source()` helper that strips
comments + blank lines when a user @-mentions a file. But this is a TUI-only
feature triggered by explicit `@file` syntax. The agent loop itself does not
minify file content before sending it to the model. `docs/archive/ideas/vfs-minification.md`
(63L) is a note describing a "virtual filesystem" where the model sees
minified versions of files (comments stripped, whitespace collapsed,
imports elided) for context-window efficiency. Vix's tree-sitter VFS is a
differentiator; KirkForge has the minification helper but not the VFS layer.

## Root cause
The `minify_source()` helper was built for the TUI mentions feature. Wiring
it into the `read_file` tool (so the model always sees minified content)
requires a decision: minify always? minify only above a size threshold?
minify only for non-edited files? That decision was never made.

## Files to touch
- `src/shared/minify.rs` — extend `minify_source()` to support per-language
  minification: Rust (strip `//`/`///` comments, collapse blank lines, elide
  `use` imports), TypeScript/JavaScript (strip `//`/`/* */`, collapse),
  Python (strip `#`/docstrings, collapse), Go (strip `//`/`/* */`, collapse)
- `src/tools/read_file.rs` — add a `minify: bool` parameter (or a
  `minify_above_bytes: usize` threshold). When the file content exceeds the
  threshold, the tool returns the minified version with a note: "[minified:
  N lines → M lines, use read_file with minify=false to see full content]"
- `src/shared/mod.rs` / `Config` — add a `minify_above_bytes` config field
  (default: 4096, so small files are never minified)
- `docs/archive/ideas/vfs-minification.md` — update from "idea" to "implemented"
- `docs/adr/` — new ADR for the minification decision

## Approach
1. Extend `minify_source()` with per-language rules (use tree-sitter to
   parse + strip comments/docstrings precisely, not regex — the
   tree-sitter grammars are already in the workspace via
   `kirkforge-context-index`)
2. Add `minify_above_bytes` to `Config` (default 4096)
3. In `read_file`, when content size > threshold, return minified content
   with a note
4. Test: a 500-line Rust file with 200 lines of comments → minified to ~300
   lines; the model sees the minified version; a second call with
   `minify=false` returns the full content
