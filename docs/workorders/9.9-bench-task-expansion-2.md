# Workorder 9.9 — Bench Task Expansion: Real-World Task Shapes

## Status: Done

5 new multi-file/multi-turn task toml files added (total 30 tasks, was
24): `multi_file_pattern`, `test_fix_cycle`, `pr_review`,
`refactor_trait_extraction_multi`, `debug_log_trace`. Each exercises a
real agent skill (pattern-following, test-fix cycle, PR review, trait
extraction, stack-trace debugging).

The 5 new tasks use `requires_model = true` (new `BenchTask` field,
default false) because their verify specs check *post-model* content
(the WO 9.0 anti-pattern was checking setup content, which passes
`verify-only` trivially but doesn't validate the model's work). With
`requires_model = true`, `verify-only` skips them and reports
`[SKIP] skipped (requires model)`; `bench run` runs them normally and
the verify (cargo build/test/grep for the new symbol) validates the
model's output. `handle_bench_verify_only` now reports
`{passed}/{total} tasks verified, {skipped} skipped (requires model)`.

`bench verify-only` result: 25 PASS + 5 SKIP = 30. `bench list` shows
30 tasks. All gates green.

## Problem
The bench harness has 24 tasks, but they're all single-file edits (add a
function, fix a clippy warning, extract a module). They don't exercise the
multi-file, multi-turn, multi-tool shapes that real agent work involves:
- "Read these 3 files, understand the pattern, add a 4th file following it"
- "Run the tests, find the failing one, fix the bug, confirm green"
- "Refactor this module: extract a trait, implement it for the 3 existing
  types, update all call sites"
- "This PR adds a feature; review it for bugs and suggest fixes"

Without these shapes, the bench measures single-shot editing skill, not
agent skill. The ChatGPT sixth-pass review named "automatic benchmarking"
as the item that turns "agent capability B+" from code-reading grade into
measured grade — and that requires *representative* tasks, not just *any*
tasks.

## Root cause
The bench tasks were written for the WO 6.x/7.x/8.x series to test the
harness, not to test the agent. They're correctness-checks for the bench
system, not capability-measures for the agent.

## Files to touch
- `benches/tasks/multi_file_pattern.toml` — new: setup creates 3 files
  following a pattern; model must read all 3 and add a 4th
- `benches/tasks/test_fix_cycle.toml` — new: setup has a failing test;
  model must run tests, read the failure, fix the bug, re-run to confirm
- `benches/tasks/refactor_trait_extraction.toml` — new: setup has 3 types
  with duplicated methods; model must extract a trait, implement it, update
  call sites
- `benches/tasks/pr_review.toml` — new: setup is a git repo with a branch
  containing a PR with a subtle bug; model must review the diff, identify
  the bug, suggest a fix
- `benches/tasks/debug_log_trace.toml` — new: setup has a program that
  crashes with a stack trace; model must read the trace, find the source
  line, fix the root cause
- `crates/kirkforge-bench/src/lib.rs` — if multi-file tasks need a new
  `setup_files` shape (e.g., a directory tree, not just a flat file map),
  extend the harness

## Approach
1. Write 5 new task toml files with multi-file setups. Each setup creates
   a realistic mini-repo (2-5 files) that exercises a real agent skill.
2. The verify spec for each must run a command that validates the *outcome*
   (tests pass / build succeeds / lint clean), not just check for a
   substring — so `test_passes` or `command_exits_zero`, not `file_contains`
   (the WO 9.0 lesson)
3. Run `bench verify-only` to confirm all 5 new tasks pass the verify spec
   against the setup (without model edits — the verify must be
   post-model-only)
4. If the verify spec can't run without model edits (e.g., "tests pass"
   requires the model's fix), add a `requires_model: true` field to the
   verify spec so `verify-only` knows to skip it and `bench run` knows to
   run it
